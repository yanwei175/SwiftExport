## 3. 指纹协议（v1）

COM payload 使用 ASCII 文本，固定 LF 换行，末尾保留 LF：

```text
SwiftExportThumbnail:v1
SourceSha256=<64位大写十六进制>
Spec=jpeg-v1;maxEdge=256;quality=85;noUpscale=1;whiteBackground=1;orientationNormalized=1
```

- SourceSha256 计算对象是**服务端最终重新编码、实际写入的原图完整 JPEG 字节**，不是用户输入文件、像素数组或缩略图。
- 原图不嵌入本协议。只有缩略图记录来源，避免自引用哈希。
- 原图 SHA-256 不变；API 的 ThumbnailSha256 必须对**插入 COM 后实际发布的缩略图完整字节**计算。不能返回插入前哈希。
- 规格值必须与现有处理器参数一致，复用现有参数或最小集中定义，不让两个常量来源漂移。
- 不增加时间戳、随机 ID、路径、用户信息或其他未要求字段。相同输入和规格不应仅因元数据变化而每次产生不同内容。
- 这是自定义来源标签，不是数字签名，也不保证检测任意人为篡改缩略图。没有标签或标签无效应视为“不能确认匹配”，不能当作已匹配。

## 4. JPEG 读写边界

- 不能简单追加文本到文件尾，必须使用 JPEG 标准 COM marker、两字节大端长度（含长度字段本身、不含 marker），严格检查容量。
- 保留 JPEG 原有 APP/EXIF/ICC 等段的字节和顺序；在首个 SOS 前的合法边界插入 COM，不破坏编码扫描数据，不再次有损编码。
- 写入只面向本处理器新生成的 JPEG；拒绝不完整或非法结构，不尝试“修复”任意坏图。
- TryRead 按 marker/段长度遍历头部，遇 SOS 停止，不把熵编码数据当成普通段，也不靠全文搜索字符串；明确头部扫描预算、整数边界、截断和长度非法处理。读取缺失/未知版本/重复本协议标签/非法 SHA 或规格时返回不能确认，不抛未处理异常。
- 不实现通用 EXIF/XMP 编辑器，不引入第三方元数据 DLL。实现前核对 JPEG COM 的权威格式说明，避免凭记忆猜 marker 规则。

## 5. 上传发布语义

1. 读取、解码、方向修正、生成最终原图和缩略图。
2. 计算最终原图哈希，嵌入缩略图 COM，得到最终缩略图。
3. 取得现有同名目标锁；先发布原图，再发布最终缩略图。
4. 两张全部写入完成才返回该项成功。之后返回两份实际最终文件的哈希与既有 URL。
5. 任一步失败不得报成功；保留已成功发布的原图，不执行可能误删旧版本的回滚；允许用户重新上传同名图片修复。
6. 保留现有取消语义：取消不证明已发布文件被撤销。最后一次文件发布已成功后不要追加会把成功改判取消的检查。

两份文件不是一个文件系统事务，读取者短暂看到新原图/旧缩略图属于既有约束。删除 JSON 后不再有持久化 pending/complete 记录；检查来源标签或重建缩略图负责后续恢复，不声称具有断电事务保证。

同名进程锁保留、不同名字允许并行；不新增全局串行锁、数据库回执、Redis、自动重试、读取时重建或后台清理。

## 6. 旧图片与未来检查工具

- 旧原图和旧缩略图继续正常通过既有静态地址读取，不要求全量迁移后才能使用。
- 旧缩略图没有标签时，未来工具将其视为需重建；也可现在由用户显式重传原图生成新缩略图。
- 旧 JSON 不再读取或更新。程序不自动递归清理磁盘；在说明中写明升级完成、所有旧写入进程停止后，确认专用旧目录内容再由管理员删除。

### 协议与行为结果

- COM payload 严格为 ASCII、LF 结尾的三行 v1 协议；`SourceSha256` 是最终原图完整 JPEG 字节的 64 位大写十六进制 SHA-256。
- COM 使用 `FF FE` marker 和包含两字节长度字段的大端段长，插入首个 SOS 前；写入保留原 JPEG 所有既有字节和段顺序，拒绝不完整、超预算或已含本协议标签的输入。
- `TryRead` 只遍历头部 marker，遇 SOS 停止；缺失、未知版本、重复协议标签、非法 SHA/规格、截断、非法长度或超过预算均返回不能确认，不扫描熵编码数据。
- API `OriginalSha256` 继续对应最终原图；`ThumbnailSha256` 对插入 COM 后的最终缩略图完整字节计算，HTTP/DTO/URL/文件名保持不变。
- 发布仍按同名进程锁隔离，先原图后缩略图；第二张失败不返回成功、不删除已发布原图，重传同名图片可修复。程序不再创建、读取或更新 `.product-image-state` JSON。
- 旧图片继续按原 URL 读取；无标签旧缩略图仅在未来工具中视为需要重建，本轮不自动迁移或清理。旧 JSON 只能在所有旧写入进程停止后由管理员确认并人工删除。

JPEG marker、COM `FFFE`、SOS `FFDA` 和 COM 段长语义按 [ITU-T T.81](https://www.w3.org/Graphics/JPEG/itu-t81.pdf) 核对；COM 位于 JPEG marker sequence、SOS 前的顺序语义另参考 [Oracle JPEG metadata specification](https://docs.oracle.com/en/java/javase/25/docs/api/java.desktop/javax/imageio/metadata/doc-files/jpeg_metadata.html)。
