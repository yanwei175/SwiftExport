# 客户与销售产品选择控件

## 已移植的控件

- `Features/Customers/Components/CustomerAutoSuggestComboBox`：包装 LookupTextBox，按 CustomerCode／CustomerName 本地筛选，显示客户代码，提交完整 CustomerDto。ItemsSource 由页面绑定 ReferenceDataCacheService.Customers，控件不主动加载缓存。
- `Features/Suppliers/Components/SupplierAutoSuggestComboBox`：包装同一个 LookupTextBox，按 SupplierCode 本地筛选，候选同时显示编码和名称，提交完整 SupplierDto。ItemsSource 由页面绑定 ReferenceDataCacheService.Suppliers，控件不主动加载缓存；采购导入预览页仍按当前审批边界保留占位。
- `Features/Sales/Orders/Components/SalesProductLookupTextBox`：包装远程 Lookup，显示 SKU、客户型号和完整英文描述。Text／SearchCommand／IsBusy／SearchDelay／MinimumSearchLength 转发给内部编辑器，提交 SalesOrderProductLookupDto 和 ProductId。
- 三者保留确认、清除及可选命令参数。产品选择的 FocusEditor 继续使用 Lookup 的生命周期检查。未移植业务页面或保存 API，也未修改共享 DTO。

客户示例：

```xml
<!-- xmlns:customers="clr-namespace:SwiftExport.Client.VSTO.Features.Customers.Components" -->
<customers:CustomerAutoSuggestComboBox
    ItemsSource="{Binding ReferenceData.Customers}"
    SelectedCustomer="{Binding SelectedCustomer, Mode=TwoWay}"
    SelectionCommittedCommand="{Binding CustomerSelectedCommand}"
    SelectionClearedCommand="{Binding CustomerClearedCommand}" />
```

产品示例：

```xml
<!-- xmlns:sales="clr-namespace:SwiftExport.Client.VSTO.Features.Sales.Orders.Components" -->
<sales:SalesProductLookupTextBox
    ItemsSource="{Binding ProductCandidates}"
    SelectedProduct="{Binding SelectedProduct, Mode=TwoWay}"
    SelectedProductId="{Binding SelectedProductId, Mode=TwoWay}"
    Text="{Binding ProductSearchText, Mode=TwoWay}"
    SearchCommand="{Binding SearchProductsCommand}"
    IsBusy="{Binding IsSearchingProducts}"
    SelectionCommittedCommand="{Binding ProductSelectedCommand}"
    SelectionClearedCommand="{Binding ProductClearedCommand}" />
```

供应商示例（页面首次使用时先等待 `IReferenceDataCacheService.EnsureLoadedAsync()`；不要在 Excel Startup 预热）：

```xml
<!-- xmlns:suppliers="clr-namespace:SwiftExport.Client.VSTO.Features.Suppliers.Components" -->
<suppliers:SupplierAutoSuggestComboBox
    ItemsSource="{Binding ReferenceData.Suppliers}"
    SelectedSupplier="{Binding SelectedSupplier, Mode=TwoWay}"
    SelectionCommittedCommand="{Binding SupplierSelectedCommand}"
    SelectionClearedCommand="{Binding SupplierClearedCommand}" />
```

客户加载、客户切换后的产品候选重置、远程请求取消／过期结果检查、登录会话隔离及错误提示仍由页面负责。选择器不保存服务器资料，允许补充的字段写入当前导入模型，不修改共享缓存 DTO。

## HTTPS 图片

现有 `Resources/Image.xaml` 是样式，原生 Image 可以显示 BitmapImage。销售候选中的 CachedImage 替换为轻量 `Resources/Controls/HttpsImage.cs`，显式使用原来的 SwiftExportImage 样式和悬停预览。

- `SourcePath` 接受**完整 HTTPS 地址**，MainImage 直接绑定到它；不拼接 API 根地址，不接受相对路径、本地磁盘、UNC、HTTP 或内嵌用户名密码。空地址正常留白，非法地址或失败显示空白缩略图并设置 LoadFailed。
- Loaded 后才创建 BitmapImage，默认按 96 像素宽解码，候选显示 48×48。DecodePixelWidth 可设 1 至 2048；悬停预览复用同一个已解码缩略图，不额外下载原图。
- UriCachePolicy 使用 NoCacheNoStore，CreateOptions 使用 IgnoreImageCache，不读取已有 URI 缓存；插件不创建图片目录、不写缓存文件、不注册 ImageCacheService。OnLoad 是当前位图的内存解码方式，不是磁盘缓存。
- 保持系统 TLS／证书校验，不附加 API 登录 Token。因此地址必须匿名可访问，或由后端提供可直接读取的 HTTPS 签名地址。需要 Bearer 授权头的图片不在本次范围。
- 换地址时立即移除旧图和位图事件。Unloaded 时清除 Source、解除下载和解码事件；旧下载结束不会重新显示到新候选或已关闭控件。
- WPF 原生 URI 下载没有公开取消接口：卸载保证断开 UI 更新关系，不保证底层网络立即中止。重载重新请求，不实现自动重试；日志只写固定事件及异常类型，不记录地址查询参数。

接口依据：[BitmapImage](https://learn.microsoft.com/en-us/dotnet/api/system.windows.media.imaging.bitmapimage?view=netframework-4.8)、[UriCachePolicy](https://learn.microsoft.com/en-us/dotnet/api/system.windows.media.imaging.bitmapimage.uricachepolicy?view=netframework-4.8)。

## 验证

独立 WPF 程序的 `--lookup-only` 入口运行三个包装器及图片测试。图片测试在独立进程中仅接管 `https://vsto-image.test/`，以模拟 WebRequest 给真实 BitmapImage 下载／PNG 解码管线提供内存字节；验证缓存策略、正常解码、坏图片、网络失败、换址和卸载迟到结果，不访问真实图片服务器。

这不能替代真实 TLS、证书、图片域名可达性、签名地址到期和 Excel 中候选弹层的验收。WIC 解码依赖 Windows COM；本环境沙箱限制该访问，专项测试需在允许 WIC 的执行环境运行。
