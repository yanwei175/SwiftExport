# 采购订单导入预览页

## 本期入口与职责

登录成功后，在 Excel Ribbon 的“数据导入 → 采购订单导入预览”打开非模态 WinForms 窗口，窗体内通过 `ElementHost` 承载 WPF 页面。传入的首选尺寸为 1280×820，实际初始尺寸由所属显示器的可用区域调整；可手动调整大小并与 Excel 同时操作。同一 Excel 窗口重复点击只激活原窗体，不重建页面；不同 Excel 窗口各有自己的页面 Scope。关闭窗体即释放 Scope，再次点击创建新窗体；插件退出时关闭所有自有窗体。

本期只供审批页面布局。`PurchaseOrderImportViewModel` 仅继承 `ViewModelBaseEx`，没有数据加载、属性和命令。页面没有采购 API、Excel 选区读取或草稿保存；所有操作按钮均标注“待实现”并禁用，客户、供应商和日期选择也无法提交。单头显示只读占位，明细只有列标题和空白区域，页脚汇总显示“—”，不会展示假业务数据。

## 审批时重点查看

1. **单头**：客户、供应商、采购单号、客户 PO 号、来源／系统单号、下单／期望／回复日期、业务员、跟单员、币种。窗口缩放时字段换行排列，不横向撑开窗体。
2. **产品与包装要求**：进水管、起泡器、托盘、内盒、标贴、说明书、外箱、包装要求、折扣备注、价格浮动率、价格直接浮动、商标类型、特殊要求、文件地址。详情页的 `LogoType` 标签为“光标”，预览页按字段含义显示为“商标类型”。检查字段名称和分组是否适合采购导入。
3. **采购行**：沿用 .NET 10 采购详情的 19 个列标题，包含图片、SKU、供应商型号、产品单位、数量、未税单价／总价、计划交期、送至供应商、来源单／行及备注。原生 DataGrid 在窗口内横向滚动；图片只有空占位，审批后再决定是否接入 VSTO HTTPS 图片控件。
4. **页脚**：产品行数、订单数量和人民币总额的占位位置。数值口径待数据模型阶段确定。

采购详情页的确认、取消确认、作废、刷新等服务器生命周期操作，以及确认人、复核人、更新时间等历史审计字段，没有放入此导入页面。客户和供应商位置复用 VSTO 本地选择控件的外观，均禁用且不加载缓存；采购产品 Lookup 尚未接入，明细仅保留表头占位。

## 技术边界与验证

文件位于 `Features/Procurement/PurchaseOrders`。Ribbon 经 Bootstrapper 调用 `ModelessElementHostWindowManager` 打开预览，Manager 负责按 Excel HWND＋页面键复用、WinForms `ElementHost` 承载及 Scope 释放；不创建采购专用 Coordinator 或采购 API。XAML 仅使用 VSTO 的 WPF-UI 主题资源与原生 DataGrid，不引用 EnterpriseGrid、.NET 10 控件／转换器或本地图片缓存。后续审批 View 时以实际布局为准，不能把静态占位看作已有功能。

自动检查：使用 Visual Studio MSBuild 构建 Debug／Release；独立 STA 运行 `--purchase-preview-only` 验证页面布局，运行 `--modeless-host-only` 验证实际采购页面在 WinForms `ElementHost` 中打开、重复激活和关闭释放。销售导入专项 `--import-only` 仍需通过，确保页面迁移没有影响销售页。

Excel 实机需检查 Ribbon 在所属 Excel 窗口打开采购预览、多 Excel 窗口各自拥有页面、窗体尺寸和 DataGrid 横向滚动、输入焦点在 Excel 与窗体间切换，以及关闭窗体和插件退出时的释放。自动测试不能代替这些实机验收。

本次验证：VSTO Debug／Release 构建通过；纯托管测试 39 项、采购预览 STA 13 项、非模态窗口 STA 9 项、销售导入 STA 29 项通过。纯托管构建因无法访问 NuGet 漏洞审计服务出现 NU1900 警告。尚未在 Excel 中实机验收。
