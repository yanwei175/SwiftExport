# 地址配置设计与读取说明

## 使用流程

从 Ribbon → SwiftExport → 设置 →“Excel 读取配置”打开右侧窗格；销售及采购导入页也显示同一窗口的同一侧栏，按对应业务组定位。顶部业务组来自 ExcelImportRegistry，各组使用自己的通知模型特性目录；切换分组确认未保存修改，取消保留原组。普通用户在导入页选择配置，维护需要 System.ExcelFieldMapping.Manage（兼容已有授权的历史键，显示为“Excel读取配置维护”）。旧表头别名映射模块和 Ribbon 入口已删除，只使用 ExcelReadProfile／ExcelReadField 地址规则。

配置页整体沿用导入页的顶部操作、单头卡片、明细与底部反馈布局。单头控件输入 A1 地址，点击“获取”通过 Excel InputBox 选择单格或完整合并区域，取消保持原地址。明细 DataGrid 为四列：模型特性字段名称／键、首条明细地址、IsDownward、获取／清除。所有可配置字段由 ExcelImportRegistry 的模型特性生成，空地址表示不配置，不生成空数据库字段。

参考工作表名称只在顶部设置一次，可空，保存时统一写入各字段的 WorksheetName。首次获取地址可补齐参考名称；读取不使用该名称定位工作表。旧配置含多个参考名称时提示统一，保存使用顶部名称。单元格预览仅存在当前页面内存，不保存到服务器，也不写日志。

配置名称、新建、完整快照保存、软删除与重新加载复用现有 IExcelReadProfileApi。更新带 ExpectedVersion；版本冲突保留本地编辑并显示错误，不自动重试覆盖。切换配置、重新加载或删除有未保存修改时确认；读写进行中锁定输入。侧栏 × 或再次点击 Ribbon 仅隐藏，保留未保存编辑与 Scope，重新显示不重置内容；插件退出释放且不提示。确认框 Owner 使用所在 Excel 窗口。客户端未知字段只读显示并保留，保存不静默删除；未知键会阻止本客户端读取。

## 配置字段显示顺序

单头地址卡片和明细地址表格由导入模型的 `ExcelImportField` 特性生成。需要调整顺序时，在对应模型属性的特性上设置 `DisplayOrder`，例如：

```csharp
[ExcelImportField("Header.CustomerPoNo", "客户 PO", DisplayOrder = 10)]
public string CustomerPoNo { get; set; }

[ExcelImportField("Header.Remark", "备注", DisplayOrder = 900)]
public string Remark { get; set; }
```

数字越小越靠前；未设置时默认为 `int.MaxValue`，排在已设置字段之后。同序号按 `FieldKey` 排序，单头和明细各自在自己的区域显示。建议使用 10、20、30 等间隔，方便以后插入字段；`Line.*` 特性也采用相同写法。未识别的旧配置字段继续在末尾只读显示并保留。

修改位置是各业务的 `Models/*ImportHeader.cs` 和 `Models/*ImportLine.cs`（销售、采购、PackingList），不是 XAML 或数据库。修改后重新构建插件并重启 Excel。该顺序仅控制配置页展示，不改变已有地址配置、读取规则、受控赋值或导入页 DataGrid 列顺序；无需更新数据库记录。本次未设置具体业务字段的优先级，原有未设置字段保持按键排序。

## 读取协议

- 单头字段 IsDownward=false，选择存放值的单格或合并单格，只读指定值；不要选择单头标签。明细字段 IsDownward=true，地址为第一条数据的单元格，不是表头，同一起始行。例如第 7 行为表头，第 8 行为首条数据，应配置客户型号 C8、数量 K8 等，读取包含第 8 行，不自动跳过一行。
- 不支持明细字段读取一次后复制到各行；保存前按模型边界校验读取方向。
- EndMode=0 未指定；有明细字段时不能读取。
- EndMode=1 使用 LastRowColumn 最后一个非空且未合并的单元格所在行。指定列通过分块 Value2 从底部查找，跳过所有合并单元格，包括横向合并的合计；没有合格候选时继续查找上一个数据块。包含隐藏与筛选隐藏行，不依赖 UsedRange、Find 或用户查找设置。空结果公式与空白文字不算有值；零和错误值算有内容。仅有值的候选才检查合并状态，完全未合并的块不逐格访问 COM。判断列应选客户型号等未合并的明细专用列；未合并的合计或备注仍会被算入，此时可改用 EndMode=2 明确边界。
- EndMode=2 读取到 SummaryCellAddress 所在行之前。该地址不会自动跟随插行更新。
- 整个确定范围包含隐藏行。全部配置明细字段为空的内部行跳过并提示行号，部分为空保留待修正，空行不作为终止条件。
- 单头合并单元格读左上角；明细同一行内横向合并可读。销售的 Line.NwOfCarton／GwOfCarton／CbmOfCarton 遇到跨行合并合计时，目标字段留空并提示合并地址，原合计值保留在本地 Source.Cells 供核对；不复制到每条明细，也不自动分摊。它们仅作销售快照，本次不新增包装业务或保存校验。PackingList 的箱唛、每箱数量、每箱净重／毛重／体积同样留空提示。数量、型号、价格等其他明细字段仍拒绝跨行合并，错误显示字段键及合并地址；误将纵向合并表头配置为起点仍可能触发拒绝。

一次读取开始时捕获活动工作簿／Worksheet，所有字段使用这一份工作表，图表页拒绝读取。读取单头与明细分别是独立操作。字段区域最多 20 万单元格；LastRowColumn 边界扫描按块最多覆盖该列起始行至 Excel 末行，不计入输出字段快照。COM 在 Excel STA 完成，纯托管转换在后台，UI 接纳、反馈与完成状态显式投递 IUiDispatcher，不依赖 SynchronizationContext。

日期序号遵循工作簿 1900／1904 体系；1900 虚构闰日拒绝转换。当前英文模板日期文本采用 en-US，失败保留来源并允许人工修正。公式读取已有 Value2，不强制重算；公式错误值显示问题。读取得到的原值、字段键和行列保留在 Source.Cells，不能作为身份字段赋值入口。

## 与业务编辑的边界

配置加载与保存不读取 Excel、不覆盖订单。每次实际读取前重新取得已保存详情，重新检查本地字段目录和结构，不仅信任 CanRead。重新读取确认后只替换相应部分：单头保留客户身份与明细，明细不改单头。取消、失败、旧账号或释放后的结果不得回写。

配置服务不存储共享资料缓存；只按需调用 API，启动不预热。成功保存／删除通知仍存活的导入页刷新配置，不自动读取。完整配置预览优先显示首条明细；只有单头配置时显示单头。未保存配置须先保存后预览；获取单个地址可立即显示临时原值。

产品匹配、非标选择、后端检查与新建草稿已接入，见 [销售导入检验与草稿保存说明](销售导入检验与草稿保存说明.md)。配置 DTO 的结构完整不表示订单业务有效，保存须通过当前版本的业务检查。

## 实机验收

1. 新建配置，获取单头与首条明细地址，保存并再次打开核对版本与地址。
2. 验证单头合并区域、两种结束方式、隐藏／筛选行、空结果公式、内部空行、无数据边界。
3. 在另一个工作表读取，确认参考名称不会改变实际来源；图表页应提示不可读取。
4. 人工修改后重新读取并取消，确认原值保留；确认后只替换对应部分。
5. 验证配置变更通知、多个窗口 Owner、InputBox 键盘与取消、关闭未保存确认、退出释放。
6. 所有自动测试均不启动 Excel，不能替代以上实机验收或真实服务器配置读写。

## 读取配置的侧栏宿主

`TaskPaneRegistrar.CreateDefault()` 注册 `excel-read-profile`，首次右侧停靠、宽度 560；用户调整后不覆盖。每个 Excel 窗口按 HWND + 页面键复用独立 Scope。Ribbon 入口调用 `TogglePane`；销售入口调用 `ShowPane`，已显示时保持显示，初始化配置定位只在首次创建时执行。

Bootstrapper 借用 VSTO 的 CustomTaskPanes 创建并拥有 TaskPaneManager，退出先释放窗格页面再释放容器；不创建第二个 WPF 线程，不定时删窗格。配置页去掉 700 最小宽度，单头地址纵向排列，明细四列在窄侧栏中布局。

实机检查：Ribbon 权限与显隐、多窗口独立编辑、隐藏重开保留输入、读取地址时工作表可操作、确认框归属、宽度/停靠调整保留及 Excel 关闭时释放。独立 ElementHost 测试不能替代 Office CustomTaskPane 实机验收。
