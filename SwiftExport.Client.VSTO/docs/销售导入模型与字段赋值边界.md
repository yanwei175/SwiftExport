# 销售导入模型与字段赋值边界

## 当前实现

页面继续绑定 `SalesOrderImportHeader`、`SalesOrderImportLine`，继承 Toolkit `ObservableObject`，手写 C# 7.3 属性通知；不引入 BaseLineModel、BaseListModel 或单据状态机。

模型承载能力、反射字段目录、地址读取、ForExcel 检验及新建草稿保存已接入。旧表头别名配置与解析链路已删除；本次不清理运行数据库的旧映射数据。

手工模型保留今天／USD／数量 1 的默认值；销售汇率已弃用，始终不补默认值。解析时使用 `SalesOrderImportHeader.CreateForImport()` 和 `SalesOrderImportLine.CreateForImport()`：日期、币种与数量初始为空，不能让模板缺失值被默认值掩盖。客户默认值可在明确选择客户后应用；双币种报价独立保留，不换汇。

## 四种数据的归属

| 数据 | 模型位置 | 处理规则 |
|---|---|---|
| 可编辑商业资料 | Header、Line 的通知属性 | 页面与后续受控赋值器写入 |
| 原始单元格 | Header.Source.Cells、Line.Source.Cells | 不可变纯文字、逻辑字段键与一基行列坐标；不得放 Range |
| 未解决解析问题 | Source.Issues | `SetIssues` 显式替换；进入 Error 汇总，人工改值不自动隐藏问题 |
| 后端匹配反馈 | Line.MatchStatus／MatchCandidates／CheckIssues | 接纳后复制为不可变快照，不直接绑定可变响应 DTO |

Source.SetCells 复制来源集合；编辑字段改变不会改写原文。Source.SetIssues 的字符串反馈为首期承载接口，后续赋值器必须保留字段／坐标上下文，不能简单清掉全部问题来放行。

## 已有目录与模型对应

后端手写 `ExcelFieldCatalog` 已删除。VSTO 的 `ExcelImportRegistry` 显式注册销售、采购模型组合，由 `ExcelImportDefinition` 反射读取属性上的 `ExcelImportFieldAttribute`，生成唯一的字段目录和赋值表。`ExcelReadField.TargetFieldKey` 与标记中的稳定键对应，不必等于 CLR 属性名；地址配置 DTO 不承载单据值，不绑定为订单编辑模型。旧 ExcelFieldMappingDto 已删除。

| 当前逻辑字段键 | 编辑模型属性 | 说明 |
|---|---|---|
| Header.InvoiceNo／CustomerPoNo | 同名 Header 属性 | 原单据编号，不代替系统 OrderNo |
| Header.OrderDate | Header.OrderDate | 原表 Date；缺失须补充 |
| Header.Etd／Eta／DeliveryDate | 同名 Header 属性 | 日期转换由后续赋值器负责 |
| Header.ExchangeRate（已弃用） | 不在活动反射目录中 | 旧配置保留，但跳过地址校验、读取、解析与赋值；旧快照原文可保留在 Source |
| Header.Currency／ShippedBy | 同名 Header 属性 | 保存值须明确，保留原表运输文字 |
| Header.ShipToName／ShipToAddress／ShipToPhone | 同名 Header 属性 | 独立编辑快照 |
| Header.Incoterm／IncotermLocation／Remark | 同名 Header 属性 | Terms 不能直接拆成已确认条款 |
| Line.CustomerSku | Line.CustomerSku | 原表 Customer Code，与客户代码组合匹配 |
| Line.DescriptionEn／ColorNameEn／FeaturesEn | 同名 Line 属性 | 保留 Excel 商业快照 |
| Line.Qty／CnyPrice／UsdPrice | QtyText／CnyPriceText／UsdPriceText | 保留非法输入，不能转成零 |
| Line.PcsOfCarton／NwOfCarton／GwOfCarton／CbmOfCarton | 对应 `*Text` 属性 | 可空；数量提供时大于零，重量体积非负 |
| Line.ExpectedDeliveryDate／SubNote | 同名 Line 属性 | 行交期与备注 |

Aquavit Code 在模型中落入 **OriginalLinkSku**，检查请求的 LinkSku 使用这个原值。检查返回中性型号落入 **LinkSku**，真实产品型号落入 **Sku**。反射目录新增 `Line.LinkSku → OriginalLinkSku` 和 `Line.Unit → UnitSnapshot`；后者供非标行补充单位。原销售字段中只有 `Header.ExchangeRate` 退出活动目录，其余字段保持兼容。不能把原表 Aquavit Code 映射到系统 SKU。

OriginalTerms、OriginalUpdateDateText、OriginalAmountText、OriginalCartonsText、OriginalCbmText 保留原文供预览或后续对账，不作为保存字段。发票更新日期改为独立可空快照 `InvoiceUpdateDate`：通过 `Header.InvoiceUpdateDate` 特性配置地址，解析为日期后进入现有销售草稿保存 DTO 和销售单头实体；不参与金额、交期或需求计算。发票日期仍为 `Header.OrderDate`，不另建 InvoiceDate 字段。源金额／箱数／体积不新增落库字段；不通过任意公共 setter 自动开放导入。

## 受控身份与检查接纳

ProductId、CustomerProductId、Sku、系统 LinkSku、MainImage 不提供公共 setter，字段映射不得写入这些属性。

`TryApplyCheck(responseLine, expectedRevision)` 核对 Uid 与行编辑版本，验证标准行产品身份、有效性、SKU 和单位。成功只填写身份／系统型号／单位／图片，不改 CustomerSku、原表中性型号、描述、颜色、配置、数量、价格、包装、交期和备注。多候选状态只展示候选，不自动选第一个。

业务输入变化使 MatchStatus 回到 NotChecked、递增 EditRevision 并清掉旧反馈。型号变化复位差异确认；CustomerSku 改变同时清除原产品身份。`AcceptLinkSkuMismatch` 是下一次检查请求的确认输入，修改它不能直接放行保存。检查错误和未确认提示进入 Error 汇总。

`SetNonStandard(bool)` 保留商业资料与稳定 Uid，清空 ProductId／CustomerProductId、系统中性型号和图片，生成稳定非标编号。转回标准行需重新匹配；非标仍需描述、单位、正数量。页面已提供转换入口，转换后旧搜索与旧检查不能回填。

模型的 EditRevision **仅是行级防护**。页面还核对客户、整单编辑版本、账号会话、页面存活和请求序号；仅有 Matched 不能判定整单可保存。保存须通过当前版本的整单检验，详见销售导入检验与草稿保存说明。

## 字段目录与受控赋值已接入

地址配置侧栏的分组与目标选项来自同一反射目录。后端只验证地址配置自身格式、长度、权限、唯一性、版本和事务，不校验订单业务；见仓库 `docs/Excel单据地址读取配置后端说明.md`。

`TryAssign` 接纳稳定键和单个纯托管值；`TryAssignValues` 接纳一组逻辑键值。旧 TryAssignMappedValues 已删除。销售旧 `Header.ExchangeRate` 直接忽略，不转换、不赋值；其余输入键及存储类型先校验、转换成功后才写属性，同次赋值的重复目标会报错，不静默采用最后一个。

赋值器不读取二维数组、识别单头区域或执行订单业务检查。字符串数值保留原文，由模型判断是否有效；数值对象转换为当前UI文化下的文字，符合模型的数值解析文化。日期文字须由调用方明确指定文化；Excel 数值日期不能直接赋值，快照解析流程需先根据工作簿的1900／1904日期体系转换成 DateTime。当前解析将缺失／转换问题附上来源行号，在页面 ParseMessage 中明确显示，并保留 Source.Cells 原值；不将这些提示永久写入 Source.Issues，以免用户已手工修正后仍被旧提示阻断。Source.SetIssues 留给后续需要显式解决的来源校验，不代替保存前的业务检查。

地址配置快照只读使用、不修改 DTO；除销售已弃用的汇率键外，未知目标或错误模型归属拒绝赋值。配置设计页保留旧汇率配置原文而不提供编辑入口，销售读取时过滤该字段；详见 [销售汇率弃用与验收](../../docs/销售汇率弃用与验收.md)。未配置的图片、统计、银行资料等源内容不任意写模型；已读取值保留来源原文和坐标。整单检查／账号与生命周期保护继续由页面负责。

新增属性和新业务的步骤见 [反射字段映射开发指南](反射字段映射开发指南.md)。目前注册销售与采购编辑模型；未实现的业务不从 DTO 猜测字段目录。

销售与采购均已接入各自的 ForExcel 检验和新建草稿 API；尚需 Excel 实机验证。代码测试通过不代表实际模板与服务器保存已验收。
