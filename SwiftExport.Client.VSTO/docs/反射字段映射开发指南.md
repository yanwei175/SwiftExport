# 反射字段映射开发指南

## 从哪里维护映射

业务人员通过 Ribbon 的“设置 → Excel 字段映射”打开设置页，选择业务组、新增表头别名、选择目标字段并保存。数据库记录的是 `GroupCode + ExcelHeader + TargetFieldKey`；同组规范化表头唯一，不同表头可以指向同一个字段。

后端维护配置，客户端决定哪些属性允许导入。订单客户、产品、数量、价格等业务判断仍由模型及 ForExcel／草稿保存服务承担，映射服务不参与这些判断。

## 给已有业务增加字段

在真实编辑模型的公共属性上添加标记，不再另写字段数组：

```csharp
[ExcelImportField("Line.Qty", "数量")]
public string QtyText
{
    get => qtyText;
    set { if (SetProperty(ref qtyText, value)) NotifyAmounts(); }
}

[ExcelImportField("Line.LinkSku", "中性产品型号（Aquavit Code）")]
public string OriginalLinkSku
{
    get => originalLinkSku;
    set => SetProperty(ref originalLinkSku, value);
}
```

键是稳定配置协议：`Line.Qty` 对应 `QtyText`，`Line.LinkSku` 对应 `OriginalLinkSku`。重命名模型属性不改键；不能随意重命名已有键，否则需要显式处理数据库旧配置。Model 的通知和输入验证仍按 C# 7.3 手写，不使用源生成器。

当前赋值器支持 `string`、`DateTime?` 两种属性存储类型，覆盖现有标记字段。数字通过文本模型保留非法输入，再由模型提供派生数值和错误反馈。不要仅为了导入将 ProductId、CustomerProductId、Sku、Uid、状态或命令标记成可导入；这些字段只通过受控业务方法更新。

目录在启动注册时反射一次，不扫描整个程序集。模型新增标记字段后需重新构建、重新加载插件，设置页就能选择新目标；已有Excel表头关系仍需要用户在设置页配置，不会凭字段名称自动猜表头。

## 新增一种导入业务

先实现有通知属性的单头／明细模型，再在 `ExcelImportRegistry.CreateDefault()` 注册组合：

```csharp
new ExcelImportDefinition("SalesOrder", "销售订单",
    typeof(SalesOrderImportHeader), typeof(SalesOrderImportLine))
```

同一业务注册一次，字段全部从标记生成。注册组码与已有数据库保持大小写一致；查找可忽略大小写，但请求API使用定义的规范组码。组码最长40字符，逻辑字段键最长100字符，只使用ASCII标识或点分隔标识。单头键以 `Header.` 开头，明细键以 `Line.` 开头。重复键、重复组、非公共setter、索引器、非法键或不支持类型在注册时直接报配置错误。

当前生产注册仅销售订单。采购与装箱单历史数据保留，待真实模型完成后再注册；不从传输DTO假造页面模型。新增业务页面的View／ViewModel、DI与Ribbon入口仍需要明确注册，与字段目录生成是独立步骤。

## 接入未来解析流程

Excel读取层先在STA取得二维数组、单元格坐标和日期体系，再将纯托管值交给解析流程。赋值器不持有 Range，不自动识别单头或明细区域。

新地址读取流程应按 TargetFieldKey 把单元格原值交给模型定义（读取接线尚未实施）：

```csharp
var definition = imports.Find("SalesOrder");
var line = SalesOrderImportLine.CreateForImport();
var values = new[]
{
    new KeyValuePair<string, object>("Line.CustomerSku", "AQ4101BG"),
    new KeyValuePair<string, object>("Line.Qty", 64d)
};
string error;
if (!definition.TryAssignValues(line, values,
    CultureInfo.GetCultureInfo("en-US"), out error))
{
    line.Source.SetIssues(new[] { error });
}
```

示例使用稳定目标字段键，不依赖旧表头缓存。日期文化须按来源明确提供，不根据电脑环境猜日期含义。旧 TryAssignMappedValues 仅保留历史兼容。

赋值器规范化配置与源表头，复制启用配置的键，再检查目录和源列冲突。所有键／类型转换成功后才执行setter；未知目标、错误模型、重复配置表头、同次多个源列命中一个目标都拒绝，转换失败不部分写入。模型setter抛异常属于程序错误，不承诺事务式回滚。未配置的源内容不赋值，解析流程须保留原值与来源坐标，并识别必填字段是否缺失。

数值对象转为模型当前UI文化的文字；数字字符串保持原样。非法数值可能赋值成功但模型校验失败，这是为了保留可修正输入，不能将赋值成功当成订单有效。日期字符串使用明确提供的文化，空日期转null；Excel序号日期须先按工作簿1900／1904体系转换为DateTime，赋值器不猜。

Source记录原文和坐标；解析问题经定位后放入Source.Issues。用户修正后应仅解决对应问题，不一键清空所有反馈。页面请求接纳还须核对整单编辑版本、客户、会话和生命周期；反射赋值并不代替这些边界。

## 现有数据与发布验证

原有28个销售字段键保持兼容，另加入 `Line.LinkSku`、`Line.Unit`。未知旧键在设置页显示“不支持”，启用时需修正或停用；停用记录保留，不自动迁移或删除。服务器只存配置，合法格式的键不代表当前客户端支持。

后端已删除目录接口，前后端需要配套更新。旧客户端可能仍调用已移除接口，不应把新后端单独发布后继续使用旧插件。
