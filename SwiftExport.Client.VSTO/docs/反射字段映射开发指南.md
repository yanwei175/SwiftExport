# 模型反射字段与地址读取开发指南

当前仅使用 ExcelReadProfile／ExcelReadField 地址配置。旧 ExcelHeader、NormalizedHeader 表头别名链路已删除；Ribbon 设置入口只保留“Excel 读取配置”。

## 目录来自模型特性

在真实通知模型的公共属性上声明 ExcelImportFieldAttribute。例如 Line.Qty 对应 QtyText，Line.LinkSku 对应 OriginalLinkSku。稳定字段键是配置协议，不必与 CLR 属性名相同；重命名属性不改变已保存的键。

ExcelImportRegistry.CreateDefault 显式注册 SalesOrder 和 PurchaseOrder 的单头／明细组合；ExcelImportDefinition 反射这些模型生成字段目录与可赋值表。新增业务需明确注册模型组合、页面、DI 和 Ribbon，不扫描程序集猜测业务组。

当前支持 string、DateTime? 属性。数字使用文本输入保留非法值，由编辑模型显示校验问题。不要给 ProductId、CustomerProductId、Sku、Uid、命令或检查状态增加导入特性；身份须由业务检查接纳。

## 地址配置维护

通过 Ribbon → 设置 → Excel 读取配置进入右侧栏。管理员选择业务组及配置，单头填写或选择单格／合并格地址，明细配置首行地址与 IsDownward；EndMode、LastRowColumn、SummaryCellAddress 决定向下读取的共同结束边界。

参考工作表名称只在顶部设置一次，可空；实际读取以选定工作表为准并包含隐藏行。数据库保存 TargetFieldKey、CellAddress 等地址配置，不保存表头别名。新增标记属性需重新加载插件，在配置侧栏为该字段设置地址，不会自动猜测 Excel 布局。

## 受控赋值

ExcelAddressReader 在 Excel STA 取得值、坐标和日期体系，生成纯托管快照。SalesOrderAddressParser／PurchaseOrderAddressParser 将地址对应的值交给 TryAssign 或 TryAssignValues；赋值器不持有 Range，也不执行订单匹配或保存。

TryAssignValues 先检查所有稳定键、模型归属、重复目标及存储类型，转换成功后才写属性。数值字符串保留原文；非法数值赋值成功不表示订单有效。日期文字用调用方提供的文化，Excel 序号日期先按工作簿 1900／1904 体系转换。

模型 Source 保留来源坐标、原文与读取问题。修改商业输入后旧检查失效，页面仍须核对整单版本、行版本、请求序号、会话与生命周期；身份匹配及保存资格由 ForExcel 检查和单据保存协议决定。

## 权限与验证

地址配置维护继续使用 System.ExcelFieldMapping.Manage 历史权限键兼容已有角色授权，显示为“Excel读取配置维护”。该键不代表旧 API 仍存在。

本次源码退役不删除运行数据库旧表或数据，也不会把旧表头文字转换成地址。开发验收按 [地址配置设计与读取说明](地址配置设计与读取说明.md) 和 [基础设施验收清单](基础设施验收清单.md) 执行；构建及 STA 测试不能替代 Excel 实机验证。
