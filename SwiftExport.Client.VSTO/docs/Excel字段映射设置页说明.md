# Excel 字段映射设置页

拥有 `System.ExcelFieldMapping.Manage` 权限的登录用户，可从 Excel 的 **SwiftExport → 设置 → Excel 字段映射** 打开非模态 WinForms 设置窗口。窗口内以 `ElementHost` 承载原 WPF 页面，可以保持窗口打开并继续操作 Excel。普通登录用户仍可通过 API 读取启用映射，但 Ribbon 不提供维护入口；服务端始终独立校验保存和删除权限。

窗口使用统一的 `ModelessElementHostForm`。入口传入 1920×1080 作为首选外框尺寸，窗体按所属显示器的可用区域调整初始大小，并统一 DPI 自动缩放模式、边框和浅色背景；用户仍可手动调整尺寸。多显示器不同缩放比例下的实际观感须在 Excel 中检查。

页面首次打开才加载分组目录。选择分组后读取该组的目标字段目录与全部映射（包含停用项）。Keyword 只在本地筛选表头、目标字段和备注；保存提交当前分组已加载的全部行，筛选隐藏的行也会提交。切换分组遇到未保存修改时，可选择保存、放弃或取消。

“新增表头别名”允许多个不同 Excel 表头指向同一目标字段。新行必须填写真实表头；初始化脚本产生的空表头行可继续保持停用，填入表头后再启用。目标字段选项标出创建、更新适用性，尤其要注意采购字段并非都可用于草稿更新。保存由后端单次事务处理新增和更新；未提交的行不自动删除。已有行的“删除”立即逐条调用删除 API，本地未保存的新行直接移除。

保存或删除成功后，页面刷新该分组的启用映射缓存，供后续导入使用；缓存刷新失败时页面会提示“服务器已保存，但缓存刷新失败”，不要把它当作数据库回滚。登录身份变化会清空页面内容，需要点击“重新加载 / 重试”。同一 Excel 窗口重复点击 Ribbon 只激活现有设置窗口；关闭窗口或退出插件时释放页面 Scope、ViewModel 与请求生命周期。

上线前须部署字段映射表结构及 `SwiftExport.Infrastructure/Database/Excel字段映射初始数据.sql`。自动构建和独立 STA 测试不能代替 Excel 实机检查：应验证多窗口入口归属、Ribbon 权限显示、设置窗口输入框的连续键盘编辑、在 Excel 与设置窗口之间切换焦点、切组确认和窗口关闭后的资源释放。这个宿主调整用于验证 Excel 是否仍会抢键盘输入，不能仅凭静态检查宣称问题已解决。
