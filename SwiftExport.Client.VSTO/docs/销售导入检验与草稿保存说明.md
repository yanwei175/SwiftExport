# 销售导入检验与草稿保存

## 图片与发票更新日期快照（2026-10-10）

明细图片列只读绑定匹配／产品选择回填的 `MainImage`，使用 `HttpsImage` 和缩略图放大提示样式。控件支持完整 HTTPS 及本地绝对路径／file URI，显式采用 TLS 1.2，只缓存有上限的内存缩略图；不解析 Excel 嵌入图片、不建立磁盘缓存，非标行或无图片时留空。详见 [图片控件说明](客户与销售产品选择控件.md)。

发票日期继续使用 `Header.OrderDate`。可空的发票更新日期使用 `Header.InvoiceUpdateDate`，在 Excel 读取配置中设置值单元格地址，也可在导入页手工填写；空值不补当前日期，非法日期保留来源原文并提示。该字段通过现有销售草稿 API 保存为销售单头快照，详情返回及 .NET 10 编辑模型回传均保留，不参与金额、交期或需求计算，也不增加必填或日期大小校验。

已有业务库须先人工执行 [PostgreSQL 增量脚本](../../SwiftExport.Infrastructure/Database/PostgreSQL销售发票更新日期快照.sql)，再更新后端及客户端，详见 [部署说明](../../docs/销售发票更新日期快照.md)。本次只生成脚本，未访问或迁移业务库。

## 当前闭环

读取地址配置 → 按配置读取单头与明细 → 手工修正 → 检验与匹配 → 处理提示并再次检验 → 保存新草稿。

销售导入仍由非模态 WinForms + ElementHost 窗体承载，可同时操作 Excel。本次新增销售草稿写入能力；历史文档中的“只读”“保存未实现”不再描述当前销售导入页。采购预览及其他页面不因此获得保存能力。

## 复用接口与身份

- 检验：`IForExcelSalesOrderApi.CheckAsync`，`POST /api/for-excel/sales-orders/check`。
- 保存：`ISalesOrderDetailApi.SaveAsync`，`POST /api/sales-orders/detail/save`。没有新增 ForExcel 保存接口。
- 两步均需 `Sales.Order.Maintain`。前端只控制按钮体验，实际权限及业务有效性仍由后端决定。
- 新订单头 `Uid=Guid.Empty`、Version=0，订单号由服务器生成；已有订单候选的 Uid 绝不进入新建请求。明细 Uid 在页面创建时生成并保持稳定。
- `CheckSalesOrderImportRequest` 只负责检验输入；`SaveSalesOrderRequest` 负责完整草稿命令。保留两个既有契约，不合并页面万能 DTO；2026-10-10 的销售汇率弃用同时调整共享契约及后端校验。

## 匹配和编辑

人民币单价／金额列只在单头币种为 CNY 时显示，切换币种不清除价格快照；每箱数量与每箱体积始终显示。数量可解析且小于等于零时显示和编辑文字均为红色。

网格上方工具行展示数量、箱数、毛重及体积汇总：每行箱数＝数量÷每箱数量，不向上取整；毛重／体积＝箱数×对应每箱快照。缺失、非法或溢出的行值不计入对应统计，并显示“包装汇总不完整”；显示格式不改变内部精度。这些统计不用于库存、履约或保存门禁。

销售单头读取只覆盖本次地址配置实际读取的字段，未配置字段保留客户默认资料和人工输入，包含币种、付款方式、贸易术语、交期等；已配置单元格为空时仍清除对应值。客户、订单日期／Date 和币种标签使用红色星号，InvoiceNo 保留原有红色星号。

点击“匹配处理”列头可按 `IsCheckPassed` 排序：升序将未校验通过的行集中在前面，降序将通过的行集中在前面。排序仅改变网格显示顺序，不改原始明细集合或行身份；匹配状态改变后，再点击列头重新排序即可。

客户代码来自选定客户；明细 CustomerSku 是原表 Customer Code，OriginalLinkSku 是原表 Aquavit Code。检查结果回填 ProductId、CustomerProductId、真实 Sku、系统 LinkSku、单位和图片，数量、价格、描述、颜色、配置、交期及备注保留人工/Excel 输入。

“匹配处理”模板列显示简短校验状态和“匹配 SKU”按钮，按钮传入所属行对象，无须先选择网格行。“处理”开关打开本行 Popup：显示客户型号、Excel／系统中性型号、候选 SKU、差异确认及详细反馈。多候选须选择一个可用候选，再点击“应用候选（需重新匹配）”；随后点击弹层“匹配本行 SKU”或顶部“检验与匹配”重新请求。不得默认取第一条。原表型号和系统型号不一致时，核对两者后勾选确认，再次匹配／检验。修改型号或产品选择使对应确认失效。关闭弹层保留输入；支持关闭按钮、Esc、外部点击及入口重复切换，行模板卸载时关闭弹层，不再使用 RowDetailsTemplate。

明细工具栏保留“匹配全部 SKU”，原“匹配选中 SKU”及对应命令退出，改为模板列的 MatchLineSkuCommand（行参数命令）。全部／单行匹配复用既有 ForExcel 检查接口，仅接纳请求范围内的行匹配结果；每次最多 500 行。单头资料未完成不阻止独立产品匹配，未选客户、未获维护权限、读取／检验／保存期间禁止匹配；单行命令必须传入本页尚未删除的行，空参数不得误执行全部匹配。网格选中状态仅继续用于删除，不决定单行匹配目标。局部匹配不弹重复订单确认，也不接纳服务器返回的整单 CanSave。执行独立匹配后保存资格失效，保存前仍须顶部整单检验，不能用若干次行匹配替代。

类型与行类型处理合并为“非标件”模板列：勾选执行受控非标转换，取消则回到待匹配标准行；不直接写 ProductId。原匹配状态列改为行头红绿圆点：未检查、匹配失败、多候选、型号差异未确认或行输入无效均为红色；本行后端检查通过且本地无错误时为绿色，非标行也须检查通过。详细原因显示在匹配处理 Popup，圆点提示提供文字说明；绿色不代表整单可保存。顶部检查反馈采用红色文字，底部完整校验保留限高滚动。

Popup 通过 PlacementTarget 显式连接行 DataContext 和页面命令，复用 ImportHeaderPopup 的关闭／Esc／卸载处理，不创建新的编辑模型。行按钮 Loaded／DataContextChanged 在 DataBind 完成后仅刷新命令资格，解决虚拟化或客户切换造成的旧禁用状态；不在视图中执行业务 API。专项验证：20 项销售提交测试、26 项 STA 交互断言通过，VSTO Debug／Release 构建通过；Excel 实机效果仍待验证。

### 客户币种与废弃汇率

VSTO 客户选择使用按需加载的客户缓存，缓存通过 `ICustomerApi.GetPagedAsync` 获取 `CustomerDto`。客户 DTO 的 `Currency` 回填订单币种，不提供汇率。销售订单仅管理价格快照，主要从 Excel 导入；USD/CNY 单价及金额分别保留，不按汇率推导另一币种。

销售 `ExchangeRate` 已弃用：页面汇率输入框及反射字段目录退出，`Header.ExchangeRateText` 仅兼容旧内存调用，不解析、不校验、不参与检查版本或请求组装。检查与草稿请求不提供汇率，也不补 1。旧 `Header.ExchangeRate` 地址配置不读取、不赋值，即使原值为空、零、负值或非法文本也不产生销售错误；配置页不再创建其编辑器，保存其他字段时原样保留记录。仅有废弃地址时跳过读取，保留当前销售输入。

后端检查忽略兼容汇率；普通销售草稿保存也不校验、不接纳该输入。新建留空，更新保留既有数据库值；查询契约保留可空历史值。币种主数据 `RateToBase`、采购及其他业务规则保持原有行为。详见 [销售汇率弃用与验收](../../docs/销售汇率弃用与验收.md)。

“切换标准/非标”仅作用于按钮所在行：显式转非标清除产品身份，保留商业值，要求描述和单位；切回标准须重新匹配。匹配失败本身不会自动转换。

服务端返回 Success=true 只表示检查请求成功，只有 CanSave=true、响应客户/行身份完整一致、逐行通过且当前输入版本未变化，才允许保存。检查最多 500 行，不能分批检查后假称全单有效。

单价和包装数字允许空白，非法非空文本在前端阻断，不能悄悄变成 null。汇总中空单价的提示不等于保存必填单价。原表 UpdateDate、Amount、CTNS、CBMS 只供核对，不写入草稿请求。

## 重复订单

后端按客户及非空发票号/PO 返回已有订单。确认框列出系统单号、商业编号、状态及 Uid；默认取消。明确同意后发送补充确认的检查请求，不自动保存，不更新已有订单。修改资料使整单检查与重复确认失效，需重新检验。

检查只是当次只读快照，不是锁或保存凭证；服务器草稿保存仍执行事务内校验。

## 保存、重试与页面生命周期

- 检验或保存期间锁定输入、读取入口和普通关闭，取消在途产品搜索；全部 UI 接纳回到宿主 STA。
- 修改活动单头、明细、行类型或增删行后，整单检验版本失效；废弃汇率兼容文本变化不影响资格。旧请求同时核对会话、页面存活、整单版本、行序列和逐行版本，不回填旧账号/已删行。
- 首次保存复制完整请求并生成 CommandId。明确业务拒绝保留编辑，允许修正后重新检验；不自动重放写请求。
- 断网、超时、无确定回执、COMMAND_BUSY、SERVICE_UNAVAILABLE、OUTCOME_UNKNOWN 保留原请求并锁定输入，用户用“重试原保存请求”重发完全相同的请求及 CommandId。曾经未知后权限/限流拒绝不证明原操作未提交，仍保留原请求。
- 成功只展示回执中的系统单号和 Uid，并锁定当前页面，避免再次新建同一份输入。“开始新导入”清空输入，不复用已保存明细或命令身份，不进入既有单据维护。
- 原请求仅保存在当前页面内存；结果未知时普通关闭提示 CommandId 和无法安全重试的后果。用户仍关闭、账号切换、登出或 Excel 退出后不持久化该请求，重新导入前须先核实服务器订单，避免重复。
- SaveAsync 当前没有取消参数；HTTP 使用现有明确超时，页面释放/换号通过请求身份拒绝迟到回执，不声称取消客户端能撤销服务器写入。

## 验证与实机步骤

自动测试仅使用内存替身，不连真实服务器、不加载 Office。真实验收需使用开发环境：

1. 登录具备维护权限的账号，读取配置及真实工作表，核对单头、全部明细与报价。
2. 检验唯一匹配、多候选、未匹配及非标转换；对比原表型号、系统 LinkSku 和真实 Sku。
3. 修改已通过检验的值，确认保存立即禁用；再次检验后才开放。
4. 同客户同发票/PO 测试重复提示的取消和继续新建；不得覆盖原单。
5. 保存后到客户端/数据库核对新草稿、稳定行身份和商业值，仅验收人员查询，不由插件直连数据库。
6. 模拟保存超时，用原请求重试，核对仅生成一张订单；未知时关闭或换号前记录 CommandId 并核实结果。
7. 核对请求期间 Excel 可操作、Owner/焦点、多次打开复用、普通关闭确认、登出清空及退出释放。

未完成上述 Excel/真实 API 验证前，不标记为可发布。
