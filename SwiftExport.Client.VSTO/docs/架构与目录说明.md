# VSTO 基础架构

## 定位

这是 .NET Framework 4.8、C# 7.3 的 Excel 插件。WPF 和宿主位于一个程序集，通过目录约束依赖。后续主要做只读单据查询、Excel 制单与少量导入；服务器业务门禁仍由 WebApi 执行。禁止直接连接数据库。

当前根工程总纲中“VSTO 已移除”的描述已过期，本目录以实际工程和本说明为准；未改变 .NET 10 客户端规则。

## 目录职责

| 目录 | 职责 |
|---|---|
| Bootstrapper | 显式读取配置、启动和停止、自有资源清理 |
| Ioc | 唯一服务注册入口，页面使用构造函数注入 |
| Hosting/Threading | 捕获 Excel STA，投递 UI／COM 操作 |
| Hosting/Windows | Owner、同键窗口复用、关闭 Scope |
| Hosting/TaskPanes | 读取配置、销售与采购列表侧栏的 Config／Registrar、Manager、Context 与 ElementHost 桥接；销售/采购导入页不使用 |
| Hosting/Windows | 非模态 WinForms 窗体与 WPF ElementHost 承载、Excel Owner 和页面 Scope 释放 |
| Authentication | 内存会话、加密 Token、候选登录、登录页面 |
| Api | Refit 创建、请求授权头、错误分类 |
| Services/Caching | 当前账号的共享基础资料内存缓存；首次使用加载、显式刷新、会话变更清理 |
| Mvvm | ViewModelBase 和项目扩展层 ViewModelBaseEx |
| Excel/Context | 从 Ribbon 获取所属 Excel 窗口 |
| Excel/Reading、Writing | Reading 在 Excel STA 选择区域并取得纯快照；Writing 预留 |
| Resources、UI/Themes、Assets | WPF 主题资源、预留主题扩展与素材 |
| Features/DocumentGeneration、DataImport | 预留业务目录，无空白页面入口 |
| Diagnostics | 有界日志，只记录固定事件与异常类型 |

## 生命周期和线程

Excel Startup 初始化服务、WPF 资源字典和已创建句柄的调度控件；缓存身份验证在后续消息轮次异步运行。WPF 和 Excel 共用 STA，不创建第二个顶层消息循环。资源承载 Application 采用 OnExplicitShutdown，但插件绝不调用 Application.Shutdown 或 Dispatcher.InvokeShutdown。

WindowManager 区分 Show 与 ShowDialog。需要同时操作 Excel 的工具使用 Show，Scope 随 Closed 释放；登录和切换账号使用 ShowDialog，不注册非模态键盘互操作。LoginCoordinator 在返回后的 finally 中释放 Scope、复位 IsOpen，显示失败和取消也经过同一路径；重复入口在 IsOpen 时被阻止。模态消息循环仍允许异步 HTTP 请求，禁止 Result／Wait。TaskPaneManager 按 MateExcel 示例使用 HWND＋页面标识缓存，点击时切换 Visible，不再定时清理或比较 COM 窗口引用。隐藏保留内容；再次访问已失效实例时清理重建，插件停止统一释放 Scope，窗格集合由 VSTO 最终销毁。

网络层不触碰 UI。状态通知可能来自网络线程，由 Bootstrapper 投递到 Excel STA 后更新 Ribbon。未来页面异步结果在 UI 接纳时核对页面存活及请求编号；不能通过 Task.Run 访问 COM。

## MVVM

继承链：Toolkit ObservableObject → ViewModelBase → ViewModelBaseEx → 页面。

ViewModelBase 仅提供标题、Busy、错误、命令刷新和 Dispose。ViewModelBaseEx 是未来增删项目行为的唯一扩展入口，首期不加空扩展点。Toolkit 的源生成器被排除，禁止 ObservableProperty、RelayCommand 特性和 partial property。手写属性使用 SetProperty，命令使用库的 RelayCommand／AsyncRelayCommand。

## 身份与配置

`vsto.config.xml` 随插件输出，ApiBaseUrl 默认 https://localhost:7286。部署时改成受信 HTTPS 站点根地址，不关闭证书验证，不读取或修改 Excel.exe.config。

实际配置从插件程序集所在目录读取，启动后不会热更新；源码配置由构建复制到输出目录。HTTPS 未指定端口时使用 443。登录的通用网络提示不能区分证书、TLS、代理、连接失败或超时，需要查看 `%LOCALAPPDATA%/SwiftExport/Vsto/Logs/addin.log`。启动记录 `ApiEndpoint` 的主机和端口；异常记录最多八层类型、HResult、WebException 状态及 Socket／Win32 错误码，HTTP 传输失败同时记录 Excel AppDomain 当下的 TLS 设置。日志不输出异常消息、请求正文、密码、Token 或完整响应，不改变宿主 TLS 或证书验证设置。更新诊断程序集后须保存工作簿并完整退出、重开 Excel 再复现；独立进程连通不等于 Excel 内请求成功。

启动有缓存时调用 /api/auth/me；没有缓存不发认证请求。只有验证成功才建立身份。Ribbon 登录、切换、退出均为显式入口，恢复时不弹窗。

本插件认证与业务 HTTP Handler 显式使用 TLS 1.2，保留平台证书验证。原因是实机曾记录 Excel AppDomain 的全局 SecurityProtocol 为 Ssl3、Tls，HTTPS 请求以 SecureChannelFailure 失败；不通过修改 ServicePointManager、Excel.exe.config 或注册表影响其他插件。诊断中的 SecurityProtocol 仍表示宿主全局值，不能据此误判本插件 Handler 未使用 TLS 1.2。未来服务器协议要求改变时需重新验证传输策略。

2026-10-08 验证：Debug／Release 构建通过，错误诊断及认证专项 17 项通过（NuGet 审计源不可达 NU1900）。独立 .NET Framework 进程模拟宿主 Ssl3、Tls，加载实际 Debug 插件并调用未携带身份的 `/api/auth/me`，服务器返回 401，且全局协议保持原值，证明插件连接可完成 HTTPS 握手；此结果不等于 Excel 内用户名密码登录验收，需重启 Excel 后再次验证。

切换使用独立候选令牌和 /me，成功才提交；取消、失败保留原账号。会话版本递增使旧请求无法回填或通过 401 清掉新账号。403 不退出，网络失败不删缓存，不自动重放写请求。

Token 按服务器 SHA256 分目录，在 LocalApplicationData/SwiftExport/Vsto 下 DPAPI CurrentUser 加密；命名互斥锁保护原子替换。多个 Excel 进程的内存身份互不自动同步；退出清理共享磁盘缓存不等于远端撤销 JWT。没有 Refresh Token 协议，过期需重新登录。密码不绑定到模型、不持久化。

Contracts 当前认证方法没有 CancellationToken 参数。关闭用生命周期令牌阻止迟到接纳，传输由超时结束，插件停止释放自有连接。该限制不等于可以让旧请求更新已关闭窗口。

## 新增一个功能

采购已接入地址读取、本地编辑、ForExcel 检验及独立采购草稿创建，见 [采购订单导入页说明](采购订单导入预览页说明.md)。原静态预览说明已被当前实现取代。

基础资料优先注入 `IReferenceDataCacheService`，接入与数据编辑边界见 [基础资料缓存接入说明](基础资料缓存接入说明.md)。Excel Startup 和登录成功不预热资料；需要手动补充的导入字段放在页面独立 Model，不修改缓存 DTO。

1. 在 Features/具体功能 下按 Views、ViewModels、Models、Services 放文件，传统 csproj 必须登记新增 Compile／Page 项。
2. ViewModel 继承 ViewModelBaseEx，注入 API 和所需宿主接口，不用 Globals 或服务定位器。
3. 在 Ioc 注册页面 Scope；Ribbon onAction 调用宿主入口，再交给 WindowManager。业务功能增多后再提取窄协调器，不把业务塞入 Bootstrapper。
4. 服务端 DTO 留在 Contracts；Excel 模板、列宽、坐标和打印设置留在具体 Feature。
5. 读取 COM 得到纯数组后才能后台计算；写回前重验目标，不重新使用 ActiveWorkbook 猜目标。
6. 按权限键控制按钮体验，服务端授权仍为最终依据。新增业务 API 从 ApiClientRegistration.Create 创建。
7. 补充功能对应测试和 Excel 人工验收，不迁入大型 CRUD 行状态框架。

## WPF-UI 主题和资源生命周期

Resources/Themes.xaml 是运行时与设计器共用的主题入口；先加载 WPF-UI Light、Controls，再加载项目颜色与字体。WpfRuntimeHost 在 Excel STA 创建或借用 Application，显式合并字典，不需要另建 App.xaml。

WPF-UI 4.3.0 的 UiApplication 只按顶层 Wpf.Ui 字典识别 Application。公共包装字典不会被它识别，因此 ThemeService 显式连接 UiApplication.Resources 与 Application.Resources，并暂时关闭库的隐式强调色初始化。否则颜色可能进入库的私有字典，窗口仍读不到。

WpfRuntimeHost 在 Excel STA 手动创建 App，App 构造函数显式调用 InitializeComponent 加载 App.xaml，再由 ThemeService 调用 ApplicationThemeManager.Apply(ApplicationTheme.Light, WindowBackdropType.None)。App.xaml 使用 Page 构建，不生成 Main 或第二个消息循环；已有 Application 时只追加本插件资源并初始化 Light，不替换他人的资源根或全局主题。主题固定 Light，不监听系统主题、不切换 Dark／高对比度；强调色在初始化时取系统色并补齐 Primary 的颜色／文字别名，不启用 Mica／Acrylic。卸载恢复自有根资源和 WPF-UI 入口，不调用 Shutdown。

Primary 普通、悬停、按下背景依赖 AccentFillColorDefault／Secondary／Tertiary（Color），不能只补同名 Brush。禁用模板实际读取 ButtonBackgroundDisabled／ButtonForegroundDisabled／ButtonBorderBrushDisabled。兼容覆盖集中在 ThemeService，不复制控件模板。

官方强调色 API 写入 Application 根资源。服务记录实际变更的原值与最后写入对象，释放时只恢复仍由自己持有的键，保留后来者改写的键；随后恢复 UiApplication 资源入口与自动强调色设置。窗口、窗格先关闭，再释放主题资源。Application 与 Excel Dispatcher 保持存活；同一个 WpfRuntimeHost 释放后不能再次初始化。初始化失败回滚自有字典及强调色写入。

Properties/DesignTimeResources.xaml 通过 ContainsDesignTimeResources 向设计器提供同一主题及最小强调色预览值，运行时不引用它。设计器预览、独立 STA 验证与 Excel 实机属于三种不同证据。

实现依据：[WPF-UI 4.3.0 UiApplication](https://github.com/lepoco/wpfui/blob/4.3.0/src/Wpf.Ui/UiApplication.cs)、[按钮模板](https://github.com/lepoco/wpfui/blob/4.3.0/src/Wpf.Ui/Controls/Button/Button.xaml)。升级包时重新验证资源和宿主行为。

## 样式复用边界

### 统一字体

正文字体集中在 `Resources/Typography.xaml`，首选顺序为 `Microsoft YaHei, 微软雅黑, Microsoft YaHei UI, 微软雅黑 UI, Segoe UI, Arial`，缺少某字体或字形时由 WPF 按序回退。`SwiftExportFont` 是页面主入口，已有 `SwiftExportFontFamily`、`UserFontOrder` 保留相同顺序。Typography 在控件字典之后加载，普通及命名 TextBlock 样式统一字体。字号、字重和控件模板沿用原设置。

WindowManager、ModelessElementHostForm、TaskPaneHostControl 在承载根页面时绑定 `SwiftExportFont`，子控件继承，避免 ElementHost 的 WinForms 默认字体决定页面外观；新增页面不必重复声明字体。显式特殊字体及 WPF-UI 图标字体保留。不修改全局字体属性元数据，也不向其他插件写入字体根资源。设计器通过现有 DesignTimeResources 加载同一字体资源与文字样式；具体页面输入控件的设计预览不等于实际 ElementHost 承载效果。

2026-10-09 验证：统一字体 STA 专项覆盖资源回退顺序、普通／命名文字、派生页面、原生与 WPF-UI 输入框、下拉和 DataGrid、两个 ElementHost 宿主字体变化、独立 WPF 窗口及图标／特殊字体例外。Excel 实机需重启后检查页面外观和布局。隐式样式专项仍失败于既有“合并顺序保留项目只读无边框覆盖”，没有删除或放宽断言。

资源迁移清单、兼容性调整及 DataGrid 示例见 [样式迁移说明](样式迁移说明.md)。订单导入预览当前采用 API 只读匹配、前端数据组织和目标 DTO 组装，暂不引入编辑行／列表的 CRUD 状态机。样式不承担数据加载、匹配或选择同步行为。

销售订单本地导入预览已接入 Ribbon，页面编辑、只读搜索与生命周期边界见 [销售订单导入页说明](销售订单导入页说明.md)。本期不保存服务器草稿，不解析 Excel。

## 原生控件隐式样式

TextBoxes.xaml 的原生 TextBox 和 ui:TextBox 分别直接继承 WPF-UI 的 DefaultTextBoxStyle、DefaultUiTextBoxStyle，不在覆盖隐式键时再以同一类型键作为基样式。DatePicker 的紧凑样式继承 DefaultDatePickerStyle，内部 DatePickerTextBox 继承 DefaultDatePickerTextBoxStyle，保留已有紧凑模板。DatePicker 的官方资源依赖会导入 TextBox，因此项目 TextBoxes.xaml 在 DatePicker.xaml 之后合并，保证只读覆盖仍优先。

隐式样式测试必须检查实际模板，而不只检查 Style 非空：错误继承时 Style 可以存在，但 BasedOn 为 null，控件仍回退到系统模板。`--implicit-only` 验证原生 TextBox／DatePicker 和 ui:TextBox 的模板、x:Type 资源引用、官方初始化、固定 Light 与资源释放；`--design-resources-only` 检查设计资源装载，不代表 Visual Studio 设计器进程已经实测。

### 当前非模态窗口与预留任务窗格

Ribbon 销售和采购导入入口均通过 `ModelessElementHostWindowManager`，在触发操作的 Excel 窗口打开 `ModelessElementHostForm` 非模态 WinForms 窗体，使用 `ElementHost` 承载 WPF 页面。两页首选尺寸均为 1280×820，设置页首选尺寸为 1920×1080；窗体按所属显示器可用区域调整初始尺寸、统一 DPI 自动缩放模式与边框外观，避免固定像素尺寸在高分屏显得过小或在小屏幕越界。同 Excel HWND、同页面键重复打开只激活原窗体。用户关闭销售页且有编辑内容时可取消，确认后释放页面 Scope；插件退出不弹确认。业务 ViewModel 不接触 COM。Excel 混合 DPI 跨屏效果仍须实机验证。

销售、采购导入不登记到 `TaskPaneRegistrar`；关闭时释放各自 Scope，插件退出时先关闭窗体再销毁容器。导入页确认框使用 Scope 内的 `ModelessWindowContext` 归属对应窗体。地址配置使用右侧任务窗格，见 [地址配置说明](地址配置设计与读取说明.md)。旧字段映射设置页已删除。Excel 键盘焦点仍需实机验证，见 [销售导入说明](销售订单导入页说明.md)、[采购导入说明](采购订单导入预览页说明.md)。

### 注册新的侧边栏页面

`Hosting/TaskPanes/TaskPaneConfig` 保存页面标识、标题、ViewType、DefaultWidth 和 DockPosition；配置只描述页面，注册时不创建 UI 或请求 API。当前侧边栏支持 `Dock.Left`／`Dock.Right`，默认右侧。

`TaskPaneRegistrar.CreateDefault()` 是侧栏配置入口，当前注册 excel-read-profile（右侧默认宽度 560）、sales-order-list 和 purchase-order-list（两者右侧默认宽度 720）。销售、采购导入均使用非模态窗体，不在此注册；两者共用读取配置侧栏，由页面确认分组切换。列表侧栏见 [销售订单列表侧栏说明](销售订单列表侧栏说明.md)、[采购订单列表侧栏说明](采购订单列表侧栏说明.md)。

新增页面步骤：

1. 在 ServiceRegistration 注册 scoped View、ViewModel 和页面服务。
2. 在 TaskPaneRegistrar 增加稳定标识与配置，例如 `new TaskPaneConfig("customer-query", "客户查询", typeof(CustomerQueryView), 420, Dock.Left)`（示例类型需自行实现并注册）。
3. Bootstrapper 已创建并持有 `TaskPaneManager`；由 Ribbon 回调转交 Bootstrapper 调用 `taskPanes.TogglePane(context.GetWindow(control), 页面标识)`，保留登录和页面权限门禁。不要为仅打开页面再复制专用 Coordinator。

Manager 统一检查登录，在未命中已有窗格时创建 Scope，先设置该 Scope 的 TaskPaneContext，再解析页面。需要确认框的视图服务注入 TaskPaneContext 作为 IWin32Window Owner；业务 ViewModel 不接触句柄。重复打开不创建 Scope、不重置用户尺寸。页面 × 仅隐藏；再次访问失效实例或插件停止释放 Scope 及上下文。销售页无需专用 Coordinator。

侧栏统一注册时期的历史验证：当时 Debug／Release 构建、纯托管测试及销售／采购 STA 预览通过。采购现已迁至非模态窗体，本段不再描述当前接线；Excel 实机仍需验证窗口归属与输入焦点。

配置职责与边界：

| 类型 | 负责内容 |
|---|---|
| TaskPaneConfig | 不可变元数据：Id、Title、ViewType、DefaultWidth、DockPosition |
| TaskPaneRegistrar | 集中注册和查询配置；重复 Id 抛错，不静默覆盖 |
| TaskPaneManager | 登录检查、按窗口与 Id 复用、首次创建 Scope／页面、停靠与宽度、失败清理及最终释放 |
| TaskPaneContext | Scoped 的 IWin32Window Owner；页面创建前赋值，Scope 结束清除 |
| TaskPaneHostControl | WinForms／ElementHost 桥接，释放时断开 WPF 可视树 |

配置的 ViewType 必须为非抽象 WPF UIElement，并在 DI 中注册为 Scoped；DefaultWidth 必须大于零。配置仅支持初始左／右停靠，不支持顶部／底部高度配置。注册不会预加载资料；首次显示后由页面自己的初始化入口按需加载。修改默认尺寸只影响后续创建，已存在的窗格不会被重新设宽。

普通侧栏页面新增配置和 DI 注册即可接入，不需复制页面专用 Coordinator。LoginCoordinator 管理模态登录流程，与任务窗格注册无关，继续保留。

## 历史销售窗格生命周期（按 MateExcel 示例）

本节取代前文历史记录中“每 1.5 秒核对窗口”“实际窗口关闭即释放 Scope”和“重复点击仅显示”的描述。现已删除 Timer／Reconcile 和 COM 窗口引用比较，按 HWND＋页面标识缓存实例。Ribbon 调用 TogglePane 切换 Visible；首次创建设置尺寸，复用保留尺寸和内容。宿主先创建 ElementHost 并加入 Controls，再 LoadWpfUI。
