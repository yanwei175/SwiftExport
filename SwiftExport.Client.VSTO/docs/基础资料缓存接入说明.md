# 基础资料缓存接入说明

## 用途与范围

`Services/Caching/ReferenceDataCacheService` 从 .NET 10 客户端的同名服务迁移，适配 net48、C# 7.3 和 VSTO 的登录会话、Excel STA 调度。它是插件单例，供销售、采购及后续其他导入共用。

| 数据 | 读取方式 | 首次加载入口 |
|---|---|---|
| 客户、供应商 | 当前用户可见的全部分页，每页 200 条 | `EnsureLoadedAsync` |
| 产品颜色、分类 | 全量；分类保留树和共用节点的扁平集合 | `EnsureLoadedAsync` |
| 启用币种 | 独立币种 API | `EnsureLoadedAsync` |
| 字典类型、字典值 | 非删除资料；保留停用值供历史展示 | `EnsureLoadedAsync` |
| 活动仓库候选 | 独立分页 | `EnsureWarehouseSitesLoadedAsync` |
| Excel 表头字段映射 | 按 `SalesOrder`、`PurchaseOrder`、`PackingList` 等业务组读取启用项 | `EnsureExcelFieldMappingsLoadedAsync(groupCode)` |

沿用原服务的整体刷新和逐类刷新方法。`RefreshAllAsync` 的范围与 `EnsureLoadedAsync` 相同，仓库及字段映射始终独立按需加载、刷新。不包含产品图片缓存、磁盘资料缓存或后台定时刷新。

## 加载时机

采用用户确认的**首次使用时加载**。Excel Startup、恢复登录、登录成功和切换账号都不触发基础资料请求。DI 构造和解析缓存也不请求网络。

页面在异步初始化或用户打开选择器时注入并调用 `IReferenceDataCacheService`。不要在 ViewModel 构造函数、Ribbon getter 或 Excel Startup 中调用加载方法，更不能使用 `.Result`／`.Wait()`。

```csharp
// 页面异步初始化中的接入片段；cache 由构造函数注入。
var result = await cache.EnsureLoadedAsync();
// 回到页面 UI 后还须核对页面生命周期和初始化时捕获的会话版本。
if (!result.Success)
{
    // 将 result.Message 交给当前页面的 ErrorMessage；允许用户重试。
    return;
}
// 下拉候选绑定 cache.Customers、cache.Currencies 等稳定集合。
// 只有需要仓库选择器时，才 await cache.EnsureWarehouseSitesLoadedAsync()。
```

导入解析需要字段映射时，先 `await cache.EnsureExcelFieldMappingsLoadedAsync("SalesOrder")`，成功后调用 `cache.GetExcelFieldMappings("SalesOrder")` 取得独立快照。采购、装箱单分别传 `PurchaseOrder`、`PackingList`。配置变更后可调用 `RefreshExcelFieldMappingsAsync(groupCode)`；刷新失败仍可读取当前账号的旧快照。将 Excel 表头与配置比较时使用 Contracts 的 `ExcelHeaderNormalizer.Normalize`，本次缓存接线不负责把数组转换为 DTO。

重复、并发的首次加载共用进行中的任务；成功后不重复请求，失败后再次调用可重试。需要主动更新时调用对应 `Refresh...Async`。全量加载保持原服务语义：任何一类失败就不接纳本次完整快照。只需要单类资料的入口可调用对应刷新方法，避免因无关资料的读取权限失败而阻断当前操作。

## 会话、线程与失败

- API 通过 `ApiClientRegistration.Create<T>("api/控制器前缀")` 创建；长期 HttpClient 共用认证处理器，超时 30 秒。缓存仅调用读取方法（客户、供应商的 POST `/page` 是查询），不会调用保存接口。
- 刷新按队列串行执行，基础资料的可观察集合通过 `IUiDispatcher` 发布；每次单集合替换发出一次 Reset，集合对象本身不更换，绑定和枚举应在 UI 线程进行。字段映射不提供可观察集合，按组在锁内替换快照，调用方取得 DTO 副本。
- 换号、退出、当前账号 401 会立即使加载标记和未完成请求失效；字段映射快照同步清空，基础资料集合清理投递到 Excel STA。之后仍等首次使用才加载。旧请求、旧排队操作和释放后的结果不能发布到新会话。
- 403、网络失败、分页提前结束或缺失数据返回失败并保留同一会话已有快照。缓存不代表权限凭据，也不是离线业务保证；服务端仍执行每次请求的门禁。
- 分类的孤立、自引用和循环父链节点提升为根，避免无法显示或无限递归。字典通过 `GetDictionaryValues(code)` 默认筛选启用项，需要历史展示时传 `enabledOnly: false`。
- 所有资料只存当前 Excel 进程的内存，不跨进程同步。关闭页面不会销毁共享缓存；插件退出时 DI 释放订阅及 API 连接，迟到结果被拒绝。

## 允许手动补充的导入资料

缓存 DTO 是候选参考资料，**页面不得直接修改缓存中的 DTO**。`ReadOnlyObservableCollection` 只能限制集合增删，不能使 DTO 属性只读。

Excel 解析失败后的客户选择、币种选择、数量或其他允许补充字段，存入当前导入页面的独立 Model（手写 Toolkit 通知属性），用选中候选的 ID 和必要字段构造目标 DTO。更改页面数据不会修改共享候选，也不会自动保存到服务器。

页面关闭、账号切换后应阻止旧页面异步结果更新；共享缓存清空不会自动清除页面已经复制的候选或导入草稿，页面必须按自己的会话边界重置或关闭。缓存不包含 BaseLineModel／BaseListModel、CRUD 行状态机、EnterpriseGrid 或图片服务；后续已接入的无磁盘缓存 HTTPS 图片见 [客户与销售产品选择控件](客户与销售产品选择控件.md)。

## 验证边界

`ReferenceDataCacheTests` 使用真实 Contracts Refit 代理、模拟 HTTP 和可控 UI 队列，覆盖懒加载、并发、路由、授权头、分页、失败保留快照、分类树、清理、账号切换、401／403、释放和迟到发布。测试不连接真实 API，不加载 Excel。

实际页面接入后仍须在 Excel 检查：启动及登录无资料请求；首次打开能提示加载与失败；手动选择不污染其他页面；刷新后绑定正常；切换账号后旧草稿按页面规则清理。图片不属于本次验收范围。
