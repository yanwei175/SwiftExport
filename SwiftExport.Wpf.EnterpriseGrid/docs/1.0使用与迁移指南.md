# Enterprise Grid 1.0 使用与迁移指南

## 1. 迁移原则

现有页面无需替换 `DataGrid`。文本和数值列继续使用 `DataGridTextColumn`；ComboBox、CheckBox、图片和自定义编辑器统一使用 `DataGridTemplateColumn`。先为需要跨模块识别的列设置稳定 `GridColumn.Key`，再逐项启用功能。

```xml
<DataGridTextColumn Header="SKU"
                    gridColumns:GridColumn.Key="sku"
                    gridColumns:GridColumn.FieldPath="Sku"
                    Binding="{Binding Sku, UpdateSourceTrigger=PropertyChanged}" />
```

`FieldPath` 对原生 `DataGridBoundColumn` 可由简单 `Binding.Path` 推断；TemplateColumn、远程筛选、布局持久化和导出建议显式设置。ColumnKey 一旦写入用户布局或远程查询契约，就应视为稳定 API。

## 2. 选择、原生编辑与 Excel 操作

- FullRow 以 SelectedItem 为当前行；Cell/CellOrRowHeader 以 CurrentCell.Item 为当前行并回写 `GridSelection.CurrentRow`。
- Extended 多选时 CurrentRow 仍是唯一活动 Cell 所在行；完整范围保留在原生 SelectedCells，不用集合替代 CurrentRow。
- 宿主可用 `GridSelection.IsCurrentCell` 区分活动 Cell：选区使用浅强调色背景，活动 Cell 使用强调色边框。
- EnterpriseGrid 不接管双击、F2、Enter、Tab、Shift+Tab 或 Esc，全部沿用 DataGrid、Column 和编辑器原生行为。
- Selection 不在 `PreviewMouseLeftButtonDown` 阶段预写 `DataGrid.CurrentCell`；跨 Cell 单击先由原生 `DataGridCell` 完成选择与焦点切换，子控件点击后备同步只在冒泡末端执行，因此不会为同一次鼠标事件额外触发编辑。
- `GridOperations.IsEnabled=True` 后，Ctrl+Z 撤销最近一次已提交 Cell、整次粘贴、整次填充或整次清空；Ctrl+C/Ctrl+V 使用 Excel 兼容 TSV 在连续矩形 Cell 选区间复制粘贴；Ctrl+D 按矩形选区逐列向下填充；Delete 可原子清空选中的可编辑 `DataGridTextColumn`，并支持不连续 Cell 选区。
- Ctrl+D 只处理连续矩形，跳过只读、隐藏和无可写路径的列。普通 Template/Lookup 列可设置 `GridColumn.FieldPath` 参与单字段填充；同时维护 ID、代码、名称等关系的复合 Lookup 应设置 `GridColumn.FillDownFieldPaths="Id,Code,Name"`，框架会把这些字段作为一个逻辑 Cell 原子填充和撤销。复合元数据只服务 Ctrl+D，不会让该列参与 Grid 级 Copy/Paste/Delete。
- `GridColumn.CanFillDown="False"` 可禁止整列填充，默认 `True`，不改变编辑、Copy/Paste/Delete。逐行限制使用 `GridColumn.CanFillDownPath="CanEditSupplier"`：这是目标行上的布尔属性路径，不是列的 DataContext Binding；可使用点分隔的嵌套路径。未配置时保持原行为，配置后只有读取到布尔 `true` 才允许填充，false/null/路径错误/非布尔值/读取异常均跳过目标 Cell。全部目标受限时命令不可用，不生成撤销记录。
- 模板内控件的 `IsEnabled`、`IsReadOnly` 不会被自动扫描。请让 `CanEditSupplier` 与控件的可编辑条件保持一致，例如编辑器设置 `IsEnabled="{Binding CanEditSupplier}"`；只读条件需取反，多个限制可合并为行模型的一个布尔属性。这样屏幕内外的虚拟化 Cell 采用同一规则，不从上一行或已回收的控件推断状态。仅在控件上硬编码只读而不配置填充许可，不会自动阻止 Ctrl+D。
- 填充仍以矩形顶行作为来源，不要求来源行的许可为 true；逐个目标 Cell 判断并跳过，不改变选区、不改用相邻行作为来源。许可在每次执行前重新读取，并在本次批量写入前快照，保证复合字段整体填充；所有实际改动仍可一次撤销。
- Grid 级 Ctrl+C/Ctrl+V/Ctrl+D/Delete 只在 `SelectionUnit=Cell/CellOrRowHeader` 时可用；FullRow 下 Undo 仍保持可用，当前编辑器自身的文本编辑和剪贴板命令不受影响。Delete 选区若混入只读列或 Template/CheckBox/ComboBox/Lookup 等非文本列则整次拒绝；字符串清为 `string.Empty`，可空/引用类型清为 `null`，非可空值类型恢复默认值。Paste 遇到只读列、无可写 FieldPath、越界或类型转换失败时整次拒绝。页面可使用 `GridSelectionUnitConverter` 将 bool ToggleSwitch 映射为 FullRow/CellOrRowHeader，非法值默认回退 FullRow。

需要行勾选和表头全选时，页面直接使用原生 `DataGridTemplateColumn`：HeaderTemplate 内放置绑定列表全选状态的 CheckBox，CellTemplate 内放置绑定行选择状态的 CheckBox，两者按页面需要直接设置对齐。该方式不约定 IsChecked/IsAllChecked 属性名，也不建立会参与测量的 Border、Viewbox、Padding 或 Margin 包装。列应显式设置 `CanUserSort=False`；Item Binding 使用 TwoWay 与 PropertyChanged，Header Binding 使用 TwoWay。

业务页面禁止使用原生 `DataGridComboBoxColumn` 和 `DataGridCheckBoxColumn`。ComboBox 与 CheckBox 必须放进 `DataGridTemplateColumn`；文本、数字仍优先使用 `DataGridTextColumn`，视觉通过 `ElementStyle/EditingElementStyle` 调整。模板列若参与 Ctrl+D、筛选或导出，必须显式设置 `GridColumn.FieldPath`；需要特殊导出显示值时设置 `GridColumn.ValueAccessor`，不得扫描可视控件。

`GridRowHeader.ShowRowNumber=True` 使用当前 DataGrid 视图顺序显示一基行号，不读取或写入业务 RowIndex，也不会修改宿主的 `RowHeaderWidth`。客户端命名样式默认使用紧凑的 32 DIP，页面可显式覆盖；排序、筛选、增删和虚拟化回收后会重新编号。自定义 RowHeaderTemplate 时必须让 `DataGridRowHeader.HorizontalContentAlignment=Stretch`，否则模板只按最小内容宽度布局，即使 RowHeaderWidth 足够，多位数也会被裁剪。

### 2.1 单据行上移/下移

需要保留 WPF-UI 默认 RowHeader 外观时，可改用独立行号列：

```xml
<DataGrid gridCore:EnterpriseGrid.IsEnabled="True"
          gridCore:GridRowHeader.ShowRowNumberInColumn="True" />
```

`ShowRowNumberInColumn` 默认 false；启用后在最前方插入标题为“行号”的普通只读文本列，初始宽度 48 DIP，数字右对齐，可拖动调整列宽，禁止该列排序和拖动换位，不参与填充、导出及筛选。它沿用宿主单元格和列头主题，不改写 RowHeaderStyle、RowHeaderTemplate 或 RowHeaderWidth，也不写业务字段。排序、筛选及容器回收后复用当前视图的一基行号。与 `ShowRowNumber` 同时开启时列模式优先，RowHeader 恢复原内容；关闭列模式后按 `ShowRowNumber` 设置恢复。关闭功能或卸载时只移除框架自己的列。页面原有业务“序号”列不会被自动删除。

`DataGridLineReorder` 为原生 DataGrid 动态注入一个紧凑的上移、下移命令列。框架只把当前行作为 CommandParameter 转发，不读取 `LineNumber`、不修改 ItemsSource，也不调用业务服务。

```xml
<DataGrid ItemsSource="{Binding Lines.Items}"
          CanUserSortColumns="False"
          gridCore:EnterpriseGrid.IsEnabled="True"
          gridOperations:DataGridLineReorder.IsEnabled="True"
          gridOperations:DataGridLineReorder.MoveUpCommand="{Binding MoveLineUpCommand}"
          gridOperations:DataGridLineReorder.MoveDownCommand="{Binding MoveLineDownCommand}" />
```

ViewModel 使用实际业务集合索引执行移动，并在移动后按单据自己的规则重新生成 LineNumber。当前 `BaseListModel.Move(line, newIndex)` 内部使用 `ObservableCollection.Move()`，支持 `AcceptChanges()` 接纳新顺序和 `RejectChanges()` 恢复上次接纳顺序，但不会替业务决定 1、10 或其他编号步长。

```csharp
[RelayCommand(CanExecute = nameof(CanMoveLineUp))]
private void MoveLineUp(OrderLineModel? line)
{
    var index = line is null ? -1 : Lines.Items.IndexOf(line);
    if (index <= 0)
    {
        return;
    }

    using (Lines.SuppressListEvents())
    {
        Lines.Move(line, index - 1);
        ResetLineNumbers();
    }

    SelectedLine = line;
}

private void ResetLineNumbers()
{
    for (var index = 0; index < Lines.Items.Count; index++)
    {
        Lines.Items[index].LineNumber = index + 1;
    }
}
```

下移命令使用同一模式，只把目标索引改为 `index + 1`，并在 `CanExecute` 中要求 `index < Lines.Items.Count - 1`。命令还应组合页面的 Busy、写权限和只读状态，并在集合、选中行或页面状态变化时调用生成命令的 `NotifyCanExecuteChanged()`。

- 默认列宽 56 DIP、DisplayIndex 为 0、Header 为空。
- DataGrid 只读时默认隐藏；设置 `ShowWhenReadOnly=True` 后显示为禁用。
- `CanUserSortColumns=True`，或当前 ICollectionView 存在 SortDescriptions、CustomSort、Filter、GroupDescriptions 时，按钮禁用且不清除用户视图。
- 操作按钮不参与 Tab 焦点，列始终只读，不会触发 Cell 编辑或接管 DataGrid 原生编辑按键。
- 查询单据行仍应按持久化的 LineNumber 排序；新增、删除、保存前的行号维护属于业务 ViewModel/Application 职责。

### 2.2 向下填充开关与 ViewModel 配置

两个属性都是配置输入，Grid 不会修改它们或回写 ViewModel；不需要 `TwoWay`。

| 配置 | 作用范围与取值来源 |
|---|---|
| `CanFillDown` | 列级布尔开关，默认 true；可设常量或显式源的 OneWay Binding |
| `CanFillDownPath` | 目标行对象上的布尔属性路径字符串，默认 null；每次执行前从各目标行重新取值 |

**逐行限制（推荐）：** 将路径写在列上，让模板内编辑器共享同一个行级可编辑状态。

```xml
<DataGridTemplateColumn Header="供应商"
                        gridColumns:GridColumn.Key="supplier"
                        gridColumns:GridColumn.FillDownFieldPaths="SupplierId,SupplierCode,SupplierName"
                        gridColumns:GridColumn.CanFillDownPath="CanEditSupplier">
    <DataGridTemplateColumn.CellTemplate>
        <DataTemplate>
            <TextBox Text="{Binding SupplierName, Mode=TwoWay}"
                     IsEnabled="{Binding CanEditSupplier, Mode=OneWay}" />
        </DataTemplate>
    </DataGridTemplateColumn.CellTemplate>
</DataGridTemplateColumn>
```

此处 TextBox 仅演示状态接线，实际页面保留既有 Lookup 等编辑器及其对象选择逻辑，不代表允许直接编辑供应商名称来修改关联关系。控件若使用 `IsReadOnly`，应与 `CanEditSupplier` 取反后的条件保持一致；同时存在禁用、只读等限制时，行模型应合并这些条件。

`CanEditSupplier` 必须属于 `ItemsSource` 中的行对象，而非仅存在于页面 ViewModel。Grid 已从所选 Cell 获得目标数据项，不需要按字符串寻找 ViewModel 或控件；字符串只用于读取该数据项的属性。例如 `Permissions.CanEditSupplier` 表示从目标行读取 `Permissions`，再读取其 `CanEditSupplier`。支持点分隔属性路径，不是完整 WPF Binding 语法，不支持在路径里写 Converter、ElementName 或 RelativeSource。

**列级绑定页面 ViewModel：** DataGridColumn 不自动继承 DataContext，不能直接假设 `{Binding AllowSupplierFillDown}` 能找到页面。SwiftExport 客户端可复用已有 `BindingProxy`（`resourceProxies` 映射到 `clr-namespace:SwiftExportClient.Resources.Proxies`）：

```xml
<!-- 放在页面的 UserControl.Resources 中 -->
<resourceProxies:BindingProxy x:Key="FillDownViewModelProxy" Data="{Binding}" />

<!-- 放在 DataGrid.Columns 中，可与逐行许可同时使用 -->
<DataGridTemplateColumn Header="供应商"
                        gridColumns:GridColumn.FillDownFieldPaths="SupplierId,SupplierCode,SupplierName"
                        gridColumns:GridColumn.CanFillDown="{Binding Data.AllowSupplierFillDown,
                            Source={StaticResource FillDownViewModelProxy}, Mode=OneWay,
                            FallbackValue=False, TargetNullValue=False}"
                        gridColumns:GridColumn.CanFillDownPath="CanEditSupplier" />
```

`AllowSupplierFillDown` 是页面 ViewModel 的布尔属性，`CanEditSupplier` 是每个行对象的布尔属性。两层许可均允许且原有只读/字段可写检查通过时才填充。页面和行模型按既有 CommunityToolkit MVVM 规范发布属性变更通知，保证控件绑定及时更新；Grid 的行级许可值不缓存，每次填充重新读取。

通常让 `CanFillDownPath` 保持固定字符串。它本身也可绑定，但绑定值必须是路径字符串（如 `"CanEditSupplier"`），不能写成 `CanFillDownPath="{Binding CanEditSupplier}"` 来传布尔值。动态路径也需要显式源；路径绑定失败应回退到非空无效路径以禁止填充，不能回退为 null/空白，因为空路径表示不附加行级限制。

**找不到属性时：** 路径字符串没有编译期成员检查，重命名、拼写/大小写错误、嵌套对象为 null 都可能导致读取失败。已配置非空路径时，只有实际布尔 true 放行；false、null、非布尔值（包括字符串 `"True"`）、缺失属性和 getter 异常均跳过目标 Cell。框架当前不弹出路径错误提示，也不会自动改用页面 ViewModel 查找。不要把“路径错误时禁止”与“未配置路径时不限制”混淆。

接入后至少检查：一行允许、一行禁止时只填允许目标；状态反转后结果同步反转；路径拼错时不写入；滚动到屏幕外的目标也遵守许可；复合字段填充后一次 Undo 恢复。字符串路径重命名需同步修改 XAML，并保留对应回归测试。

## 3. 验证与业务行状态

`GridValidation` 聚合 WPF `ValidationRule`、`IDataErrorInfo`、`INotifyDataErrorInfo` 和行级错误。业务错误通过 `GridCellValidationState` 显示细边框和 Tooltip，不使用 `ValidatesOnDataErrors` 阻止用户离开 Cell；保存命令再执行硬校验。强类型转换失败仍由 WPF 原生提交事务处理。错误引用只包含 Item、ColumnKey 和文本，不缓存虚拟化 Cell。

业务 Added/Modified/Deleted/Unchanged 仍由业务 Model 拥有。客户端使用 Trigger、Converter 或 Selector，把它映射到 `GridRowPresentation` 的画刷、字形和可访问文本。框架没有 `GridRowState`。

当前 SwiftExport 的删除逻辑会把 Deleted 行移出可见 `Items`；是否保留墓碑行或提供撤销面板是业务列表决策，Grid 不伪造已移除数据。

## 4. Numeric、ComboBox 与 Lookup

`NumericDataGridColumn` 继承 `DataGridTextColumn`。它不拦截输入法或中间文本，只在原生提交点校验格式、范围和小数位。

枚举或静态选项列使用 `DataGridTemplateColumn + ComboBox`。候选源使用 `x:Static` 或稳定的应用资源，业务值使用 TwoWay Binding；页面卸载、重建和候选源初始化不得把空值回写到业务模型。

`LookupDataGridColumn` 分离：

- `SelectedValueBinding`：业务 ID，通常 TwoWay。
- `DisplayBinding`：已有显示字段，可选。
- `ItemsSource/ItemsSourceBinding`：本地候选。
- `Provider/ProviderBinding`：远程 `IGridLookupProvider`。
- `SelectedValuePath/DisplayMemberPath`：候选值与显示路径。

远程编辑器支持取消、去抖、最少搜索字符、空结果、错误文本和已保存 ID 回填。Provider 由 ViewModel/Service 实现并负责 API 调用；Grid 不访问后端。

需要 `LookupTextBox` 一类自定义 Popup 时，使用原生 `DataGridTemplateColumn`：显示模板只放轻量 TextBlock，`CellEditingTemplate` 注入自定义 Lookup。编辑控件只在当前 Cell 进入编辑后生成。列头按钮或筛选入口直接使用原生 `DataGridColumn.Header/HeaderTemplate`，不增加框架专用列头体系。

## 5. Filter、Grouping 与 FilterRow

页面必须显式选择：

- `GridFilterMode.Local`：组合并保留现有 `ICollectionView.Filter`，不复制集合。
- `GridFilterMode.Remote`：只向 `RemoteFilterCommand` 发送 `GridFilterRequest`，命令负责去抖、取消、最新请求获胜和 API 错误。

`GridFilterSet` 是快照化描述，使用 ColumnKey、FieldPath、操作符和值。筛选前默认提交 Cell 与 Row；失败时 `LastApplySucceeded=False`，当前编辑和视图不移动。`GridFilterRow` 只组合原生 TextBox，不替换 Header/Column 模板，并跟随动态可见性、顺序、宽度和水平滚动。

## 6. ColumnChooser 与布局持久化

`GridColumnChooser` 是纯原生 `StackPanel`，可以直接放入 WPF-UI `ContentDialog` 的内容区域。它不依赖 WPF-UI。

`GridLayout.State` 保存：可见性、DisplayIndex、宽度单位、排序方向/优先级及 FrozenColumnCount。宿主把该状态序列化到用户配置即可；框架不写磁盘。恢复规则：

- 未知 Key 忽略并返回在 `IgnoredColumnKeys`。
- 新列保留页面默认值。
- 重复 Key、重复/负 DisplayIndex、未来版本和非法宽度明确失败。
- 当前编辑验证失败时不应用布局。

## 7. 导出

导出分两步：

1. UI Dispatcher 调用 `GridExport.CreateRequest`，按当前视图、全部数据或选中行捕获稳定值快照。
2. 将请求交给 `CsvGridExportProvider` 或 `XlsxGridExportProvider` 写入宿主提供的 Stream。

导出从数据项和列元数据读取，绝不扫描 DataGridRow/DataGridCell。TemplateColumn 没有 FieldPath 或 `IGridValueAccessor` 时按选项跳过或报错。CSV 默认防护公式注入；XLSX 文本始终写为 inline string，不生成公式。XLSX 目前支持单工作表、文本、数值、布尔和日期，不提供图表、公式、图片或复杂样式。

文件选择、覆盖确认、WPF-UI Dialog/Snackbar 和错误通知属于宿主 UI Service，不属于 Grid Provider。

## 8. 虚拟化与性能

`GridVirtualization.IsEnabled=True` 可恢复地启用：

- `EnableRowVirtualization=True`
- `EnableColumnVirtualization=True`
- `VirtualizingPanel.IsVirtualizing=True`
- `VirtualizationMode=Recycling`
- `ScrollViewer.CanContentScroll=True`

框架不缓存 Row/Cell 容器。WPF Recycling 可能让已回收 Cell 暂留在内部视觉 Children 中，但它们不属于 realized 视口；不要用“可视树节点总数”作为列虚拟化指标。

这是 UI 虚拟化，不是数据虚拟化。十万级远程数据仍应由业务查询实现分页/增量加载；Grid 不复制或自动分页业务集合。

## 9. 生命周期与线程

- DataGrid、附加属性、布局捕获和导出请求快照必须在所属 Dispatcher 线程调用。
- Provider 写流可异步执行；取消后宿主应丢弃不完整文件。
- `Unloaded`、禁用或 ItemsSource 替换会解绑模块事件、数据错误订阅和延迟 Dispatcher 操作。
- 功能关闭后恢复原生行为或原始 View Filter/虚拟化配置。

## 10. 版本兼容

1.0 公共 API 遵循向后兼容原则。新增列元数据和枚举值优先追加；ColumnKey、布局版本及远程 descriptor 属于持久化契约。破坏性调整必须提升主版本并提供迁移说明。
