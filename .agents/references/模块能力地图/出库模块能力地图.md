# 出库模块能力地图

> **2026-09-16 采购确认职责修正：** 采购确认只校验采购事实并锁定订单、允许入库；不读取完整 BOM、不创建新 BOM 确认节点、不绑定消耗仓，也不要求首次确认存在历史快照。已有确认快照仅作历史查询。草稿建立的未释放 Link 阻断需求回退；取消确认不释放，删行或作废才释放。客供件消耗归 PackingList 正式出货过账，实际仓和数量届时确定；跨供应商用料先调拨，禁止任意仓扣减。该自动消耗、选仓与调拨接线尚未实现。本轮不新增分解快照表。


> 核对日期：2026-09-16。本次按用户已确认并实施的手工库存出库方案同步；不新增业务决策，不代表共享数据库或真实桌面联调已经验收。
>
> 本文将手工库存凭证与 PackingList 销售交付分开。手工 StockIssue=22 是独立库存动作；PackingList 自动出库由 PackingList 专用命令编排。
>
> **需求退出交接：** PackingList/正式客户出库是 GrossDemand 的交付事实，未反向时阻断销售、售后来源取消确认；其反过账只恢复库存并撤销正式交付贡献，不自动反向入库、采购或物料。手工 StockIssue=22 及其反过账不计来源履约，也不改变来源取消资格。

## 1. 使命与边界

出库保存库存扣减事实，不负责需求分配、采购进度、客户交付归属或 PackingList 装柜编辑。

- 手工库存出库独立于 PackingList：StockIssue=22，TriggerPackingListId 为空。
- 手工出库不计入销售、售后结案或来源需求交付；这些领域的交付依据归 PackingList，不从手工库存出库推测。
- 最终客户发货仍只能由 PackingList 内部编排创建；手工入口不能伪装客户发货。
- 所有库存写入调用统一库存内核，不直接更新余额或删除原流水。
- 不开放负库存放行、部分反向、实际退货或已反过账单重新过账。

## 2. 事实与字段归属

| 对象 | 当前职责 | 边界 |
|---|---|---|
| OutboundDocument | 仓库、单号、类型、日期、出库原因、备注、状态与审计，保留 TriggerPackingListId | 手工单触发字段为空；不承担客户交付归属 |
| OutboundDocumentLine | 产品历史快照、数量、头行身份、CommandItemId、OriginalLineId | 不承担 GrossDemand 履约归属；自动行通过原始业务依据追溯 |
| InventoryBalance | 仓库与产品键下的当前库存投影 | Picker 参考量，不是本次出库数量，不被草稿预占 |
| InventoryLedgerEntry | 原类型22负向流水、类型900反向流水及反向关联 | 不可覆盖；原流水精确证明后才能整单反向 |
| PackingList | 销售交付及上游履约依据、自动出库编排 | 不把手工出库数量当客户已发货量 |

历史不可证明的来源不按单号、SKU 或相同数量补关联。当前产品名称、单位不用于重算历史反向事实。

## 3. 当前页面与交互

| 页面 | 已实现动作 | 限制 |
|---|---|---|
| OutboundManagerView | 查询、分页、头行详情、手工草稿增改删、正向预览/过账、整单反过账 | 每单一个仓库；已过账和已反过账只读 |
| OutboundItemPickerView | 按所选仓库搜索和分页选择正库存产品 | 不查需求或采购；排除本单已有产品 |
| 出库原因补填弹窗 | 保存前逐张补填缺失原因 | 必填且最多500字；已有原因不覆盖 |
| 正向/反向预览弹窗 | 展示库存影响和阻断项；反向独立填写原因 | 预览不预留库存，不允许修改恢复数量 |

- 新选产品的本次数量留空，必须人工填写正数，最多四位小数；重复选择不覆盖已填数量。
- 有明细时不能直接切换仓库；已保存单需先清空并保存。
- 保存先验证数量，再补齐全部待保存单据的缺失原因，之后才发送首个草稿命令。中途取消不发送草稿，已确认原因与其他编辑保留。
- 后端草稿契约仍允许历史空原因；客户端补填不等于新增数据库非空约束。过账始终要求合法出库原因。
- 结果未知时冻结并重试原命令；成功响应后的详情失败只重读当前单，不丢弃其他草稿。
- 专用出库 Trace、PackingList 自动编排不属于本次手工切片的已完成能力，不能因历史文档存在相关名称就视为可用。

## 4. 状态、权限与事务

状态为 Unposted=0 → Posted=1 → Reversed=8。反过账后保留原单只读；重新出库必须新建，不恢复草稿。

- 查询和草稿沿用库存模块访问权限；正向预览/提交另需 Inventory.Outbound.Post。
- 反向预览/提交同时要求库存模块访问权限和 Inventory.Outbound.Reverse，不以 Post 权限替代。
- 仅活动、未删除、已过账的手工22且无 PL 触发关联可以整单反向。
- 每条有效行必须唯一对应类型22负向原流水，核对头行、CommandItemId、仓库、产品、单位和数量；缺失、额外、重复或已有反向/纠错关联均阻断。
- 提交按命令锁和日志重放、头行锁及版本检查、原流水重验、统一内核反向、单头审计和操作日志的顺序，在同一 Application 事务完成。
- 反向生成类型900正向恢复流水，ReversalOfLedgerId 指向原流水，来源仍指向原出库头行；不新增反向出库单。
- 原过账信息、原出库原因和原流水保留；反向原因独立必填且最多500字，历史原出库原因为空不单独阻止合法反向。
- 库存不足阻断正向过账；反向缺失/删除的余额投影阻断，主数据历史边界沿用库存内核。库存或日志失败整体回滚。

## 5. 当前 API、DTO 与实现入口

基址 api/inventory/outbounds，接口 IOutboundManagerApi；Application 为 IOutboundManagerService/OutboundManagerService，仓储为 IOutboundManagerRepository/OutboundManagerRepository。

| 用例 | HTTP 与路径 | 专用契约 |
|---|---|---|
| 列表 | POST /search | OutboundManagerSearchRequest、OutboundManagerListItemDto |
| 详情 | GET /{uid} | OutboundManagerDetailDto、OutboundHeaderDetailDto、OutboundLineDetailDto |
| 库存选择 | POST /items/search | OutboundItemSearchRequest、OutboundItemCandidateDto |
| 草稿新增/更新/删除 | POST /drafts、PUT /drafts/{uid}、POST /drafts/{uid}/delete | Create/Update/DeleteOutboundDraftCommand、OutboundDraftCommandResult |
| 正向预览/提交 | POST /{uid}/post-preview、POST /{uid}/post | OutboundPostPreviewRequest/Dto、PostOutboundCommand、OutboundPostResult |
| 反向预览/提交 | POST /{uid}/reverse-preview、POST /{uid}/reverse | OutboundReversePreviewRequest/Dto、ReverseOutboundCommand、OutboundReverseResult |

Contracts 保持 netstandard2.0、公开类型独立文件；前端编辑状态由 OutboundHeaderModel/OutboundLineModel 承担，结构映射使用 Mapster。旧 Workspace API、DTO、Service、Repository 与页面不再作为当前入口。

## 6. PackingList 自动出库边界

手工 StockIssue 与 PackingList 自动出库是两条独立入口，共用库存内核，但不共用编辑和命令：

- 手工出库的 TriggerPackingListId 为空，只表达库存扣减，不计 GrossDemand 正式交付。
- PackingList 最终客户出库与客供件消耗由 PackingList 最外层事务生成，头保存 TriggerPackingListId。
- 最终客户出库行以 PackingListLine 为原始业务依据；客供件消耗行以 PackingListConsumptionDetail 为原始业务依据。
- 一条业务依据对应一条库存行，不合并丢失来源。
- 手工出库 Manager 不得查询、编辑、过账或反向 PackingList 自动单据。
- 非标 PackingList 行不生成出库或库存流水。
- PackingList 整单反向由 PackingList 命令编排，先反向最终客户出库和客供件消耗，再反向本单自动入库；不能用手工出库反向代替。

出库只记录库存事实。GrossDemand 的正式交付净额由有效已过账且未反向的 PackingList 行负责，不能从出库单再次推导另一套履约数量。客供件库存不足或最终出库会造成负库存时必须阻断。
