# 出库模块能力地图

核对日期：2026-10-21。本文描述当前工作树实现，不沿用旧阶段计划或以历史测试代替当前验收。业务判断以所列服务、实体和实际调用方为准；新增业务规则须另行确认。全部 HTTP 入口见[业务 API 索引](../../../docs/业务API索引.md)，跨域主线见[业务总纲](../业务架构总纲.md)。

## 职责与事实

OutboundDocument、OutboundDocumentLine 保存库存出库事实。类型明确区分 FinalCustomerShipment、CustomerSuppliedConsumption、StockIssue；手工普通出库不贡献客户正式交付。

## 当前能力

| 能力 | 实现 | 边界 |
| --- | --- | --- |
| 候选、列表、详情 | OutboundQueryService | IOutboundManagerApi；OutboundManager、OutboundItemPicker |
| 草稿保存、删除 | OutboundDraftService | 人工 StockIssue；原因、仓库/产品/单位及版本校验 |
| 过账预览、过账 | OutboundPostingService | 活动、未过账、无 TriggerPackingListId 的 StockIssue；库存不足拒绝 |
| 反向预览、反向 | OutboundReversalService | 对原库存事实形成受控反向，保留历史与来源 |
| 最终客户出库及客供件消耗 | AutomaticPostingPorts | PackingList 整单命令、共享父事务，不经手工页面操作 |

## 权威边界与限制

客户正式交付以有效已过账且未反向的 PackingList 行聚合，最终出库只提供对应库存证据；不得从任意 StockIssue 推断订单已交付。自动出库由 TriggerPackingListId 标明归属，必须跟随箱单整单反向。已发货的实际退货是另一个业务事件，不等同于撤销错误过账；当前不能根据反向按钮推断具有完整退货业务。

页面读取、新建、编辑、删除、过账和反向分别校验对应权限；客户端按钮状态不是最终准入判断。Preview 不预占库存，Post 重验令牌、版本及真实可用数量。


## 出库管理交互与查询契约

- 出库类型、过账状态使用多选集合；集合为 null 时兼容旧单值，为空时不限，集合内取并集、字段间取交集。计数与分页使用相同筛选，关键词最多 200 字符。
- `POST /api/inventory/outbounds/warehouses/search` 使用出库查看权限读取有效仓库候选，不要求仓库管理查看权限；客户端复用现有仓库选择界面。
- 保存草稿不改变库存。保存过的明细即使已在本地全部删除，也须先保存空明细，才能换仓并重新获取产品。空草稿允许保存，过账仍须有效明细。
- 字段编辑和写入命令统一受对应权限、单据状态、版本冲突及待恢复命令限制；结果未知时保留原账号、原 CommandId、ExpectedVersion 和载荷，禁止其他账号重发。
- 删除后保留仍存活的选择；选中行被删时，按当前显示顺序优先选择上一幸存行，再回退下一行，集合为空时选择为 null。
