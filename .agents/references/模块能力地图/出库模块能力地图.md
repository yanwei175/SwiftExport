# 出库模块能力地图

核对日期：2026-08-31。本文件为设计与治理，不表示业务能力已实现。权威见 [业务架构总纲](../业务架构总纲.md) 第 12—14 节；必读 [PackingList](PackingList模块能力地图.md)、[库存](库存模块能力地图.md)，自动入库/反向再读 [入库](入库模块能力地图.md)。

## 1. 使命与边界

为仓库、出货及审计人员提供正式最终客户发货、客供件消耗及反向链查询。出库保存正式执行事实，不负责计划出货、装柜编辑、需求分配或供应商货好确认。

- 最终客户出库和客供件消耗分别记账；直接交付客户的备件属于前者，不能只按产品分类判断。
- 业务写入口仅为 PackingList 提交及其授权纠错/反向编排，统一库存过账服务写流水和投影。
- 普通出库页面只读，不提供无来源人工出库、直接改数量/仓库/客户或余额操作。

## 2. 交接与事实归属

| 提供方 → 消费方 | 权威事实 | 禁止越界 |
|---|---|---|
| PackingList → 出库 | 有效修订、逐来源交付贡献、客户身份、产品单位、仓库、消耗历史依据、稳定命令身份 | 强制活动 Allocation，或用头部 InvoiceNo 覆盖来源编号 |
| 出库 → 库存 | 正式出库头行及库存动作，原/反向/替代关联 | 绕开统一服务更新余额，删除原流水 |
| 库存 → 提交编排 | 同客户仓库产品可用数量、总余额及并发版本 | 使用其他客户库存、用无归属历史量充当已证明可用量 |
| 出库 → 来源/需求履约 | 来源可识别的最终客户交付净额及纠错/反向事实 | 把 B 消耗或 PackingList 草稿计入已交付；要求需求存在才认可出库 |
| 真实错发 → 售后/退回收货 | 原发货事实、售后问题、实际退回记录和补发关联 | 仅修改旧出库表示未曾错发，未收回就加库存 |

总库存投影与客户归属需可对账；历史不可证明须核实，不能假定零库存再自动补货。源头身份与快照保留，UI 查询聚合不另存已发货缓存。反向净额只计算一次。

## 3. 页面与命令

| 页面/入口 | 职责与用户 | 允许动作 | 禁止动作 |
|---|---|---|---|
| 正式出库列表，库存导航 | 仓库/出货按单号、类型、客户、来源、日期、仓库筛选 | search、打开详情 | 创建任意人工出库 |
| 出库详情，列表/PL/库存 Trace 打开 | 展示头行、来源贡献、InvoiceNo 分组、库存流水、有效修订关联 | 只读、导航 PackingList 权威纠错入口 | 保存出库字段、独立修改生成单据 |
| 出库 Trace，详情打开 | 审计查看原出库、反向、替代、PL 修订及售后交接 | 查询、跨单据导航 | 执行过账、取消、反向或售后处置 |

查询需服务端查看权限和客户/字段可见范围；隐藏按钮不是授权。正式生成、纠错、整单反向由 PackingList 的不同权限/预览命令发起，出库端仍校验身份、幂等、原单状态和依赖。

当前状态为 Posted/Reversed，无普通人工未过账出库草稿。业务修订不是给现有枚举随意增加值：旧事实保持、显式反向/替代关联，有效版由 PackingList 管理。

## 4. 数量、事务与反向门禁

- 最终出库逐客户交付来源守恒；同来源多贡献合计不得超可交付额度。
- B 按已证明历史配置与累计出货计算增量消耗，保留尾差及历史消耗证据；不能读当前 BOM 重算过去。
- 同客户/仓库/产品的最终出库与 B 消耗合计校验；分仓、分客户不能相互抵销。
- 正常库存不足阻断；特殊缺口放行须独立授权、明确原因、类型 90 及审计，不能伪造入库或跨客户借量。
- 出库与 PL 状态、必要自动入库、流水、客户归属及总余额、操作日志在一个外层事务；重复意图不生成重复单据，失败全回滚。
- 整单反向先撤销本 PL 的最终出库/B 消耗，再撤销它的自动入库，检查下游消耗和全部生成单据；不能独立撤一行造成总量不守恒。
- 已过账库存/履约纠错通过 PL 专用流程完成原事实—反向—替代；不能把中间恢复的库存暴露给并发任务。真实退回只按实际收回增加库存，补发关联新售后来源，不篡改原发货。

## 5. API、DTO 与前端 Model

当前 SwiftExport.Contracts/Apis/Inventory/IOutboundWorkspaceApi.cs 只有 search、get detail、get trace，与只读边界一致；目标不因此新建人工出库写 API。

| 用例/权限 | 当前类型与字段来源 | 消费者/目标 Model | 复用边界 |
|---|---|---|---|
| search / 查看 | OutboundSearchRequest、OutboundListItemDto；正式头行与仓库聚合 | OutboundWorkspaceViewModel；SearchModel、只读列表 | 查询筛选 UI 状态不入 DTO，不用详情全集当列表 |
| detail / 查看 | OutboundDetailDto、HeaderDto、LineDto；正式头行/贡献/历史快照，InventoryLedgerItemDto 为流水 | 出库详情；只读 DetailModel | 详情不作为写 Command；逐来源客户/编号与可选需求身份分离 |
| trace / 追溯 | OutboundTraceDto；正式出库、贡献和流水链 | 出库 Trace | 不拿 Trace 外壳复用成 PL 编辑模型；敏感字段服务端裁剪 |
| PL 生成/纠错/反向 | 内部领域命令及结果，不开放普通出库写接口 | PackingList 编排，非页面直接消费者 | 客户范围、来源容量、版本、幂等由服务端校验，UI 不复制编排 |

一个公开类型一文件。业务 DTO 只有至少两个真实消费者且业务含义、单位/空值、权限、生命周期与演进一致才复用；已在多个详情使用的窄 InventoryLedgerItemDto 可按同口径保留，未建页面不是复用证据。Contracts 保持 netstandard2.0；结构转换使用 Mapster，数量计算不进入映射。

## 7. 后续切片与验收

1. Backend 随客户库存和来源契约切片落实正式出库来源身份/历史快照，不要求先建立需求。
2. Backend 随 PL 提交切片验证生成、B 消耗、并发与整单反向事务。
3. Frontend 独立完善列表、只读详情/Trace、来源编号及客户归属展示，纠错只导航到 PL。
4. 联合修订切片验证原/反向/替代及实际退回/补发链，Reviewer 检查授权与履约净额。

验收：无需求但合法交付可查询追溯；备件最终交付不算 B 消耗；多来源分组不丢身份；跨客户库存拒绝；同键合计扣减；反向净额不重复；重复命令不重复出库；中途失败全回滚；真实未退回不加库存；越权查询拒绝；只读页无库存写入口；修订保留历史且有效履约唯一。

以上不是已执行测试。Agent 修改/复制/扩大偏差前必须按 [模块治理规则](../业务模块能力与页面契约治理规则.md) 提醒 ID、源码、影响与最小重构并暂停；未触碰仅报告。

## 8. 主数据与当前 BOM 交接补充

同时读 [主数据地图](主数据模块能力地图.md)、[BOM 地图](BOM模块能力地图.md)。主数据停用本身不抹历史或自动阻断已确认合法交付，仍校验来源承诺、单位、客户归属、仓库及数量；新行/新增承诺不能绕过停用。基础单位在产品已有正式流水后冻结，更名不改变身份或历史流水。

客供件消耗使用需求已接受拆解或独立采购确认的执行快照；当前 BOM 保存不重算已发生消耗，修改记录不能代替历史执行依据。仓库停用、负库存、纠错和整单反向门禁不变。
