# 销售模块能力地图

> **2026-09-16 需求反向交接：** 销售确认通过来源接收能力建立 GrossDemand，不自动拆解或采购。纠错取消确认必须先完成正式客户出库反过账、采购入库反过账、采购 Link 释放和物料安全回退；销售只调用来源退出能力，不直接扫描或维护 NetDemand、采购、入库和 Link。物料未回退或有效 PackingList/正式交付仍存在时整单阻断。来源退出成功后，无物料历史的 GrossDemand 删除，有历史的转 Voided，销售才恢复待确认。

> **2026-09-07 口径修正：** 以《业务架构总纲》开头“采购来源可选与独立供货修正”为准。本文旧“采购必须对应一个销售单”、强制销售归属迁移及相关验收/提示词已撤销。采购可选关联来源需求；无上游的独立采购可正常入出库，PL 可选择其供货，交付要求仍来自来源需求。客供件池仅在实际消耗时明确归属并经用户批准，不得将订单池约束提升为所有采购的必填条件。阶段 02 使用已修订提示词。

本文保留已确认的目标设计，不表示全部已实现。2026-09-28 已按当前源码更新销售查询入口与偏差；其他跨领域目标仍须在实施前核对源码。权威规则见 [业务架构总纲](../业务架构总纲.md) 第 7、8、14 节。交接必读 [需求计划](需求计划模块能力地图.md)、[PackingList](PackingList模块能力地图.md) 地图；涉及采购承诺读 [采购](采购模块能力地图.md)，涉及库存与正式交付读 [库存](库存模块能力地图.md)、[出库](出库模块能力地图.md)。

## 2026-09-06 当前修订

统一口径以业务总纲第 24.7 节和需求计划地图最新修订为准：GrossDemand 幂等汇聚销售、品质售后，是 PL 必需的选源与交付额度入口；NetDemand 与 Link 不作客户出货归属。销售只定义销售事实，正式客户出库通过来源需求追溯原始来源。

以[业务总纲第 24 节](../业务架构总纲.md#24-订单级客供件池与领域解耦2026-09-06)为当前目标，不代表源码已实现。

销售维护销售事实，来源需求维护统一交付身份/额度，通过正式客户出库查询履约，不依赖物料需求或采购 Link。来源需求经理页保留为权限控制的管理入口，普通销售用户不需要逐层操作。未触及的商业修订/关闭规则保留。

实施步骤与提示词见[本领域治理方案](../领域治理/01-销售领域治理.md)。

## 1. 使命、用户与非目标

为销售人员维护客户商业承诺、订单生命周期和交付要求，为跟单人员提供跨订单只读履约跟踪。销售决定客户要什么、多少、何时交付及成交条件；需求决定计划，采购决定实际采购，PackingList 编排实际出货，库存保存正式库存事实。

本次只建设设计与治理。首期币种限定 CNY/USD，不扩展多币种、应收、收款、结算、完整售后流程或独立非标库存体系。销售页面不直接执行采购、入出库、需求拆解，也不维护其他领域的内部表。

## 2. 能力、权威事实与上下游

| 事实/能力 | 所有者及来源 | 交接与禁止事项 |
|---|---|---|
| 当前客户关系 | 销售头 CustomerId；客户领域验证有效身份 | CustomerCode/名称为快照，不能以可变编码替代关系；已确认换客户另建关联订单 |
| 订单与来源身份 | 销售头/行 Uid、OrderNo、稳定行身份 | 行号用于顺序，不作为外部幂等键；导入需稳定外部行到内部 Uid 映射 |
| 商业编号 | 销售 CustomerPoNo、InvoiceNo | InvoiceNo 为自定义形式发票号，向 PL 提供来源快照；不当唯一来源身份、不用头部摘要覆盖多个来源 |
| 产品及商业快照 | 销售行 ProductId、CustomerProductId、SKU/描述/客户 SKU、数量、价格等 | 主数据改变不自动刷新成立时快照；换品终止旧行剩余部分，新增关联替代行 |
| 交期和船务 | 销售保存客户交期/承诺和运输要求，PL 保存实际装运资料 | 行交期优先于头交期的现有来源规则保留；不得把 PL 实际船务信息静默回写成销售承诺 |
| 需求接收/退出 | 需求领域契约 | 销售确认后幂等接收实物行，不自动拆解/采购；取消确认只在物料已安全回退且正式交付已退出后撤回来源；销售不得直接维护需求内部表 |
| 已承接采购与货好 | 采购领域正式承诺与最新有效跟进 | 销售只读聚合和导航，不编辑采购状态、不把 ReadyQty 当库存或已发货 |
| 客户交付来源 | 销售的有效客户、产品单位、当前允许交付量和来源版本 | PL 可直接使用，无需物料需求或 Link；无采购/无货好不阻断合法计划草稿 |
| 正式交付 | 按来源可识别的最终客户出库及纠错/反向事实 | 销售只读计算履约，不保存可编辑 ShippedQty；B 消耗不计客户交付 |
| 真实退回/补发 | 售后处置、实际退回收货及新补发来源 | 原实际出货不抹掉；退回不自动重开原来源需求交付额度，补发不能双开额度 |

### 2.1 非标关联

非标允许先接单、确认、接收需求和计划；正式库存动作前显式关联有效产品身份。通过受控关联命令校验产品、单位、来源及下游影响，保留原非标快照和关联历史，不能用普通保存静默改为另一产品。既有采购/计划的引用通过所属领域明确协调，不覆盖历史；销售关联不等于授权修改产品主数据或已执行单据。

当前非标 ProductId 为空的记录仍是合法历史事实；不批量猜测 SKU 对应关系，不造第二套非标库存身份。未关联可提示待完善，不得伪造可正式出库条件。

## 3. 状态与数量边界

分别表达：单据 Open/Closed、确认状态、行交付是否终止、业务修订、需求/采购处置进度、查询计算履约进度。不得合成万能 OrderStatus，不在本次新增枚举值或物理字段。

| 数量 | 口径 | 禁止混用 |
|---|---|---|
| 当前订购量 | 当前有效销售商业要求，保留原要求与变更差异 | 不以采购承诺替代 |
| 正式交付净额 | 逐销售来源最终客户出库，纠错/反向净影响只计一次 | 不计 PL 草稿、货好、B 消耗或收货覆盖 |
| 终止剩余量 | 显式终止时停止的未交付承诺及恢复历史 | 不通过删行、归零原订单数量隐藏取消 |
| 允许新交付量 | 当前生效要求扣除已交付及仍有效的终止部分；关闭/终止范围内为零 | 只读计算，不把其他草稿作为预占，不与需求处置完成绑定 |
| 待处置差额 | 当前要求与历史已接受承诺之间的差异 | 不伪装为已取消采购或可用库存 |

减量与终止不能重复扣同一份剩余量；减量少于既有正式交付事实时，提示冲突并进入明确纠错/售后处理，不能截断已发货量或制造负可交付量。订单级汇总不能让一行超发抵消另一行未发；不同单位的数量合计不能当库存判断依据。

全部发完仅更新履约展示，不自动关闭。关闭/终止不把实际未发数量标为“已发完”，须同时展示未交付及停止原因。用户恢复时重新评估允许交付量和待承接差额，不重置历史交付、不无条件恢复旧计划或采购承诺。

### 3.1 管理列表的状态与交期提醒（2026-09-28 查询规划）

- 管理列表分别显示单据生命周期（Open/Closed）、确认状态、按有效正式交付计算的履约进度。`Open` 建议显示为“开放”，避免“正常”被误解为已确认或交付正常；不为查询摘要增加订单头持久化状态。
- 正式交付净额已确定只按销售来源下有效已过账、未反向的 PackingList 行数量求和；同来源跨箱单累加，自动出库只记库存事实，不重复计入销售交付。
- 待确认行没有 GrossDemand 是正常草稿，显示已发 0、商业未交为订购量；已确认行缺少可信来源或过账历史无法核实则显示“未知／需核实”，不按零计算。
- 整单履约进度按活动销售行分别判断未发、部分发、全部发；任一行无法核实则整单“未知／需核实”，不同产品或单位不通过头部总量相互抵消。
- 销售行正式已发量高于当前订购量时保留真实已发值、商业未交量显示 0，并标“超发需核实”；行与整单均不判为“全部发货”。
- 没有活动销售行的订单，整单履约进度显示“无有效明细／无法判断”，不进入“未发货”或“全部发货”筛选；确认命令仍应阻断空明细。
- 管理列表订单级订购、已发、未交数量只在全部有效行单位一致且可核实时汇总；混合单位或单位未知时显示“多单位／查看明细”，行级数字仍如实展示。
- 按销售行计算正式已交付量、剩余可交付量和是否全部交付，再汇总整单进度；各行单位不一致时不以头部数量合计判断完成。关闭且仍有未交付量、待处置执行事项应分别提示，不能显示为“已发完”。
- 临近交期与逾期是只读提醒：以未完成销售行的有效交期为判断依据，保留“无交期／无法判断”语义；头部交期仅用于概览。待确认但交期已过仍归“待确认”并附“交期已过”提示；“逾期未交”快捷筛选只含开放且已确认的订单。筛选优先覆盖待确认、未发货、部分发货、逾期未交、已关闭但有遗留事项，以及客户、客户 PO、SKU/客户货号和日期范围。
- 有效客户交期已确定优先取销售行 `ExpectedDeliveryDate`，为空再取销售头 `DeliveryDate`；两者都为空显示“无交期／无法判断”，不以 ETD、ETA 或 PL 实际船务日期替代。
- “提前几天提醒”是查询阈值，不等于客户交货周期、客户产品生产提前期或供应商供货周期。销售临近交期阈值已确定由服务端固定为 **7 个自然日**，以北京时间 `Asia/Shanghai`（UTC+8）确定“今天”；本阶段不建字典或配置实体，不写回销售单据。具体查询口径见 [销售订单查询与履约实施待办](../../../docs/销售订单查询与履约实施待办.md)。
- 交期早于北京时间今天才算逾期；今天至未来第 7 个自然日（含第 7 天）为临近交期，交期当天仍属临近、次日才逾期。履约逾期快捷筛选只含开放且已确认、仍有商业未交量的订单。
- 当前 `Customer.LeadTimeDays`、`CustomerProduct.LeadTimeDays`、`SalesOrderHeader.LeadTimeDays` 是交期业务数据，`Supplier.DefaultLeadTime` 是供应商默认供货周期；这些字段不能直接充当统一的临期提醒天数。`SysDictData` 仅有名称、备注等文本列，也不适合存放需要整数校验的阈值。以后若要求管理员在线调整阈值，再评估一份有类型的交期提醒配置，不为每张订单建实体，也不提前设计万能键值参数表。

## 5. 命令、准入与事务

所有写命令由服务端校验操作权限、来源范围、状态/版本；幂等意图与内容绑定，预览失效须重算。前端可见权限不是后端授权。

| 命令 | 准入 | 结果及边界 |
|---|---|---|
| 保存/删除草稿 | 草稿编辑/删除权限、Open + 待确认、版本一致；删除无下游 | 保存有效头行及快照；不得经此修改已确认订单或抹除历史 |
| 确认 | 确认权限、有效客户及活动行、状态/版本有效 | 经需求领域契约幂等接收实物需求，单体事务内订单确认与接收全成全败，不自动拆解/采购 |
| 取消确认 | 专用权限、原因、版本；正式交付已反向、物料已安全回退 | 调用来源退出能力：无物料历史删除 GrossDemand，有安全历史转 Voided；不自动反向出入库、采购或物料，不代替客户业务取消 |
| 受控变更预览/确认 | 变更权限、有效版本、差异和原因 | 同号业务修订；价格/说明等不影响需求的字段不无条件重建需求；数量/产品/交期变更向需求提供差异和版本 |
| 行级终止/整单终止交付 | 终止权限、明确范围、剩余量、原因/版本 | 生效后立即限制对应新交付和新需求承接；不停止无关行，不自动取消采购/反向库存 |
| 关闭 | 关闭权限、Open、原因、版本及遗留事项/责任记录 | 停止销售新交付，允许采购仍待处置；显示“执行处置未完成”，不级联关闭需求/采购 |
| 恢复订单/恢复行交付 | 恢复权限、影响预览、原因、状态/版本及来源校验 | 恢复明确范围，重新计算额度及需求差额；重新打开订单不自动恢复先前独立终止的行 |
| 非标关联产品 | 关联权限、明确产品单位、来源/版本及影响预览 | 保留非标原貌和关联历史，经领域契约协调后续身份；不改写既有执行事实 |

业务修订号、记录身份与并发 Version 分离。已确认客户不可原位替换；换品新行与旧行关联，新交付承诺须正式生效后才可使用。新增/改品/增加量不绕过销售确认，临时编辑或尚未确认的变更草稿不产生交付额度。

销售新要求生效与其交付限制在同一命令边界更新，并通过需求契约记录变更，防止销售已停止而新需求仍被承接。需求处置可未完成，已有合法采购/收货继续；商业生效不等待采购处置完成。跨 PL 提交与销售变更须针对同一来源版本/数量最终重验，不能以旧预览超交付。

订单修订不能自动覆盖已出货 PL 的 InvoiceNo/产品等历史快照；PL 改动走自己的修订/纠错命令。销售关闭不是撤销实际发货，重新打开也不改写原流水。

| detail / 查看 | 现有 `SalesOrderDetailDto`、`SalesOrderDetailLineDto` | 销售商业快照及按来源核实的已交／未交；`SalesOrderDetailViewModel`、头行编辑 Model | 详情与保存方向不同，只读履约数量不进入写入请求 |
| 客户/产品 Lookup / 查看 | 现有 SalesOrderCustomerLookupDto、SalesOrderProductLookupDto 及搜索请求 | 有效客户/产品/客户产品关系；详情选择组件 | 保留已有用例，不因未来页字段相似抽共享宽 DTO |
| 草稿 save / 编辑 | SaveSalesOrderRequest/Response、EditHeaderDto/EditLineDto、DeletedLineDto | 用户商业输入，服务端验证关系并计算金额；详情 EditModel | 保留现有拆分，不误报为桶文件；只读发货量不进入保存 |
| confirm/cancel-confirmation / 各自权限 | 现有命令及 SalesOrderConfirmationResultDto | 订单状态与需求接收/安全退出结果；详情动作 | 既有确认结果多个真实消费者，语义兼容才保留；取消原因和幂等契约不可弱化 |
| 履约跟踪 detail / 查看 | `ISalesFulfillmentApi.GetAsync` 按销售订单 Uid 返回 `SalesFulfillmentDetailDto` | 销售行、可信来源需求、有效 Link 采购贡献、采购行最新货好、有效箱单正式交付及反向历史；`SalesFulfillmentDetailViewModel` | 专用只读 Query；货好保留采购行粒度，共享采购行不分摊给销售行；跨模块详情入口另受目标模块权限控制 |
| 变更 preview/confirm / 变更 | 专用 Command、PreviewDto、CommandResult | 原有效修订、新商业要求、受影响来源及遗留事项；详情变更组件 | 预览与已生效结果分开，不复用 Save 请求 |
| terminate/close/restore / 独立权限 | 按终止、关闭、恢复分开命令及影响结果；close 目标完善遗留语义 | 明确订单/行范围、原因、版本、幂等身份和影响；详情组件 | 不靠模式布尔字段构造万能状态命令 |
| 非标关联 preview/confirm / 关联 | 专用关联 Command、Preview/Result | 原非标来源、选择产品单位、受影响执行链；详情关联组件 | 不复用产品主数据编辑或普通销售保存 |
| 历史/Trace / 追溯 | 专用只读历史/Trace Query | 销售修订、替代行、需求处置及 PL 正式事实；详情历史组件 | 不扩成跨领域写 DTO，不向只读跟踪页泄露无权商业价格 |

联表治理：头行按 SalesOrderId 一对多；客户/产品关系实时字段与商业快照分列。需求、采购、跟进和出库等一对多数据先按各自权威粒度汇总再关联，防止乘法重复。可选执行/需求关系使用保留销售来源的关联，不因缺物料需求、Link、采购或跟进丢行。正式发货按来源头行身份聚合有效最终交付事实，反向净影响只计一次；主数据失效不抹掉历史。无关联返回明确未承接/可空，不能伪造已完成或将未知归属库存当零。

金额本期只承诺 CNY/USD，币种白名单需服务端约束；不把任意币种按 USD 处理。现有双价格含义不在本轮擅自合并或新增通用折算模型，历史金额与新计算差异列为后续实施核验，不自动重算历史单据。

业务 DTO 复用须至少两个真实消费者且概念、字段单位/空值、来源、权限、校验、生命周期与演进一致；平台包装按规范。一个公开类型一文件，不在 VM 内定义 DTO；UI 选择、脏状态、Busy 留在 Model，结构映射使用 Mapster，商业/数量规则显式实现。Contracts 保持 netstandard2.0。本次不生成类型、DDL、新索引或更改既有 JSON 字段。

## 8. 分阶段任务与验收

1. Backend：销售来源、商业修订/终止/关闭/恢复及需求交接契约；明确字段权威、版本、幂等、权限与查询血缘，不提前固定物理修订表。保留安全取消确认测试。
2. 联合库存/PL 切片：客户库存归属与交付来源衔接、非标产品证明、销售变更和正式提交并发；不以未完成采购处置锁死独立执行。
3. Frontend：管理列表增加交付进度、交期提醒及快捷筛选；复用详情权威命令，独立只读履约跟踪、影响预览与历史组件；不越界改后端，DTO/Model 依规范转换。提醒阈值只用于查询，不改写订单交期或状态。
4. Reviewer：联验下列行为和对应 DP/PL/OUT 偏差，实际重构后才更新账本完成状态。

验收场景：

- 草稿保存、重复确认幂等，取消确认两条历史路径和不安全下游拒绝继续有效。
- 部分发货后减量/终止只影响剩余承诺，其他行继续；低于实际交付冲突不被截断掩盖，减量和终止不重复扣额度。
- 换客户另单；换品新行与旧行关联，原出货不丢；临时变更草稿或未确认增量不扩大出货额度。
- 已生效销售限制与 PL 提交并发，旧预览不能超交付；不依赖物料需求的合法客户交付可追溯，B 消耗不计交付。
- 关闭后新交付停止、已确认采购可合法收货、待处置事项仍可见；恢复不重置交付或自动复活旧采购，全部发完不自动关闭。
- 真实退回不自动恢复来源需求交付额度，新售后补发不双开额度，PL 修订不覆盖原销售历史。
- 非标可先接单和计划，正式库存前关联有效产品；关联不擅改历史采购/已出库身份。
- CNY/USD 正常；其他币种拒绝新增/变更或明确历史异常，不误算 USD；主数据更新不改历史快照。
- 查询无执行关联不丢销售行、多对多不重复计量；跟踪页无跨域写入；越权拒绝、版本冲突、同意图重试和事务失败回滚。

本次仅文档校验，以上不是已执行测试。按 [Agent 偏差门禁](../业务模块能力与页面契约治理规则.md)，后续修改、复制或扩大 SO/关联偏差前必须报告编号、源码证据、影响、最小重构及兼容代价并暂停；未触碰仅报告。地图不是自动 CI，也不授权顺手重构。
