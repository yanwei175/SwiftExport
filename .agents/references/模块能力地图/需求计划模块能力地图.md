# 需求计划模块能力地图

> **2026-09-16 采购确认职责修正：** 采购确认只校验采购事实并锁定订单、允许入库；不读取完整 BOM、不创建新 BOM 确认节点、不绑定消耗仓，也不要求首次确认存在历史快照。已有确认快照仅作历史查询。草稿建立的未释放 Link 阻断需求回退；取消确认不释放，删行或作废才释放。客供件消耗归 PackingList 正式出货过账，实际仓和数量届时确定；跨供应商用料先调拨，禁止任意仓扣减。该自动消耗、选仓与调拨接线尚未实现。本轮不新增分解快照表。


> **2026-09-16 正反向能力重整：** 当前权威主链为 `GrossDemand → NetDemand → PurchaseOrder → DemandExecutionLink → Inbound → Outbound`。`NetDemandAllocation` 与计划命令日志已经物理退出，任何页面、接口、测试和新单据都不得恢复该结构或它的状态语义。
>
> 需求驱动采购采用“草稿即预留”：采购草稿创建时建立 `TargetType=PO` 的活动 Link；采购确认不重复建链；取消确认只回到草稿并保留 Link；草稿删行或整单作废才累计 `ReleasedQty`。有效贡献固定为 `AllocatedQty - ReleasedQty`，存在正数即阻断物料回退。
>
> 本轮只冻结 PO 链。其他执行单据出现明确业务场景后再设计，不预建通用执行协议，也不以新名称恢复 Allocation。独立采购不制造需求 Link，但仍可按采购与库存规则正常确认、入库和出库。

本文同时记录目标规则与当前源码偏差。带“已收口”的能力可以作为现行事实；DP-005、DP-009 等开放项不得描述成已经实现。跨域规则同时读取[采购](采购模块能力地图.md)、[入库](入库模块能力地图.md)、[库存](库存模块能力地图.md)、[PackingList](PackingList模块能力地图.md)与[出库](出库模块能力地图.md)地图。

## 1. 使命、用户与非目标

为计划经理接收销售、品质售后和手工实物要求，保存来源需求、BOM 拆解修订和物料需求事实，并提供采购承接前提、安全回退和只读追溯。需求计划拥有 GrossDemand 与 NetDemand 生命周期，不拥有来源单据、采购单、入出库单或库存状态。

售后仅把已认可的正数量补件要求接入；投诉事实、责任、费用和结案仍归售后。需求不自动拆解、下采购、反向库存或级联取消其他领域单据。本轮不实现生产工单、自动 MRP 抵扣、库存预留、跨来源单采购合并或分布式流程。

## 2. 已确认决策与权威模型

| 能力/事实 | 所有者 | 决策与边界 |
|---|---|---|
| 来源确认/业务变更/取消 | 销售或服务领域 | 自己维护商业状态，通过明确契约通知/协调需求，不直接维护需求内部表 |
| 来源需求接收 | GrossDemand | 来源认可实物行后自动幂等接收；手工需求为独立入口；不自动拆解或下采购 |
| BOM 拆解与历史修订 | NetDemand | 保留拆解版本，不被当前 BOM 或采购结果改写；当前 NetQty 未自动扣库存 |
| 推荐采购供应商 | NetDemand | 仅为计划建议；无建议仍可采购，实际供应商由采购确定 |
| 哪份需求被哪个执行单据承接 | DemandExecutionLink | 保留实际执行关联与历史贡献；不复制采购、收货状态，不把计划变更当采购减量 |
| 采购草稿与实际承接 | 采购领域 | 需求驱动草稿创建采购头行和活动 PO Link；独立采购不建 Link；实际供应商和收货目标由采购决定 |
| 采购确认与反向 | 采购领域 | 确认不重复建 Link；取消确认保留 Link；删行或作废释放贡献；不自动回退物料或来源 |
| 入库、库存事实 | 入库/库存领域 | 依赖合法执行凭证，不依赖需求是否仍活动；见入库地图交接矩阵 |
| 履约完成情况 | 来源认可的正式履约事实的查询投影 | 销售参考正式客户出货；服务由服务领域认可实物履约，不以收货或采购覆盖冒充服务完成 |

`NetDemand` 多对一归属 `GrossDemand`；采购行可接收多条 NetDemand，同一 NetDemand 也可分次进入多个采购行，数量关系只由 `DemandExecutionLink` 表达。来源、拆解、执行和库存职责保持分离，不复制跨域状态到需求表。

## 3. 正向、反向与来源结束

| 阶段 | 准入与责任 | 结果/阻断 |
|---|---|---|
| 销售/售后确认 | 来源单状态、版本和有效行可证明；调用来源接收契约 | 同事务幂等建立 GrossDemand；不自动拆解或采购 |
| BOM 拆解 | GrossDemand 活动、版本与当前 BOM 有效 | 一条来源行形成一组 NetDemand；保存修订、结构和来源快照 |
| 需求转采购草稿 | NetDemand 活动、剩余可承接量有效；采购选择实际供应商和目标 | 同事务创建采购草稿与活动 PO Link；草稿阶段即预留需求贡献 |
| 采购确认 | 草稿资料和 Link 守恒、版本有效 | 采购转已确认并保存确认依据；不得重复建立 Link |
| 采购入库 | 采购已确认、采购行仍有可收量 | 入库过账形成库存事实；是否存在需求 Link 不作为独立采购收货前提 |
| 正式客户出库 | 来源需求有效、交付额度及库存条件成立 | PackingList/正式客户出库形成来源交付事实；普通手工仓库出库不计来源履约 |
| 出库反过账 | 正式出库允许反向、原流水完整 | 恢复库存并保留正反向事实；不自动反向入库或采购 |
| 入库反过账 | 原入库完整且下游/库存允许 | 扣回库存并将入库标为 Reversed；不自动改变采购状态 |
| 采购取消确认 | 已确认且正式下游已经安全反向 | 回到采购草稿，保留需求 Link 和原确认历史 |
| 草稿删行/整单作废 | 草稿或可直接作废的采购满足下游安全检查 | 释放对应 Link，使 `ReleasedQty=AllocatedQty`；历史 Link 不删除 |
| 物料安全回退 | 同一来源活动修订一致，所有 Link 剩余贡献为零 | 整组 NetDemand 转 RolledBack，保留修订、原因、人员和时间 |
| 来源取消确认 | 正式来源交付已反向；相关物料历史无活动修订且完整安全退出 | 无物料历史的 GrossDemand 物理删除；有历史的转 Voided；随后来源单恢复待确认 |

反向动作必须逐层显式执行，后一层只消费前一层已经提交的状态，不建立跨采购、库存、需求的一键级联事务。销售和售后取消确认复用来源退出能力，但不会自动回退物料；物料未回退或正式客户交付未反向时必须返回明确阻断。

纠错取消确认与业务取消分开。上述反向链适用于完整撤销错误操作；已有执行但不要求全部反向的客户减量、终止或继续备货仍走 DP-005 的业务变更能力，不能放松安全回退条件冒充完成。

## 4. 数量、关系与一致性

- 来源键使用来源类型 + 来源头/行 Uid；来源版本用于并发，不以 SKU/单号推测重复。重新确认生成新活动需求时保留既有历史规则，不能以历史存在为由误判重复。
- 当前需求、推荐供应商、Link 有效贡献、正式收货和来源交付分别呈现；不存在“Allocation 数量守恒”或可恢复的计划分配状态。
- 已承接量按活动 Link 的 `AllocatedQty - ReleasedQty` 汇总，剩余可转量不得因来源刷新、采购取消确认或推荐供应商变化而重置。
- 库存、在途仅供参考，不自动抵扣 NetQty 或形成预留；同一供给出现在多条需求的参考信息中不代表各条都已独占。
- 采购取消确认本身不修改 `ReleasedQty`；只有采购草稿删行、整单作废或未来明确设计的采购减量命令才能释放贡献。需求页面不得直接修改采购行或 Link。
- 需求终止不删除历史 Link，也不使原采购失去收货资格。收货覆盖只针对当前有效需求按总纲 13.5 计算；历史贡献与当前覆盖分开，不用覆盖量判断专属库存。
- 同来源单内可按兼容产品、单位、收货目标合并采购行；来源单之间继续隔离，不能因供应商相同跨单合并。
- 单体内经领域契约协调接受数量与采购创建，失败回滚；不引入消息基础设施来替代清晰的职责。源码迁移时必须覆盖并发变更与转采购、幂等冲突和失败重试。

## 5. 页面职责及权限

| 页面/组件 | 用户/入口 | 负责 | 禁止 |
|---|---|---|---|
| 来源需求经理页 | 计划经理；权限控制的需求导航 | 来源接收情况、来源分组/详情、手工来源创建修改关闭、导航物料建立；保留现有管理能力 | 替销售/售后取消确认、直接维护拆解结果、采购单或库存 |
| 物料需求管理页 | 计划员/采购员；需求导航或来源跳转 | 已建立物料事实、推荐采购供应商、已关联采购量、来源建立和安全回退 | 恢复旧计划编辑/Trace 页面；把推荐供应商当实际采购事实；直接写采购头行 |
| 采购候选与预览 | 采购页面；采购创建权限 | 拉取可承接物料需求、选择实际供应商和目标、创建采购及 PO Link | 放回物料需求页面；要求推荐供应商等于实际供应商 |
| 需求变更详情（目标新增） | 来源/需求打开；变更处置权限 | 影响清单、处置记录、差额、显式完成或关闭 | 复制采购取消、入库反向命令；无结论自动关闭 |
| 需求 Trace | 来源/需求打开；查询权限 | 需求修订、计划、执行关联、收货覆盖及正式履约 | 任意写命令，拿当前覆盖改历史归属 |

来源需求经理页是受权限控制的管理入口，不是普通销售/售后用户的必经页面；销售和售后取消确认直接复用来源退出能力。物料需求页是拆解与安全回退入口。各领域页面只调用自己的权威命令，不复制跨域资格判断。

## 6. 契约、前端模型与字段来源

截至 2026-09-16，当前接口为 `IGrossDemandWorkspaceApi`、`INetDemandManagerApi` 和采购域 `IPurchaseDraftApi`。物料需求的生产链已经退出旧 `INetDemandWorkspaceApi`、PlanEditor、Trace 与 Allocation 维护契约。

| 用例 | 当前契约/目标增量 | 消费者与前端模型 | 来源和复用边界 |
|---|---|---|---|
| 来源接收/安全退出 | ISourceDemandReceptionService 的来源身份、版本、实物内容及取消确认协议 | 销售、品质售后与手工来源管理 | 来源领域提供快照；需求验证物料退出，Shipping 验证正式交付；来源服务不直接维护采购、入库或 Link |
| 毛需求搜索/详情 | GrossDemandSearchRequest、GrossDemandListItemDto、GrossDemandDetailDto | GrossDemandWorkspaceViewModel、详情/手工编辑 | 来源快照与当前需求状态；编辑状态单独 Model，来源业务字段不可越权编辑 |
| 来源建立/安全回退 | SourceDemandCandidate*、EstablishMaterialDemands*、RollbackMaterialDemands* | SourceDemandCandidatePickerViewModel、NetDemandManagerViewModel | 由物料历史和执行事实判断，不回写来源兼容拆解字段，不套用业务取消 |
| 物料事实搜索/来源分组 | MaterialDemandManagerSearchRequest/ItemDto、MaterialDemandSourceGroupSearchRequest、NetDemandSourceGroupDto | NetDemandManagerViewModel、MaterialDemandManagerRowModel | 聚合来源、推荐供应商与有效采购关联；不读取 Allocation，不恢复旧详情/Trace 聚合 |
| 推荐采购供应商修改 | UpdateSuggestedPurchaseSupplierCommand/Result | NetDemandManagerViewModel、MaterialDemandManagerRowModel | 只修改物料建议，不回写既有采购单的实际供应商或收货目标 |
| 采购交接 | IPurchaseDraftApi 下的候选、Preview、Create 窄契约 | PurchaseOrderFromMaterialView、PurchaseDraftWorkflowViewModel | 创建采购草稿与活动 PO Link；确认不重建 Link；取消确认保留，删行/作废释放 |
| 变更评估/处置/关闭 | 目标窄 Query/Command/Result：需求身份/版本、变更身份、影响项、处置理由与执行结果引用 | 目标需求变更详情/来源流程 | 不把变更藏在普通 Save、属性 setter 或采购释放命令中；具体类型在实现切片冻结 |
| 收货覆盖/履约跟踪 | 目标只读查询项，参考既有 Trace 投影 | 需求/采购 Trace | 实收按采购行聚合，覆盖按有效需求计算，来源认可的履约事实独立；不能放进 EditCommand |

来源退出的目标内部契约冻结如下，当前实现差距见 DP-009：

- `IMaterialDemandEstablishmentService` 按一组 GrossDemandId 返回逐条物料退出评估：历史数量、是否存在活动修订、历史是否完整。来源服务只消费评估结论，不自行解释 NetDemand、Link、采购或入库表。
- `ISourceDeliveryService` 增加按来源类型、来源头 Uid 和 GrossDemandIds 核验来源交付是否可退出的内部方法。成功不返回业务数据；失败使用稳定代码 `SOURCE_DELIVERY_EXISTS`、`DELIVERY_QUERY_UNAVAILABLE`、`SOURCE_DELIVERY_HISTORY_INVALID`。
- 外部命令保持不变：`RollbackSourceEstablishmentAsync` 仍是物料回退唯一入口，`ISourceDemandReceptionService.CancelConfirmationAsync` 仍由销售和售后取消确认复用；不新增来源需求独立取消确认 HTTP 命令。

字段快照与实时值明确标识：SKU/描述/单位/来源交期为接收或拆解快照，建议供应商来自计划，实际供应商/送达目标来自采购，收货来自正式入库，客户发货来自正式出库。缺少可选关联返回空或明确未承接，不内联过滤掉合法独立采购。

沿用 DTO 门禁：业务 DTO 仅在同概念/角色、字段单位空值、来源权限、校验生命周期与演进一致且至少两个真实消费者时复用；未来服务单不是预先抽象万能 DTO 的理由。公开类型独立文件；UI 状态留在 Model，结构转换使用 Mapster，数量与状态决策显式表达。

## 7. 源码偏差账本

核对日期 2026-09-16；路径相对仓库根。已退出的旧链继续保留偏差 ID 和处置结论，避免后续从历史文档恢复。

| ID | 当前源码证据 | 影响与最小治理方向 |
|---|---|---|
| DP-001（已收口） | 销售与售后通过 `ISourceDemandReceptionService` 接收或退出来源；历史计数及安全性由 `IMaterialDemandEstablishmentService` 协调物料边界 | 禁止销售/售后重新直接写需求仓储或读取来源兼容拆解字段 |
| DP-002（已收口） | 采购入口由 `Procurement/PurchaseDraftService`、`Procurement/PurchaseDraftCreationService` 和 `IPurchaseDraftApi` 负责，同事务创建采购与 PO Link | 采购创建实现不得迁回 DemandPlanning，也不得恢复需求页面采购写入口 |
| DP-003（已收口） | `NetDemandManagerService` 只维护推荐采购供应商；采购候选/预览保存实际采购供应商和目标 | 保持建议与实际事实分离，不让推荐值重新成为采购硬约束 |
| DP-004（旧链已退出） | `NetDemandWorkspaceService`、`NetDemandPlanReplacementPlanner` 和 PlanEditor 已删除；当前页面不提供旧计划替换命令 | 需求变化评估仍是目标缺口，但不得通过恢复旧计划编辑链冒充实现 |
| DP-005 | SwiftExport.Application/Services/Orders/SalesOrderCancellationPolicy.cs 与销售取消服务实现安全回退路径；GrossDemandWorkspaceService.cs 的 CloseManualAsync 限手工未拆解需求 | 缺少已执行后的业务变更/终止路径；新增独立用例，不放松原纠错回退测试来冒充解耦 |
| DP-006 | SwiftExport.Application/Services/DemandPlanning/GrossDemandDecompositionPlanner.cs 将 NetQty 设为毛需求/组件计算数量 | 当前没有库存/在途净算，这是本轮允许的实现差异；界面必须标明未自动抵扣，不伪称 MRP 已完成 |
| DP-007（已收口） | 旧 `INetDemandWorkspaceApi`、聚合计划命令、采购生命周期及来源采购追溯 DTO 已退出；物料 Manager 与采购草稿使用各自窄契约 | 公开类型继续独立文件，禁止重新建立跨用例聚合 DTO、来源追溯假接口或把采购命令放回物料 API |
| DP-008（已收口） | 旧 `PurchaseDraftLifecycleService` 与 `PurchaseDraftReleasePlanner` 已退出，采购反向动作由采购领域显式用例承接 | 需求变化不得自动释放采购贡献；反向动作继续保留采购权限、原因、审计和事实检查 |
| DP-009（目标已冻结，源码待收口） | 当前来源退出仍通过 `HasSourceExitBlockerAsync` 直接扫描物料、Link 和采购入库，并在交付查询未接入时返回 `SOURCE_EXIT_SAFETY_UNAVAILABLE` | 目标改为物料历史提供传递证明，Shipping 独立核验有效 PackingList/正式客户出库；实现前不得删除 fail-closed 阻断 |

DP-005、DP-009 等开放项在触碰、复制或扩大前必须读取真实源码并单独验收。带“已收口”的旧链不得从历史测试或文档恢复；文档冻结来源退出目标不等于当前 `SOURCE_EXIT_SAFETY_UNAVAILABLE` 已解除。

| 顺序 | 角色与任务 | 后续完成证据 |
|---|---|---|
| 1 | Backend：把来源退出的物料检查收敛为批量历史评估 | 活动物料阻断；全部历史 RolledBack/Voided 后返回删除/作废分流所需计数；不再由来源层解释 Link/入库表 |
| 2 | Shipping：提供来源退出交付核验 | 有效 PackingList 草稿、未反向正式客户出库及异常历史分别阻断；普通手工仓库出库不参与 |
| 3 | Backend：销售/售后取消确认接入两项退出证明 | 无历史物理删除、有历史 Voided、混合行全成全败；不自动回退物料或库存 |
| 4 | Frontend：保持来源经理页与物料安全回退入口 | 页面权限、Busy、未保存更改、阻断错误可读；普通销售/售后无需进入来源页 |
| 5 | Reviewer：联合验收完整正反向链 | 采购取消确认保留 Link，删行/作废释放；出入库反向、物料回退、来源退出顺序和并发均有证据 |

业务场景（待实现验证，不代表本次运行）：

1. 销售/售后重复确认只接收一次来源需求；一次拆解修订可生成多条物料需求。
2. 需求驱动采购草稿创建活动 Link；多个物料需求可进入同一采购行；采购确认不重复建链。
3. 采购取消确认保留 Link；草稿删行只释放选中行；整单作废释放全部；未反向入库或异常流水阻断。
4. 任一 Link 剩余贡献为正时物料整组回退失败；全部释放后允许回退并保留历史。
5. 活动物料阻断来源取消；物料已回退但有效 PackingList 或正式交付未反向时仍阻断；交付反向后才允许退出。
6. 无物料历史的来源需求物理删除；有完整安全历史的转 Voided；同一来源单混合分流必须全成全败。
7. 手工仓库出库及其反过账只影响库存，不计来源履约；独立采购无 Link 仍可合法收货。
8. 采购释放与物料回退、物料回退与来源退出、来源退出与正式交付提交并发时，最终事务内复核不得留下悬空事实。

当前代表性测试见 `SalesOrderCancellationPolicyTests`、`GrossDemandDecompositionPlannerTests`、`MaterialDemandEstablishmentContractTests`、`NetDemandManagerSqlContractTests`、`NetDemandManagerSourceNavigationTests` 与 `PurchaseDraftPreviewBuilderTests`。旧 PlanEditor、计划替换、计划命令幂等及初始 Allocation 测试已随功能退出删除；现有覆盖仍不能证明尚未实现的需求变更生命周期。

## 9. PackingList 交付回传

销售来源同时读取 [销售地图](销售模块能力地图.md)，正式交付同时读取 [PackingList 地图](PackingList模块能力地图.md)和[出库地图](出库模块能力地图.md)。

GrossDemand 是 PackingList 唯一交付入口，不按 SourceType 建立白名单。准入只校验来源活动、客户可证明且与 PackingList 头一致、正式剩余量为正。标准产品和非标来源都可建立草稿并正式过账；非标行计入正式交付净额，但不产生库存、采购绑定或客供件事实。

正式交付净额由有效已过账且未反向的 PackingList 行聚合。最终客户出库只记录库存事实，不建立第二套来源履约权威；草稿、Preview、ReadyQty 和客供件消耗均不计交付。来源退出与 Post 并发时必须在事务内锁定并复核，不能超交付或留下已退出来源的新正式事实。

## 10. 主数据与当前 BOM 交接补充

同时读 [主数据地图](主数据模块能力地图.md)、[BOM 地图](BOM模块能力地图.md)。BOM 只有单套当前结构，保存生效；修改记录不是可选择版本。需求拆解 revision 保留，每次保存实际采用的一致完整结构/路径/比例/单位/角色快照，不能以旧 BomVersion 字段引入多方案选版。子 BOM 更新不修改已有拆解快照。
