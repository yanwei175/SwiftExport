## 1. 使命与边界

为出货、跟单人员提供计划出货、装柜草稿、实际出货确认及可追溯纠错。计划出货是工作台，不另建独立计划出货单；PackingList 是装柜与提交编排权威。

- 一单一个最终客户，可合并该客户多张销售订单、售后补货单、不同 InvoiceNo 及多个合法仓库；逐来源保留贡献。
- 来源领域提供合法客户实物交付需求；需求计划提供可选追溯，不垄断出货准入。
- 不负责销售商业变更、采购确认、需求拆解、售后责任/结算、任意库存调整或完整生产流程。
- 普通产品通常不手工入库不等于无凭证造库存；实际出货时编排必要自动入库。客供件 B 通常独立实际收货。

## 2. 上下游与权威事实

| 交接 | 提供方权威 | PackingList 使用方式与禁止事项 |
|---|---|---|
| 客户交付来源 | 销售/售后提供来源类型、头行 Uid、单号、客户、产品单位、允许交付数量及状态/版本 | 保存精确贡献；正式净交付抵减可交付量；不强制活动 Allocation，不伪造销售来源 |
| 备货与采购 | 采购头行、实际供应商/收货目标、确认状态、正式净收货与剩余可收；跟进提供 ReadyQty | ReadyQty 只排序/提示；合法采购行才可作为自动入库凭证；不能以计划量或备好量证明收货 |
| 客户库存 | 库存提供同客户、同仓库、同产品及兼容单位的已证明可用量 | 先用库存，跨客户禁止自动借用；无需求库存不因无 Allocation 被排除 |
| 客供件消耗 | 与本次执行相关的已证明历史拆解/配置及累计消耗事实 | 保留历史比例、版本、目标仓和舍入依据；不重新读取当前 BOM，不强制存在活动需求计划 |
| 正式事实 | 入库/出库领域产生正式单据，统一库存服务追加流水及更新投影 | PackingList 只在外层事务编排，不绕过统一过账服务直接改余额 |
| 履约回传 | 来源可识别的正式最终客户出库及纠错/反向事实 | 来源领域计算交付净额；需求按来源接收履约，不把 B 消耗算客户交付，不以草稿回写发货 |

### 2.1 单号与 InvoiceNo

销售来源须同时读取 [销售地图](销售模块能力地图.md)。销售的当前生效要求与来源版本是交付额度权威：行级终止/关闭立即停止对应新交付，减量后按新额度重验，不能等待采购处置完成才生效；未影响的行继续。销售增加量或替代新行须确认后才产生新额度，变更草稿无额度。恢复不重置历史交付，也不自动恢复已终止的独立行。

PL 草稿不预占来源需求交付额度；既有草稿在销售变更后提示来源已变化，正式提交与销售变更并发时锁定/校验同一来源状态、版本及净额，旧预览不能超交付。销售处置待完成不作为通用出货门槛，当前来源已关闭/终止则必须阻断。非标未关联产品可以进入待完善计划，正式库存动作前须有受控产品身份及单位证明。已确认换客户另建订单，换品新增关联销售行，不原位替换旧 PL 来源。

销售 InvoiceNo 与 PackingList 展示的 InvoiceNo 是同一自定义形式发票号，不另定义“出货发票号”。售后有自己的单号，客户提供的编号对应其 InvoiceNo。贡献以来源头行 Uid 标识，不以 InvoiceNo 当主键。

列表、详情、打印、导出按“来源类型/单号 + InvoiceNo”分组，允许一张 PackingList 多组；无编号如实显示未提供。头部摘要不能用一个可编辑标量覆盖所有来源值。保留来源编号历史快照与修订依据；来源后续改号不得静默改写已出货历史。

### 2.2 客户归属与自动入库

采购头现有 CustomerCode 需解析到稳定客户身份，编码/名称作快照；不是直接用可变编码作库存所有权主键。客户归属数量必须能与仓库产品总余额、正式流水对账。本任务不指定新表或物理迁移结构。

- 同客户、同仓、同产品和兼容单位可共用库存，不把需求覆盖当专属库存。跨仓必须分别核算，不能净额抵销。
- 历史客户归属不明须待核实；不能当作可用，也不能当零后重复自动入库。缺口无法证明时阻断正式自动动作，不阻断计划草稿。
- 按整单库存键合计本次最终出库，先分配已证明库存；剩余缺口再选择合法已确认采购行，验证客户、产品单位、目标仓和剩余可收容量。
- 自动入库保留采购头行与 PackingList 贡献证据，计入采购正式净收货；后续人工入库共享同一容量校验，不能重复收货。
- 多贡献使用同一库存/采购行先聚合；跨 PackingList 并发锁定同一权威数量，不能逐行重复使用余额或采购容量。
- 库存已足够时不额外要求新采购/新收货；库存不足又无合法来源时，正常正式过账阻断。

## 3. 页面职责

| 页面/入口 | 用户与职责 | 主要动作 | 禁止职责 |
|---|---|---|---|
| 计划出货工作台，出货导航入口 | 出货/跟单；按客户汇总合法未交付来源，优先展示已报货好 | 查询、筛选、查看跟进、选源建立/加入草稿 | 默认隐藏未报货好、要求先采购/分配、写库存 |
| PackingList 管理列表 | 出货人员查状态、客户、来源、编号、日期及有效修订 | 新建、打开详情、查看历史 | 内嵌另一套保存/提交实现 |
| PackingList 草稿/详情，列表或计划入口打开 | 编辑贡献、仓库、包装、运输信息；区分计划与真实出货 | 保存、作废草稿、预览、确认实际出货、修订、整单反向 | 保存/打印即过账，普通 Update 覆盖已过账事实 |
| 影响预览/确认组件，详情显式命令打开 | 展示入库来源、出库、B 消耗、各客户库存前后值、阻断与警告 | 确认当前业务意图；独立权限校验 | 客户端自行计算权威余额或自动绕过阻断 |
| Trace/修订历史/输出，详情打开 | 只读展示来源贡献、生成单据、原/反向/替代链和历史输出 | 导航、按有效修订打印/导出 | 修改正式单据、丢弃旧修订或合并来源身份 |

未采购、未填或不足 ReadyQty 均可进入计划并保存合法草稿；其他活动草稿的计划数量单独提示，不预占库存/交付额度。正式提交重新校验来源可交付量，多个草稿不得造成超交付。实际出货确认与保存、预览、打印是不同动作。

## 4. 命令、事务与纠错

| 命令 | 准入/权限 | 结果与阻断 |
|---|---|---|
| 建立/保存草稿 | 编辑权限、合法客户交付来源、同客户、正数量；更新版本匹配 | 保存文档与贡献，不动库存；缺 ReadyQty/采购不是阻断；来源非法/合计超允许交付阻断 |
| 作废草稿 | 作废权限、未过账、版本和原因 | 留存历史，不生成库存反向 |
| 实际出货预览 | 提交权限、有效草稿 | 只读真实影响；输入/来源/库存/历史消耗变化使预览失效 |
| 确认实际出货 | 实际已交付、提交权限、预览与状态/版本有效 | 服务端重验，外层事务完成自动入库、最终出库、B 消耗、客户与总余额、状态、日志；失败全回滚 |
| 文档性修订 | 修订权限、已过账、版本/原因；字段不影响库存或交付归属 | 同业务单号追加修订历史，不写库存，不普通覆盖原版 |
| 库存/履约纠错修订 | 专用权限、影响预览、原因、版本、下游可纠正 | 产品、数量、客户、仓库、采购来源或消耗依据变化必须原事实—反向—替代关联；原子更新有效修订及履约，失败全回滚 |
| 整单反向 | 反向权限、有效预览/原因、所有生成单据及下游可反向 | 先反向出库和消耗，再反向本单自动入库；不撤销其他合法实收；保留历史 |

同意图重试复用 CommandId/CommandItemId，标识相同但内容不同须拒绝。预览不是保留库存或免校验令牌。纠错中间恢复的库存不能暴露给并发任务使用。

### 4.1 客供件与负库存

消耗按历史执行依据与累计实际出货计算本次增量，处理部分出货、最后一批舍入及反向后重算，不能重复扣历史已消耗数量。B 以实际送达目标仓为准，不取当前 Allocation 重新选仓。

缺少必要消耗依据阻断正式过账，不阻断计划；B 库存不足正常阻断。特殊负库存仅按总纲授权、强提示、原因及类型 90 审计放行，不伪造 B 入库。最终产品出库与 B 消耗落到同一库存键时合计验证，成品自动补入库不能隐式补掉 B 缺口；负库存例外也不能借其他客户的库存。作为备件直接交给客户的产品属于最终客户出库，不因它常作为 B 就记成消耗。

### 4.2 修订与真实错发

- 保持 PackingList 业务单号，区分业务修订号、内部记录身份、并发 Version；旧版不可丢失。打印/导出标明修订及有效版本，历史输出可追溯。
- 录入错误走文档性或库存/履约纠错，不等同真实退货。
- 真实错发保留实际发货事实，关联售后问题及处置。只有实际收回才可建立客户退回收货，记录真实产品、数量、客户和接收仓；不冒充采购收货，不提前增加库存。
- 补发建立新的售后实物交付来源及 PackingList，关联原发货；不能覆盖原发货，也不能自动重新开放原销售行额度后再额外增加补发额度。
- 本阶段只定义退回/补发交接，不开放无凭证人工出入库，也不实现完整售后结算。

## 5. 契约、Model 与复用决策

下表目标为用例形状，不代表已建立 API/DTO；现有 API 位于 SwiftExport.Contracts/Apis/Shipping/IPackingListWorkspaceApi.cs。

| 用例与权限 | 字段来源/权威 | 消费者与目标前端 Model | 契约决策 |
|---|---|---|---|
| 计划来源查询：来源查看 | 来源领域交付凭证 + 跟进 + 库存只读投影 | 计划工作台；计划筛选 Model、来源选择 Model | 独立 Query，不沿用强制 Allocation 的旧 Source DTO；前端选中/Busy 不入 DTO |
| PackingList search/detail：单据查看 | 文档、逐来源快照、当前有效修订 | 管理列表、详情；SearchModel/DetailModel | 窄列表项与详情分开，不能以编辑字段全集返回列表 |
| drafts create/update：编辑 | 用户输入 + 来源身份/版本，服务端复核 | 详情 EditModel/LineModel | 独立 Command；不以来源 Query 或 Entity 当保存请求 |

| 修订/纠错预览与确认：专用权限 | 原有效修订、差异、依赖、正式事实 | 详情修订组件 | 专用 Command/Preview/Result；不扩大普通 Update 权限 |

| trace/export：追溯/输出权限 | 原始来源编号快照、贡献、正式事实、修订链 | Trace、打印/导出服务 | 输出按来源分组；窄共享项须证明已有至少两个真实消费者和相同可见权限 |

业务 DTO 默认按用例拥有，不按每个页面复制一套；仅当至少两个真实消费者具有同概念、字段/单位/空值、权限、校验、生命周期和演进口径时复用。尚未实现的计划页/售后页不算已有消费者。一个公开类型一文件，名称体现业务用例和 Query/Command/Result 职责；公共分页包装沿平台规范。结构转换使用 Mapster，库存/履约计算不可藏在映射配置里。Contracts 保持 netstandard2.0 兼容。

## 7. 实施与验收

1. Backend：客户库存归属和来源交接契约，含历史未知归属核实；不从页面字段反推表结构。
2. Backend/Frontend 分任务：计划工作台及草稿、跨来源编号、无货好/无采购可计划，保持各自写入边界。
3. Backend：真实预览、采购容量、同客户库存、自动入出库/B 消耗及并发幂等事务。
4. Backend/Frontend 分任务：同号修订、影响预览、实际退回/售后补发交接、历史版输出。
5. Reviewer：联验地图及全部下列场景，核对授权、事务和追溯。

验收覆盖：同客户多 SO/售后/InvoiceNo；跨客户拒绝；未报货好/无采购可草稿；草稿不预留；已有同客户库存不重补；未知归属不视作零；自动收货与人工收货合计不超 PO；重复来源/并发提交不超交付；B 不足/历史配置缺失；同键成品与 B 合计；授权类型 90；任何中途失败全回滚；超时重试不重复过账；文档修订不动库存；库存纠错完整反向替代且历史可查；真实未退回不加库存；补发不双开额度；整单反向遇下游依赖拒绝。

Agent 触碰、复制或扩大 PL/关联偏差时，按 [治理规则](../业务模块能力与页面契约治理规则.md) 输出 ID、证据、影响、最小重构方案并暂停等待选择；未触碰只报告。此文是人工执行门禁，不是已运行的 CI。
