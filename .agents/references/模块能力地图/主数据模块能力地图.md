# 主数据模块能力地图

核对日期：2026-10-06。本文描述当前工作树实现，不沿用旧阶段计划或以历史测试代替当前验收。业务判断以所列服务、实体和实际调用方为准；新增业务规则须另行确认。全部 HTTP 入口见[业务 API 索引](../../../docs/业务API索引.md)，跨域主线见[业务总纲](../业务架构总纲.md)。

## 职责与事实

主数据维护产品、主型号、中性资料、分类/颜色、客户、供应商、双方产品对应及客户采购默认配置。Product 保存真实库存/交易产品身份、单位、供货方式、BOM 绑定和默认值；ProductMaster、ProductNeutral、ProductDetail、ProductPackage 按现有实体分担资料。客户/供应商产品是对应关系，不是独立库存维度。

## 当前边界与限制

产品单位允许资料阶段为空；新增/更改明确单位按有效 Unit 字典归一化，历史交易仍使用 UnitSnapshot。当前 BOM 绑定保存有专门共享图校验；不能通过普通产品更新绕开组成边界。默认仓库、制造商字段已在 Product，不应按旧提示词重复新增。

主数据查询、维护和具体执行准入是不同职责；停用后的既有单据是否可继续要读取对应执行服务，不能写成所有流程一律拒绝或一律放行。编码、主数据单位冻结、生命周期能力只按实际公开入口认定；不要把旧“专用更名/恢复治理目标”当已存在命令。保存历史快照，不用名称匹配替代稳定 Uid。

### 包装基础规则（2026-10-15，用户确认的第一阶段）

包材仍是 Product，物料类型在成品、零件、虚拟件、客供件之外增加“包材”；采购资格和 BOM 消耗沿用各自既有校验。ProductPackage 的 OwnerProductId 指向被包装物料，PackagingMaterialId 指向包材物料；所属物料与包装类型的未删除记录唯一。包装规格不自动同步 BOM，也不修改历史单据快照。

PackageType 保存已有 ProductPackageType 内置字典的稳定英文代码：InnerBox（内盒）、ShippingBox（单套运输盒）、Carton（出货外箱）、Pallet（托盘），允许自定义类型，各层均可省略。装率表示成品基础单位数，体积由调用方维护。物料分页、物料详情和箱单来源只取当前物料未删除的 Carton，缺失返回 null，不回退其他类型或采用默认标记；箱单来源继续保留非标和来源匹配条件。

第一阶段仅调整基础规则。结构基线用于本地评审，已有库使用[外箱规则增量迁移](../../../SwiftExport.Infrastructure/Database/PostgreSQL产品包装外箱规则迁移.sql)；身份迁移前置条件、执行顺序及固定目标见脚本，交付脚本本身不代表部署或真实 PG 写入验证完成。

### 包材档案专页（第二阶段）

WPF 新增独立“包材管理”入口（`packaging-materials`），复用普通 Product 身份、查询和批量保存协议，类型始终限定包材。页面维护编号、描述、文本规格、单位、供货方式、默认供应商、参考价、图片、单件自重及备注；不新增结构化尺寸、包装关系编辑器或独立包材 CRUD。权限沿用 Products.Product.View/Create/Edit/Delete；已保存记录的详情仍使用 `product:{Uid}` 文档身份。

Product Lookup 可按 MaterialType、ActiveOnly 过滤；指定包材时服务端固定要求启用，旧普通候选默认行为保持。所有物料写入口共用有效 ProductPackage 包材引用保护，被引用包材不能删除或改成非包材；既有 BOM 保护继续生效。批量 ProductDto 的 UnitWeight 表达单件自重，UpdateUnitWeight 明确区分更新/清空与旧客户端省略；旧客户端未声明更新时保留数据库值。

第一阶段迁移状态：用户在主窗口明确确认 SQL 已人工执行；第二阶段只读核对 `192.168.3.12:5432/dv_next`，`is_default` 已移除，两物料身份列保留，包装表当时为 0 行。此运行库核对不表示运行库写入、回滚或并发验收通过；后续真实写入验收仅使用下述获准隔离库。

### 物料详情包装规格（第三、四阶段，2026-10-16）

ProductDetail 增加“包装规格”页签，维护各层包装类型、正整数装率、可选包材引用、包装长宽高、净重、毛重、手工 CBM 和备注。包材候选只接纳启用包材身份；不把包材单件自重或档案值自动复制为成品包装结果。读取保留失效引用的包装行及提示，允许显式修复或解除引用。既有失效引用未改选时可保留；新增或替换引用须重新校验包材资格。

详情响应 Packages 为 null 表示区块未加载，客户端不可据此当空集合保存；请求 PackagingChanges 为 null 或无操作表示保持，增删改分别提交行身份和 Version。OwnerProductId 由父详情确定，不接受客户端跨 Owner 修改。基础资料、标签与包装在既有详情 Serializable 事务内原子保存，父物料 ExpectedVersion 和包装行 Version 均参与校验。先按 PG uid 顺序锁定 Owner 与相关包材，再锁包装；普通物料改型/删除复用相同物料锁及引用保护。存在有效自有包装的物料须先在详情移除关系，再删除；没有自动级联删除。

同 Owner/类型的有效行保持唯一，删除后重建和类型互换均在同一事务完成，临时类型不会提交。详情子区块接入保存、撤销、关闭保护和原生 DataGrid 编辑缓冲；数字转换错误阻止保存和切换页签。旧列表创建时空 ColorId 归一为 null，避免新建包材随后打开详情被误判为无效颜色身份；显式详情空身份仍拒绝。

本次最终整合验证：后端定向回归 187 项、WPF 定向回归 61 项全部通过，包含原生 STA 输入、权限、撤销、回执及资料/标签/包装组合回滚。真实 PG 在用户批准的 `192.168.3.12:5432/dv_next_product_main_image_tests_20261015` 上通过 21 个独立用例；其中六种包材失效竞争补强双方失败类别后复验通过。覆盖三处 Carton 投影、Owner/版本边界、后序写入失败回滚、类型互换、同类型并发与交叉引用锁序。测试限定随机夹具有限提交、失败回滚和按记录身份清理，各例复核残留为零；不创建/清空数据库，不改历史单据。本次第三、四阶段没有新增结构迁移。

验收证据位于 `SwiftExport.Application.Tests/TestResults/包装模块最终后端回归.trx`、`包装模块真实PG验收.trx`、`包装并发失败类别复验.trx`，以及 `SwiftExport.Client.Wpf.Tests/TestResults/包装模块最终WPF回归.trx`。这些结果证明相应 Application/Repository 和客户端自动化边界，不等同真实 HTTP、生产写入或客户端人工验收。

主窗口另经 DBX 独立只读复核：从上述真实 PG TRX 提取的 27 个唯一夹具前缀物料及来源残留均为 0，临时 `__editing__` 类型残留为 0；隔离库 `product=17306`、`product_package=0`、`gross_demand=0`，与测试前基线一致。
