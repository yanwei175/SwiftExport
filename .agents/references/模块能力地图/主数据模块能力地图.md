## 1. 使命、用户和非目标

为产品资料维护、销售及采购人员维护稳定业务身份、当前属性和交易默认值。主数据不保存订单履约、库存余额、实际消耗或业务单据历史事实。完整范围包含产品、客户、供应商、双方产品关系、分类、颜色、主型号、包装、产品资料和客户采购默认配置；不是要求所有页面本次实现。

不建设单位转换、第二套库存身份、BOM 多版本中心、价格审批/财务结算或文件存储平台；本次不修改业务代码、契约、DDL 或枚举。

## 2. 权威事实与字段审计

| 对象/字段组 | 归属与结论 | 引用/快照及禁止边界 |
|---|---|---|
| Product.Uid/Sku | 保留稳定身份；SKU 是业务编码，专用更名 | 旧单 SKU 保持历史快照；编码不能代替 Uid |
| Product.MaterialType/SupplyType/Unit | 保留物料角色、供货方式和基础单位；不是执行状态 | B 为采购型终端物料；正式库存流水后 Unit 冻结，历史角色/单位用执行快照 |
| Product.DefaultSupplierId | 保留当前默认供应商权威关系 | 既有双入口共用设置命令；改默认不改历史计划/采购 |
| 默认客户/供应商编码及 SKU 兼容字段 | 目标关系归 CustomerProduct/SupplierProduct；列为迁移候选 | 不在本轮删除字段，不因旧接口使用编码继续建立双重权威 |
| Customer/Supplier | 保留稳定 Uid、编码、名称、联系/商务默认值 | 不保存销售/采购历史金额、当前库存或交付进度 |
| CustomerProduct | 必属客户、可选关联 Product 的客户产品资料；客户 SKU/描述/价格/MOQ/客户包装覆盖独立保存 | 无 Product 时仍可建档、查询和修改；不自动创建或按编码绑定 Product，单据采用后自存快照 |
| SupplierProduct | 必属供应商、可选关联 Product 的供应商产品资料；供应商 SKU/描述/采购价格独立保存 | 无 Product 时仍可建档、查询和修改；不保存库存，也不自动设置 Product 默认供应商 |
| ProductCategory/ProductColor | 分类树/排序、颜色名称代码 | 组织显示而非交易身份；分类循环、同级重名及颜色代码按现有唯一规则校验 |
| ProductMaster | 主型号默认描述、分类等 | 不成为独立库存身份；保存请求显式选项、主型号页下发或产品页按所选物料拉取才更新关联 Product 的指定资料，普通建档不自动覆盖 |
| ProductPackage | 产品通用包装、装率、尺寸重量体积及默认规格 | 客户产品可覆盖；单位/层级含义明确，不把包装换算当库存基础单位转换 |
| ProductDetail | 稳定 ProductId、文件位置及可读编号 | 历史仅编码关系需可证明回填，不能猜测；删除记录不自动删除真实文件 |
| CustomerPoConfig | 客户及必要供应商范围的采购默认要求 | 标识、包装、人员等建议，不替代客户产品规格，不自动生成 BOM 消耗 |
| Product.BomNo/BomVersion | 当前实现兼容字段 | 目标只有单套当前 BOM；不作为多版本选择入口，见 BOM 地图 |

现有业务键继续区分产品 SKU、客户编码、供应商编码、客户产品关系与供应商产品关系，不机械统一成 CommonCode。历史记录与编码重用可能产生歧义时必须核实，不自动映射到另一 Uid。本任务不重新制定编号生成器或批量迁移规则。

## 3. 生命周期、更名及默认值

- 新建、新增关系、增量承诺必须引用允许新业务的主数据。停用禁止这些新引用，不等同执行冻结；既有已确认合法单据可按历史身份/快照和自己的状态、数量规则继续履行。
- “已有承诺继续”不是免校验：对象缺失、身份冲突、单位不相容、单据已关闭/取消或库存不足仍按对应领域阻断。不能靠旧订单新增行或增加数量绕过停用。
- 停用与删除分开，历史查询与引用保留；已有引用不可通过物理删除消除。现有 IsDeleted/IsActive 表达不统一，后续按来源事实规划，不能把软删除标志直接当已实现的业务停用机制。
- 恢复需操作权限和版本校验，不自动恢复旧订单、旧计划或已终止承诺。仓库自身停用与负库存规则保持原门禁，不因供应商停用放宽。
- SKU/客户/供应商编码更名走独立权限、原因、版本和影响校验，Uid 不变，记录旧新值；历史单据快照不改。实时关系按 Uid 更新显示；仍依赖旧编码的查询、导入和外部映射必须明确处理，不能默认旧编码永久别名或自动转指其他对象。
- 产品已有正式库存流水后冻结基础单位，即使当前余额为零也不能普通修改；换单位新建产品身份。尚无正式流水时也要检查订单、BOM 与执行引用，不能只验证单位字典。名称拼写修正不等于物理单位转换。
- 产品普通资料保存可按现有规则选择有效默认供应商；供应商产品页的专用设置入口必须有真实 Product 与匹配的 SupplierProduct 关联，并验证 Product.Version。普通供应商资料保存不触发该入口。
- 包装采用“产品默认 + 客户产品明确覆盖”：同含义字段客户明确配置优先，未覆盖沿产品默认；有效零值不按未配置处理，非法装率等不得借回退掩盖。销售/采购/PL 采用后形成自己的快照，模板修改不自动刷新。采购配置的文字要求不静默覆盖客户产品的定量包装规格。
- 主数据价格仅提供当前建议，成交价和历史金额归单据；不在本轮重定义 CNY/USD 双价格含义或增加价格版本系统。

## 4. 页面与命令

| 页面/入口与用户 | 职责/动作 | 禁止职责 |
|---|---|---|
| 产品管理，产品资料维护 | 查询、新建、编辑当前资料、默认供应商、停用/恢复；导航 BOM/关系/包装资料 | 普通保存改已冻结单位、改已有引用编码而不审计、编辑库存 |
| 客户/供应商管理，销售/采购资料维护 | 身份、联系/商务默认值；更名、停用/恢复组件 | 关闭其全部业务单据、覆盖历史客户/供应商快照 |
| 客户产品/供应商产品管理及上下文组件 | 维护专属编码/描述/价格和客户包装覆盖，导航同一产品 | 建立第二套产品身份、独立写产品默认供应商规则 |
| 产品包装/资料组件，产品详情入口 | 通用包装、默认规格、文件位置；显示覆盖来源 | 自动改变既有单据快照、自动删除磁盘文件 |
| 分类/颜色/主型号辅助维护 | 分类组织、颜色和新建产品默认资料 | 从分类/主型号直接生成库存事实 |
| 客户采购默认配置 | 客户及供应商范围的文字/商务默认要求 | 自动改 BOM 或向已确认采购回灌最新要求 |

新建/编辑、停用/恢复、更名、单位纠正、默认供应商设置各有明确授权和状态准入。涉及引用影响的命令先只读预览，正式提交重验版本和引用，原因/变更记录与写入同事务；相同意图重试不得重复更名或丢历史。只读组件不能调用变更命令，客户端权限不替代服务端授权。

## 5. API/DTO/Model 与数据血缘

当前契约分布于 Contracts/Apis/ProductApis、CustomerApis、SupplierApis，沿各自业务用例演进，不建主数据万能 API。产品、客户/供应商及关系查询和批量保存已存在；更名/完整停用策略、客户包装覆盖和部分资料页面的完成度须按源码核实，不以 Entity 存在认定已完成。

| 用例/权限 | 契约和来源 | 消费者/Model | 新建或复用判断 |
|---|---|---|---|
| 各主数据列表/详情/查看 | 当前各模块 Query/DTO；对象本表与必要实时名称 | 对应管理 VM、SearchModel/EditModel | 不因字段都有 Code/Name 而合并；编辑状态不入 Contracts |
| 客户/供应商产品查询及维护 | 关系本表 + 产品/客户/供应商 Uid 关联 | 关系管理页及已有上下文组件 | 多真实消费者且同权限、语义、生命周期才复用窄项 |
| 更名/停用/恢复/单位纠正 | 专用 Command、影响 Preview、Result | 管理详情的确认组件 | 不扩成万能 Update 或复用列表 DTO；返回影响不是已经生效结果 |
| 默认供应商设置 | 已有产品/供应商产品入口，共同 Product 权威 | 产品管理、供应商产品页 | 共用业务命令，不能为各页面复制规则 |
| 产品包装与客户覆盖 | 产品默认、客户产品覆盖及采用来源 | 产品/客户关系编辑组件；单据选择组件 | 管理编辑与解析后默认值查询分开；不复用单据历史 DTO 作为模板写入 |
| 资料/辅助配置 | 各自对象的当前资料、稳定关联 | 辅助维护页/产品组件 | 没有现成消费者不提前造共享 DTO；文件路径不是客户端命令执行授权 |

字段血缘要求：Product→Color/Category/默认 Supplier 是多对一；客户/供应商产品资料必属各自客户/供应商，至 Product 为可选 Uid 关联，未关联行的普通查询不能因 Product 连接消失。包装多行须先选择明确默认/覆盖，再形成单据读取投影，禁止直接 Join 导致重复行。新选择器过滤停用项；历史详情须保留原快照和已停用引用，不能使用同一活动过滤把历史行丢掉。来源未知明确返回异常/未配置，不伪造关系。

业务 DTO 复用须至少两个真实消费者且字段含义、单位/空值、来源、权限、校验和演进相同；平台包装按既有规范。一公开类型一文件，Contracts 保持 netstandard2.0；结构转换用 Mapster，停用准入、包装优先级和单位规则不藏在映射中。此处仅设计契约边界，不新增字段、表、索引或泛型 CRUD 框架。

## 7. 实施切片与验收

1. Backend：身份、更名、停用/恢复、单位冻结和引用影响契约，保留既有默认供应商能力与测试。
2. 联合 BOM/执行：当前结构、修改记录与执行快照，确保主数据停用不破坏既有历史解释。
3. Backend/Frontend 分任务：客户包装覆盖、默认值解析、单据快照及资料/辅助页面，遵守各自写入边界。
4. Reviewer：更名后身份不变/历史不变、停用拒新承诺/旧承诺可履行、流水后单位冻结、包装覆盖与多对多查询不重复、版本冲突/越权/失败回滚/同意图重试。

特别验收：停用供应商不自动停其仓库；仓库自身停用仍按库存门禁。非标关联产品保持销售地图边界。修改默认值不刷新销售/采购/PL 历史，删除资料记录不删除文件。检查 DTO 文件组织、权限与字段来源。
