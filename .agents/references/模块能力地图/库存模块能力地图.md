# 库存模块能力地图

## 2026-09-14 入库实体变更兼容性评估

- 本批新增入库 Manager/Picker 非过账后端，不调用库存写入内核，未修改 InventoryPostingService 或 InventoryService。数据库未连接、未迁移。
- 两个服务不直接读取入库实体中已删除的销售、需求、供应商或 SourceUid 字段，本次无需同步修改。库存流水 SourceDocumentId/SourceLineId 指向库存业务凭证头行；以后采购来源关系由入库行继续向上追，不能把流水 SourceLineId 直接改为采购行。
- InventoryPostingService 的普通追加、完整反向、原子纠错、幂等、单位和负库存校验属于同一库存事实职责；约 400 行不等于过度设计，本批不拆服务、不删保护。它仍须由上游 Application 掌握外层事务及业务合法性。
- 待过账阶段明确交易类型映射：库存 TransactionType 尚区分采购/客供件/PackingList 自动入库，新入库 DocumentType 与 CreationMode 已分离，不能直接枚举强转；当前不支持生产入库交易类型。不要为了非过账查询提前改变历史枚举数值。
- InventoryService 混合仓库维护、余额/流水查询及审计重放，职责偏宽；后续可按 Warehouse 管理与 Inventory 查询拆分，但不为本批入库改实体而顺带重构。仓库权限、幂等和删除引用保护继续保留。
- 下文 INV-002/003/005 的旧期初方法已不在当前 InventoryService；它们是历史证据，不应据此恢复期初入口。订单池、PL 自动补入库及跨领域库存归属问题并未由本批解决。

> **2026-09-07 口径修正：** 以《业务架构总纲》开头“采购来源可选与独立供货修正”为准。本文旧“采购必须对应一个销售单”、强制销售归属迁移及相关验收/提示词已撤销。采购可选关联来源需求；无上游的独立采购可正常入出库，PL 可选择其供货，交付要求仍来自来源需求。客供件池仅在实际消耗时明确归属并经用户批准，不得将订单池约束提升为所有采购的必填条件。阶段 02 使用已修订提示词。

> 2026-08-31 用户确认的目标设计；不代表源码已实现。业务权威见 [业务架构总纲](../业务架构总纲.md)，交接集中见 [入库地图](入库模块能力地图.md) 第 2 节；配套 [采购地图](采购模块能力地图.md)、[模块治理规则](../业务模块能力与页面契约治理规则.md)。

## 2026-09-06 当前修订

以[业务总纲第 24 节](../业务架构总纲.md#24-订单级客供件池与领域解耦2026-09-06)为当前目标，不代表源码已实现。

客供件从客户粒度收紧为销售订单＋供应商仓库＋产品＋统一库存单位。不同父件共享，同客户不同订单不共享，不以父件/采购行/Allocation 切池。当前余额流水无订单维度，需改持久化及并发，不能仅改显示。池与总账同事务、可重建对账；未知归属不当零/不自动分配。下文同客户共用语义在客供件范围由本修订替代，普通确认不扩大负库存例外。

## 1. 使命与能力范围

配套 [需求计划地图](需求计划模块能力地图.md)：库存/在途对计划只供参考，不自动抵扣或预留。需求关闭不级联撤销真实库存，继续备货保留执行历史；需求履约与来源业务关闭不是库存领域的状态。

库存为仓库管理人员、跟单查询人员和授权期初操作人员提供供应商虚拟仓管理、余额、流水、追溯及期初录入。统一库存过账能力服务入库、出库和 PackingList，不拥有这些上游业务状态。

第一阶段仅启用供应商虚拟仓；不新增内部实体仓、盘点、调拨、预留、独立人工出库或财务成本核算。未来生产仅作为合法执行收货来源，不在库存模块复制生产规则。

## 2. 权威事实与字段审计

| 数据 | 权威与字段来源 | 写入/关系边界 |
|---|---|---|
| WarehouseSite | 自身 Code/Name/IsActive；SupplierId → Supplier.Uid | 每供应商一条活动虚拟仓；代码/名称非关系主键；供应商有效性由服务端校验 |
| InventoryBalance | `(WarehouseSiteId, ProductId)` 当前余额投影，OnHandQty、LastLedgerSequence | 唯一键；只能由统一过账更新，可与流水累计校验 |
| InventoryLedgerEntry | QuantityDelta、BalanceAfter、Sequence、CommandItemId、来源头行及 ReversalOfLedgerId | 追加式库存事实；幂等、序列唯一；禁止普通更新/删除 |
| 当前可用量 | 当前阶段无独立预留，可用量按既有库存口径展示 | 不减草稿提示量；需求收货覆盖不是仓库可用量或专属库存 |
| 查询名称 | Balance → WarehouseSite/Product，供应商按仓库关系读取 | 显式说明实时名称与历史快照；主数据缺失不能使历史流水从查询消失 |
| 历史 SKU/单位/仓库摘要 | 单据与流水形成时快照 | 保留，不以当前名称覆盖历史事实；余额当前产品名可独立显示 |
| 来源 Trace | Ledger → 正式来源单据行 → 执行单据；需求关联 0..N | 无需求关联可停在采购单；查询只读，不要求补造 Link |

查询先按事实粒度聚合，再联接一对多关系，防止 Ledger/Link 展开使余额或净收货倍增。跨领域逻辑 Uid 关联由 Application 校验并配必要索引；本次不新增表、字段或数据库约束。

## 3. 页面、命令与权限

| 页面/用例 | 入口、用户与职责 | 状态/权限/阻断 | 禁止 |
|---|---|---|---|
| 虚拟仓管理 | 库存导航；仓库管理人员搜索、新建、改名、停用 | 读与管理授权分开；供应商有效、活动仓唯一；更新版本匹配，停用原因必填 | 改库存或把已有仓转归另一供应商 |
| 库存余额 | 库存导航；跟单/库存查询人员筛选与查看余额、打开 Trace | 余额查看及相应数据范围 | 直接改 OnHandQty、嵌入期初编辑状态 |
| 库存流水 | 库存导航/Trace；审计查询人员按仓库、类型、时间、来源查询 | 流水查看及相应数据范围 | 编辑/删除流水、在流水页发起业务反向 |
| 库存 Trace | 余额/流水链接打开；授权查询人员 | 只读关系与净影响，导航到来源单据 | 复制来源单据写命令 |
| 期初录入组件 | 库存管理入口或余额页导航；期初授权人员 | 独立 EditModel、验证和预览/确认，服务端检查 Inventory.OpeningBalance.Post 能力 | 作为普通余额编辑、通用调账或库存不足绕过入口 |
| 正式业务反向 | 导航至入库详情或 PackingList | 来源业务校验和独立反向授权 | 库存查询页自行生成任意反向流水 |

期初采用独立组件/用例，不要求另建导航页；取消不写入，预览展示真实 Before/Delta/After，提交重新校验。没有冻结期初批次、截止日或关账制度，本次不擅自添加，但也不将期初声明为日常调账能力。

虚拟仓存在余额或历史流水不可删除；当前停用实现连历史流水也阻断，作为现行保守约束保留，不在本次放宽。正式过账中的仓库有效性与并发须复核，不凭先前页面选择放行。

## 4. 库存写入与交接门禁

- 统一过账能力校验仓库/产品/单位、幂等与数量，追加流水、更新余额；调用业务服务掌握最外层事务，业务状态和日志同提交，失败全回滚。
- 重试复用原业务意图标识，相同标识不同内容必须冲突；来源头行 Uid 和快照可追溯。
- 原事实保留，反向流水指向原流水；存在下游消耗或将违反正常库存约束时不能独立反向入库。
- 正常动作不允许负库存；PackingList 特殊授权缺口按总纲独立处理，不能扩散成期初/入库通用豁免。
- 需求覆盖是查询投影；实际出货归属由 PackingList/正式出库决定。无法证明自动入库缺口时阻断自动动作，不将无需求库存当作不存在。
- UI 权限只改善体验，服务端授权是权威；权限名称常量不等于实际检查已经实现。

| 用例 | 当前契约 | 真实消费者/目标前端模型 | 复用边界 |
|---|---|---|---|

## 8. PackingList 客户库存交接补充

同时读取 [PackingList 地图](PackingList模块能力地图.md)、[出库地图](出库模块能力地图.md)。在现有仓库/产品总投影之外，目标须提供可证明的客户归属数量并与流水/总余额对账；不在本次冻结物理表。同客户、同仓、同产品及兼容单位可共用，跨客户禁止自动借量，CustomerCode 须解析稳定客户身份。

历史客户归属不明标记核实，不当作可用也不当零后自动补入库。最终出库与 B 消耗同键合计校验，特殊负库存不绕过客户归属。修订纠错在单一事务内完成反向/替代与有效版更新，不暴露中间恢复库存。实际退回才增加库存。以上客户归属能力当前未闭环，联合 PL-003、INB-008/INV-006 作为第一实施切片，不重复登记同一根因。

## 9. 主数据与当前 BOM 交接补充

按 [主数据地图](主数据模块能力地图.md) 区分主数据停用与仓库停用。供应商/客户/产品停用不自动停仓或阻断已有已确认合法承诺的库存动作；仍须验证来源、客户归属、仓库状态、单位和数量，不准新承诺绕过停用。仓库本身的停用保守约束、负库存和反向门禁不变。

产品只要有正式库存流水即冻结基础单位，余额为零也不普通修改，换单位新建产品身份；更名不改变 Uid、余额归属和历史流水快照。MD-002/005 与库存场景联合验收，不另造库存转换流程。
