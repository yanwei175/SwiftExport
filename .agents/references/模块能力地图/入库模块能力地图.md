# 入库模块能力地图

核对日期：2026-10-06。本文描述当前工作树实现，不沿用旧阶段计划或以历史测试代替当前验收。业务判断以所列服务、实体和实际调用方为准；新增业务规则须另行确认。全部 HTTP 入口见[业务 API 索引](../../../docs/业务API索引.md)，跨域主线见[业务总纲](../业务架构总纲.md)。

## 职责与事实

入库保存 InboundDocument、InboundDocumentLine；收货来源是真实采购行，不能把 DemandExecutionLink.Uid 当采购行 Uid。需求关联不是所有入库的必填条件。未过账草稿不改变余额，正式库存事实由统一库存过账能力写入。

## 当前能力

| 能力 | 实现 | 契约/消费者 |
| --- | --- | --- |
| 列表、详情 | InboundQueryService | IInboundManagerApi；InboundManager 页面 |
| 采购来源选择及可收容量 | InboundSourceQueryService | IInboundSourceApi、InboundSourcesController；InboundSourcePicker |
| 草稿保存、删除 | InboundDraftService | InboundDraftController；版本、数量、单位及来源资格校验 |
| 过账预览、过账 | InboundPostingService | InboundPostingController；ExpectedVersion 与 CommandId，正式命令复核 |
| 反向预览、反向 | InboundReversalService | InboundReversalController；已过账人工采购收货及库存反向条件 |
| 自动入库内部端口 | AutomaticPostingPorts | PackingList 父事务调用；不经人工页面创建/操作 |
| 收货仓库候选 | InboundQueryService | IInboundManagerApi.GetWarehouseOptionsAsync；入库查看权限下读取活动仓库，不授予仓库管理权限 |

## 关键规则

供应商筛选使用 `GET api/inventory/inbound-sources/suppliers/picker`，仅要求 `Inventory.Inbound.View`，返回 `InventorySupplierLookupDto` 的 Uid、编码和名称。包含停用但未删除的供应商，不按是否已有采购记录缩小；不依赖全量基础资料缓存或供应商管理权限。单页及关键词上限均为 200。候选加载失败不阻断不带供应商条件的来源首次查询。

采购追溯打开入库文档时，按稳定 Uid 读取最新头行及状态，刷新仍使用该 Uid；上游单号和过账状态快照不作为定位条件。文档保持只读，原有编辑和待恢复命令不得被覆盖。

实际采购可收资格和净收货数量通过入库查询/验证能力计算，不保存需求收货缓存。过账核对采购容量、供应商虚拟仓、产品和单位，写单据状态、流水、余额和审计/回执；父命令失败整体回滚。Preview 不写库存或预占。

人工过账要求 Active、Unposted、Manual、无 TriggerPackingListId；人工反向要求已过账的人工 PurchaseReceipt，并检查当前可反向数量。自动单据由箱单整单反向处理，不通过手工 API 绕开归属。用户操作错误需受控反向，不能清流水或删已过账历史。

本轮确认的整改边界（2026-10-21）：收货异常按采购行定位关联入库头，检查该头完整事实，只影响同头关联采购行，不把未知收货当作零，不扩散到无关单据。收货仓库候选与入库查询使用 `Inventory.Inbound.View`，创建、编辑、删除、过账和反向分别检查对应操作权限。查询输入由 `InboundQueryLimits` 统一限制关键词 200 字、单页 200 条。

客户端恢复保留原 CommandId、ExpectedVersion 和输入；未知结果不能通过重新创建命令绕过。原命令明确成功后，当前单据合法的后续版本不应被误判为原命令未完成。页面编辑同时遵守权限、只读入口、Busy、单据状态及未决命令边界，不改变 UI 布局。

管理查询的入库类型与过账状态支持多选：同一维度取并集，两个维度同时满足；空集合不限制该维度。集合未提供时保留旧单选请求语义。已保存的人工活动未过账草稿仍可在编辑权限下获取采购来源、增删明细及修改数量；入库类型在保存后固定，不能把类型固定误解为整单只读。新增明细必须来自真实采购行，不支持无来源空白行。
