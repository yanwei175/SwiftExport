## 1. 使命、用户与非目标

需求生命周期与采购承接见 [需求计划地图](需求计划模块能力地图.md)：受影响需求暂停新转采购，不自动停止既有采购或合法收货。需求业务取消不是反向真实入库的理由；已终止需求的历史关联仍可追溯，不再计入当前需求覆盖。

入库面向收货人员、跟单人员和授权过账人员，负责对合法执行单据登记实收、保存草稿、预览、过账、反向与追溯。普通采购和客供件均以采购订单行为来源；需求生成、手工建立、外部导入采购使用相同收货准入。

不负责净需求拆解、Allocation 调整、需求固定分摊、库存预留、采购确认或生产完工判定。未来生产收货由生产领域提供合法凭证与可收数量，本次不创建生产页面或万能来源框架。无需求采购合法，无执行单据的普通收货首期不开放。

## 2. 采购—入库—库存交接矩阵

本节是三份地图间的交接索引；数量公式与状态权威仍在业务总纲，不各自另造规则。

| 交接 | 上游提供 | 接收方责任 | 禁止行为 |
|---|---|---|---|
| 需求 → 采购 | 需求驱动时提供计划与 Link 贡献 | 采购维护执行单据；手工/独立导入可无 Link | 为无需求采购伪造需求或 Link |
| 采购 → 入库 | 采购头行 Uid、确认/生命周期、产品单位、收货目标、可收数量及版本 | 选择执行来源、记录实收；过账再校验 | 把 Allocation/Link 作为通用入库凭证；用 ReadyQty 当实收 |
| 入库 → 库存 | 正式单据头行、仓库产品、数量、幂等标识、快照 | 统一过账能力追加流水并更新余额 | UI/Repository 自行改余额；部分成功留下单据与库存不一致 |
| 库存 → 查询 | 余额、流水和来源单据引用 | 查询投影与只读 Trace | 用需求覆盖量冒充当前库存或预留 |
| 入库 → 需求查询 | 按采购行聚合的正式净收货量 | 需求领域计算当前覆盖，详见总纲 13.5 | 将覆盖写回 Allocation/Link，或当作每批收货的固定归属 |
| 反向 | 原入库、流水及下游依赖 | 入库校验；统一过账追加反向流水，同事务更新状态和日志 | 删除原事实，绕过下游消耗或负库存阻断 |
| PackingList → 自动入库 | 经证明的本次缺口和贡献 | PackingList 掌握最外层事务及整单反向 | 普通入库详情独立改写/反向自动入库 |

PackingList 目前依赖 Allocation 维度入库数量，见 INB-008。迁移不得把查询覆盖当专属库存，也不得看到未关联需求的现存库存便再次补入库。无法证明缺口时阻断自动补入库动作并说明原因；不阻断无需求采购的合法普通收货。本次不定义新的库存归属或耗用算法。

## 3. 权威事实、关系与字段来源

| 数据 | 权威来源与关系 | 目标结论 |
|---|---|---|
| 来源采购头行 | PurchaseOrderLine.PurchaseOrderId → PurchaseOrderHead.Uid；每入库行对应一个执行行 | 保留明确头行 Uid，单号作快照；不得将 Link Uid 冒称采购行 Uid |
| 实收数量、产品单位 | InboundDocumentLine.Quantity 与单据快照；首次从采购行合法快照建立 | 保留事实；不随主数据改名/改单位重写历史，不自行默认单位冒充已验证单位 |
| 采购供应商 | PurchaseOrderHead.SupplierId | 与收货目标供应商分别表达，不能用仓库供应商覆盖采购供应商 |
| 收货目标 | 采购单确定的送达目标 + WarehouseSite 的有效关系 | 生成采购时可由计划推导；收货不重新用当前 Allocation 决定目标；不得合并不同收货目标为同一来源行 |
| 净收货、剩余可收 | 按执行行聚合正式入库及反向净额，采购数量扣减净收货 | Query DTO；按来源先聚合再联表，避免多 Link 使数量倍增 |
| 其他草稿数量 | 同来源、活动未过账草稿行合计，编辑时排除当前单 | Query DTO 提示；不扣正式可收量、不构成预占 |
| 需求关联 | 采购行 → 0..N Link → Allocation → NetDemand | 可选追溯；无关联返回空集合，不使用 inner join 排除合法采购行 |
| 库存影响 | InventoryLedgerEntry、InventoryBalance | 库存领域提供真实前后量，入库预览不能填写固定零余额 |

需求关联为一对多，不在通用入库行塞一个必填 Allocation 冒充全部来源。旧入库 Link/Allocation 关系保留历史可解释性；后续迁移必须显式解析真实采购头行，无法证明的历史记录报异常，不静默换写 SourceUid 或删除历史。源类型枚举已有数值不得重排。

## 4. 页面与权限边界

以下均为目标职责，不表示新页面已建立。权限以服务端授权为准，表中为能力要求，不宣称已有权限策略。

| 页面/组件 | 入口与用户 | 负责 | 禁止 |
|---|---|---|---|
| 入库管理列表 | 入库导航；收货/跟单人员 | 筛选、摘要、新建/打开详情、打开 Trace | 编辑明细、直接过账或复制反向编排 |
| 入库详情 | 新建或按入库 Uid 打开；编辑/过账授权人员 | 来源选择、数量编辑、保存、草稿作废、预览及显式命令 | 修改采购、需求分配；普通修改已过账事实 |
| 来源选择组件 | 详情调用；具备来源查看权限 | 采购来源筛选、多行选择、正式剩余量与草稿提示 | 自选任意 SKU 收货、回写采购或分配计划 |
| 预览/反向确认组件 | 详情调用；相应操作授权人员 | 展示真实影响/阻断，输入反向原因，确认或取消 | 另建过账入口；以按钮隐藏代替后端授权 |
| 入库 Trace | 列表/详情/库存来源链接；追溯权限人员 | 只读入库、执行单据、库存流水及可选需求链 | 保存、过账、反向 |

新建详情使用临时打开身份，保存后转换为正式单据身份；同 Uid 激活已有详情，不重复打开或覆盖脏状态。选择/确认组件取消不回填；异步、关闭、验证、权限和反馈继续遵循既有 WPF 横向 Skill，不在地图复制技术规则。

## 5. 命令、状态、权限和事务

| 用例 | 准入/权限 | 结果与阻断 |
|---|---|---|
| 来源查询 | 来源查看；采购已确认、活动且未关闭/作废；产品单位、目标仓有效 | 返回剩余量大于零的执行行；没有 Link 不是阻断 |
| 创建/更新草稿 | 入库编辑；更新须 Active + Unposted、版本匹配 | 同目标仓、数量正数、按来源合计不超收；只写草稿，不动库存 |
| 作废草稿 | 入库作废；Active + Unposted、原因和版本有效 | 保留作废历史，不写反向流水；当前接口缺失，见 INB-007 |
| 过账预览 | 入库过账权限；草稿有效 | 真实来源和库存前后量、阻断及预览标识；不写业务事实 |
| 过账 | 同上，预览有效、幂等和版本匹配 | 同一事务重新锁定/校验来源及库存；按来源汇总本单实收，防止重复行超收；单据、流水、余额、日志全成全败 |
| 反向预览/执行 | 独立反向权限；已过账、原因有效 | 校验下游消耗与库存守恒；原事实保留、反向流水追加；PackingList 自动入库转交整单反向 |

重试同一业务意图复用 CommandId/CommandItemId；标识相同而内容不同必须冲突，不能把不确定响应当失败重新生成标识。单据、来源、库存或输入变化后重新预览；成功过账后刷新失败不得显示为过账失败。正常收货/反向不借用 PackingList 负库存特权。

## 6. API、DTO、前端 Model 与复用矩阵

现有接口为 Contracts/Apis/Inventory/IInboundWorkspaceApi.cs，对应 Controller 基址 `api/inventory/inbounds`。下表现有类型均位于 Contracts/DTOs/Inventory/InboundWorkspaceDtos.cs；目标新增项明确标注，接口与类型仅设计，不在本次实现。

| 用例及当前方法 | 契约/目标调整 | 消费者与前端 Model | 复用决定 |
|---|---|---|---|
| search | InboundSearchRequest / InboundListItemDto | 管理列表；InboundSearchModel（目标） | 列表专用，不承担编辑或 Trace |
| GET uid | InboundDetailDto、InboundHeaderDto、InboundLineDto | 当前 API；目标详情使用 InboundEditModel/InboundLineEditModel | 编辑状态不进入 DTO；完整 Trace 不反向复用整个编辑详情 |
| sources/search | InboundSourceSearchRequest / InboundSourceDto；来源改为采购头行，增加其他草稿提示及区分供应商角色 | 当前工作台；目标来源选择模型 | 不复用采购编辑行；Link/Allocation 不作通用必填输入 |
| drafts、PUT drafts/uid | Create/UpdateInboundDraftCommand、InboundDraftLineCommand / InboundCommandResultDto | 目标详情从 EditModel 映射命令 | 创建/更新外层分离；行协议须按身份与版本语义审查，不因现有共用就默认合法 |
| 草稿作废（目标新增） | 专用作废命令，含单据、版本、原因和幂等标识；窄状态结果 | 详情 | 不复用已过账反向命令，不预造 HTTP 路由 |
| post-preview、post | InboundPostCommand / InboundPostPreviewDto 或 CommandResultDto | 详情预览/提交 | 预览与写命令的必填校验分开；结果不得冒充预览 |
| reverse-preview、reverse | InboundReverseCommand / 当前同一 PreviewDto | 反向确认组件 | 核对反向影响语义，不能沿用正向数量算法；若字段/语义不能一致则独立窄预览类型 |

业务 DTO 复用必须满足同概念/角色、字段与单位/空值语义、来源及权限、校验与版本生命周期、至少两个真实消费者、可独立演进。公共分页和响应包装沿用平台规范。一个公开类型一个文件；禁止页面 DTO 桶。结构转换使用 Mapster，来源校验和覆盖计算保持显式。

## 9. PackingList 自动收货与实际退回交接补充

同时读取 [PackingList 地图](PackingList模块能力地图.md)、[出库地图](出库模块能力地图.md)。自动入库先扣可证明的同客户库存，仅补最终产品缺口；必须保留合法已确认采购头行、客户/产品单位/目标仓和剩余可收证明。自动入库计入采购正式净收货，与人工收货按相同采购行合计校验；同源多贡献及跨单并发不得超收。ReadyQty、Allocation、需求覆盖不能替代凭证。归属未知库存不能视为零再次补入库。

客供件 B 仍按实际独立收货，不伪造 B 自动入库；成品补入库不能掩盖 B 缺口。整单反向仅撤销本 PL 生成的自动入库并先处理出库/消耗及下游依赖。真实错发的实际退回是独立来源能力：记录原出货/售后、实收产品数量、客户与接收仓，不冒充采购收货，不预分配枚举或开放通用无凭证入口；未实际收回不增加库存。

INB-008、INV-006、PL-003 共用自动补入库整改，不重复记账。此补充不改变普通采购收货与需求解耦的准入，也不表示退回业务已实现。
