# 入库模块能力地图

核对日期：2026-10-06。本文描述当前工作树实现，不沿用旧阶段计划或以历史测试代替当前验收。业务判断以所列服务、实体和实际调用方为准；新增业务规则须另行确认。全部 HTTP 入口见[业务 API 索引](../../../docs/业务API索引.md)，跨域主线见[业务总纲](../业务架构总纲.md)。

## 职责与事实

入库保存 InboundDocument、InboundDocumentLine；收货来源是真实采购行，不能把 DemandExecutionLink.Uid 当采购行 Uid。需求关联不是所有入库的必填条件。未过账草稿不改变余额，正式库存事实由统一库存过账能力写入。

## 当前能力

| 能力 | 实现 | 契约/消费者 |
| --- | --- | --- |
| 列表、详情 | InboundQueryService | IInboundManagerApi；InboundManager 页面 |
| 采购来源选择及可收容量 | InboundSourceQueryService | IInboundSourceApi、InboundSourcesController；InboundSourcePicker |
| 草稿保存、删除 | InboundDraftService | InboundDraftController；版本、数量、单位及来源资格校验 |
| 过账预览、过账 | InboundPostingService | InboundPostingController；预览令牌和 ExpectedVersion，正式命令复核 |
| 反向预览、反向 | InboundReversalService | InboundReversalController；已过账人工采购收货及库存反向条件 |
| 自动入库内部端口 | AutomaticPostingPorts | PackingList 父事务调用；不经人工页面创建/操作 |

## 关键规则

实际采购可收资格和净收货数量通过入库查询/验证能力计算，不保存需求收货缓存。过账核对采购容量、供应商虚拟仓、产品和单位，写单据状态、流水、余额和审计/回执；父命令失败整体回滚。Preview 不写库存或预占。

人工过账要求 Active、Unposted、Manual、无 TriggerPackingListId；人工反向要求已过账的人工 PurchaseReceipt，并检查当前可反向数量。自动单据由箱单整单反向处理，不通过手工 API 绕开归属。用户操作错误需受控反向，不能清流水或删已过账历史。
