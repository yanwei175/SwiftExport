# 售后模块能力地图

> **2026-09-16 需求反向交接：** 售后确认只把正数量实物要求接入 GrossDemand，不自动拆解或采购。纠错取消确认先要求正式售后交付已反向、采购入库已反向并释放 Link、相关物料修订已手工安全回退；售后随后调用来源退出能力并在同一事务解锁。售后不直接维护需求、采购或库存内部表。

> 2026-09-08：后端第一批已实现并验证，WPF 页面未实施。依据业务总纲“售后事实与来源交接”及 [后端实施与前端交接](../../../docs/售后模块后端实施与前端交接.md)。

## 1. 职责与边界

售后保存一客户多行投诉和实物要求，同一行分别描述问题成品及补发物料。只有 AfterSalesHeader/AfterSalesLine 两张事实表；Supplier 是责任方，费用是人民币行总额，NULL 未定、0 免费、正数付费。不建立采购关系，不写库存或物流事实。

## 2. 能力与权威入口

| 能力 | 权威服务 | 状态 |
|---|---|---|
| 两表保存、分页、详情、窄候选 | IAfterSalesService / AfterSalesRepository | 已实施 |
| 明确确认正数量要求 | IAfterSalesService → ISourceDemandReceptionService | 已实施，NULL/0 不接收 |
| 取消确认并解锁 | 来源安全退出成功后更新售后；物料回退和各执行反向均须事先显式完成 | 当前调用链已实施；正式交付核验仍以需求地图 DP-009 为开放偏差，失败整体回滚 |
| 结案、重开、作废 | IAfterSalesService；来源资格由 ISourceDemandClosureService 检查 | 已实施 |
| 前后事实和命令幂等 | BusinessOperationLog + 稳定 CommandId | 已实施 |
| 模块权限 | Module.QualityControl.Access | 后端目录及操作校验已接线 |
| Manager / Detail | WPF QualityControl Feature | 后续前端计划 |
| 附件及完整进度 | 公共文件能力、来源正式交付查询 | 本批未实施 |
| 无采购特殊出货及自动入出库 | PackingList / 库存领域 | 本批未实施，不伪造采购供货 |

来源映射：SourceType=CR、SourceUid=头 Uid、SourceNo=AfterSalesNo、SourceLineId=行 Uid、DemandQty=正数量。问题成品、责任方和金额不扩入 GrossDemand。物料需求不是交付准入，但取消确认时必须已经安全回退；部分出货与反向由 PackingList/Shipping 管理。

## 3. 页面与命令契约

根路由 `/api/quality-control/after-sales`，Contracts 为 IAfterSalesApi 及 DTOs/QualityControl/AfterSales。Manager 读取去重单头摘要和已知费用/未定费用标记；Detail 读取 Header/Lines/Capabilities，显式提交新增、更新、删除集合。

DocumentStatusEnum 0/8/9 与 ConfirmationStatusEnum 0/1 分离。状态能力不是下游资格预占。确认后锁定事实与行结构，仅允许说明、备注、退回收到日期补充；失败取消不能解锁。正数量须确认且正式交付完成或来源合法关闭才结案；不以已拆解或PL草稿判断完成。重开不重放需求，作废先安全撤回。

## 4. 验收与后续

后端构建通过；33 项针对性测试含 4 项隔离 LocalDB 集成测试通过。业务库只读核验，两表状态 tinyint、无外键/触发器。前端需按实际 DTO、稳定身份、版本、能力和错误协议实施，具体示例见交接文档。

本图不承诺特殊出货已完成。后续涉及供货、单位/仓库、客供件消耗时必须读取需求计划、PackingList、库存、出库对应地图，按各领域明确依据实施。
