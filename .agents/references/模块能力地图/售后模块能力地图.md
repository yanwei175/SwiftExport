# 售后模块能力地图

核对日期：2026-10-06。本文描述当前工作树实现，不沿用旧阶段计划或以历史测试代替当前验收。业务判断以所列服务、实体和实际调用方为准；新增业务规则须另行确认。全部 HTTP 入口见[业务 API 索引](../../../docs/业务API索引.md)，跨域主线见[业务总纲](../业务架构总纲.md)。

## 职责与事实

售后使用 AfterSalesHeader、AfterSalesLine 保存服务事实、客户和认可的补发要求，不直接采购或写库存。来源类型 CR 由确认产生 GrossDemand；单据状态 Open/Closed/Voided 与确认状态分开。

## 当前能力

| 能力 | 实现 | 准入与交接 |
| --- | --- | --- |
| 查询、候选 | AfterSalesQueryService | 查询 Controller，IAfterSalesApi；列表、详情、关联对象候选 |
| 草稿保存、删除 | AfterSalesMaintenanceService | 版本与编辑边界由服务判断，保留历史对象引用 |
| 确认、取消确认 | AfterSalesConfirmationService | 正数量补发行必须有单位；确认调用来源接收，取消调用来源安全退出 |
| 结案、重开、作废 | AfterSalesLifecycleService | 独立命令及公共回执；重开仅 Closed，作废按现有来源保护执行 |
| WPF 管理与详情 | AfterSalesManagerViewModel、AfterSalesDetailViewModel | NavigationRouteRegistry 已注册，消费 IAfterSalesApi；并非“前端尚未实施” |

## 实际限制

有正数量实物要求时，CloseInTransactionAsync 仍返回 AFTERSALES_DELIVERY_QUERY_UNAVAILABLE；SourceDeliveryService.VerifyClosureAsync 也仍明确失败。因此不能把已有来源交付列表或 PackingList 过账等同于售后结案核验完成。源码当前把 CR 来源按交付专用路径处理，不能推断为标准补发已经写入库存。取消确认安全退出与结案完成证明是两个不同能力。

页面要求 QualityControl.AfterSales.View；写、确认和生命周期使用各自具体权限。补发实物交付由 Shipping 管理，实际库存边界以 PackingListPostingFactsResolver 为准。
