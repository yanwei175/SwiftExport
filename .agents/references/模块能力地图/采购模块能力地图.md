# 采购模块能力地图

> 文档性质：采购页面、API 和契约边界的目标权威设计，同时记录当前源码偏差。业务流程、状态和数量事实仍以 `../业务架构总纲.md` 为最高业务依据。

## 1. 模块使命与边界

采购模块负责把已确认的采购执行计划转化为可履约采购单，维护采购单安全草稿和确认状态，并以追加式供应商进度报告支撑跟单。

采购模块不负责：

- 决定 BOM 拆解和净需求数量。
- 直接修改 Allocation 或伪造 DemandExecutionLink。
- 把供应商已备好量写成库存。
- 建立、过账或反向入库单。
- 管理供应商虚拟仓余额和库存流水。
- 维护供应商主数据。

## 2. 能力与上下游

| 能力 | 所属模块 | 上游 | 正式结果 | 下游 |
|---|---|---|---|---|
| 净需求转采购 | DemandPlanning/NetDemand | 活动 NetDemandAllocation | 采购草稿、DemandExecutionLink | 采购订单管理 |
| 采购订单管理 | Procurement/PurchaseOrders | 采购草稿和 Link | 采购头行、确认状态、商务字段 | 跟进、入库来源 |
| 供应商跟进 | Procurement/PurchaseOrders | 有效采购行 | 追加 SupplierProgressReport | 跟单查询、装柜计划 |
| 采购 Trace | Procurement/PurchaseOrders | 采购头行、Link、跟进和入库聚合 | 只读追溯投影 | 审查、导出 |
| 采购入库 | Inventory/Inbounds | 已确认采购行和活动 Link | 入库单、库存流水、余额 | 库存、PackingList |
| 供应商虚拟仓 | Inventory | 活动供应商和库存事实 | WarehouseSite、余额、流水 | 入库、出库 |

## 3. 页面边界

| 页面/组件 | 归属 | 负责 | 禁止承担 |
|---|---|---|---|
| 净需求工作台 | DemandPlanning/NetDemand | 选择可采购 Allocation、发起转采购 | 编辑采购单、登记跟进、收货 |
| 采购草稿 Preview | DemandPlanning/NetDemand | 预览供应商分组、行合并、来源贡献并创建草稿 | 绕过 Preview 修改正式采购事实 |
| 净需求采购选择器 | Procurement 集成组件 | 只选择净需求并转交统一 Preview/Create 用例 | 实现第二套转采购规则 |
| 采购订单工作台 | Procurement/PurchaseOrders | 搜索、列表、只读摘要、打开详情/Trace、进入统一转采购入口 | 完整草稿编辑、重复确认/取消确认编排、登记供应商反馈 |
| 采购订单详情 | Procurement/PurchaseOrders | 编辑允许的草稿字段、保存、确认、取消确认、未保存拦截 | 修改供应商和来源 Link、登记入库、覆盖跟进历史 |
| 采购订单跟进 | Procurement/PurchaseOrders | 跟进筛选、采购行浏览、追加反馈、纠错原因、历史展示 | 修改采购数量、采购商务字段、库存或入库事实 |
| 采购 Trace | Procurement/PurchaseOrders | 只读显示需求来源、Link、跟进、入库和操作日志，支持导出 | 执行任何写命令 |
| 入库工作台 | Inventory/Inbounds | 可收来源、入库草稿、Preview、过账和反向 | 修改采购单、Allocation 或 SupplierProgressReport |

采购订单详情是采购草稿和确认命令的唯一页面编排入口。采购工作台只负责发现、摘要和导航，避免同一命令在两个 ViewModel 中复制。

## 4. 状态与命令边界

| 命令 | 页面入口 | 允许条件摘要 | 权威服务 | 禁止副作用 |
|---|---|---|---|---|
| Preview/Create 采购草稿 | 净需求工作台/Preview | Allocation 活动、供应商明确、剩余量和版本有效 | DemandPlanning PurchaseDraft Service | 自动确认或入库 |
| 更新采购草稿 | 采购订单详情 | Active + 待确认、版本匹配、无不安全下游 | PurchaseOrder Application Service | 修改数量、供应商或 Link |
| 确认采购 | 采购订单详情 | 资料、价格、Link 和送达关系有效 | PurchaseOrder Application Service | 自动产生入库 |
| 取消确认 | 采购订单详情 | 无正式收货/库存事实、原因有效 | PurchaseOrder Application Service | 删除历史或 Link |
| 追加供应商反馈 | 采购订单跟进 | 采购行有效；累计量下降时有修正原因 | SupplierProgress Application Service | 覆盖旧报告或更新库存 |
| 入库过账/反向 | 入库工作台 | 来源可证明、Preview 和版本有效 | Inventory Posting Service | 回写采购 ReadyQty |

## 5. 目标 API 用例边界

| API 边界 | 用例 |
|---|---|
| PurchaseOrder Management | 搜索采购单、读取详情、更新安全草稿、确认、取消确认 |
| Supplier Progress | 跟进专用搜索、读取采购行跟进详情、读取历史、追加报告 |
| PurchaseOrder Trace | 读取采购全链追溯和导出所需只读数据 |
| NetDemand Purchase Draft | Preview、创建、取消安全草稿和减量释放 |
| Inventory Inbound | 搜索入库单、选择可收来源、草稿、过账 Preview/执行、反向 Preview/执行 |

目标上不要求一次性重命名所有接口，但新增方法必须进入正确能力边界；触碰现有混合接口时应先提醒拆分。

## 6. DTO 与前端 Model 矩阵

| 用例 | 目标契约 | 前端模型 | 复用边界 |
|---|---|---|---|
| 采购管理搜索 | `PurchaseOrderSearchRequest`、`PurchaseOrderListItemDto` | 页面 SearchModel 或只读列表项 | 只服务采购管理列表；不与跟进列表默认复用 |
| 采购详情 | `PurchaseOrderDetailDto`、`PurchaseOrderLineDetailDto` | `PurchaseOrderHeaderEditorModel`、`PurchaseOrderLineEditModel` | 详情契约不承担完整 Trace/跟进历史 |
| 草稿更新 | `UpdatePurchaseOrderDraftCommand`、`UpdatePurchaseOrderDraftLineCommand`、`PurchaseOrderCommandResult` | 由 EditModel 生成命令 | 不复用查询 DTO 作命令 |
| 确认/取消确认 | `ConfirmPurchaseOrderCommand`、`CancelPurchaseOrderConfirmationCommand`、`PurchaseOrderCommandResult` | ViewModel 命令参数 | 仅同生命周期命令可共享窄结果 |
| 跟进搜索 | `PurchaseOrderProgressSearchRequest`、`PurchaseOrderProgressListItemDto` | 跟进 SearchModel/只读行模型 | 与采购管理列表分离演进 |
| 跟进详情与历史 | `PurchaseOrderProgressDetailDto`、`SupplierProgressReportDto` | `PurchaseOrderProgressLineModel`、反馈 EditModel | 历史 DTO 可在跟进详情和 Trace 中按相同只读语义复用 |
| 跟进报告 | `ReportSupplierProgressCommand`、`SupplierProgressReportResult` | 反馈 EditModel | 不复用采购草稿更新命令或通用结果 |
| 采购 Trace | `PurchaseOrderTraceDto`、`PurchaseOrderSourceContributionDto`、`PurchaseOrderReceiptTraceItemDto`、`BusinessOperationTraceItemDto` | 只读展示模型或直接绑定 | 不参与保存 |
| 入库来源 | `InboundSourceDto` 及 Inventory 专用命令 | 入库选择/编辑 Model | 不复用采购详情行 DTO |

契约文件遵守“一公开类型一文件”；复用必须满足 DTO 复用门禁。DTO 与前端 Model 的结构性转换集中使用 Mapster，业务状态判断保持显式。

## 7. 当前源码事实

当前已经存在：

- `PurchaseOrderWorkspaceView`、`PurchaseOrderDetailView`、`PurchaseOrderProgressWorkspaceView` 和 `PurchaseOrderTraceView`。

## 8. 已知偏差账本

| ID | 当前偏差 | 影响 | 触碰时最小治理方向 |
|---|---|---|---|
| PROC-001 | `PurchaseOrderWorkspaceDtos.cs` 包含 14 个公开契约 | 文件职责和变更影响不清 | 本次触碰的类型先拆为同名文件，不批量重写无关类型 |
| PROC-002 | `IPurchaseOrderWorkspaceApi` 同时承载管理、跟进和 Trace | 能力边界与权限演进耦合 | 新增相关方法前按 Management/Progress/Trace 拆分接口或给出兼容迁移计划 |
| PROC-003 | 采购管理与跟进共用 `PurchaseOrderSearchRequest`、`PurchaseOrderListItemDto` | 跟进字段会污染通用列表 | 跟进需求变化时建立 Progress 专用 Search/List 契约 |
| PROC-004 | 采购工作台和详情都实现保存、确认、取消确认 | 命令 UI 编排重复，行为可能漂移 | 写命令集中到详情；工作台保留摘要、导航和统一入口 |
| PROC-005 | `PurchaseOrderLineEditorModel` 同时服务编辑与跟进展示 | 编辑状态和只读跟进职责混合 | 分为 EditModel 与 ProgressLineModel |
| PROC-006 | `PurchaseOrderDetailDto`/Line 同时携带来源贡献、跟进和操作历史 | 详情契约过宽，查询成本和权限耦合 | 详情保留必要摘要，完整历史迁入 Progress/Trace 契约 |
| PROC-007 | Header `Load` 和 Line `FromDto` 大量手写逐字段转换 | 容易漏字段并违背 Mapster 门禁 | 触碰映射时迁入前端 MapsterConfig，模型只保留窄适配入口 |
| PROC-008 | `PurchaseOrderDocumentOpenRequest` 声明在 ViewModel 文件 | 一个公开类型一文件和模型组织不一致 | 触碰时移动到 Models/Requests 独立文件 |

## 9. Agent 执行门禁

采购相关任务开始前必须读取本地图并核对真实源码：

- 未触碰偏差：正常执行，最终说明相关已知债务。
- 修改或复制上述偏差：先输出门禁偏差提醒，引用偏差 ID，给出最小重构与兼容方案，然后暂停等待用户决定。
- 用户未授权时不得自动执行跨页面、跨 API 或跨 Contracts 的重构。
- 新发现偏差必须补入本地图或在任务交付中明确提出治理更新建议。

## 10. 验收场景

- 新增采购跟进筛选时使用 Progress 专用契约，不扩张采购管理列表 DTO。
- 修改采购工作台时不新增草稿保存、确认或跟进写命令。
- 修改采购详情时所有写命令仍经 Application Service，并保留版本和状态校验。
- 新增收货能力时进入 Inventory/Inbounds，不写入采购页面。
- Trace 页面保持只读，查询数量来自 Link、SupplierProgressReport、入库和流水聚合。
