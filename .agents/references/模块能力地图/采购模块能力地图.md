# 采购模块能力地图

核对日期：2026-10-06。本文描述当前工作树实现，不沿用旧阶段计划或以历史测试代替当前验收。业务判断以所列服务、实体和实际调用方为准；新增业务规则须另行确认。全部 HTTP 入口见[业务 API 索引](../../../docs/业务API索引.md)，跨域主线见[业务总纲](../业务架构总纲.md)。

## 职责与事实

采购保存实际供货承诺、客户、供应商、数量和单位价格快照；需求关联可选。权威实体是 PurchaseOrderHead、PurchaseOrderLine、DemandExecutionLink。Active/Closed/Voided 生命周期与确认状态分离；收货和跟进由查询事实计算。

## 当前能力

| 用例 | Application 实现 | 契约/页面 |
| --- | --- | --- |
| 采购管理列表及展开行 | PurchaseOrderManagerQueryService | IPurchaseOrderManagerApi；PurchaseOrderManagerViewModel |
| 详情/普通查询 | ProcurementOrderQueryService | IProcurementOrderApi；PurchaseOrderDetailViewModel |
| 物料候选、预览、批量创建 | PurchaseDraftCandidateService、PurchaseDraftPreviewService、PurchaseDraftCreationService | IPurchaseDraftApi；准备、候选、预览及结果页面 |
| 独立草稿保存及编辑 | ProcurementOrderDraftService | IProcurementOrderApi，独立采购不伪造物料来源 |
| 确认 | ProcurementOrderConfirmationService、ProcurementConfirmationBuilder | 确认依据指纹、版本及活动引用重验 |
| 取消确认、删行、作废 | ProcurementOrderReversalService | 反向预览/命令，下游事实阻断；取消确认不释放 Link |
| 补关联物料 | ProcurementDemandAssociationService | 增加贡献时核对未关联量、根子关系及容量 |
| 跟进和供应商报告 | PurchaseOrderProgressQueryService、PurchaseOrderProgressReportService | IPurchaseOrderProgressApi；独立跟进页面 |
| Trace | PurchaseOrderTraceService | IPurchaseOrderTraceApi；只读追溯 |

## 关键边界

确认只校验实际采购头行、活动引用、客户/供应商/产品/单位及金额；确认前 TaxPrice 必须明确，零价允许。确认不读取当前 BOM、不创建新 PurchaseConfirmationLine/Node、不选择收货仓；ActiveConfirmationId 是批次标识。PackingList 的当前实际执行依据来自物料拆解和 PO Link，而不是新采购 BOM 快照。

实际供应商由采购输入决定，推荐供应商不构成硬约束。客供件需要明确送达供应商；仓库由入库用例确定。草稿贡献按 AllocatedQty-ReleasedQty 计算；独立未关联量 UnlinkedQty 与贡献总和必须等于采购数量。预览不预留，正式命令事务内重验。

旧 Workspace 聚合契约不能按旧 PROC 偏差表恢复；实际公开 API 已按 Manager、Order、Draft、Progress、Trace 分开，以当前文件为准。管理页读权限为 Procurement.Order.Read，编辑/确认/反向/跟进使用独立权限。
