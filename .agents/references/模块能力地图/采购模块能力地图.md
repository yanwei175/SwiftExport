# 采购模块能力地图

核对日期：2026-10-20。本文描述当前工作树实现，不沿用旧阶段计划或以历史测试代替当前验收。业务判断以所列服务、实体和实际调用方为准；新增业务规则须另行确认。全部 HTTP 入口见[业务 API 索引](../../../docs/业务API索引.md)，跨域主线见[业务总纲](../业务架构总纲.md)。

## 职责与事实

采购保存实际供货承诺、客户、供应商、数量和单位价格快照；需求关联可选。权威实体是 PurchaseOrderHead、PurchaseOrderLine、DemandExecutionLink。Active/Closed/Voided 生命周期与确认状态分离。采购管理维护订单事实、基本来源关联及生命周期；收货和跟进进度统一由订单跟踪查询，供应商反馈仍由采购写入用例追加。

## 关键边界

确认只校验实际采购头行、活动引用、客户/供应商/产品/单位及金额；创建、草稿保存、确认预检和正式确认统一要求 UnitPrice 与 TaxPrice 明确填写，允许零价，非负且最多四位小数。详情草稿提供两价输入；金额由服务端按数量乘对应单价并以 AwayFromZero 舍入至四位，确认预检与正式确认共用价格和金额一致性检查，正式确认仍在事务内重验。确认不读取当前 BOM、不创建新 PurchaseConfirmationLine/Node、不选择收货仓；ActiveConfirmationId 是批次标识。PackingList 的当前实际执行依据来自物料拆解和 PO Link，而不是新采购 BOM 快照。

实际供应商由采购输入决定，推荐供应商不构成硬约束。客供件需要明确送达供应商；仓库由入库用例确定。草稿贡献按 AllocatedQty-ReleasedQty 计算；独立未关联量 UnlinkedQty 与贡献总和必须等于采购数量。预览不预留，正式命令事务内重验。

非空 BONO 在全部未软删除采购订单中唯一，关闭、作废和已确认仍占号，空号不占；采用首尾普通空格修剪及现有 CI 比较。独立创建与需求转采购的新建都复核，显式追加与幂等重放保持原边界，不自动合并同号订单。实体基线与增量脚本已提供，尚未执行实库迁移或并发验收，详见 [BONO 升级说明](../../../docs/采购BONO唯一限制与升级说明.md)。

管理列表由数据库完成筛选、计数和分页，子表按当前采购单全量加载。客户代码与实际供应商支持多选；兼容选择器的旧单值条件与多选条件取交集。管理分页和全量子表不计算货好、收货、预计完成及交期风险；这些进度由订单跟踪采购单视角承接。正式收货异常仍按相关采购行及整入库头证据核实，未知不能用零代替。生命周期资格所需的下游阻断检查继续保留，不因进度查询迁出而删除。

管理子表展示有效需求贡献、未关联量、关联状态和来源概况；完整贡献及释放历史仍保留专用读取能力；管理页不再提供跨阶段 Trace 入口。正常作废单的当前关联摘要为“不适用”，不回写原未关联数量；异常活动引用仍需核实。确认与补关联共用已有引用的客户、产品、单位、实物依据及容量检查，保留请求版本防并发和取消确认不释放 Link 的边界。

客户端管理页与详情页共享按用户和采购身份保存的未决命令。结果未知时冻结首次完整负载，重试保留 CommandId；批量确认停止后续提交。写入成功后的查询失败只触发读取恢复，不重新生成写命令；页面的勾选、筛选、未保存和 Busy 状态不进入共享契约。

旧 Workspace 聚合契约不能按旧 PROC 偏差表恢复；实际公开 API 已按 Manager、Order、Draft、Progress、Trace 分开，以当前文件为准。管理页读权限为 Procurement.Order.Read，编辑/确认/反向/跟进使用独立权限。

## 2026-10-20 草稿数量及直接创建调整（已提交并合并原目录，未推送）

用户已确认取消从物料需求转采购的独立审核页面。准备页直接提交明确创建命令，服务端按 NetDemandId、版本及用户输入持锁重读事实；不再以整份预览 Token 或 SKU/LinkSku 展示快照一致性作为创建门槛。真实来源依据、客供关系、数量容量、权限和幂等仍需校验。

PO Link 在创建草稿时保留来源关系和占用。查询区分已确认采购量 PurchasedQty 与未确认草稿占用 DraftOccupiedQty；未采购量为需求量减已采购量，可创建量还需扣除草稿占用。取消确认只将数量转回草稿占用，不释放 Link；删除、删行和作废按各自资格释放占用。LinkStatus 不重复保存采购确认状态；数量异常或目标缺失不能当零放行。

整单删除草稿采用独立命令，要求从未确认、没有下游历史、活动待确认、头及全量行版本一致；头行逻辑删除、Link 取消释放及命令回执在同一事务执行。曾确认的单据沿用取消确认与作废，不能以当前确认标识为空证明从未确认。草稿商务编辑白名单不扩大为数量或产品自由修改。

相同命令重试读取持久回执，删除后重放创建命令也不得复建；不同命令并发按已采购加草稿占用的总容量控制。新建、追加、补关联和来源回退使用一致占用边界。本轮成果已提交并合并原目录，未推送；验收范围沿用本轮测试记录，合并不代表部署。

### 多供应商创建与未知结果恢复

一次来源创建或追加多张采购单时，同一来源命令只写一条汇总审计，结构化关联完整采购单列表；每张采购单的 Trace 可定位该事件。命令回执与审计唯一约束保持有效，不以重复写审计或放宽约束替代批次语义。

只有在命令锁下确认不存在旧回执、本次从未尝试提交且实际回滚成功时，创建接口才将未预期写入异常返回为确定的 WRITE_FAILED。回执读取失败、提交结果不明或提交后清理异常仍按未知结果处理，不能推断原命令未执行。

采购准备页在应用内按当前用户和 API 环境保留未决请求及完整输入，不读写本地恢复文件、不加密落盘。进行中的请求仍受关闭保护，已返回未知后允许保留会话关闭弹窗；同一客户端进程中重开优先恢复原执行身份，由用户显式重试，不自动创建或用新身份替代。确定结果才清理对应未决会话，退出客户端后不提供恢复；关闭弹窗或退出客户端均不代表服务端取消。

## 2026-10-20 采购管理事实化与采购单跟踪（本轮实施，尚未提交合并）

用户确认采购管理与销售管理采用相同职责边界。管理保留单号、客户和实际供应商、产品快照、数量单位、价格金额、约定和回复交期、基本来源关联、生命周期操作及其后端资格校验。供应商反馈累计货好量、预计完成时间、收货数量与状态、交期风险及跨阶段证据统一进入 OrderTracking/PurchaseOrders。

采购单视角按采购头分页，指定采购单有效行全量加载，不继承主表关键词、状态或日期筛选；独立采购单无需伪造物料需求或 Link。需求视角保持贡献语义，采购视角按采购行读取整行收货事实，不重复计入每条需求。

新查询基础权限为 OrderTracking.View 加 Procurement.Order.Read。反馈维度额外要求 Procurement.Progress.View；收货维度额外要求 Inventory.Inbound.View。无权维度不读取敏感事实，返回明确可见性及空进度；使用对应维度筛选时拒绝请求。完整反馈与收货证据独立读取，不能因一个区域失败抹掉订单事实。

供应商反馈入口收窄为选单、选行和追加反馈，不另设完整收货进度看板。采购创建、确认、取消确认、删除草稿、作废及需求关联命令不迁入只读跟踪服务；本次不改变草稿占用、确认计已采购量、取消确认不释放 Link 的规则，也不新增数据库实体或持久化进度状态。

新建专用跟踪搜索、头摘要、全量行和收货区域 DTO，避免继承或扩张管理事实 DTO。复用 SupplierProgressReportDto 的不可覆盖反馈事实，以及现有 DemandTrackingReceiptDto/PurchaseLineReceiptProgressDto 的采购整行证据语义；它们的整行数据不等于需求实收份额。验收记录完成后追加，不以本文说明代替运行结果。
