# 采购模块能力地图

核对日期：2026-10-19。本文描述当前工作树实现，不沿用旧阶段计划或以历史测试代替当前验收。业务判断以所列服务、实体和实际调用方为准；新增业务规则须另行确认。全部 HTTP 入口见[业务 API 索引](../../../docs/业务API索引.md)，跨域主线见[业务总纲](../业务架构总纲.md)。

## 职责与事实

采购保存实际供货承诺、客户、供应商、数量和单位价格快照；需求关联可选。权威实体是 PurchaseOrderHead、PurchaseOrderLine、DemandExecutionLink。Active/Closed/Voided 生命周期与确认状态分离；收货和跟进由查询事实计算。

## 关键边界

确认只校验实际采购头行、活动引用、客户/供应商/产品/单位及金额；确认前 TaxPrice 必须明确，零价允许。确认不读取当前 BOM、不创建新 PurchaseConfirmationLine/Node、不选择收货仓；ActiveConfirmationId 是批次标识。PackingList 的当前实际执行依据来自物料拆解和 PO Link，而不是新采购 BOM 快照。

实际供应商由采购输入决定，推荐供应商不构成硬约束。客供件需要明确送达供应商；仓库由入库用例确定。草稿贡献按 AllocatedQty-ReleasedQty 计算；独立未关联量 UnlinkedQty 与贡献总和必须等于采购数量。预览不预留，正式命令事务内重验。

非空 BONO 在全部未软删除采购订单中唯一，关闭、作废和已确认仍占号，空号不占；采用首尾普通空格修剪及现有 CI 比较。独立创建与需求转采购的新建都复核，显式追加与幂等重放保持原边界，不自动合并同号订单。实体基线与增量脚本已提供，尚未执行实库迁移或并发验收，详见 [BONO 升级说明](../../../docs/采购BONO唯一限制与升级说明.md)。

管理列表由数据库完成筛选、计数和分页，子表按当前采购单全量加载。客户代码与实际供应商支持多选；兼容选择器的旧单值条件与多选条件取交集。正式收货异常按相关采购行及整入库头证据核实，不因无关历史阻断列表；数量无法核实时返回空值并提供原因，不能用零代替未知。

管理子表展示有效需求贡献、未关联量、关联状态和来源概况；完整贡献及释放历史继续由 Trace 提供。正常作废单的当前关联摘要为“不适用”，不回写原未关联数量；异常活动引用仍需核实。确认与补关联共用已有引用的客户、产品、单位、实物依据及容量检查，保留请求版本防并发和取消确认不释放 Link 的边界。

客户端管理页与详情页共享按用户和采购身份保存的未决命令。结果未知时冻结首次完整负载，重试保留 CommandId；批量确认停止后续提交。写入成功后的查询失败只触发读取恢复，不重新生成写命令；页面的勾选、筛选、未保存和 Busy 状态不进入共享契约。

旧 Workspace 聚合契约不能按旧 PROC 偏差表恢复；实际公开 API 已按 Manager、Order、Draft、Progress、Trace 分开，以当前文件为准。管理页读权限为 Procurement.Order.Read，编辑/确认/反向/跟进使用独立权限。
