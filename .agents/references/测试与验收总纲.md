# 测试与验收总纲

执行规则更新：2026-10-15。本纲是验证选择、复用和重测的统一入口；不改写历史业务验收结论。具体技术检查仍按对应Skill和本任务真实风险执行。

## 验证层次

| 证据 | 能证明 | 不能证明 |
| --- | --- | --- |
| 源码/引用核对 | 当前入口、字段、调用方向、约束表达 | 已部署、当前数据合法、运行成功 |
| 受影响项目构建 | 该配置下编译及引用可用 | 业务行为或真实数据库并发 |
| 离线单元/契约测试 | 实际执行的策略、传输和边界场景 | 模拟仓储之外的PG锁/事务/方言 |
| 真实PG定向测试 | 明确实例、结构、数据和源码批次的实际场景 | 未运行路径、所有组合、运行库已验收 |
| 宿主/API测试 | 对应请求、身份和HTTP行为 | 未调用端点或完整WPF操作 |
| 客户端人工/专项测试 | 已执行界面及生命周期场景 | 后端所有状态或业务库保护 |

## 选择与时间控制

| 范围 | 适用条件与执行 |
| --- | --- |
| 静态检查 | 纯规则/文档/无行为注释：引用、结构和diff；不因此运行业务构建、测试或数据库 |
| 日常定向（默认） | 明确局部实现：受影响项目或测试项目构建及必要的相关方法/类测试，不默认整项目回归 |
| 模块验证 | 模块完成、跨模块集成或重要业务行为：模块与真实受影响消费者；API/PG/WPF按风险选择 |
| 阶段完整回归 | 阶段合并、发布、最终验收或重大共享基础设施变化：相关完整集合及跨模块兼容，不遍历无关历史专项入口 |

按可观察行为和依赖选择范围，不按文件数。公共会话、事务、异常、映射、DI、数据库约束变化扩大到受影响消费者；订单确认/过账/反向、库存、权限、事务和并发不能以“小改”为由跳过下面的必要场景。数据库特性改变仍需授权环境实证，不能等到发布前才补关键定向验证。

同一次有效读取、构建或测试可满足多个入口；直接一次定向test可同时完成必要构建，不强制先build再test。已有相同工作树内容/依赖、配置、环境和覆盖范围的证据可复用；目标或依赖、测试、资源/生成产物、配置、环境变化，或有具体失败/风险时，只重做受影响部分。仅构建产品项目不证明测试程序集已构建，只有对应测试产物有效才使用`--no-build`；`--no-restore`同样需有效资产。filter缩小执行而不缩小项目编译，不能静默排除无关编译失败文件制造成功。

修Bug先用已有证据或最小相关复现建立失败基线，不为基线先跑全量。修复后优先重跑失败方法/类及受同一原因影响的场景；定向通过后仅在依赖影响、模块/阶段收口需要时扩大。没有新变化或诊断信息不重复相同无关集合。失败区分本次回归、既有失败或环境；范围外只记录，不删除有效断言、不改业务语义、不无限修复。

实现变化不要求无条件修改Test文件。现有测试直接覆盖时复用定向测试；新行为、未覆盖回归、关键不变量或协议变化才新增/调整覆盖。接口变化可最小更新替身，夹具或断言修改须有有效业务契约依据，不能只为通过而放宽保护。

完整WPF客户端启动、全页面人工操作、截图分析不作为日常默认完成条件；Dispatcher/绑定/焦点/原生编辑等依赖使用必要的定向STA/WPF测试，视觉/主题/布局或明确视觉验收目标才按需采图。模块/阶段验收或共享壳层/主题风险再选择完整UI流程；截图不能替代行为断言。

交付记录真实命令、项目/筛选范围、工作树/依赖与配置身份、结果及未运行项；复用注明来源，不把旧TRX当当前代码通过。多个任务的公共构建/阶段回归由明确的验收执行者整合，同源专项与主项目不无条件双跑。

## 业务风险对应的定向场景

- 单据草稿：真实读写边界、版本冲突、合法/非法输入、权限拒绝与失败回滚。
- 确认/取消、建立/回退：来源版本、请求指纹与重复命令重放（`command_receipt`）、活动贡献、历史完整性和跨域父事务；正式命令在事务内重验，不依赖预览依据指纹或 Preview Token。
- 采购及收货：实际供应商/单位、已收容量、取消确认保留贡献、删行/作废释放、并发容量复核。
- 库存：负库存拒绝、空余额首次创建、幂等指纹、行锁（`FOR UPDATE`）的稳定加锁顺序、反向守恒及流水不可变。
- 箱单：同来源多行合计与并发额度、标准自动单据/客供件、非标和CR仅交付、整单反向及执行证据一致。
- 权限：有效账号/角色投影、未知键拒绝、独立操作键、最后管理员、客户端可见性与后端拒绝；测试断言每个端点都有 `[RequirePermission]` 声明。
- 客户端：编辑保留、取消/过期结果、Busy/重复提交、网络结果不明时保留CommandId和原输入。

以上是按相关改动选择的场景，不要求文档任务或小改动机械运行全部。单据命令的通用技术矩阵（未授权 403、成功、版本冲突 409、同 CommandId 重放、同 CommandId 不同内容 422、并发、提交结果未知 503）见 [后端架构治理文档第 13 节](../../Handoff/Claude/Backend-Architecture-Guide.md)。售后正数量结案仍有明确阻断，销售不存在的商业修订/恢复不能写为已验收入口。

## 数据及协作保护

锁、事务、SQL方言、并发版本和约束依赖变化安排真实PG验证。明确实例、库名、初始化/清理和允许写入范围，独立测试库或串行执行；禁止多个窗口同时重置dv_next_pg_failure_tests_20261004。已有结构和数据、备份库及运行库保护仍有效，历史“测试库”描述不自动授予破坏性操作。

同文件只有一个写入任务，主控管理公共文件和阶段验收，子任务不得跨边界顺手修复。文档整理核对引用、事实和diff，并证明未改变源码；无需因此构建或访问数据库。
