# 来源需求收窄第三步：交付与生命周期收口

状态：已实施（2026-09-09）；常规测试仍有既有跨模块与旧销售契约失败，见文末实施记录。前置：[第二步](来源需求收窄-02-物料建立交接.md)。本步只迁移来源服务当前承担的交付/结案职责，不重做 PL、采购、入库或库存模块。

## 责任与必要修改

1. 来源保留有效需求内容、生命周期、来源版本和需求并发版本的窄读取/锁定契约。PL 始终通过 GrossDemandId 确定要求，不重新从销售或售后列表建立第二交付入口。
2. `SourceDemandDeliveryService.cs`、`IGrossDemandRepository.cs`、`GrossDemandRepository.cs` 中 DeliveredQty/RemainingQty 与正式出库聚合迁到交付职责，由现有 Shipping 用例/查询仓储优先接手；需要窄端口才新增。`SourceDemandDeliveryItemDto`、对应 API/Controller 的真实消费者同步切换。旧接口迁移期单向转发到唯一实现，不保留两套可发量公式。迁出后来源本体不查询 Outbound 或维护已发缓存。
3. 当前 `PackingListService` / `PackingListRepository` 只实现查询、选源和草稿事务：直接按 `GrossDemandId` 校验有效要求与正式 PackingList 交付余额，不依赖拆解、Allocation 或采购。正式提交、供货和库存复核属于后续 PL-003，不得把草稿保存描述成已完成过账闭环。
4. `SourceDemandClosureService.cs`、相关接口/仓储以及 `AfterSalesService.CloseAsync`：售后自己决定结案，使用来源要求与交付证据；保留未完成不能冒充完成的现有规则。迁移后清理无调用者的来源结案服务，不改变售后业务条件。
5. 订单池归属、IsInventoryActionAllowed 和统一 CR 阻断从来源本体移交实际交付/库存上下文。普通无客供件交付不因缺订单池拒绝；实际消耗必须有合法池、预览批准及事务复核，不因客户/SKU 相同借池，不重复扣料。若接手模块尚缺能力，记录明确缺口并保留原保护，不能用空值/默认放行完成迁移。
6. 复查来源生命周期检查已由第二步交接：安全历史结论由编排在同事务取得，来源根据自身条件执行状态变更，不接受客户端任意传入“已安全”布尔值。不得级联撤销采购或库存事实。

服务和 DTO 不作整套结构整理；DI 仅随实际职责变更更新。采购独立供货和当前库存规则继续遵循既有授权边界。

## 字段退出门禁

`GrossDemand.DecompositionStatus/DecompositionRevision/DecomposedAt/DecomposedBy` 本系列仅弃用保留。输出完整读写消费者清单，确认建立、回退、手工编辑、来源取消确认、历史保护、DTO、查询、测试和 FreshInstall/增量脚本依赖均有替代；拆解修订及审计历史在物料侧可证明，不根据 SKU 或最新 BOM 补历史。

即使代码不再使用，本次也不执行数据库删列。后续独立迁移先只读预检，报告历史缺口、约束与索引依赖；未完成映射保留旧列，不以移除实体属性冒充数据库完成。SourceVersion、Version、需求生命周期不列入弃用。

## 最终验收

- 来源本体可以在没有物料、采购、出入库记录时完成销售/售后接收与查询，保持幂等及版本保护。
- 来源服务不编排物料、不输出执行进度/完成率、不计算售后结案或库存池准入。
- PL 仍以来源需求为唯一要求入口；多 PL 并发不超交付，旧预览遭遇来源更新/终止必须失败，命令重放不重复出库；正式反向净额只计算一次。
- 售后来源与销售来源额度隔离，结案拒绝缺失或不完整的交付证据；有/无客供件分别验证。
- 隔离 SQL 测试覆盖跨事务并发与回滚；Application 全量、后端构建及涉及的 WPF 测试/构建通过。环境不满足须报告未验证项，不放宽断言。
- 检查最终 diff，保留用户既有修改；逐项记录迁出能力、接手接口、兼容残留和仍保留的弃用列。跨域交接未完成时标为部分完成。

## 实施记录（2026-09-09）

- 新增 Shipping 边界 `ISourceDeliveryService`、`ISourceDeliveryRepository` 及其实现。正式已发、剩余可交付量、事务内额度复核和结案交付证据由 Shipping 统一计算；`GrossDemandRepository` 不再查询 `OutboundDocument/OutboundDocumentLine`。
- 旧 `SourceDeliverySql` 及其仓储端口已清理。`ISourceDeliveryService` 暂保留兼容边界，但在正式交付事实尚未接入时明确返回 `DELIVERY_QUERY_UNAVAILABLE`，不以零或空列表冒充已交付证据。
- 2026-09-16 PackingList 已完成查询、来源候选和草稿创建/更新/删除；其专用仓储按有效且已过账的 `PackingListHead` / `PackingListLine` 计算草稿额度。预览、正式提交、库存动作、反向和结案证明仍未接入 Shipping 通用交付边界。
- 售后结案改由 `AfterSalesService` 调用 Shipping 的交付证据校验。旧 `ISourceDemandClosureService/Repository` 及实现已移除；来源需求服务不再决定售后完成率或结案。
- 订单池门禁已收窄到本次实际产生正数客供件消耗的行。普通交付以及不消耗客供件的投诉补货不再因缺销售订单池阻断；一旦实际扣用客供件，预览与事务内提交都会要求唯一可证明的销售订单池归属。投诉补货未来若需要消耗客供件，仍缺独立订单池归属模型，因此当前会明确阻断，不会默认借池。
