# 全链路验收与切换

## 前置与最小完整场景

前五领域完成接口及兼容接线后再执行。使用隔离测试数据，不对生产库直接跑场景。

1. 销售单 S1 含 A、B；另有同客户销售单 S2。
2. S1 手工或导入创建采购，不为采购伪造物料需求/Allocation；销售事实应已幂等接收为来源需求；确认采用 A→X×2、B→X×1 的组成。
3. 跟单为 S1 在供应商仓 W 登记 X100 实收，S2 同仓 X100 单独归属。
4. PL 为 S1 发 A30、B20：预览非客供件必要入库/客户出库、X80 消耗；取消则库存与单据无变化。
5. 用户确认后 S1 X剩20，S2 X仍100；成品若无历史余额，本次入出相抵；采购净收货及销售交付正确，X消耗不计销售已发。
6. 第二单需要 S1 X30 时阻断，不能借 S2 的 X；普通确认不能绕过。预览失效重新确认，重复提交不重复记账。
7. 纠错反向恢复原池与采购/交付净额，历史依据保留；有后续依赖时按规则拒绝，不按新 BOM 重算。
8. 再验证需求转采购链：同单多需求合并、部分采购/到货/出货，结果与独立采购使用同一库存执行能力。

## 分层验证证据

新增必验：销售事实及品质售后认可实物行幂等汇聚来源需求；重复同步无重复可发量；未拆物料需求即可进入 PL；PL 只能从来源需求选源；旧来源版本或关闭/终止使预览失效；不同售后意图可区分，补发不双计原销售履约；非销售来源无订单池证明时不能自动借料。必须先验阶段 0，不能仅验证销售链后宣称汇聚口已完成。

| 层 | 必须证明 |
|---|---|
| Contracts | 销售/采购/库存/PL 输入输出对齐，旧消费者兼容边界明确，DTO 查询字段不泄露到写命令 |
| Application | 订单一致性、用量计算、预览确认、普通与特殊权限分离、幂等、取消无写入 |
| Repository/数据库 | 同源容量、同池并发、唯一约束、事务回滚、总池对账，不只做源码字符串测试 |
| WPF | 毛需求无逐层必经操作，实际订单/仓库清楚，确认明细和取消路径、重复点击、过期结果正确 |
| 查询 | 销售不再强 Join Allocation，先聚合防倍增，未知不当零，已发不含消耗 |

## 切换步骤

- 盘点待发草稿、已确认采购、历史 PL/库存，准备备份、迁移预览、异常清单和回退方案。
- 按实际选定方案先加字段/表和兼容读取，核实并回填有证明的销售归属/执行来源；未知记录独立处理。
- 完成新写入链与销售聚合后，比较关键数量和历史追溯；切换不能同时开放两套独立扣减入口。
- 上线失败优先停止新写入并恢复兼容服务；已发生新正式交易后不能靠删新列回退，需对账及有审计的补偿方案。
- 更新原模块偏差 ID，仅关闭有测试/运行证据的项目，不把计划落盘标为修复。
