# 来源需求收窄第一步：本体与查询

状态：已实施（2026-09-09）。依据：[现状核对](来源需求职责与依赖核对-2026-09-08.md)。本系列共三步，顺序实施，每步独立验收；本计划不授权自动实施其他领域完整功能。

## 全系列边界

来源需求统一维护销售、品控/售后认可的实物要求、来源身份、版本、生命周期和接收审计。上游确认与幂等接收在同一事务；纯投诉不生成实物需求。物料需求是下一级，在自己的页面选择来源建立。来源需求不承担 BOM 明细、单据进度、需求完成率、库存池资格或售后结案判断。

本系列不批量重命名、不重建采购/库存、不删除 Allocation、不扩展商业修订。跨领域只迁移现有真实调用所必需的接口和行为；未接手前保留旧有效查询、安全检查及事务保护。既有手工需求规则不擅自改变。

数据库字段只先在实体 XML 注释中标记“弃用候选、兼容保留、禁止新依赖”；不加 NotMapped，不改变类型、默认值或持久化行为，不执行 DROP COLUMN。待消费者全部迁移、历史依据可证明后另行设计只读预检和迁移。

## 本步实施

1. 来源管理查询仅保留来源身份、版本、客户、需求产品单位快照、数量、交期、生命周期、审计和来源导航。移除 ExecutionProgress、执行进度筛选、物料数量统计和执行树的页面职责；其他独立履约查询继续工作，不把业务进度转为新的来源缓存。
2. 来源详情不装入 NetDemand、Link、采购/收货集合。现有跨域 Trace 先核对真实调用；有消费者时暂留兼容独立入口，本步先从来源页面解除装载，第二步接手物料追溯后再移除相关旧接口。
3. 保留销售与售后接收契约、命令指纹、完整来源行身份、同版本冲突和旧版本保护。补“已拆解、同内容、较新来源头版本”回归，推进元数据不得把既有拆解状态重置 Pending。实物内容变化仍按既有处置规则阻断，不本轮扩展修订业务。

## 必要文件范围

- `SwiftExport.Core/Entities/DemandPlanning/GrossDemand.cs`：标记 DecompositionStatus、DecompositionRevision、DecomposedAt、DecomposedBy 为弃用候选；保留 SourceVersion、Version、LifecycleStatus 和业务快照。
- `SwiftExport.Contracts/DTOs/DemandPlanning/GrossDemand/` 中实际引用的列表、详情、筛选与分组 DTO；`IGrossDemandRepository.cs`、`GrossDemandRepository.cs`、`GrossDemandWorkspaceService.cs`：移除本体查询的下游进度职责，不机械拆分文件。
- `SwiftExport.Client.Wpf/Features/DemandPlanning/GrossDemand/` 中实际绑定的 ViewModel、Model、View：同步收窄筛选、列和详情加载；现有布局与异步生命周期保持。
- `SourceDemandReceptionService.cs` 及来源接收、列表分组、WPF 对应测试：修复和验证元数据版本推进问题。
- API/Refit 仅在方法签名确实变化时同步，不预设换路由。

## 验收

- 无 NetDemand、采购或库存记录的销售/售后来源均正常显示；来源本体查询不联下游表计算进度。
- 页面不显示单据执行进度或需求完成率；保留需求数量与需求生命周期。
- 相同命令同内容重放，不同内容拒绝；同来源行不重复新增，旧版本拒绝；同内容新版本不破坏拆解事实。
- 既有销售和售后确认失败仍整体回滚；不删除有效的取消确认保护。
- 执行匹配的 Application/WPF 测试及后端、WPF 构建，检查 diff；未执行的 SQL 集成测试须单列。

完成后接[第二步](来源需求收窄-02-物料建立交接.md)。仅第一步完成时，不宣称来源服务已经完全解除物料依赖。
