# 采购与 BOM 执行依据治理

> **2026-09-16 采购确认职责修正：** 采购确认只校验采购事实并锁定订单、允许入库；不读取完整 BOM、不创建新 BOM 确认节点、不绑定消耗仓，也不要求首次确认存在历史快照。旧快照数据暂保留，专用追溯查询链已移除。草稿建立的未释放 Link 阻断需求回退；取消确认不释放，删行或作废才释放。客供件消耗归 PackingList 正式出货过账，实际仓和数量届时确定；跨供应商用料先调拨，禁止任意仓扣减。该自动消耗、选仓与调拨接线尚未实现。本轮不新增分解快照表。


## 最新目标（2026-09-07）

以业务架构总纲开头“采购来源可选与独立供货修正”为准。撤销上一版及 Sol 核对建议中的强制 SalesOrderId、独立采购销售单选择、销售归属回填及无销售归属即阻断规则。

独立采购已建立，本阶段复用现有创建、确认、采购行实际仓库及 PurchaseConfirmationLine/Node。采购可选关联来源需求（GrossDemand），不直接强依赖销售、物料需求或 Allocation。未关联来源是合法采购；来源缺失不影响正常确认、收货和出库。

PL 仍以来源需求表达客户交付要求，但供货可来自没有上游关联的独立采购。交付额度与采购可收容量是两个独立约束，不能互相替代。采购来源关联与客供件订单池归属也不是同一个字段。

## 最小实施步骤

1. **核对可选关联，优先不改实体。** 区分现有 DemandSourceType/Uid 的形成来源、GrossDemand 身份及 Link 的数量贡献，列出真实消费者。能复用则复用；不能直接把历史 SO/MD 类型 Uid 当作 GrossDemandId。独立创建保留无上游路径，不增加必填销售选择器。具体关联粒度由现有数量关系决定，不为此另建通用关联框架。
2. **建立采购行可收货能力。** 以 PurchaseOrderLine.Uid 为权威身份，返回采购头行、产品、库存单位、明确收货仓、状态、头行版本、确认批次及可收量。可收量按已确认采购数量减有效净收货计算；人工与 PL 自动收货共享额度，多 Link 不倍增或切碎容量。来源引用可空，不要求销售订单身份。优先扩展已有查询，只有边界确有需要才新增窄服务。
3. **统一采购事实确认。** 需求来源与独立采购保留状态、版本、价格、产品单位、活动引用及贡献守恒检查；确认不读取完整 BOM 或绑定消耗仓，不新增结构快照。
4. **交付后续接线说明。** 阶段 03 将收货消费者从 Link/Allocation 改接采购行能力；阶段 04 让 PL 明确选择独立采购/可用库存供货，并保存交付与供货数量关系。供应产品、单位、仓库、客户适用性等按实际约束验证，不以缺少采购上游关联直接拒绝。PL 不反向补绑采购，也不通过采购生成额外交付额度。
5. **限制本次范围。** 本阶段不重写入库和 PL，不执行阶段 05 的 Allocation 收敛，不重做独立采购页面，不拆分无关 Service/DTO，不增加当前没有真实调用方的采购导入 API。

## 库存与客供件边界

普通独立采购入库只认识采购执行依据和仓库；后续出库认识明确库存来源及执行单据，不要求物料需求存在。

使用独立采购成品发货且需要消耗客供件时，PL 从交付上下文取得可证明的订单池归属，结合物料需求父子关系及本次出货数量计算消耗（待实现）。不能用采购 CustomerId 或产品相同推断可用池。缺少合法池只阻断相关消耗/过账，不使整张独立采购不能创建或收货。用户先看到消耗预览并明确批准；普通批准不等于跨订单借料或负库存授权。已记录消耗的成品不得重复扣料。

## 迁移和验收

- 不新增强制销售归属迁移，不把无上游采购列为异常，不猜测历史来源。需要迁移时仅针对实际仓库、可选关联或确认依据的真实缺口，先预检再设计，不执行生产迁移。
- 独立采购无销售单、GrossDemand、NetDemand、Allocation 仍能创建及确认，并取得可收上下文。
- 可选关联来源需求的采购保留准确追溯及贡献数量；无关联量不被强制补齐。
- 多 Link 不倍增采购行收货额度；冲销恢复净容量；人工和 PL 收货并发不超量（消费者端到端验证由阶段 03/04 完成）。
- 两类采购确认均不依赖 BOM；修改当前 BOM 不影响确认，历史快照不改写。
- 阶段 04/06 必验：来源需求与独立采购原本无关联，PL 明确配供后可完成合法发货；无客供件场景不要求订单池，有客供件场景必须合法定池、预览批准且只扣一次。
- 不自动扩大跨来源合并采购功能；原同销售单限制不得作为独立采购的全局准入条件。
