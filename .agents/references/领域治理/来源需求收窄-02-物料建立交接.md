# 来源需求收窄第二步：物料建立交接

状态：已实施（2026-09-09）；前置：[第一步](来源需求收窄-01-本体与查询.md)。本步属于解除来源反向依赖所必需的物料交接，不扩展采购承接或 Allocation 治理。

## 已确认设计

物料需求页增加“从来源需求建立”按钮，打开候选列表，默认列出有效且未建立有效物料需求的来源条目，勾选后建立。查询由物料领域拥有，以 GrossDemandId 使用 EXISTS/NOT EXISTS 判断有效拆解事实，不回写来源的“已拆解”状态。

未建立、有效拆解已存在、来源变化待处理、明确回退后可重建必须区分。不能因旧物料执行完成、来源版本提高或历史行软删除就自动重新开放。来源同内容技术版本推进不等同实物依据变化；保存实际采用的来源版本及实物依据，比较后决定是否需要处置。

优先复用 NetDemand.GrossDemandId、DecompositionRevision 和既有历史记录。实施前核对是否能证明完整的一次拆解、无 BOM/非标结果及来源版本；不足时才补物料领域的最小批次依据，列明新增字段理由，不默认建立通用关系框架。来源四个弃用字段不能直接丢弃，先证明历史迁移可解释。

## 本步实施与文件

- `GrossDemandWorkspaceService.cs`、`GrossDemandDecompositionPlanner.cs`、`NetDemandInitialAllocationPlanner.cs`：把现有拆解/回退编排交由物料用例承接，复用算法与事务，不新写另一套 BOM 展开。
- `NetDemandWorkspaceService.cs`、其 Application/Core 接口、`NetDemandRepository` 对应查询文件：提供候选查询、建立与回退；联表在物料查询侧，明确字段来源与稳定分页。需要新增窄方法时扩展现有契约。
- 来源本体接口提供按身份读取及事务内版本/生命周期校验，不返回 NetDemand、Allocation 或 BOM 明细。旧来源拆解 API 在物料入口及真实调用方切换后退出。
- WPF `Features/DemandPlanning/NetDemand/` 实际页面及契约：加入按钮和候选选择；来源页面拆解/拆解结果入口改为物料导航或移除重复入口，不建立第二套维护页面。Refit 与 Controller 同步。
- 取消确认历史保护及变更影响检查迁到明确交接编排，复用现有物料、执行事实检查。来源本体不直接读取这些内部表；编排可协调双方，但不能反向注入物料仓储到来源本体，也不建设万能处置服务。保留原删除/作废双路径和手工需求限制。
- 对应拆解、回退、来源取消确认、候选查询及 WPF 测试。

## 事务与验收

- 候选列表仅作预览，不预留。提交在共享 DbSession.Transaction 内按稳定顺序锁定来源、复核版本及有效性、检查有效拆解范围，再写完整物料依据；不依赖来源 DecompositionStatus 防重复。
- 两人同时建立同一来源最多成功一套有效拆解；同 CommandId 重放原结果，不同命令重复建立明确返回已建立。
- BOM 读取或任一写入失败全部回滚，无 BOM 与读取失败分开；非标沿既有合法规则，不伪造产品或单位。
- 来源更新与建立并发时不能使用旧要求；已存在物料且实物要求改变进入待处理，不生成第二套。
- 回退保留历史，有活动执行阻断时不得回退；重新建立修订号由物料历史决定，不复用旧批次身份。
- 建立/回退不再回写 GrossDemand 四个拆解字段；来源本体查询/服务解除物料仓储依赖。兼容历史检查逐项验证后才能停止读取弃用字段。
- 执行后端/WPF 对应构建测试，并用隔离 SQL 集成测试证明并发、原子性及历史回退；禁止连接生产库。仅代码存在不能宣称并发验收通过。
