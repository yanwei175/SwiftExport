# 销售领域治理

## 目标与边界

销售维护客户订单事实，通过契约幂等接收为来源需求；来源需求汇聚销售、品质售后实物要求，提供 PL 统一交付准入。销售履约经来源需求查正式交付，不依赖物料需求/采购是否存在。采购只能关联一个销售单，销售单可被多采购单承接。PL 可以按既有同客户规则组合多销售单，但交付与客供件池逐订单隔离。

Core 基线：SalesOrderHeader/Line 已有稳定头行身份和数量；采购头仅有 DemandSourceType/Uid 等通用字段。SalesOrderHeadRepository 发货聚合仍沿 Outbound → Allocation → NetDemand → GrossDemand，复用 SO-003 整改，不能认为地图目标已经实现。

## 实施内容

1. 销售提供自身头行事实、客户及来源版本，通过阶段 0 来源接收/变更协议幂等同步认可的实物需求。采购可消费销售身份；PL 交付上下文与额度复核统一由来源需求提供，不新建销售直供 PL 的能力。
2. 保留来源确认/关闭/取消现有保护。销售直接写毛需求内部仓储的问题按 DP-001 移交需求接收协议；本轮不因页面简化改为自动采购。
3. 定义窄的销售履约查询：订单/行、需求量、关联采购订单摘要、采购确认与跟进、有效客户出库、未发量和异常。采购无行级分摊时仅展示订单级关联，不向每行重复累计。
4. 最终已发量从来源需求交付关联聚合有效正式客户出库，不计客供件消耗、入库或 PL 草稿。组成物料采购不得直接作为销售成品已采购量；没有证明时展示组件明细。
5. 前端在现有销售页提供只读履约摘要/入口；不复制采购编辑、库存或 PL 提交命令。跨模块跳转遵循现有模块权限。

## 契约、迁移及验收

销售侧建议用例为销售事实查询、来源需求接收/变更接线、SalesFulfillment Query；交付上下文与额度复核属于来源需求。履约经原始销售行 → 来源需求 → 正式客户出库；各子事实先聚合再关联，未知与零分开。

PL/出库新来源关系完成前保留已验证旧查询；不能提前删旧 Join 后返回零。阶段 6 切换并校对新旧已发量。历史缺销售行证据进入异常清单，不按相同 SKU 自动归属。

验收：无物料需求链、但有来源需求的合法发货可查；多采购/多 PL 不乘法重复；同一订单两销售行不重复计量；消耗不算交付；取消/反向净额只算一次；无采购仍显示销售行；销售关闭不抹历史采购与已发事实。
