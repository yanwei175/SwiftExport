# 业务模块能力与页面契约治理规则

核对日期：2026-10-06。本索引连接现行模块事实，旧阶段任务和过期偏差表已由当前说明替换。

## 文档的用途

能力地图说明当前模块职责、真实服务/Entity/契约/页面、数量与状态边界和仍有的限制。源码是当前实现事实；新需求和业务目标须明确标为待确认，不以旧地图强制重构已变更的调用链。仅发现旧文档与源码不符，不自动修改业务、恢复旧接口或启动执行窗口。

业务设计仍由 Planner 主导，已授权的规范表达与引用整理由 architecture-governor 维护，实现按 Backend/Frontend 职责执行。角色不增加写入授权。

局部明确实现可复用仍有效的模块/页面结论；本次改变业务职责、状态/数量口径、跨域交接或API/DTO语义，或有相关偏差证据时才补读命中章节，不为普通小改重读全部地图。地图当前不提供旧偏差表的统一ID；权威分类、暂停条件和文档同步统一见 [范围与偏差规则](架构治理与路由判定规则.md#3-范围偏差与豁免)。不得用当前源码事实覆盖已确认目标。

## 契约与页面核对

1. 从真实用户动作核对导航/页面、ViewModel、调用API、Controller和Application，不以文件名推断已接入。
2. 明确权威Entity、查询投影、采用时快照、命令输入和UI编辑状态，不能用展示DTO整包充当写入依据。
3. 查询、Preview、正式写命令和Trace分别核对权限与副作用；Trace保持实际只读边界。Preview不预占，不将一致性读锁误称库存写入。
4. 复用或拆分DTO前核对全部调用方及字段去向；技术复用细则仍见对应Contracts Skill。接口和页面存在不等于每条状态路径验收通过。
5. 记录仍有的源码限制及证据，禁止把旧规划、枚举或历史表当作活动能力；不得自动降低现有业务保护。

当前地图不维护按旧日期累计的待办或全仓重构命令。只有用户新授权的任务才建立实施分工，按实际diff选择验证范围。
