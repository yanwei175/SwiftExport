# 业务模块能力与页面契约治理规则

## 1. 目的

本规则把业务设计稳定地传递到页面、API、DTO 和前端 Model。模块设计必须遵循以下顺序：

```text
业务目标与权威事实
  -> 模块能力与上下游
  -> 页面职责与显式命令
  -> API 用例
  -> Request / Response / Command / Result
  -> 前端 Model 与映射
  -> 验收场景
```

页面、数据库表、现有目录和已有 DTO 都不能反向决定业务边界。

## 2. 能力地图最低内容

每个业务模块能力地图必须包含：

1. 模块使命、业务用户和不做范围。
2. 上游输入、下游输出和跨模块调用方向。
3. 权威 Entity、历史快照、查询聚合和禁止缓存的事实。
4. 页面清单、页面职责、禁止职责、打开入口和主要用户。
5. 页面命令、状态准入、阻断条件、反向流程和权限要求。
6. API 用例、DTO、前端 Model、字段来源和真实消费者。
7. DTO 新建/复用判断及契约演进边界。
8. 当前源码事实、目标设计和偏差账本。
9. 可验收的阶段性实施顺序。

## 3. 页面边界门禁

- 页面围绕用户任务建立，不按数据库表机械建立。
- 管理列表、单据详情、过程跟进、Trace 和正式过账职责不同，默认不得合并为万能工作台。
- 同一业务命令只能有一个权威编排入口；多个页面可以导航到该入口，不得复制实现。
- 只读 Trace 不执行保存、确认、过账或反向命令。
- 改变库存的页面归库存单据与过账能力，不归采购、销售或需求查询页面。
- 页面专用筛选、选中、展开、Busy、脏状态和验证提示放前端 Model，不进入 Contracts DTO。

## 4. API 与 DTO 门禁

- API 以业务用例和命令边界组织，不以页面控件或数据库 CRUD 组织。
- 列表、详情、跟进、Trace、Preview、Command 和 Result 使用各自窄契约。
- DTO 复用必须满足 `.codex/skills/aspdotnet10/contracts-dto-models/references/DTO复用与文件组织门禁.md`。
- 能力地图必须记录每个 DTO 的使用角色、消费者、数据来源、权限口径和是否允许复用。
- 新页面不得先创建 DTO 再寻找业务用途；先确认页面动作和 API 用例。
- 前端可编辑状态转换为 EditModel/LineModel；结构性转换使用 Mapster，业务规则保持显式。

## 5. 目标、事实和偏差

能力地图同时维护：

- **目标边界**：后续开发和重构必须遵循的权威设计。
- **当前事实**：从真实源码确认的页面、API、DTO 和调用关系。
- **偏差账本**：当前事实与目标边界的差异、影响和建议治理顺序。

不能为了匹配现有代码而悄悄降低目标边界，也不能把目标设计描述成已经实现。

## 6. Agent 偏差处理门禁

Agent 在实现、审查或规划模块任务前必须比较能力地图与真实源码：

| 情况 | 处理 |
|---|---|
| 实现符合目标 | 正常继续 |
| 存在偏差但任务不触碰 | 正常继续，最终报告提示相关技术债 |
| 任务会修改、复制或扩大偏差 | 修改前输出门禁偏差提醒并暂停，等待用户选择 |
| 用户明确授权重构 | 把重构列入计划，按最小可验收切片实施 |

门禁偏差提醒固定包含：

1. 命中的目标规则。
2. 当前源码事实和文件位置。
3. 本次任务会如何扩大或固化偏差。
4. 最小重构方案及影响范围。
5. 暂不重构的兼容方案和后续代价。

不得自动顺带重构；不得只说“建议优化”而省略具体偏差和影响。

## 7. 模块地图索引与跨域读取

Agent/Workflow 统一按本索引选择地图，不另设各角色自己的模块名单。

| 任务对象 | 必读地图 |
|---|---|
| 产品、客户、供应商、双方产品关系、分类/颜色/主型号、包装/资料/默认配置 | [主数据模块能力地图](模块能力地图/主数据模块能力地图.md) |
| 当前 BOM、组成编辑、树、校验、修改记录、一致结构读取 | [BOM 模块能力地图](模块能力地图/BOM模块能力地图.md)、主数据地图；不默认开展多版本管理 |
| 编码更名、主数据停用/恢复、单位变更、默认值采用 | 主数据地图及实际受影响的销售/需求/采购/入库/库存/PL/出库地图；新承接与既有承诺分别校验 |
| BOM 执行快照、独立采购消耗依据 | BOM、需求计划、采购、PackingList 地图；需求拆解修订与 BOM 修改记录分开 |
| 毛需求、净需求、拆解、计划建议、来源实物接收、需求变更/关闭 | [需求计划模块能力地图](模块能力地图/需求计划模块能力地图.md) |
| 销售订单、销售履约跟踪、商业变更、行级终止、关闭/恢复、非标关联 | [销售模块能力地图](模块能力地图/销售模块能力地图.md) |
| 销售与需求生命周期交接 | 销售、需求计划地图及业务总纲第 7—8 节；商业生效与执行处置分离 |
| 销售交付来源、销售变更与 PL 提交、InvoiceNo/履约回传 | 销售、PackingList、出库地图；涉及客户库存再读库存地图 |
| 售后来源生命周期交接 | 需求计划、PackingList 地图及业务总纲对应来源章节；尚未建立完整售后地图，不伪造入口 |
| 需求转采购、采购拉取需求、计划与实际供应商边界 | 需求计划与采购两份地图；涉及收货/库存则追加对应地图 |
| 采购管理、跟进、独立采购 | [采购模块能力地图](模块能力地图/采购模块能力地图.md) |
| 来源选择、入库列表/详情、草稿、过账、反向、客供件收货 | [入库模块能力地图](模块能力地图/入库模块能力地图.md) |
| 虚拟仓、余额、流水、库存 Trace、期初、统一过账 | [库存模块能力地图](模块能力地图/库存模块能力地图.md) |
| 计划出货、装柜草稿、来源贡献、InvoiceNo、PackingList 提交/修订/真实错发 | [PackingList 模块能力地图](模块能力地图/PackingList模块能力地图.md)；涉及库存动作再读入库、库存、出库地图 |
| 正式客户出库、客供件消耗、出库 Trace、整单反向 | [出库模块能力地图](模块能力地图/出库模块能力地图.md)、PackingList 与库存地图；自动入库反向再读入库地图 |
| 采购—入库—库存交接、来源标识迁移、需求收货覆盖 | 采购、入库、库存三份地图都读；交接矩阵集中在入库地图第 2 节；涉及需求生命周期/覆盖再读需求计划地图 |
| PackingList 自动补入库、客户库存归属、修订库存影响 | PackingList、采购、入库、库存、出库五份地图；涉及来源履约再读需求计划地图；INB-008/INV-006 与 PL-003 共用整改链 |

已有地图必须先读；未建立的模块不得套用采购字段作为通用模型。地图是执行约定，不是已经实现的自动路由或 CI 检查。业务设计由 Planner 主导，确认后的治理落盘由 architecture-governor 按授权维护，不改变角色写入范围。

## 8. 能力地图维护

- 模块地图放 `.agents/references/模块能力地图/{模块}模块能力地图.md`。
- 业务规则改变时先更新业务架构总纲，再同步能力地图。
- 页面/API/DTO 边界改变时同步能力地图和偏差账本。
- 完成偏差重构并验证后，从偏差账本移除或标记已完成，并记录验收证据。
- 历史资料只能用于追溯，不能覆盖当前能力地图。
