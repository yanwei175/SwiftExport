# SwiftExport ERP 业务架构总纲

## 项目定位

SwiftExport 是面向小团队内部使用的外贸/ERP 系统。业务主线围绕产品资料、BOM、销售订单、需求拆解、采购、入库、出库、PackingList 和库存流水闭环展开。

系统设计优先级：

1. 业务流程可追溯。
2. 单据动作明确。
3. 小团队可维护。
4. 不做过重审批。
5. 库存流水和过账行为必须严谨。

## 主流程

```text
基础资料
  -> 销售订单 / 手工需求 / 投诉补货
  -> 毛需求 IndependentDemand
  -> BOM 拆解
  -> 净需求 DependentDemand
  -> 转采购 / 未来生产 / 未来外协
  -> 采购入库
  -> 手动出库 / PackingList 智能出入库
  -> 库存流水闭环
```

## 基础资料

基础资料包括：

- 产品。
- 产品分类。
- 产品颜色。
- 客户产品。
- 供应商产品。
- BOM。
- 客户。
- 供应商。
- 仓库。

产品/BOM 是需求拆解的核心。BOM 拆解时需要根据子物料 `MaterialType` 判断是否客供件，根据物料 `SupplyType` 判断采购、生产或外协。

## 需求来源

毛需求允许来自：

- 销售订单。
- 手工需求。
- 投诉补货。

投诉补货不能形成孤岛，应进入毛需求，再走净需求和采购逻辑。

## 毛需求与净需求

- 毛需求承接原始业务需求。
- 净需求由 BOM 拆解产生，是采购/未来生产的执行入口。
- 当前阶段优先实现采购。
- 生产与外协保留扩展口。

关系：

```text
销售订单行 -> 毛需求：一对一
毛需求 -> 净需求：一对多
净需求 -> 采购单行：多对一，通过 DemandExecutionLink 追溯
```

## 客供件逻辑

客供件不是固定供应商角色。供应商可以生产成品，也可以生产配件。

客供件判断：

- 在 BOM 拆解时根据子物料 `MaterialType` 判断。
- 客供件流向由净需求/执行行决定。
- 供应商 A 可以送货到供应商 B。
- 系统收到通知后，可以在系统里执行收货到 B 供应商仓库。
- PackingList 出货时，根据父物料完成情况扣减 B 仓库里的对应子物料。

## PackingList

PackingList 是外贸装柜箱单。它代表生产/供货环节已经完毕。

PackingList 确认或过账时：

- 判断对应需求。
- 未入库的自动生成入库单并入库。
- 已手动入库的执行出库。
- 自动入库必须生成正式入库单。
- 自动出库必须生成正式出库单。
- 所有库存变化必须产生库存流水。

## 状态原则

不要把所有流程塞进 `OrderStatus`。

状态应分层：

- 单据生命周期状态。
- 确认状态。
- 执行进度状态。
- 过账状态。
- 改单/变更状态。

`OrderStatus` 更适合展示和进度汇总，不作为复杂流程唯一判断依据。

## 改单原则

小团队内部 ERP 允许轻量改单：

- 库存流水产生前，可以允许人工回退下游草稿/未过账单据后重跑流程。
- 已入库、已出库、已产生库存流水后，不能靠删除解决。
- 库存流水之后必须反过账或红冲。
- 正式单据和库存流水必须可追溯。

## 当前精心设计范围

当前代码中销售订单相对成熟。毛需求、净需求、采购单、入库、出库、PackingList 下游流程仍是后续重点打磨主线。
