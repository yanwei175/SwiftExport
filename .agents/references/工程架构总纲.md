# SwiftExport 工程架构总纲

> **2026-09-16 采购确认职责修正：** 采购确认只校验采购事实并锁定订单、允许入库；不读取完整 BOM、不创建新 BOM 确认节点、不绑定消耗仓，也不要求首次确认存在历史快照。已有确认快照仅作历史查询。草稿建立的未释放 Link 阻断需求回退；取消确认不释放，删行或作废才释放。客供件消耗归 PackingList 正式出货过账，实际仓和数量届时确定；跨供应商用料先调拨，禁止任意仓扣减。该自动消耗、选仓与调拨接线尚未实现。本轮不新增分解快照表。


## 领域交接与事务（2026-09-16）

销售、来源需求、采购、库存和出货采用单体内窄契约协作。采购确认状态提供供货资格；客供件实际消耗依据在 PackingList 出货时形成（接线待实现）；库存只维护 WarehouseSiteId + ProductId 的余额和流水；PackingList 以 GrossDemand 为交付入口，并通过领域接口编排必要自动入库、最终客户出库和客供件消耗，不直接写其他领域表。

PackingList Application Service 是正式过账与整单反向的最外层事务边界。被调用服务共享同一 request scope 的 DbSession，按稳定顺序锁定单据、来源额度、采购容量和库存键，统一提交供货绑定、自动单据、流水、状态、日志和幂等结果。Preview 只读且不预留资源；Post/Reverse 必须重新校验。不引入消息总线，不允许 Controller、WPF 或 Repository 越层编排。

非标 PackingList 行只形成正式交付净额，不产生库存事实。标准行的全部数量必须绑定可证明的采购确认依据；客供件计算读取 PurchaseConfirmationLine / PurchaseConfirmationNode 快照，不读取当前 BOM。详见 [PackingList 模块能力地图](模块能力地图/PackingList模块能力地图.md) 与 [PackingList 与出库治理](领域治理/04-PackingList与出库治理.md)。

## 解决方案

- `SwiftExport.slnx`：总解决方案。
- `SwiftExport-WebAPI.slnx`：后端 WebApi 解决方案。
- `SwiftExport.Client.Wpf`：当前 .NET 10 WPF 客户端主线。
- `SwiftExport-Frontend.slnx`：当前 .NET 10 WPF 前端解决方案，包含 Client、Contracts 和 EnterpriseGrid。

## 当前前端主线

当前前端主线是：

```text
SwiftExport.Client.Wpf
  .NET 10 WPF
  CommunityToolkit.Mvvm
  Microsoft.Extensions.DependencyInjection
  Refit
  Mapster
```

旧 .NET Framework WPF、MateWpfThemes、DevApp 和 VSTO 项目已从当前仓库移除；需要追溯时使用 Git 历史，不得作为当前前端依赖重新引入。

## 后端分层

### WebApi

路径：`SwiftExport.WebApi`

职责：

- Controller。
- HTTP 请求/响应边界。
- Middleware / Filter。
- 认证授权边界。

禁止：

- Controller 写 SQL。
- Controller 承担复杂业务编排。
- Controller 直接依赖 Infrastructure Repository。

### Application

路径：`SwiftExport.Application`

职责：

- 业务服务。
- 业务校验。
- 业务流程编排。
- 调用 Repository 接口。
- 控制事务边界。

新增 API 时，先在 `Interfaces` 声明服务接口，再在 `Services` 中实现。

### Core

路径：`SwiftExport.Core`

职责：

- Entity。
- Repository Interface。
- 基础领域接口。

Core 不负责前端可见 DTO、Refit API、前端枚举。

### Infrastructure

路径：`SwiftExport.Infrastructure`

职责：

- Dapper Repository 实现。
- `RepositoryBaseContext`。
- `DbSession`。
- SQL Server 访问。
- 审计字段打戳。

禁止引用 Application。

### Contracts

路径：`SwiftExport.Contracts`

职责：

- DTO。
- Refit API Interface。
- 前后端共享枚举。
- Request / Response。
- 通用响应包装。

API/前端可见联表只读模型优先放 Contracts DTO，允许 Infrastructure Dapper 直接映射为 DTO 返回给 Application。

## 后端 API 开发顺序

```text
业务场景
  -> Contracts DTO/API/枚举
  -> Application Interface
  -> Application Service
  -> 必要时 Core Repository Interface
  -> Infrastructure Dapper Repository
  -> WebApi Controller
  -> 构建验证
```

## .NET 10 WPF 前端组织

当前业务页面放在：

```text
SwiftExport.Client.Wpf/Features/{业务域}/{功能单元}/
  Views/
  ViewModels/
  Models/
  Services/
  Components/
```

全局基础设施：

- `SwiftExport.Client.Wpf/Mvvm`
- `SwiftExport.Client.Wpf/Resources`
- `SwiftExport.Client.Wpf/Navigation`
- `SwiftExport.Client.Wpf/Shell`

主题颜色、token、命名 Style 和通用控件资源由 `SwiftExport.Client.Wpf/Resources` 统一管理；`SwiftExport.Wpf.EnterpriseGrid` 保持独立的原生 WPF DataGrid 增强边界。
