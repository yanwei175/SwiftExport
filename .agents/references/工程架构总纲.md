# SwiftExport 工程架构总纲

核对日期：2026-10-07。本文为现行代码结构说明，技术细则继续由对应项目 Skill 定义。

## 运行栈与分层

| 层 | 当前职责 | 关键入口 |
| --- | --- | --- |
| WebApi | Controller、认证授权、过滤器、中间件、HTTP响应 | Program.cs、Authentication、Filters、Middleware |
| Application | 业务校验、用例编排、最外层事务和命令回执 | Services、Interfaces、Commands、Contexts |
| Core | Entity、数据库结构元数据、仓储及领域基础接口 | Entities、Interfaces、DatabaseSchema |
| Infrastructure | PostgreSQL+Dapper、连接会话、仓储、结构生成、审计打戳 | DependencyInjection.cs、Data、Repositories、Database |
| Contracts | DTO、Refit API、枚举、共享响应和权限键 | DTOs、Apis、SysEnums、Wrappers |
| WPF | 用户交互、编辑状态、导航与API消费 | Features、Navigation、Mvvm、Resources |
| VSTO | Excel导入及专用客户端设施 | SwiftExport.Client.VSTO；不向WPF引入net48依赖 |

Controller 调用 Application 接口，不直接写 SQL 或依赖具体仓储。Application 通过 Core IDbSession、仓储接口和 IDatabaseExceptionClassifier 访问持久化边界，不引用 Infrastructure。Infrastructure 不引用 Application。只读联表 DTO 可由 Dapper 映射到 Contracts，编辑状态留在客户端模型。

## 数据库与事务接线

数据库任务的现行入口见 [PostgreSQL 当前基线](PostgreSQL当前基线.md)；旧批次迁移记录不作为当前技术栈或后续自动待办。

Infrastructure.DependencyInjection 已注册 PostgreSqlConnectionFactory、PostgreSqlExceptionClassifier、PostgreSqlDapperRepository<> 和 PG 专用仓储；DbSession 与 IDbSession 指向同一 scoped 对象，RepositoryBaseContext 共享它。当前不是 SQL Server 运行接线，也不建设长期双库切换框架。连接字符串只从配置读取，文档不保存密码。

实体 [Table] 和 DatabaseSchema 元数据经 PostgreSQL 名称/类型映射形成 Generated/SwiftExport.PostgreSql.Schema.preview.sql。生成文件不是已部署证据；只读结构检查与写入部署分开。逻辑外键不生成数据库 FOREIGN KEY，局部唯一键、CHECK、不可变规则按实体声明。

BusinessCommandExecutor 负责所属用例事务、规范化请求指纹和回执；CommandPipeline 负责授权/命令验证等公共边界。参加父事务的来源接收及自动单据端口不独立提交。Preview 的读一致性按各服务实现，不能一律写成“完全无锁”。PG资源准备、稳定锁序、并发版本及明确异常分类以实际实现为准。

PackingList 已通过内部入出库端口统一正式过账及反向；采购确认不读取当前 BOM 或新建执行节点。具体交接见能力地图。

## 客户端及公共设施

当前 WPF 使用 .NET 10、CommunityToolkit.Mvvm、Refit、Mapster。业务页按 Features/{域}/{用例} 组织；路由和菜单由 NavigationRouteRegistry 本地注册，权限目录不动态生成页面。EnterpriseGrid 是独立原生 DataGrid 增强项目，文件服务复用 DvFileStorage，HTTP和业务图片处理由宿主承担。
