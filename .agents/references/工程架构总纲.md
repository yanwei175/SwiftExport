# SwiftExport 工程架构总纲

更新日期：2026-10-22。本文描述**目标工程结构**及仍有效的现行接线。技术原则以 [后端架构治理文档](../../Handoff/Claude/Backend-Architecture-Guide.md)（最高技术依据）和 [架构决策日志](../../Handoff/Architecture-Decisions.md) 为准，本文只做摘要和入口；与其冲突时以 Guide 和决策日志为准，现有代码不得反向降低目标。迁移步骤见 [00-Foundation](../../Handoff/Refactor/00-Foundation.md)，未迁移的旧实现属于过渡事实，不是可复制的样板。

## 运行栈与分层

| 层 | 目标职责 | 不做 |
| --- | --- | --- |
| WebApi | Controller、认证、端点权限声明 `[HasPermission(Permissions.X)]` + 授权策略、FluentValidation 输入校验、`IExceptionHandler` → ProblemDetails | 写 SQL、依赖具体仓储、编排业务、字符串权限字典 |
| Application | 用例 Service、业务校验、经 `IUnitOfWork` 开启事务、全仓唯一 `CommandExecutor`（事务 + `command_receipt` 幂等） | 引用 Infrastructure、继承 `BaseService`/泛型 CRUD、使用 `ServiceBaseContext` |
| Core | Entity 及其状态流转方法、数据库结构元数据、仓储接口、`IUnitOfWork` 等基础接口 | 依赖其他层 |
| Infrastructure | PostgreSQL + Dapper、`DbSession`（实现 `IUnitOfWork`）、仓储与查询 SQL、结构生成、审计打戳 | 依赖 Application、应用级锁服务 |
| Contracts | DTO、Refit API、枚举、权限键（netstandard2.0） | `ServiceResult<T>` 等成功/失败包装 |
| WPF | 用户交互、编辑状态、导航与 API 消费 | 业务事务 |
| VSTO | Excel 导入及专用客户端设施 | 向 WPF 引入 net48 依赖 |

WPF、VSTO、Web 客户端全部自有：契约变更客户端同步修改，不做旧格式兼容。

## 公共机制（目标）

- **事务**：极薄 `IUnitOfWork`（基于 `DbSession`），只在 Application Service / `CommandExecutor` 开启；现有散落的 `BeginTransaction` 全部迁移，由架构测试禁止 `DbSession` 以外的 `BeginTransaction`/`Commit`/`Rollback`（决策 #30）。参加父事务的来源接收及自动单据端口不独立提交（跨域交接见能力地图）。
- **幂等**：正式单据命令经 `CommandExecutor.ExecuteIdempotentAsync`（`ICommandExecutor` 只有这一个方法，普通写入直接 `IUnitOfWork`）；`CommandId` 放请求体，记录沿用 `command_receipt`（`CommandReceipt`），不改名。在事务内查回执，校验、指纹兼容与同 CommandId 并发规则见决策 #28。`CommandPipeline` 与 `BusinessCommandExecutor` 合并进 `CommandExecutor`，不用 MediatR 或自建中介者。
- **并发**：行锁 `FOR UPDATE` + 唯一约束 + `Version`；删除 `PostgreSqlCommandLock`、`PostgreSqlSourceDemandLock`，前提是锁替代清单经用户确认（决策 #29）。无法覆盖的场景停下问用户。
- **预览**：允许简化 Preview Token、预览重放和独立预检；正式命令在事务内重验，影响预览改为普通 GET。
- **错误**：唯一 `BusinessException` + `IExceptionHandler` + ProblemDetails；`ServiceResult<T>` 分三批淘汰，过渡期失败也必须返回非 2xx（决策 #25）。是否生效只由事务阶段和回执判定，500 不承诺未生效（决策 #27）。
- **基础库**：System.Text.Json、Serilog（关联 ID 用框架 TraceId，不自写中间件，决策 #26）、FluentValidation、Mapster、Dapper；迁移工具 DbUp（是否已接入未验证）。
- **禁止新增**：Support/Helper/Manager/Pipeline/Builder 类；现有的在模块重构时消化。

## 模块组织

一个业务对象一个文件夹（Controller/Service/Queries/Repository/Queries.Sql/Validators），大文件按用例 partial。命名统一 `PurchaseOrder`；路由资源式 `/api/purchase-orders/{id}/{动词}`。订单跟踪（OrderTracking）是唯一跨模块追踪模块。代码形状样板见 [ReferenceDesign](../../Handoff/Claude/ReferenceDesign/README.md)（业务为虚构示意）。

## 数据库

数据库任务的现行入口见 [PostgreSQL 当前基线](PostgreSQL当前基线.md)；不建设长期双库切换框架，连接字符串只从配置读取，文档不保存密码。

实体 [Table] 和 DatabaseSchema 元数据经 PostgreSQL 名称/类型映射形成 Generated/SwiftExport.PostgreSql.Schema.preview.sql。生成文件不是已部署证据；只读结构检查与写入部署分开。Core 实体与表结构保留；表间依赖、字段引用、唯一约束及结构变更必须先问用户。

## 客户端及公共设施

当前 WPF 使用 .NET 10、CommunityToolkit.Mvvm、Refit、Mapster。业务页按 Features/{域}/{用例} 组织；路由和菜单由 NavigationRouteRegistry 本地注册，权限目录不动态生成页面。EnterpriseGrid 独立项目已退出，使用原生 DataGrid 与客户端按需行号、软验证、选择及填充适配，文件服务复用 DvFileStorage，HTTP 和业务图片处理由宿主承担。
