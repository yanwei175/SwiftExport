# 数据模型与状态规则

> 2026-09-06：订单池及领域边界以[业务总纲第 24 节](业务架构总纲.md#24-订单级客供件池与领域解耦2026-09-06)为准。独立采购可无需求但须唯一销售单；PL 正常编排非客供件入出库及客供件消耗，用户先确认具体消耗，普通确认不授权负库存。[领域治理索引](领域治理/00-全链路治理总计划.md)包含字段处置与执行提示词。

## 主键与业务键

新模型优先使用 `Uid` 作为技术主键。

业务编码用于人工查账和唯一约束，例如：

- `Sku`
- `CustomerCode`
- `SupplierCode`
- `WhseCode`
- `OrderNo`
- `ReceiveNo`
- `OutboundNo`
- `PackingListNo`

## 外键策略

跨模块追溯优先使用：

```text
Uid + 业务编码冗余
```

例如：

- `SourceUid`
- `SourceNo`
- `SourceLineId`
- `TargetHeadId`
- `TargetNo`
- `TargetLineId`

数据库侧以索引和唯一约束保障查询；跨模块一致性由 Application Service 校验。头行强父子关系可按模块补强数据库外键。

## 软删除

- 主数据停用与删除分开；历史引用保留，不能把软删除标志直接当已实现的停用机制。
- 业务单据默认软删除。
- 已过账单据不靠删除解决。
- 库存流水不可删除。

## 库存模型

主数据更名保持 Uid 和历史快照，专用命令记录影响与旧新编码；停用禁止新引用/增量承诺，但既有已确认合法单据仍按自身准入履行。不能统一删除有效性检查，也不自动停仓。产品有正式库存流水后冻结基础单位，余额为零不例外；详见 [主数据地图](模块能力地图/主数据模块能力地图.md)。

- `InventoryBalance` 保存当前余额投影，只由统一过账服务更新。
- `InventoryLedgerEntry` 保存数量变化事实，只新增，不普通修改，不删除。
- 错误通过反向流水或红字流水修正。
- 入库、出库、PackingList 过账必须生成正式单据和库存流水。
- 客供件以销售订单＋供应商仓库＋产品＋统一库存单位形成共享池，不按父件或 Allocation 分配；同客户不同订单不共用。订单归属量与总投影对账，未知归属不得当零自动补入库。持久化按领域治理择一方案，不并列两个余额权威。
- PackingList 已过账修改区分文档修订和库存/履约纠错，保持业务单号与修订历史；业务修订号、内部身份、并发 Version 分开，不能普通覆盖正式事实。
- 真实错发保留实际出库，实际退回才增加库存，补发使用新售后交付来源；详细交接见业务总纲第 14 节及模块地图索引。

## 追溯模型

统一语义：GrossDemand 为来源需求汇聚口，NetDemand 为物料需求；本轮不改物理名。销售/品质售后按来源身份、意图及版本幂等接收；PL 贡献必须锚定来源需求，物料需求/Allocation 可选。交付可发量由来源需求及正式客户出库计算，不直接从销售定义。订单池归属不是来源需求 Uid，售后映射需证明；完整规则见业务总纲第 24.7 节。

BOM 只有单套当前结构，保存即生效；修改记录、需求拆解 revision、采购执行快照是不同事实，不建立版本选择/发布/切换。现有 BomVersion 仅保留兼容，不在本轮改表或重排值。需求拆解和独立采购确认各自固定实际采用的一致完整结构，既有消耗不读当前 BOM 重算；详见 [BOM 地图](模块能力地图/BOM模块能力地图.md)。

`DemandExecutionLink` 保存需求分配对执行单据行的贡献关系，不是所有入库的必填凭证。采购可以没有需求关联；入库先追到执行单据，有需求关系再沿 Link 追溯，禁止伪造关系。

来源 Uid 表达真实对象，不能用 Link Uid 冒称采购行 Uid。需求收货覆盖是查询投影，不保存为入库固定分摊、预留或需求收货缓存。数量及历史迁移边界见 [业务架构总纲](业务架构总纲.md) 第 13 节；地图按 [模块地图索引](业务模块能力与页面契约治理规则.md) 读取。

## 单据状态分层

销售单据生命周期、确认状态、行交付终止、商业修订、执行处置进度和查询履约分别表达，不能合成万能状态。全部发完不自动关闭；商业关闭允许执行处置未完成，不级联改采购。恢复走独立命令，不重置正式交付。详见 [销售地图](模块能力地图/销售模块能力地图.md)，本次不增补枚举或冻结修订物理表。

不要把所有状态塞进 `OrderStatus`。

建议分层：

- `DocumentStatus`：草稿、有效、关闭、作废。
- `ConfirmStatus`：未确认、已确认、取消确认。
- `ExecutionStatus`：未执行、部分执行、已执行。
- `PostStatus`：未过账、已过账、已反过账、已红冲。
- `ChangeStatus`：正常、改单中、已变更。

展示状态可以汇总，但业务判断应使用明确执行节点和命令。

## 改单边界

- 未生成下游：可直接改上游。
- 下游草稿/未过账：允许删除或回退后重跑。
- 已确认但未生成库存流水：允许取消确认到安全边界。
- 已入库/出库/库存流水本身需要纠错：通过合法反过账或红冲处理，保留原事实。
- 库存流水之后不允许靠删除下游来掩盖业务变化。

来源业务减少/取消不等于库存事实错误。需求按 [需求计划地图](模块能力地图/需求计划模块能力地图.md) 评估影响，暂停受影响的新承接；采购明确减量、取消或继续备货，已有合法收货不自动停止。当前需求、计划建议、历史执行承诺和差额分开，不通过删除历史凑平数量。
