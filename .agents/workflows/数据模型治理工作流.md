# 数据模型治理工作流

## 适用范围

用于分析和治理 SwiftExport ERP 的 Core Entity、实体关系、Contracts DTO、数据库模型以及 Infrastructure 实现路线。本工作流默认只输出设计报告，不修改业务代码、数据库脚本或项目文件。

## 主 Agent

使用 `.agents/planner.toml` 作为唯一主 Agent。用户明确要求按已确认方案实现后，再切换到 `backend` Agent 和后端 API 工作流。

## 执行顺序

1. 读取 `AGENTS.md`、`.agents/router.toml` 和 `.agents/planner.toml`。
2. 读取 `.agents/references/业务架构总纲.md`、`工程架构总纲.md`、`PostgreSQL当前基线.md` 和 `数据模型与状态规则.md`。
3. 读取 `.codex/skills/aspdotnet10/data-model-governance/SKILL.md`，按任务加载相关 reference 和已有后端 Skill；涉及 PostgreSQL 表结构、索引或查询设计时，按 [后端技能索引](../../.codex/skills/aspdotnet10/index/SKILL.md) 接入 `postgres-skills`，仍保持本工作流的只读规划边界。
4. 明确本次治理的业务模块、上下游流程、已实现范围和不做范围。
5. 搜索真实 Entity、DTO、Mapster 映射、Repository Interface/实现、Application Service、DI 注册和数据库脚本。
6. 先建立当前源码事实清单，不根据命名推测实现状态。
7. 逐字段审计 Entity，区分实体自身字段、逻辑关系、历史快照、派生字段、展示字段和 UI 状态。
8. 建立实体关系矩阵，说明 Uid、业务编码冗余、快照和 Application 一致性校验责任。
9. 将 DTO 分类为 Entity DTO、Query DTO 或 Command DTO，并为联表 Query DTO 建立字段来源和 Join 映射。
10. 根据真实写入和查询方式提出表结构、主键、索引、唯一约束、默认值和逻辑外键建议。
11. 盘点 Repository Interface、实现、DI 注册、调用方和事务依赖，形成 Infrastructure 缺口与实现顺序。
12. 沿业务主链分析 Entity 变更对 DTO、映射、SQL、服务、API、前端和历史单据的影响。
13. 输出可直接交给 `backend` Agent 的分阶段任务，但分析阶段不得提前编写实现代码或 SQL。

## 强制输出

1. 治理范围与当前源码事实。
2. Entity 字段审计表：字段、当前用途、字段分类、建议、下游影响。
3. 建议修改的 Entity 清单和不得删除的历史快照字段。
4. 实体关系与一致性风险矩阵。
5. DTO 分类表和联表 DTO 字段来源/Join 映射表。
6. 数据库结构、约束和索引建议。
7. Repository/Infrastructure 缺口和实现优先级。
8. 可交给 backend Agent 的分阶段任务。
9. 待确认业务问题和验收标准。

## 边界

- 不默认增加跨模块数据库 Foreign Key；头行强父子关系可以单独评估。
- 不把页面展示字段或 UI 状态放入 Entity。
- 不把历史快照误判为可删除的冗余字段。
- 不让 Repository 代替 Application Service 承担业务一致性。
- 不假设项目使用 EF Core；Infrastructure 以 Dapper、DbSession 和 RepositoryBaseContext 为事实基础。
- 任何 Entity/DTO 删除、改名、迁移建议必须先说明影响，等待用户确认后再实施。
