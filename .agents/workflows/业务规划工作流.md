# 业务规划工作流

## 适用

需求分析、业务流程设计、状态机、改单机制、模块拆分、总纲和任务书。

## 步骤

1. 先读 `AGENTS.md`、`.agents/router.toml`、`.agents/planner.toml`。
2. 读取 `.agents/references/业务架构总纲.md`、`.agents/references/工程架构总纲.md`、`.agents/references/数据模型与状态规则.md`。
3. 按模块索引读取本次设计命中的地图；改变采购—入库—库存交接时核对三方契约。按路由policy区分有效目标与过期事实；有仍有效的偏差记录才复用ID，不寻找退役编号。
4. 搜索并读取相关源码事实、实体、枚举、DTO、服务和现有页面。
5. 先写业务流程和能力边界，再写页面、数据模型和 API，不要直接从表结构开始。
6. 明确当前事实、目标规则、偏差账本、未决问题和不做范围。
7. 拆成后端、前端、契约、验证四类任务。

## 输出

1. 业务目标
2. 当前事实
3. 业务流程与状态边界
4. 数据模型建议
5. API 契约草案
6. 前后端任务拆解
7. 验收场景
8. 风险与待确认问题
