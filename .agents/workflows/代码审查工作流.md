# 代码审查工作流

## 适用与入口

用于用户明确请求的代码 Review、验收或改动风险评估，包括 WPF、React Web、API 和 Grid。普通实施自查由当前实施 Agent 完成，不额外启动 reviewer；全局架构/规范治理审计单独按 Router 进入架构治理工作流。

公共启动及读取去重沿用 `AGENTS.md`。按技能名 `review-agent` 在当前技能目录发现官方技能；目录未列出时检查当前 Codex 技能根（`$CODEX_HOME/skills`，未设置时为 `~/.codex/skills`）下的 `.system/review-agent/SKILL.md`，路径失效时仅在技能根中查找同名技能。读取一次并复用，不修改系统技能，不硬编码个人路径。

技能不可用时如实说明，按以下核心原则降级：只读、缺陷优先，检查指定完整 diff 和必要调用方/测试；仅报告本次引入、可证明、具体可行动且作者会修复的问题，不报告猜测、历史问题、有意行为变化或无意义风格问题，不再次委派 Review。

## 执行步骤

1. 明确比较目标和文件范围：未提交改动、指定提交或基分支。优先采用用户指定范围和当前任务已知基线；无法确定时澄清，不默认为全仓库。混杂未提交变更先按任务文件与已知差异识别，同文件内无法区分归属时澄清，不把他人改动纳入目标。
2. 基分支 Review 按官方技能确定实际合并基线：配置上游存在且领先本地比较分支时采用上游，否则采用本地；执行 `git merge-base HEAD <comparison-ref>`，检查相对该基线的目标 diff。本地分支无法解析时尝试其配置上游，仍不可用则说明限制。
3. 检查指定 diff 的全部相关改动及必要调用链和测试。发现一个问题后继续覆盖剩余改动，不限首文件、首问题或发现数量。范围外调用方仅用于确认影响，不因此扩大被审改动集合。
4. 根据下述业务影响条件补齐专项上下文，确认问题由本次改动引入。高风险事务、库存、权限、数据丢失或共享契约改动深入相关失败路径、回滚、并发和消费者，不自动转成全局规范审计。
5. 复用实施阶段已有、与当前代码版本、配置和覆盖范围一致的验证证据，注明来源、命令和结果。仅代码新变化、具体疑点或证据缺失时追加最小定向验证；更广验证须先说明依赖影响依据和范围。禁止默认全项目/全解决方案测试、重复构建或无关排查；只读审查不修改源码或测试。
6. 检查完目标 diff、必要调用链及相关验证后输出结果并结束。不为凑问题扩大范围，不新增所有任务结束后再审一轮的循环；未能覆盖的范围明确说明。

## 按业务影响补齐上下文

以下是日常 Review 的读取范围规则：专项 Skill 的要求限于本次受影响边界，已读规则复用；其中对实施角色、工作流或总纲的引用不要求重走实施流程，也不自动展开无关章节。技术约束仍有效，不以收窄读取豁免关键门禁。

- 分层或依赖方向改变时检查相关层边界；WPF MVVM 改动遵循 CommunityToolkit MVVM Skill；WPF Grid 行为改动从 EnterpriseGrid Skill 选择相关子 Skill。前后端技能组 index 仅用于定位专项规则，不展开所有子 Skill。
- 数据库、仓储、SQL、连接或结构相关审查读取 `.agents/references/PostgreSQL当前基线.md`，再选择现有后端专项 Skill；SQL Server 迁移记录只作历史证据，不据旧阶段扩大审查或恢复旧实现。
- WPF 异步、资源生命周期、页面协作、权限或质量边界实际改变时，读取对应 runtime-safety、page-architecture、quality-gates Skill 的适用规则。React Web 对象从 `.codex/skills/react-web/index/SKILL.md` 选择相关 API/编辑/工作区/交付技能，不加载 WPF 专项约束。仅汇报已有测试结果不触发整套质量资料。
- API、DTO、枚举或映射变动时检查相关契约、真实消费者、路由/序列化、netstandard2.0 兼容及映射规则；新增、复用、拆分或改名 DTO 时检查 DTO 复用与文件组织门禁。
- 模块职责、页面/API/DTO 用例、状态、数量口径或跨模块交接实际变化，或已有证据提示相关偏差时，按 `.agents/references/业务模块能力与页面契约治理规则.md` 读取命中地图与业务规则相关章节；实际改变采购—入库—库存交接时核对三方契约和偏差。
- 需要判断验收证据是否足够时读取 `.agents/references/测试与验收总纲.md` 的相关章节。事务原子性、库存流水/守恒、幂等、权限权威、数据保全及共享契约兼容等适用要求必须保留。

## 输出

Findings 优先，按 P0–P3 严重程度列出全部可行动问题，每项给出简短标题、目标 diff 内精确文件/行号、受影响场景和依据。没有符合条件的问题写 `No findings.`。

随后简述审查范围、实质验证缺口和剩余风险；仅列真正影响判断的待澄清问题。缺少某个潜在测试不等于已证明缺陷；验证未运行或失败时如实说明。
