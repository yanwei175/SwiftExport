# 架构治理工作流

## 适用与主 Agent

新增或调整 Agent、Router、Workflow、Skill、开发门禁，以及治理规则审计。唯一主 Agent 为 `architecture-governor`。业务模块设计继续使用 Planner；纯代码审查使用 Reviewer。

## 执行步骤

1. 读取 `AGENTS.md`、`.agents/router.toml`、`.agents/architecture-governor.toml` 和 `.agents/references/架构治理与路由判定规则.md`。
2. 明确用户要求是只读审计还是修改；报告主 Agent、Workflow、理由和允许写入范围。只读请求不进入修改步骤。
3. 检查 Git 状态，记录目标文件及原有改动基线；核实是否有其他任务持有相同文件的写入权，未确认停止不得接管。
4. 读取命中的 Agent、Workflow、Reference、Skill 及必要源码/测试；修改 Skill 时先使用 skill-creator，再按技能组入口读取技术规范。不要为治理任务默认加载所有技术 Skill。
5. 区分当前源码事实、已确认目标规则和未决方案；记录冲突来源、影响、规则所有者与最小调整方案。语义变更或权限/豁免超出授权时暂停提问。
6. 按角色、流程、技术规范、路由分工，只在权威位置修改规则，其余入口仅接线；保护用户改动，不顺手重构业务代码或历史资料。
7. 解析全部 Agent/Router TOML，检查角色名及路由 ID 唯一、引用可达和工作流编号；Skill 有改动时执行其结构及引用验证，并如实报告环境限制。
8. 按路由判定规则中的代表性场景核对主 Agent、工作流和写入范围；关键词碰撞必须给出意图/对象依据，不将静态场景检查称为自动路由测试。
9. 审查实际 diff，运行 `git diff --check` 并单独检查新增文件；对比初始基线确认未修改业务及测试源码。纯治理任务不运行 .NET 构建或业务测试。
10. 汇报修改文件、治理依据、入口影响、验证证据、未执行项及风险；仍有阻断冲突或引用失效时不得宣称完成。

## 交付记录

- 每项治理变更记录：修改规则、理由、受影响入口、验证结果。
- 每项未解决偏差记录：来源位置、当前事实、目标规则、是否触碰、影响、最小方案及待谁确认。
- 已有偏差账本时复用其 ID；未决方案仅在本次报告中标记待确认，不自动新建全局账本或写入业务权威规则。
- 接管记录包含原任务、停止确认依据、文件范围和重新读取的基线；无法确认时保持只读并请求协调。
