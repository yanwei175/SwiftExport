# 业务模块设计治理工作流

## 适用

业务模块能力地图、页面规划、页面职责拆分、模块边界、API 用例矩阵、DTO/前端 Model 契约规划，以及现有实现与目标设计的偏差治理。

## 主 Agent

使用 `.agents/planner.toml` 作为唯一主 Agent。本工作流只输出设计、偏差账本和实施任务；已确认方案的治理落盘由 architecture-governor 按授权执行。用户明确授权业务实现后，再切换到对应前端或后端 Agent。

## 执行顺序

1. 读取 `AGENTS.md`、`.agents/router.toml`、`.agents/planner.toml`。
2. 读取 `.agents/references/业务模块能力与页面契约治理规则.md`、业务架构总纲、工程架构总纲和数据模型与状态规则。
3. 按模块索引读取本次设计命中的地图；改变采购—入库—库存交接时核对三方契约。有仍有效的偏差记录才复用ID，不从旧表恢复已退出的目标或待办。
4. 搜索真实页面、ViewModel、前端 Model、Refit API、DTO、Controller、Application Service、Entity、Repository 和测试。
5. 先定义业务能力、上下游和权威事实，再划分页面；不得从现有目录、数据库表或巨型 DTO 反推目标边界。
6. 为每个页面建立职责、禁止职责、读模型、写命令、权限和验收入口。
7. 为每个 API 用例建立 Request/Response/Command/Result、数据来源和真实消费者矩阵，并执行 DTO 复用门禁。
8. 对比目标设计和真实源码，将差异分成已知偏差、新发现偏差或允许的实现差异。
9. 输出不修改代码的能力地图、偏差账本和分阶段重构任务。

## 偏差门禁

- 已知偏差未被当前任务触碰：允许继续，在最终报告中提示，不扩大任务范围。
- 当前任务触碰偏差时，按路由policy先区分有效目标、过期事实与未决设计；需要改变有效目标、扩大授权或豁免门禁时说明依据并等待决定，只暂停依赖该决定的部分。
- 不得因发现偏差自动顺带重构，也不得静默沿用偏差作为新代码模板。

## 强制输出

1. 模块目标与上下游边界。
2. 能力地图和权威事实来源。
3. 页面职责/禁止职责矩阵。
4. 页面动作、状态准入和权限矩阵。
5. API 用例与 DTO/前端 Model 矩阵。
6. DTO 复用或新建理由。
7. 当前实现事实与偏差账本。
8. 分阶段前端、后端、契约和验收任务。
