# 用户权限与设置中心部署说明

本文只说明 022、023 数据库迁移和对应应用版本的部署顺序。执行前应备份目标数据库，并在隔离库使用同版本结构和代表性账号、角色数据完成验证。不要在本说明、命令历史或版本库中保存真实连接字符串、密码或哈希。

## 一、部署顺序

1. 停止向旧后端继续发布账号、密码或权限写入，并备份目标数据库。
2. 使用新的独立查询窗口确认当前会话没有遗留事务：

   ```sql
   SELECT @@TRANCOUNT AS TranCount, XACT_STATE() AS XactState;
   ```

   两项都应为 `0`。如果旧迁移窗口仍有事务，只能在确认该窗口没有其他业务事务后回滚；不确定时关闭该连接并新建查询窗口。
3. 完整执行 `022_SysUser_CredentialVersion.sql`。该脚本幂等增加并回填凭据版本；新列引用使用独立动态批次，兼容首次执行和列已存在但约束未完成的中间状态。
4. 验证 022：

   ```sql
   SELECT c.name, c.is_nullable, dc.name AS DefaultConstraint
   FROM sys.columns c
   LEFT JOIN sys.default_constraints dc
     ON dc.parent_object_id=c.object_id AND dc.parent_column_id=c.column_id
   WHERE c.object_id=OBJECT_ID(N'dbo.SysUser')
     AND c.name=N'CredentialVersion';

   SELECT COUNT(*) AS InvalidCredentialVersionCount
   FROM dbo.SysUser
   WHERE CredentialVersion IS NULL OR CredentialVersion<1;

   SELECT OBJECT_ID(N'dbo.CK_SysUser_CredentialVersion_Positive', N'C')
       AS CredentialVersionCheckConstraintId;
   ```

   预期：列非空、存在默认约束、非法值计数为 0、检查约束 ID 非空。
5. 保持 `023_SysUser_ModulePermissions.sql` 中 `@ApplyLegacyProcurementMigration=0`，完整执行一次。此次执行会幂等创建／核对模块权限表和索引，并输出历史采购候选与异常角色关联；不会写入历史采购模块授权。注意：这是“数据迁移预览”，不是纯只读脚本，因为首次运行会创建数据库结构。
6. 保存并审核 023 输出，重点确认候选用户、`AlreadyMigrated`、孤儿 RoleId 和冗余 RoleName 冲突。先人工处理不能接受的角色异常，不根据冗余名称猜测 Admin。
7. 在受控副本中把 `@ApplyLegacyProcurementMigration` 改为 `1`，再次完整执行 023。记录最终 `InsertedCount`，并核对：

   ```sql
   SELECT UserId, PermissionKey, CreatedBy, CreatedDate, IsDeleted
   FROM dbo.SysUser_ModulePermissions
   WHERE PermissionKey=N'Module.Procurement.Access'
   ORDER BY UserId, IsDeleted, CreatedDate;
   ```

   脚本只为符合条件的历史采购细权限普通用户补采购模块；其他普通用户不会获得默认全模块权限。重复执行不会重复建立活动授权。
8. 022、023 均验证成功后再发布后端。新后端依赖 `CredentialVersion` 和 `SysUser_ModulePermissions`，不能先发布代码。
9. 发布 WPF 客户端。发布后要求所有用户重新登录：旧 Token 没有 `credential_version` 声明，会按设计失效。

## 二、管理员本机密码恢复

恢复工具只允许修改数据库中通过有效 RoleId 关联确认的活动 Admin，不创建账号、不提升角色。先确认 022 已成功应用，再在本机 PowerShell 执行：

```powershell
$env:SWIFTEXPORT_ADMIN_RECOVERY_CONNECTION = '<从本机安全来源取得的连接字符串>'
dotnet run --project .\_tools\AdminPasswordRecovery\AdminPasswordRecovery.csproj
Remove-Item Env:SWIFTEXPORT_ADMIN_RECOVERY_CONNECTION
```

用户名由工具交互读取；新密码隐藏输入并二次确认。不要把密码放在命令行参数中。恢复成功会递增 `CredentialVersion` 和行版本，旧 Token 在下一次受保护请求时失效。

## 三、管理员与普通用户操作

- 管理员创建用户：打开“设置”→“创建用户”。新用户创建后没有模块权限，当前管理员会话不会切换。
- 管理员分配模块：打开“设置”→“模块权限”，选择普通用户并保存完整模块集合。目标用户退出并重新登录后，菜单按新的 `Permissions` 更新。
- 管理员重置普通用户密码：打开“设置”→“重置用户密码”。Admin 目标不能从该入口修改；目标用户旧 Token 会失效。
- 普通用户修改本人密码：打开“设置”→“修改我的密码”，输入当前密码和两次新密码。成功后客户端返回登录窗口。
- 无模块用户：仍可登录、打开首页和设置中心，并修改本人密码；业务模块不会显示。
- 字典管理：管理员打开“设置”→“字典管理”。窗口右上角关闭按钮、Esc 或 Alt+F4 均应经过未保存变更检查；保存中的写操作不会被普通关闭中断。

## 四、尚需在部署环境验证

- 022、023 在目标 SQL Server 版本、排序规则和真实数据上的执行结果。
- 真实 JwtBearer 请求在旧版本、改密后版本和停用账号场景下的 401 行为。
- 实际登录后创建用户、分配模块、重新登录及菜单变化的端到端链路。
- 设置窗口在目标机器上的鼠标、Esc、Alt+F4、焦点返回、高 DPI、高对比度和屏幕阅读器表现。
