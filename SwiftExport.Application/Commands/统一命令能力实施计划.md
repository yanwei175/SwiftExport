### 2. 实体调整

BusinessOperationLog 保留现有字段名与基本类型：

| 字段 | 本批要求 |
|---|---|
| Uid | 日志记录主键，继续由服务端生成 |
| CommandId | 关联业务命令；注释明确它不再承担本批命令的唯一回执职责 |
| CorrelationId | 保留 string；注释改为“产生本条业务审计的调用关联标识，用于关联技术日志，不用于业务幂等” |
| ChangedFieldsJson | 本批命令写实际业务变化摘要，不再存指纹 |
| RelatedObjectsJson | 本批命令写相关业务对象摘要，不再存完整返回 DTO |

CorrelationId 由现有 ICorrelationContext 注入读取。禁止以 CommandId 代替，不新增与它同义的 RequestId 或 LogId 字段。重放不新增业务审计，重试调用有自己的追踪日志。

现有 `UX_BusinessOperationLog_Command` 唯一约束覆盖 Module、OperationType、CommandId，其他模块仍依赖它。本批每个草稿命令仍只追加一条审计，保留该约束；不要提前放开或删除。需要同一操作多条审计时，在对应迁移批次重新设计审计事件粒度。

新增 CommandReceipt 实体、专用仓储及实体元数据。采用设计文档约定的数据库内 CommandId 全局唯一、服务端 ActorUid/CommandType、请求目标、版本化指纹和成功结果。回执只追加，不以软删除释放身份。

### 3. 公共执行与接入

1. 先实现事务所有权、命令锁、回执检查、指纹核对、执行委托、回执追加与提交。复用 DbSession，仓储不依赖 Application 类型。
2. 业务用例提供细权限要求、规范化输入、业务锁和业务行为。执行器不识别入库/出库状态、数量和来源。
3. 入库 Create/Update/Delete 接入；权限先于重放，回执先于首次执行的版本校验。
4. 出库同类命令接入，验证公共机制确实可复用；不复制第二份执行器。
5. 删除这两个服务已被替代的私有执行框架和日志重放分支，保持路由、DTO、成功结果和现有业务规则。
6. 事务内业务、审计、回执全部成功才提交。提交不确定保留 OUTCOME_UNKNOWN；回滚异常不能覆盖原异常。

CommandId 沿用客户端请求体中的 Guid；本期不增加 Idempotency-Key Header 双入口，也不组合用户名生成 ID。不建设重启恢复队列，不假称内存待确认请求已经能够跨重启恢复。

## 最小验证集与停止条件

只运行一次与最终改动匹配的构建和专项验证；出现失败、代码再次变化或明确疑点时才针对性重跑。不得为了“更保险”自动扩展到全仓测试、WPF 全量、Excel 插件、性能测试或全部数据库专项。

1. **构建**：WebApi 项目及本批测试项目/必要依赖，不默认构建整个总解决方案。
2. **执行器专项**：首次成功；同身份同内容重放；用户/操作/目标/内容差异冲突；权限拒绝不能读取回执；重放时旧 ExpectedVersion 不导致重复执行；外层事务不得被接管；取消/回滚/提交不确定不误报成功。
3. **消费者专项**：仅入库、出库草稿相关现有测试及必要补充，验证首次返回形状、版本与审计内容；不重复为每个模块复制完整执行器测试矩阵。
4. **SQL 最小实证**：使用明确隔离的临时空库，聚焦真实命令锁竞争、CommandId 唯一约束和“业务写入+审计+回执”中途故障全回滚。复用已有测试设施，参数化覆盖关键情况，不建大而全的新测试框架。环境缺失或不允许时明确报告未验证，不用 mock 宣称 SQL 锁已验证，不长时间安装环境或尝试多个数据库。
5. **结构与静态检查**：生成器 verify；相关引用、旧分支残留和 diff 检查。

如果其他任务的 BOM/数据库改动阻止整套测试编译，记录具体阻塞，不修改无关断言、不删除有效断言。可以用临时限定项目链接本批真实测试验证自己的改动，但不得把结果描述为全套测试通过。
