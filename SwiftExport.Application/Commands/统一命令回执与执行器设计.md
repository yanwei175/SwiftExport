# 当前命令回执与事务执行

核对日期：2026-10-06。当前公共命令组件是CommandPipeline、CommandRequestValidator与BusinessCommandExecutor；所属模块决定业务输入、权限和状态，不由公共组件定义领域规则。

## 执行顺序

1. CommandPipeline调用所属用例授权，再做异步请求验证，进入业务执行委托；被拒绝不进入写事务。
2. BusinessCommandExecutor要求有效身份、非空CommandId且没有现成业务事务。调用方传入版本、目标及业务字段形成规范化SHA-256指纹。
3. 当前PG回执仓储可先准备命令租约，所属模块可在事务前声明来源/库存资源；首次事务快照前完成必要准备，退出时按顺序释放。
4. 最外层执行器开启用例指定或默认隔离事务，取得命令锁并查完整回执。同身份/类型/目标/指纹重放已存成功结果；不同内容同CommandId拒绝，未知历史格式返回结果不明。
5. 首次执行业务委托，写业务事实、审计和完整结果回执后一起提交。业务失败回滚，不独立提交子服务；提交异常不能仅凭回滚尝试认定未写入。

来源接收和自动单据端口参加父事务，不再次运行独立执行器。普通CRUD及本位币切换并非全部强行进入公共命令流水线，按实际用例实现。

## 返回与日志

CommandExecutionResult保存Value及IsReplay；Pipeline返回现有ServiceResult<T>并区分Succeeded/Replayed/Rejected/Busy/Unknown/Cancelled/Failed完成日志，含关联ID、操作者、耗时和错误代码。业务审计描述发生了什么，不代替机器回执。

COMMAND_BUSY可按原CommandId重试；OUTCOME_UNKNOWN须核实原结果。客户端不能为网络失败自动换ID或更改原请求重放。原业务错误、序列化明确终止与提交结果未知按异常分类分别处理，不用隐藏失败或自动重试换绿色。
