# 命令验证与耗时日志实施方案

状态：已实施于本地 `main` 工作树，尚未提交。首批仅覆盖入库、出库草稿创建、修改、删除六个命令。未执行数据库迁移，也未扩大到其他业务命令。

实际落点：`Commands/CommandPipeline.cs`、`CommandExecutionResult.cs`、`Validation/CommandRequestValidator.cs`、`CommandValidationException.cs`、`Services/Inventory/Validation/Inbounds`、`Outbounds`，以及两个 Manager、Application 依赖注册、WebApi 统一异常出口与文件日志模板。FluentValidation 12.1.1 仅由 Application 直接引用。消费者与公共入口测试位于 `SwiftExport.Application.Tests/Inventory`、`Commands`，HTTP 契约测试位于 `Authentication/HttpErrorContractTests.cs`。

## 1. 目标与范围

在 Application 命令入口统一执行请求验证、记录调用耗时和结果，复用现有命令执行器的事务、锁和成功回执能力。首批仅接入入库、出库草稿的创建、修改、删除，不扩展到采购、过账、反向、查询或 Preview。

同一批实施 FluentValidation 和耗时日志，它们共享命令入口，能一起验证调用顺序。保留 Newtonsoft.Json、现有 Refit 请求与响应格式，不新增实体、表或数据库字段。

## 2. 文件夹地图

命令相关公共能力集中放在 `Application/Commands`，便于在 IDE 中查找。目录排序是便利，目录职责仍限定为命令入口和执行机制；不把查询、Mapster 映射、认证实现和全部公共服务搬入 Commands。

公共验证调用器属于 Commands；具体业务 Validator 归模块，不能全部堆进公共目录。现阶段日志编排可以直接放在 CommandPipeline，不为一次调用再建立日志接口、日志服务和通用行为注册框架。后续只有出现独立职责才拆 `Commands/Diagnostics`。

不要求给每个具体类建立接口，不引入 MediatR、动态代理、反射拦截全部服务或第二套事务框架。

## 3. 当前源码事实

- Application 目标框架为 net10.0，目前没有 FluentValidation 包引用。
- Contracts 为 netstandard2.0，承载共享 DTO 与 ServiceResult，不承载服务端 Validator。
- BusinessCommandExecutor 已支持回执核对和重放，但当前只返回业务结果 T，无法向外围直接表明是否重放。
- 入出库的 RunAsync 负责权限、结果包装和异常转换；其通用 catch 会将未知异常转换为 OUTCOME_UNKNOWN。
- GlobalExceptionMiddleware 当前将未处理普通异常映射为 UNEXPECTED；直接抛验证异常并不能自动得到 VALIDATION。
- ServiceErrorResponse.Create 支持 field，WriteAsync 目前只有 code/message 参数。
- ServiceErrorDto 当前只有单个字段路径，不存在字段错误集合协议。

实施前以 Sol 完成后的源码为准核对上述事实，不覆盖其迁移结果。

## 4. 调用顺序与接线

```text
Controller 完成模型绑定
  → 模块命令入口调用 CommandPipeline
      → 启动 Stopwatch，建立本次调用日志作用域
      → 模块提供的身份与访问权限检查
      → CommandRequestValidator.ValidateAsync
      → 模块命令执行委托
          → BusinessCommandExecutor
              → 开事务、命令锁、查回执
              → 已成功：核对身份/内容，返回原业务结果 + IsReplay=true
              → 无回执：业务锁、版本/状态/数量校验
                        → 写业务、审计、回执 → 确认提交
                        → 返回业务结果 + IsReplay=false
      → 根据成功、失败或异常记录一条完成事件
  → 正常业务结果返回 Controller
  → 验证异常向上传播，由 GlobalExceptionMiddleware 输出 HTTP 400
```

CommandPipeline 是 Application 显式调用的公共入口，注册 Validator 不会自动拦截任意服务方法。迁移六个命令入口时，各自只保留一次 Pipeline 调用，公共入口内部负责自动找对应 Validator 并执行，Controller 不逐个调用 Validator。

Pipeline 接收真实请求类型、服务端确定的命令类型和命令身份、权限检查委托及执行委托。路由 uid 仍由模块校验并传入执行器；不因为它不在 body 中就漏掉验证或指纹目标。不建立前端可传任意命令类型的通用执行接口。

执行器的内部返回值调整为 `CommandExecutionResult<T>`，仅包含 Value 与 IsReplay；由 Pipeline/模块映射成原有 ServiceResult<T>。它不是 Contracts DTO，不进入 ResultJson，不改变前端成功响应。执行器仅保存原业务结果 T，不保存外围状态包装或失败的 ServiceResult。

六个写入口改用新 Pipeline，消除它们与 RunAsync 的重复权限、验证、计时和错误转换。查询以及未迁移命令仍走原入口，不全局重写 RunAsync。模块特定异常转换保留在模块；必须让 CommandValidationException 与请求取消穿过宽泛 catch。业务错误可继续返回失败结果，Pipeline 必须检查 Success/Error.Code，不能仅靠是否抛异常判断成功。

## 5. FluentValidation 边界

仅在 Application 引入 FluentValidation 及所需的依赖注入扩展。实施时选择与 net10.0 匹配的稳定版本并遵循项目包管理方式，不为 VSTO 锁定旧版，不在 Contracts/Core/客户端新增该依赖。

统一采用 `ValidateAsync(request, cancellationToken)`。首批每种顶层命令注册一个 Validator，可通过子 Validator 复用 Draft 结构规则；按明确顺序验证，避免对共享 DbSession 并发执行多个验证器。对已迁移的必验命令，漏注册 Validator 应视为配置错误，不能静默跳过。

| 规则 | 所属位置 |
|---|---|
| CommandId 非空、ExpectedVersion 为正数 | 请求 Validator |
| 必填、长度、枚举、日期有效性、明细数、正数与小数精度 | 请求 Validator |
| 同请求重复行、重复来源、创建不允许已有行 ID | 请求 Validator |
| 当前访问权限 | 模块授权，且必须先于回执披露 |
| 当前数据库版本是否等于 ExpectedVersion | 无回执时，事务内业务校验 |
| 单据状态、仓库有效性、来源可用量、库存 | 模块按业务锁和事务边界校验 |
| 数据库唯一性和不可变约束 | 数据库最终保障 |

Validator 不写库、不预占资源、不建立回执，不查询当前状态来决定已成功命令能否重放。不能把“ExpectedVersion > 0”与“等于当前数据库版本”混为同一规则。

输入结构在重放前校验；已经成功的命令必须能使用原版本重放。未来修改验证规则时还需评估既有成功请求的结构兼容性，避免新规则封死旧回执。

不使用 MVC 传统自动验证管道承载异步规则，不调用 `.Result`、`.Wait()` 或同步 Validate。JSON 反序列化和模型绑定错误继续使用已有 WebApi 错误契约，不强行转成 Application 异常。

## 6. 验证异常与 HTTP 契约

公共验证调用器将 FluentValidation 的失败转成专用 `CommandValidationException`。首批保留内部失败信息所需的安全消息和字段路径，按稳定顺序选择第一条对外展示；不新增 Errors 数组，不借此要求前端升级。

映射结果固定为：

```text
HTTP 400
Success = false
Data = null
Error.Code = ServiceErrorCodes.Validation（VALIDATION）
Error.Message = 安全的中文校验消息
Error.Field = 对应请求字段路径，例如 Draft.Lines[0].Quantity
Message 与 Error.Message 一致
```

字段路径沿用现有 DTO/客户端约定，不擅自混用 PascalCase、camelCase 和显示名称。使用明确中文消息，不将 AttemptedValue、完整请求或内部异常文本直接返回；日志同样不输出请求全文。

GlobalExceptionMiddleware 在通用 Exception 分支前捕获该异常，复用 ServiceErrorResponse 和现有 Newtonsoft.Json 设置。给 WriteAsync 增加可选 field 参数，保持其他调用方兼容。响应清理后保留 X-Correlation-ID；响应已开始时不得重写正文。中间件负责 HTTP 映射，Application 不依赖 HttpContext 或 HTTP 状态码。

## 7. 耗时与结构化日志

计时范围是进入 Application 命令入口至结果确定，包含授权、输入验证、等待锁、执行/重放和事务结束。它不包含之前的模型绑定，也不声称包含 HTTP 响应发送时间。模型绑定或认证中间件直接拒绝的请求，由现有 WebApi 请求日志覆盖。

使用每次调用局部 Stopwatch 和 `ILogger<CommandPipeline>`，由现有 Serilog 管道接收；不直接创建全局静态 Logger、不调整全站日志配置。日志作用域通过 ILogger.BeginScope/现有日志上下文关联 CorrelationId，不能改成 CommandId。字段必须验证实际进入 Serilog 事件，不仅检查控制台显示文本。

每次命令调用恰好一条完成事件：

| Outcome | 条件 | 建议级别 |
|---|---|---|
| Succeeded | 首次业务写入及回执已确认提交 | Information |
| Replayed | 返回已提交回执，未再次执行业务 | Information |
| Rejected | 参数、权限、版本、状态或业务规则拒绝 | Information |
| Busy | 命令锁竞争返回 COMMAND_BUSY | Warning |
| Cancelled | 请求取消且未被判定提交结果未知 | Debug |
| Unknown | OUTCOME_UNKNOWN，不能确认结果 | Warning |
| Failed | 未处理异常或 UNEXPECTED 技术错误 | Error |

完成事件至少包含 CommandType、CommandId（可缺失）、CorrelationId、ElapsedMs、Outcome 和可选 ErrorCode。ActorUid 只取认证上下文。CommandType 使用稳定服务端用例名，不直接取客户端字符串或 C# 类全名。日志模板使用属性占位符，不用字符串插值代替结构化参数。

示意模板：`命令 {CommandType} 执行结束，结果 {Outcome}，耗时 {ElapsedMs} ms`。失败事件可增加 ExceptionType；异常堆栈仍由指定的异常所有者记录。

为避免重复堆栈，首批完成事件仅记录结果、耗时、错误码和异常类型：未处理异常堆栈由 GlobalExceptionMiddleware 记录；被模块转换为失败结果的技术异常继续由模块记录；提交结果未知的原始异常继续由执行器记录。验证拒绝无需再记 Error 堆栈。后续若调整堆栈所有权，必须成对删除旧记录点，不同时重复打印。

完成日志不是 BusinessOperationLog，也不存入 CommandReceipt。回执重放会产生本次技术完成日志，但不会追加成功业务审计。日志输出失败不得改变已提交事实、生成第二个 CommandId 或触发业务重试；保持现有日志提供器的故障隔离方式，不在 finally 中覆盖原业务异常。

## 8. 实施步骤

1. 确认 Sol 已完成相关文件写入，重新读取源码和未提交差异。只接管本计划所需文件。
2. 新建公共验证调用器、验证异常和六个顶层命令 Validator；从原 ValidateDraft/身份/原因校验中按原义迁出规则，保留事务内业务校验。不并行保留两套有效验证规则。
3. 新建轻量 CommandPipeline；让执行器返回内部重放标识，接入一个入库草稿命令验证完整链路，再迁移其余五个。
4. 接通验证异常到统一 HTTP 400 的映射及 field 写入，确认原有宽泛 catch 不截断异常。
5. 接入单次完成事件和结构化字段，逐类确认成功、重放、失败结果、取消及结果未知。
6. 运行下面的最小验证，直接更新本文状态与实际文件清单，删除被替代的孤立代码。无需数据库脚本或前端变更。

## 9. 最小验收

- Validator 单元测试只覆盖实际搬迁规则的代表性边界，不对每个属性机械建立大量同形测试。
- 公共 Pipeline：验证失败不调用执行器；权限先于回执；使用异步验证并传递取消；成功、重放、失败 ServiceResult 和异常的 Outcome 正确；每次只有一条完成事件，耗时非负，字段可查询。不依赖精确毫秒数或 sleep 测时。
- HTTP 定向测试：真实中间件/响应写入返回 400、VALIDATION、Field、Data=null、CorrelationId；普通异常仍返回安全 500，取消保持现有语义。
- 消费者：入出库草稿原有定向测试，重点保留旧 ExpectedVersion 重放、权限撤销拒绝、业务校验仍在事务内以及审计不重复。
- 构建仅涉及后端宿主与目标测试项目；不跑整仓、WPF、VSTO、性能压测或全部数据库测试。
- 本批未改 SQL、数据库约束或业务写入顺序时，不重复展开数据库专项环境建设。上一批真实 SQL 验证缺口保持如实登记，不能宣称被本批单元测试覆盖。

完成标准：六个真实命令入口自动执行 Validator，字段错误沿现有契约到达客户端；同一入口产出可关联、可区分重放的耗时日志；无失败被记录为成功，无事务内业务校验被提前移出，无新增前端依赖或数据库变更。
