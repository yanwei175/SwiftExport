# 系统设置与身份权限职责整理实施计划与提示词

编制日期：2026-09-25。状态：已实施，待统一 Review；验证结果见第 9 节。本文依据实施前源码盘点；只授权职责和目录整理，不授权改变认证、权限及系统设置业务规则。

## 1. 目标与边界

让开发者通过文件夹区分“维护系统资料”“识别当前用户”“维护账号”“判断权限”“分配权限”。Application 的接口与实现按相同能力路径对应，Core 仓储接口和 Infrastructure 实现按所属资源对应。

一次连续实施，内部先整理系统资料，再拆身份权限，最后清理失效文件和验证，统一 Review。无需每移动一个模块就停下来等待确认。

保留简单 CRUD，不为每个方法创建服务，不引入审批、CommandId、命令回执、第二套事务框架或新的权限模型。保持 HTTP、Refit、公开 DTO namespace／字段与现有客户端行为。内部 namespace 随目录迁移。

当前工作区已有 SalesOrders 扁平目录迁移及空服务删除，不得覆盖或回退；执行者先记录工作区基线，区分本轮与既有改动。

## 4. 其他层如何对齐

### 系统资料

- Core/Interfaces/Systems 与 Infrastructure/Repositories/Systems 采用 Dictionaries/Types、Dictionaries/Data、Currencies、ExchangeRates、ViewRoutes、Numbering 对应目录。
- Core/Entities 中相关 Systems 与 SystemEntities 的实体归同一 Systems 能力树，实体名、Table 名、字段及结构元数据不变；只处理本轮对应实体，不清空其他历史目录。
- WebApi/Controllers/Systems 按资源归位，保留 Controller 类名和原路由特性。检查 BaseController 继承动作，不能因搬迁漏掉或新增写入口。
- Contracts/Apis/SystemApis、DTOs/SystemDtos 内按同资源归位，公开 namespace、Refit 签名、序列化字段保持不变。Requests／Responses 放各资源下；ClientVersionInfo 可留现有 Updates 契约目录，不做无意义重复搬迁。

### 身份与权限

- Application/Models/Auth 的认证结果归 Session，权限投影归 Permissions/Evaluation；不要让前端引用 Application 模型。
- Core/Interfaces/Auth 和 Infrastructure/Repositories/Auth 内，认证读取与账号维护归 Accounts，权限事实与分配仓储归 Permissions。本轮允许一个现有仓储供两个窄 Application 服务使用，不为接口对称复制 SQL 或再套转发仓储。
- IAuthRepository、IUserPermissionRepository 及 SysUser／SysRole／SysUserRole 仓储先按事实归位，不在本轮重写持久化协议。GetActiveUsersAsync 可继续由当前权限仓储提供，账号服务注入复用即可。
- ICurrentUser 保持当前 Core 身份上下文位置，WebApi CurrentUser、JWT 签发、凭据校验、DevUser 继续归 WebApi/Authentication。IAuditStampService 属于审计基础能力，本轮不因处于 Auth 文件夹就混入权限分配。
- Application 内移动的密码实现和接口同步所有消费者；不把 BCrypt 或密码策略放到 Contracts。
- Auth DTO 可按 Session、Users、Permissions 物理归位；IAuthApi 保留客户端聚合契约，八条路径和现有账号密码传输契约不变。

根目录的 IBaseService、Core IRepository 是基础抽象，保留现有位置；IBOMService、IBomExecutionReader、BOM 仓储接口属于另一业务模块，本轮不为清空根目录而迁移。完成记录列明保留原因。

## 5. 必须保持的行为

### 认证与账号

- 登录只接受现有活动账号和 BCrypt 密码验证；用户不存在和密码不对保持原响应。
- JWT claims、CredentialVersion、Token 生命周期和验证链不变。密码修改／重置之后旧凭据失效规则必须保留，不能让 Token 验证器误接“仅查用户存在”的新方法。
- me 继续通过唯一权限投影获取角色和权限，不在 Session 复制权限展开规则。
- 注册必须由当前真实 Admin 执行，新用户不自动获取角色或模块权限；保留持久化时管理员身份复核。
- 本人改密仍校验旧密码；管理员重置仍保留目标限制、并发／凭据版本条件和原错误映射。
- 不记录密码、密码哈希、完整 Token；不改变开发身份开关、生产阻断、中间件顺序、匿名端点或授权特性。

### 权限

- Evaluation 是唯一投影和判断入口，未知权限键不放行；所有业务服务迁移到该窄接口，不再持有权限分配能力。
- Admin 固定权限、可分配键集合、现有采购兼容映射保持；模块访问和其他细权限关系不能重新解释。
- 管理用户列表与分配读取仍检查当前真实 Admin。
- 分配保存保持整组替换、目标 Admin 保护、Serializable 事务、仓储内操作者与目标复核、失败回滚与 Session 清理。不要拆成多次独立提交。
- 权限更新何时影响当前 Token、me 和客户端界面沿用现状，不新增缓存或主动刷新协议。

### 系统资料

- 字典类型／数据的层级、受保护记录、删除约束、启用、重复编码与版本规则保持。
- 币种／汇率、页面路由的查询投影和服务端保留字段保持；批量保存仍全成全败。
- 单号格式、序列作用域、事务参加方式和并发分配 SQL 保持，不把编号请求改成只读 Preview 或强制幂等。
- 客户端版本入口保持现有匿名与配置读取行为，不新增数据库表。

## 9. 本轮实施记录（2026-09-25，待统一 Review）

### 实际文件与职责

- Systems 的 Application 服务和接口、Core 仓储接口、Infrastructure 仓储、WebApi Controller 已按 `Dictionaries/Types`、`Dictionaries/Data`、`Currencies`、`ExchangeRates`、`ViewRoutes`、`Numbering` 归位；`SystemBatchSaveSupport` 在 `Systems/Internal`。`ClientVersionController` 仅移动到 `Systems/ClientVersions`。五个系统资料实体及视图路由实体移动到对应 Core 目录，内部 namespace 与元数据 partial 同步；离线 SchemaGenerator 验证生成基线未变化。
- Contracts 的七个 Systems Refit 文件、25 个 Systems DTO 文件按资源物理归位；12 个 Auth DTO 文件按 `Session`、`Users`、`Permissions` 归位。公开 namespace、类型、字段和 Refit 声明均未改。`IAuthApi` 保持原位置和注册身份。
- 后端新增 `Auth/Session/AuthSessionService`、`Auth/Users/UserAccountService`、`Auth/Permissions/Evaluation/PermissionEvaluationService`、`Auth/Permissions/Assignment/UserPermissionAssignmentService` 及镜像窄接口。`IPasswordHasher`、BCrypt 实现和密码规则移到 `Auth/Passwords`；两个 Application 内部模型分别移到 Session 与 Evaluation。Core 的账号与权限仓储接口、Infrastructure 实现分别移到 `Auth/Accounts` 和 `Auth/Permissions`，SQL 和持久化方法未修改。
- `AuthController` 直接注入 Session、Users、Assignment；`CredentialVersionTokenValidator` 只依赖 Session。Application DI 注册四个窄服务，Infrastructure DI 引用迁移后的仓储；运行时权限消费者仅注入 Evaluation。WPF 的同名 `IAuthService/AuthService` 保持原样。

| 新接口 | 方法 | 已迁移的直接消费者 |
| --- | --- | --- |
| `IAuthSessionService` | 登录、me、凭据版本验证 | `AuthController`、`CredentialVersionTokenValidator`、JWT 契约测试 |
| `IUserAccountService` | 注册、本人改密、管理员重置、管理用户列表 | `AuthController`；列表复用现有权限仓储的活动用户查询与唯一权限投影 |
| `IPermissionEvaluationService` | 统一投影、权限键判断 | Session、Assignment、销售、售后、需求、采购、入出库、仓库、PackingList、交付 Controller 和对应测试替身；采购兼容映射仍在这一处 |
| `IUserPermissionAssignmentService` | 读取、整组保存目标权限 | `AuthController`；继续复用同一 `IUserPermissionRepository` 和请求级 `DbSession` |
| Systems 六个资源接口 | 原各资源查询、CRUD、批量或编号方法 | 各原 Controller、Application DI、采购／销售／售后／库存等直接消费者；仓储接口与实现一一归位，未新增转发层 |

### 删除依据与契约核对

- 删除后端 `IAuthService/AuthService`、`IUserPermissionService/UserPermissionService` 四个旧宽类型：生产调用方已迁至上述窄接口，没有保留转发壳。
- 核查源码、项目排除项、DI、WPF/VSTO 引用后，删除旧 Settings 三个服务、三个 Application 接口、三个 Core 仓储接口、三个 Infrastructure 实现；删除空 `ICustomersPoDetailsService`、已排除编译的 `ICustomersPoDetailsRepository/CustomersPoDetailsRepository`、只被后者引用的旧 `IUnitOfWork`。同步移除三层 csproj 中失效的 `Compile Remove` 和空目录项。保留对应实体和数据库表。
- `IDictApi` 仅有自身声明及 WPF 的未消费注册，已删除两者；保留 `ISysDictTypeApi/ISysDictDataApi`。`IBaseService`、`IRepository`、BOM 接口与仓储及审计接口仍有真实职责，原位置不动。
- Auth 八条路径仍为 `POST /api/auth/login`（匿名）、`GET /api/auth/me`、`POST /api/auth/register`、`POST /api/auth/change-password`、`POST /api/auth/admin/reset-password`、`GET /api/auth/admin/users`、`GET /api/auth/admin/users/{userId:guid}/modules`、`PUT /api/auth/admin/users/{userId:guid}/modules`；后七项保留 `[Authorize]`，原四个写入口保留防重复标记。注册、重置、用户列表和权限读写仍由真实 Admin 复核；本人改密只校验本人旧密码。Controller、`IAuthApi` 的 HTTP 方法、参数与返回契约未变。
