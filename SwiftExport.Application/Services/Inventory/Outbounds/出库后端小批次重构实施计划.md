# 出库后端小批次重构实施记录

## 目标与边界

手工出库按 Query、Draft、Posting、Reversal 四类真实用例拆分。正式 Post、Reverse 先经 `CommandPipeline` 授权、验证和记录耗时，再由 `BusinessCommandExecutor` 独占事务、命令锁和持久化回执。业务方法在同一事务内依次锁定单据、重验状态与库存、写库存事实、更新单据和追加 `BusinessOperationLog`。

PackingList 自动出库仍由 PackingList 最外层事务编排，自动端口只使用调用方的 `DbSession`；手工写入口不能处理 `TriggerPackingListId` 非空的自动单据。本次不调整采购、仓库主数据、库存内核或历史业务数据，也不连接数据库。

## 四批文件与验收

| 批次 | 文件范围与职责 | 保持不变的行为 | 最小验证与完成条件 |
|---|---|---|---|
| 查询与草稿 | `Application/Interfaces/Inventory/Outbounds`、`Services/Inventory/Outbounds` 的 Query、Draft、Support、Validation；Controller 与 DI | 十个 HTTP 用例及 Refit 签名、草稿不预占库存、行身份和快照、版本与审计 | 后端构建；出库查询、选品、草稿与 Validator 定向测试；旧 Manager 不再被生产代码依赖 |
| 正式过账 | `OutboundPostingService`、接口、Validator、对应 Controller | 只允许活动、未过账、非 PL 的人工 `StockIssue`；预览只读，提交锁定后重验，负库存阻断 | 成功、权限、版本、重放、冲突、库存及审计失败回滚；回执只由公共执行器保存 |
| 整单反向 | `OutboundReversalService`、接口、Validator、对应 Controller | 原流水完整证明、整单恢复库存、保留原单和原因；不作实际退货或 PL 反向 | 独立权限、异常流水、重放、冲突、失败回滚；业务方法不提交事务 |
| 仓储与目录收口 | Core、Infrastructure 的 Query、Document、ExecutionRead 窄接口及实现；Contracts DTO/API 文件目录；自动端口的必要依赖和测试 | SQL 筛选、排序、锁和版本条件，DTO namespace、Refit 签名、PackingList 原子调用不变 | 后端构建；出库、自动端口及 PackingList 协调器定向测试；核对路由与 DI，无旧宽仓储消费者 |

所有批次只修改本模块及必要的直接调用方，保留无关未提交改动。DTO 仅移动文件并保留公开类型及 namespace，不新增相似契约。没有业务库，真实 SQL 锁、并发和原子性待将来隔离数据库验收；替身测试不能代替该项。若实施中必须改变手工出库准入、反向原因语义或 PackingList 自动命令归属，先由用户决定。

## 本轮实施结果与现存偏差

四批代码已接线；`BusinessOperationLog` 只承载业务审计，首次成功结果由 `CommandReceipt` 保存和重放。WebApi 十个端点、Refit 类型及 DTO namespace 保持不变。`dotnet build SwiftExport-WebAPI.slnx --no-restore` 通过；出库、命令 Validator、自动端口、PackingList 协调器定向测试 77 项通过，路由契约测试 1 项通过。未连接业务数据库，SQL 锁与真实事务仍待隔离环境验证。

原查询 SQL 的 `SearchAsync` 和 `GetDetailAsync` 未过滤 `TriggerPackingListId`，与出库能力地图中“手工 Manager 不查询自动单据”的目标存在偏差。本轮为保持查询行为只移动 SQL，没有改变筛选；后续是否收窄查询需独立业务决定。PackingList 能力地图中“正式过账与反向尚未实现”的状态也落后于当前源码，不作为本轮实现事实。
