# 入库接口与契约目录整理第四阶段实施计划

状态：用户授权由 Sol 实施。主任务规划，实施按后端文件组织、Controller、Contracts DTO/Refit 和 netstandard2.0 技能执行。

## 目标与授权边界

入库 Application 已拆为五类用例。本批将 HTTP 入口和共享契约按同一业务能力组织，保持现有路由、HTTP 方法、授权、请求绑定、JSON 字段、默认值及业务行为不变。所有现有 DTO 均复用，不创建替代模型或兼容转发层。

用户已明确目前没有业务库：按新空库推进，不规划旧数据转换、旧库兼容或旧回执迁移。本文不授权执行数据库脚本。真实 SQL 验证属于正确性验证，本批纯目录整理不扩大数据库测试范围。

写入限于入库 Controller、Contracts 入库 DTO/API、必要的后端及客户端命名空间引用、相关测试和文档。前端只允许为本次命名空间迁移调整引用/类型名，不改 UI、交互、业务流程或依赖框架。

## Controller 划分

统一位于 WebApi/Controllers/Inventory/Inbounds，namespace 跟随目录：

| 类型 | 方法 | 保留的路由 |
|---|---|---|
| InboundQueryController | SearchAsync、GetAsync | POST api/inventory/inbounds/search；GET api/inventory/inbounds/{uid:guid} |
| InboundSourcesController | SearchAsync | POST api/inventory/inbound-sources/search |
| InboundDraftController | CreateAsync、UpdateAsync、DeleteAsync | POST api/inventory/inbounds/drafts；PUT api/inventory/inbounds/drafts/{uid:guid}；POST api/inventory/inbounds/drafts/{uid:guid}/delete |
| InboundPostingController | PreviewPostAsync、PostAsync | POST api/inventory/inbounds/{uid:guid}/post-preview；POST api/inventory/inbounds/{uid:guid}/post |
| InboundReversalController | PreviewReverseAsync、ReverseAsync | POST api/inventory/inbounds/{uid:guid}/reverse-preview；POST api/inventory/inbounds/{uid:guid}/reverse |

每个 Controller 只注入对应窄服务，保留 ApiController、Authorize、FromBody、CancellationToken 和返回类型。多个 Controller 可共享前缀，但必须核对实际端点唯一，不能依赖新控制器名称隐式改变 URL。删除旧 InboundManagerController 与旧选源文件，不留重复端点。

## DTO 文件归属

根目录 Contracts/DTOs/Inventory/Inbounds，子目录及 namespace 同步：

- Query：InboundManagerSearchRequest、InboundManagerListItemDto、InboundManagerDetailDto、InboundHeaderDetailDto、InboundLineDetailDto。
- Sources：InboundSourceSearchRequest、InboundSourceCandidateDto。
- Draft：CreateInboundDraftCommand、UpdateInboundDraftCommand、DeleteInboundDraftCommand、InboundDraftData、InboundDraftLineInput、InboundDraftCommandResult。
- Posting：PostInboundCommand、InboundPostPreviewRequest、InboundPostPreviewDto、InboundPostPreviewLineDto、InboundPostStockImpactDto、InboundPostResult、InboundPurchasePostingSourceDto。
- Reversal：ReverseInboundCommand、InboundReversePreviewRequest、InboundReversePreviewDto、InboundReverseLedgerDto、InboundReverseImpactDto、InboundReverseResult。
- 模块根保留 InboundErrorCodes 和 InboundPostBlockerDto：后者实际被过账与反向预览共同引用，本批保留类型名和单份契约，不复制，也不为了名称改造字段或语义。职责说明标明其共享用途。

一个公开 DTO 一个文件。保持 netstandard2.0 语法和项目引用边界，不引入服务端验证包，不添加字段验证特性。模块内部跨用例复用现有详情与阻断项是本批保持的既有契约，不借此扩展新的跨域复用。

## Refit 与调用方

将 Contracts/Apis/Inventory/IInboundManagerApi.cs、IInboundSourceApi.cs 移至 Apis/Inventory/Inbounds，namespace 跟随目录。保留两个接口的名称和成员，不拆成五个 Refit 接口。当前 WPF InboundManagerViewModel 与 InboundPersistenceService 消费前者，InboundSourcePickerViewModel/InboundSourceDialogService 消费后者，Bootstrapper 注册基址保持原值。

全仓按具体 DTO/接口搜索调用方，包括 Application、Core 仓储接口、Infrastructure Dapper、映射、WPF 服务/ViewModel、测试、XAML 类型引用或字符串类型名。仅迁移相关引用，不对 Inventory 根命名空间做全局粗暴替换。若存在真实 VSTO 消费者则同步机械引用；没有则不触碰该项目。

## 验证与实施顺序

1. 读取最新规则、源码、Git 状态，记录本批端点清单与调用方。保护所有既有未提交变更。
2. 移动 DTO/API 并同步 namespace 和真实引用，保持类型名、字段及序列化配置不变；直接更新实际路径引用。
3. 拆 Controller，更新按旧类型或文件路径定位的契约测试，不降低原断言。检查新端点完整覆盖上表且无重叠。
4. 构建后端宿主和受影响测试项目。Contracts 改名空间影响真实 WPF 消费者，因此允许一次 WPF 项目构建及入库相关契约/持久化定向测试；不跑全前端、全后端或整个解决方案测试。出现无关构建故障如实报告，不顺手修复。
5. 路由/Refit 对齐测试应覆盖全部十个入库端点，包括选源独立前缀，以及 Authorize、参数绑定、返回类型。按现有测试框架复用，不另建测试平台。
6. 必要的代表性序列化检查证明 namespace 移动没有改变 JSON；不重复全面验证已完成的库存业务。全仓检查旧限定名及旧文件路径，区分测试名称/历史描述与真实失效引用。
7. 同步模块职责说明和三份架构文档的实际目录。直接更新“没有业务库”的当前前提，删除不适用的待迁移旧业务库事项；真实 SQL 验证缺口仍如实保留，不混淆二者。

不确定业务语义、字段归属与真实消费者相矛盾、或必须扩大范围时问用户，不猜测；普通机械移动与 using 修正自主完成。
