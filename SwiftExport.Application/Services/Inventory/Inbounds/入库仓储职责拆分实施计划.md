
| 新仓储 | 原方法 | 职责 |
|---|---|---|
| Query | SearchAsync、GetDetailAsync | 入库单据列表与完整详情读模型 |
| Source | SearchSourcesAsync、GetSourcesAsync、ReadPostingSourcesAsync、LockPurchaseSourcesAsync、HasUnprovenReceiptAsync | 采购选源、快照、过账容量及来源并发保护 |
| Document | LockHeaderAsync、LockLinesAsync、SaveAsync、DeleteAsync、MarkPostedAsync、MarkReversedAsync | 入库头行锁、草稿写入与生命周期状态写入 |
| ExecutionRead | HasLedgerAsync、ReadBalanceAsync、ReadActiveWarehouseNameAsync、ReadReverseLedgersAsync、ReadReverseBalanceAsync、ReverseWarehouseExistsAsync | 入库执行所需库存、仓库与原流水只读事实 |
| 删除候选 | LockCommandAsync | 入库命令已使用公共回执命令锁，先确认全仓无有效消费者再删除 |

四类仓储保持现有方法签名和返回模型。Source 是来源数据能力，包含明确命名的事务内锁方法，不应被描述为全部只读。ExecutionRead 不写库存余额或流水，实际写入仍由库存内核负责。

## 4. SQL 与事务不变量

- 每个仓储注入现有 scoped RepositoryBaseContext，使用同一个 DbSession.Connection 和当前 Transaction；不自行建立连接、开启、提交或释放业务事务。
- Query/GetDetail 和 Source 的读取在正式命令内部也必须传入当前事务，不能因目录叫 Query 就绕开外层事务。
- 原采购头 → 采购行 → 入库头行及库存内核锁序保持；Application 决定调用顺序，仓储保留方法内部的稳定排序。
- 参数化、LIKE 转义、分页排序、临时表生命周期、枚举条件、版本条件、软删除、头行身份及审计打戳保持原样。不在搬迁时优化 SQL。
- SourceProjection 留在 Source 实现中供两类来源读取复用；避免复制整段投影。原 CommandDefinition 小型构造帮助方法可在各具体仓储内部保留，不为一行包装另建公共框架。
- InboundReceiptHistorySql.Guard 是入库事实完整性检查，不是旧库迁移脚本。采购进度查询和采购管理查询也在调用；移动 namespace 时同步它们。仍为 Infrastructure 内部 SQL，不开放到 Core/Application，不因当前没有业务库删除事实保护。
- 每条 SQL 最终只有一个实现归属，仓储间不互相转发，也不复制相同锁/写入 SQL。
