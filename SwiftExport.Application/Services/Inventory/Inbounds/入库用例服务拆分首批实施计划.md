# 入库用例服务拆分首批实施计划

状态：第一批已实施并完成定向验证。入库 Posting/Reversal 仍留在原 Manager，真实 SQL 集成测试未在本批运行。

## 范围与完成目标

从 InboundManagerService 提取 Query、SourceQuery、Draft 三类真实用例，形成独立接口、实现和精简依赖。保持全部 HTTP 路由、DTO、权限、错误码和业务行为不变。公共命令机制复用 Application/Commands，不新增执行框架。

本批不拆出库，不迁移入库 Posting/Reversal 的事务与旧回执协议，不创建不存在的 Confirmation 用例，不调整 SQL、数据库、前端或业务规则。发现业务含义不清、权限差异、状态规则冲突或必须扩大范围才能继续时，直接询问用户，不自行推断；不受影响工作继续推进。

## 已核对的调用方与用例

| 新接口 | 方法 | 当前调用方 |
|---|---|---|
| IInboundQueryService | SearchAsync、GetAsync | InboundManagerController |
| IInboundSourceQueryService | SearchSourcesAsync | InboundSourcesController |
| IInboundDraftService | CreateAsync、UpdateAsync、DeleteAsync | InboundManagerController |
| 暂留 IInboundManagerService | PreviewPostAsync、PostAsync、PreviewReverseAsync、ReverseAsync | InboundManagerController，以及采购 SQL 集成测试中的相关调用 |

实施时全仓查找上述接口、具体类型构造、DI 解析、反射及路径契约测试，补齐真实调用方矩阵。测试按调用的方法分别切换，不批量替换整个旧类型名。

## 文件与依赖组织

```text
Application/Interfaces/Inventory/Inbounds/
  IInboundQueryService.cs
  IInboundSourceQueryService.cs
  IInboundDraftService.cs
Application/Services/Inventory/Inbounds/
  InboundQueryService.cs
  InboundSourceQueryService.cs
  InboundDraftService.cs
  Validation/                        从原 Inventory/Validation/Inbounds 移入
  入库用例职责说明.md                  简短说明当前能力和剩余工作
```

接口与实现的 namespace 跟随目录。模块 Validator 类型及规则保持不变，自动扫描注册的程序集锚点与测试引用同步；不改变出库 Validator。计划暂存于 Commands，实施后移动到上述入库模块目录，与模块说明相邻，避免 Commands 长期承载模块文档。

Query 和 SourceQuery 不依赖命令执行器、回执仓储、业务审计写入、单号服务或库存过账服务，不进入写事务 Pipeline。Draft 继续使用 CommandPipeline、BusinessCommandExecutor、CorrelationContext 和原有审计，不依赖库存过账服务。

现有 IInboundManagerRepository 本批可以共享，仓储接口与 SQL 不机械拆分。不得建立新服务再转发旧 Manager：实际逻辑和所需私有方法必须移入新服务。

原 InboundManagerService 和接口本批仅保留四个过账/反向方法及其真实依赖、公共私有辅助方法；删除已经迁出的查询与草稿方法，不保留兼容转发。原 Posting/Reversal partial 文件仍归该剩余类型，不宣称整个 Manager 已消除。后续迁移这四个方法后再删除剩余 Manager。

## 公共与模块内辅助逻辑

梳理 RunAsync、AuthorizeDraftAsync、DraftException、ValidatePage、ValidateIdentity、Fingerprint 等的真实使用关系。草稿的可编辑检查、头行保存和结果构造归 Draft；过账/反向仍使用的辅助方法不得误删。

权限要求和错误映射按现有行为迁移，不顺手把查询 422 改成 400/404。必要时在入库模块建立小型、职责明确的访问/错误辅助组件供真实消费者组合复用；不复制多份完整 RunAsync，不创建聚合全部依赖的基类或万能 InboundContext，也不为几个简单条件强制建服务。辅助类命名与拆分属于实现选择，但不能改变异常传播及事务所有权。

## 最小验证与验收

- 构建 WebApi 和受影响测试项目；不默认整仓或前端构建。
- 运行现有入库 Query/Source/Draft 定向测试，必要时补权限拒绝、分页/选源行为和新 DI 解析的缺口；验证查询零写入，草稿重放与版本冲突行为不变。
