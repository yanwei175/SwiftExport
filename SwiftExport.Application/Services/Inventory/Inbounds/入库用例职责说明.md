# 入库用例职责

本批已将管理查询、采购选源查询和人工草稿命令拆为 `InboundQueryService`、`InboundSourceQueryService`、`InboundDraftService`。各自接口位于 `Application/Interfaces/Inventory/Inbounds/`，五个 Controller 位于 `WebApi/Controllers/Inventory/Inbounds/`，分别只调用对应窄接口；十个 HTTP 端点及其授权、绑定和返回类型保持不变。

`InboundDraftService` 使用现有 `CommandPipeline`、`BusinessCommandExecutor`、命令回执与业务审计。`InboundServiceSupport` 仅统一入库权限、异常映射和分页上界；查询与选源不进入写事务。入库草稿 Validator 位于 `Validation/`。

第二阶段已将 `PreviewPostAsync`、`PostAsync` 迁入 `InboundPostingService`。Preview 保持只读；正式 Post 使用 `CommandPipeline`、`BusinessCommandExecutor` 与持久化 `CommandReceipt`，在执行器的外层事务中按采购来源、入库头行的原顺序锁定并复核，库存内核参与同一事务。业务审计仍使用 `InboundManager` 模块和 `Post` 操作分类，记录状态变化及关联行，不承担机器重放。

第三阶段已将 `PreviewReverseAsync`、`ReverseAsync` 迁入 `InboundReversalService`，并删除旧 `IInboundManagerService` / `InboundManagerService`。Preview 只读；正式 Reverse 先核对模块与反向细权限，按 Trim 后原因校验和计算请求指纹，在公共执行器事务中复核原流水与余额、追加整单反向事实、状态、审计和持久化回执。业务审计继续使用 `InboundManager` 模块和 `Reverse` 操作分类，不承载机器重放。入库仓储名称与 SQL 本批保持原样。

五类入库 Application 用例已拆分。共享契约位于 `Contracts/DTOs/Inventory/Inbounds/` 的 Query、Sources、Draft、Posting、Reversal 子目录；过账、反向预览共用的 `InboundPreviewBlockerDto` 保留在模块根目录；命令忙碌与结果未知使用公共 `ServiceErrorCodes`。两个 Refit 接口位于 `Contracts/Apis/Inventory/Inbounds/`，保留原成员与基址。入库仓储、出库及全项目命令机制尚未因此完成治理。目前没有业务库，按新空库推进，无旧数据或旧回执迁移事项；真实 SQL 原子性仍待隔离数据库验证。
