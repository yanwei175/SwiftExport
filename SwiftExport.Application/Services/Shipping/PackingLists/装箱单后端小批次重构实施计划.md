# 装箱单后端小批次重构实施计划

## 边界

保持现有 11 个 HTTP 用例、Refit 签名、公开 DTO namespace、错误码、权限及 WPF 调用方式。结构治理复用 `CommandPipeline` 的授权、输入验证与耗时日志，以及 `BusinessCommandExecutor` 的事务与持久化回执。`BusinessOperationLog` 仅记录业务审计；执行证据继续保存实际单据、库存流水和反向关联。

PackingList 是正式过账及整单反向的外层事务所有者；自动入库、自动出库端口共用请求级 `DbSession`。本轮不改变供货绑定、客供件选仓或跨供应商调拨的业务规则，不连接业务数据库，不安排历史迁移。

## 批次与完成标准

| 批次 | 文件职责 | 完成标准 |
|---|---|---|
| 1．公共命令 | 公共执行器支持可选 `IsolationLevel`，原调用维持默认事务选择 | 定向测试验证默认与显式隔离级别、回执和回滚 |
| 2．查询和草稿 | Query、Draft 服务及接口分开；草稿入口使用公共管线，事务和回执交给执行器 | 查询只读，草稿保留原有来源、版本、拼箱和包装规则；定向测试通过 |
| 3．正式过账 | Posting 服务保留只读预览、事务前资源探测和事务内锁后重算 | 自动入库先于自动出库；状态、执行证据、审计共用一个事务；重放不重复执行 |
| 4．整单反向 | Reversal 服务独立，依据原执行证据先反向出库和消耗、再反向自动入库 | 只读预览与独立权限保留；任一步失败全回滚；不解释为实际退货 |
| 5．文件收口 | 仓储按 Query、Document、SourceExit 消费接口分离；Controller、DTO、服务归入模块目录 | SQL、路由和公开契约不变；旧宽接口及无消费者的专用命令锁清理 |

## 实施记录与未验证项

上述五批已按当前源码完成。`SwiftExport-WebAPI.slnx` 构建通过；PackingList、公共执行器、来源退出及自动端口定向测试共 141 项，133 项通过，8 项因缺少 SQL Server 业务库而跳过。真实 SQL 锁顺序、并发及跨端口原子性仍需隔离数据库验证；替身测试不作为这三项的证明。

能力地图已将过账、反向和自动端口改为当前源码事实。供货绑定方式、用户调整建议、客供件实际选仓和跨供应商调拨仍是独立业务验收事项，未在本轮结构重构中裁定。
