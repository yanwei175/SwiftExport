## 2. 协议与职责

四个现有请求增加 Guid CommandId（中文职责说明），保留类型名、namespace、路由、Refit 签名及 Version 字段。Contracts 继续满足 netstandard2.0。不接受空 ID，不在服务器生成替代 ID；客户端一次意图生成一次，重试原请求。

| 操作 | CommandType | RequestTargetUid | 指纹内容 |
|---|---|---|---|
| 创建 | DemandPlanning.Source.Manual.Create | null | 全部有效创建输入 |
| 修改 | DemandPlanning.Source.Manual.Update | 来源 Uid | Uid、Version、全部有效修改输入 |
| 关闭 | DemandPlanning.Source.Manual.Close | 来源 Uid | Uid、Version、Trim 后原因 |
| 建议维护 | DemandPlanning.Material.SupplierSuggestion.Update | NetDemandId | NetDemandId、Version、可空 SuggestedPurchaseSupplierId |

创建 Uid、单号仅在首次执行事务内生成，回执保存完整 GrossDemandDetailDto，重复请求不能再取号或建记录。手工 DTO 的 Sku 当前不用于生成事实，不因补指纹而引入新的 SKU 业务；实施者列出实际生效字段，规范化仅复用现有 Trim/null 语义，不修改输入对象。公共执行器负责操作人、类型、目标等公共指纹，不复制哈希实现。

服务复用 CommandPipeline、扫描注册的 FluentValidation、BusinessCommandExecutor、CommandReceipt，删除被替代的私有事务包装。验证纯输入，事务内检查可变来源、产品、供应商及活动物料。权限先于验证/回执，回执先于版本和状态重验。完整业务结果与回执同事务；保留现有默认隔离级别、DbSession、锁顺序和仓储 SQL。完成日志走现有 Serilog；不新建日志表，不将审计日志作为回执。现有业务审计若有则保留，本轮不扩展审计体系。

保持：手工来源只能维护 MD、数量规则、标准/非标字段处理、客供根限制、活动物料阻断、关闭原因 Trim 后不超过500；MD 上游版本可空。建议维护保留版本检查、null 清除、相同建议不递增版本、不改采购事实。无变化成功也保存命令回执；之后版本变化仍能重放原结果。

## 4. 客户端恢复

手工编辑器保存不可变创建/修改原请求；关闭入口保留原来源身份、版本、原因、ID。未知结果期间冻结实际编辑控件，并保护弹窗/编辑器关闭、切换来源、列表刷新和页签关闭；保留手动重试，不只锁保存按钮。

建议逐行持有原请求和结果状态：每行独立 ID；保留当前逐行提交/部分成功语义。成功行不重复新提交；失败行重试原 ID，未提交行不冒充已失败。未知行不得因撤销建议、筛选分页、重载数据或关闭页面而丢失身份；选用阻止破坏性刷新或页面内保存上下文的最小实现，保证重试入口仍可用。不同物料行不共用 ID，不新增批次回执。

必须区分：首次明确前置拒绝（401/403/429）可结束意图；已有未知结果后再前置拒绝不能证明原请求结局，应继续保留。OUTCOME_UNKNOWN、命令忙、无法证明未提交的传输故障保留原请求；明确的事务内业务拒绝结束意图。前置验证/权限拒绝与回执后的业务拒绝不能一概而论。页面/命令分别记录未知状态，不把另一条请求的未知状态继承过来。

回执代表首次结果，不代表当前最新详情。成功后适当刷新当前事实，不能用历史 Version 覆盖后续更改，也不能刷新覆盖其他尚未提交的脏行。不得为了取最新 Version 改写未决请求。页面实例内恢复即可，不增加跨进程持久缓存，不承诺强制退出后恢复。复用现有正确实现，不为四入口新建通用重试框架。
