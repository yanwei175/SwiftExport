# Project Onboarding Guide

## 适用场景

适用于 Codex 接手新项目、新模板、新模块或陌生技术栈时的第一轮扫描和定位。

## 推荐做法

- 先扫描根目录、README、AGENTS、解决方案/项目文件、入口和测试。
- 识别技术栈、目录职责、依赖方向、构建命令和运行方式。
- 找到现有模式后优先复用，不先发明新结构。
- 对模板库项目，要区分 Template、Skill、Guide、Agent、Example、Script。
- 对业务项目，要区分项目专属规则和可复用规范。

## 禁止事项

- 禁止未扫描就直接修改。
- 禁止把一个项目的业务规则当成公共规范。
- 禁止忽略已有 README、AGENTS 或项目约定。
- 禁止在不确认构建方式时随意引入新依赖。
- 禁止把探索命令产生的缓存当成项目文件提交。

## Codex 修改前检查清单

- 当前仓库根目录和工作区状态是否已确认。
- 是否存在未暂存用户改动。
- 相关入口、配置、文档和现有模式是否已读取。
- 任务属于修 bug、加功能、整理文档、迁移目录还是生成模板。
- 是否需要先输出计划或风险说明。

## 常见错误

- 只凭文件名判断用途，不读内容。
- 忽略 `_review`、legacy 或历史目录的保留价值。
- 把示例代码和正式模板混在一起。
- 未检查 Git 状态就覆盖用户改动。
- 发现目录空就直接删除，导致占位意图丢失。
