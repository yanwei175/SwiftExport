# 交付验证

## 完成定义

1. 解决方案构建通过，无新增警告（可空、未使用引用）。
2. 相关测试通过：
   - 状态方法：单元测试（无数据库）。
   - 正式命令：成功、重复 `CommandId` 重放、同 `CommandId` 不同内容 422、`Version` 冲突 409、业务规则不满足 422。
   - 改变下游事实的命令：下游数据与反向操作正确（具体断言来自业务文档）。
   - 权限：未授权 403。
3. Contracts 仍为 netstandard2.0 可编译；DTO 无 `record`/`init`/`required`/`DateOnly`。
4. 改表时有新增迁移脚本，未修改旧脚本。
5. 残留检查：本次范围内无新增 Support/Helper/Manager/Pipeline、无 Newtonsoft、无操作名字面量、无 Service 内 try/catch 转错误、无仓储内开事务。
6. 重构任务：被替换的旧代码已删除或列入明确删除计划。

## 风险测试矩阵

按本次改动类型选最小验证（由旧 `aspdotnet10` 质量门禁抽取，已去掉预览 Token 项；验证范围与证据复用以 [测试与验收总纲](../../../../.agents/references/测试与验收总纲.md) 及 Guide §13 为准）：

| 改动类型 | 最小验证 |
|---|---|
| DTO、枚举、Refit、路由 | 契约测试 + 受影响项目构建 |
| 普通保存/删除 | 校验、`Version` 冲突、软删除、路由与请求体 Id 一致 |
| 查询或分页 SQL | 参数化、筛选、稳定排序、空值与分页边界 |
| 权限 | 未认证 401、无权限 403、有权限通过、拒绝路径零写入 |
| 正式状态命令 | 状态前置、`CommandId` 重放/冲突、`Version` 冲突、审计与回执 |
| 库存类过账 | 数量方向、余额守恒、流水唯一、锁顺序、失败回滚 |
| 反向/冲销 | 原事实不变、反向关系、后续依赖阻断、重复反向拒绝或重放 |
| 实体/结构/索引 | 元数据、脚本、唯一/检查约束、仓储列一致 |

锁、死锁、唯一约束等替身无法证明的行为，标注仍需真实 PostgreSQL 验证。测试失败时区分实现缺陷、环境缺失、旧有失败和无关改动。

## 数据库测试

PostgreSQL 集成测试只在用户授权的测试库运行；不得连接生产库。无授权时说明未运行项。

## 报告

分开列出：已完成、已验证（附命令/测试名）、未验证及原因、发现但未处理的问题。不把“编译通过”表述为“业务验收通过”。
