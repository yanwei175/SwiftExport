# 数据访问规定

本文从旧 `aspdotnet10` 的 Dapper、DbSession、仓储基类、审计打戳、DI 技能和索引的 PostgreSQL 插件章节中抽取而来（决策 #23）。

旧的事务写法 `_session.Transaction = BeginTransaction()`、命令锁服务和 SQL Server 锁提示分别与决策 #6、#7 冲突，已删除。

SQL 形状以 [SqlConventions](../../../../../Handoff/Claude/ReferenceDesign/src/SwiftExport.Infrastructure/Persistence/SqlConventions.md) 为准，会话与事务以 [DbSession 样板](../../../../../Handoff/Claude/ReferenceDesign/src/SwiftExport.Infrastructure/Persistence/DbSession.md) 为准。当前运行接线见 [PostgreSQL 当前基线](../../../../../.agents/references/PostgreSQL当前基线.md)。

## 会话、连接与事务

- `DbSession` 按 scoped 注册，`IDbSession`、`IUnitOfWork` 指向同一个实例。禁止注册多个实例，禁止注册为 singleton。
- 仓储只用当前会话的 `Connection` 和 `Transaction`。不得 `new NpgsqlConnection`，不得自行开启或提交事务，也不得在 Controller 中创建连接。
- 最外层用例拥有事务（`IUnitOfWork`），内层端口不提交。回滚失败不得覆盖原始异常。
- 不硬编码连接字符串。Infrastructure 不读取业务配置去绕开 `DbSession`，也不注册 Application 服务。
- `CancellationToken` 贯穿 Controller → Service → 仓储 → Dapper `CommandDefinition`。

## SQL 与 Dapper

- 必须参数化，禁止 `SELECT *`。分页使用稳定排序。联表查询使用与 DTO 属性一致的显式别名。
- PostgreSQL 物理名使用小写，位于 `public` schema。实体元数据只由一个 `EntityMetadataCache` 提供，禁止为兼容列名添加影响全部 DTO 的 Dapper 全局映射。
- 锁定读取使用 `FOR UPDATE`，由调用方决定锁集合与固定顺序；不写 SQL Server 锁提示。
- 软删除表的查询必须带软删除条件。

## 仓储

- 新代码按 ReferenceDesign 编写按业务对象划分的专用仓储（构造注入 `IDbSession`）。
- 现有泛型仓储（`IRepository<T>` / `PostgreSqlDapperRepository<T>`）只保留单实体 CRUD，不得为单个模块扩大其能力，也不得往里加入分页、动态查询、批量保存或复杂联表。
- Repository 接口放 Core，实现放 Infrastructure。Infrastructure 不引用 Application，不重复实现业务校验。
- 不把页面展示字段塞进 Entity。

## 审计与主键

- 审计字段由仓储在写入时打戳，业务代码不手写。
  - 新增：`Created*`、`Updated*` 采用 `??=`，不覆盖已显式赋值的字段。
  - 更新：覆盖 `Updated*`。
- 审计打戳不能和审批、确认、状态流转混为一谈。库存流水等不可变记录不能通过普通更新修改。
- `GuidSequentialGenerator` 维持现状，不为 PostgreSQL 单独调优。数据库不再另加与应用生成冲突的主键或审计默认值。

## 标识语义

- `Version`：乐观并发。
- `CommandId`：命令幂等。
- `CommandItemId`：批量命令中的单项标识。
- `CorrelationId`：请求追踪；现有列结构不改，写入请求的 TraceId（决策 #26）。

四者不得互相替代。反向操作追加相反记录并引用原事实。正向命令和反向命令使用各自的 `CommandId`。

## PostgreSQL 插件技能

- 遇到 PostgreSQL 通用技术问题，先按名称从当前会话技能目录发现 `postgres-skills:postgresql-best-practices`，读取后再按实际问题选择其 reference。SQL 审查、结构与索引规划、性能分析都适用。
  - 不复制插件正文。
  - 不在项目文档中写入本机路径或插件版本。
- 插件只补充通用建议。Dapper 参数与映射、`DbSession` 共享、事务所有权、业务规则和验收仍以本项目规则为准。
- 只有明确涉及 Apache AGE、openCypher、知识图谱或属性图的任务，才读取 `postgres-skills:pg-graph`。普通 BOM 树、递归 CTE 和单据追溯不触发它。
- Azure 专项规则只在明确的 Azure 任务中使用，或在已核实为 Azure 部署时使用。
- 纯源码审查和离线规划不为激活插件而连接数据库。
- 实际执行前先确认实例、库名、版本和部署类型，不猜测连接串，也不假定存在 `postgres_mcp_*` 工具。能力检查无法完成时，说明限制并停止依赖该连接的步骤。
- 插件示例不是执行授权。DDL、安装扩展、修改配置、导入数据和维护操作都不能由只读任务触发。`EXPLAIN ANALYZE` 会真实执行语句。
- 插件未安装或无法读取时如实报告，不假称已使用。
