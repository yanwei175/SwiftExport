# 后端安全规定

本文从旧 `aspdotnet10` 的认证、管道与 Filter 技能中抽取而来（决策 #23）。其中与决策 #8、#9、#22 冲突的旧内容已经删除。授权写法、异常处理与 ProblemDetails 以 [Backend-Architecture-Guide](../../../../../Handoff/Claude/Backend-Architecture-Guide.md) 为准，本文只补充安全底线。

## 认证与 JWT

- 必须配置 `Auth:JwtKey`；`Auth:JwtIssuer`、`Auth:JwtAudience` 与 `Program.cs` 中的验证参数保持一致。
- 生成 token 时保留可解析的身份 claim：`sub`、`unique_name`、`ClaimTypes.NameIdentifier`、`ClaimTypes.Name`。改动 claim 时，须同步检查 `ICurrentUser` 和客户端。
- 密码只存 BCrypt 哈希。
- 登录失败时不得透露用户是否存在。
- 注册用户需要 Admin 角色。
- 重置密码属于高风险接口，修改时须说明验证方式与安全边界。
- `AuthController` 直接使用认证仓储和 `DbSession`，这是历史特例，普通业务 API 不得照搬。

## 开发用户中间件

- `DevUserMiddleware` 只在 Development 环境且 `Auth:UseDevUser=true` 时生效；请求已带 token 时不注入开发用户。
- `Program.cs` 必须保留生产阻断：非 Development 环境禁止 `Auth:UseDevUser=true`。
- 管道顺序：DevUser 在 `UseAuthentication` 之前，`UseAuthentication` 在 `UseAuthorization` 之前，Controller 映射放在最后。

## 授权

- 只用 `[HasPermission(Permissions.X)]` 加 ASP.NET 授权策略（决策 #9、#22）。
- 高风险命令（确认、过账、反向、作废等）使用独立的细粒度权限码，模块访问或查看权限不能替代。
- 权限检查先于 `CommandId` 历史结果重放：无权限请求不得因重放而拿到首次结果。
- 匿名端点须显式标注 `[AllowAnonymous]`。
- Service 不检查权限。

## 日志与错误响应

- 日志不得输出密码、JWT、验证码或完整的敏感请求体。
- 错误响应（ProblemDetails）不得泄露堆栈、SQL、连接字符串、JWT 或密码。
- 关联 ID = `Activity.Current.TraceId`（无 Activity 时 `HttpContext.TraceIdentifier`），只用于请求追踪，不能替代 `CommandId`；不自写关联 ID 中间件，客户端不发送自定义关联头（决策 #26）。

## 防重复提交

- `[PreventDuplicateRequest]` 基于 `IMemoryCache`，只在单实例内防抖，粒度为“用户 + Action”，不包含请求体，只作为体验补充。
- 不得用它替代 `CommandId` 幂等、`Version`、事务或数据库唯一约束。
- 不用于查询。
- 多实例部署时须改用分布式缓存。

## 配置

- 连接字符串和密钥不得硬编码，也不得提交到仓库。
