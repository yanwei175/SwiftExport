# 数据模型治理（技术方法）

由旧 `aspdotnet10/data-model-governance` 抽取（决策 #23）。业务目的、字段含义、状态取值以 `.agents/references` 与 Core 实体为准。Core 实体与表结构保留，任何结构、约束、字段引用变更先询问用户（决策 #3）；落地脚本按 [backend-schema-change](../backend-schema-change/SKILL.md)。实施顺序以决策日志 #19 及 `Handoff/Refactor` 任务书为准，本技能不规定模块顺序。

## 执行规则

1. 先从业务文档确认实体存在的目的，再读源码事实；区分当前事实、目标设计、迁移建议和待确认业务规则。
2. 根据真实接口、实现、DI 和调用方判断实现状态，不凭目录或命名推断。
3. 只做设计时不修改 Entity、DTO、SQL、脚本或 Repository。

## 字段分类与结论

分类：技术字段（`Id/Uid`、`Version`、`IsDeleted`、审计）、实体自身业务字段、逻辑关系字段、历史快照字段、派生字段、展示字段、UI 状态。

- 派生字段、展示字段通常进 Query DTO；UI 状态不得进 Entity。
- 不能因字段可联表获得就删除历史快照；快照不跟随主数据更新，也不用于校验当前主数据。

每个字段给出一种结论：保留 / 改名（说明兼容影响）/ 移至 DTO / 明确为快照 / 删除候选（列出引用与迁移影响）/ 待业务确认。

## 关系与一致性

- 内部关联优先保存目标 Id；业务编码用于唯一约束、人工查账、外部交换与可读追溯；需保留成立时语义时保存“Id + 编码/名称快照”。
- 不默认增加跨模块数据库外键，逻辑外键靠索引、唯一约束和 Application 校验；不能脱离头存在的明细行可单独评估强 FK，并说明软删除、改单、导入、删除顺序与历史数据影响。
- Application 校验责任：目标存在且未软删除、Id 与编码指向同一记录、当前状态允许建立/解除关系、单位等属性兼容。
- 风险检查：孤立逻辑外键、Id 与编码不一致、同一关系多字段表达无主来源、实时字段与快照混用、软删除主数据被新单引用、改编码破坏追溯。

## DTO 分类与字段来源

- Query DTO（列表、详情、Lookup、统计、联表）由 Dapper 直接映射，不作写入模型；Command/Request 只携带用例参数，不混入展示字段。DTO 规则见 [契约与DTO规定](../index/references/契约与DTO规定.md)。
- 联表 DTO 的每个非本表字段记录：来源表.字段、Join 类型/别名、Join 条件、关系基数、关联过滤（软删除等）、实时/快照、空值策略、更新责任。简单稳定来源可写 XML `<remarks>`；复杂或多处复用的 DTO 输出映射表：

| DTO字段 | 来源表.字段 | Join类型/别名 | Join条件 | 关系基数 | 关联过滤 | 实时/快照 | 空值策略 | 更新责任 |
|---|---|---|---|---|---|---|---|---|

## 表、索引与约束检查

- 每张表职责单一；技术主键与业务唯一标识分开；沿用现有 `Version`、软删除、审计语义；明细行有稳定行号；数量、金额、日期、枚举类型明确；当前余额、正式单据与不可变流水分离。
- 状态按维度拆分（如生命周期、确认、执行、过账），具体取值以业务文档为准。
- 软删除后编码可复用时用部分唯一索引；明细行评估 `(头Id, 行号)` 唯一；每个索引须服务真实用途（唯一性、关联、编码查询、头行、追溯、状态/日期分页、未删除过滤），避免机械建索引和重复前缀索引。
- 应用生成的主键与审计字段不再另加冲突的数据库默认值。
- 建议须区分“当前已有约束”与“目标约束”。

## 实体变更影响分析

修改、删除、改名、拆分或合并实体字段前，按此链搜索真实引用（含列名、SQL 别名、JSON 字段、映射配置和业务编码，不只搜 C# 属性名）：

```text
Core Entity → 其他 Entity / Repository Interface → Contracts DTO/枚举 → 映射配置
→ Infrastructure SQL/别名 → Application Service/命令/校验 → Controller/Refit
→ WPF/VSTO/Web 绑定 → 数据库脚本/索引/约束 → 历史单据/不可变流水/追溯关系
```

影响分类：编译、契约、数据、业务、历史、查询、写入。主数据当前值与单据快照分别分析。

| Entity/字段 | 引用方 | 当前用途 | 变更影响 | 兼容或迁移措施 | 风险等级 |
|---|---|---|---|---|---|

结论只能为：可直接调整 / 需要兼容迁移 / 必须保留为快照 / 需先补关系或 DTO / 待业务确认。

## 最低输出

字段审计表、关系与一致性风险矩阵、DTO 分类与字段来源表、主键/业务键/索引/约束建议、Repository 接口—实现—DI—调用方矩阵、变更影响链、可交给 backend Agent 的分阶段任务与待确认问题。
