# Web 验证与交付

## 输入与范围

输入是实际 diff、版本/锁文件、授权目标、检查脚本、测试与当前工作树状态。实现/补测可写当前任务相关 Web 检查与测试；只读审查不写。文档/技能治理执行 TOML/元数据/引用/diff 验证，不安装工程依赖。

采用 [测试总纲](../../../../.agents/references/测试与验收总纲.md)、[架构矩阵](../../../../docs/Web客户端架构与脚手架决策.md#web-rule-checks)、[多标签第 9 节](../../../../docs/Web多标签工作区设计.md) 和 [契约证据](../../../../docs/Web首批接口契约验收.md)；这里选择证据，不复制规则正文。

## 验收步骤

1. 从行为风险选适用规则及可观察结果，列检查→规则→当前版本→范围。项目未创建、脚本不存在或环境缺失时明确说明，不声称命令已经可用。
2. 工程改动运行项目实际 typegen/typecheck、lint、Framework SPA build；记录根渲染未读浏览器身份/业务 API。依赖边界检查覆盖 shared 反向、feature 深层互引；生成改动重新生成对比 diff，不手工接受漂移。
3. 编辑纯逻辑选择还原、增删、baseline 隔离、回执关联等状态测试；输入/焦点/Form/Activity/缓冲/关闭采用实际浏览器，不能以源码字符串代替行为验证。
4. 保存按端点覆盖未发送、已验证短路、无法确认失败、响应丢失、完整成功及真实行级部分成功；检验接纳/解锁/未知恢复与输入保护闭环。恢复导出场景随功能实施验证，不假称当前存在。
5. 会话/权限验证菜单与已驻留页、候选读取、401 同用户恢复和换用户隔离；普通 Web 测试不自动获得后端、PG 或运行库写权限。真实 API/PG 证据仍按独立接入门槛和明确实例/数据范围安排。
6. 针对最终整合版本执行必要检查，区分本次回归、既有失败和环境；不删除断言/广泛 skip。已通过且无新变化不机械重跑。
7. 审查实际 diff 与新文件、生成变化、权限和日志；报告文件、业务行为、命令及结果、未运行原因、历史与当前证据差异。静态接线、Mock、浏览器、PG、部署分别声明。

## 禁止事项

不以 tsc/Vite 任一单项代替全部必要证据，不以历史 155 通过或断言数量静态更新代替当前整合，不以 WPF 可用推断 Web 可用。不得为交付自动推送、部署、扩权、清库，或临时更换框架绕过失败。
