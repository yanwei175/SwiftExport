# 服务上下文规则

## 当前源码事实

`ServiceBaseContext` 位于 `SwiftExport.Application/Contexts/ServiceBaseContext.cs`：

- 聚合 `DbSession`。
- 聚合 `ILoggerFactory`。
- 作为 Application Service 的基础依赖入口。

当前链路：

```text
HTTP Request Scope
  -> DbSession
  -> ServiceBaseContext
  -> Application Service
  -> Repository Interface
  -> Infrastructure Repository
```

## 使用规则

- 新增服务时优先注入 `ServiceBaseContext`，而不是分别散落注入 `DbSession`、`ILoggerFactory`。
- Service 中需要日志时，通过 `context.LoggerFactory.CreateLogger(GetType())` 或服务基类封装的 `Logger` 使用。
- Service 中需要事务时，使用同一个 `_session`，确保下游 Repository 参与同一连接和事务。
- Repository 基础依赖由 `RepositoryBaseContext` 管理，Service 不直接访问 Repository 的内部连接对象。

## 禁止事项

- 禁止 Application Service 直接 `new SqlConnection`。
- 禁止 Application Service 硬编码连接字符串。
- 禁止 Repository 自己开启跨业务命令的事务。
- 禁止 Core、Contracts、DTO 依赖 `ServiceBaseContext`。
- 禁止把 UI 状态、弹窗、WPF Busy 状态放进 Service Context。

## 检查清单

- DI 生命周期是否为 scoped。
- Service 和 Repository 是否共享同一个 `DbSession`。
- 事务提交、回滚和释放路径是否在 Application 层清楚。
- 日志是否使用 `ILoggerFactory`，没有临时静态 logger。
- 异常是否包装成 `ServiceResult` 或项目统一响应，而不是泄露基础设施细节。
