# DTO 复用与文件组织门禁

## 核心决策

DTO 的设计边界是 API 用例和稳定契约语义，不是页面、数据库表或字段集合。

- 一个页面可以消费搜索、列表、详情、Lookup、命令和结果等多个 DTO，不需要合并成页面万能 DTO。
- 一个 DTO 也不应仅因多个页面需要相似字段就被复用。
- 少量字段重复通常比错误共享契约更安全；只有满足强语义复用条件时才消除重复。
- 页面专用交互状态放 WPF 前端 Model，不进入 Contracts DTO。

## 新建或复用前的强制步骤

1. 先定义 API 用例、传输方向、数据来源和真实消费者。
2. 搜索目标业务模块已有 DTO、Refit API、Controller、Application Service、Mapster/Dapper 映射和前端调用方。
3. 对候选 DTO 执行复用条件检查，不按类型名或字段重合度直接判断。
4. 在实现计划中明确记录：复用哪个 DTO 以及满足哪些条件，或为什么需要新建专用 DTO。
5. 修改现有 DTO 前列出全部调用方；无法确认兼容性时，新建专用 DTO，不扩大旧契约职责。

## 允许复用的条件

除 `BaseDto`、分页包装、保存结果等稳定平台契约外，业务 DTO 只有同时满足以下条件才允许复用：

1. 表达同一个业务概念，并在各消费者中承担同一种角色，例如始终是产品 Lookup 项，而不是一处作列表结果、一处作保存命令。
2. 每个共享字段的业务含义、单位、空值语义、默认值和精度一致。
3. 数据来源、权限过滤、敏感字段暴露和序列化要求一致。
4. 校验规则、必填性、并发字段和版本演进节奏一致。
5. 当前至少存在两个真实消费者；不能只为假设中的未来页面提前抽象。
6. 任一消费者新增字段或改变语义时，不会迫使其他消费者接收无关字段或破坏兼容性。

稳定的 Lookup 项、平台级分页包装、统一保存结果等可以复用；仍需保持明确、窄小的职责。

## 必须新建专用 DTO 的情形

出现以下任一情况时，应新建按用例命名的 DTO：

- 列表、详情、导出、追踪、预览或打印需要不同字段口径。
- 查询结果与创建、更新、确认、过账、反过账等命令输入方向不同。
- 不同接口的权限、脱敏、租户过滤或敏感字段暴露不同。
- 相同字段名在不同流程中单位、精度、空值或业务含义不同。
- 一个消费者变化频繁，另一个需要稳定兼容。
- 为复用必须增加大量可空字段、模式标记或与当前用例无关的属性。
- 候选 DTO 只是结构相似，没有共同且稳定的契约语义。

禁止创建 `CommonDto`、`SharedDto`、`BaseXxxDto` 等只为减少字段重复、但没有稳定业务抽象的类型。继承只用于真实且稳定的“是一个”关系；普通 DTO 组合优先于人为继承层级。

## 页面、API 与前端 Model 的关系

```text
WPF 页面
  -> ViewModel 编排
  -> SearchModel / EditModel / LineModel / StateModel 保存 UI 状态
  -> Refit API
  -> 按 API 用例设计的 Request / Command / DTO / Result
```

- 页面可以调用多个 API，因此拥有多个 DTO 是正常的；这些 DTO 必须放在 Contracts 对应业务模块中，不得定义在 ViewModel 或页面文件里。
- 不为减少页面转换代码而让多个 API 共用万能 DTO；DTO 与前端 Model 的结构性转换使用 Mapster。
- 如果 API 返回的就是稳定只读展示契约，页面可以直接读取 DTO；需要编辑、选择、脏状态或本地验证时转换为前端 Model。

## 命名与文件组织

- 普通传输数据：`XxxDto`。
- 列表行：`XxxListItemDto`。
- 详情：`XxxDetailDto`。
- Lookup：`XxxLookupDto`。
- 查询条件：`XxxSearchRequest`。
- 创建或更新请求：`CreateXxxRequest`、`UpdateXxxRequest`。
- 业务动作：`ConfirmXxxCommand`、`PostXxxCommand`、`ReverseXxxCommand`。
- 命令结果：`XxxCommandResult`。

默认一个公开顶级类型一个 `.cs` 文件，文件名与类型名一致。禁止新增 `XxxDtos.cs`、`XxxModels.cs`、`XxxCommands.cs`、`WorkspaceDtos.cs` 等聚合桶文件。紧密依附主类型且不作为独立契约使用的私有嵌套类型可以留在同一文件。

历史聚合文件采用“触碰即治理”：只拆分本次新增或实质修改的相关类型，不为统一格式批量重写无关 DTO。

## 审查清单

- 是否先搜索了已有 DTO 和全部调用方。
- 是否记录了复用或新建理由。
- 复用是否满足全部强语义条件，而不只是字段相同。
- 是否把列表、详情、命令或不同权限口径错误合并。
- 是否出现为了复用而增加的无关可空字段或模式标记。
- 是否把页面 UI 状态泄露到 Contracts。
- 是否遵守一个公开类型一个文件和类型/文件同名。
- 是否同步检查 Refit、Controller、Application、Dapper/Mapster 和 WPF 调用方。
