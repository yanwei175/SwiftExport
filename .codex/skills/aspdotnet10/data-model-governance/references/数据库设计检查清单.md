# 数据库设计检查清单

## 表结构

逐表检查：

- 表是否只承担一个明确业务职责。
- `Uid` 是否为技术主键，业务编码是否承担唯一业务标识。
- 是否遵循现有 `Version`、`IsDeleted` 和审计字段语义。
- 单据行是否有稳定 `LineNumber`，并可用于排序、Excel 和人工核对。
- 金额、数量、日期、单位和枚举的数据类型是否明确。
- 历史快照字段是否有清楚命名和不可自动刷新的语义。
- 当前余额、正式单据和不可变流水是否被正确分离。

## 默认约束建议

- `Uid`：`uniqueidentifier NOT NULL`，按项目现有约定作为主键。
- `Version`：`int NOT NULL`，默认值与现有乐观并发实现保持一致。
- `IsDeleted`：`bit NOT NULL DEFAULT(0)`。
- 业务编码：根据是否允许软删除后复用，选择普通唯一索引或过滤唯一索引。
- 单据行：评估 `(HeadUid, LineNumber)` 唯一约束。
- 逻辑关系 Uid：根据 Join 和查询方向建立索引。
- 高频状态、日期分页：根据真实 SQL 的过滤和排序建立组合索引。

`Uid` 如果由应用生成顺序 Guid，不机械增加数据库 `NEWID()` 默认值。审计字段默认值必须与 `AuditStampService` 的责任保持一致，不能形成两个相互冲突的写入来源。

## 外键策略

- 不默认增加跨模块数据库 Foreign Key。
- 逻辑外键依靠索引、唯一约束和 Application Service 校验。
- 无法脱离头单独存在的明细行可以单独评估强 FK。
- 每个强 FK 建议必须说明软删除、改单、导入、删除顺序和历史数据影响。
- 历史快照字段不是外键，不要求与当前主数据保持同步。

## 索引检查

每个索引必须服务至少一种真实用途：

- 唯一性保障。
- Uid 关联。
- 业务编码查询。
- 单据头行查询。
- 来源/目标单据追溯。
- 状态和日期分页。
- 未删除数据过滤。

避免为每个字段机械建索引、创建重复前缀索引、忽略软删除条件，以及在没有稳定排序索引时进行分页。

## 输出要求

对每张表给出：主键、业务键、逻辑关系、快照字段、唯一约束、索引、默认值、数据迁移影响和待确认项。建议必须区分当前已有约束与目标约束。
