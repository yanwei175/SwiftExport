# 服务基类规则

## 当前源码事实

`IBaseService<TEntity,TDto>` 位于 `SwiftExport.Application/Interfaces/IBaseService.cs`，当前只提供：

- `GetByIdAsync(Guid uid)`
- `AddAsync(CreateItemRequest<TDto> item)`
- `UpdateAsync(UpdateItemRequest<TDto> item)`
- `DeleteAsync(DeleteItemRequest item)`

`BaseService<TEntity,TDto>` 位于 `SwiftExport.Application/Services/Base/BaseService.cs`，依赖：

- `IRepository<TEntity>`
- `ServiceBaseContext`
- `DbSession`
- `ILoggerFactory`
- Mapster
- `SaveItemResultFactory`

## 适合继承 BaseService 的场景

- 主数据维护。
- 简单字典维护。
- 标准新增、修改、软删除。
- 校验能在新增/修改/删除前完成，不涉及复杂状态机。

## 不适合只靠 BaseService 的场景

- 确认、取消确认。
- BOM 拆解。
- 净需求转采购。
- 入库过账、出库过账、PackingList 过账。
- 反过账、红冲、改单。
- 需要多表事务和执行链路回写的业务命令。

这些场景可以复用 BaseService 的通用查询或基础 CRUD，但必须在具体 Service 中写明确业务命令。

## 校验 hook

具体服务需要业务校验时重写：

```csharp
protected override async Task<string?> ValidateBeforeCreateAsync(List<CreateItemRequest<MyDto>> createItems)
{
    return await Task.FromResult<string?>(null);
}
```

规则：

- hook 只做保存前校验，不做状态流转和下游生成。
- 批量场景应按列表整体校验唯一性、重复行和跨行冲突。
- 错误消息应能直接给前端展示。
- 不要在 hook 中隐藏执行确认、过账、拆解等业务命令。

## 输出规则

- 新增成功返回 `SaveItemResultFactory.FromCreate`。
- 修改成功返回 `SaveItemResultFactory.FromUpdate`。
- 删除成功返回 `SaveItemResultFactory.FromDelete`。
- Repository 返回 `RepositoryWriteResult` 后由 Application 包装为 `ServiceResult<SaveItemResult>`。
