# 复杂单据文件切片

## 推荐用例切片

```text
Contracts/Apis/<Module>/<Document>/
  I<Document>QueryApi.cs
  I<Document>DraftApi.cs
  I<Document>LifecycleApi.cs

Contracts/DTOs/<Module>/<Document>/
  Queries/
  Drafts/
  Confirmation/
  Posting/
  Reversal/

WebApi/Controllers/<Module>/<Document>/
  <Document>QueryController.cs
  <Document>DraftController.cs
  <Document>LifecycleController.cs

Application/Interfaces/<Module>/<Document>/
  I<Document>QueryService.cs
  I<Document>SourceQueryService.cs
  I<Document>DraftService.cs
  I<Document>ConfirmationService.cs
  I<Document>PostingService.cs
  I<Document>ReversalService.cs

Application/Services/<Module>/<Document>/
  <Document>QueryService.cs
  <Document>SourceQueryService.cs
  <Document>DraftService.cs
  <Document>ConfirmationService.cs
  <Document>PostingService.cs
  <Document>ReversalService.cs
  <Document>Policy.cs

Core/Interfaces/<Module>/<Document>/
  I<Document>QueryRepository.cs
  I<Document>Repository.cs

Infrastructure/Repositories/<Module>/<Document>/
  <Document>QueryRepository.cs
  <Document>Repository.cs
```

这是选择清单，不是强制每个单据生成所有文件。只有独立语义、消费者或事务边界真实存在时才拆分。

## 各切片职责

- Query：Search、Detail、Trace 等只读用例，不承担状态流转。
- Source/Lookup：候选和选源查询，不创建预留或正式关系。
- Draft：创建、整体保存、删行或删除草稿，使用 Version 和 CommandId。
- Confirmation：确认上下文、确认与取消确认。
- Posting：Preview/Post，编排库存或正式执行事实。
- Reversal：Reverse/Void/Redress，引用原事实并保留历史。
- Policy：对已加载事实做纯业务判断；不访问 HTTP、不控制事务。

## 拆分步骤

1. 列出真实路由、前端消费者和 Application 方法。
2. 标记每个方法的权限、事务、Repository、状态和输出事实。
3. 按用例族聚类，确认哪些方法必须共享同一事务服务。
4. 先建立窄接口；必要时可由原实现类临时实现多个接口。
5. 迁移 Controller 和调用方，再拆实现和 Repository。
6. 保持路由与 DTO 兼容；需要破坏性变化时单独确认迁移方案。
7. 删除旧接口前运行契约、DI、权限和业务测试。

## 禁止的拆分

- 只按行数把同一类改成多个 partial 文件并称为职责拆分。
- 每个 public 方法建立一个 Service 或 Repository。
- 将事务内必须原子执行的步骤拆成客户端多次调用。
- 为了复用而把领域实体、状态枚举或业务规则塞入泛型基类。
- 按 WPF 控件、页签或布局创建后端服务。
