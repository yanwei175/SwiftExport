# WPF 运行时安全 Skill

## 阶段一边界

本 Skill 只治理跨页面通用的运行时安全闭环：异步查询、写命令、Busy、页面生命周期、错误与反馈边界、资源释放和未保存变更。

不在本阶段建立模块能力地图，不引入 Feature Service、权限体系、普通表单验证框架、导航参数或 Dialog 返回协议，也不扩展到自动化测试体系、可访问性、本地化、性能、日志合规、缓存和导入导出治理。任务若触及这些主题，只记录与本门禁直接相关的接口限制，不顺带设计或实现。

## 核心门禁

- 先把异步操作分为“可被新请求替代的查询”和“不得静默替代的写命令”；两者不能共用同一取消、并发和反馈策略。
- 查询默认采用 latest-request-wins：启动新请求时取消旧请求，并以请求身份和页面存活状态共同阻止过期结果回写。
- 保存、确认、过账、删除等写命令默认禁止并发；不能仅靠按钮禁用，命令入口仍须有 Busy/IsRunning 门禁。
- 页面级 Busy 由最外层用户操作拥有；同一操作的内部刷新调用 Core 方法，不嵌套创建新的 Busy 所有权。
- 调用链必须传递 `CancellationToken`；用户取消属于控制流，不显示失败消息，也不能清空已有数据或覆盖较新的状态。
- 页面离开或释放时取消仍在飞行的查询、防抖和延迟任务；任何延续在提交 UI 前再次检查页面存活和请求身份。
- HTTP、业务失败、字段验证、并发冲突、认证授权、网络/超时、未知异常必须分类处理；不得以异常消息字符串替代稳定分类。
- 技术异常由 API/基础设施边界记录，ViewModel 负责业务上下文和一次用户反馈；不得在多层重复弹出同一错误。
- 初始化必须幂等；重复激活不得隐式重复订阅或重复加载。订阅者负责在离开或 `Dispose` 时解除事件、Messenger、Timer 和 CTS。
- 刷新、搜索、分页、切换对象和关闭前必须处理未保存变更；写命令执行中默认不允许关闭或用取消查询的方式中断提交。

## 渐进迁移

- 不因普通任务批量重构现有页面。
- 触碰异步查询时，至少补齐该查询的取消、过期结果和释放闭环。
- 触碰写命令时，至少补齐命令并发、Busy、结果反馈和成功后状态接纳。
- 触碰页面生命周期时，必须审计该页面全部订阅、Timer、CTS 和未保存关闭入口。
- 现有基础设施表达不了稳定错误分类时，先记录兼容限制，不在 ViewModel 中通过消息文本猜测错误类型。
