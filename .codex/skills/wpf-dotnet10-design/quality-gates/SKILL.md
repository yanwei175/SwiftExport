# WPF 测试与非功能质量门禁 Skill

## 阶段三边界

本 Skill 选择 WPF 验证层级并约束本次受影响的非功能边界，不表示已实现自动执行器，也不要求普通任务执行全部主题。具体业务、测试基础设施、主题、日志、缓存或导入导出实现仍归各自职责。

阶段一的查询取消、Busy、错误反馈与资源释放仍由 `../runtime-safety/SKILL.md` 定义；阶段二的页面职责、权限、验证和导航协议仍由 `../page-architecture/SKILL.md` 定义。本 Skill 只要求用适当证据验证这些行为，不重新定义 owner。

## 必读

公共启动沿用 `AGENTS.md`；以下仅补齐当前业务任务尚未读取的依赖，不回溯已读入口。

- `.agents/references/测试与验收总纲.md`
- `references/前端质量门禁矩阵.md` 的本次适用章节
- 新增或改变页面组成/命令边界时读 `../feature-page/SKILL.md`；质量验证本身不要求重新规划页面
- 模块/完整UI验收或专项非功能评估时读取 `references/检查清单与代表性验收.md` 的适用项；普通定向验证不展开全部代表场景
- 实际改变控件、搜索、主题或 Grid 边界时补读对应子 Skill 和真实源码/测试，不因页面引用控件就全部加载

## 核心门禁

- 先按变更的可观察行为和所需运行环境选验证层，不按文件扩展名或是否方便写测试决定。
- 默认受影响构建与定向方法/类测试；构建、失败优先重测、已有测试复用和扩大条件统一遵循测试总纲，不为本Skill再增加一轮执行。
- ViewModel、纯策略、Converter、映射和验证优先普通单元测试；依赖 Dispatcher、焦点、绑定、DataGrid、控件加载/卸载或键盘路由时使用 STA/WPF 测试；Refit/DTO 的路由、方法、序列化和稳定字段语义使用契约检查。
- 测试验证行为、状态变化和不变量；禁止只搜索实现文本、断言类型内部结构或复制生产算法得到同一结果。
- 触碰交互时检查完整键盘路径、焦点顺序、可理解名称与反馈；颜色不得是唯一状态载体，高对比度和系统强调色下仍须可辨认。
- 新业务提示和展示格式必须有资源 owner；契约和业务计算保持文化无关，解析、时区换算与展示边界显式。
- 禁止 UI 线程同步 I/O。分页、虚拟化、增量更新和批量通知根据代表性数据测量选择；不得缓存虚拟化容器或关闭虚拟化修复功能。
- 日志只记录必要技术诊断和业务动作上下文，不记录 Token、密码、连接字符串、完整敏感 DTO；异常堆栈不得直接展示。审计日志仍以后端为权威。
- 缓存必须有 owner、key、用户/租户隔离、TTL/失效和刷新/写后失效语义；页面 UI 状态不是跨页面缓存，缓存也不等于离线支持。
- 导入导出必须显式限定类型、大小、编码、路径、权限、敏感字段、当前视图/全部数据语义、取消、进度、临时文件和错误报告；CSV/Excel 文本防公式注入。EnterpriseGrid 通用导出管线已退出；业务文件服务负责导出，字段与权限由具体用例明确。
- 豁免只能用于矩阵允许的最小变更，必须记录理由、未覆盖风险和人工验收；“没有测试项目”不是永久豁免。
- 采用触碰即治理：只治理本次变更的质量边界，范围外偏差记入完成证据，不借机重构业务代码。
