# WPF 前端质量门禁矩阵

## 1. 测试与完成证据

| 改动类型 | 首选证据 | 必须覆盖的行为 |
|---|---|---|
| ViewModel、纯策略、Converter、映射、验证、缓存策略 | `SwiftExport.Client.Wpf.Tests` 普通单元测试 | 状态迁移、命令准入、边界值、失败保留、失效规则 |
| Dispatcher、Binding、焦点、键盘、Popup、控件生命周期 | `StaTest` 驱动的 WPF/STA 测试 | 实际事件顺序、焦点/编辑事务、Loaded/Unloaded、重复启停 |
| EnterpriseGrid 行为 | `SwiftExport.Wpf.EnterpriseGrid.Tests` | 原生编辑兼容、虚拟化、选择、验证、导出和关闭功能后的回归 |
| Refit、DTO、路由、序列化 | 契约检查或精确反射检查 | HTTP 方法/路由、Request/Response、字段、枚举与兼容性 |
| 纯治理文档或不改变行为的注释 | 结构、引用和 diff 检查 | 入口有效、范围正确、无业务源码改动 |
| 纯视觉 token/样式且无交互变化 | 构建 + 代表性人工视觉验收 | 普通/禁用/焦点/错误/高对比度状态和影响范围 |

新增或修复业务行为、竞态、权限准入、验证、缓存失效、导入导出或既有回归时必须具备匹配的测试覆盖；现有测试直接覆盖即可定向复用，缺失场景才新增/修改测试，不要求每次改实现都改Test文件。XAML绑定、焦点或生命周期无法由普通单测证明时，不得用ViewModel测试冒充WPF行为证据。

测试应断言公开状态、命令结果、输出文件内容或可观察交互。禁止把 `rg` 命中、源码片段、私有字段名、方法行数、调用次数本身或生成代码文本当成行为测试；调用次数仅在它表达“不得重复提交/不得重复 I/O”等不变量时使用。测试不得复制生产算法来计算同一预期，也不得依赖真实生产 API、用户 Token、个人目录或外部网络。

普通单元测试适用于 ViewModel、纯策略、Converter、Mapster 映射和同步/异步验证。需要 Dispatcher、焦点、真实 Binding、DataGrid、键盘路由、Popup 或 Loaded/Unloaded 时升级为 STA/WPF 测试。Refit/DTO 变更必须检查 HTTP 方法、路由、Body、包装和序列化字段/枚举。

纯治理/文档/无行为注释只做结构、引用和diff，不运行.NET或UI。无交互变化的局部token/样式做受影响构建和必要代表性视觉检查；契约不变且无法合理隔离的小范围Binding修正可说明替代人工步骤、未覆盖风险和补测条件。没有测试项目不构成永久豁免；已有覆盖复用不属于门禁豁免。

日常定向命令示例（按本次实际改动选择，不能全部照跑）：

```powershell
dotnet test .\SwiftExport.Client.Wpf.Tests\SwiftExport.Client.Wpf.Tests.csproj --filter "FullyQualifiedName~ReferenceDataCacheServiceTests"
dotnet build .\SwiftExport.Client.Wpf\SwiftExport.Client.Wpf.csproj
```

报告筛选范围。Grid改动选择相关专项方法/类；涉及多个Client/Contracts/Grid消费者时可统一用前端解决方案构建，复用同批结果，不再逐项目重复执行。整项目test只在模块/阶段验收或共享影响依据成立时选择。Frontend解决方案不含测试项目，构建不替代测试；证据有效性与重测统一按测试总纲，失败/未运行如实记录。

日常不默认启动完整客户端、操作全部页面或分析截图。实际绑定、焦点、键盘、编辑事务用必要的定向STA测试；视觉/布局/主题或明确验收目标按需截图，模块/阶段再选完整UI。既有测试会显示窗口或写PNG时注明副作用与桌面占用，不能假称纯离线逻辑测试，也不在业务任务中顺手改测试基础设施。

## 2. 可访问性

- 所有核心操作可通过键盘完成；Tab/Shift+Tab 顺序符合视觉和业务顺序，Popup/Dialog/抽屉形成可预测焦点范围，关闭后返回触发源或明确后继。
- Enter、Esc、Space、方向键、F2、Tab/Shift+Tab 与业务快捷键不得互相抢占；子编辑器先处理自身语义，未处理输入再交回 DataGrid/宿主。
- 图标按钮、无文本输入、动态筛选和状态标记提供稳定 `AutomationProperties.Name`/HelpText 或等价名称，名称表达动作或状态。
- 错误、Busy、保存成功、空结果和只读状态有屏幕阅读器可理解的文本反馈；颜色、位置、动画不能是唯一线索。
- 使用系统主题、强调色和高对比度资源；焦点、选择、错误、禁用和行状态在高对比度下仍可辨认。
- Grid 不缓存虚拟化容器；搜索、自定义控件和 Grid 的既有键盘/焦点规则继续生效。

新增/改变的交互覆盖受影响键盘与焦点路径；公共主题、壳层或模块/阶段UI验收再覆盖代表性的高对比度、强调色、200%缩放和错误定位。纯VM/后端改动不因此启动窗口，精确事件顺序使用定向STA测试。

## 3. 本地化、文化与格式化

- 新增业务提示、按钮文案、列标题、验证文本和复合格式必须有资源 owner：Feature 专用文案归 Feature，共享控件/壳层归应用资源，Grid 通用文案归 Grid；Contracts 不拥有 WPF 展示文案。
- 禁止继续在 ViewModel、Service、Converter 和 XAML 中复制可见业务文案或格式字符串；页面一次性文案可以局部保留，但重复出现时必须收敛资源。
- 不把中文提示作为错误分类、字段识别或业务分支依据。契约枚举、业务键、缓存 key、业务计算和序列化保持文化无关。
- 日期/时间明确 `DateTimeOffset`、UTC 与业务本地时间的换算 owner；不得把未声明时区的值静默当作本地时间。
- 金额保留币种语义；数量、百分比、单位的精度、舍入、负数、零和空值显示明确，空值不得与 0、空字符串或未知状态混同。
- 用户输入解析、复制粘贴和导入明确接受的文化、小数和日期格式；展示使用当前 UI 文化或显式业务文化。
- 导出区分原始值与显示值：机器格式使用 invariant 规则，面向用户的显示格式由导出请求文化决定。

当前尚无完整多语言资源体系时采用触碰即治理，不借普通任务批量迁移历史 XAML。

## 4. 性能与 UI 线程

- UI 线程不得执行同步网络、磁盘、数据库、图片解码、压缩、Office Interop、大文件解析或大集合计算；仅抓取稳定 WPF 快照和提交最终结果。
- 大列表先确定服务端分页、本地虚拟化、增量加载或快照策略；禁止无依据一次性加载全部数据，不复制业务集合来修复性能。
- 批量加载、回滚、勾选、映射和集合替换使用已有批量通知/抑制能力；快速搜索遵守防抖、取消和 latest-request-wins。
- 禁止关闭行/列虚拟化、长期缓存 `DataGridRow`/`DataGridCell`/编辑器容器、全局 `UpdateLayout` 或扫描可视树修复功能。
- 优化前记录代表性数据规模、设备/配置、操作和指标；优化后复测同一场景，不以主观“更快”作为完成证据，也不凭空规定统一毫秒阈值。
- 影响 Grid 或大集合时覆盖快速滚动、排序筛选、动态列、ItemsSource 重置、编辑和虚拟化并存。

## 5. 日志与敏感信息

- API/基础设施边界拥有 HTTP、网络和技术异常日志；Feature/ViewModel 只补充最小业务动作上下文。用户反馈和错误分类继续服从运行时安全 Skill，不在此重定义。
- `Trace/Debug` 用于可关闭诊断，`Information` 用于低频重要生命周期/动作，`Warning` 用于可恢复异常或降级，`Error` 用于影响操作完成的未预期异常；正常取消、空结果和验证失败不一律记错。
- 禁止记录访问/刷新 Token、密码、连接字符串、Cookie、Authorization Header、完整用户对象、完整敏感 DTO、文件内容或不必要的个人路径。
- 使用结构化属性和稳定动作名；确需记录业务标识时只保留定位问题所需的最小非敏感键，不高频逐项刷日志。
- 异常详情只进入技术日志；UI 不显示堆栈、内部 URL、SQL、本地绝对路径或异常 `ToString()`。
- 前端日志只用于诊断，不能替代后端审计、授权、业务操作历史和单据状态权威。

## 6. 缓存

新增或修改缓存前必须明确：

| 项目 | 要求 |
|---|---|
| Owner | Feature 或基础设施 Service；ViewModel 不用静态集合充当共享缓存 |
| Key | 业务键及必要用户、租户、文化、权限、环境或版本维度，禁止跨身份串数据 |
| 生命周期 | request、页面、会话、进程或磁盘；默认选择最短足够周期 |
| 失效 | TTL、写后失效/更新、版本变化、登出/切换用户、显式刷新和负缓存到期 |
| 并发 | 同键请求合并、取消、刷新覆盖和失败是否缓存必须明确 |
| 安全 | Token、密码、连接字符串、权限敏感结果、未提交编辑和高易变状态默认不缓存 |

缓存命中不得绕过权限、版本和业务状态校验。页面筛选、选中、展开、Busy、脏状态和草稿属于页面 UI 状态，不因为放入 Service 就成为跨页面缓存。登录/租户切换时必须清理或切换命名空间，旧请求不得污染新会话。离线读取、冲突、重试、写队列和恢复语义未明确前，不得宣称缓存提供离线支持。

## 7. 导入导出安全

- 先定义“当前视图、选中项、全部匹配数据、当前页或指定单据”；全部数据不得偷偷等同当前页，列、筛选、排序、权限和敏感字段与语义一致。
- Grid 只负责列元数据、稳定行快照、文化与通用 provider；业务字段、权限、数据获取、文件命名、对话框和错误报告属于宿主 Feature/UI Service。
- 导入验证扩展名和实际格式、文件大小、编码/BOM、行列上限、压缩炸弹、必填列、重复项和逐行错误；不得执行宏、外部链接或嵌入对象。
- CSV/TSV/Excel 文本以 `=`, `+`, `-`, `@` 等公式前缀开头时必须转义或作为纯文本写入；不可信文本不得成为公式。
- 文件路径来自用户选择或受控应用目录；临时文件使用受控唯一名称，并在成功、失败、取消和退出路径清理，最终发布不得留下半成品。
- 大文件流式或分批处理，提供取消和有界进度；取消不报告成功，错误报告可定位但不泄露敏感值。
- 导入/导出前执行页面操作权限和字段敏感性过滤，后端仍是数据访问权威；错误报告也不得包含被排除字段。
- 测试覆盖特殊字符、公式注入、空值、文化格式、错误编码/格式、超限、隐藏/敏感列、取消、写入失败和临时文件清理，并用目标应用实际打开代表性输出。

## 8. 豁免、基线与交付证据

不新增测试的典型情况：纯治理/文档/注释、无行为变化的局部视觉token，或现有直接覆盖且有效证据可用。复用遵循测试总纲，不必为没有Test diff申请豁免；确需替代适用测试时仍说明理由、替代证据、残余风险和补测条件，不降低高风险门禁。

当前事实与偏差：

| 当前事实 | 触碰即治理要求 |
|---|---|
| 已有两个 WPF 测试项目和 `StaTest` | 扩展现有项目，不为单个 Feature 新建重复框架 |
| API Runner、Token Store、版本服务已有日志，但客户端仅 Debug provider 且无统一脱敏清单 | 触碰日志时补 owner/级别/脱敏证据，不在本阶段建设日志基础设施 |
| ReferenceData 与 Image Cache 已有实现和测试，但无统一缓存声明格式 | 触碰缓存时补 owner/key/隔离/TTL/失效，不推广为万能缓存 |
| Grid 已有 CSV/XLSX provider、公式防护和测试，多个 Feature 有导出 Service | 复用 provider；权限、敏感字段、范围与清理由 Feature 负责 |
| Automation 名称集中在少量共享控件/Grid，全页面键盘/屏幕阅读器证据不统一 | 新增或触碰交互补齐，不批量修改无关 XAML |
| 业务 XAML/ViewModel/Service 有大量硬编码中文和格式 | 新增重复文案先资源化，触碰格式明确文化/时区，不全量迁移 |
| 页面已有分页、虚拟化和异步模式，但无统一性能基线 | 触碰性能敏感路径时记录代表性数据与同场景前后指标 |
| 当前无通用业务文件导入管线 | 新增导入前先定义格式、安全、预览/校验与业务命令边界 |

每次交付说明修改、是否改业务代码、实际命令/复用证据及范围、未运行项和实质风险；仅对本次适用的人工/性能/文化/安全项补证据。模块/完整UI或专项非功能验收再按 `检查清单与代表性验收.md` 的相关项收集，不展开无关主题。
