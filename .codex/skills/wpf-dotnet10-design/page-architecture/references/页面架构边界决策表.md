# WPF 页面架构边界决策表

## 0. 范围与所有权

本文是阶段二横向门禁。Agent 管角色边界，Workflow 管执行顺序，本 Skill 管技术决策，Router 管意图触发。阶段一的生命周期、Busy、错误分类、反馈和未保存关闭规则仅引用 `../../runtime-safety/SKILL.md`，不得在此另建第二套定义。

## 1. ViewModel、Refit API 与 Feature Service

| 场景 | 依赖选择 | 所有权 | 禁止 |
|---|---|---|---|
| 单个窄 API 完成页面用例，结果无需跨来源归一化 | ViewModel 直接注入 Refit API，可配合 `IApiCallRunner` | ViewModel 编排并接纳 UI 状态 | 为一行转发强制包装 Service |
| 同一用户动作协调多个 API 或多个调用步骤 | Feature Service | Service 完成跨调用协调并返回稳定结果；ViewModel 接纳 UI | Service 修改可绑定集合、选中项、Busy、验证摘要 |
| 多种接口结果需统一为页面可消费的非 UI 结果 | Feature Service | Service 归一化技术/用例结果，映射规则按 Mapster 门禁 | Service 弹窗或写状态消息 |
| 仅需构造 View、ContentDialog 或平台输出外壳 | Feature 专用 UI Service | UI Service 隔离具体 WPF/WPF-UI 类型 | 业务 ViewModel new View/Window/控件 |

Feature Service 可以依赖 Refit API、`IApiCallRunner`、映射器和无 UI 基础设施；不得依赖业务 ViewModel、View、Window、具体控件、`IDialogService` 或 `IMessageService`。需要用户决策时，由 ViewModel 先调用 Dialog，再把确认后的输入交给 Feature Service。

API 客户端在组合根集中注册。ViewModel 和 Feature Service 不配置 `HttpClient`、BaseAddress、超时、认证 Handler 或序列化，不捕获并解析底层 HTTP 文本。错误类别、日志与反馈 owner 继续服从阶段一；DTO 与 Model 转换继续服从 Contracts DTO 和 Mapster 门禁。

## 2. 权限边界

| 层级 | 问题 | 推荐表达 | UI 策略 |
|---|---|---|---|
| 导航访问 | 用户能否发现并进入页面 | 路由/菜单所需权限策略或能力键 | 完全不适用或不可发现时隐藏；深链打开仍复核 |
| 页面操作 | 用户能否保存、确认、删除、导出等 | 独立操作能力与 `CanExecute` | 可理解但当前无权时禁用并提供原因；敏感入口可隐藏 |
| 字段编辑 | 用户能否修改特定字段/区段 | 字段/区段只读能力与业务状态共同计算 | 保持数据显示，按字段或区段只读；不要整页 `CanWrite` 粗暴代替 |

- 权限代码依赖稳定的权限键、能力对象或策略接口，禁止比较 `"Admin"`、`"Manager"` 等角色名。
- 业务状态能力（例如已确认不可编辑）与用户权限是两个输入，最终可执行性应同时满足二者和阶段一 Busy 条件。
- 隐藏/禁用只改善体验，不构成安全边界。所有 API 调用必须接受后端 401/403，且不得因前端判断为可用而覆盖后端拒绝。
- 页面若只能取得全局 `IsReadOnly/CanWrite`，应记录为兼容限制；触碰具体权限需求时建立最小权限表达，不在 ViewModel 硬编码角色兜底。

## 3. 普通表单验证

| 类型 | Owner | 触发与反馈 | 保存行为 |
|---|---|---|---|
| 单字段本地规则 | EditModel/LineModel 的 DataAnnotations 或验证方法 | 编辑后就地错误 | 有错误时阻断 |
| 本地跨字段规则 | Model 的显式整体验证方法 | 字段变化清理相关旧错，保存或明确动作时重验 | 有错误时阻断并定位首错 |
| 异步验证 | ViewModel 协调、Model 接纳字段结果；必要时窄 Feature Service 调 API | 可取消、防过期，避免每次 setter 直接发请求 | 未完成或失败策略必须明确；不得误清本地错误 |
| 服务端字段错误 | Model 按稳定字段键接纳，ViewModel 负责分发 | 字段就地提示 + 页面摘要 | 保留输入、焦点和脏状态 |
| 业务/状态校验 | 后端 Application 权威，ViewModel 展示命令结果 | 页面或命令级反馈 | 不伪装成字段错误，不接纳成功状态 |

保存顺序：提交当前编辑 → 本地字段验证 → 本地跨字段验证 → 必需的异步验证 → 构造 Request/Command → 调用 API。首错反馈至少包含可见摘要，并尽可能聚焦或滚动到首个无效字段；验证失败、业务失败、409、401/403 和网络失败均不得清空用户编辑。

setter/`OnXxxChanged` 只能做属性相关的轻量通知、清理受影响的陈旧错误，或调度可取消的异步验证；不得在 setter 中保存、导航、弹窗、串行业务流程或直接调用 API。

如果服务端没有稳定字段错误结构，记录协议缺口并使用页面级业务反馈；禁止按消息文本猜测字段名。

## 4. 导航参数、打开请求与 Document Tab identity

- 打开请求是客户端 Feature 协作类型，放 `Features/{域}/{功能}/Models/XxxOpenRequest.cs`；不在 ViewModel 文件中顺带声明公开类型。跨进程 Request/Response 才放 Contracts。
- 打开请求只包含定位与初始化所需的稳定值，不携带 View、控件、ServiceProvider、可变 ViewModel 或整个 DTO 图。
- 普通页面打开请求表达入口意图；文档页签打开请求与 identity 分开：请求可以携带初始化上下文，identity 只负责判定“是不是同一个文档”。
- identity 至少包含路由/文档类型语义和规范化业务键，例如 `sales-order:{uid}`；新建文档使用每次打开唯一的临时 identity。禁止仅用裸 Guid 导致不同文档类型碰撞。
- 每个入口必须明确：重复打开是激活现有 Tab 还是新建；激活现有 Tab 时是忽略、合并还是拒绝新参数。默认不得用新参数静默覆盖未保存编辑。
- 从临时 identity 更新为持久化 identity 时，必须定义与已打开持久化 Tab 冲突的接纳策略；关闭/离开和初始化失败仍服从阶段一生命周期门禁。

## 5. Dialog、抽屉与子页面返回协议

| 协议元素 | 规则 |
|---|---|
| 输入 | 使用窄 `XxxDialogRequest`/`XxxOpenRequest`，由调用方创建，接收方不得反向读取调用方 ViewModel |
| 完成原因 | 明确区分 Confirmed、Cancelled、Closed；取消和窗口关闭不得伪装为成功的默认值 |
| 结果 | 使用 `XxxDialogResult` 或等价判别结果；只返回调用方需要接纳的业务值，不返回 View/控件/ViewModel |
| 未保存检查 | 关闭与取消是否需要确认服从阶段一未保存门禁；写命令进行中默认不允许关闭 |
| 结果接纳 | 调用方仅在 Confirmed 后更新页面；Cancelled/Closed 保持原状态，必要时恢复打开前选择/焦点 |

业务 ViewModel 依赖抽象 `IDialogService`、`IMessageService`、`INavigationService` 或 Feature 专用接口。创建具体 View、绑定 Dialog ViewModel、调用 WPF-UI `ContentDialog` 的职责属于 UI Service/Resolver。Feature Service 不借 Dialog Service 变成混合 UI 编排器。

## 6. 与阶段一的唯一衔接点

| 阶段二定义 | 阶段一继续权威定义 |
|---|---|
| 打开请求、Tab identity、重复激活参数策略 | 首次进入、离开、释放、初始化失败、未保存关闭 |
| Dialog 输入、完成原因、结果对象、接纳规则 | 写命令 Busy、关闭中断、用户取消、反馈 owner |
| 异步验证的 owner 与字段结果归属 | CTS、latest-request-wins、过期结果防回写、页面存活 |
| API/Feature Service 职责 | HTTP/业务/401/403/409/网络/超时/未知错误分类和日志边界 |

若两个 Skill 同时触发，先用本表确定依赖和协议，再按运行时安全门禁实现生命周期与并发；禁止复制一套新的 Busy、CTS、错误分类或未保存机制。

## 7. 当前代表性偏差与触碰即治理

| 位置 | 当前事实 | 触碰即治理要求 |
|---|---|---|
| `Navigation/NavigationService.cs` | 文档去重只比较全局 `DocumentKey`，重复激活直接忽略新参数 | 触碰文档打开时采用带路由/文档类型的 identity，并明确参数接纳；初始化失败收尾仍按阶段一治理 |
| `Features/Procurement/PurchaseOrders/ViewModels/PurchaseOrderDetailViewModel.cs` | `PurchaseOrderDocumentOpenRequest` 直接声明在 ViewModel 文件 | 触碰该打开协议时迁入 Feature `Models` 独立同名文件，不顺带批量搬迁其他类型 |
| `Features/Sales/Orders/Models/SalesOrderDocumentOpenRequest.cs` 与多个打开请求 | 文件所有权已有正确方向，但各类型形态与 identity 规则不统一 | 新增或触碰打开请求时统一窄类型、独立文件和显式 identity，不批量格式化历史代码 |
| `Navigation/NavigationRouteRegistry.cs`、`Shell/ShellViewModel.cs` | 菜单与路由未表达访问权限；当前用户仅暴露 Roles/IsAdmin | 触碰页面访问控制时引入稳定权限/能力表达，禁止在 Shell 或 ViewModel 硬编码角色名 |
| `Mvvm/ViewModelBaseEx.cs` 与业务页面 | `CanWrite/IsReadOnly` 主要表达整页写入，尚不能区分操作与字段权限 | 触碰细粒度权限时拆分对应能力；保留后端授权权威和业务状态条件 |
| `Features/DemandPlanning/GrossDemand/Models/GrossDemandManualEditModel.cs` | 已使用 `ObservableValidator` 和跨字段保存校验，可作局部起点；仍以字符串摘要为主 | 触碰验证时补齐首错/字段 owner；服务端字段错误须用稳定字段键，不复制消息文本猜测 |
| `Services/Api/ApiCallRunner.cs` 与现有 Contracts | 当前没有通用结构化服务端字段错误接纳通道 | 触碰字段错误链路时先明确最小契约；协议未具备时保留页面级反馈，不在 ViewModel 解析文本 |
| `Features/**/Services/*DialogService.cs` | 已隔离部分具体 View/ContentDialog，但结果常用 `bool`、`null` 或空集合合并取消/关闭 | 触碰返回协议时引入可判别结果并由调用方显式接纳；具体 WPF-UI 类型继续留在 UI Service |
| 多数业务 ViewModel 与 `Bootstrapper/ApiRegistrationExtensions.cs` | 单个 Workspace API 直接注入是主流，尚无多 API Feature Service 范式 | 保留简单窄调用；只有真实多接口编排/归一化时新增 Service，并在组合根注册 |

范围外偏差只记录，不自动重构。若本次改动会复制或扩大偏差，实施前说明规则、源码事实、影响和最小迁移方案；只治理任务实际触碰的边界。

## 8. 实施与审查清单

- 是否列出 ViewModel 全部 API/Service/UI 依赖，并说明直接 Refit 或 Feature Service 的理由。
- Feature Service 是否无页面状态、无弹窗、无 View/控件依赖；API、Service、ViewModel 是否在正确组合根注册。
- ViewModel 是否远离 HTTP/序列化细节，错误与 DTO/Mapster 是否继续服从既有门禁。
- 导航访问、页面操作、字段编辑权限是否独立，是否存在硬编码角色名或把前端判断当授权。
- 字段、跨字段、异步、服务端字段错误与业务/状态失败是否各有 owner；失败是否保留编辑。
- 保存是否阻断无效输入并提供首错反馈；setter 是否只承担轻量属性响应。
- 打开请求是否由 Feature 拥有并独立成文件；identity、重复打开和参数接纳策略是否明确。
- Dialog/抽屉/子页面是否区分确认、取消、关闭，结果是否只在确认后接纳。
- 是否只引用阶段一运行时安全，没有重定义 Busy、生命周期、错误分类和未保存关闭。
- 是否遵守触碰即治理并记录范围外代表性偏差，没有修改或重构无关业务代码。
