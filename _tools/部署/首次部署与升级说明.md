# Windows Server 2019 内网部署：首批

> 2026-10-08 已选择 Caddy 内部 CA + Windows 服务的新方案。首次切换与日常更新请从 [Caddy 首次安装与日常更新](Caddy首次安装与日常更新.md) 开始；下文保留旧 IIS 部署记录，不作为本次安装步骤。

> 已有服务器的日常更新请使用 [现有服务器后端更新操作手册](现有服务器后端更新操作手册.md)。2026-09-26 实际采用手工部署，站点/应用池名为 `SwiftExport_WebApi`，目录为 `D:\Apps\SwiftExport_WebApi`；本文件下方保留的是通用首批方案与脚本验证记录，示例名称和“尚未部署”描述不代表当前实际服务器状态。通用部署脚本未按本次手工站点名称迁移，不要直接用它更新现有站点。

目标：IIS 托管现有 WebAPI，用内网 IPv4 和内部证书访问，产品图片位于独立目录。以下脚本已提供，但尚未在你的服务器实际执行或验收。首次安装需要管理员权限及数据库连接等环境信息；后续升级复用配置、文件和证书。

## 本批功能

- FileStorage:Enabled 显式启用时，从 FileStorage:RootPath/ProductImages 提供 /files/ProductImages 下的 GET/HEAD 图片读取。
- 根目录不配置时保持原功能；启用但目录无效会明确阻止启动。目录由部署脚本创建。
- 只开放 jpg/jpeg/png/gif/webp/bmp，不开放目录列表、其他类型或 AfterSales/Temporary。
- 固定路径图片使用 no-cache、标准 ETag/Last-Modified，支持条件请求和 Range。人工替换后不要刻意保留原修改时间；同大小且同时间的文件可能无法被标准静态文件校验区分。
- 这不是上传、缩略图或附件服务；不建表，不改 Product.MainImage，不改 WPF 缓存。浏览器能访问以后再接 WPF 网络图片。

## 第一次部署需要准备

1. 服务器固定内网 IPv4（以下 192.168.1.10 仅为例子）、可用 HTTPS 端口，默认 443。不要照抄示例 IP。
2. 管理员账户，磁盘目录建议 D:\Apps\SwiftExport.WebApi 与 D:\ERPFiles。
3. 数据库连接账户。不要为了部署脚本修改数据库或关闭现有数据库服务；SQL Integrated Security 涉及应用池身份，应由管理员配置，不直接假定本机开发登录可用。
4. 从微软取得 **.NET 10 Hosting Bundle** 安装程序，复制到服务器。本批发布依赖框架，不需要在服务器安装 SDK。

## 开发电脑：打包

先正常恢复项目依赖。随后从仓库根目录运行（选择一个不存在的新输出目录）：

```powershell
& .\_tools\部署\打包后端.ps1 -OutputDirectory D:\Packages\SwiftExport-v1
```

打包脚本会移除发布包内的开发配置。将输出目录及 Deployment 工具目录复制到服务器；不要把整个源代码仓库、开发 appsettings、CA 私钥交给客户端。

## 管理员电脑：创建一次内部根及服务器证书

在受控、长期保留的管理员 Windows 电脑用管理员 Windows PowerShell 执行：

```powershell
& .\创建内网证书.ps1 -ServerIp 192.168.1.10 -OutputDirectory D:\Certificates\SwiftExport-first -CreateRoot
```

输入 PFX 密码。输出 Root.cer、Server.pfx、证书信息.txt。根私钥留在该电脑的 LocalMachine\My，设置为不可导出；服务器证书有效期一年，根十年。这是首期小型内部签发方案，不是完整企业 CA/吊销平台。保护该管理环境，根遗失后需重新部署客户端信任；公司已有内部 CA 时优先由管理员使用其签发。

将 Server.pfx 安全复制到服务器，在服务器管理员 PowerShell 导入：

```powershell
$password = Read-Host 'PFX 密码' -AsSecureString
Import-PfxCertificate -FilePath D:\Install\Server.pfx -CertStoreLocation Cert:\LocalMachine\My -Password $password
```

服务器也应使用下节脚本信任同一 Root.cer。记录服务器证书指纹，核对证书信息.txt。不必把根私钥搬到服务器。

## 服务器：准备环境与配置

首次运行：

```powershell
& .\准备服务器环境.ps1 -HostingBundleInstaller D:\Install\dotnet-hosting-10-win.exe
```

参数填实际文件名。脚本安装 IIS 和管理员提供的已签名 Hosting Bundle；不会自动重启，首次维护时由管理员安排重启。若 IIS 已托管其他程序，安装和重启会影响其运行，应先安排维护窗口。

复制服务器配置示例.json 为服务器私有配置文件，填写 ConnectionStrings.Default、Auth.JwtKey、JwtIssuer/Audience。JWT 密钥至少 32 字符、使用随机值且升级保持不变；不要提交配置到仓库。可用以下方式生成随机密钥，直接写入该私有文件，避免输出密钥到终端：

```powershell
$configPath = 'D:\Install\服务器配置.json'
$config = Get-Content -LiteralPath $configPath -Raw | ConvertFrom-Json
$bytes = New-Object byte[] 48
$rng = [Security.Cryptography.RandomNumberGenerator]::Create()
try { $rng.GetBytes($bytes) } finally { $rng.Dispose() }
$config.Auth.JwtKey = [Convert]::ToBase64String($bytes)
$config | ConvertTo-Json -Depth 10 | Set-Content -LiteralPath $configPath -Encoding UTF8
```

真实数据库连接信息由你填写，不使用仓库里的开发配置。文件只给管理员及运行应用的账户读取。

```powershell
& .\部署内网服务器.ps1 -PackagePath D:\Install\SwiftExport-v1 `
  -ServerIp 192.168.1.10 -CertificateThumbprint '服务器证书指纹' `
  -ConfigurationPath D:\Install\服务器配置.json
```

脚本创建专用 IIS 站点/应用池、图片目录、日志目录及最小必要权限；固定 Production 环境、绑定 HTTPS。防火墙规则仅 Domain/Private 配置文件、指定 IP、默认 LocalSubnet。不同 VLAN 按真实内网 CIDR 指定 InternalSubnets；不要为了排错开放 Any。现有防火墙/路由器规则仍需管理员核对，新增限制规则不能收紧原本更宽的允许规则。

已有同名非目标站点、端口冲突或配置错误会中止，不接管其他业务。复制失败保持 app_offline.htm，不启动半更新程序。发布不会镜像删除文件，也不会自动执行数据库迁移；重大版本含删除程序集时，应另审发布清单，不能靠累积覆盖处理一切升级。

## 客户端信任与验收

只分发 Root.cer 与已通过可信渠道核对的根指纹，在客户端管理员 Windows PowerShell 执行：

```powershell
& .\安装客户端根证书.ps1 -CertificatePath D:\Install\Root.cer -ExpectedThumbprint '根证书指纹'
```

后续可由安装包调用，目前提供的是脚本，不是已经集成的客户端安装器。不能用跳过证书校验解决连接失败。

人工放置一张真实 JPEG 到 D:\ERPFiles\ProductImages\TEST.jpg，在另一台客户端打开：

```text
https://实际服务器IP/files/ProductImages/TEST.jpg
```

非 443 端口需加端口号。验证无证书警告、图片可读、不存在文件 404、同路径替换刷新可见。然后再验登录与只读业务查询，避免将图片读取成功误认为数据库接线已通过。当前 WPF 尚不能读取 HTTP 图片，不修改原 MainImage 来试验。

## 后续升级与证书续签

升级先备份现有程序和私有生产配置，保留文件根目录；维护窗口用新的发布包重新运行部署脚本，**不传 ConfigurationPath**。脚本保留配置、不重新生成证书。失败可用原发布包重新部署；本批没有自动回滚或无人值守健康检查承诺。

服务器证书到期前，在持有根私钥的原管理员电脑重新运行创建内网证书.ps1，传 -RootThumbprint 及新的输出目录，不传 -CreateRoot。导入新 PFX 后部署脚本用新服务器指纹更新绑定；同一根仍有效时，客户端通常不用重新安装根。IP 变化也需重新签发。根替换则需要重新下发客户端信任。
