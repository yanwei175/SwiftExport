# 本机管理员密码恢复工具

当前工具入口使用 PostgreSQL + Dapper。迁移进度和验证证据见 [主迁移清单](../../docs/postgresql-migration/主迁移清单.md)及[恢复工具验收](../../docs/postgresql-migration/任务结果/P06-密码恢复PG存储-主控验收.md)。全站数据库接线仍按主清单推进，不能从本工具接入推断已完成全站切库。

目标 PG 库须已具备验收所需的 `sys_user`、`sys_role`、`sys_user_role`、凭据版本/审计字段及 `public.erp_dictionary_ci`。工具不会创建或迁移结构；原 SQL Server 的 `022_SysUser_CredentialVersion.sql` 不适用于 PG。使用目标 PostgreSQL 连接字符串设置原环境变量并运行：

```powershell
$env:SWIFTEXPORT_ADMIN_RECOVERY_CONNECTION = '<本机安全取得的 PostgreSQL 连接字符串>'
dotnet run --project .\_tools\AdminPasswordRecovery\AdminPasswordRecovery.csproj
```

工具交互读取现有 Admin 用户名，并隐藏读取、二次确认新密码。它只修改活动且通过真实角色关联确认的 Admin，不创建用户、不授予角色、不接受命令行密码；成功时递增 `CredentialVersion` 和 `Version`，令旧 JWT 在下次请求时失效。

不要把连接字符串、密码或哈希写入脚本、日志、聊天记录或版本库。完成后从当前 PowerShell 会话移除环境变量：

```powershell
Remove-Item Env:SWIFTEXPORT_ADMIN_RECOVERY_CONNECTION
```
