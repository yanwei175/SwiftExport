# 本批基础数据补迁

一次性P05工具，固定七张基础表、当前实体映射和有效关联条件。不是长期双库支持；不启动WebApi、不播种账号、不搬单据历史、不写源库或备份库。

主控独占运行和数据库写入；A/B只读报告不运行此工具。连接只经进程环境变量 `SWIFTEXPORT_P05_SOURCE_CONNECTION`、`SWIFTEXPORT_P05_TARGET_CONNECTION` 传入，不把连接串写进命令、报告或文件。源固定 `192.168.3.12:1433/dv_next`（源配置大小写dv_Next属于同一库），PG固定该实例5432的dv_next或指定failure库。

```powershell
dotnet build _tools/基础数据补迁/基础数据补迁.csproj --no-restore
dotnet run --project _tools/基础数据补迁/基础数据补迁.csproj --no-build -- --preview
dotnet run --project _tools/基础数据补迁/基础数据补迁.csproj --no-build -- --apply-isolated docs/postgresql-migration/任务结果/P05-基础数据补迁-隔离库预检.json
dotnet run --project _tools/基础数据补迁/基础数据补迁.csproj --no-build -- --apply-runtime docs/postgresql-migration/任务结果/P05-基础数据补迁-运行库预检.json
```

首次构建前用 `dotnet restore ... --ignore-failed-sources -p:NuGetAudit=false` 生成资产，复用D:/DevCaches/NuGet已有依赖，不复制别的项目资产文件。

`--preview`只有SELECT，检查所有126列映射、实际NULL/长度、空或重复UID，输出数量、UID MD5和全部字段规范化SHA256；逐表READ COMMITTED不是稳定源快照。它不替代A/B的decimal、枚举、关联闭包、唯一/CHECK、BOM全图审查，也不证明文件可访问。

`--apply-isolated`只允许dv_next_pg_failure_tests_20261004；先在最长30秒、锁等待5秒的Serializable只读源事务取得候选，提交释放源锁后才写PG。不能启用源Snapshot或用NOLOCK。源可能短时阻塞并发写入；遇到锁等待/超时或数据变化即退出，不能循环重试。

`--apply-runtime`只允许dv_next，主控必须先完成隔离库本批验收、核实备份可读及运行库旧数据摘要，使用运行库独立预检JSON。两个写入参数不是自动切库部署入口；不启动WebApi，不允许给备份改名绕过库名守卫。

写入前必须与已核对的预检文件数量及全部字段摘要完全一致。PG同一事务锁定七表写入边界，并重新确认所有表仍为空；任何已有数据均停止整批，不DELETE/UPDATE/TRUNCATE或覆盖。COPY逐列指定PG实际类型，保留UID、Version、审计及业务值；全部字段实际读回摘要一致才提交。异常时整个PG事务回滚。

SQL datetime2(7)与PG timestamp(6)精度不同，50个源日期字段涉及27条记录，PG只能保存微秒；摘要明确截断到微秒，不声称源日期完全无损。字符串、NULL、价格等没有业务归一化，路径只迁值，不复制文件。目标结构不变。

再次运行写入会因非空表拒绝，不能把它当覆盖同步工具。执行前后由主控另存50表完整摘要、确认七表以外原有数据及号段不变，并记录实际命令和退出码；任何失败保留首轮证据，不通过改业务、删除断言或清库解决。源码SQL依赖待P09移除，当前工具保留仅为完成本批迁移。
