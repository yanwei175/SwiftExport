# 权限目录同步 SQL

从 2026-10-10 起，默认入口改为**离线生成 SQL，不直接写库**。可直接取用已生成的 [权限目录同步.sql](权限目录同步.sql)，在明确核实的目标 PostgreSQL 数据库中人工执行整个文件。文件不包含连接、环境变量、账号或密码；同一目录与实体元数据重复生成的内容一致。权限目录或表结构变更后仍须重新生成并审核，旧 SQL 是当时的固定快照。

## 生成与执行

需要重新生成时，在仓库根目录运行：

```powershell
# 首次为本工具准备隔离编译依赖；不读取 WebApi 配置，不连接业务库。
dotnet restore .\_tools\DbSeed\DbSeed.csproj --artifacts-path .\_tools\DbSeed\bin\SQL生成构建 -p:NuGetAudit=false
& .\_tools\DbSeed\同步权限目录.ps1
```

默认输出到 `_tools/DbSeed/权限目录同步.sql`。可指定其他本地文件：

```powershell
& .\_tools\DbSeed\同步权限目录.ps1 -OutputPath 'D:\Install\权限目录同步.sql'
```

生成器从 `PermissionCatalog.All` 和现有 `EntityMetadataCache` 投影，写 UTF-8 无 BOM 文件。DbSeed 的 `--export-permissions-sql <输出.sql路径>` 在读取任何连接/账号环境变量前直接返回，且不创建连接。编译产物隔离在现有 `bin` 忽略范围内，不覆盖运行中 API 的 DLL。

使用现有数据库管理工具选择正确目标库，在没有其他事务的独立会话中一次执行完整 SQL。脚本包含 Serializable 事务、角色→权限稳定锁序、结构与重复键/拼写门禁，失败不自动重试。表结构须已部署，数据库须有内置 `gen_random_uuid()`；脚本仅建立随事务销毁的临时目录表，不迁移业务结构。

SQL 只插入缺失定义、更新已有名称/分组/排序，保留已有 UID、Key、状态、版本、审计以及角色/用户关系。停用或软删除定义不会被复活，目录外定义保留；不创建账号、不授予新增权限、不清库。核实目标、执行与读回验证由人工部署步骤完成，生成成功不代表已同步数据库。

`-ConfigurationPath`、`-EnvironmentName`、`-DryRun` 不再是当前 PowerShell 入口参数，旧用法会报参数错误，不会隐式连库。原 DbSeed 管理员引导及 `--sync-permissions [--dry-run]` 专用命令保留原行为，用于已有明确调用；本次没有执行它们，SQL 生成不借用其连接环境变量。WebApi 启动仍不隐式同步。

旧 `ExcelFieldMapping` 功能已退出，目前读取配置使用 `excel_read_profile` 与 `excel_read_field`。当前 `System.ExcelFieldMapping.Manage` 是保留的权限键名称，显示名为“Excel读取配置维护”，实际控制 `ExcelReadProfileController` 的新增、修改、删除接口；同步该定义不恢复旧表或旧功能。

`SWIFTEXPORT_RUNTIME_DV_PASSWORD` 是运行验证的 dv 应用登录密码，`SWIFTEXPORT_RUN_PG_TESTS` 与 `SWIFTEXPORT_PG_TEST_CONNECTION` 用于测试；本生成入口不读取或使用这些变量，也不会自动选择测试库。
