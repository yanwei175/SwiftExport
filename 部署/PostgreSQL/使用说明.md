# PostgreSQL 每日自动备份

本目录是备份能力的源码入口，支持 Windows PowerShell 5.1。服务器每天当地时间 02:00 备份 `dv_next` 到 `D:\dbback`，继续使用已有 NAS 单向同步。无需运行 pgAdmin。

| 文件 | 用途 |
| --- | --- |
| `每日备份.ps1` | 单次备份、检查归档目录、发布文件；支持 `-ConfigPath` 和只读 `-ValidateOnly` |
| `注册每日备份任务.ps1` | 创建或更新同名任务；支持 `-ConfigPath`、`-Credential`、`-WhatIf` |
| `备份设置示例.json` | 不含密码的参数模板 |
| `验证自动备份.ps1` | 开发机隔离验证，不连接数据库、不注册真实任务 |

## 服务器安装

从仓库的 `部署` 或部署工具 ZIP 复制本目录到服务器稳定位置，例如 `D:\ERPDeploy\部署工具\PostgreSQL`。任务会引用这个绝对路径，注册后不要移动或删除；位置变更后重新注册。现有 `D:\PgBackupTools\pgpass.conf` 和 `D:\dbback` 可以继续使用。

在服务器管理员 Windows PowerShell 中执行，首次创建设置；已有设置不覆盖：

```powershell
$toolRoot = 'D:\ERPDeploy\部署工具'
$configPath = Join-Path $toolRoot '本机配置\PostgreSQL\备份设置.json'
New-Item -ItemType Directory -Path (Split-Path $configPath -Parent) -Force | Out-Null
if (!(Test-Path -LiteralPath $configPath)) {
    Copy-Item -LiteralPath (Join-Path $toolRoot 'PostgreSQL\备份设置示例.json') -Destination $configPath
}
notepad.exe $configPath
```

检查 PostgreSQL 工具实际安装目录、连接账号、库名及路径。`WorkDirectory` 与备份目录须在同一盘符且互不包含；同盘移动完成文件，避免 NAS 同步未完成的归档。默认工作目录仍为 `D:\PgBackupTools\work`。真实设置位于 `本机配置`，不提交仓库；升级工具保留该目录。

设置文件不保存密码。`PasswordFile` 指向 UTF-8 **无 BOM** 的 `pgpass.conf`，每行格式如下（将占位文字替换为真实密码）：

```text
127.0.0.1:5432:dv_next:postgres:实际数据库密码
```

主机、端口、库名、用户名须与 JSON 一致；密码中的 `:` 写成 `\:`，`\` 写成 `\\`。脚本通过 `PGPASSFILE` 指定文件，不依赖 Windows 用户配置目录。全局角色导出通常需要 PostgreSQL 超级用户，示例使用 `postgres`。密码文件和工作目录只允许任务账号及服务器管理员访问；全局 SQL 可能包含角色密码哈希，同样保护备份和 NAS 权限。

已有密码文件正常时无需重建。以下仅用于确认原文件是正确 UTF-8 文本后去掉 BOM，不会显示密码：

```powershell
$passFile = 'D:\PgBackupTools\pgpass.conf'
$strictUtf8 = [Text.UTF8Encoding]::new($false, $true)
$content = [IO.File]::ReadAllText($passFile, $strictUtf8)
[IO.File]::WriteAllText($passFile, $content, [Text.UTF8Encoding]::new($false))
```

本目录 `.ps1` 已保存为 UTF-8 **带 BOM**，兼容 Windows PowerShell 5.1 中文解析。不要将两种文件的编码要求混淆。

## 验证、注册与手动运行

```powershell
# 只检查设置、工具文件和密码文件编码，不连接数据库。
& "$toolRoot\PostgreSQL\每日备份.ps1" -ConfigPath $configPath -ValidateOnly

# 首次先单独运行一次；脚本进程成功为 0，失败为 1。
& "$env:SystemRoot\System32\WindowsPowerShell\v1.0\powershell.exe" -NoProfile -NonInteractive -ExecutionPolicy Bypass -File "$toolRoot\PostgreSQL\每日备份.ps1" -ConfigPath $configPath
$LASTEXITCODE

# 预览不获取 Windows 密码，也不注册任务。
& "$toolRoot\PostgreSQL\注册每日备份任务.ps1" -ConfigPath $configPath -WhatIf

# 输入执行备份的 Windows 账号和登录密码；不是 PostgreSQL 密码。
& "$toolRoot\PostgreSQL\注册每日备份任务.ps1" -ConfigPath $configPath

$settings = Get-Content -LiteralPath $configPath -Raw -Encoding UTF8 | ConvertFrom-Json
Start-ScheduledTask -TaskName $settings.TaskName -TaskPath '\'
# 等任务完成后查看结果与当天日志。
Get-ScheduledTask -TaskName $settings.TaskName -TaskPath '\' | Select-Object TaskName, State
Get-ScheduledTaskInfo -TaskName $settings.TaskName -TaskPath '\' | Format-List LastRunTime, NextRunTime, LastTaskResult
```

任务使用 Windows 密码登录，即使无人登录也可运行；采用普通权限，账号必须能读取脚本、设置、PG 工具和密码文件，并写入备份/工作目录，还需“作为批处理作业登录”权限。域策略禁止该权限时需服务器管理员调整。Windows 密码变化后重新注册任务。相同任务名会更新已有任务；改名不会删除旧任务，应显式停用旧任务，避免双份备份。原先使用相同默认任务名的任务可直接更新到本目录入口。

注册不自动触发备份。首次触发为下一个 02:00；错过时间后补跑，已有实例运行时忽略新触发。手动与计划运行同一工作目录时还会使用文件排他锁。任务执行期间显示 Running 不是成功；完成后同时确认 `LastTaskResult = 0` 和日志 `SUCCESS`。

## 输出与失败处理

默认输出：

```text
D:\dbback\dv_next_pg_20261012_020000.backup
D:\dbback\pg_globals_20261012_020000.sql
D:\dbback\dv_next_pg_20261012_020000.log
```

业务库使用 `pg_dump -Fc`，角色/表空间使用 `pg_dumpall --globals-only`，以业务库作为初始连接。两次导出分别执行，不构成跨文件的统一快照。两者退出码均为零且非空、`pg_restore --list` 成功后才发布；`SUCCESS` 是这一轮完整结束的标记。发布两个文件不是一个原子操作，中断时可能只出现其中一个，应结合日志确认配对完整。

NAS 若只同步 `*.bak`，须将 `*.backup`、`pg_globals_*.sql` 和日志纳入同步；原 SQL Server `.bak` 保留。脚本不自动清理历史备份和临时文件。失败产物及工具输出留在 `WorkDirectory` 供排查，按服务器容量人工清理已确认不再需要的运行子目录，勿删除正在运行的目录或锁文件。

`no password supplied` 优先检查密码文件路径、编码和连接字段是否匹配；`ValidateOnly` 只检查本地前置条件，不验证密码正确性或运行账号权限。实际导出错误查看对应日志和工作目录的错误输出。

`pg_restore --list` 仅检查目录可读，不能代替恢复演练。应在独立 PostgreSQL 测试实例/新库中验证恢复；本脚本不提供自动覆盖数据库的恢复操作。每日逻辑备份不包含业务图片/附件，也不提供 WAL 时间点恢复。

## 后续部署工具接入约定

- 复用以上两个脚本入口；GUI 收集非敏感参数写入 `本机配置\PostgreSQL\备份设置.json`，随后调用 `-ValidateOnly` 展示检查结果。
- 注册入口接收内存中的 `PSCredential`，避免 GUI 调用时弹出控制台提示；Windows 和 PostgreSQL 密码均不写入 JSON、命令行、日志或工具 ZIP。
- 单次备份通过独立 `powershell.exe` 进程运行，根据退出码及日志显示状态；不要把含 `exit` 的运行入口点源加载进 GUI。
- 安装/更新计划任务显式调用注册入口；任务状态查询使用 ScheduledTasks 模块。修改时间或任务路径后重新注册；连接/输出参数在下次运行时读取。
- 当前已收录脚本到离线部署 ZIP 白名单，**尚未接入部署窗口按钮或自动安装流程**。代码整理不代表服务器已经部署或验证恢复成功。
