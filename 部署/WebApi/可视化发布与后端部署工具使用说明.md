# 可视化发布与后端部署工具使用说明

> 当前选定方案的首次安装、IIS 切换、证书分发与日常更新请先读 [Caddy 首次安装与日常更新](Caddy首次安装与日常更新.md)。Visual Studio 发布方式保持本节说明；首次安装使用 Caddy 专用窗口，日常更新使用后端部署窗口。

你可以一直使用 Visual Studio 的“发布”，无需执行打包脚本。部署工具在 Windows 服务器上运行：选择已复制到服务器的完整发布目录，点击“部署 / 更新”。它不需要 IIS，提供直接运行和 Windows 服务两种模式。

## 开发电脑：在 Visual Studio 中发布

右键 `SwiftExport.WebApi` → “发布”，选择已经准备的 `Windows文件夹` 配置。配置文件在 `SwiftExport.WebApi/Properties/PublishProfiles/Windows文件夹.pubxml`；它是本机发布配置，仓库默认忽略 `.pubxml`。仓库保留 `部署/WebApi/Windows文件夹发布配置模板.xml`，另一台电脑可将模板复制到上述位置并改名为 `.pubxml`；也可在 Visual Studio 创建“文件夹”发布配置并设置：

- 配置：Release，目标框架：net10.0。
- 部署模式：框架依赖，目标运行时：win-x64。
- 使用普通文件夹发布，保持完整文件集合，不启用单文件或裁剪。
- 输出目录使用开发电脑的独立发布目录；发布前清理的是这个输出目录，不能指向服务器正在运行的程序目录。

准备的配置输出到 `artifacts/部署/WebApi/Windows文件夹/publish/`，排除 `appsettings*.json`，避免携带开发配置。发布后必须包含 `SwiftExport.WebApi.exe`、同名 `.dll`、`.deps.json`、`.runtimeconfig.json` 和依赖 DLL。Windows 服务模式还需要 `Microsoft.Extensions.Hosting.WindowsServices.dll`，须重新发布本次增加服务托管接线的后端。

Visual Studio 和命令行使用相同发布管线；配置可在 Visual Studio 中直接选择、修改和运行。参考 [Microsoft：Visual Studio 发布配置](https://learn.microsoft.com/en-us/aspnet/core/host-and-deploy/visual-studio-publish-profiles?view=aspnetcore-10.0)。如果使用自己已有的发布配置，工具仍接受完整 Windows 发布目录；更新时忽略发布包的所有 `appsettings*.json`，保留服务器原有配置。

## 服务器：首次部署

服务器须已有 x64 ASP.NET Core Runtime 10；已安装对应 Hosting Bundle 的机器也具备该运行时。Windows 服务托管使用 Microsoft 官方 `Microsoft.Extensions.Hosting.WindowsServices`。参考 [Windows 服务托管说明](https://learn.microsoft.com/en-us/aspnet/core/host-and-deploy/windows-service?view=aspnetcore-10.0)。

1. 把发布目录复制到服务器的暂存目录，例如 `D:\ERPDeploy\20261008\`。
2. 将新版部署工具 ZIP 完整解压到独立目录，例如 `D:\ERPDeploy\部署工具\`，保留同级 `WebApi` 和 `公共`。不要只复制三个脚本，也不要放进后端安装目录。
3. 准备该服务器的生产配置 JSON。沿用当前 PostgreSQL、JWT 和文件服务配置，首次单独提供；不要使用历史 SQL Server 示例，不要重新生成正在使用的 JWT 密钥。配置内容不会显示在窗口或写入窗口设置。
4. 按生产配置提前创建独立文件存储根目录、`ProductImages` 和启用的容器目录。上传文件目录必须位于程序目录之外，例如程序在 `D:\Apps\SwiftExport_WebApi`，文件在 `D:\ERPFiles`。
5. 打开 `WebApi` 目录并双击 `启动后端部署工具.cmd`，选择发布目录、安装目录和首次生产配置，再选择运行方式和监听地址，点击“部署 / 更新”。Windows 服务模式需要右键启动入口“以管理员身份运行”。

直接运行模式使用当前账户在后台启动程序，关闭部署窗口不会停止后端；重启服务器后不会自动启动。工具记录 PID、启动时间和程序路径，更新只终止由它管理且身份匹配的进程，因此维护前须先完成正在进行的保存或过账。服务模式通过服务管理器正常停止并等待退出。如果目标目录已有手动启动的进程，请先结束维护中的该实例，再让工具接管；不会按进程名批量结束程序。

Windows 服务模式首次创建 `SwiftExport_WebApi`，设为自动启动，使用 `NT SERVICE\SwiftExport_WebApi` 虚拟账户。工具授予该账户程序目录读取权限、日志目录修改权限，以及生产配置显式文件根目录的修改权限，不授予管理员身份。已有同名服务必须指向所选程序目录；更新中不能切换运行方式。程序已增加服务生命周期支持，服务启动时从程序目录读取配置及写日志，避免误用 `System32` 工作目录。

更新窗口默认 Windows 服务模式、`D:\Apps\SwiftExport_Service` 和 `http://127.0.0.1:5081`，匹配 Caddy 首次安装默认值。后端更新核心仍支持已有直接进程部署；Caddy 托管保持服务模式和回环地址。日常更新不修改防火墙或证书，首次 Caddy 安装另行生成 CA、导出公钥及创建 HTTPS 规则，详情见新手册。生产配置的显式 Kestrel 端点不能覆盖回环监听。

## 以后更新：复制发布目录，再点一次

1. 在 Visual Studio 再次“发布”。
2. 把完整发布目录复制到服务器的新暂存目录。
3. 打开工具，选这次发布目录；安装目录和运行方式保持原值，首次生产配置一栏留空。
4. 维护期间先结束保存、过账等操作，再点击“部署 / 更新”。

工具先准备新目录，再停止旧实例。旧程序目录完整改名为同级 `_backup_时间_随机后缀`；新程序使用干净目录，保留服务器 `appsettings*.json`、对应配置权限和日志，避免累积覆盖残留旧程序集。程序以 Production 启动。上传目录独立保存，文件内容不复制、不移动、不清空。

不建议在后端运行时直接把 DLL 拖进去覆盖：文件可能被占用，复制中途也可能混入两个版本。你的日常操作仍然只是复制发布目录，再点击一次更新，由工具完成停机与替换。

启动检查只验证新实例存活及根 HTTP 管道的相关标识，允许未登录的 401、未匹配的 404 或现有 HTTPS 跳转响应，不请求数据库接口。显示成功后再人工验证客户端登录和本次功能。数据库结构变化须有独立升级及回退方案，工具不会执行数据库迁移，换回程序也不等于回退数据库。

## 失败与备份

更新复制或启动失败时，工具保留新版本暂存/失败目录，并尝试恢复旧程序目录。原来受工具管理的旧进程会重新启动并通过同样启动检查；已有服务恢复原完整命令行及此前运行状态，已有工具记录的运行服务再验证 HTTP。恢复也失败时明确提示人工检查。首次部署没有旧版本可恢复，失败目录保留；本次首次创建的服务会被撤销，已有服务不会被删除。备份目录和配置包含服务器密钥，只保存在受控服务器目录，工具不自动删除旧备份。

工具自身仅在工具根目录的 `本机配置/WebApi/部署窗口设置.json` 保存发布目录、安装目录、运行方式和地址；不保存配置内容。启动入口的 `ExecutionPolicy Bypass` 仅作用于本次 PowerShell 进程，不修改机器或用户执行策略。PowerShell 脚本采用 UTF-8 BOM，支持 Windows PowerShell 5.1。

## 验证范围

`验证部署更新.ps1` 使用仓库 `artifacts/部署/验证/deployment-tests/` 隔离目录和进程/服务查询替身，验证首次部署、已有空目录、配置和日志保留、完整备份、旧程序集退出、启动失败恢复、同目标并发拒绝、独立文件存储保护和 PID/服务身份保护；HTTP 探测使用独立 loopback 响应。Windows PowerShell 5.1 下还编译并真实运行只记录启动选项的无业务替身，验证后台启动、目录、Production、参数、身份核验和句柄终止；不运行实际业务宿主。

本次没有操作现有服务器或数据库。Windows 服务的 SCM 注册、虚拟账户 ACL、开机启动和服务器真实更新仍需在目标服务器验收；离线文件操作验证不能代替这些运行验证。

2026-10-08 本地验证：Windows PowerShell 5.1 的隔离更新场景全部通过，窗口 16 个控件构建成功（未显示窗口）；后端解决方案构建成功，58 项现有 WebApi/文件服务定向测试通过，无跳过。Visual Studio Windows 发布配置实际发布成功，检查包含 EXE、完整依赖、原生图片库及服务托管库，并排除开发配置。构建仅有 DbSeed 的既有 NU1900 漏洞数据源获取警告；没有执行该工具或任何数据库操作。
