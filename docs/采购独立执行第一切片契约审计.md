# 采购独立执行第一切片契约审计

审计日期：2026-08-31。范围：手工独立采购创建、安全商务保存、确认及确认执行依据；新旧链路并存。本文记录实施前源码事实和契约决定，不代表所列目标已实现。前端、入库过账、PackingList、新供应商跟进及完整 Trace 实现不在本切片。

依据为根 AGENTS.md、Router 及路由判定规则、业务模块设计治理工作流、业务模块能力与页面契约治理规则、采购／需求／BOM／主数据及 PackingList 地图、Contracts DTO 和 Refit 技能。用户已授权先审计、再建立独立新链路；不继续要求重复门禁确认。本文仅是审计交付，不修改能力地图或宣布关闭偏差。

## 1. 已冻结的决定

- 新契约进入 `SwiftExport.Contracts/DTOs/Procurement/OrderManagement/`，独立命名空间、每个公开顶级类型独立同名文件；API 新根为 `api/procurement/orders`，与旧 `api/procurement/purchase-orders` 不重叠。
- 旧 14 个 DTO、8 个 Refit 方法和旧序列化字段全部保持兼容，不增字段、不作为新 DTO 的基类、不在新查询中组装后裁剪宽 DTO。
- 本次不实质修改旧 DTO，因此不机械拆分 `PurchaseOrderWorkspaceDtos.cs`。PROC-001 留待对应旧能力迁移时按触碰类型治理；新类型全部遵守一类型一文件。这不是把拆文件当作职责拆分的替代。
- 新链按管理查询、订单命令、确认依据分别设计窄契约；不建立第二个 Workspace。详情不继承列表项，不携带完整来源贡献、供应商报告、入库／出库或业务日志集合。
- 保持一套采购头行事实，只使用 `OriginKind` 表达手工、需求等业务来源；数据库不保存 API 或页面迁移状态。
- 第一切片只创建手工独立订单；旧链继续处理其既有订单。新旧写入入口均须显式校验所属执行链，旧回执重放也不能绕过。
- 可复用 `ServiceResult<T>`、分页包装、已经冻结的确认／生命周期枚举等稳定平台语义；不复用宽业务模型。新业务结果不能沿用带 `SupplierProgressReportId` 的 `ProcurementCommandResult`。

## 7. 新旧隔离：不能只处理 Workspace

| 旧入口或共享位置 | 现有保护 | 新链并存必须增加／核对 |
|---|---|---|
| APP.RequireOperableHeadAsync | 状态／版本及 DemandSource/ExecutionRequestId 完整性 | 保护保存、确认、取消确认、报告四个写命令 |
| APP.ExecuteMutationAsync 幂等 prior 分支 | 在 RequireOperableHeadAsync 之前按日志返回当前单据状态 | 回放也检查旧执行链；不能凭已有 CommandId 进入新单 |
| REPO.SearchAsync/GetHeadSummary/GetHead/行详情 | 当前按采购 Uid 或筛选查共享表 | 旧页面查询只取旧执行链；不让新单在旧页面显示为来源损坏的只读记录 |
| APP.GetTraceAsync/GetProgressCoreAsync | Trace 读头，progress 直接读报告 | 统一验证旧链归属；GetProgress 不能因绕过头读取而泄露新链报告 |
| PurchaseDraftCreationService → GetSafeAppendCandidatesAsync/GetSafeDraftForUpdateAsync/ValidateAppendHead | 安全草稿、供应商与来源匹配 | 显式只接受旧链，重复创建回读和 GetByExecutionScope 也保持旧链范围 |
| PurchaseDraftLifecycleService → GetLifecycleDraftAsync/EnsureMutableDraft | Repository 已要求 ExecutionRequestId／DemandSource 非空，服务校验 Active＋待确认 | 显式旧链校验；取消、减量及 preview 都不能按新单 Uid接管。不要误报现有代码完全无来源保护 |
| PurchaseOrderDraftRepository 写 SQL | 追加行、头版本推进、行数量／生命周期更新 | 以所属头的旧链标识限制写入，避免后续调用者省略服务守卫产生旁路 |
| 新仓储／命令服务 | 尚未建立 | 面向同一采购事实；来源类别必须显式、独立，不保存 API 归属 |

共享采购表消费者还包括 NetDemandRepository.Workspace、NetDemandExecutionLinkRepository、InboundSourceRepository、InboundDocumentRepository、PackingListWorkspaceRepository（经 Link/进度聚合）以及 SysDicCurrencyRepository。它们不是旧采购 DTO 的直接消费者，但属于持久化兼容核对范围：新增列／空来源不得破坏旧查询；手工新单不借假 Link进入入库/PL；本切片不重写这些业务能力。现有入库选源依赖 DemandExecutionLink，所以新手工采购能确认并不代表已可收货。

历史记录迁移默认归旧执行链，不通过缺字段自动认领为新手工单；历史 BOM 依据未知不根据今天结构补造。旧头行新增兼容字段优先采用非破坏式增量，精确检查 NOT NULL、默认值和旧 INSERT 列清单。
