# 销售订单单位快照实施交接

> 2026-09-28。独立任务已完成单位快照代码实施与验证，用户已确认旧数据库销售行完成单位补值。下文保留当时的实施要求与交接现场，供追溯；后续管理查询使用已实现的销售行单位快照。

## 已确认的业务决定

- `SalesOrderLine` 增加持久化 `UnitSnapshot`，保存销售行订购量所用单位的代码。字段最终必须非空，不能以空值作为正常销售行状态。
- 标准产品行由服务端从所选 `Product.Unit` 取得单位并写入快照；草稿再次保存同一产品时保留已有快照，改选产品时重取。产品单位为空应阻断保存，不写入未知单位。
- 非标行没有 `Product` 单位来源，需在销售行编辑与保存契约中提供单位录入，并校验非空；确认需求时使用销售行快照。优先复用项目现有 Unit 字典和输入模式，具体控件按现有代码判断。
- 既有销售单据的单位由用户自行在数据库中补齐；本任务不推断旧订单单位、不替用户回填业务数据。旧库部署时，须先完成旧行补值，再使数据库列满足 `NOT NULL`。数据库结构基线由 SchemaGenerator 生成。
- 详情查询返回单位快照；后续管理查询的同单位汇总以此字段为准，不再以实时 `Product.Unit` 或来源需求单位替代销售行历史快照。
