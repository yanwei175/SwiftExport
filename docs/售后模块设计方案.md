# 售后模块设计方案

> 2026-09-22：按“一单一个投诉，明细只保存补件”重构。本文件替代原来的同行投诉/补件设计。旧客户端不能继续调用新契约。数据库脚本仅交付，不自动执行业务库迁移。

## 1. 业务边界

只保留 AfterSalesHeader / AfterSalesLine 两张事实表。一单一个客户、一个投诉；问题成品属于单头，补件可以有多种，也可以没有。售后单号就是服务单号，不另设业务编号。

保存不接入来源需求。显式“确认实物需求”仅将 Quantity > 0 的补件交给 GrossDemand，之后由来源需求及其他领域接管。售后不创建采购、不直接操作库存，不保存出货进度。允许分批出货，属于 PackingList 范畴。

本次不接入 PackingList、出库、文件微服务或附件管理。正数量单据仍以 AFTERSALES_DELIVERY_QUERY_UNAVAILABLE 阻断结案，不能以来源关闭、物料拆解或出货草稿冒充已交付。

## 2. 字段归属

### 单头 AfterSalesHeader

原有 Uid、AfterSalesNo、CustomerId、客户快照、AcceptedDate、OwnerId、DocumentStatus、ConfirmationStatus、DemandConfirmedAt/By、ExpectedCompletionDate、Conclusion、Remark、Version 和审计字段保留。

| 新增到头（从旧行移入） | 数据库类型 | 规则 |
|---|---|---|
| CustomerComplaintNo | nvarchar(100) NULL | 客户投诉单号，允许重复，去首尾空格，空白存NULL |
| ResponsibleSupplierId | uniqueidentifier NULL | 责任方，逻辑关联Supplier；有正数量确认时必填 |
| IssueProductId | uniqueidentifier NULL | 问题产品，可空 |
| IssueSkuSnapshot | nvarchar(100) NULL | 问题Product.Sku历史快照 |
| IssueCustomerSkuSnapshot | nvarchar(100) NULL | 问题客户型号历史快照 |
| IssueLinkSkuSnapshot | nvarchar(100) NULL | Product.LinkSku，即AQ型号；只存字符串，不关联ProductNeutral |
| IssueDescription | nvarchar(2000) NOT NULL | 投诉描述，业务保存必填 |
| QualityCategoryId | uniqueidentifier NULL | 保留契约和存储，功能待开发，不校验分类主数据 |
| CauseAnalysis | nvarchar(2000) NULL | 原因分析 |
| OriginalSalesOrderLineId | uniqueidentifier NULL | 可空，所选原销售行必须属于单头客户 |
| TreatmentDescription | nvarchar(2000) NULL | 处理说明 |
| ServiceAmountCny | decimal(18,2) NULL | 整单人民币成本；NULL未定，0免费，正数付费，禁止负数 |
| RequiredDate | date NULL | 整单补发要求交期，发布到每条正数量来源需求 |
| ReturnedReceivedDate | date NULL | 客户退回品收到日期；多数情况不退回，可空，不产生入库 |

ServiceAmountCny 不是单价，不按补件数量相乘，不进行汇率换算，不进入采购域；向客户收费仍属于销售。ExpectedCompletionDate 是预计处理完成日期，与补发要求交期分开。

### 补件行 AfterSalesLine

保留 Uid、HeaderId、LineNumber、Version、审计字段，以及：

| 字段 | 含义 |
|---|---|
| ProductId / IsNonStandard | 标准补件身份或非标标记，互斥 |
| SkuSnapshot / CustomerSkuSnapshot / LinkSkuSnapshot | 补件物料编号、客户型号、AQ型号 |
| DescriptionSnapshot | 补件描述 |
| ColorId / ColorSnapshot | 补件颜色及快照 |
| SpecificationSnapshot | 补件规格 |
| Quantity | 补发数量，NULL或0均不进入来源需求，负数拒绝 |
| UnitSnapshot | 默认Pcs，标准产品取其单位；非标沿用自动SKU规则 |
| Remark | 补件备注 |

旧行字段 IssueColorId、IssueColorSnapshot、IssueProductDescription 完全移除。问题颜色和问题产品描述不保留在头上。

同一标准产品普通编辑保留历史编号及单位；重新选择产品才读取当前快照，换客户刷新客户型号。问题产品可不关联实体，保留手工型号快照。

## 3. 保存和空行

新建页面默认零补件，“新增补件”创建带稳定Uid的新占位。

- 仅包含Uid、行号、版本、默认Pcs的新占位不提交、不落库，后端同样过滤。
- 显式Quantity=0、非标标记、产品、描述、型号、颜色、规格、备注或非默认单位均算已填写。
- 已填写但Quantity为空的行正常保存。
- 已保存行即使清空内容也不隐式删除，必须通过DeletedLines显式删除，可以删除最后一行。
- 投诉描述在Header必填，支持仅有单头的投诉保存、查询、修改、结案。

## 4. 确认、锁定和生命周期

DocumentStatus 与 ConfirmationStatus 分离，数据库使用tinyint：开放0 / 结案8 / 作废9，待确认0 / 已确认1。

有正数量才需要实物确认。确认校验整单责任供应商、已确定人民币成本及正数量补件的身份、单位、描述长度和数量。无正数量不调用来源服务，也不标记已确认。

确认后锁定客户、责任方、成本、问题产品和型号、原销售行、交期、原有负责人/受理日期/预计完成日期、预留分类，以及补件事实与行结构。开放且已确认时允许：

- Header.CustomerComplaintNo、IssueDescription、CauseAnalysis、TreatmentDescription、ReturnedReceivedDate、Remark。
- Lines[Uid].Remark。

补充保存不重新发布需求。修改锁定事实必须先取消确认，来源安全退出失败则整体回滚并保持锁定，成功后才能修改及重确认。

无正数量的投诉不需要实物确认，填写结案说明即可结案。正数量保留当前交付核验暂不可用阻断。已结案、已作废拒绝保存；重开不发布需求，作废必须无活动来源需求。

## 5. 来源映射和审计

| GrossDemand字段 | 售后来源 |
|---|---|
| SourceType | CR |
| SourceUid / SourceNo | Header.Uid / AfterSalesNo |
| SourceLineId / SourceLineNumber | 补件行Uid / LineNumber |
| ProductId及型号、颜色、规格、单位 | 实际补件身份和快照 |
| DemandQty | 补件行Quantity，严格大于0 |
| RequiredDate | Header.RequiredDate |

问题产品、责任方和成本不扩入来源需求。保留CommandId幂等、头行Version、同事务保存/接收/取消/日志，以及完整前后Header/Lines事实审计。补件版本只在该行实际写入时增加。

## 6. 查询和页面

Manager直接读取单头投诉型号、客户投诉单号、供应商及整单成本。KnownAmountCny=COALESCE(头金额,0)，HasUndeterminedAmount=头金额是否NULL；分别显示“待定”“免费”或人民币金额，不再累计行费用。

关键词匹配单头售后单号、投诉号、问题三种型号；补件三种型号通过EXISTS匹配，零明细投诉可查询，多条匹配补件不会重复单头。

Detail上方为投诉信息、问题产品、处理信息；下方只显示补件列表与选中补件编辑区。QualityCategoryId只保留模型，不建设选择功能。头字段错误使用Header.字段名，行错误使用Lines[Uid].字段名。
