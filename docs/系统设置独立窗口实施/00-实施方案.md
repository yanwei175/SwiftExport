# 系统设置独立 FluentWindow 实施方案

状态：用户已确认布局并授权实施。规划者本轮只写方案，执行者按本文实现；最终由原规划聊天复核。

布局参考：[已确认布局参考.png](已确认布局参考.png)。该图是设计稿，不是实现截图；实际字段、保存边界和字典复用以本文为准。

## 1. 已确认范围

采用第一版审批图：独立 FluentWindow、左侧导航、右侧 Page；用户和角色使用列表加右侧编辑面板。参考 Ant Design Pro 的信息布局，沿用现有 WPF Fluent 主题，不引入 React、WebView 或新的主题框架。

- ShellWindow 的设置页面保留“修改我的密码”“刷新我的权限”，系统设置只保留“打开系统设置”按钮。
- 新窗口集中承载“用户管理、角色管理、权限定义、字典管理”。
- 用户管理：列表、右侧用户资料及角色编辑；创建用户、重置密码也在新系统窗口内完成。
- 角色管理：列表、右侧角色资料及权限勾选；资料和权限分别保存。
- 权限定义：只读 DataGrid，搜索/分组，不在线增删改权限目录。
- 字典管理：**只迁移现有前端宿主，不重新设计字典 UI、数据流或业务行为**。
- **不新增或修改后端 API，不修改 Contracts、不修改权限模型、数据库或业务规则。** 便利性必须在现有接口范围内实现。
- 此方案覆盖前一版“四页均表格编辑”的草图；用户/角色不用改成批量编辑 DataGrid。图中合并“保存”的表现以本文分范围保存规则为准。

## 3. 当前代码与复用入口

| 现状 | 实施要求 |
|---|---|
| `Features/SystemSettings/SettingsCenter` 有个人和四个系统管理入口 | 个人不动，系统入口收敛成一个命令 |
| `Services/UI/SettingsWindowService` 打开多个模态窗口，维护实例和会话关闭 | 扩展为统一系统窗口入口，仍由 UI Service 创建和激活窗口，VM 不 new Window |
| `RbacManagementWindow/ViewModel` 合并用户、角色、权限选项卡 | 按三页职责拆出 View/状态，保留已验证 API、版本、权限、错误处理及保存修订号语义，不复制一套新授权逻辑 |
| `Dictionaries/Views/DictionaryManagerView` 已是可复用 UserControl | 页面直接承载该 View 和现有 VM；不复制 XAML，不重做字典布局 |
| `DictionaryManagerWindow` 持有局部 Dialog、消息、关闭检查 | 把需要的宿主职责转移到新窗口，尤其 CommitPendingEdits、CanCloseAsync、消息订阅和 Dispose |
| `UserRegistrationWindow`、`ResetPasswordWindow` 已有表单和 VM | 提取/复用内容放到新窗口内的面板或本地 ContentDialog，移走 DialogResult/窗口关闭耦合；密码仍只在提交时读取 PasswordBox 并及时清除 |
| `ChangePasswordWindow` 是个人设置功能 | 保留原功能和入口，不顺手改版 |

先盘点真实调用方，再决定删除已失去调用的旧系统窗口壳和注册；不能保留从 Shell 继续打开旧独立 RBAC/字典窗口的并行入口。现有共享服务和 VM 基类能完成的职责不要重新搭框架。

## 4. 窗口与页面交互

### 4.1 新窗口

推荐名 `SystemSettingsWindow`，归属 `Features/SystemSettings` 下独立功能目录。一个会话最多一个实例，Owner 为 Shell；采用非模态 `Show()`，再次点击恢复最小化窗口并激活，避免长期锁住业务 Shell。个人修改密码仍可保持现有模态行为。

建议初始尺寸 1280×820，最小 1000×680，并限制在工作区内；左导航约 200，内容区伸缩，编辑面板约 320—400；低宽度时内容能滚动，不裁掉保存/取消。样式使用现有命名资源与 4px 间距，不覆盖全局隐式控件样式。

左导航分为“访问控制”：用户管理、角色管理、权限定义；“基础配置”：字典管理。右侧为实际页面内容，不是点击后再开一层系统管理 Window。标题栏显示“SwiftExport · 系统设置”；导航只负责内部切页，不进入 Shell 业务文档页签。不需要 URL 路由或新导航框架。

页面内容可由 Page 包装复用 UserControl；若现有导航约定允许直接承载 UserControl，则按最小实现，不为名词额外套多层。新窗口拥有本地 Dialog/消息宿主，不覆盖 Shell 的全局宿主。

### 4.2 用户管理

- 列表展示现有 DTO 能提供的用户名、昵称、邮箱/电话、启用状态、管理员标记；不虚构部门、租户、登录时间等字段。
- **ManagedUserDto 不含角色名列表**。草图的“角色”列不作为必须项，不为它逐行调用 GetUserRoles；选中用户后在右侧显示角色和有效权限。
- 右侧显示只读用户名，可编辑昵称、邮箱、电话。资料区“保存资料”，角色勾选区“保存角色”，有效权限只读或展开查看。启停和重置密码为独立动作。
- 新建用户使用现有注册契约；成功后刷新并定位新用户，再单独分配角色。明确“账号创建成功，待分配角色”，不能伪装成跨接口原子操作。
- 重置密码绑定当前目标用户，不允许 UI 选错目标；沿用现有服务端“不重置管理员密码”的规则。本次不增加用户删除能力。
- 筛选只使用 ManagedPageRequest 真实支持字段。若状态筛选需前端实现，必须在已完整加载的数据上过滤并显示正确计数；不能只过滤当前服务端页却显示全库总数。

### 4.3 角色管理

- 列表选中角色，右侧编辑名称、说明，已存在 RoleCode 只读；新建角色独立输入状态，不能共用现有角色的脏状态造成串写。
- “保存资料”和“保存权限”独立。权限按分组呈现、可搜索，勾选结果必须保存**完整权限集合**；搜索隐藏的勾选项不丢失，不提交保留权限。
- SYSTEM_ADMIN 自动权限只读展示，沿用后端对内置角色的不可删/不可停用等规则，不通过名称判断身份。
- 状态与删除独立命令，展示后端版本冲突、有关联不能删除等业务消息，不新增自动解绑。

### 4.4 权限定义

使用 GetPermissionsAsync 的目录：权限键、名称、分组、活动状态、是否可分配。只读 DataGrid，前端搜索和分组即可，不显示新增/编辑/删除按钮。不要把“可分配”列变成可编辑开关。

### 4.5 字典管理

直接嵌入 `DictionaryManagerView`，保留原布局、类型/值维护、系统项保护、按钮权限、行编辑、删除池、批量保存、引用数据缓存刷新。切页或关闭前先提交 DataGrid 编辑，**提交失败时不得离开页面**，再检查未保存内容；不能只看尚未更新的 IsDirty。

## 5. API 边界与页面权限

| 页面操作 | 必须复用的接口 |
|---|---|
| 用户列表/详情/资料/启停 | ISystemRbacApi.SearchUsersAsync、GetUserAsync、UpdateUserAsync、SetUserStatusAsync |
| 用户角色/有效权限 | GetUserRolesAsync、ReplaceUserRolesAsync、GetEffectivePermissionsAsync |
| 创建用户/重置密码 | IAuthApi.RegisterAsync、ResetUserPasswordAsync；复用现有表单校验与 API Runner |
| 角色列表/详情/创建/修改/启停/删除 | SearchRolesAsync、GetRoleAsync、CreateRoleAsync、UpdateRoleAsync、SetRoleStatusAsync、DeleteRoleAsync |
| 角色授权 | GetRolePermissionsAsync、ReplaceRolePermissionsAsync |
| 权限目录 | GetPermissionsAsync |
| 字典 | 现有字典 API 和 DictionaryManagerViewModel，不调整传输契约 |

导航以 me 中已有 PermissionKey 判断，不用角色名称。读取导航原则上分别对应 `System.Users.View`、`System.Roles.View`、`System.Permissions.View`、`System.Dictionary.View`；写操作分别检查实际 Manage/Create/Edit/Delete 键。读取某个页面时只加载该页面必需数据，不能启动字典页就要求用户/角色管理权限。只有字典 View 的普通用户必须能打开系统窗口并进入字典页。

执行者核对实际服务端用例所需权限；本方案不能把只读目录接口的额外权限需求隐藏掉。若右侧角色候选依赖角色读取，按现有权限决定是否展示该编辑能力，不扩权。

默认选中第一个有权限的页面。同用户权限刷新后重算菜单和命令；失去当前页权限时不继续显示/接受该页敏感响应，安全转到可访问页面；所有权限消失则关闭系统窗口。账号切换、退出、会话失效强制取消/失效旧响应、清空密码和敏感数据并关闭窗口，不能被未保存提示阻止；普通主动关闭仍须确认。

## 6. 状态与生命周期：不可回退的约束

- 保留权限改造 R6 的四范围编辑修订号/请求快照语义：资料、用户角色、角色资料、角色权限分别跟踪。请求返回不能清除等待期间的新编辑。
- 共用聚合版本需要同步：保存用户资料后，下一次保存其角色须用新 Version；角色资料/权限同理。失败或版本冲突保留输入，刷新需先确认。
- 切用户、切角色、切导航、关闭编辑面板、刷新和关闭窗口都检查将被丢弃的编辑；不同页面/范围不能互相清理脏状态。确认取消必须恢复原选择与页面。
- 写期间不允许关闭/切目标或重复提交；如允许继续输入则用提交修订号保护。新建用户/角色的输入同样要防止请求返回时丢失后续编辑。
- 查询采用取消和请求序号/会话身份双重接纳检查；释放后的 token 不能被访问而抛异常，响应不得写回旧窗口。不得对已经 dispose 的 CTS 再取 Token。
- 页面按需初始化；可缓存本窗口内页面实例以保留状态，但离开后的旧结果不得覆盖新选择。关闭窗口后对称取消、释放事件订阅、页面 VM、消息/Dialog 绑定。
- 保留自己撤权、最后管理员保护、未知权限拒绝和后台 403 的原有行为；本任务不修后台规则。

## 7. 分阶段执行与门禁

1. **盘点与拆分**：读实际 View、VM、窗口服务、注册、契约和测试，记录文件归属及旧入口去向。现有工作区包含权限、迁移和测试改动，按本次文件范围保护，不重置。
2. **窗口骨架与入口**：新 FluentWindow、左导航、页内宿主、Shell 单按钮、单实例/Owner/会话生命周期。确认字典仅 View 场景可进入。运行 WPF 项目构建。
3. **三页与表单迁移**：用户、角色、只读权限页及创建/重置的页内操作；API/Contracts 零变更，资料/授权独立保存。运行编译和相关 VM 测试，保留延迟响应覆盖。
4. **字典宿主迁移**：复用现有 View/VM，把编辑提交、局部 Dialog/消息及离开检查接入窗口；确保未保存单元格、取消切页、写期间关闭仍正确。
5. **清理与统一自查**：删本次造成的无调用旧系统窗口壳和注册，保留个人修改密码；核对实际 diff、调用方、源生成 MVVM、中文职责注释。跑以下范围的必要验证并更新交接。

每步发现失败先在授权范围内闭环，不把“旧窗口删了”作为跳过回归的理由。允许将旧窗口测试迁移成新宿主等价行为测试，禁止仅删除断言或改成弱文本检查。

最低自动化验收：

- Shell 个人功能保留、系统入口唯一；重复打开激活单实例，Owner 正确。
- 四页导航及权限过滤；仅字典权限不会发用户/角色管理请求；无权限不得打开。
- 用户/角色资料与授权独立保存、版本同步、搜索后的完整授权集合保存、失败保留输入。
- 四条保存中的二次编辑，第二次保存确实提交后续内容；创建表单也不丢在途编辑。
- 未保存切页/换目标/关闭取消；字典单元格待提交及提交失败场景。
- 账号切换/会话结束时强制释放，新会话无旧数据；同用户撤权后菜单/当前页处理；在途响应不回写。
- 密码提交/取消/切页/关闭清除 PasswordBox，重置对象固定，不泄漏日志。
- 原字典及个人密码、权限刷新回归。

至少执行 `dotnet build .\SwiftExport.Client.Wpf\SwiftExport.Client.Wpf.csproj --no-restore -v:q`，以及 `SwiftExport.Client.Wpf.Tests` 中当前设置/窗口/会话相关定向测试（先编译再使用 --no-build）。用 STA/WPF 测试验证真正的窗口和导航/编辑提交行为；不能全部替换为 mock。构建通过不等于 UI 验收完成。做可用环境下的窗口尺寸/键盘/弹窗和真实页面截图检查；无法真人/真实 API 验证必须明确记录，不默认操作测试库数据。
