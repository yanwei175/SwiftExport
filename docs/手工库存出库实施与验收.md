## 本次交付

手工库存出库是独立库存凭证，不承担销售、售后或来源需求交付。页面入口为库存模块的“出库单管理”，沿用入库 Manager 的上下主从布局。

- `SwiftExport.Client.Wpf/Features/Inventory/Outbounds`：Manager、库存产品 Picker、删除与过账预览弹窗、模型、映射及 API 持久化服务。
- `SwiftExport.Contracts/DTOs/Inventory/Outbounds` 与 `Apis/Inventory/IOutboundManagerApi.cs`：独立查询、详情、候选、草稿和过账契约，保持 netstandard2.0。
- `SwiftExport.Application/Services/Inventory/OutboundManagerService*.cs`：草稿校验、版本锁、命令指纹、操作日志、正向过账事务。
- `SwiftExport.Infrastructure/Repositories/Inventory/OutboundManagerRepository*.cs`：单据读写、库存候选查询及数据库锁；不直接扣减余额。
- `SwiftExport.WebApi/Controllers/Inventory/OutboundManagerController.cs`：`api/inventory/outbounds` 全部约定端点。
- `OutboundDocument.Remark`、单据类型及库存交易类型 22、草稿状态 0；权限目录、设置页面与服务端接入 `Inventory.Outbound.Post`。
- `033_手工库存出库_Preflight.sql` 和 `033_手工库存出库_AdditiveSchema.sql`：人工审核预检和增量结构。

## 行为约定

1. 人工新增固定 StockIssue=22，TriggerPackingListId 明确为空。不恢复旧 Workspace、需求归属或销售编号快照契约。
2. 先选仓库再获取正库存产品；Picker 固定每页 50 条，服务端分页和排重。已加入产品不再次出现，因此候选“本单已选数量”为零，剩余可选量等于查询时在手量。其他草稿不扣减余额。
3. 一产品一行，默认数量取候选余额，可在 Manager 修改。草稿允许暂存空明细，以便清空并保存后切换仓库；过账至少一行。已保存且仍有明细的单不能同时换仓，需先清空保存。
4. 草稿保存校验产品、单位、仓库和 decimal(18,4) 正数数量，不以库存余额阻止合法草稿。已存在行保留身份、产品快照和 CommandItemId；余额只作展示，不参与脏状态。
5. 正向过账预览及提交均检查模块权限和过账权限。提交在 Application 事务中锁命令、头和行，重新校验余额，调用统一库存内核，再更新状态与日志。类型 22 仅支持负向交易，内核其余类型规则未改。
6. 结果未知保留原命令；恢复优先重放原命令，成功响应后的详情读取失败仅重读详情。同命令不同内容、操作或用户明确冲突。
7. 初始版本不开放反过账；现已按下文追加手工整单反过账。仍无负库存放行、PackingList 自动写入或交付汇总变更。
