# 售后模块后端实施与前端交接

> 2026-09-08：后端第一批已完成。本轮修改后端、Contracts、相关测试及文档；未修改 WPF/VSTO，未向业务数据库写入数据或执行迁移。
> 对应[后端实施计划](售后模块后端实施计划.md)。下一批按[前端实施计划](售后模块前端实施计划.md)实施。

## 1. 已交付边界

- `AfterSalesHeader`、`AfterSalesLine` 两表的保存、详情和分页；问题成品与实际补件分开。
- 显式确认正数量来源需求、安全取消确认、结案、重开及作废。
- 稳定 Uid、头行 Version、CommandId 幂等、事务回滚、前后事实审计、模块权限和状态能力。
- 标准产品快照、非标自动 SKU、Pcs 默认、客户原订单校验及窄候选查询。
- 来源领域增加只读结案资格检查；未改采购、库存、PackingList 执行规则。

附件、完整进度页、自动入出库和旧单据枚举统一不在本批范围。售后交给 GrossDemand 后由其他领域接管，不能据此宣称无采购的特殊出货链路已贯通。

## 2. API 与契约

入口：[IAfterSalesApi](../SwiftExport.Contracts/Apis/QualityControl/IAfterSalesApi.cs)。根路径 `/api/quality-control/after-sales`，所有返回使用 `ServiceResult<T>`。业务失败读取 `Error.Code`、`Error.Field` 及 `Message`；不要只看 HTTP 状态。

| HTTP / 相对路径 | 请求 | 成功 Data |
|---|---|---|
| GET 根路径 | AfterSalesSearchRequest | PagedResponseBase&lt;AfterSalesListItemDto&gt; |
| GET /{uid} | 路由 Uid | AfterSalesDetailDto：Header、Lines、Capabilities |
| POST 根路径 | SaveAfterSalesCommand | AfterSalesCommandResult |
| PUT /{uid} | SaveAfterSalesCommand | AfterSalesCommandResult |
| POST /{uid}/confirm-demand | ConfirmAfterSalesDemandCommand | AfterSalesCommandResult |
| POST /{uid}/cancel-demand-confirmation | CancelAfterSalesDemandConfirmationCommand | AfterSalesCommandResult |
| POST /{uid}/close | CloseAfterSalesCommand | AfterSalesCommandResult |
| POST /{uid}/reopen | ReopenAfterSalesCommand | AfterSalesCommandResult |
| POST /{uid}/void | VoidAfterSalesCommand | AfterSalesCommandResult |
| GET /lookups/{kind} | AfterSalesLookupRequest | PagedResponseBase&lt;AfterSalesLookupDto&gt; |

候选 kind：`customers`、`owners`、`suppliers`、`products`、`sales-order-lines`、`colors`、`quality-categories`。共同字段为 Uid/Code/Name；产品额外提供 CustomerSku/LinkSku/Unit/ColorId/ColorName/Specification。产品及原订单候选应传当前 CustomerId，订单候选不跨客户。Owner 只返回身份和显示信息，不暴露完整用户记录。

列表支持客户、责任供应商、生命周期、确认状态、受理日期范围和单号/问题及补件型号关键词。PageIndex 从 1 开始，默认每页 50，上限 200。列表金额为已知行金额合计 `KnownAmountCny`，另有 `HasUndeterminedAmount`；存在未定费用时不能显示为“整单免费”。

DTO 按用例新建：既有采购/销售契约包含不适用的商业或执行状态，不能复用。读模型与编辑模型分离，编辑 DTO 不开放单号、状态、审计及 HeaderId/LineNumber。候选统一于本售后候选入口，未扩大其他模块 DTO。简单同名结构使用默认 Mapster；主数据快照与状态规则由服务显式处理。

## 3. 前端保存协议

新建页一次生成头 Uid，每行一次生成 Uid，沿用项目顺序 Guid 工具。首次保存由后端生成 `CRyyyyMM0001` 单号；不在客户端生成单号或非标 SKU。每次用户动作生成新的 CommandId；网络结果不明时保留原 CommandId 和完全相同的内容重试。

保存提交完整 Header 可编辑字段及显式 AddedLines/UpdatedLines/DeletedLines。UpdatedLines 中每行提交完整可编辑字段和当前行 Version；DeletedLines 仅 Uid/Version。未进入集合的行保持原样；换客户时服务会校验所有保留行的原订单并更新关联产品的客户型号快照。行号由后端分配，删除行号不复用。

创建示例（CustomerId、SupplierId 替换为候选真实身份；示例 Uid/CommandId 不能硬编码复用）：

```json
{
  "commandId": "10000000-0000-0000-0000-000000000001",
  "uid": "10000000-0000-0000-0000-000000000002",
  "version": 1,
  "header": {
    "customerId": "20000000-0000-0000-0000-000000000001",
    "acceptedDate": "2026-09-08"
  },
  "addedLines": [{
    "uid": "10000000-0000-0000-0000-000000000003",
    "issueDescription": "成品松动，补发螺丝",
    "isNonStandard": true,
    "descriptionSnapshot": "螺丝",
    "quantity": 2,
    "responsibleSupplierId": "30000000-0000-0000-0000-000000000001",
    "serviceAmountCny": 0
  }],
  "updatedLines": [],
  "deletedLines": []
}
```

保存结果返回头最新 Version、AfterSalesNo、状态和能力，不返回行版本。成功后重新 GET 详情，替换已保存基线和头行版本，再执行下一动作；幂等重放返回最初结果并标记 `AlreadyApplied=true`，也须重新读取当前详情。

确认请求只包含 CommandId/Version。取消确认、结案、重开、作废还需非空 Reason，最多 2000 字。先保存再确认，确认不顺带保存客户端尚未提交的修改。

## 4. 状态与校验

`DocumentStatusEnum : byte` 为 Open=0、Closed=8、Voided=9；`ConfirmationStatusEnum` 复用待确认=0、已确认=1。数据库两列均 tinyint，旧模块枚举未迁移。

Capabilities 是服务端状态准入：CanSave、CanEditFacts、CanConfirm、CanCancelConfirmation、CanClose、CanReopen、CanVoid。它不预占下游资格，CanClose/CanCancelConfirmation 为 true 时命令仍可能因下游变化被阻断。所有读取和写入均检查 `Module.QualityControl.Access`；普通用户由既有权限分配机制授权。

- 每单至少一行，投诉描述必填。Quantity NULL/0 完全不建 GrossDemand，全零确认保持待确认且 CanConfirm=false，可填写原因直接结案。
- 正数量确认必须有责任供应商和非空人民币金额；0 免费、正数付费，金额不随数量相乘。
- 正数量标准补件须 ProductId；非标必须无 ProductId 且有描述，SKU 为 `NonStandardSkuGenerator.Create(lineUid)`。AQ 型号仅 LinkSku 字符串快照。
- 数量最多 14 位整数/4 位小数，人民币金额最多 16 位整数/2 位小数，禁止负数。
- 售后事实的补发描述/规格允许 500 字，但现有 GrossDemand 对应列为 300 字；确认时超过 300 明确返回字段错误，不截断、不改来源表。UI 对将交接的正数量行提示此限制。
- 确认后头事实、问题及补件身份/型号/颜色/原订单、责任方、金额、数量、单位、交期、行增删均锁定。只允许投诉描述、原因分析、处理说明、备注、客户退回收到日期补充；补充不重发需求。
- 先取消确认，由来源服务安全撤回后才解锁；失败时状态和需求原样保留。取消成功、编辑、重新确认不产生第二份活动额度。
- 正数量未确认不能结案；确认行来源缺失、重复或数量异常不能结案。正式交付净额完成或来源合法 Closed 才可结案；已拆解、计划量、PL 草稿不算完成。
- 重开保留确认和来源，不重新接收。作废必须开放、待确认且无活动来源；已结案先重开。

## 5. 失败处理

| Code | 前端处理 |
|---|---|
| VALIDATION | 展示 Message，按 Field 定位；行字段格式 `Lines[Uid].字段名` |
| VERSION_CONFLICT | 保留用户输入，提示刷新并对比，不自动覆盖保存 |
| COMMAND_CONFLICT | 同一 CommandId 内容变化；停止重试并核对请求 |
| BUSINESS_BLOCKED | 展示状态或业务原因，不自动取消/终止 |
| SOURCE_NOT_COMPLETED | 到下游完成或合法处置剩余要求 |
| SOURCE_MISMATCH | 来源事实异常，保留原状态并核查 |
| SOURCE_EXIT_BLOCKED 等来源服务错误 | 显示原始业务原因；取消失败继续锁定 |
| FORBIDDEN / NOT_FOUND | 权限或单据不存在，停止编辑提交 |
| UNEXPECTED | 整体未提交；结果不明确时按同命令内容重试 |

来源服务的错误码原样透传，不枚举为售后自有状态。普通 HTTP 参数验证、认证及防重复请求过滤仍沿用 WebApi 既有机制。
