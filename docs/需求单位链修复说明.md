# 需求单位快照与部署说明

## 已实施口径

- `GrossDemand.UnitSnapshot` 已存在且可空，不新增同义列。销售和售后确认通过 `ISourceDemandReceptionService` 传递来源行单位，标准和非标实物均必须有明确单位。
- 新增 `NetDemand.UnitSnapshot`，`nvarchar(300) NULL`，无默认值。标准根和非标根采用 `GrossDemand.UnitSnapshot`；客供子件在拆解时采用子产品 `Product.Unit`。只清理首尾空格，不进行单位换算。
- 物料写入和锁定读取、Manager、物料 Trace、来源 Trace 的采购贡献检查、采购候选与采购草稿预览均读取持久化物料单位。产品后续改单位不会刷新既有物料快照。
- 售后实体、查询/保存 DTO、客户端新行不再默认 `Pcs`。标准补件首次选择产品采用当前单位，同一产品重存保留原快照；非标用户填写单位，正数量确认时缺失单位拒绝。详情增加单位列，标准单位只读，确认后单位锁定。
- 标准销售行新选产品采用当前单位，同一产品重存不从当前主数据填补历史未知；未知历史保存/确认拒绝并要求核实。非标销售行保持用户填写单位。
- 现有采购候选与物料查询 DTO 保留 `Unit` 名称，数据来源改为 `NetDemand.UnitSnapshot`；未知显示空值/需核实，采购预览阻断。`ProductLookupDto.Unit` 仅用于用户显式选择产品时建立新售后快照。
- Excel 销售导入检查已有 `Unit` 字段：非标单位必填，标准候选必须有产品单位。本轮未改变导入协议，不恢复已移除的 VSTO 项目。

## 历史数据边界

升级不自动回填已有 NetDemand，不从当前产品、来源父件或 `ProductId` 缺失推断历史单位，也不统一填 `PCS`。旧售后已存 `Pcs` 无法自动识别究竟是人工确认还是旧默认，应由业务证据人工核实，不自动抹除或宣布可信。

旧物料单位为空时会影响采购预览及当前贡献/覆盖证明；保留原 Link 历史，不删关联，不改变已确认采购/入出库事实。需按原来源和拆解业务凭证明确单位后，由用户制定逐条修复方案。

手工来源当前编辑协议仍没有明确单位输入：旧/现有未知来源拆解后保持未知，采购预览会阻断。本任务限定销售和售后单位链，不为手工来源猜测单位或增加新维护用例。

需求计划能力地图中“根物料产品单位优先、缺失再回退来源”的旧说明已被本轮明确授权的快照口径替代；地图治理未在本次改动中展开。

## 用户手工升级 SQL

先停止业务写入并备份，连接到用户明确选定的目标数据库，手工执行以下 SQL；本任务没有执行升级或连接业务库。

```sql
SET XACT_ABORT ON;
BEGIN TRANSACTION;
IF OBJECT_ID(N'dbo.NetDemand', N'U') IS NULL
    THROW 53001, N'目标库缺少 NetDemand，请确认数据库。', 1;
IF COL_LENGTH(N'dbo.NetDemand', N'UnitSnapshot') IS NULL
    ALTER TABLE dbo.NetDemand ADD UnitSnapshot nvarchar(300) NULL;
COMMIT TRANSACTION;
```

无需新增 GrossDemand 单位列。新库使用实体生成的 `SwiftExport.Infrastructure/Database/Generated/SwiftExport.Schema.sql`，其中 NetDemand 建表列为 `[UnitSnapshot] nvarchar(300) NULL`。该完整建表基线只能在空库执行，不应在已有业务库运行。

部署顺序：备份并停止写入 → 手工增列 → 部署后端/Contracts → 部署 WPF → 验证销售标准/非标、售后标准/非标确认及客供拆解 → 恢复业务写入。历史单位核实为单独操作，不随部署批量推断。
