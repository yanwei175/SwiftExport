## 1. 目标、角色和边界

执行角色为 Backend，遵循后端 API 工作流及按需命中的 Contracts、Application、Dapper、状态和审计技能。执行前重新读取 AGENTS、Router、工作流及真实源码。

完成两表保存、分页和详情查询、实物需求确认／取消确认、结案／重开／作废，贯通来源需求。可修改后端各层、必要 Contracts 及对应测试；不修改 WPF 页面。

不建设附件、完整进度界面、采购单关系或 PackingList 特殊自动入出库。本轮不迁移旧模块生命周期枚举。用户已完成建表和两个状态列的 tinyint 修改；不得重新建表、增加外键或触发器。执行前只读核对实际数据库，发现差异报告，不能自动修表。

## 2. 冻结决策

| 项目 | 实施口径 |
|---|---|
| 数据模型 | AfterSalesHeader、AfterSalesLine 两表；同行分别保存问题成品和实际补发物料 |
| 生命周期 | 新增公共 DocumentStatusEnum : byte，Open=0、Closed=8、Voided=9；仅售后采用，不修改其他单据 |
| 确认 | 复用 ConfirmationStatusEnum；数据库 tinyint 映射单独验证，不为存储类型迁移整个共享枚举 |
| 单号 | 首次保存由后端复用编号服务，CR＋受理日期 yyyyMM＋至少四位流水；生成后锁定，允许流水空号，不要求连续无缺口 |
| 来源 | SourceType=CR，SourceUid=售后头 Uid，SourceNo=售后单号，SourceLineId=售后行 Uid |
| 数量 | Quantity>0 才接收；NULL/0 完全不建 GrossDemand，负数拒绝 |
| 单位 | 缺失或空白补 Pcs，已有明确单位保留 |
| 非标 | 复用 NonStandardSkuGenerator.Create(lineUid)，不得重新发明编码；SKU 稳定持久化，非标不绑定 ProductId |
| 确认必填 | 所有正数量行必须有责任 Supplier 和非空人民币金额，金额允许 0；投诉行可以待定 |
| 费用 | 每行人民币总金额，NULL 未定、0 免费、正数付费；不是采购单金额，不设置汇率或客户收费字段 |
| 锁定 | 确认后锁定客户、责任方、金额、问题产品／型号／颜色／原订单及全部实物要求和行结构 |
| 可补充 | 已确认且开放时仅投诉描述、原因分析、处理说明、备注、退回收到日期可改；不自动重新发布需求 |
| 负责人 | OwnerId 关联 SysUser.Uid，默认当前用户 |
| 品质分类 | QualityCategoryId 关联 SysDictData.Uid，新增代码 AfterSalesQualityCategory；可空，具体分类项由现有字典管理维护 |
| 权限 | 增加 Module.QualityControl.Access，接入既有模块目录、分配及能力输出；首轮模块授权用户可操作，动作另受状态约束 |
| 结案 | 只检查下游结果，不增加售后终止剩余要求入口 |

原订单可空，按当前客户过滤候选并校验关系。AQ 型号使用 LinkSku 字符串快照，不关联 ProductNeutral。问题与补发快照分开，不将成品 SKU 或数量传成补件要求。数量和金额独立，不对零数量强制零金额。

## 3. 执行步骤

### B1：数据核验、实体与基础接线

- 只读核对两表全部列、类型、精度、空值、默认约束、CHECK 和索引，特别验证 DocumentStatus/ConfirmationStatus 为 tinyint；不输出连接字符串或凭据。
- 创建 Entity、Repository 接口和 Dapper 实现，遵守 BaseEntity、DbSession、审计与并发约定。父子及跨模块关联由 Application 校验，无外键、无触发器。
- 保存涉及行变化时同步增加头 Version；行 Version 用于行冲突检测，不允许改行而头版本不变。
- 注册服务、仓储、映射和权限；品质模块授权应由后端真正检查，不借用采购权限或未启用的 DocumentPermissionDto。
- 同步设计文档的数据库状态、tinyint 和已冻结决策；按授权为业务总纲及模块索引补售后交接规则，不批量改写旧规则。

### B2：查询及写入契约

统一根路由 `/api/quality-control/after-sales`：

| HTTP / 路由 | 用例 |
|---|---|
| GET / | 单头分页和明细摘要筛选 |
| GET /{uid} | 两表详情及允许操作能力 |
| POST / | 创建单头明细，后端生成单号 |
| PUT /{uid} | 保存变更 |
| POST /{uid}/confirm-demand | 确认正数量实物要求 |
| POST /{uid}/cancel-demand-confirmation | 来源安全撤回后解锁 |
| POST /{uid}/close | 结案 |
| POST /{uid}/reopen | 带原因重开 |
| POST /{uid}/void | 带原因作废 |
| GET /lookups/{kind} | 窄候选查询 |

候选 kind 固定为 customers、owners、suppliers、products、sales-order-lines、colors、quality-categories。按关键词分页；产品可按当前客户带出客户型号，原订单只返回当前客户的销售行。用户候选只提供身份和显示名称，不返回完整用户 Entity。

采用售后专用 SearchRequest、ListItemDto、DetailDto、SaveCommand 及各状态 Command/Result；Contracts 保持 netstandard2.0 兼容，公开类型单独文件。分页、响应包装及确认枚举复用平台既有类型。Controller 与 Refit 路由严格一致。

保存传头版本、变更行版本、显式新增／修改／删除集合；不把未出现在请求中的行当成删除。删除行软删除，行号不复用历史身份。状态命令传预期头版本；取消、重开、作废传原因，结案传说明。写操作带稳定 CommandId，返回单据 Uid、单号、最新版本、结果及能力。

字段错误与业务阻断使用稳定结构表达，不能要求前端解析中文错误文本。查询金额先按行汇总再联接，返回已知金额和未定费用标记，不跨单位合计数量；多行匹配不能重复返回单头。

### B3：保存、确认和取消确认

保存头行在一个事务中完成，任何版本冲突整体回滚。标准件选择由服务核对 Product 并取得快照；非标必须有描述且不绑定 Product。历史快照不因读取详情或主数据更名被刷新。正数量草稿允许待完善，确认时执行完整校验。

确认按固定顺序：校验权限与头行版本 → 检查开放状态 → 筛选正数量行 → 验证必填／标准非标 → 保存稳定实物快照 → 在同一个 DbSession 事务内调用来源接收 → 写确认状态和业务日志。全零单返回无需确认实物需求，保持未确认。

来源映射使用补发组：ProductId、IsNonStandard、SkuSnapshot、CustomerSkuSnapshot、LinkSkuSnapshot、描述／颜色／规格／单位、Quantity、RequiredDate、Remark；SourceVersion 使用本次接收采用的头版本。责任方、金额和问题成品不扩进 GrossDemand。

幂等使用既有操作日志机制和稳定命令标识：相同命令及内容返回原结果，不新建单号、非标 SKU 或需求；同 CommandId 不同内容拒绝。确认失败不得留下部分来源需求或已确认状态。

取消确认传已确认正数量行的身份集合，复用 ISourceDemandReceptionService.CancelConfirmationAsync。只有成功退出才改待确认、清当前确认人／时间、解锁并写日志；历史确认保留在日志中。已有执行导致拒绝时整个事务保持原状态。

后端真实比较锁定字段，不能只依赖 UI 只读。正数量改零／空必须先成功取消确认，不能靠下次接收时忽略旧行来清除需求。

### B4：生命周期与来源就绪检查

在来源需求领域增加窄内部检查，按 SourceType、SourceUid 和行身份批量检查结案资格；售后不直接写需求表，不编排采购／库存。

- 无正数量投诉单填写结案说明后可结案。
- 有正数量但未确认的单不能结案；先确认，或在未确认状态明确修正要求。
- 已确认行须有可证明的来源记录，且正式交付完成，或已由下游合法关闭／终止。缺失、重复、异常数量阻断；已拆解、计划量、PL 草稿不算交付。
- 正式交付净额复用现有来源交付查询口径，包含反向影响；不通过活动来源筛选漏掉已合法结束的记录。
- 最终检查和状态写入在同一事务内，采用来源领域一致的锁顺序，防止检查后并发变更。
- 重开只改售后生命周期，不清确认、不重放交付额度。已关闭／已作废常规编辑只读。
- 作废要求待确认且不存在未处置来源事实；已结案先重开。作废不自动撤销来源。

不增加 CompletedAt/CompletedBy，操作人、时间和原因写现有业务日志。取消失败后的处置留在下游，本轮不增加售后终止剩余命令。

## 4. 验证与交接门槛

必须验证：

1. NULL/0/正数量混合仅接收正数，全零正常保存和结案。
2. 成品问题只补配件，来源身份和数量正确；非标 SKU 重试稳定，Pcs 默认正确。
3. 正数量确认缺责任方或金额拒绝，金额 0 通过；历史关系、当前客户及快照一致性正确。
4. 锁定字段后端拒改，可补充字段保存不重新接收需求。
5. 同 CommandId 幂等、异内容拒绝；头行版本冲突、来源失败完整回滚。
6. 取消拒绝仍锁定，取消成功后修改重确认不增加第二份有效交付额度。
7. 部分交付、已完成、合法终止、异常／缺失来源的结案结果正确，状态与日志原子一致。
8. 查询无单头或金额重复，未定费用不当免费，填退回日期不产生库存动作。
9. 权限拒绝、跨客户原订单拒绝；不能借候选接口读取用户敏感字段。

运行后端构建及相关 Application/来源接收测试。Dapper、事务和并发使用隔离测试数据库验证，禁止对生产库写入测试数据。已有失败单独记录，不删除断言或弱化检查。

交付给前端：实际 Refit/DTO、路由、错误与能力约定、正常及阻断示例、测试证据、数据库只读核对结果。第一批构建及核心业务测试通过后才开始第二批。契约仍缺字段时由后端补齐，前端不得自行推导权威事实。
