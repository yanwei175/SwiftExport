# 订单跟踪首阶段设计与交付

确认日期：2026-10-19。用户批准独立订单跟踪方向，本轮建立第一个可用切片。首阶段已完成开发与定向验收，成果尚未提交、合并或部署。

## 模块边界

订单跟踪是只读查询域，以成品需求 GrossDemand 为起点，一行一条需求。销售管理继续维护订单事实；现有需求管理与 Trace 页面保持原状，不作为新页面布局模板。未确认且未形成成品需求的销售订单不进入跟踪列表。

第一阶段完成总览与基础明细，不接入物料、采购、收货、交付和逾期进度，不显示空区域或假零，不创建新的业务实体或表。后续按正式交付、物料、采购与收货、总览摘要顺序逐切片接入。

## 页面与事实

总览支持来源类型（默认 SO，另有 CR、MD、全部）、客户代码 MultiSelectLookupButton 多选、来源单号、客户 PO、发票号、产品/客户型号/中性型号、要求交期和需求生命周期筛选，按需求行分页。

默认列优先展示图片、客户代码、来源单号、Sku、CustomerSku、LinkSku、数量、单位、要求交期和生命周期，便于首屏阅读。客户名称、来源类型、行号、客户PO、发票号、描述、颜色和规格保留为可选列，由现有列显隐菜单打开。表格只读，复用现有右键注入器、复制、列显隐和行/单元格选择模式，没有批量业务动作便不增加勾选列。

需求数量、单位、产品型号、图片、描述、颜色、规格与交期来自 GrossDemand 保存的快照。客户代码和名称为当前客户显示资料；客户 PO、发票号来自 SO 来源当前销售头，其他来源为空，不误称需求快照。客户或来源缺失不得通过内连接隐藏需求，空单位和空交期保持未知，不回填当前主数据或默认交期。

总览以 GrossDemandId 打开独立基础明细页签，同一身份重复打开激活已有页签。明细独立加载基础事实、备注、生命周期变更与审计信息。返回总览保留筛选、分页和选择；异步取消及过期结果不得回写其他身份。

## 查询契约与权限

现有 GrossDemandListItemDto 带链路存在提示，Trace 契约一次读取下游集合，与本模块独立基础读取的演进边界不同，因此新增专用契约；只复用既有分页和 ServiceResult 包装。

| HTTP（根 api/order-tracking） | 契约与职责 |
| --- | --- |
| POST overview/search | OrderTrackingSearchRequest → PagedResponseBase<OrderTrackingListItemDto> |
| GET customer-codes | 非软删除需求关联客户的非空代码候选，去重排序 |
| GET demands/{grossDemandId} | DemandTrackingHeaderDto，按稳定需求身份读取基础明细 |

来源集合默认 SO；显式空集合表示 SO/CR/MD 全部来源。生命周期空集合表示全部非软删除需求。集合内并集、不同条件交集；字符串查询按字面包含匹配，不解释用户通配符。日期区间含首尾日，空交期不满足日期条件。页码归一化、默认每页20、上限200，超末页仍返回总数；排序包含稳定身份打破同时间并列。

PermissionKeys.OrderTrackingView = OrderTracking.View，独立控制菜单、隐藏明细路由及三个后端端点。客户代码候选不依赖销售或客户管理权限。该权限只暴露本阶段需求基础事实，不自动授予销售、采购、需求写操作。代码目录变化后需显式同步权限目录、按角色分配并刷新登录权限；本轮不执行数据库同步或自动分配。

## 第二阶段：来源主从与下游查询（已完成工作树验收）

本节取代首阶段关于独立文本框、选择模式及尚未接入下游的当前目标；上述验收记录保留为首阶段历史，本阶段结果以下方记录为准。

- 来源单号、客户 PO、发票号、产品编码、客户型号和中性型号合并为 Keyword，在这些字段间做 OR 包含匹配；与客户多选、来源、交期、生命周期等条件做 AND。
- 来源主表在服务端按来源分页，成品需求子表独立分页。分组键是 SourceType 加 SourceGroupId；SourceUid 有效时作组键，空身份时回退 GrossDemandId，单号文字不作身份。主表分别给出来源全部需求数与当前过滤命中数，子表保留相同过滤，仅展示命中需求。
- DataGridExtensions 负责已加载页的列头筛选，不承担服务端分组；界面明确提示筛选范围。所有只读表固定 FullRow，保留复制和列显隐，移除单元格模式入口。
- 需求明细保留基础事实，另设物料、采购、收货和正式交付四个独立读取区域。每区分别处理加载、重试、无权、空结果、错误和待核实，迟到响应不得覆盖新的需求身份。

新增契约：POST sources/search；GET demands/{grossDemandId}/materials、purchases、receipts、deliveries。原 overview/search 增加成对的 SourceGroupType/SourceGroupId 参数并改用 Keyword。Contracts 按 Sources、Materials、Purchases、Receipts、Deliveries 组织，前后端按实际查询用例拆分，不创建空扩展点。

| 区域 | 在 OrderTracking.View 之外必须同时具备的权限 | 数量口径 |
| --- | --- | --- |
| 物料 | DemandPlanning.Material.View | 分解记录自身的毛量/净量与版本历史 |
| 采购 | Procurement.Order.Read | 关联分配减释放为贡献；采购整行数量单独标明 |
| 收货 | Inventory.Inbound.View 与 Procurement.Order.Read | 关联采购行的收货证据，按入库行去重，不分摊为当前需求收货量 |
| 交付 | Shipping.PackingList.View | 正式过账净交付与反向历史，异常证据下净额和未交为未知 |

各区域后端强制权限组合，不以客户端隐藏代替授权。已有收货历史守卫仅影响收货区域；材料或采购区域不调用整个旧 Trace。共享采购行不重复求和，不把整行收货或供应商货好量计作当前需求进度。旧 Trace 与其他页面的业务行为保持原有边界。
