# M13-E-IMPL-01 执行资格仓储与实库分派

主控独占新增 PostgreSqlExecutionEligibilityRepository.cs、独立 PostgreSqlExecutionEligibilityServiceTests.Integration.cs、阶段结果及公共文档；A/B不写本轮文件。复用现有三方法接口、当前44项离线通过的必要服务衔接和PG日志准备，无DI/DDL/新业务规则。

授权锁沿用已验收的RBAC角色目录锁顺序：Serializable首次SELECT/DML之前取得sys_role SHARE ROW EXCLUSIVE，再取得sys_permission SHARE；角色目录锁与RBAC全部管理命令互斥，权限定义表锁保护目录同步/空范围，随后按用户、关系及角色/权限行锁读取实际授权。SYSTEM_ADMIN不添加IsSystem条件。原账户活动、软删、有效角色/有效权限及版本/状态/审计规则不变。固定Product/Customer/Supplier三表白名单、当前事务、取消及审计打戳，不自建/提交事务。

限制：锁角色目录的局部队列会延长其他RBAC管理事务等待，应记录范围；不新建全局业务锁、通用锁框架或自动重试。未来PG DbSeed/权限目录写入须同顺序由主控冻结，尚不能宣称所有外部写入方通过。普通主数据CRUD不走角色目录队列；其在授权读取后更新同一目标，可能使PG Serializable行锁产生40001而非源VersionConflict。该真实并发情形必须保留原断言验收，若失败登记阻塞，不用降隔离/吞异常/放宽断言掩盖。

真实测试主控串行使用192.168.3.12:5432 / dv_next_pg_rbac_tests_20261005，复用已部署50表及预置管理员角色；仅随机夹具实体可清理，保留不可删除的业务审计。拒绝其他库/备份、DDL/清库/重置。覆盖三种对象成功、同状态/旧版本/软删、普通角色合法授权（含IsSystem=false管理员原语义）、审计真实JSON约束及取消原子回滚、资格命令竞争及RBAC撤权排队后最新授权、普通CRUD行锁竞争及清理。记录实际命令和每个失败，不将部分通过标整M13/P04验收通过。
