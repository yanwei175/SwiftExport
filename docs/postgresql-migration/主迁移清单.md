- Infrastructure/DependencyInjection.cs 仍注册 SqlConnectionFactory、SqlServerExceptionClassifier、DapperRepository<> 及 SQL Server 专用仓储；WebApi/Configuration/WebApiConfiguration.cs 调用全量注册。不能只换连接串或连接工厂。
- 扫描 Repositories 去重后共 69 个现有仓储类（含泛型基类），23 个有同名 PostgreSql 对应实现，46 个未发现对应实现；其中 SysUser/BomExecution 需核对实际消费者后处置。这个统计不等于完成率，也不表示每个缺类都必须新建。下方任务覆盖全部 69 类及 partial。
- 已有 PG 连接、异常分类、映射、参数、泛型仓储、命令锁/回执/日志/取号，以及产品/BOM、客户/供应商、字典/汇率/Excel 配置、权限读取、仓库查询/候选/维护。ProductDetail/ProductPackage 复用泛型实现，不新建无用专用仓储。
- AuthController → AuthSessionService/UserAccountService → IAuthRepository；JWT 凭据验证也依赖该仓储。PG 权限读取不能替代登录。RbacManagementService → IRbacManagementRepository + IBusinessOperationLogRepository，有 Serializable 事务，存在 P04 的真实阻塞。
- 销售/售后确认 → 来源接收/退出 → 需求；MaterialDemandEstablishmentService 同时依赖产品、供应商、BOM、来源/物料仓储和日志。已有 BOM 实库测试不证明完整需求 PG 命令可运行。
- 采购草稿/确认/反向依赖需求 Link、采购事实锁与主数据。IProcurementOrderFactLockRepository 当前通过反向仓储解析；迁移需保留同一实例。
- InventoryPostingService → IInventoryPostingRepository + IWarehouseManagementRepository；先锁仓库再操作余额/流水。PackingList 正式链依赖需求、采购、入出库、库存，不能按文件夹名称认定独立。
- PackingListRepository 的查询、文档、来源退出三个接口指向同一个 scoped 实例，所有 partial 归一个任务。
- DevUserMiddleware 仍直接使用 TOP/方括号/NOLOCK；DbSeed、PermissionCatalogSync、AdminPasswordRecovery 直接使用 SqlClient。Application 扫描未发现 SqlClient/SqlConnection 直接使用，但事务编排仍需 P04 核对。
- 模块地图存在滞后描述：例如 BOM 仍有“未共享写入”，部分库存/PL 仍写“未实现”，而当前已有相应服务。记录为文档偏差，不能据此重新实现业务，详见问题记录。
