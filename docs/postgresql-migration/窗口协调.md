## 状态填写约定

1. 收到本约定后，执行窗口首先在自己的状态页登记真实聊天 ID、绝对工作目录、基线 commit 和已有修改；无法获取真实 ID 时如实填写“未知”，不能拿 clientThreadId 替代。
2. 每轮开始工作前先写“运行中”，填写主控分配的轮次、任务、开始时间、允许文件和预计交付；未获实现放行时只能继续审查。
3. 关键进展、开始/结束必要验证、发生阻塞时更新状态与时间。需要公共文件或跨边界修改，先记“等待主控”并停下相关写入；不自行扩大范围。
4. 本轮工作结束时，**先写任务结果，再更新状态页，最后发聊天最终答复**。完成分配内容填“运行完毕，待主控验收”；只读审查完成但实现未放行填“等待主控”；无法继续填“阻塞”；明确结束执行填“已停止”。写清结束时间、交付路径、实际命令/结果及未验证事项。
5. 状态页中的“运行完毕”只说明窗口本轮停写，不代表迁移任务“验证通过”或“已接入运行”。这些状态由主控检查当前 diff 和证据后写入主清单。
6. 每轮使用不同轮次，保留上一轮简短记录；下一轮不能沿用旧轮次的完成标记。主控不能替执行窗口伪造“本人完成”的记录；本次初始化均明确标注为主控根据用户说明登记。

时间统一使用 `YYYY-MM-DD HH:mm:ss +08:00`。状态页不写连接密码、令牌或完整连接字符串。

## 主控如何接回执行

主控派工前、收到交付后、聊天工具读取失败时，直接读取两份绝对路径状态页，核对轮次、更新时间、停止说明、实际 worktree diff 和结果文件。未完成身份登记前，不猜 A/B 对应关系，不代写两个 worktree 的代码，也不重复派发同一任务。

文件是最后一次主动报告，无法保证异常退出时仍能更新。若停留“运行中”超过 15 分钟而没有进展报告，主控只记“状态过期，待核实”；须用聊天状态、执行者明确停写说明或用户确认核实，不能凭超时判断已经停止并接管文件。正在运行较长命令时，应提前在状态页记命令与预计等待情况。

必要测试仍按任务范围运行；数据库写入、结构变更和较大回归统一由主控串行安排。专用测试库 `dv_next_pg_failure_tests_20261004` 的占用以[主控状态](窗口状态/主控.md)记录为准，执行 A/B 不同时使用或重置该库。验证后的结构同步 `dv_next`；备份库保持只读。

若执行窗口的沙箱拒绝写主仓库的独占状态页，在自己的 worktree 写同名相对文件，并在最终答复提供绝对路径及失败原因；主控登记该路径为该窗口唯一实际状态入口，不同时维护两份。不得隐藏状态写入失败，也不以反复申请替代交付。
