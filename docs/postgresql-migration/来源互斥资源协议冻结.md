## 首次快照与发现

高隔离必须在父业务事务/首个回执Find/审计快照之前准备，而非在GetActive/GetById已进入事务后补advisory。保留原Serializable/RepeatableRead，不自动降隔离、重试业务、吞40001或改成VersionConflict。已有同CommandId租约仅保护机器回执，不能充当不同命令的S/U锁。

已知来源单据UID的SO/售后入口可先准备S；只有Gross UID的物料批量入口须事务外发现来源UID集合，先S后U。获取完以后在同连接、事务外复核Gross→SourceUID绑定；若出现缺失→存在/删除重建/换来源绑定，不持U后追加新的S，须释放本轮资源并重新进行有界准备，或返回现有技术并发分类。此准备重查不是重试业务action，不能生成单号/写审计/回执或提前执行业务校验。

原接口无token的仓储方法不能靠新helper测试声称等待全链可取消；新准备能力须透传调用方token。默认RC方法可用随父事务释放的局部事务锁，但真实调用者稳定顺序、缺失/空范围与全部写者共同参与仍要验证。高隔离缺少有效事务前覆盖的调用不得悄悄当作保护已成立。
