## 实际变更与必要原因

新增 `PostgreSqlGrossDemandDocumentRepository` 实现原九方法和专属Core `ISourceDemandTransactionPreparation`。事务外发现Gross→来源绑定，完整取得S(SourceUID)/U(GrossUID)后复核；变化时释放后有界重新准备，不重试业务。九方法保留原写列、枚举顺序、版本、审计、消息、生命周期和无父事务逐行提交边界，不自行拥有业务事务。已有父事务须具备有效覆盖，缺失覆盖明确拒绝，不能把事务内迟到的advisory当作高隔离首次快照保护。

`BusinessCommandExecutor` 新增末尾可选beforeTransaction资源准备委托，位于机器Command准备后、BeginTransaction和回执Find前；父事务结束后逆序释放。`SourceDemandReceptionService` 转发专属准备，现运行SQL仓储使用临时无动作资源对象。此兼容须在最终SQL退出时删除，不建设提供者切换框架。

售后Confirm/Cancel/Void和物料Establish增加准备调用。原因是原Serializable父事务的回执/审计/头读取会先建立快照，PG后续FOR UPDATE及事务内advisory无法刷新该快照。只增加技术准备，原授权、CommandId/指纹、ExpectedVersion、业务委托、隔离及回执语义不变。没有改Controller、DTO/API或用户操作。
