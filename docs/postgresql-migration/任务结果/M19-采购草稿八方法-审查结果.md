### 2.1 GetByExecutionScopeForUpdateAsync（22–49）

## 4. SafeFacts历史与最小公共前置

SafeFacts/WithLocks（269–307）逻辑相同，锁提示不同：

1. 当前PO全部采购行UID，**含软删采购行**。
2. 引用这些UID的任意InboundDocumentLine，只要ISNULL(IsDeleted,0)=0即阻断；不要求入库头存在/活动/过账，不过滤类型/数量/仓。
3. 任意Ledger.SourceLineId→InboundLine.Uid→采购行即阻断；Ledger和中间InboundLine不加软删/正反向/替换过滤。软删入库仍有immutable流水就阻断，反向不解除历史保护。

PG历史nullable IsDeleted用COALESCE(...,FALSE)=FALSE等价；不能只用活动采购行集合。当前逻辑外键不变，不新增数据库外键/级联。

主控需先冻结：

- **P(PO UID)与顺序/租约合同**：现有需求C_item→S→U之后、原事务首次数据语句之前整组取得；已知追加/缺失目标都声明。PO保存/确认/反向/关联、反馈、IN草稿/正式收货/反向/自动入库等相关writer必须参加。此处仅PO局部SafeFacts，不扩为反向服务全库Guard或库存全局锁。
- **最后等待后的重验**：目标→source/supplier/customer绑定、历史行owner/收货身份覆盖。资源变化整组释放再发现（尚未Begin）；只有Version/状态/安全资格变化，原APPEND_TARGET_UNSAFE/MISMATCH/CONCURRENCY返回，不重执行业务/取号。现有Source重验不代表P重验。
- **新建私有头与无父事务边界**：新PO UID原取号后生成，不为预声明P移动编号。主控冻结受已保护来源下本次新建、尚未公开头的窄借用/非等待验证例外，或另授权最小技术UUID预留；不能扩为任意后发现既有P补锁。八方法原不强制父事务，不能全面改为必须父事务/自开局部原子批次；无父事务如何按方法持技术租约、父事务如何借已完成租约须明确，单方法不能因此承诺整链原子。
- **失败/公共文件归属**：保留原null/0/异常与应用错误；40001/40P01/23505不吞成计数或伪装乐观版本，创建泛异常来源失败边界不擅自改。公共取消/预算/连接epoch/PID/未知解锁/提交沿联合协议，由主控固定。仓储实现方不能自行写共享lease/DbSession。

FOR UPDATE只保护选中行；空scope、空行/MAX、空历史范围仍依P/来源及双方writer。聚合/LATERAL/NOT EXISTS不机械加FOR UPDATE获得HOLDLOCK语义。[PG显式锁](https://www.postgresql.org/docs/18/explicit-locking.html)。保留来源创建默认隔离，不借移植统一升降消费者隔离。
