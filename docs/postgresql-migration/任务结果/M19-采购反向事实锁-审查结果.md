## 逐方法及事实锁范围

| 方法/阶段 | 当前实际行为与必须保留的边界 |
| --- | --- |
| LockAsync(uid,ct) | 委托 LockCore(uid,空 Net 集合,true)；不是仅锁一张采购单。事务必须已存在，缺失事务抛“采购事实锁定需要事务。”。 |
| LockForAssociationAsync(uid,netDemandIds,ct) | 委托同一 LockCore(...,false)，请求 Net 身份额外参与发现。空数组不提前返回，仍锁采购及已有引用；方法本身不增加参数验证或单位/收货规则。 |
| 发现来源 | Link、Net、采购行子查询均 READCOMMITTED。取 TargetType=PO 且 TargetHeadId=uid **或** TargetLineId 属本单的引用，并 UNION 请求 Net 的 GrossDemandId。不按软删/LinkStatus/Net 生命周期筛选，历史和同头错配要留下。UNION 去重后按 .NET Guid 排来源；独立采购无 Link 合法，损坏 Link 因 JOIN 缺 Net 被丢掉则由后段 ownLinks 识别，二者不能混同。 |
| Gross → Net → Link | 逐来源 Gross(Uid) UPDLOCK/HOLDLOCK；缺 Gross 直接 InvalidOperationException“采购来源需求缺失，不能完成操作。”。逐来源读取全部 Net，含历史分解/失活/软删；再按所有 Net UID 读全部 Link，无目标类型/状态/删除过滤。空 Net 集合跳过该 Link 查询，但来源下 Net 空范围仍是保护对象。 |
| ownLinks 与采购事实 | 独立再查 PO 自有 Link，包括缺 Net 的引用；若 Net 不在已锁集合，返回 Facts=null、CONCURRENCY_CONFLICT、ExpectedVersion、“采购引用已变化或物料来源缺失，请重新预览。”。全源 Link 与 ownLinks 按 Uid DistinctBy 合并。随后头按 Uid、行按 PurchaseOrderId 全量锁，包含软删/历史；Quantity 从 QTY 别名还原。 |
| 锁后重验 | 头行锁后再次执行 ownLinks，比较 HashSet(Uid,Version,NetDemandId,TargetLineId)。变化返回同类冲突、“锁定过程中采购引用集合发生变化，请重新预览。”。不补拿晚发现 Gross，不扩大 tuple、不重试、不返回半套 Facts。当前未比较 TargetHeadId 等全 payload；不得在翻译时自行扩大业务规则。 |
| false 分支 | 重验后立即返回，不读未归属入库、正式入库、库存流水或报告。关联不能因采购收货或出货历史新增阻断。 |
| true 分支 | 先全局 HasUnattributedInbound，后采购全部行关联 Inbound 头→这些头全部行→相关 Ledger→供应商报告。采购行空仍执行全局检查，随后返回。Inbound 头/行 UPDLOCK,HOLDLOCK，Ledger 和 Report 仅 HOLDLOCK；不存在“全部下游 FOR UPDATE”的现有语义。 |

HasUnattributedInbound 为全局 EXISTS，非本单范围：未删头行，DocumentType 11/12 且 PostingStatus 1/8，或 Type10 找不到采购行且已过账/已反向，或活动草稿。不能用只覆盖正式历史的共享 Guard 缩小它；也不能因为该判断全局就新增全局业务锁。

Inbound 头筛选 SourceLineId 属采购全部行，读取包括软删/各状态；其所有行一并读取。Ledger 覆盖 SourceDocumentId、SourceLineId 及原流水的 ReversalOfLedgerId/ReplacementOfLedgerId；不只读当前余额，不过滤历史/软删，不写库存。报告只读未删历史，按 PurchaseOrderLineId、Sequence 升序；Policy 按 Sequence 降序取最新警告，报告本身不阻断反向。现有唯一(PurchaseOrderLineId,Sequence)不允许同序合法并列夹具。

**ConfirmationNodes 实际没有锁或读取阶段。** Facts 无该集合，ConfirmationBuilder 不读 BOM/仓库，Document.ConfirmAsync 只更新头及确认批次身份；确认服务明确不创建 BOM/仓库快照。IndependentProcurementSqlTests 中仍有旧“Snapshot/Bom”名称，但断言节点/确认行零条及保留 ActiveConfirmationId。本轮不按旧名字添加节点/快照表依赖，既有历史不因此获得清理授权。

## ApplyAsync 的持久化与错误边界

先 StampForUpdate(head)，按 Uid/旧 Version/LifecycleStatus=0/IsDeleted=0 更新头，Version+1；取消确认设待确认并清 ActiveConfirmationId/ConfirmedDate/ConfirmedBy，作废设 LifecycleStatus=9。影响数非1立即返回头 CONCURRENCY_CONFLICT；成功再推进内存版本。

取消确认仅改头，不释放 Link、不删行。作废/删行遍历属于本头、所选行、未删且 Active 的 Link，StampForUpdate，设置状态8、ReleasedQty=AllocatedQty、取消时间/人员/原因、更新审计、Version+1；SQL 保留 UID/旧版本/活动/未删条件。第二项失败立即返回其身份和原版本，已写前项必须由外层回滚。保持来源 Link 目标身份、AllocatedQty 等不可变事实，不能改为硬删。

删行再逐选中行软删，保持头归属/版本/未删条件，更新审计和 Version+1；计算剩余未删行 PlannedDeliveryDate 的 Min，再按头 UID 更新 ExpectedDate，该最后语句当前不推进版本/审计、无版本条件、未检查影响数。Policy 禁止删光全部活动行；仓储不是独立业务验证器。上述不对称属于当前翻译事实，不在本轮顺手修复。作废不删采购行，只将头内存状态同步作废。成功返回 Ok(head UID,旧头版本,新头版本)。没有 Gross/Net/反馈/入库/库存/BOM 写入。

RequireLockedFacts 将 CONCURRENCY_CONFLICT 映射 VersionConflict/ExpectedVersion；缺 Gross 的 InvalidOperationException 经读/写支持映射 BusinessBlocked，不得统一成版本冲突。缺头由上层拒绝。错误 Facts 不可消费；写返回失败必须 EnsureWriteSucceeded 抛出，才能阻止前序写和日志/回执提交。

ReversalPolicy 仍拥有活动头、确认状态、所选行版本、数量守恒、损坏/错头/缺失引用、下游历史完整性及限制；取消确认经过引用守恒但不释放需求，已有完整反向历史与草稿/正式收货分别判断。不要在 PG 仓储另造生命周期规则。

DI 的 IProcurementReversalRepository 为 scoped；IProcurementOrderFactLockRepository 通过 GetRequiredService<IProcurementReversalRepository>() 返回**同一实例**。确认/关联注入 FactLock，反向注入 Reversal；必须继续共用 RepositoryBaseContext.Session/父事务，不另造连接或事务。反馈、独立采购编辑及收货也占同采购物理头行锁，但不是三个 FactLock 消费者之一。

LockCore/Apply 全部 SQL 用 CommandDefinition 透传 ct；当前方法无硬编码 commandTimeout/lock_timeout/等待预算，也不持独立租约。不能据此承诺无限或固定等待时间，Dapper/连接全局默认须实测。M15 Gross 等方法接口缺 token 的旧边界仍存在，不因本仓储有 token 就宣布整链等待可取消。

公共执行器当前对真实 SerializationFailure 在回滚后映射 ServiceUnavailable“并发数据已变化，本次事务未提交，请刷新后重新提交。”，非 VersionConflict、非 OutcomeUnknown；提交无法确认另有 OutcomeUnknown。不吞40001，不伪造40001，不自动重试。ReadSupport 未特判序列化失败，走 Unexpected 日志边界；保留这一真实差异，若统一须主控授权。执行器 finally 释放事务、清 Session，Dispose 失败关闭连接；preparedCommand 的声明顺序使事务先释放，准备租约后释放。仓储只用缓冲 Query，不提交/Dispose 父资源。

## PG 前置和最小实施切片

普通 SELECT 在 PG RepeatableRead/Serializable 使用既定事务快照，等待来源锁后重查不会自动刷新；同一旧快照两次 ownLinks 可以相等而遗漏后来提交的引用。锁定被快照后更新的现存行还可能真实中止事务。Serializable 谓词冲突检测不等于 SQL Server HOLDLOCK 的阻塞范围锁。[PostgreSQL 官方事务隔离说明](https://www.postgresql.org/docs/current/transaction-iso.html)

FOR UPDATE/SHARE 只作用于查到的行，空谓词/缺 UID 无行可锁。适用于已存在 Gross/Net/Link/采购/入库行的物理互斥，不能单独证明缺失 Gross、来源下空 Net、空 Link、采购空行、无入库/报告、无反向/替换流水安全。读结果 ORDER BY 也不证明优化器按该顺序取得全部锁；来源批次 .NET Guid 与 SQL uniqueidentifier 排序不同。[PostgreSQL 官方锁说明](https://www.postgresql.org/docs/current/explicit-locking.html)

对接 M15 已接回报告：候选 S(SourceType,SourceUid)/U(GrossUid) 必须覆盖 SourceReception、Manual、Material 建立/回退、采购生成/关联/反向等真实保护者；本仓储只输入采购/Net UID，不能凭空造可信 S。需统一发现→来源身份→多资源偏序→锁后重读、SQL 字典比较/尾空格等价键、第一次相关快照前的准备点；不得先持 U 后补 S 或锁头后补 Gross 造成倒序。M15 还登记销售头→Gross 与采购后段销售头潜在倒序，这里只报告，不声称已复现死锁。单 Command 租约只保护同 CommandId，单槽不能承载多个来源资源。

真实竞争方已经看到：反馈用 Serializable，先 Document 头→行→最新报告 UPDLOCK/HOLDLOCK→追加报告/日志，未调用 Gross/Net/Link；收货过账默认父隔离，先详情发现采购行→采购头→采购行→入库头→入库行→锁后来源集合重验→库存内核，采购来源归属变化抛 DBConcurrencyException。当前 PG 范围不能只迁反向一方就证明报告空范围或入库/流水历史稳定；收货草稿/撤销/反向等完整写者参与及反向/替换流水写入顺序仍须主控专项确认，未在本轮宣布齐备。

## 后续真实独立连接验收清单（全部未运行）

由主控明确实例/专库/随机 UID、可提交夹具及精确初始化清理范围；单连接 finally 回滚夹具不能冒充跨连接提交。保持 CHECK/不可变触发器/唯一索引，不能制造非法 TargetType、相同报告 Sequence 或不完整已取消贡献来过测试。

- 发现与来源集合变动：另一连接在发现后新增/取消/版本推进 Link、改变所涉来源集合；涵盖多来源与请求 Net、软删/失活历史、错头但本行、缺 Net、缺 Gross。证明冻结后的重验看到权威集合或真实40001整体中止，不靠桩替换返回集合。
- 高隔离先快照：真实命令回执 Find 或一致读先开始，另一连接提交来源/采购更新后释放锁；核验首次资源准备位置、原 ExpectedVersion/PreviewToken/ContextFingerprint 和分类。不能用事务内自写可见或预取消证明。
- 缺失/空范围：独立无 Link 单正常确认/取消/作废，空请求 Net，缺 UID 与新增同 UID，来源下空 Net/Link、首条报告、首笔收货、首个反向/替换流水竞争。无范围插入保护前不得标通过。
- 反向对确认/关联：同单不同 CommandId、跨单共享 Gross、反向输入顺序多来源；一个合法提交后另一个应按现有版本/状态/贡献重新校验，不超配、不释放他单贡献；false 分支已有收货/出货历史仍可补关联。
- 反向对反馈/收货：反馈先持头或反向先持来源，两种调度；首次反馈插入、收货过账/草稿及历史完整反向。核对头/行/入库/流水偏序与报告只警告、正式收货/未证历史阻断；避免用无关全局锁把所有来源串行化。
- 同/异 CommandId：同命令同输入只写一次及原结果重放，变用户/操作/目标/内容 CommandConflict；授权撤销先于回执。不同命令同资源不能依赖命令租约互斥，不同资源并发能力另测。
- 写入原子性：头成功后第二 Link/第二行旧版本，审计/回执写入失败；查询真实库头/全部行/Link/日志/回执完整回滚，内存版本前进不代表数据库提交。取消仅清头确认；Void 释放贡献但不删行；Delete 保留剩余 ExpectedDate；旧返回身份、消息与版本逐项比对。
- 等待取消/失败：使用真实生产 CommandDefinition 在已确认服务端等待时取消 token/耗尽冻结预算；观察事务清理、Session.Transaction、连接可用性/失效关闭及租约释放。M15 未透传 token 的方法不能凭本仓储测试覆盖；不固定 sleep 冒充等待证据。
