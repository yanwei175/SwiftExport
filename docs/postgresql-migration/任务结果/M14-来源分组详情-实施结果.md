## 两方法口径

分组仅限制软删除和传入生命周期，SourceUid 分组，SourceType、SourceNo 各自 MAX，COUNT 显式 integer。两项 MAX 可以来自不同的行；不按 Version/CreatedDate 选择最新来源，不增加客户、产品、活动资格或分页。MAX 在冻结 ICU 字典比较下运行并返回原字段；排序对 MAX 键按既有 ASCII 尾空格比较边界处理，使用字典排序及源 SqlGuid 规范字节优先级 `10,11,12,13,14,15,8,9,7,6,5,4,3,2,1,0` 的数组尾键，不用 .NET Ordinal 替代聚合或普通 PG UUID 顺序。

生命周期先 Distinct，保持首次出现顺序，再转 int[]。null/空集合不加状态条件，不以空列表提前返回。未知枚举值仍作为输入整数，不擅自归为全部或丢弃。null 请求先抛 ArgumentNullException，优先级与源一致。

首轮离线发现现有 PostgreSqlParameters.Add(int[]) 只赋 Value，实际 NpgsqlDbType 仍 Unknown，不满足明确 integer[] 门禁。共享类只读，因此新文件内增加仅负责 SourceLifecycleStatuses 的私有 IDynamicParameters：每次创建一个 NpgsqlParameter，类型明确 Array|Integer，SQL显式 CAST integer[]；不依赖连接包装器名字，不改公共参数类或建立通用数组框架。空集合继续使用既有空参数包。没有跨文件写入。

详情只按 uid 和软删除，完整 quoted CLR 别名直接投影原字段，包括版本、生命周期、来源身份/版本、商业快照、NULL客户/产品、单位原文及审计墙上时间；不加入指纹/客户/产品资格、联表集合、COALESCE、Trim 或计算数量。原接口和服务错误处理不变。两个方法各一条参数化只读命令，借用同一 context.Session 连接及可空事务，透传取消令牌，不开启/结束事务或关闭连接。
