## 补关联三方法对照

### SearchCandidatesAsync

- 输入与原方法一致：Keyword 先 .Trim()，非空则按原顺序转义 ~、%、_、[ 后包 %；SourceType 空白转 null，否则 .Trim()；SourceUid 原 nullable 值，Uid/LineId 不补校验。PageIndex/PageSize 原样返回，Skip 仍先算 int PageIndex-1，再转 long 相乘；仓储不代替服务钳制分页。Take<=0 在 SQL 维持技术失败（负 LIMIT），负 Skip 仍错误。
- 原 #Candidates 一次生成后供计数与分页复用，改为现有 MATERIALIZED 模式：一次物化 candidates，totals 与 page 共用；空页经 totals LEFT JOIN page 仍保留总数，不把占位当真实候选。没有临时表清理、公共会话资源或额外事务。
- 总数 int；页和最终传输都按 SourceNo、SourceType 的 CI/ASCII 尾空格键（NULL优先），SourceUid 的 SqlGuid 字节顺序、SourceLineNumber（NULL优先）、NetDemandId 的 SqlGuid 顺序；不以 .NET Ordinal 或 PG 默认 UUID 排序取代。
- 21 个 DTO 字段与物化投影逐名核对一致，显式 CLR 别名；Unit 原快照，NULL/空单位允许展示。Dapper 多映射按 NetDemandId 分割总数/空页标记与原 DTO；真实行映射缺失不默默补零身份。只传输当前页。
- Net/Gross 均未软删且生命周期0，Head 未软删且生命周期0、确认状态0/1，Line 未软删；头与来源客户匹配，采购行精确属于头；采购未关联量>0、物料尚有余量、拆解修订>0。
- 源需求指纹存在，物料指纹等值；标准产品要求双方 ProductId 相同、来源非标标记false、MaterialType/SupplyType 相同；非标分支保留双方 ProductId NULL 且来源非标true；物料 SupplyType 必须“采购”。
- 物料 used.Qty 汇总仅按 NetDemandId、TargetType=PO、未软删和 AllocatedQty>ReleasedQty，**原本未筛 LinkStatus，翻译也不追加**；不读/扣库存，不补 SourceDemandVersion/SourceVersion 校验、单位非空或当前产品资格。
- SourceUid/Type 可选筛选、Head 的 DemandSourceUid/Type 约束保留，四项 Keyword LIKE ESCAPE '~'。文本等值局部用公共 ICU CI 及 ASCII rtrim，原展示值不改变。此 Keyword 的 [ 已按原代码转义为字面，不是裸 LIKE 字符组需求。
- 一个命令借用当前事务并透传 ct；无预取消短路、锁定候选或容量预占，提交仍由服务重验。

### ReadTargetsAsync

保持输入 .Distinct().Order().Chunk(500)，此处 .NET Guid 排序与分块顺序不能改为全局 SqlGuid 排序；每批 SQL 对头 Uid、行 Uid 使用原 SQL Server SqlGuid 顺序。空集合无查询。使用共享明确 uuid[] 参数和 ANY，不展开数组。

保留七字段 LineId/HeadId/SupplierId/HeadVersion/LineVersion/ProductId/DeliveryTargetSupplierId，行/头未软删、头生命周期0；不追加确认、客户、Link 或供应商活动规则，不新增 FOR UPDATE。各批独立观察、各自透传事务/ct，与原方法一致。

### ApplyAsync

首先检查已有公共事务，缺失抛原同文异常，未发生打戳。保存原 head.Version，StampForUpdate(head)，只更新原头字段 DemandSourceType/Uid/No、Version、UpdatedDate/By；原 Uid+Version+未软删+LifecycleStatus0+ConfirmationStatus0/1 谓词不变。恰好一行才 head.Version++，否则立即返回原失败身份/当前版本、CONCURRENCY_CONFLICT 及原中文信息。

行仍按 .NET Guid Uid 排序逐项 StampForUpdate；只更新 UnlinkedQty、SourceType/Uid/No/LineId/LineNumber、Version、UpdatedDate/By，谓词 Uid+PurchaseOrderId+Version+未软删。失败立即返回原行身份/当前版本及原错误，不继续后续行；成功行才实体 Version++。全部成功返回 Ok(head.Uid,旧头版本,新头版本)。

更新使用共享元数据和 PostgreSqlParameters.Entity，NULL、整数枚举及时间绑定遵循既有映射。失败/取消/异常不撤销已经发生的实体打戳和已成功项 Version++，不自行回滚、提交、抛代替失败结果或吞异常。

MAIN AssociationService 的 ApplyInTransactionAsync 调用 EnsureWriteSucceeded(repository.ApplyAsync(...))；Support 把失败结果抛业务异常；BusinessCommandExecutor 的公共 Serializable 事务在异常路径回滚并清理。BuildAsync 通过 factLocks 锁源/物料/引用/采购事实，贡献 Link 插入及审计属于外层用例。本仓储不取代跨模块锁或公共回执。

## 供应商报告两方法对照

GetLatestForUpdateAsync 保留原17字段、单条/null结果，PurchaseOrderLineId 精确匹配、COALESCE(IsDeleted,FALSE)=FALSE（原ISNULL语义）、Sequence DESC，再Uid按SqlGuid DESC。LIMIT1 FOR UPDATE锁实际最新返回行，没有额外事务守卫、CT参数或报告范围/父头锁。

InsertAsync 沿用 StampForInsert 后令 SupplierReportedDate=CreatedDate，缺创建时间抛原中文异常；固定原17插入字段及顺序，返回影响行数。不强制 Version=1、不生成/替换Uid、不添加事务守卫、不更新历史。时间绑定用既有 Entity 参数，保持 nullable ReadyQty/ExpectedReadyDate 和原审计字段。

共享打戳只填缺失的 CreatedDate，原代码显式已有 CreatedDate 仍会保留；此翻译没有擅自改为总是当前时间。报告业务可见时间与实际打戳后 CreatedDate 完全相同，不再次取 now，不使用独立输入的 SupplierReportedDate。

MAIN ProgressReportService 在公共 Serializable 执行器中先 orders.GetHeadAsync/GetLinesAsync 取得头行并核对版本/活动已确认资格，再读最新报告、CreateReport 继承未知字段并决定序号/纠错、插入反馈和业务日志。原 Document 仓储头/行读取有 UPDLOCK/HOLDLOCK，PG 联合替代的最终接线与协议由主控。反馈仓储本轮不扩大为通用锁框架。
