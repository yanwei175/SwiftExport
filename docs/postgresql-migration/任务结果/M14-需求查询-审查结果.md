## 必须保留的事实边界

### Gross 工作台与详情

1. SourceUid 模式固定 PageIndex=1，PageSize 为总量至少 1，不能加 200 或 10000 行截断。普通分页上限 200；RequiredDate 空值最后，再按日期、CreatedDate、Uid 排序。PG UUID 排序与 SQL Server uniqueidentifier 不可直接宣称完全相同。
2. 默认只排除删除来源，不默认限定来源生命周期；列表过滤去重后传入，空列表不限制。截止日期按日期次日排他处理，起始时间保留输入时间。
3. 普通 Keyword 被 Trim 后直接包 `%`，四个快照字段原始 LIKE，无 ESCAPE；CustomerKeyword 则走 `SqlLikePattern.Build` 和 `ESCAPE '~'`。二者必须分别处理。
4. HasMaterial 只验证有效未删除 NetDemand；HasPurchase 另验证版本、指纹、客户、正剩余有效关联和目标单行，采购头允许生命周期不等于 9。HasDelivery 只检查正式过账装箱。不能把三个提示统一为一套数量或 Manager 的严格资格规则。
5. 详情保留需求快照，不回退当前商品数据。`ManualGrossDemandService` 在创建、修改、关闭的命令事务内回读详情，PG 必须借用同一会话／外层事务。
6. 原工作台数据和计数为两个独立命令且数据先读；单连接无显式事务不保证两次读取同一快照。迁移若选择一致快照应由主控明确协议和验收，不能当作方言替换顺手改变。

### Gross Trace

- 采购范围由该来源全部历史／删除物料关联中 TargetType=PO 的行生成，不能提前仅筛有效关联。
- 五个读取结果依次是来源头、全部物料修订、采购历史、交付历史、无效装箱历史计数；没有头时返回 null。物料／关联历史保留，缺目标时 HasPurchaseTarget=false，相关有效数量未知。
- ReadyQty 取整条采购行最新供应商进度，ReceivedQty 为整条采购行正式入库，不归属回当前 Gross；关联量另算。不能重复累计整行收货来表示当前来源覆盖。
- PackingList posting=1 与 8 均可展示，只有 1 计入交付；隐藏的删除、孤儿、快照或单位异常仍通过无效历史计数令 DeliveredQty 未知。
- 源身份、类型、版本、64 位大写十六进制指纹的审查原因与交付审查原因相互独立。现有测试明确：指纹或 SO 来源版本缺失可以有 ReviewReason，同时正式 DeliveredQty=4。不能把任一审查原因统一映射为所有数量 null。

### Material Trace

- 采购范围包括所选物料全部 PO 关联历史，树结果实际读取同 Gross 下所有未删除修订，而非限定同 Root。DTO 注释“同一拆解树”与当前查询范围存在偏差，应登记，不在本轮修正查询或扩契约。
- 收货覆盖先检查采购行上全部有效正关联及其来源／物料证据，再按需求日期空值最后、来源行号空值最后、LinkId 分配正式收货；任何无效关联、超分配、负采购／收货或单位异常令覆盖未知。
- whole-line ReceivedQty、当前关联覆盖、未覆盖收货、历史关联量是不同事实。两个 6 的关联对采购 12／收货 7，当前覆盖应为 6 和 1，不是各 7。

## 共享入库历史校验：需主控串行冻结

事实源：`InboundReceiptHistorySql.cs`。Gross Trace、Material Trace 和 PurchaseOrderTrace 使用 `ScopedGuard`；InboundSource、InboundQuery、PurchaseOrderManagerQuery、PurchaseOrderProgressQuery 等使用全局 `Guard`。不得逐个仓储复制独立规则或把 scoped 查询扩成全库历史阻断。

ScopedGuard 用采购临时集合定位相关入库头，scopeLine 不排除删除行，然后证明整个相关入库头的全部有效行历史。无关采购的坏反向历史不能阻挡当前 Trace；相关入库中其他行也不能漏检。

校验覆盖未删除 type=10、posting=1/8 入库头：无有效行、非正数／已有 OriginalLineId 的旧行，以及反向头创建模式／触发身份、反向时间／原因、每行原始与反向库存流水完整配对、精确两倍流水数量、产品仓库单位数量、负量反向类型 900、无替代修正关系及外部引用。禁止把旧负数反向单当普通净量相减绕过证明。

SQL Server 以 THROW 51001 报“入库反向历史不完整或存在旧负数反向单，净收货量尚未核实。”；SQL Server classifier 映射 `UnverifiedReceiptHistory`，两类查询服务据此返回“正式入库反向历史需核实，收货量未知。”。当前 PG classifier **没有此类别映射**。随便 RAISE P0001 只会走 Unknown，不能算契约等价；更不能借用序列化、取消或结构错误分类。

主控应冻结共享 PG 校验的形态、作用范围、绑定采购范围方式、专用错误识别与 classifier 映射，并共同覆盖所有消费者。是否使用现有异常协议扩展、私有参数化 SQL 或其他具体实现由主控定案，本轮不新增通用框架、函数或 DDL。

## 方言、会话与比较语义

| SQL Server 事实 | PG 实施检查点 |
|---|---|
| dbo／实体 Table 名称 | 复用 `PostgreSqlEntityMetadata`／`PostgreSqlNames` 的 public snake_case 物理名；DTO 别名显式保留 CLR 大小写 |
| bit、COUNT、空值占位、枚举 | 验证 bool／整数／numeric／Guid／nullable Dapper 映射；COUNT bigint 不直接冒充 int；UNION／CASE 空值显式类型 |
| `IN @Ids`／列表去重 | 复用现有参数机制；空数组、可空字段、枚举数组的过滤含义保持，不机械照抄 Dapper SQL Server 展开 |
| TOP／OUTER APPLY／ISNULL／DATEADD | 对应 LIMIT／LATERAL／COALESCE／日期参数；Latest Sequence＋Uid 排序、左连接缺项仍须保留 |
| STRING_AGG DISTINCT 来源子查询／FOR JSON PATH | 保留去重键、私有 JSON 反序列化、空数组与字段类型；不顺手改变展示排序 |
| SELECT INTO #temp／OBJECT_ID／DROP／QueryMultiple | 主控先定义无外层事务、已有事务、异常、取消、提前返回时的执行／清理协议；Npgsql 批处理可能引入隐式事务，不能直接照搬 SQL 批次 |
| 源列比较及 Trim | 核对实际 M14 源列类型／collation／PG 目标；SQL LTRIM/RTRIM 的空格语义不自动等同所有 Unicode 空白处理 |

`SqlLikePattern.Build` 当前规则为：空白输入返回空串，其余包 `%`；`~/%/_/[` 用 `~` 转义；ASCII 空格变 `%`，问号变 `_`，其他字符保持。它不替调用方 Trim。Material 关键字和 Gross 客户关键字均走这条路径，方括号是字面值，不能套入 RBAC 原始字符组解析器。

Gross 普通 Keyword 为原始 LIKE，方括号／连续连字符类字符组进入 B07 未闭合范围。主控已冻结当前 RBAC 代码、测试和 B07 缺口，本轮不再探针或修改它。M10 四个 RBAC 源列的 Chinese_PRC_CI_AS 与容量证据不能外推到 M14 各列；本轮没有查询 M14 数据库列元数据。字符串等值、MIN/MAX、排序、指纹、单位和原始 LIKE 应各自验证，不凭一个 ICU collation 宣称与源全等价。

可研究 Manager 私有 MATERIALIZED CTE 加总量／页面封装以免临时表，但这仍取决于主控读取快照协议；不能提前宣布单语句改变多语句快照无影响。所有查询借用现有会话／外层事务，禁止仓储自开独立连接或接管业务事务。
