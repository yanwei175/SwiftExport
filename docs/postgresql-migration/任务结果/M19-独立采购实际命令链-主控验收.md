## 实际行为与测试结果

使用真实 WebApi 服务注册和既有活动管理员身份，权限服务仍查询真实授权。两个 request scope 有不同 PG backend PID，调用原 IProcurementOrderDraftService.CreateAsync；业务执行器保持原 Serializable，正常执行映射、单位引用、PO实际取号、头行插入、业务审计和成功回执。

第一轮两个请求并发提交同一 CommandId，日志记录一次 Succeeded、一次 Replayed，随后第三次调用 Replayed。所有业务断言实际通过：返回同一头ID和单号，头/行/日志/回执各1，PO号段当前值1。随后测试夹具错误地删除成功回执，触发 P3100“只追加事实禁止更新或删除”，所以 **第一轮整体测试失败，不能标绿**。清理事务完整回滚，没有删除此前提交事实。原 SQL Server 生成结构也对回执/日志设只追加保护，这不是 PG 引入的新业务规则。

保留原失败 TRX。仅修测试政策，取消删除成功回执/日志/号段，登记并保留已提交事实；未关闭触发器、改结构或删除业务断言。为避免再造一批事实，新增明确传入原已登记 CommandId 的无增量重放场景，复用原输入及原操作者。此场景首次夹具误引用非持久化非标字段 `is_non_standard`，真实PG报42703；只改新增查询为实际 `product_id IS NULL`。修正后两真实请求重放 **1测试通过/0失败/0跳过**；原两失败记录均保留。
