SQL 文本次序可确认，**驱动是否提前执行后续语句、GridReader.Dispose 在未读完时是否排空／取消、首个结果可读取的具体服务端执行位置没有本轮实证**。不能声称“读到头时后续都没执行”，也不能声称“Dispose 后临时表必然清掉”。源三个方法都没有显式 DROP，临时表的批作用域和连接重用行为须结合 SQL Server 实际命令执行方式核验；PG 的临时表不能照搬同名创建而忽略调用后清理。

三个查询均传当前会话 Transaction 和 CancellationToken，不创建事务，不显式加锁。公开只读服务可以没有外层事务；Detail 又被保存／关闭命令在同一外层业务事务中调用，必须看见该事务自己的写入。迁移实现不得另开连接、提交调用者事务、引入全局业务锁或强制要求每个只读请求有事务。也不得静默引入 RepeatableRead／单 CTE 冻结全部商业头行。

## Manager 筛选、分页与头汇总

公开 `SalesOrderQueryService.SearchAsync`（38–45）只转发并传 `DateTime.UtcNow.AddHours(8).Date`；未另做页大小规范化。`PagedRequestBase` 默认 1／20；Repository 将 PageIndex<1 改为 1，PageSize<=0 改为 20，上限 200。与 M14 服务／仓储的分页处理不能类推；Offset 仍为 int 乘法，极端溢出是原实现边界，本轮不修改。

CustomerCodes、CustomerSkus 去空白、Trim、OrdinalIgnoreCase 去重；状态列表去重；Guid.Empty CustomerId 不筛选。OrderNo／CustomerPoNo／InvoiceNo 和 Keyword 使用 SqlLikePattern.Build：两端 `%`、ASCII 空格变 `%`、`?` 变 `_`、`~ % _ [` 转义，其余文本保留，**没有 Trim 输入**。Keyword 同时查询头快照、当前客户名称及有效销售行 Sku／CustomerSku／LinkSku／DescriptionEn。OrderDate 起点 `.Date`，终点 `.Date.AddDays(1)` 排他；有效交期筛选同样按日区间，但 LineFacts 的 EffectiveDueDate 由日期 cast 形成。未提供的有效交期参数仍被加入；PG 要提供正确 nullable timestamp 参数类型。

QuickView 0–8 的原分支需保留：待确认；零交付且有未交；部分交付；无未交；七天内到期；逾期；已关闭仍有未交；需核实／无有效行。2／3／4 要求有行且 ReviewCount=0。未知枚举值不命中任何分支，不能改成 All。DueSoon 含 Today 到 Today+7 两端；提醒只统计开放、已确认、可核实且未交>0 的行；PendingPastDue 不额外要求开放。EarliestOpenDueDate 包含未知或未交行。

头数量只在 LineCount>0、UnknownCount=0、UnitCount=1、MissingUnitCount=0 时返回；否则四项总量／单位为空。该门槛**不要求 ReviewCount=0**：超发量仍保留，FulfillmentStatus 则为空且 NeedsReview=true。多单位也不能求一个总量，但仅因多单位并不会自动生成 ReviewReason。无有效行 NeedsReview=true、原因“无有效销售行”、HasUndatedOpenLine=false。NULL 求和、空 LEFT JOIN 行对 MissingUnitCount 的影响必须保持。

页排序：仅 QuickView 5／6 使用最早到期／逾期日期，再 CreatedDate DESC、Uid DESC；PG 默认 NULL 排序和 UUID 排序不等同 SQL Server，应按冻结范围明确适配并用跨页样例验证。ReviewReason 是去重、排序后以“、”连接的非空值，不可改成随意拼接。客户名称来自当前 Customer，客户码／商业金额来自订单头；空客户 ID 映射 Guid.Empty，金额／汇率默认 0，不能把这些 DTO 回落扩展到未知交付数量。

## 共享行事实：未知与零、来源及箱单

事实构造器 7–119 为三个入口共用：

- 只选 SO＋头 Uid＋行 Uid、未删除、Active 或 Voided 的 Gross；Closed Gross 不参与。先 Active，再 SourceVersion DESC、Uid 升序；有 Active 时 CandidateCount 是 Active 数，否则是全部候选数。一个 Active 加多个 Voided 不等于重复活动来源；没有 Active 时多个 Voided 仍属重复。
- **开放待确认且没有候选 Gross** 直接视为可核实，已交 0、未交 Qty；这个分支在客户／单位／历史核验之前。已确认缺来源、来源重复、身份／单位／修订／历史异常时已交和未交为 NULL，不可 COALESCE 成零。
- 已确认一般要求 Active；关闭订单允许对应 Voided。核对来源单号、客户非空同归属、行号、非标／产品／Sku、若干产品文本快照、销售单位、Qty、RequiredDate。文本快照的空值和 ASCII 空格处理并不都相同，须保持各原表达式与 SQL 三值逻辑。
- SourceVersion 是正数且不大于候选头 Version，**不是必须相等**。Fingerprint 是 64 位大写 ASCII 十六进制格式检查，查询未重新计算哈希。此有限格式不要求重新做 B07 通用字符类探针；SQL LEN、BIN2 原始 LIKE 及尾空格应作针对性转换，不能只替换成普通大小写不敏感匹配。
- 箱单净交付仅累加有效头行且 PostingStatus=Posted 的 Qty；Reversed 不参与净量，也不是再减一次负数。历史验证独立检测孤儿头、删除行仍过账、无效／删除头、客户／单位／产品／Sku／来源快照不一致、缺过账或反向日期等。非删除 Unposted 行的坏快照也可能触发历史异常；不能把检查范围缩成已过账行。
- 原因有优先级：待确认残留来源、缺来源、重复来源、来源状态、旧证据、箱单历史、来源身份／单位、超发。可核实且超发：已交保留实际大于 Qty 的量，未交截为 0，原因“超发需核实”。不能以 NeedsReview 为由清空所有已交数量。

Detail 的商业头映射（235–265）沿用销售订单快照，不回查当前产品补值；ETA／ETD 映射 Eta／Etd，关闭信息独立保留。Detail 行的 ReviewReason 可以为 SQL NULL；Fulfillment 将其回落为空字符串，这是原 DTO 投影差异。

## Fulfillment 采购和历史的独立口径

履约行的 Gross ID／数量／单位／Version 仅在 ReviewReason 为 NULL 或“超发需核实”时公开，否则全部为空。SourceState 先判“需核实”，无 Gross 且待确认为“待确认”，其他无关联／有关联分别显示“未关联”／“已关联”。已关闭时 AllowedFurtherDeliveryQty 对已知未交返回 0，对未知仍是 NULL。

构造 FulfillmentLines 时重新挑选 Gross，而不是复用 LineFacts 内选中实体。第二次虽计算 CandidateCount，却没有再次以它独立挡住投影；保留旧原因与新 Gross 混合观察的可能性，或改为统一冻结，都需要 M16-P04 决定，不能在移植中默改。

采购读取（76–137）直接连接 Gross、Net、Link、采购头行、当前 Product、SupplierProgressReport：

- Gross 活动、Net 活动且未删除；Net 的 GrossVersion、SourceVersion、Fingerprint 快照都须等于 Gross 当前值；活动未删除 PO Link 且 AllocatedQty>ReleasedQty；采购目标头行可定位且未删除，头只排除 Voided，并非只允许活动头。
- LinkedQty 汇总 AllocatedQty-ReleasedQty；采购客户空／不等 Gross 客户或任一贡献单位不兼容时返回 NULL 并显示原因，不能丢掉整行而解释为无关联。
- **单位核验读取当前 Product.Unit，空时仅根 Net 回落 Gross.UnitSnapshot；没有读取 Net.UnitSnapshot。** 子 Net 无单位不得套根来源单位。此口径与 M14 Material 查询不同，现有 SQL Server 集成测试还明确修改 Product.Unit 来验证该行为。它是需登记和冻结的源事实，不是本轮统一快照规则的授权。
- `pol.QTY` 是 SQL Server 物理名，CLR 为 PurchaseOrderLine.Quantity；PG 预览目标是 `quantity`，不能机械 snake_case QTY 得到 qty。
- 最新报告按 Sequence DESC、Uid DESC；HasProgress 表示报告存在，ReadyQty 可以为空、零或较旧报告更小，保留整采购行的报告量，不按销售贡献分摊；不是入库量。共享采购行仅检查另一 Gross 的活动净需求／活动正剩余 Link，不额外套当前行全部版本核验。

箱单结果（139–147）同时展示 Posted／Reversed 的正 Qty 历史，CountsTowardDelivery 仅 Posted 为真。异常 ID 查询（150–173）还检查非活动 Net、缺／不匹配三项版本证据、缺目标、采购作废及单位异常；采购客户错配由采购结果中的 ReviewReason 处理，不在异常 ID SQL 条件中。C# 先 SourceState “需核实”→PurchaseState “未知／需核实”，否则异常 ID 或任一采购原因→“需核实”，否则按有无采购项显示“已关联”／“未关联”。异常 ID 对应 PurchaseReviewReason 固定“采购关联证据异常”。

## 调用链、接线与真正前置

直接消费接口的 Application 实现只有 QueryService、FulfillmentQueryService、DraftService、LifecycleService。确认／取消确认服务不直接调用这个查询接口；删除草稿也不返回 Detail。QueryService 的客户代码／产品候选／客户候选分别用 Customer／Product 仓储，不扩大本接口的方法清单。

Draft Save（53–145）经 CommandPipeline／BusinessCommandExecutor；更新时头、行加锁，写入完成后第 141 行 GetDetail 不传 token。Close（47–96）同样经命令执行器，头行加锁、收口来源、写关闭状态后第 94 行 GetDetail 不传 token。BusinessCommandExecutor（25–137）开启并共享外层事务，执行委托后写回执并提交，失败回滚、finally 清 Session.Transaction。查询不得夺走这项职责；保存／关闭目前未给 GetDetail 传 token 是源调用事实，本轮不顺手改服务。

## 方言与验证建议

方言涉及 SELECT INTO 临时表、TOP/OUTER/CROSS APPLY、CONVERT(bit/date/decimal)、ISNULL、dbo 标识符、IN 数组参数、OFFSET FETCH、STUFF/FOR XML、BIN2／LEN／LIKE、SQL Server 排序与补空格比较。可用 PG 私有分阶段工作集／LATERAL 等实现，但最终结构依 P02–P04，而非本审查自行选择。boolean 返回为 bool、decimal 保留精度；源 timestamp without time zone 语义不得经 UTC 转换改变商业日期。B07/B10 已登记范围只标影响：本入口搜索来自限定 SqlLikePattern，不能扩大为任意 SQL LIKE 解析；Unicode、尾空格、大小写及排序兼容边界需沿主控冻结记录，不做新探针。

现有测试的事实：`SalesOrderManagerQuerySqlTests` 是一条受 `SWIFTEXPORT_RUN_SQL_TESTS=1` 控制的隔离 LocalDB 大场景，涵盖草稿零交付、已确认部分交付、采购共享／最新修正／当前产品单位、取消 Link、缺目标、箱单累加／反向／超发、缺指纹、关闭余量、空头、多单位及坏来源／历史。源码契约与路由注册测试只能证明文本／反射契约；确认命令测试的内存事务也不能证明 M16 PG 读取协议。本轮未执行它们，不沿用历史通过数。

未来真实 PG 最小验收，须由主控明确实例、库名、初始化／清理范围后授权：

1. 三入口一致对照：开放待确认无来源为 0/Qty；已确认缺来源／指纹／客户／单位／修订为 NULL；无有效行、缺头返回各自正确结构；Active＋Voided、重复活动、关闭＋单 Voided、SourceVersion小于／等于／大于头版本。
2. 一头多行、混单位／缺单位／未知行对总量和快捷筛选影响；超发 12/10 保留 12／0、Review=true、状态 NULL，不能进 FullyShipped；日期起止、Today+7、未知 QuickView、空过滤、PageSize 0/超限、超末页总数、稳定跨页及 ASCII 模式转义。
3. 箱单 Posted→Reversed 后净量归零且历史保留正量、Count=false；坏历史与欠快照按原原因优先级。约束已禁止的负量等样例应验证 CHECK 拒绝，不禁用约束硬造非法历史。Gross 非标／产品、Link not-deleted／正剩余／取消全释放约束也需合法夹具；旧 LocalDB SQL 不能原样搬到 PG。
4. 采购三项快照、同客户／错客户、目标错头／缺失／作废、根与子 Net 单位、当前 Product 单位变化、活动贡献与全释放、共享采购行、报告缺失／NULL／零／修正更小量；采购反馈保留 whole-line，取消无采购与证据异常必须区分。
5. 协议：预取消、服务器阻塞中取消、不同结果位置取消／抛错、空头早返和未读完 Dispose 后连接复用；连续同连接调用无临时表冲突／残留。外层事务调用可见自身写入，查询不 commit/rollback/dispose 外层事务；返回后调用者还能继续写入／回滚。
6. 用两连接和明确阶段屏障观察候选头后、LineFacts 后、头结果后、count 后分别改变头／行／Gross／箱单／采购；记录真实源与目标可见内容，不能仅靠串行 DTO 测试宣称一致。无外层事务及已有 ReadCommitted／调用者其他隔离分别验；不为了取证新增生产锁。
