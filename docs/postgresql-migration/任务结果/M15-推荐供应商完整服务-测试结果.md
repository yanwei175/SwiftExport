## 真实链路与保持的语义

组合真实 MaterialDemandSupplierSuggestionService、CommandPipeline、请求验证器、BusinessCommandExecutor、PGNet、PGSupplier、PGReceipt 与同一个原生 DbSession。当前人、关联标识及权限使用分派允许的明确测试端口；不声称 HTTP、JWT 或真实权限投影通过。

唯一回执装饰端口只在真实 Insert 前后放置屏障/故障，AcquireBeforeTransaction、Lock、Find、Insert 均委托真实仓储；保留 ICommandTransactionPreparation，不替代物理锁或数据库事实。

原执行器默认业务事务隔离保持不变，没有为了用例改成 Serializable。源码实际更新仅四列：SuggestedPurchaseSupplierId、Version、UpdatedDate、UpdatedBy；全列快照比较其他字段。同值建议仍先验证供应商资格，保留版本且提交一次回执。清空、更换按原返回快照验证。

PGSupplier 原 GetById 按未删条件读取，不额外过滤 IsActive。停用但未删的既有供应商用例保持该事实，没有因错误文案而新增拒绝策略，也不写供应商主数据。

来源准备实际持有 C_cmd 后，在首个业务事务前取得 S/U；来源等待以独立 backend PID、pg_stat_activity 的 try-lock/无 backend_xid 以及 owner 的 pg_locks 同键 granted 取证，再验证 owner 提交后的业务结果。未用 Delay 时长充当唯一竞争证据。

取消用例断言 OperationCanceledException 继续传播、调用方及异常关联令牌已取消、无事务/事实变化/回执，资源归还后第三个 backend 能重取命令与来源覆盖。准备层使用关联令牌，因此不错误要求异常 CancellationToken 与原调用方令牌实例相等。
