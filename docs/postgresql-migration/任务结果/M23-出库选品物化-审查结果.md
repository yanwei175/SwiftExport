## 非null排除列表的最小单语句候选

建议以下单语句结构；所有物理名正式实现经固定实体metadata构造，参数禁止外部标识符。下面是**尚待主控冻结/实测的候选SQL**，仅非null `Guid[]`参数语义已能从类型与集合代数审查；不是已落地代码。

```sql
WITH candidates AS MATERIALIZED (
  SELECT b.uid AS "Uid", b.warehouse_site_id AS "WarehouseSiteId",
         b.product_id AS "ProductId", p.sku AS "Sku", p.link_sku AS "LinkSku",
         p.description_zh AS "Description", p.main_image AS "ImagePath",
         p.unit AS "Unit", b.on_hand_qty AS "OnHandQty",
         dw.name AS "DefaultWarehouseName"
  FROM public.inventory_balance b
  JOIN public.product p ON p.uid=b.product_id
  JOIN public.warehouse_site w ON w.uid=b.warehouse_site_id
  LEFT JOIN public.warehouse_site dw ON dw.uid=p.default_warehouse_site_id
                                        AND dw.is_deleted=FALSE
  WHERE b.warehouse_site_id=@WarehouseSiteId
    AND b.is_deleted=FALSE AND b.on_hand_qty>0
    AND p.is_deleted=FALSE AND p.is_active=TRUE
    AND w.is_deleted=FALSE AND w.is_active=TRUE
    AND NULLIF(btrim(p.unit,' '),'') IS NOT NULL
    AND b.product_id <> ALL(@ExcludedProductIds)
    AND (@Keyword IS NULL
      OR p.sku COLLATE public.erp_dictionary_ci LIKE @Keyword ESCAPE '~'
      OR p.link_sku COLLATE public.erp_dictionary_ci LIKE @Keyword ESCAPE '~'
      OR p.description_zh COLLATE public.erp_dictionary_ci LIKE @Keyword ESCAPE '~')
), totals AS (
  SELECT count(*)::integer AS "TotalCount" FROM candidates
), page AS (
  SELECT c.*, TRUE AS "HasItem" FROM candidates c
  ORDER BY rtrim(c."Sku",' ') COLLATE public.erp_dictionary_ci ASC NULLS FIRST,
           ARRAY[get_byte(uuid_send(c."ProductId"),10),get_byte(uuid_send(c."ProductId"),11),
                 get_byte(uuid_send(c."ProductId"),12),get_byte(uuid_send(c."ProductId"),13),
                 get_byte(uuid_send(c."ProductId"),14),get_byte(uuid_send(c."ProductId"),15),
                 get_byte(uuid_send(c."ProductId"),8),get_byte(uuid_send(c."ProductId"),9),
                 get_byte(uuid_send(c."ProductId"),7),get_byte(uuid_send(c."ProductId"),6),
                 get_byte(uuid_send(c."ProductId"),5),get_byte(uuid_send(c."ProductId"),4),
                 get_byte(uuid_send(c."ProductId"),3),get_byte(uuid_send(c."ProductId"),2),
                 get_byte(uuid_send(c."ProductId"),1),get_byte(uuid_send(c."ProductId"),0)] ASC
  LIMIT CASE WHEN @Take<=0 THEN -1 ELSE @Take END OFFSET @Skip
)
SELECT t."TotalCount", COALESCE(pg."HasItem",FALSE) AS "HasItem",
       pg."Uid",pg."WarehouseSiteId",pg."ProductId",pg."Sku",pg."LinkSku",
       pg."Description",pg."ImagePath",pg."Unit",pg."OnHandQty",pg."DefaultWarehouseName"
FROM totals t LEFT JOIN page pg ON TRUE
ORDER BY rtrim(pg."Sku",' ') COLLATE public.erp_dictionary_ci ASC NULLS FIRST,
         /* 同上ProductId的完整SqlGuid字节数组，正式SQL不得省略或改.NET排序 */
         ARRAY[get_byte(uuid_send(pg."ProductId"),10),get_byte(uuid_send(pg."ProductId"),11),
               get_byte(uuid_send(pg."ProductId"),12),get_byte(uuid_send(pg."ProductId"),13),
               get_byte(uuid_send(pg."ProductId"),14),get_byte(uuid_send(pg."ProductId"),15),
               get_byte(uuid_send(pg."ProductId"),8),get_byte(uuid_send(pg."ProductId"),9),
               get_byte(uuid_send(pg."ProductId"),7),get_byte(uuid_send(pg."ProductId"),6),
               get_byte(uuid_send(pg."ProductId"),5),get_byte(uuid_send(pg."ProductId"),4),
               get_byte(uuid_send(pg."ProductId"),3),get_byte(uuid_send(pg."ProductId"),2),
               get_byte(uuid_send(pg."ProductId"),1),get_byte(uuid_send(pg."ProductId"),0)] ASC;
```

候选只有基础表生产读取一个定义，count/page两次扫描是同materialized集合；count聚合无GROUP BY，候选0也有一行TotalCount0；count LEFT JOIN page，超末页仍一行TotalCount>0/HasItemfalse。只使用COUNT OVER放在page行上会丢失空页总数；count CROSS JOIN page也丢；UNION假DTO默认身份会污染客户端资格。外层必须重复页排序，不能依赖内层ORDER BY传递，也不在C#排序。

Sku排序候选局部rtrim仅用于U+0020尾空格比较，不更改返回Sku或关键词列；collation是现PG字典资源，**主控必须冻结这个具体排序键并对源Sku排序取证**，尤其相等SKU文本变体后才轮到ProductId。源码原ORDER BY Sku没有显式Trim。当前ICU与源Chinese_PRC_CI_AS的广域差异、B10/B19未解决；不能把已有SourceType样本升级为全Sku排序/LIKE等价，不加硬编码样本/全局normalize/ILIKE替代。

MATERIALIZED保证候选关系只生成一次，不等于全用例锁、库存预占或与SQL Server锁式RC逐时刻扫描完全同快照。PG单语句MVCC观察点是目标候选方案的一部分，需要主控明确接受；不能把“两独立SELECT同SQL文本”称源一次物化等价。不要新增临时DDL/事务、二次生产表查询、全量候选传到C#再Count/Skip/Take、通用物化框架或共享抽象。

## Dapper私有投影与参数

建议私有嵌套行模型（不是Contracts DTO/公开Core模型）：TotalCount int，HasItem bool，Uid/WarehouseSiteId/ProductId为Guid?，OnHandQty decimal?，六个文本Sku/LinkSku/Description/ImagePath/Unit/DefaultWarehouseName为string?。三种UID和数量设nullable是LEFT JOIN空页行真实NULL所需，**不能用Guid.Empty或OnHandQty=0判断是否有项目**。HasItem来源page的TRUE常量，外层仅将不存在的标志COALESCE false；真实Guid.Empty（数据库未CHECK禁止）也不得在仓储丢弃。

一次`QueryAsync<私有行>(Command(sql,args,token))`缓冲**一页+最多一个空页占位行**，不缓冲全量候选到客户端。第一行TotalCount为SQL COUNT；HasItem=true逐行仅组装原十字段DTO，保持SQL行序和NULL文本。不能C#再查资格/改余额/重算TotalCount/Distinct。原COUNT总有一行，若映射结果异常空集合，保持技术异常而非默默TotalCount=0；true行缺必需身份/余额应暴露映射错误而非默认或忽略。不向API暴露HasItem/TotalCount重复列，不为投影新增公开构造或公共映射器；私有默认构造/属性实际Dapper反射可用性需离线实际Dapper及真Npgsql验证。

局部参数明确WarehouseSiteId uuid、ExcludedProductIds uuid[]、Keyword text（可DBNull）、Skip bigint、Take integer，每个命令新实例，借当前可空Transaction/原token，不新开连接/事务。现四查询QueryParameters只识别Uid/ProductId、Ids、Keyword、Skip，其余默认Integer，**直接把新参数塞进去会将仓库/排除数组错误指定Integer**。最小方案是新partial内独立ItemQueryParameters，不扩公共参数组件；可复用已有private Command、Like、Table、C、ProductMap/BalanceMap及UuidOrder，它们无需改public/protected可见性。WarehouseMap可私有定义在新partial。

## 排除数组证据边界：必须由主控定案

Dapper依赖实际2.1.66；本机NuGet XML只说明PackListParameters收IEnumerable参数，**不说明null/empty展开/参数DbType/SQL Server执行语义**。本轮未调用PackList/反编译/实库探针。现消费者默认空列表、非空列表和重复GUID，服务显式拒null；既有假仓储/WPF测试不证明Dapper生成SQL。

- 非null Guid列表：显式uuid[]+`product_id <> ALL(...)`在非NULL产品ID下可表示NOT IN；空数组比较真，重复/Guid.Empty保留，无需Distinct/COALESCE/NOT EXISTS。仍须真实源empty/nonempty的Dapper展开+执行结果确认。
- **列表本身为null**：源直接仓储可能被Dapper当空枚举重写、绑定NULL标量或产生技术异常，本轮不猜。PG `<> ALL(NULL::uuid[])`是UNKNOWN，不会等价于空数组；直接公共AddIds(null)也可能提前抛出不同异常。未经主控源证据与授权不选null→[]、COALESCE或新Validation。
- 正常List<Guid>无NULL元素；不为不可构造DTO成员新增nullable集合/框架。若主控另测原始SQL含NULL元素，SQL NOT IN三值语义必须另列，不以NOT EXISTS自动忽略NULL冒充等价。
- 服务Count按原列表长度：500重复有效，501重复仍拒绝，不在仓储去重后规避服务限制。

主控只读探针最小输入：空List、null List、单GUID、重复GUID、Guid.Empty，读取实际匿名参数类型、Dapper发出SQL/参数类型、执行结果/错误；有/无候选及正常页。不能凭一条手写NOT IN(NULL)探针代替源Dapper调用，也不能以本轮审查申请DB写权。

## 非法参数、异常与取消

源先候选INSERT临时集，再count，page错误可能在执行/读count/读page阶段出现；QueryMultiple缓冲/SQL Server流式错误具体时刻未取证。PG单语句LIMIT/OFFSET可能先评估、count::int或候选产生错误顺序也可能不同。两者正常服务只返回完成PagedResponse，**不能承诺内部阶段、部分reader数据、取消优先级/具体错误文本完全一样**。无需模拟Count先返回才能表示用户结果等价，主控需冻结可观测成功/技术失败及资源清理边界。

候选局部`LIMIT CASE WHEN @Take<=0 THEN -1 ELSE @Take END OFFSET @Skip`保留源FETCH<=0技术失败，避免PG LIMIT0成功；OFFSET<0也技术失败，不改PageIndex或服务错误码。这一行为在四查询真PG已验，仅作为同类证据，**本候选在count0/超末页/查询优化分支也必须实测**，不能因LEFT JOIN就未经运行宣称所有非法页必拒绝。

保留int减1溢出后long乘：PageIndex=int.MinValue的int减1在当前unchecked表达式可能回绕int.MaxValue；不能重写成`((long)PageIndex-1)*PageSize`。覆盖PageSize0/-1/int.MinValue、PageIndex0/-1/int.MinValue/int.MaxValue、极大合法Skip，candidate0/非空/超末页矩阵，原页值回传。null request仍是仓储原成员访问技术失败；服务ValidatePage先拒绝，不加仓储统一ArgNull/先token检查静默改变优先级。

仅新单语句/一次命令变更读取格式；原token传CommandDefinition，QueryAsync完整缓冲后再组装；无候选也必须执行SQL得到COUNT，不照搬GetProducts空输入早返。取消场景需分别测预取消、Execute前、服务端真实等待、ReadAsync中、组装前/读取完成边界、传输异常；以真实token/reader处置与连接SELECT1或父事务rollback恢复为准。SQLServer临时DROP在取消/异常后的具体残留行为未证实，PG CTE无持久临时资源是候选设计差别，不为复制潜在残留建临时表。Npgsql服务器57014不自动等于用户token取消；沿原classifier/support，不包装成VersionConflict或新增业务错误。仓储不回滚/释放父事务；PG异常导致aborted由外层结束。
