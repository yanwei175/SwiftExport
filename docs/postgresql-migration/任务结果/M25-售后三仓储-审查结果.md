写入细节：插入包含调用方 `IsDeleted`，不强制 false，不生成 Uid；插入审计只填 null 的 Created/Updated 日期和用户名，保留已传值。更新审计强制当前时间和用户名，Created 字段不改。事务检查在审计和实体解引用之前，因此 null 实体无事务先报事务错误，有事务后会出现原空引用；不得静默加入另一层业务校验。写入失败没有恢复输入对象的审计字段；这与父数据库回滚是两个边界。原始仓储可更新已删行、允许更新 HeaderId；真实维护服务没有暴露任意换头，但新守卫若改变直接调用语义，须由主控先界定授权调用和资源归属。

没有取消参数、权限判断、内部重试或批量保存。每次行写入一条 SQL；维护循环写行不能折叠成新批次并改变审计/Version/失败位置。

### Query：SearchAsync

输入 request 为 null 时原空引用；仓储不做业务验证。PageIndex 至少 1，PageSize<=0 使用 50，然后限制 1..200。Skip 使用原 int `(page-1)*size`，大索引可能溢出；源端也是问题，迁移不能悄悄改成长整型分页。请求对象不被改写。

筛选：头 `IsDeleted=0`；CustomerId、ResponsibleSupplierId、DocumentStatus、ConfirmationStatus 都是可空等值条件（没有 OwnerId 筛选），Empty Guid/非法非空枚举也直接入 SQL。DateFrom/DateTo 取 `.Date`，分别 `>=`、`<=`，结束日只有午夜上界；同日午夜之后 AcceptedDate 被排除。反向日期范围自然无结果，不新增验证。没有额外客户有效性、权限、生命周期或确认条件。

Keyword 空白转 null，否则 Trim 后直接包 `%...%`，**不转义**。匹配 AfterSalesNo、CustomerComplaintNo、IssueSkuSnapshot、IssueCustomerSkuSnapshot、IssueLinkSkuSnapshot，以及 EXISTS 中未删明细的 SkuSnapshot、CustomerSkuSnapshot、LinkSkuSnapshot。原 `%`、`_`、SQL Server 方括号模式/否定集是查询语言；不可套用会转义通配符的 `SqlLikePattern.Build`，也不可用 ILIKE 假装完全覆盖方括号和源比较语义。多行命中不重复头；零行头仍可由头字段匹配；不搜索问题描述、文件夹、颜色等新字段。

一次 QueryMultiple 命令，**两个 SELECT、两次原观察**：先 COUNT(int)，后分页。无隐藏事务/隔离升级；继承父事务。无事务/ReadCommitted 下计数与页可因并发不同，父 RepeatableRead 下共享快照；不能改成同一语句 MATERIALIZED 快照或新增内部事务。使用 CommandDefinition 传 token，GridReader Read 使用原 API；using 释放 reader。

页 SQL 是头 35 列加 5 个计算列，共 40 列；实际列表 DTO 为 17 属性：`Uid,Version,CustomerComplaintNo,AfterSalesNo,CustomerId,CustomerCodeSnapshot,CustomerNameSnapshot,AcceptedDate,OwnerId,DocumentStatus,ConfirmationStatus,ExpectedCompletionDate,OwnerName,IssueModels,ResponsibleSuppliers,KnownAmountCny,HasUndeterminedAmount`。其余 SQL 列被 Dapper 忽略，不新增 DTO 属性；保留原全局映射及 null/初始化空字符串行为，不改 ApplyNullValues。

- OwnerName = COALESCE(NickName,UserName,'')；关联 SysUser 不过滤删/停用，空/空格 NickName 不回退。
- KnownAmountCny = COALESCE(ServiceAmountCny,0)，NULL 用 HasUndeterminedAmount 区别于免费 0；金额不乘数量。
- IssueModels = COALESCE(NULLIF(IssueCustomerSkuSnapshot,''),IssueSkuSnapshot,'')；源 NULLIF 比较可能把尾空格等视作空，PG 原生 NULLIF 不能直接当等价。
- ResponsibleSuppliers = COALESCE(SupplierName,'')，关联 Supplier 不过滤删/停用。
- 顺序 AcceptedDate DESC、SqlGuid Uid ASC；PG uuid 顺序不能代替 SqlGuid。

### Lookup：LookupAsync 与 ReferenceAsync

`LookupAsync(kind,request,token)` 先构造白名单 ReferenceSql，再解引用 request：非法/null/大小写不同/带空格 kind 均 ArgumentException（参数 kind，原提示“不支持的售后候选类型”），即使 token 已取消也先遇该边界。合法 kind+null request 原空引用，不 Trim kind。分页、int Skip、Trim 后未转义 Keyword 与 Search 一致；Keyword 仅 Code/Name。一个 QueryMultiple、COUNT 后页两 SELECT，按 Code 的源比较顺序及 SqlGuid Uid 排序。PG ASC 默认 NULLS LAST 不能替代源 NULL 前置；应按合法源投影是否可能为 null 决定样本，不能造违反非空约束的数据。

`ReferenceAsync(kind,Guid uid,Guid? customerId,bool requireActive)` 一个 QuerySingleOrDefault，无 FOR UPDATE、无 token，无隐藏事务；按 q.Uid 查询，缺失返回 null。Empty Guid 直接查询；CustomerId null 对销售明细 `=@CustomerId` 无匹配，对产品无客户 SKU，其余类型忽略 CustomerId。七类动态 SQL 只来自固定白名单，禁止从输入拼表名或建立提供者框架。

| kind | 两方法共用投影/过滤（Lookup 固定 requireActive=true） | 需保留的反直觉边界 |
| --- | --- | --- |
| customers | 未删 Customer；active 时加 IsActive；Uid/CustomerCode/CustomerName | Reference false 可以返回停用客户，但仍不返回软删。 |
| suppliers | 未删 Supplier；active 时加 IsActive；Uid/SupplierCode/SupplierName | 同上。 |
| owners | 未删 SysUser；active 时加 IsActive；Code=UserName，Name=COALESCE(NickName,UserName) | 没有第三个空字符串回退；空 NickName 仍空。 |
| colors | 未删 ProductColor；Code=ColorCode，Name=COALESCE(ColorNameEn,ColorNameZh) | **忽略 requireActive**；空英文名称优先于中文。 |
| quality-categories | 未删 SysDictData；DictCode='AfterSalesQualityCategory'；active 时 IsEnabled | Code=COALESCE(DataNameEn,Zh)，Name=COALESCE(Zh,En)；不加 IsSystem/字典类型 join。字典常量需源比较规则。 |

产品另含 OUTER APPLY TOP(1) CustomerProduct：匹配 Product Uid 和 CustomerId，关系始终未删且 active，即使 Reference requireActive=false；按 **SqlGuid 关系 Uid** 选第一条。缺失关系 CustomerSku 为 null；不加客户活跃性或产品库存/物料条件。PG 需等价 LEFT JOIN LATERAL + LIMIT 1，不可改成任意 MIN/普通 join 造成重复。产品 9 投影为 `Uid,Code,Name,CustomerSku,LinkSku,Unit,ColorId,ColorName,Specification`；其余类型只投影前 3 列，其余 DTO 属性保留初始化/默认值，不增加补查。Reference 没有取消接口，不能宣称传 token 的全链取消。

## 服务调用链、首条 SQL 与外部副作用

认证/权限可能在命令事务之外先访问数据库，不将“第一业务 SQL”混作系统第一 SQL。纯验证/指纹之后 BusinessCommandExecutor：事务前回调（若有）→ Serializable 父事务→回执 Lock→回执 Find 是事务内首个数据 SELECT/快照→回放可能提前结束→业务委托→业务审计→不可变回执 Insert→提交。锁准备必须早于 Find，不能等业务头读或更新后补。沿用共享异常、事务和提交未知协议，不内建仓储重试。

所有写服务通常先审计 Snapshot：GetHeader(true)，存在时 GetLines(true)；随后业务再读头/行；成功后审计再读头/行。存在头的常见执行是三次头、三次明细观察（具体按分支），不是“一次读再复用”。创建头缺失的审计不读行，维护另有头存在判断；缺失/回放/失败分支更少，不能宣称所有分支固定六读。

| 链 | 当前事务/首条业务 SQL | 业务边界和副作用 |
| --- | --- | --- |
| Query Search/Lookup | 验证认证、View 权限、token 后对应仓储；不建事务 | 参数 ArgumentException 转验证结果，AfterSalesException 保留业务错误；原空引用不归入新增验证。 |
| Query GetAsync | 禁外部已有事务；Begin RepeatableRead；RequireHeader/GetHeader(false) 首读，再 GetLines(false) | 服务过滤软删行后映射详情/能力；父提交/失败回滚并清 Session.Transaction。接口读无 token，启动后不能宣称 driver 可取消。 |
| Maintenance ExecuteSaveCommandAsync | Serializable；**无事务前 Source 准备回调**；先审计头锁读 | 创建用输入 Uid、CR 编号生成在父事务内；读全部历史行，下一行号 max+1，不复用软删 ID。逐头/行写、审计、回执；Save 不 Receive Source。 |
| Confirmation 执行确认 | 已有事务前 `AcquireBeforeTransactionAsync([uid],[],ct)`；回执后审计头锁读 | 校验版本、开放/待确认、正数量行，Receive CR（SourceVersion=头 Version+1，RejectUnsubmittedActiveLines=true），再确认字段/头更新/审计/回执。没有正数量时跳 Receive 和确认字段赋值，但仍写头递增 Version。 |
| Cancellation 执行取消确认 | 同样已有 Source 准备；回执后审计头锁读 | 版本/状态/原因/已确认检查；按正数量行 UID Cancel CR；成功清确认人/日期、改待确认、写头/审计/回执。Source 失败整链回滚。 |
| Lifecycle Close/Reopen | Serializable；**二者无事务前 Source 准备回调**；LoadForChange 的审计头锁读在先 | 正数量未确认禁止结案；正数量已确认仍固定交付查询未接入错误。零正数量结案写 Closed/Conclusion；重开仅 Closed→Open，不 Receive。 |
| Lifecycle Void | 已有 Source 准备；审计头锁读在先 | 已确认直接阻止，不调用 HasActive；否则查活跃 CR Source，有则阻止；无则改 Voided。不是自行 Close/Void Gross。 |

维护规则不能因技术迁移变化：标准新产品复制当前单位/快照，同身份历史单位保留，不自动修补旧未知单位；客户变更刷新客户 SKU，也涉及未显式编辑行。非标产品无 ProductId、使用既有确定性 SKU；草稿占位/NULL/0 数量允许，负数不允许，确认正数量必须有合法单位。已确认只开放原追踪/说明字段及行 Remark，不能改事实结构。CustomerComplaintNo 最长 100 且允许重复；LocalFileFolder 最长 1000，仅保存文本，无文件系统副作用；原串不任意规整。ServiceAmountCny NULL 未定、0 免费、正值收费；正数量确认要求相应头与引用条件。

Receive 链：SourceDemandReceptionService →既有 Source/Item 准备、Gross 写入与源版本；Cancel 链：Source 验证→MaterialDemandSourceExitService→Net 评估→SourceDeliveryService/装箱退出检查及 Outbound 相关门禁→父事务状态改变。M24 已验 SourceDeliveryQuery 三个只读方法，不包括 GetForUpdate；这里装箱退出使用 PackingListRepository.SourceExit，不可用那三个方法通过替代。CR Number 使用 DocumentNoService 和既有 PostgreSqlDocumentSequenceRepository 能力，仍需 P04 整体链与父事务验收。

审计在 Source/头行写之后，回执在审计之后；任一失败保留父回滚和提交未知分类。确认服务日志影响数非 1 用售后 LOG_WRITE_FAILED；通用审计的失败可走 InvalidOperationException/外层 Unexpected，迁移不擅自统一错误码。SQL 读取和日志前后快照不可被合并。
