## 父头锚点与联合并发边界

LockHeader WHERE uid/IsDeleted=false，锁现有有效头。LockLines 独立先 SELECT uid FROM 实际父头 WHERE uid FOR UPDATE，不按父头软删过滤，随后按源独立明细筛选 IsDeleted=false、父ID、ORDER BY uid FOR UPDATE 并完整缓冲。

父头不存在时不造假身份/临时表/表锁，也不新增异常或提前返回空集；仍按源读取孤立有效明细，但**没有集合锚点或缺失身份保护**。已有父头才可作为协作写者集合锚点；不声称 PG 行锁重现 SQL Server HOLDLOCK 的缺失行/范围锁。两个锁方法有调用方事务检查，仓储不选择隔离级别。

MAIN 实际草稿更新/删除先 RequireEditable→LockHeader，再 LockLines，然后 Save/Delete；Save 内部始终头先写行后写。Post/Reverse 也先锁头行，再调用库存持久化及状态写入。入库 Post/Reverse 先从详情发现来源，再 LockPurchaseSources，锁入库头行后重验来源/版本；源采购与库存联合协议没有下沉或被本仓储替代。另只读确认 AutomaticDocumentRepository.InsertInbound/Outbound 先 Add(header) 后遍历 Add(line)，该写者仍在 MAIN 迁移范围，不改其代码或声称全部写者验收齐备。

PG 的 ORDER BY uid 提供统一的现有 UUID 行锁顺序；SQL Server uniqueidentifier 比较与 PG uuid 的具体顺序不完全相同，未新增排序兼容框架。调用方仍保留自身原排序/校验；结果顺序兼容和交叉写者锁顺序由 MAIN 复核。RepeatableRead/Serializable 下首次读取及外层命令快照可能已建立，单纯加父头锁不能刷新旧快照或替代事务前准备，可能出现原始并发数据库错误；未降隔离、吞 40001、引入公共租约或全局表锁。
