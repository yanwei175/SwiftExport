## 四方法与原行为对照

|方法|保留行为及 PG 翻译|
|---|---|
|GetHeaderAsync|35 列固定投影，显式 CLR 别名；Uid 精确匹配、IsDeleted=FALSE；缺失返回 null。forUpdate 时对实际返回头行 FOR UPDATE。|
|GetLinesAsync|21 列固定投影；只按 HeaderId 取全部行，包含软删历史行；LineNumber 升序，其次原 SqlGuid 字节顺序。forUpdate 时先锁已有实际父头，再锁返回明细。|
|WriteHeaderAsync|固定原头列清单插入或乐观更新；借用外层事务，恰好影响一行返回 true。|
|WriteLineAsync|固定原行列清单插入或乐观更新；外层调用负责头先行后，不新增业务锁框架。|

两清单与 MAIN 原清单逐项、顺序比较完全相同：头 35、行 21。共享 PostgreSqlEntityMetadata / PostgreSqlNames 将固定 CLR 属性映射到 public 蛇形表列，SQL 引用与参数保持分离，不使用泛型 AddAsync。

插入先 StampForInsert，再令实体 Version=1，保留调用方 Uid、IsDeleted 和其他输入值。插入失败/异常不撤销已经发生的原实体打戳或版本赋值。更新先 StampForUpdate；排除 Uid、Version、CreatedDate、CreatedBy 后写剩余固定列，谓词仍为 Uid+Version，数据库 Version=Version+1；仅影响一行时令实体 Version++。更新不补 IsDeleted 条件，不把冲突改为异常，不吞底层异常；影响零行返回 false，仍保留原更新审计副作用。写入缺少事务时在打戳前抛原同文异常。

参数使用现有 PostgreSqlParameters.Entity：整数枚举和布尔遵循既有映射，NULL 保留为数据库 NULL，日期沿用共享列类型绑定（timestamp 保留墙上时间，timestamp with time zone 按既有 UTC 要求）；无新转换器。没有替换共享异常分类。

## 父头锚点及实际生产写者

MAIN 全 Application 的 WriteLineAsync 调用只发现 Maintenance 的售后写行点。五服务和审计辅助链核验如下：

|调用方|实际头行次序与事务|
|---|---|
|Query|RepeatableRead 明细读取先 RequireHeader，再 GetLines(false)；提交/清理会话由服务拥有。|
|Maintenance|BusinessCommandExecutor 的 Serializable 用例先读取/校验头并 GetLines(true)；164 行 WriteHeader 成功后，166 行逐项 WriteLine。新建时先写新头再写新行。|
|Confirmation|Serializable 执行器中 78 行 GetHeader(true)，87 行 GetLines(true)，99 行 WriteHeader；不写行。|
|Cancellation|Serializable 执行器中 63 行 GetHeader(true)，66 行 GetLines(true)，76 行 WriteHeader；不写行。|
|Lifecycle|Serializable 执行器中的 LoadForChange：145 行头锁、148 行行锁；FinishChange 的 156 行写头，不写行。|
|AfterSalesCommandAudit|Snapshot 先 GetHeader(true)，头存在才 GetLines(true)，包含审计前后快照调用。|

GetLines(true) 的新增锁查询按 Uid 锁实际父头，包含软删头；这是锁锚点而非返回资格过滤，随后仍返回原全部历史行。已有父头且生产写者遵守头先行后、使用同一外层事务时，空行集合有父头锁作为协调锚点。没有实际父头则查询无行，不创建占位头、不增加 NOT_FOUND，也不宣称锁住不存在的范围。读方法保持原无额外事务守卫的接口行为；无外层事务的 forUpdate 调用仅有各语句锁寿命，不能声称跨两语句保护。生产加锁调用当前均由外层业务事务承载；仓储不创建、提交、回滚事务。

FOR UPDATE 只锁现有元组，不能等同 SQL Server HOLDLOCK 的缺失身份/范围语义；Serializability、旧快照及业务回执仍由完整链验证。没有新增公共接口、表、会话租约、全局/表锁或重试。
