## NULL、分页、字符串与驱动冻结项

1. SQL NULL与DTO默认分开。Header及List若干字符串初始化空串，候选/行很多字符串没有初始化；Base审计字符串默认为NULL。仓库未配置SqlMapper.Settings.ApplyNullValues，需沿既定Dapper默认映射并以真实DBNull核对，不能全局改变设置或统一SQL COALESCE。Header ShipmentDate初始化DateTime.Today与默认enum也不是缺列授权；投影必须完整。
2. 普通头/行删除条件是=0，NULL删除标志不会像ISNULL(...,0)=0被包含；PG为=FALSE，不擅加COALESCE。候选当前产品/仓库同理。异常历史是否能合法制造以约束为准。
3. COUNT(*)在PG为不同数值类型，DTO TotalCount/LineCount是int；需要明确类型/溢出技术失败边界，不能扩大共享DTO为long。
4. PG LIMIT0可成功而SQL Server FETCH0失败；C#Skip/Take也不保留负分页数据库错误。非法直接仓储输入、int减1位置、可空枚举类型推断与巨页Skip须先冻结；服务验证与仓储事实分开。
5. LIKE保留本类字面转义，不套来源原始通配协议。Sku字符串排序/搜索依P03当前比较；ASCII大小写、尾空格、中文、[/%/_/~、Unicode组合形式和空白要区分验证。P03/B19广域Unicode仍开放，不能以ILIKE或全局normalize宣称等价，不自行确定公共LIKE协议。
6. 正常读方法都借用同连接/可空事务，不建新连接、启动事务或提交/回滚。源命令直接带token，仓储一般没有预取消；空GetProducts分支例外。真实取消后的Npgsql事务aborted和reader释放由主控验证，不由仓储吞错。
7. 无头详情仍缓冲第二集合，不以其他Trace冻结文件的空头协议替代。多结果中的服务端技术错误必须仍可见，不降级为null、0或空页。
8. 技术异常在仓储没有catch。OutboundServiceSupport.cs:23–48：token请求取消的OperationCanceledException重新抛；业务异常保留代码；DBConcurrencyException映射VersionConflict；SchemaMismatch映射BusinessBlocked；其他技术异常（含未匹配取消）映射OutboundErrorCodes.OutcomeUnknown。保留现用中文及类型分类，不新增收货Guard异常。
