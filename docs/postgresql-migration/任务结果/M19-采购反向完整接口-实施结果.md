## 接口与调用事实

`LockAsync` 返回完整反向事实；`LockForAssociationAsync` 先合并待选 NetDemand 来源，复用同一锁序，跳过下游历史；`ApplyAsync` 保持原取消确认、删行、作废写入。命令统一沿现有 Session 事务，缺事务仍抛“采购事实锁定需要事务。”，透传取消，不自行建立事务或改变隔离。

已核对 MAIN 原仓储、继承接口、事实模型、实体、确认/反向/补关联及 ReadSupport/CommandSupport 的真实调用。确认、反向预览使用 ReadConsistent 的 Serializable；写命令在外层 Serializable 执行器中调用事实锁。补关联传入选中需求 ID 再建立上下文。失败事实为空，服务按 ExpectedVersion 冲突处理；写入失败由父用例异常触发回滚。仓储没有承担资格校验、权限、命令回执、审计日志或自动重试。

## 锁与集合范围

1. 来源发现沿原 Link→NetDemand JOIN，加选中 NetDemand 的来源 UNION。来源 ID 保持原 .NET Guid 排序；后续 SQL ORDER BY 使用 SqlGuid 字节序，不混为同一种排序。
2. 先锁 GrossDemand，再逐来源锁全部 NetDemand，再锁需求关联的全部 Link，继而独立读取本采购的 Link（不 JOIN NetDemand），再锁采购头行，最后重读采购 Link。缺来源保持原异常；坏 NetDemand 引用返回原 CONCURRENCY_CONFLICT，不把损坏引用当独立采购。集合重验严格采用原 (Uid, Version, NetDemandId, TargetLineId) 四元组，不补锁新增来源。
3. 来源、需求、Link、采购头行均不增加软删除筛选；需求相关 Link 及本单 Link 按 Uid 去重的取值顺序保持原实现。补关联在集合重验后直接返回，无入库、库存、报告或未知收货事实读取。
4. 完整读取先查全局未归属入库标记，保留原有效头行及单据类型/过账/生命周期条件、采购行可空判定；即使本采购无行，也先完成此标记。采购行的软删除不加入该匹配条件。
5. 入库头通过关联入库行 EXISTS 读取，头及后续全部入库行不筛软删除。台账保留来源单据、来源行、冲销原台账、替代原台账四个历史分支，不增加软删除或排序。供应商报告仅原有效报告，保留采购行、Sequence 顺序及 NULLS FIRST。
6. 可空采购行侧在 LATERAL 内 FOR SHARE 实际行，外层 EXISTS 仅 FOR SHARE OF h,l；入库来源行在 EXISTS 内 FOR SHARE，入库头和全部入库行 FOR UPDATE；台账和报告 FOR SHARE。未对聚合、外连接可空侧或 EXISTS 结果直接施加非法更新锁。SQL 尚未实库解析和执行，EXISTS 可仅锁见证行，不声称锁全结果集合。

### 高隔离及联合准备仍未完成

原发现读取和采购行子查询含 SQL Server READCOMMITTED 提示。PG 在同一 Serializable 事务中不能等价取得每条语句的新提交视图，本实现明确沿现有事务读取，不暗中开新连接、降隔离或增加业务重试。锁后四元组重验仍保留，但不能证明捕获高隔离首次快照后新增的来源/Link 集合。

FOR SHARE/FOR UPDATE 只覆盖实际已有行，不能宣称等价替代 HOLDLOCK 的缺失关系、范围、新增行防护。全局未归属入库的未知历史、来源发现与来源锁之间的变化、确认/反向/补关联的准备顺序、采购与入库库存联合准备以及等待后观察一致性，均留给 MAIN 源/命令协议及原生并发验收。本文件不新增租约、公共锁、全局业务锁或框架。
