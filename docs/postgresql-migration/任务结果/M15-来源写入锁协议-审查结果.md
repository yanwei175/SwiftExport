## 最小候选协议与可实施切片

建议主控先冻结两个具体业务资源：S=(GrossDemand来源SourceType等价键,SourceUid)，U=(GrossDemand.Uid)。S只协调该来源集合，不全库；U协调该Uid存在/缺失与相关下游操作。资源命名必须与已有Command锁分域，稳定编码，不用进程GetHashCode。是否需要两类锁或可在既存实体父锁上合并，应以以下矩阵和实库证据决定。本轮不新增通用锁框架或新业务表。

| 入口 | 必须解释/参与的候选边界 |
|---|---|
| GetActiveBySource / HasActive / Receive / Cancel / ClosePending / 采购来源读取 | S即使空；集合现存行按冻结顺序读取锁定，必要时协调U。 |
| Add | 每个真实实体S+指定U先锁后INSERT；包含MD无父单、SO/CR直接仓储调用，不依赖调用者“通常先查”。 |
| GetById含不存在 / 手工改关 / 建立回退 | U即使缺失；存在行若参与S，先可信定位来源身份，再按冻结S/U顺序重新读取校验。不能先持U后临时取S与来源S→U互相倒序。 |
| 三版本命令、批量硬删/作废、VoidPending | 修改前参与对应S/U，身份定位不能漏掉将要失活/被删除行；保留原ExpectedVersion/活动/未删条件、RETURNING/影响数，不先改业务事实再补锁。 |

来源锁必须完整覆盖全部七写方法，不只GetActive。Uid缺失锁必须由Add同Uid参加；普通FOR UPDATE没有缺失行可锁。只锁S也不足解释GetById缺失范围，尤其MD无来源头和保留指定Uid原始新增。只锁Uid不能阻止空来源出现全新随机Uid。

共享前置由主控冻结：
- 比较键：Receive标准化SO/CR不等于仓储所有入口都标准化。源SQL等值可能大小写不敏感并忽略尾空格，PG varchar/当前索引、rtrim/erp_dictionary_ci的等价范围需与同一个锁键一致；“so”“SO”“SO ”不能查询同一集合却锁不同S。不要擅自对整个SourceType Trim/Upper或新增强校验，尤其NULL/空串仓储现有行为。非ASCII等价、源Uid空、SourceType NULL/SourceLineId边界另列取证，公共比较归主控。
- 锁顺序：命令租约→所需业务资源→实体/下游的统一偏序必须覆盖销售头→行→Gross、售后审计前读、手工U、批量Gross .NET Guid排序和采购后段销售头。多个S/U若在循环内边拿边发现，批次可交叉倒序；必须先收集可信作用域、排序后取锁并重新校验。源显示SqlGuid顺序与.NET Guid批次排序不是同一顺序，不用结果ORDER BY替代公共锁顺序。
- 高隔离：在Serializable/RepeatableRead事务中取得S事务锁，不保证等待后的普通SELECT取得新快照；售后Snapshot、机器回执Find可能已建立快照。既有Command事务前租约仅同CommandId，不能保护不同命令同来源。若目标要求像SQL锁式读在等待后观察最新版本，来源/U资源准备必须进入首次相关快照前的最外层编排，并处理原子释放/取消；不能仅在G方法插pg_advisory_xact_lock或偷偷降隔离。允许40001中止与“必须等待后正确业务结果”的目标由主控明示，沿现有异常分类，不吞40001或自动重试。
- 直接仓储可空事务：源允许null；运行消费者要求事务。候选advisory必须有生命周期，不能在null事务下取瞬时锁后称保护整个用例。是否明确限制新PG写仓储必须外层事务或保留直调兼容，由主控授权；不静默加TransactionRequired影响旧契约。
- token：九方法/Core没有CancellationToken，R也无token；父服务局部token检查不取消正在等锁的仓储命令。真PG等待取消要由主控批准最小接口/消费者透传或规定明确等待预算，不能以预取消测试冒充锁等待可取消。
- 路由定位：Uid输入缺失时只能锁U，不能编造S；现存身份查询后锁前变化必须锁后重读，源身份目前不可改有助简化但不自动允许脏读取。不为定位新增长期实体表。

可分三段实施，均需明确授权写入：
A. 九方法投影/RETURNING/参数与消息迁移，离线严格行为和字段验收；**保持未接DI**，不能单凭此通过并发门禁。可先做三个版本写命令和空输入路径的翻译，锁类方法/插入/退出不按现存行假设放行。
B. 主控冻结S/U编码、参与矩阵、批次偏序及高隔离准备点后，统一最小公共资源实现及九方法/真实消费者接入。优先复用DbSession、事务租约安全边界、现有参数/元数据/错误分类；Source准备支持多资源不等于复用现有单CommandLease槽冒充多锁。跨Core/Application/Material/Shipping的最小接口接入要独立授权，不由本轮自扩。共享资源文件仅一个归属窗口。
C. 先仓储真实独立连接锁等待，后最外层SO/CR/MD/Material/采购用例的状态、历史、审计和完整回执回滚验收；最后运行接线。M15材料Document/ExecutionLink可仅为真实调用链所需方法另分片，不泛化为整个模块实现。

没有现成方案可同时满足“只改九方法仓储、全部调用者零参与、Serializable等待后必得最新快照、空范围互斥”。应将共享前置显式列为待冻结，不能用表锁/全局锁、永久双库、隔离下降或重试绕过。

## 定向真实PG取证计划（本轮全部未运行）

1. 空来源双Receive：不同CommandId，同等价S、同SourceLineId及不同LineId两组；T1先完成范围锁并停在插入前，T2实际进入接收写入口须可证等待。T1提交后T2观察并进入同版本未变化/冲突或旧版本明确分支；T1回滚后T2能首次创建。不能只等两个Task最终报唯一冲突当作空范围互斥。
2. 对S保护的所有写者：T1实际GetActive锁（分别空和非空），T2分别Add、UpdateSource、UpdateManual、CloseManual、HardDelete、VoidRolledBack、VoidPending；设置合法符合谓词夹具。非同S应可进展，同S按冻结边界等待。直接Add单独验证，禁止只通过同父头的两Confirm间接证明。

5. 隔离与先快照：默认实际隔离、显式Serializable，售后before Snapshot/回执Find后另一连接提交来源改变，再来源锁读取；核实首次提交/回滚、源旧ExpectedVersion、SourceVersion和指纹冲突。冻结若要求最新权威值，必须证明准备锁发生在相关快照前；若返回40001，由原执行器分类回滚，不自动重试或当VERSION_CONFLICT。单连接自写可见不代表该场景。
6. 退出历史：同源混合无历史硬删和安全回退作废、活动Net阻断、不完整历史、有效Link/Shipping装箱草稿/正式交付/正式客户出库阻断。另一连接在Assess之后插Net/Link/交付，证明必须保护的真实写者协议；不让Gross源锁替代未迁的下游事实锁。
7. 完整原子回滚：第二Gross插入/更新失败，Net/Link/父头/源行写入失败，来源及父业务审计、回执插入失败；确认头Version、全部Gross/Net/Link/商业事实/日志/机器回执一致回滚，无部分成功。采购每来源事务的合法跨来源部分成功独立断言，不能改成全批原子。
8. 取消和失败：实际等待锁后token取消/预算耗尽/数据库异常，原事务aborted和连接失效分别按会话安全处理；外层Rollback/Dispose清Session.Transaction/资源租约，后续允许时SELECT1、新命令可用，无会话锁泄漏。接口token未接入前不得宣称该证据完成。
