## 3. DbSeed Program（默认引导）

### 参数、读取与事务

连接仅来自 SWIFTEXPORT_DBSEED_CONNECTION，无内置连接；username/passwordHash/nickname分别来自 SWIFTEXPORT_DBSEED_USERNAME、SWIFTEXPORT_DBSEED_PASSWORD_HASH、SWIFTEXPORT_DBSEED_NICKNAME。用户名/昵称可空Trim；Hash不Trim、不校验BCrypt格式、不调用PasswordPolicy或Hasher。
先读四环境变量、先校验连接缺失，再解析args。无args要求username/hash非空白；有args仅接受 --sync-permissions 或 --sync-permissions --dry-run，大小写及顺序精确、最多2参数。--dry-run单独/未知参数失败；sync路径不要求username/hash，也不创建用户。
默认连接SqlConnection OpenAsync无token；Begin Serializable SqlTransaction。所有Command同连接同事务，无外层DbSession/机器回执/业务审计日志。全部成功Commit；catch尝试Rollback，清理错误不盖原异常，再throw；顶层未映射业务码或自定义exitcode。
schema第一条SQL用OBJECT_ID验证 SysUser/SysRoles/SysUser_Roles/SysPermissionDefinitions/SysRole_Permissions五表，仅明确检查RoleCode/PermissionKey两个关键列；不DDL、不自动迁移。别把注释“当前结构”提升成源码已校验每一列。

### 原执行顺序、字段与副作用

1. PermissionCatalog.All 是权威顺序；代码重复检测 Ordinal（与sync不同）。
2. SELECT全部 PermissionKey UPDLOCK/HOLDLOCK，无删除/状态过滤；HashSet Ordinal。任何目录外键失败，包括大小写偏移，**默认引导不保留目录外键继续执行**。
3. 逐定义按PermissionKey SQL等值读取 Uid/DisplayName/GroupKey/SortOrder/IsActive/IsDeleted，UPDLOCK/HOLDLOCK。名称/分组Ordinal相等、排序=index+1、活动且未删才接受；有差异直接失败，不修正/重新启用。
4. 缺定义INSERT：Uid Guid.NewGuid、Version1、IsDeleted0、Created/UpdatedDate SYSUTCDATETIME、By DbSeed、PermissionKey/DisplayName/GroupKey/SortOrder、IsActive1。
5. 按RoleCode参数SYSTEM_ADMIN读取Uid/IsActive/IsSystem/IsDeleted锁；已有必须活动+系统+未删，否则失败。缺角色INSERT同基础审计/版本，RoleCode、RoleName“系统管理员”、Description“内置系统管理员”、Active/System均1。
6. 按UserName读取Uid/IsActive/IsDeleted锁，**无读取过滤**；命中停用/删除用户拒绝，不另建同名。不管普通账号是否可注册同名，种子只保留此原规则。
7. 已有活动用户须有此adminRole的未删SysUser_Roles关联（UPDLOCK/HOLDLOCK EXISTS），否则拒绝普通账号静默提升。通过者不改Hash、昵称、Version、CredentialVersion，不新关系；仍要求环境Hash存在，这是原入口检查。
8. 新用户INSERT同基础审计，UserName、NickName为nickName??userName（显式空昵称仍空）、环境Hash、CredentialVersion1、IsActive1；Email/Phone等未写列依原默认/null。
9. 新用户才INSERT SysUser_Roles：随机Uid、Version1、IsDeleted0、UTC审计/DbSeed、UserId/RoleId。**没有写SysRole_Permissions**；第五表只是schema必需，SYSTEM_ADMIN由消费者授权全部代码权限。
10. 最后提交并打印目录数量、用户名、既有密码未改/新账号关联的信息，不打印密码/Hash或连接。

原默认种子新增/核验是单Serializable原子事务：定义或角色先插、后发现普通账号时全部回滚，不允许迁移中分批提交。它不是重置密码或修复权限的工具；不加默认超级账号、固定Uid、明文密码或自动提升分支。

## 4. PermissionCatalogSync（仅目录模式）

- 代码重复检测 OrdinalIgnoreCase。Serializable独立连接事务；schema验证定义表/角色权限表及Uid、PermissionKey、DisplayName、GroupKey、SortOrder、IsActive、IsDeleted、PermissionId各指定列，不检查/写账号角色。
- 一次读取**全部**定义 Uid/Key/Name/Group/SortOrder，UPDLOCK/HOLDLOCK，无启停/软删过滤；Dictionary OrdinalIgnoreCase重复即失败。
- codeKeys OrdinalIgnoreCase；目录外项按Key OrdinalIgnoreCase排序，仅报告且保留，**不同于默认引导目录外拒绝**。
- 代码同键在数据库中的Key若Ordinal拼写不同直接失败，要求显式迁移；不自动改PermissionKey。
- 缺键列入insert；已有只比较Name/Group Ordinal与SortOrder=index+1，计划update。不把停用/软删记录当缺失，不重新激活。
- dry-run仍Open、Begin Serializable、schema和带更新/范围锁读取、打印计划、Commit；**不写数据但不是无连接/无锁操作**。它可能阻塞其他写者，不能当无副作用的普通命令随意运行。
- 实际insert与默认引导同基础字段：随机UID、Version1、未删、UTC审计DbSeed、代码键名/名称/分组/顺序、活动；affected必须1，否则抛原失败。
- 实际update只 SET DisplayName/GroupKey/SortOrder WHERE Uid+PermissionKey，affected必须1；**不递增Version、不更新审计、不改Key/UID/状态/软删或任何角色关联**。不借迁移“统一打戳”。
- 所有insert先执行、后所有update；提交后输出计数。所有异常尝试回滚并保留原始失败；无CancellationToken接口/额外幂等回执。

## 6. 实际身份/权限消费者与技术前置

CurrentUser读取Name→unique_name、NameIdentifier→sub；GUID解析失败null，未有Name回system，认证来自Principal。开发Claims保持四项即可，不授予SYSTEM_ADMIN。
AuthSession用户名Trim，活动仓储读取后BCrypt Verify；错误Hash按原Hasher false；/me重读活动用户+PermissionEvaluation，无效身份失败，不能单凭静态dev UID授权。
PermissionEvaluation从有效用户/角色/关联生成投影：IsAdmin获全部PermissionCatalog代码键；普通用户只获IsAssignable且Ordinal键命中的权限。目录外/大小写漂移不能偷偷授权；目录展示同步不等于给普通角色新增权限。
在线UserAccount创建需要真实Admin，创建用户无角色；本人改密验证旧密码；在线ResetNonAdmin明确拒绝Admin目标。**不能将本机恢复复用为在线重置或反过来用非Admin仓储实现恢复**。
AuthTokenFactory签发四身份Claims和CredentialVersion，12小时；CredentialVersionTokenValidator GUID/版本>0并重读账号版本；WebApiConfiguration OnTokenValidated使用RequestAborted，失败认证。
