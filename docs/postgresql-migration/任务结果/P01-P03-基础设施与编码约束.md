## 三索引变更

源 SQL Server sys.columns 只读核实：
SysUser.UserName、WarehouseSite.Code、CustomerPoConfig.CustomerCode/SupplierCode 均为 Chinese_PRC_CI_AS。
PG 原三索引为原列 btree；ICU 已有 public.erp_dictionary_ci / und-u-ks-level2，记录及实际版本均 153.128。

本批只改变：
- ux_sys_user_user_name：rtrim(user_name,' ') + 既有 ICU；
- ux_warehouse_site_code：rtrim(code,' ') + 既有 ICU；
- ux_customer_po_config_codes：两个编码各使用同一表达式，并使用 NULLS NOT DISTINCT。

三个未删除域的冲突组均为 0，事务内持表锁后重新检查。客户 PO 可空键按 SQL Server 唯一组合中 NULL 相等的语义迁移；不改变列空值、文本存储、IsActive 或软删过滤，不扩大其他唯一索引。复用既有 ICU 已确认边界，仍不完全仿真源排序的可忽略字符。

依据：[SQL Server 唯一索引规则](https://learn.microsoft.com/en-us/sql/relational-databases/indexes/create-unique-indexes?view=sql-server-2017)、[PG18 唯一索引/NULL 规则](https://www.postgresql.org/docs/18/indexes-unique.html)。

执行顺序：
1. 保存源 PG 三索引真实定义，检查 0 冲突；
2. 专用库前向 ROLLBACK 演练，采集新定义；
3. 同事务前向 → 严格回退 → ROLLBACK，验证原定义可恢复；
4. 专用库正式提交三个索引；
5. 串行真实测试、针对失败复测、前后数据摘要核对；
6. dv_next 同步同一前向脚本；
7. 两库结构一致及旧备份不变的最终只读核对。

变更和回退脚本均绑定实例/库名、ICU 版本和原索引精确定义，使用固定锁顺序和超时，不使用 CASCADE，不改数据。脚本非幂等，已应用后禁止盲目重跑。回退只恢复原 PG 定义，不用于撤销测试记录。
