## 实现与保留边界

1. 四方法各自仅一条参数化 SELECT。使用现有 `RepositoryBaseContext.Session.Connection`；允许 Transaction=null，有则原样传递；取消通过 CommandDefinition 透传。不自建连接、事务、锁、多语句批次或临时表。空 PurchaseDraftCandidateQuery 仍最先报 ArgumentNullException。
2. 九个实体表名来自 `PostgreSqlEntityMetadata`／`PostgreSqlNames` 的 public snake_case 映射，未使用 SQL Server Table 名称转 PG。实际生成 SQL 的表别名下所有引用列均经离线元数据断言；所有公共可写标量字段均有明确 CLR 大小写别名。
3. 待建立来源只排有效未删除 NetDemand；历史和删除物料不阻挡。分组按 SourceType＋SourceUid，SourceNo 取聚合，不按编号混组。类型比较／分组使用尾 ASCII 空格和冻结 ICU 规则；分组用原存储类型的 MIN 选择等价组代表，不回写原值。按来源类型＋Uid 返回完整来源，无分页或上限；日期空值最后、来源行号空值最前。
4. 采购候选保持有效来源／物料、采购 SupplyType、NetQty 大于有效采购贡献之和的原资格。贡献为 AllocatedQty−ReleasedQty；不增加正剩余筛选、Allocation、来源指纹／客户／单位完整性规则，也不新增产品或推荐供应商 IsActive 筛选。
5. 候选图仅当前物料 Product.MainImage，LinkSku 同样仅当前物料；单位仅 `btrim(unit_snapshot, ' ')` 后空串转 null，不回退来源／商品单位、不用 .NET 全 Unicode Trim。来源快照、可空来源版本和日期继续按原 DTO 输出。
6. 送达目标要求目标 Uid 同时等于 DeliveryTargetNetDemandId 和 ParentNetDemandId，并且 Gross、Root、Revision、一致有效未删除。无关系、无推荐、推荐已删除分别保留既有中文提示；推荐和父项实际采购供应商独立。
7. OUTER APPLY 改为 LEFT JOIN LATERAL；采购单号按原 DISTINCT 键去重。父项实际供应商按 SupplierId 分组，编号／名称 MAX、当前有效供应商标记、采购单号聚合及外层编号／Uid 顺序保留。局部 JSON 使用 jsonb_build_object／strip_nulls／agg，私有字符串反序列化后只返回现有结构化 DTO；空数组、省略 null 字段和布尔／UUID／文本类型保留。未规定的单号聚合顺序未新增排序契约。

文本比较使用冻结 ICU 和 ASCII 修剪范围。未证明 Unicode 全范围等价，未扩大 B10；PG UUID 排序与 SQL Server 不同的已登记边界保留，未宣称跨库逐行绝对同序。等价字符串组的存储代表、MIN/MAX 相等权重取值仍不作为字节完全一致的承诺。

## 需主控注意的约束边界

当前主仓库和本人工作树 `SwiftExport.Core/DatabaseSchema/EntitySchemaMetadata.cs` 对 Link 明确声明：TargetType=PO；AllocatedQty>0、0<=ReleasedQty<=AllocatedQty；活动 Link 必须 ReleasedQty<AllocatedQty、取消／冲销必须全释放；IsDeleted=0。PG 生成器转换这些 CHECK，不能合法构造“软删 Link”“负贡献”或“活动全释放”的历史异常夹具。

本轮未改或绕过这些共享约束。真实四场景明确验证当前约束拒绝；原查询对软删 Link 的防线、无正剩余附加条件、父项实际供应商不依据剩余量筛选由独立离线 SQL 契约保留。**不能把约束拒绝当成旧异常历史查询已实库验收。** 若主控需要证明已有脏历史读取，须另行确定隔离历史证据和授权方式，不能为了造数据禁用约束或修改共享夹具。

主控分派反馈已只读确认九表存在和列数；本人没有实库复核字段类型、CHECK 名称部署、collation、计划、查询结果或性能。真实文件按当前元数据的 snake_case 约束名断言，实际部署不一致应由主控核验，不静默放宽断言。仓储仍保留源规则，不为当前 CHECK 擅自删掉历史查询防线。
