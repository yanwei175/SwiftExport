## 7真实用例覆盖

1. 同Item跨不同Source真实互斥、独立Item/Source可通过；等待者0锁、父事务为空，释放后取得自己C/S/U。
2. 已取C_item后等S、尚无U，取消后Item零残留、holder S保持；独立目录与try-lock证据。
3. Empty与另Item反向/重复输入仍按实际key获取，等待第二Item时来源/U空；取得后4锁、重复Dispose不泄漏。
4. 持需求后取C_cmd拒绝且原资源保持；正确C_cmd→C_item→S→U可共存，父Serializable准备拒绝不破坏原事务。
5. 已取消Link和软删/回退Net仍发现原Gross及同Source关闭/软删成员；4键实保护，不作业务资格返回。
6. 等Item时合法维护同连接按原两Gross S/U准备后改Net归属；取得后重验释放旧S/U，新三键保护，未开父事务/业务重试。
7. 初始Item无行，holder同连接持C/S/U后插入合法取消Link；waiter重验发现并保护原来源与新请求资源，5键覆盖，不按新来源隔离全局身份。

6/7数据维护/插入是专项合法夹具，不是未完成PGNet/Link仓储或采购服务。真实PID/服务器try-lock目录、第三连接try-key与锁数证明争用；固定Delay只轮询，不独立充并发。未注入未知提交、断线或整发现循环超时。
