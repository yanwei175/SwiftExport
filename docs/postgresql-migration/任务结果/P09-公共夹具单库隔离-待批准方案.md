## 新库限定重置及事实保留

为保持原独立LocalDB夹具的空表计数、全库守卫及每例权限/失败注入边界，在每例结束后导出本新库全部表的UID、Version及字段事实和结构摘要到本地TestResults，记录测试名称、结果、SHA及首轮失败。导出或校验失败、还有活动连接/事务/测试任务时立即停止，不重置、不强制断开。

确认导出完成、所有该例作用域/连接已结束且没有其他客户端后，只允许重置本新库的public schema并重新执行固定50表基线。此动作会删除该新库上一例夹具数据、测试触发器/约束及重置该新库序列，保留本地事实导出和TRX；不操作任何现有数据库、备份或账号。新库本身保留，不DROP DATABASE；不会创建20个或更多持久库。

测试失败注入只在本新库创建，并随本新库例间重置清除，不同步到运行库。新库初始基线沿用现行PG结构；若发现需改变正式基线，应另按原迁移范围判断及同步，不借测试批准自动修改运行库。

## 开发与验证顺序

公共隔离夹具和SQL/异常/锁观测仅在测试项目调整，不修改生产仓储、服务规则、API、DI及应用配置。按共享夹具分批转换既有文件，统一必要编译、单轮过滤测试、单份结果；锁/事务/版本/约束使用真实PG，已有绿色实证复用。未改接PG的旧测试不开启，不把跳过标为通过。

凭据仅从已授权配置/环境在进程内读取，校验实例及库名，不打印或写入报告。批次前后只读核对现有failure/运行库的保护状态；新库身份守卫必须精确等于上述固定名称，重置代码没有其他目标或自动回退路径。
