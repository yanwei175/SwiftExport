## 二、SearchAsync：所有谓词、投影、排序和非法分页

R:16–35，一次 QueryMultipleAsync 批次含两个 SELECT：COUNT(*) + 当前页。两个语句复用同 filter 文本，不先取候选身份/冻结全列表，不采用 count window，不在 C# 计算完整列表后分页。

| 项目 | 原语义及迁移必须保留 |
|---|---|
| 主头过滤 | h.IsDeleted=0 精确条件，无 COALESCE；DocumentType 和 PostingStatus 可空时不限制，有值精确相等。不筛 CreationMode、LifecycleStatus、TriggerPackingListId、日期、仓库、采购来源/产品有效性 |
| 关键词 | null/全空白→null；非空 .NET Trim，然后依次 ~→~~、%→~%、_→~_、[→~[，外围 `%`；SQL ESCAPE '~'。仅 DocumentNo、WarehouseNameSnapshot 或本单未删行 SkuSnapshot，三者 OR；不搜 Remark、描述、仓库编码、SourceNo、BoNo、LinkSku 或当前 Product.Sku |
| 行子查询 | 关键词 EXISTS、LineCount、TotalQuantity 都限定本头及 l.IsDeleted=0；空头行Count=0，SUM通过COALESCE为0。无Product/采购 JOIN 导致扩行 |
| 摘要投影 | Uid,Version,DocumentNo,DocumentType,CreationMode,LifecycleStatus,PostingStatus,WarehouseSiteId,WarehouseNameSnapshot,ReceiptDate,Remark,LineCount,TotalQuantity。其他头审计、仓库编码、触发箱单/Command 不在列表 DTO |
| 商业量 | TotalQuantity 是本单所有有效入库行 Quantity 的 SUM，不等于采购量、净收货、余额或草稿可占用量；SQL decimal SUM 返回宽聚合精度，不擅自 cast decimal(18,4) 缩窄 |
| 日期与序 | ReceiptDate 完整值 DESC，然后 SQL Server uniqueidentifier Uid DESC；没有单号中间键、不截日期、不按 CreatedDate。PG 尾键必须保留 SourceSqlGuid 顺序，不能 PG uuid或.NET Guid替代 |
| 响应 | TotalCount读取 int；Items完整缓冲ToList；PageIndex/PageSize原请求值。超末页仍保留全TotalCount，空页不是总数0 |
| 分页计算 | `(long)(request.PageIndex - 1) * request.PageSize`：先 int 减1，再 long乘法；不是 `(long)PageIndex-1`。int.MinValue边界在通常unchecked编译下会先绕回int.MaxValue；不得“防溢出”改写为新分页业务规则 |

直接调用仓储没有夹取/默认50/页大小上限：PageSize>200仍发送，非法枚举仍作 SQL 条件可能空结果，Keyword>200仍转义发送。负 offset 或 FETCH<=0 在 SQL Server 是技术错误；null request 会在参数构造访问时报技术异常。PG LIMIT 0 可返回空页，不天然等价源 FETCH 0；不能把 PageSize<=0 改为默认值或页1。需要主控冻结保持技术失败的最小方案（如仅源非法偏移/Take门禁），不是服务层 Validation，也不应声称已证明错误发生时机/父事务状态相同。

SQL COUNT(*) 是 int，PG count 返回 bigint；应保留 DTO int边界及超范围技术失败，不能静默饱和/int绕回或改公共 DTO。本轮未实测极端行数与所有非法组合；计算、技术失败和读阶段验证要分开。

源多 SELECT 不表示 count与页永远同一个事实快照，普通 RC 下可有独立观察；保留两个 SQL 语句和读取次序，不自行新增快照事务合并。实际 SQLServer/Npgsql批次、第二语句执行与结果缓冲时机须主控定向读协议实测，不用内存注入变化冒充实库证据。

## 三、GetDetailAsync：Guard、头行及 NULL

R:39–69：先 InboundReceiptHistorySql.Guard 全局检查，再同批两个 SELECT；ReadSingleOrDefaultAsync<InboundHeaderDetailDto> 后 **无条件 ReadAsync<InboundLineDetailDto>().ToList()**，最后才看 header 是否为空。同步 using 释放 GridReader。缺头不能提前返回、跳过全局Guard/第二结果技术错误/取消或改为只按初次头状态筛行。

### 3.1 历史 Guard 的真实边界

源 InboundReceiptHistorySql:14 是全局，不是 ScopedGuard；未删DocumentType=10、PostingStatus IN(1,8)的采购正式入库，即使与目标uid无关，也会阻断详情。Search不调用此 Guard。Guard不等于 sourceRepository.HasUnprovenReceiptAsync 的来源证明门禁，普通详情不追加后者。

完整条件：正式采购头必须有有效行、行数量正数且 OriginalLineId为空；PostingStatus=1到这里即结束，不强求原库存流水。PostingStatus=8还需人工/自动CreationMode与TriggerPackingListId匹配、ReversedDate、非空反向原因、头下流水计数恰好2×有效行数、每行唯一完整原/反向对；原CommandItem=lineUid、来源类型InboundDocument、原交易人工10/11自动12、原W/P/qty/unit正确，反向900负原qty/W/P/unit对应，两者非软删且原没有反向/替代/纠错关系、反向没有替代/纠错关系；外部反向/替代引用不得指向其他头或空SourceDocumentId。全量头流水计数不排软删，不能将全局检查缩小到目标头。

可复用已有 `PostgreSqlInboundReceiptHistoryGuard.ValidateGlobalAsync(context.Session,token)`，专用 UnverifiedReceiptHistoryException 保留分类；它普通 EXISTS→C#已证明信号，不把任意RAISE/P0001猜成历史失败，也不破坏父事务。此共享helper及分类已存在，独占实现只读依赖，不修改。PG helper另一个命令后再QueryMultiple，与源Guard+两个SELECT同批的协议差异需要真实入口测试；不为合批自动新建事务/SQL函数。

### 3.2 头投影与过滤

头只按 Uid及IsDeleted=0，无其他状态/建立方式/类型过滤；因此人工、自动、已反向、非活动、其他DocumentType的未删头均可读取，动作资格另由服务判定。

完整显式投影：Uid、Version、DocumentNo、DocumentType、CreationMode、LifecycleStatus、PostingStatus、WarehouseSiteId、WarehouseCodeSnapshot、WarehouseNameSnapshot、ReceiptDate、Remark、PostedDate/By、ReversedDate/By、ReverseReason、TriggerPackingListId、CommandId、CreatedDate/By、UpdatedDate/By、IsDeleted；保持 DTO BaseDto 与本体字段，日期不取Today默认覆盖数据库值，不进行UTC换算。

## 四、源约束与比较偏差

Core/DatabaseSchema/EntitySchemaMetadata.cs:268–281：头状态CHECK允许Lifecycle 0/8/9和Posting 0/1/8；未删DocumentNo唯一、非空CommandId唯一。行LineNumber>0、Quantity>0，未删同头行号唯一、未删SourceLine普通索引。无单头产品/来源唯一约束，因此合法重复产品/采购来源行应保持统计，不按产品或SourceLine去重。LogicalReference不是数据库外键，采购/产品缺失的合法测试不需要绕过外键。

当前结构会拒绝Quantity<=0夹具，历史Guard仍保留检测旧历史的语义。可用合法正Qty+OriginalLineId、合法反向头缺日期等触发，不能关闭CHECK/append-only/唯一索引造测试。

两查询没有 SourceType 字符串谓词。源产品历史过滤和上游失效读取是当前实现事实，不能因主数据资格治理目标擅加过滤。Guard里的SourceDocumentType及Unit等值比较沿源SQL字典口径，现有helper使用rtrim+erp_dictionary_ci；LIKE的DocumentNo/WarehouseName/Sku使用源列排序规则，不应机械用ILIKE或C#OrdinalIgnoreCase冒充源SQL比较。PG18 LIKE支持非确定性排序规则，ILIKE不支持相同规则，依据[官方LIKE文档](https://www.postgresql.org/docs/current/functions-matching.html)。公共比较/B10残余差异由主控，仓储可复用已定规则但不独自冻结全面Unicode/尾空格等价。

非法分页差异须单独保留技术失败：[官方LIMIT/OFFSET](https://www.postgresql.org/docs/current/queries-limit.html)描述PG限制/偏移语义；不能把LIMIT等同源FETCH所有非法参数行为。此报告不新加业务校验规则。
