# M24 标准库存箱单实际 PG 验收

更新时间：2026-10-05 15:46 +08:00。主控独占公共文件及实库；A/B 本轮无新增派工。

## 结论与必要修改

真实宿主的标准库存箱单过账及反向已执行成功，两个物理连接同 CommandId 各一次成功/一次重放，自动出库、执行证据、回执及审计均只追加一次。修正测试查询后复用原事实，2 项真实 PG 通过；不能把复验重放称为又一次新建成功。阶段编译 0 错误/10 既有警告，72 项受影响普通测试通过；没有全量回归。

首先真实复现阻塞：PackingList 外层 Serializable 命令租约只声明父身份，AutomaticPostingPorts 的兼容审计使用既有派生子身份；GetByModuleCommandAsync 被命令锁拒绝，返回 WRITE_FAILED。两次过账均回滚，没有消耗库存序号/取号或追加执行事实。不是借机改业务锁规则。

最小修改：新增 Core 可选 ICommandRelatedTransactionPreparation；PG 日志仓储转发已有命令锁，原租约在事务开始前取得明确的子身份，统一逆序释放，未知响应隔离连接。两个 Application 箱单方法仅在既有 beforeTransaction 回调准备原 SHA256 派生身份；其他仓储、业务委托、Serializable、预览指纹、流水方向、执行证据与幂等契约保持。SqlServer 实现不具备此可选能力，原调用规则未变。不允许事务内临时追加身份，不降隔离、不自动重跑业务、不引入全局业务锁。

涉及文件：
- SwiftExport.Core/Interfaces/Commands/ICommandRelatedTransactionPreparation.cs（必要可选能力；非 DTO/API）。
- SwiftExport.Infrastructure/Data/PostgreSqlCommandLock.cs（同一现有租约准备/释放子身份）。
- SwiftExport.Infrastructure/Repositories/Auditing/PostgreSqlBusinessOperationLogRepository.cs（能力转发）。
- SwiftExport.Application/Services/Shipping/PackingLists/PackingListPostingService.Execution.cs（派生 inbound/outbound）。
- SwiftExport.Application/Services/Shipping/PackingLists/PackingListReversalService.cs（派生 reverse-outbound/reverse-inbound）。
- SwiftExport.Application.Tests/Database/PostgreSqlRuntimeWiringTests.cs、PostgreSqlCommandLockLifecycleTests.cs（针对性验证）。
没有拆分原仓储，没有修改配置、数据库结构、约束、触发器或既有有效断言。
