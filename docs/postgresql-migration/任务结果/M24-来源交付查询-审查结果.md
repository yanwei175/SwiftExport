### 27 字段与准入

投影完整保留：GrossDemandId、DemandVersion、SourceType、SourceUid、SourceNo、SourceLineId、SourceLineNumber、SourceVersion、CustomerId、CustomerCode、CustomerName、ProductId、IsNonStandard、Sku、LinkSku、CustomerSku、Description、Color、Specification、ImagePath、Unit、DemandQty、DeliveredQty、RemainingQty、LifecycleStatus、IsActive、RequiredDate。

DemandVersion 来自 g.Version；身份/来源/数量/生命周期/要求日期及商品描述单位均来自 GrossDemand 当前快照，不替换为当前 Product 的 SKU、单位或产品身份。客户 c 仅 LEFT JOIN 同 UID 且未删；c 存在才输出 g.CustomerId，客户停用不排除。产品 p 仅 LEFT JOIN 同 UID 且未删；标准来源必须 IsNonStandard=false、ProductId 非空、p 存在；非标必须 IsNonStandard=true、ProductId 为空，不依赖产品存在。没有 Product.IsActive、Customer.IsActive、Unit 非空、SourceType 白名单、采购 Link、NetDemand 或 BOM 准入。

所有方法共同排 g.IsDeleted。Search 再要求 LifecycleStatus=Active 的派生 IsActive、客户存在、RemainingQty>0；可选 SourceType 精确、CustomerId 精确、SourceNo 与 Sku 模糊条件互相 AND。Keyword OR 范围仅 SourceNo、Sku、LinkSku、CustomerSku、Description、Color 六列，不扩 Specification、Unit、客户名称。

SourceType 用 .NET IsNullOrWhiteSpace→null / Trim；三个文本模式用同规则、包 `%`，依次转义 `~`、`%`、`_`、`[`，ESCAPE '~'。文本 NULL 原样；NULL 不会命中非空 LIKE，无关键词时不额外排除。直接仓储 null request 原样失败，不借迁移增参数数量/长度限制。

Search 顺序：SourceNo ASC、SourceType ASC、ISNULL(SourceLineNumber,2147483647) ASC、GrossDemandId ASC。NULL 行号与实际 int.MaxValue 是等键，最后仍按 SQL Server uniqueidentifier（SqlGuid）尾序。Skip 原表达式 `(long)(pageIndex - 1) * pageSize`，先 int 减一再 long 乘；Take 不在仓储修正。COUNT ReadSingle<int>；极端非法直接仓储请求是技术失败边界，不替换业务错误或默默裁剪。

### 正式交付净额及全部历史边界

Delivered 是 **所有 l.GrossDemandId 分组的 SUM(l.Qty)**，只纳入 l.IsDeleted=false、h.IsDeleted=false、h.PostingStatus=Posted 且头行关联存在的行；GetForUpdate 额外限本次 Ids。无合计 COALESCE=0；RemainingQty=DemandQty-DeliveredQty，不 clamp，不要求正数，不在源投影扣当前草稿或其他草稿数量。

该定义不筛 h.LifecycleStatus，不查 PostedDate/ReversedDate、执行证据、ProductId 一致性、SourceTypeSnapshot，不扣或加 Outbound/Inbound/InventoryLedger 数量。已反向头 PostingStatus=8 后原行保留但不再计入；未过账头为0不计；多行/多箱单均合计。未关联 GrossDemandId 的草稿行可有 NULL 分组，但不会关联任何 g.Uid。缺头、删头/删行被排除。存在 Posted 但缺执行证据/库存的异常历史不会在此投影自动失败；不要扩大本查询为全局历史验证。

合法结构对 GrossDemand.DemandQty>0、PackingListLine.Qty>0 有 CHECK；负 Remaining 可由正式正 Qty 超需求构成，无需写非法负 Qty。负 Delivered 无合法夹具用例时不得拆 CHECK 或改历史来制造；负净余额可以合法验证。

## 四、GetForUpdate共同准备和锁偏序

源 Projection(true) 在 Gross、PackingListLine、PackingListHead 加 UPDLOCK/HOLDLOCK，Gross与交付行都限 Ids。这是一个优化器可重排的CTE查询，源码没有先独立完成Gross锁再完成交付行锁的物理阶段保证；调用方之前的 PackingListPostingFactsRepository.LockSources 则确实按 Gross→Net→Link 三阶段锁，然后进入箱单。源范围锁的实际粒度还取决于索引/计划，本轮无DB证据，不把源码提示当空范围已验。

PG 不可直接在 aggregate/group by 或 nullable outer join 上套 FOR UPDATE；拆明确源行、头行、相关事实行锁和净额读，但保持数字定义。现存行锁无法覆盖无Gross、无交付行、首次新增关系，Serializable也不能自动代表等待后读到了刚提交净额；首个事务快照可能早已由回执、IsSchemaReady或头读建立。

现有可复用准备事实：

- Core ISourceDemandTransactionPreparation 接收 sourceUids+grossIds；PG Gross实现事务外发现所有软删/生命周期绑定、来源成员，先 S(SourceUID) 后 U(GrossUID)，取得后重验；变化则释放后重新准备，不重跑业务写入。
- PostgreSqlSourceDemandLock 绑定原生已打开同物理Npgsql连接/epoch/PID；不允许父/环境事务内新租约、嵌套或并行来源租约；SourceType不分区，禁止按字符串哈希分不同资源；预算30s，取消传播，未确认/释放失败隔离连接。
- BusinessCommandExecutor 可选 beforeTransaction 位于命令准备后、BeginTransaction及Lock/Find回执前；事务释放后再释放租约，失败回滚，40001原分类不业务重试。M15部分来源/物料服务已调用，不能冒称M19/M21/M24全部覆盖。

**必要最小技术入口建议，仅供主控冻结：** 在 PackingList Draft ExecuteWrite、Posting ExecutePostCommand、Reverse ExecuteReverseCommand 的现有 Executor 调用处接现有 beforeTransaction 能力，以事务外已知 observed+incoming GrossIds 推给现有来源准备入口发现 SourceUID/完整成员。租约等待必须先于回执首次SQL和任何父事务快照；不能放在SourceDeliveryService.VerifyForUpdate内部补，因为该方法已经要求父事务且太晚。共同接口复用/由postingFacts提供技术转发还是注入已有Gross准备端口，由主控决定，不另建全局锁/公共框架，不把业务验证、版本校验、日志、回执、取号搬到事务外。

输入已知Gross可事务外发现绑定；关联命令还需observed现存Gross与新分配；Posting/Reverse已有事务外observed集合可复用。动态生成新Gross只允许在已覆盖的S来源下取得U，遵循既有Gross特殊新身份边界；已绑定但漏发现的Gross、来源改绑或箱单来源集合变化必须拒绝/重新准备完整计划，不能持U/箱单锁后追加S。Draft关联当前把旧数量合并在事务内，准备资源须预知覆盖旧集合，而不是提前执行业务聚合替代原验证。

M15来源建立/更新/关闭/硬删、M19 Net/Link建立释放及采购确认/反向/关联、M21库存 automatic scope、M24 Draft/Post/Reverse/SourceExit 必须共同遵守主控冻结偏序：命令资源→完整S→完整U→Net/Link→箱单及采购/单据/库存资源（后半确切顺序需联审）。M19实际采购反向会发现 Link→Gross→Net/Link→采购头行再重验集合；M21资源接口不可任意后置/追加。这里仅指出重叠和先后约束，不单方面确定箱单与采购/库存的最终全序。

对客户/产品软删停用等主数据变化还需区分原普通投影与权威资格，复用现有资格/父事实协议，不能新全局业务锁。来源S/U只能保护同样参协作的写者；独立PG读取实现不使旧SQL仓储或其他写者自动参与。
