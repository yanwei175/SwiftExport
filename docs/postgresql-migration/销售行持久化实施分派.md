## 原SQL Server语义冻结

逐方法实现原接口，继承现有PG泛型，避免重复框架。GetLines完整实体quoted投影、有效条件、line_number后源SqlGuid尾键，false不加事务，true复用既有GetLockHint要求外层事务并FOR UPDATE；不新增token接口、范围/全表锁。空返回不是范围互斥证据，销售服务默认隔离/头锁不改。

Add必须override：非空Uid保留、空Uid生成、非正Version置1、正Version保留、审计原StampForInsert、不自行事务；InsertProperties经Metadata物理列及现有Entity参数。成功/失败原销售文案/结果不变。Update继承，包括失败时实体Version预推进及OldVersion现有事实，不顺手纠正。

Stage保持两个实际命令：MAX有效行（空0）→long offset=M+N+1及offset+M>int.MaxValue门禁→UPDATE当时全部有效行号+offset返回int行数。不用旧UID数组、重新MAX、一条CTE、临时表、负号、延迟/放宽唯一键、自动重试或仓储自开事务。Stage不改Version/审计。超界在任何UPDATE前抛 **InvalidOperationException("销售订单行号暂存超出 int 范围。")**；注释说明源THROW52720。这是必要的提供者异常载体翻译，源执行器仍走Unknown/Unexpected并回滚，不伪造SqlException/SQLSTATE、不改API失败码。PG本地门禁不会自行将事务置aborted，此差异在报告明确记录；完整服务失败/回滚由主控另验。

批量Add/Update/Delete按IEnumerable顺序逐个await，普通失败继续、技术异常停止传播，不补整体原子性。DeleteLines专属有效Uid+原Version UPDATE RETURNING版本+1和Now/User打戳，原中文文案/OldVersion，不能委托泛型软删。DeleteByOrderId一次条件软删所有当前有效行、Version+1及审计，返回行数，不物理删除或混入来源退出。
