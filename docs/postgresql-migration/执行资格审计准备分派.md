## 冻结协议

认证、非法命令及已有外层事务守卫和错误码/消息/抛异常边界保持原顺序。有效命令生成本地非空服务器 CommandId，operationLogs 实现已有可选 ICommandTransactionPreparation 时，在 BeginTransaction 前用同一ID/令牌获取租约；无此接口的 SQL Server 路径仍直接开始原 Serializable。空租约抛 TimeoutException，不建事务/写业务；准备异常及取消原样传播。准备后检查取消，再开始事务。

日志使用同一 CommandId，不用可变服务字段、不增加客户端字段或重放功能。事务中仍依次授权重验→目标锁→预期版本→同状态拒绝→版本更新→日志→取消检查→提交，原成功及拒绝返回保留。任一操作异常仍向外抛原异常，不引入通用 Unexpected/VersionConflict/Forbidden 映射、降隔离或重试。

开始/业务拒绝/审计/提交失败均结束本层事务。回滚/释放的次生异常不得掩盖业务拒绝、原数据库异常或取消；事务先释放并清空 Session.Transaction，无法释放时隔离连接，再释放租约，记录清理诊断且日志失败不能遮蔽结果。准备/BeginTransaction失败同样清理本次租约，不接管其他事务。
