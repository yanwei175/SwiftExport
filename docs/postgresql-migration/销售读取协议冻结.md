主控按三份SQL Server源码、执行A的M16-REVIEW-01和真实只读协议探针冻结本文件。源码/调用方见[审查结果](任务结果/M16-销售查询与履约-审查结果.md)；当前三个查询已分别交付限定验证，全归主控独占，A/B转后续任务。冻结协议本身不等于完整业务或PG运行验收。

## 边界与必要改写

三个方法共用一个请求连接和调用方可空事务，逐条传 CancellationToken。既有 SQL Server batch 中多个 SELECT INTO/SELECT 是不同观察阶段；PG 不把整批隐式事务或单个 CTE 当作等价替换，不新开业务事务、不加生产锁、不强制提高隔离、不提交/回滚调用方事务。

候选头、行事实、头事实/过滤身份、履约行分别保留原物化时刻。PG 使用局部缓冲记录及带类型的 JSON 关系参数传递已物化内容，SQL 仍负责所有商业数量和可信性判断；C# 不重新计算交付/分摊。不存在持久/临时表、DDL、全局缓存或跨模块通用业务规则。与 M14 没有仓储调用依赖；M16 独立维护其行事实 SQL，不统一销售与物料单位规则。

这是替换 SELECT INTO 临时工作集和 Npgsql 整批隐式事务所需的基础设施重写。Application、Core 接口、DTO/API、保存/关闭调用顺序不改；未完备类只暴露已实现方法，不以占位方法或 SQL Server 委托凑接口，完整三方法后才声明接口/接DI。

## 冻结阶段

| 切片 | PG 调用顺序 | 仍重新观察的内容 |
|---|---|---|
| M16-S01 Manager | 候选头→一次行事实SQL→一次头事实汇总/过滤/count→当前头/客户页 | 候选保存Uid/Version/状态/CustomerId/OrderNo/DeliveryDate七字段；行事实完整缓冲，汇总只读取冻结关系；页再读当前真实头和客户，源页不再次限制头IsDeleted。超末页独立count不丢失 |
| M16-S02 Detail | 候选头→一次行事实SQL→当前有效头→完整缓冲当前有效行联冻结事实→空头分支/DTO | 行商业字段可以较事实更新；保留金额NULL回落单价×Qty、LineNumber和源UUID升序。已有事务自写可见，同一事务返回后仍能使用 |
| M16-S03 Fulfillment | 候选头→一次行事实SQL→当前头/客户→再次选择Gross构造并缓冲履约行→空头分支→采购→箱单历史→异常行ID→原C#组装 | 头不重加软删除；第二次选择Gross不是第一次选中实体的缓存。采购/历史/异常仍逐阶段读取当前事实，不冻结为一个万能视图 |

Detail/Fulfillment 空头采用“先完整缓冲原第二结果，再返回null”。源只读协议探针已证明第二结果元数据前的错误可见；元数据之后尾部错误可以不被空头分支观察。不在内部取消活动读取器，避免误伤PG调用方事务。只保证合法业务空结果和阶段边界，不能声称不同驱动对坏行映射、预取/取消及任意尾部异常的技术表现完全相同；完整方法仍需真PG早返/取消/复用取证。

## 保留的销售口径

- 开放待确认且无来源直接0/Qty；已确认缺可信来源为NULL/NULL；未知不能用COALESCE置零。
- 活动/作废Gross候选优先活动，再SourceVersion DESC NULLS LAST及源SqlGuid Uid ASC。ActiveCount大于0时只用其计数，否则用AllCount。Closed Gross排除；关闭销售允许单个Voided。
- 正SourceVersion可以小于头Version；只校验Fingerprint为64位大写ASCII十六进制，不重算指纹。原快照比较、NULL三值逻辑、ASCII修剪边界及原因优先级保留。B10 Unicode全字符差异仍登记，不扩大迁移为文本治理。
- 箱单净量只累加未删头行且Posted的正量；Reversed保持历史正量但不再计净量。非Posted/删除历史检查范围不能缩减。
- 超发12/10保留12/0及“超发需核实”，头总量门槛不增加ReviewCount=0。多单位只使总量未知，不自动产生需核实原因。
- 履约采购核验当前Product.Unit，空时仅根Net回落Gross单位；不能改成M14的Net.UnitSnapshot。最新反馈保留整采购行，Sequence并列按源SqlGuid Uid DESC。
- Manager字面搜索沿限定SqlLikePattern语义；状态未知枚举不自动归All；QuickView和日期边界、页默认1/20上限200不改。排序显式源NULL方向及SqlGuid尾键；商业事实选择不能采用PG默认UUID顺序。
