# 采购用例说明

核对日期：2026-10-11。当前管理、详情、准备、关联、跟进与Trace各有实际契约；本说明替代旧准备页重构及前置实施计划。

1. 物料采购从候选选择实际供应商/目标，经Preview后创建草稿；版本/指纹改变须重新读取，Preview不预留。独立采购可不关联需求，未关联量由UnlinkedQty表达。
2. 管理列表和展开行用IPurchaseOrderManagerApi；详情和草稿、确认/反向用IProcurementOrderApi；准备用IPurchaseDraftApi；跟进/报告用IPurchaseOrderProgressApi；Trace用IPurchaseOrderTraceApi。
3. 确认前含税单价须明确（零价允许），单位、实际供应商、活动贡献和金额一致。确认不选择库存仓、不读取BOM或冻结新确认组成节点。
4. 取消确认回到草稿并保留Link；删行或整单作废按服务规则释放贡献。有实际收货/下游执行时由反向预览解释阻断，不自动撤销库存。
5. 补关联只增加合法未关联容量的需求贡献；来源Uid必须是真实物料/采购身份。供应商虚拟仓候选独立查询，存在活动仓不意味着所有用途均可选。
6. 非空 BONO 跨客户和供应商在全部未软删除采购单中唯一，已确认／关闭／作废仍占号，软删除释放，空号不占。独立创建及需求转采购新建在事务中复核，并由 PostgreSQL 部分唯一索引保护并发。幂等重放及显式追加现有草稿不重新占号；不能用相同 BONO 再新建另一张需求采购，需追加时使用原显式追加流程，不自动合并。普通草稿更新不扩展 BONO 修改权限。升级步骤见 [BONO 升级说明](采购BONO唯一限制与升级说明.md)。

当前服务、权限、数量规则和页面来源见[采购地图](../.agents/references/模块能力地图/采购模块能力地图.md)、[入库地图](../.agents/references/模块能力地图/入库模块能力地图.md)、[API索引](业务API索引.md)。命令网络结果不明时保留原CommandId与请求，不能改内容/新建ID自动重发。本轮未运行客户端或采购命令。
