# PackingList 过账设计讨论记录

## 第一项：Picker 准入（已实现）

- 普通来源仍需活动 NetDemand 和未释放 DemandExecutionLink（AllocatedQty > ReleasedQty）。
- 当前售后均为供应商免费补做、直接发客户；以 GrossDemand.SourceType = ComplaintReplenishment（CR）识别，免物料需求、采购及 Link 前置条件。
- 两类来源共同要求有效、属于当前客户、待交付数量大于零。非标继续允许，不新增标准产品限制。
- 待交付数量为来源数量减有效已过账 PackingList 行数量；按 GrossDemandId 汇总，同来源可分批出现在多个箱单。草稿不计数，反过账退出有效交付。
- 前端继续扣除当前草稿有效行已选数量，扣完后不再可选。分页总数为服务端结果，本页可选数为前端扣除后的结果。
- 保留只读多选、批量关键词搜索、ImagePath；数量在草稿详情调整。后端准入在统计和分页前执行，不新增 API 或修改布局。

## 边界与后续

本项不实现过账、反过账、自动入出库或工单。供应商直发售后只记交付、不记库存是后续目标，并非已实现。

旧能力地图中统一准入及所有标准品必须有采购依据的描述，不适用于本次确定的售后例外。其余过账细节继续逐项讨论。

验收关注售后免执行关系、普通来源保留限制、共同客户与余额条件、非标、分页前过滤、交付投影、关键词参数化及图片字段；无数据库单元测试不替代真实数据库验收。
