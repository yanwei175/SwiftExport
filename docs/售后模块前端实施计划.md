## 1. 目标与边界

执行角色为 Frontend，遵循 .NET 10 WPF 工作流及 Feature 页面、CommunityToolkit MVVM、映射、页面架构、运行时安全和质量门禁技能。

完成品质管理下 AfterSalesManagerView、现有 AfterSalesDetailView 的真实 API 接入。写入 WPF 及其相关测试；共享契约问题交回第一批修复，不在页面绕过后端。不修改 EnterpriseGrid 框架或后端业务行为。

首轮不提供附件、完整交付进度、采购、库存或 PackingList 执行入口；不摆放未实现按钮。分批交付仍由 PackingList 负责。数据库不再建表，不运行迁移。

## 3. 页面实现

### F1：基础模型、服务和导航

- 按现有 Features/QualityControl/AfterSales 组织 Views、ViewModels、Models、Services，建立 Mapster 配置。
- 模型使用 partial、ObservableProperty、RelayCommand；可编辑状态用 EditModel/LineModel，不绑定 Entity，不把 Busy、选中或脏状态放 DTO。
- 简单查询可直接 Refit；保存后确认的多调用协调放 Feature Service，服务不持有可绑定状态、不弹窗、不访问控件。
- 注册 Refit、DI、导航及品质管理菜单。客户端使用稳定模块权限，不硬编码角色名，后端仍为授权权威。
- Detail 打开参数放 Models；身份 after-sales:{Uid}。新建临时身份唯一，保存后切换持久化身份；重复打开激活已存在页面，不覆盖未保存内容。

### F2：Manager

布局为筛选＋工具栏＋表格＋分页，一行一单。

筛选：关键词（单号、客户型号、AQ 型号、SKU）、客户、责任供应商、DocumentStatus、ConfirmationStatus、受理日期范围。不同明细同时命中不得重复显示单头。

默认列：售后单号、客户、受理日期、负责人、问题型号摘要、责任方摘要、单据状态、实物需求确认、人民币金额和费用未定提示。

操作：新建、打开、刷新及分页；双击打开详情。业务确认与生命周期集中 Detail，不添加批量状态操作。

金额展示使用后端已知金额与未定标记；有 NULL 金额不能显示为全部免费。不显示跨单位数量总和，不本地计算正式交付进度。

### F3：Detail

布局：顶部命令及两个独立状态；单头客户、日期、负责人和预计日期；中部问题成品／补发物料分组明细；下方当前行投诉、原因分析、处理说明和备注编辑区。

- 问题产品和实际补发物料分别选择及保存，不能自动用问题成品覆盖配件。
- AQ 为 LinkSku 快照；颜色对应 ColorId；原销售行候选按当前客户过滤，可为空。
- 数量允许空或零；负数阻断。纯投诉无补发产品也能保存。
- 单位缺失默认 Pcs，已有值保留。非标 SKU 由后端生成，不在客户端另写算法。
- 金额标签“人民币行金额”，空为待定，0 免费，正数付费；不显示单价、币种切换或汇率。
- 品质分类可空，空字典允许继续录单，不由前端伪造分类。
- 收到日期标签“退回品收到日期”，可空；不出现发回日期、运输号、运输方式或独立实际完成日期输入。

命令：保存、确认实物需求、取消确认、结案、重开、作废。使用后端允许操作能力与本地 Busy 共同控制，并显示阻断原因。

确认前先提交当前 DataGrid 编辑并本地验证，保存当前变更；保存成功后取最新 Version 调用确认。统一最外层 Busy，禁止重复点击。保存成功而确认失败时保留“已保存、未确认”的真实状态，不声称整段操作回滚。

确认后锁定客户、责任方、金额、问题产品／型号／颜色／原订单、实物要求及行结构。仅投诉描述、原因分析、处理说明、备注、退回收到日期可继续补充。确认必填责任方和金额只针对正数量行；无正数量不调用接收，提示无需确认。

取消确认输入原因，由后端检查退出；失败保持确认及锁定，成功更新版本并解锁。结案填写说明；下游未就绪只展示阻断，不在售后提供强制完成或终止按钮。重开／作废需原因，行为由后端条件决定。

### F4：运行时、错误和可访问性

- 查询可取消并使用请求身份检查，旧响应和已离开页面的响应不得回写。
- 写命令禁止并发；超时重试沿用原 CommandId。已经成功的保存与失败的后续确认分别表达。
- 本地及服务端字段错误定位到具体行和字段；首错可见，失败保留输入。
- 401/403、版本冲突、业务阻断、网络超时分别反馈；并发冲突不能自动覆盖用户编辑。
- 关闭、刷新或切换前处理未保存变更，写入中阻止误关闭；生命周期释放订阅和取消对象。
- 提供键盘操作、标签及必要 Automation 信息；沿用主题、高对比度与 DataGrid 虚拟化，不做 UI 线程同步 I/O。

## 4. 验证与完成标准

| 场景 | 验收结果 |
|---|---|
| Manager 多行命中、分页、筛选 | 单头不重复，旧查询不覆盖新查询 |
| 金额含 NULL/0/正数 | 未定和免费有明确区别，无误导合计 |
| 成品问题补配件 | 两组身份及字段独立，传输补发数量正确 |
| 零数量投诉 | 无补发物料仍可保存和结案 |
| 非标和单位 | 自动 SKU 由后端返回且重试稳定，默认 Pcs 正确 |
| 确认必填及锁定 | 正数量缺责任方／金额阻断；确认后全部指定字段只读 |
| 保存后确认 | 保存成功确认失败保留真实状态，不重复建单 |
| 取消失败、409、超时 | 不丢输入、不错误解锁、不重复提交 |
| 页签及离开 | 重复激活不覆盖编辑，未保存关闭有保护 |
| 生命周期 | 状态与确认分开；结案阻断不得在前端绕过 |
| 权限 | 无模块权限不显示入口，API 拒绝正确反馈 |

运行 WPF 构建、相关 ViewModel 单元测试、需要的 STA/WPF 绑定测试；完成真实 API 联调和人工键盘验收。测试按风险选择，不仅用源码字符串检查代替交互验证。已有失败和新增失败分别报告，不削弱断言。

第二批完成定义：两页可以维护真实售后数据、正确确认／取消确认到来源需求并执行有依据的结案操作。不宣称公共附件、完整交付进度、无采购自动入出库已经完成。
