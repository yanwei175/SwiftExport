# 销售订单查询与履约实施待办

> 2026-09-28 建立。本文用于逐项确认销售订单查询口径和实施切片；“已确定”“建议”“待确认”须分开阅读。当前只规划，不表示功能已实现。业务边界另见 [销售模块能力地图](../.agents/references/模块能力地图/销售模块能力地图.md)。

## 目标与范围

让销售人员从管理列表查到待确认、未发货、部分发货、临近交期、逾期未交、已关闭未交及需核实的订单，并能进入独立只读履约跟踪页查看需求、采购、货好和正式交付。销售查询不承担采购、装箱或库存写入。

## 已确定

- 单据生命周期仍由销售头 `Open/Closed` 表示；确认、正式交付进度和交期提醒分别展示，不新增万能订单状态。
- 临近交期提醒阈值由服务端固定为 **7 天**。本阶段不新增字典值、参数实体或管理员设置页，也不把提醒结果写回销售单据。
- 7 天按**自然日**计算，不引入工作日历或节假日扣除。销售交期查询以北京时间 `Asia/Shanghai`（UTC+8）确定“今天”，不依赖服务器部署地点或客户端时区。
- 按顺序实施：① 确定行级正式交付净额、未交量和逾期口径；② 补管理列表查询字段、服务端筛选和页面；③ 建独立只读履约跟踪页。
- 全部发完不自动关闭；已关闭且未全部交付不能显示为“全部发货”。管理列表与跟踪页不得将采购货好、PL 草稿、入库或客供件消耗当作客户正式交付。
- 已关闭订单仍保留并展示商业未交量；关闭后可继续交付量为 0。例如订购 100、正式交付 40 后关闭，显示“已发 40、商业未交 60、可继续交付 0”。关闭不把未交量改写成已发货。
- 已确认销售行缺少可信来源需求，或来源／过账历史无法核实时，已发、未交及履约状态显示“未知／需核实”；不能按零计算或显示确定的“未发货”。
- 待确认且客户交期已过的订单仍归入“待确认”，另显示“交期已过”提示；“逾期未交”快捷筛选只统计开放且已确认的订单，不将尚未生效的订单计入履约逾期。
- 销售正式交付净额统一按销售来源下有效已过账、未反向的 PackingList 行数量求和；同来源跨多个箱单累加，不另加算自动生成的出库，避免重复计数。
- 待确认销售行尚未建立来源需求时属于正常草稿，显示“已发 0、商业未交等于订购量”；已确认行缺少可信来源仍按异常口径显示“未知／需核实”。
- 整单履约进度逐活动销售行判断：各行均已发 0 为“未发货”；存在已发且仍有商业未交为“部分发货”；所有行商业未交均为 0 才是“全部发货”。任一行无法核实则整单为“未知／需核实”，不同产品或单位不得跨行抵消。
- 有效客户交期优先取销售行 `ExpectedDeliveryDate`，为空时取销售头 `DeliveryDate`；均为空显示“无交期／无法判断”，不以 ETD、ETA 或实际船期替代。
- 交期早于北京时间今天才算逾期；今天至未来第 7 个自然日（含第 7 天）为临近交期。交期当天仍属临近，次日才逾期；以上提醒仍受待确认、关闭及商业未交量准入限制。
- 正式交付净额高于销售行当前订购量时保留真实已发量，商业未交量显示 0，并标记“超发需核实”；该行和整单履约进度均为“需核实”，不显示“全部发货”。例如订购 100、已发 110 时展示已发 110、未交 0。
- 订单没有任何活动销售行时，整单履约进度显示“无有效明细／无法判断”，不进入“未发货”或“全部发货”筛选；确认命令仍阻断空明细订单。
- 管理列表订单级订购、已发、未交数量只在全部有效行单位一致且可核实时汇总；混合单位或单位未知时显示“多单位／查看明细”，以行级数量为准，不再直接跨单位求和。
- 销售行必填单位快照已由独立任务接通：标准行从所选产品单位记录，非标行录入单位，确认沿用销售行快照；用户已确认旧数据库记录完成补值。实现记录见[销售订单单位快照实施交接](销售订单单位快照实施交接.md)。
- 整单交期摘要取尚未完成行中最早的有效客户交期；相关行缺少交期时同时提示“部分行无交期”，不能仅凭已有日期宣称整单按期。
- “临近交期”“逾期未交”快捷筛选按订单命中：任一符合准入条件的活动行满足日期条件，整单进入结果；列表显示命中行数及最早命中交期。
- 已确认行的已交付或商业未交量无法核实时，该行不进入确定性的“临近交期／逾期未交”计算；列表仍显示其交期，订单进入“需核实”快捷筛选。
- 快捷筛选允许重叠：同一订单存在无法核实行和另一条可核实的逾期行时，同时进入“需核实”和“逾期未交”；逾期命中行数仅统计后者，整单履约进度仍为“未知／需核实”。
- “已关闭仍有未交”只凭至少一条可核实且商业未交量大于 0 的活动行命中；只有无法核实行时仅进入“需核实”，两类行同时存在时两个筛选都命中。
- “需核实”涵盖已确认行缺少可信来源或交付历史、来源身份或单位不一致、超发，以及无有效销售行的订单；正常待确认草稿和单纯缺少交期不算履约异常，列表展示具体原因。
- 首期已关闭快捷筛选命名为“已关闭未交”，只表达可核实的商业未交量；跨采购、货好等执行遗留待跟踪查询建立后另行定义。
- 管理列表默认显示订单号、客户、发票号 `InvoiceNo`、下单日期、单据状态、确认状态、履约进度、最早未完成交期、交期提醒、订购／已交／未交数量摘要与异常原因；其他商务和审计字段在详情页展示。当前源码虽已有 `InvoiceNo` 列，但需按此范围调整其余默认列。
- 一次只选一个快捷视图；快捷视图与客户、订单号、发票号、SKU、日期等普通条件按同时满足组合。切换快捷视图或普通条件后返回第 1 页。
- 普通“有效交期起／至”日期范围按每条活动行的 `ExpectedDeliveryDate ?? DeliveryDate` 判断，任一行落入区间则整单命中；已完成行也可用于查历史交期，此筛选与只看尚未完成行的交期摘要用途不同。
- 增加“全部发货”快捷视图：全部活动行可核实、商业未交量均为 0，且无超发；已关闭但已全部正式交付的订单仍可命中，无活动行订单不命中。
- 本批次沿用现有“多行客户型号”精确查询；不新增批量公司产品 SKU 查询。通用关键词现有的公司 SKU 模糊匹配可保留。
- 本批次普通条件保留客户代码、通用关键词、订单号、客户 PO、发票号、多行客户型号、下单日期范围、单据生命周期状态（`Open/Closed`）和确认状态；原头部“订单交期范围”改为行级“有效交期范围”。待确认、未发货、部分发货、全部发货、临近交期、逾期未交、已关闭未交、需核实分别作为快捷视图，不混成一个落库的单据状态。

## 逐项确认清单

### 1. 行级正式交付与未交量

- [x] **正式已交付量的计算口径**：已确定按销售行 Uid 找到对应销售来源需求，再汇总该来源下有效已过账、未反向的 PackingList 行数量；同一来源跨多个箱单累加，同箱单多行逐行计实际数量，自动出库不重复计。具体聚合与历史兼容仍需在实施时验收。
- [x] **无法核实的历史**：已确定，已确认销售行找不到可信来源需求，或来源／过账历史不完整时，已发、未交和履约状态均显示“未知／需核实”，不得按零计算。
- [x] **待确认且无来源**：已确定正常待确认行无 GrossDemand 时，已发为 0、商业未交等于订购量；不得把该规则套用到已确认行的缺失来源异常。
- [x] **商业未交量与关闭**：已确定显示 `max(销售行当前订购量－正式已交付量, 0)`，已关闭订单仍保留真实未交部分；未来行终止生效时另显示“终止剩余量”，不把它伪装为已发货。若已交付量超过订购量，另显示异常，不以截断后的未交量掩盖超发。
- [x] **关闭后的可继续交付量**：已确定为 0，且与商业未交量分列。开放订单仍须核对确认、来源有效性和行终止等准入；管理列表首期可先只展示商业未交量，跟踪页再显示可交付量及阻断原因。
- [x] **整单进度**：已确定依据每一活动行分别判断未发、部分发、全部发；不因不同单位的头部数量相加或某行超发抵消另一行未发而判定完成。若存在无法核实的行，整单进度显示“未知／需核实”。空行及超发异常的处理在实施验收时单独覆盖。
- [x] **超发异常**：已确定已交付量超过当前订购量时显示真实已发、商业未交 0 及“超发需核实”，行和整单履约进度为“需核实”，不得截断已发量或显示“全部发货”。来源与销售行单位或身份不一致仍须在实施时校验并作为无法核实处理。
- [x] **无活动明细**：已确定整单显示“无有效明细／无法判断”，不落入“未发货”或“全部发货”筛选；确认命令继续阻断空行订单。
- [x] **订单级数量汇总**：已确定仅全部有效行单位一致且可核实时汇总订购、已发、未交；混合单位或单位未知时显示“多单位／查看明细”，以行级数字为准。现有列表直接加总行 Qty 的做法需在管理查询切片调整。

### 2. 行级交期与 7 天提醒

- [x] **提醒计日**：已确定以自然日计算 7 天，不扣除周末或节假日。
- [x] **有效交期**：已确定取销售行 `ExpectedDeliveryDate`，为空时取销售头 `DeliveryDate`；均为空显示“无交期／无法判断”。不以 `ETD`、`ETA` 或 PL 实际船务日期代替客户交期。
- [x] **提醒业务日期**：已确定，服务端用北京时间 `Asia/Shanghai`（UTC+8）确定“今天”，不使用部署机器的本地日期或客户端日期。
- [x] **日期区间与准入**：已确定交期早于北京时间今天且仍有商业未交量为“逾期”；今天至未来第 7 个自然日（含第 7 天）且仍有商业未交量为“临近交期”；更晚为“未到提醒期”。交期当天仍属临近，次日才逾期。待确认订单仅提示“交期已过”，不进入履约逾期快捷视图；已关闭订单也不进入。
- [x] **待确认与履约逾期分开**：已确定待确认且交期已过的订单归入“待确认”并显示“交期已过”；“逾期未交”快捷视图只列开放且已确认、仍有商业未交量的订单行。已关闭但未交完由专门快捷视图提示。
- [x] **整单交期摘要**：已确定展示尚未完成行的最早有效交期；相关行全部无交期时显示“无交期”，部分行缺失时同时提示“部分行无交期”，不得显示为“按期”。
- [x] **交期快捷筛选的订单命中**：已确定以整单为返回单位，任一活动行满足“临近交期”或“逾期未交”准入与日期条件即命中；显示符合该筛选的行数与最早命中交期，避免其他行的日期掩盖风险。
- [x] **无法核实履约的交期行**：已确定该行即使交期落入逾期或未来 7 天，也不进入确定性的交期提醒筛选；列表保留交期，整单进入“需核实”快捷筛选。其他可核实行仍可触发交期筛选。
- [x] **快捷筛选重叠**：已确定同一订单可以同时进入“需核实”与由其他可核实行触发的“逾期未交”；整单进度仍为“未知／需核实”，交期命中行数仅计算实际满足条件的可核实行。
- [x] **已关闭仍有未交**：已确定至少一条活动行有可核实且大于 0 的商业未交量才命中；无法核实的行单独进入“需核实”，不得据此推断已关闭仍有未交；两类并存则两个筛选同时命中。
- [x] **“需核实”的范围**：已确定包括已确认行缺少可信来源／交付历史、来源身份或单位不一致、超发、订单无有效销售行；正常待确认草稿和仅缺少交期不纳入。列表须说明实际触发原因。
- [x] **首期已关闭筛选命名**：已确定用“已关闭未交”，只表示可核实的商业未交量；当前不以“已关闭有遗留事项”概括尚未接入的采购、货好等事实。
