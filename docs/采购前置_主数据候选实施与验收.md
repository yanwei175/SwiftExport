## 1. 本次实现与边界

新增独立采购 UI 的客户、供应商、产品候选查询，及采购管理现有 CustomerId / SupplierId 筛选所需的历史筛选项。不建设主数据管理页面，不重复最小启停命令，不改采购创建/确认规则、BOM、迁移、通用包装、WPF 或治理规则。

- 新增候选：只读，过滤停用/删除、空 Uid 和无效编码。供应商还要求非空名称；客户名称可空，符合现有采购创建/确认口径。
- 产品还须采购供给，物料类型为成品、零件或客供件；排除以既有“非标件”前缀标识的产品及虚拟/生产/外协产品。须匹配唯一启用、未删除的 Unit 字典项，返回该项规范单位；重复、缺失或空白单位不返回。
- 候选不要求 SupplierProduct 目录关系，不依赖默认供应商，不选择仓库，不读取当前 BOM 或创建任何承诺。
- 历史筛选包含未删除的启用及停用客户/供应商，不施加新增编码/名称资格；返回当前名称与 IsActive，仅按稳定 Uid 筛选。查询结果不是历史快照，不能覆盖采购详情的历史名称/编码。
- 历史筛选不恢复软删除对象，不按旧编码猜测身份；既有订单自身仍由采购查询读取快照。本阶段不修改它。
- 采购当前管理搜索无 ProductId 条件，因此不预建无人消费的历史产品筛选 API。
- 查询只提供选择时参考；选择后资料仍可能变更，创建和确认必须保留原有事务内最终校验。

## 3. 权限与错误交接

Controller 要求认证；Application 使用真实当前 UserId。数据库按有效 SysUser、未删除 SysUser_Roles 和 SysRoles 重验 Admin 或对应采购角色，权限锁保持到查询完成，不信任客户端角色或旧角色快照。本阶段不新增角色种类、权限框架或自动授权。

HTTP 分类：
- 401：由既有认证管道处理未认证。
- 403：真实用户/角色无权限，服务抛 UnauthorizedAccessException，Controller 按类型映射。
- 400：分页或关键词无效，或模型绑定无效。客户端不依赖响应正文一定同形。
- 500：查询异常，Controller 返回泛化说明并记录技术异常，不泄漏 SQL/堆栈。
- 取消：继续透传，沿既有请求取消处理，不伪装成成功空集合。

不修改 ServiceResult，不增加全局错误码框架，不解析 Message 中英文内容。Refit 消费者应按 ApiException.StatusCode 分流；后续采购错误契约若调整不得假设这里返回 HTTP 200 业务失败。
