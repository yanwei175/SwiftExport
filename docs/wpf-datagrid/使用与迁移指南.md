# 原生 DataGrid 客户端适配使用与迁移指南

## 独立项目退出（2026-10-16）

1. 删除 EnterpriseGrid 的 ProjectReference、解决方案项目条目及所有 EnterpriseGrid.IsEnabled；删除旧 Columns 命名空间。独立源码/测试项目退出，bin/obj 仅为本地构建缓存。
2. 行号及验证的 XAML 命名空间改为 `clr-namespace:SwiftExportClient.Resources.Behaviors`，不带旧 assembly。GridRowHeader 的两种显示方式保持原有语义。
3. GridColumn.Key 全部移除。主型号供应商列与采购候选供应商列通过 x:Name 原生对象引用识别；错误转换器接收 `DataGridCell.Column`，不再绑定 Key。
4. 删除普遍配置的 FieldPath。原生绑定列按 Binding.Path；仅销售单位模板列声明 `gridValidation:GridValidation.FieldPath="UnitSnapshot"`。该字段只做错误映射，不决定复制或填充。
5. 软验证当前保留 5 处：颜色、字典数据、销售明细、入库行、出库行。采购候选已有独立验证结果列，已退出无显示消费者的挂载。只挂在真实错误来源且需要提示的表格上；普通保存校验无需挂载。
6. 原生 ValidationRule/Binding 转换、页面保存校验、Ctrl+D 业务命令、编辑器 Undo 与页面放弃修改保留。移除无效软验证不会关闭 WPF 原生错误。
7. 有效行号、验证、虚拟化、原生编辑/命令/活动项测试迁入客户端 `Resources/DataGrid`；填充等测试在 `Resources/Behaviors`。只验证协调器结构的测试随类型退出。

回归证据见 [精简回归记录](精简回归记录.md)，不再运行已退休测试项目。

## 1. 迁移原则

现有页面无需替换 `DataGrid`。文本和数值列继续使用 `DataGridTextColumn`；ComboBox、CheckBox、图片和自定义编辑器统一使用 `DataGridTemplateColumn`。EnterpriseGrid 独立项目与协调器已退出，客户端仅按真实需求挂接行号、软提示或 Ctrl+D。

```xml
<DataGridTextColumn Header="SKU"
                    Binding="{Binding Sku, UpdateSourceTrigger=PropertyChanged}" />
```

GridColumn.Key/FieldPath 均删除。错误直接关联原生 DataGridColumn；View 确需识别列时使用 x:Name 引用。GridValidation.FieldPath 只为真实软验证的模板列配置，普通绑定列从 Binding.Path 推断。

## 2. 选择、原生编辑与 Excel 操作

- 固定 FullRow 页面按选中项语义绑定 SelectedItem；需要活动格所在行的页面绑定 CurrentItem，显式 Mode=TwoWay，不将二者同时双向绑定同一 VM 字段。
- CurrentItem 不承诺在集合 Reset 后清空；页面/列表的删除、重载用例负责清空或恢复活动项。需要程序化滚动时在 Loaded 后调用 ScrollIntoView。
- CurrentCell/CurrentColumn 直接使用原生属性；活动样式用 MultiBinding 和无状态 Converter 读取原生 CurrentCell。
- 不再提供 GridSelection 镜像、SelectionSnapshot 或鼠标后备同步；模板按钮直接向命令传行对象。
- 双击、F2、Enter、Tab、Shift+Tab、Esc 沿用 DataGrid/编辑器原生行为。
- GridOperations 和 Grid Undo 已退出。编辑器自身撤销保留；页面放弃修改恢复已接纳基线，不能替代为逐步 Undo，也不能直接接到 Ctrl+Z。
- Ctrl+D 由客户端薄行为和页面命令接管，仅 Cell/CellOrRowHeader 的连续矩形选区可用；固定 FullRow 页不新增填充入口。
- 行为先提交原生单元格和行编辑，转换失败保持输入。业务许可、关联 Id/名称等完整回填由页面处理；主图标志、图片地址、排序号、唯一编码和操作列禁止填充。
- Ctrl+C 使用原生 DataGrid；Grid 级 Ctrl+V、Delete 清空和 TSV 管线已退出。编辑器内复制、粘贴、Delete、Undo 保持原生。宿主设置 CanUserDeleteRows=False，关联对象继续走已有清空命令。

需要行勾选和表头全选时，页面直接使用原生 `DataGridTemplateColumn`：HeaderTemplate 内放置绑定列表全选状态的 CheckBox，CellTemplate 内放置绑定行选择状态的 CheckBox，两者按页面需要直接设置对齐。该方式不约定 IsChecked/IsAllChecked 属性名，也不建立会参与测量的 Border、Viewbox、Padding 或 Margin 包装。列应显式设置 `CanUserSort=False`；Item Binding 使用 TwoWay 与 PropertyChanged，Header Binding 使用 TwoWay。

客户管理页已试点批量勾选右键菜单：勾选、取消勾选、反选选区内行，以及全选/清空当前筛选结果（仅当前已加载页）。原生整行选区读取 SelectedItems，格选区读取 SelectedCells.Item 并去重；空选区不补当前行。菜单打开时由页面 code-behind 读取本次选区，关闭后释放参数，不新增共享选择行为或持续同步状态。页面命令复用 Customers.SuppressListEvents，只修改 IsChecked，并在执行时检查 Busy、当前视图及行归属；隐藏行、换页前快照和外来行不写入，不加载其他页。勾选属于 UI 状态，不制造保存变更，也不扩展为主图、启用等业务字段的通用写入。编辑器继续使用原生文本菜单，原有表头全选仍操作本页列表；菜单“筛选结果”按当前集合视图限制范围。此次仅接入客户管理页，不自动注入其他表格、不引入 DataGridExtensions。


业务页面禁止使用原生 `DataGridComboBoxColumn` 和 `DataGridCheckBoxColumn`。ComboBox 与 CheckBox 必须放进 `DataGridTemplateColumn`；文本、数字仍优先使用 `DataGridTextColumn`，视觉通过 `ElementStyle/EditingElementStyle` 调整。模板列参与字段验证时显式设置 GridValidation.FieldPath；填充独立声明客户端 Field，不扫描可视控件。

`GridRowHeader.ShowRowNumber=True` 使用当前 DataGrid 视图顺序显示一基行号，不读取或写入业务 RowIndex，也不会修改宿主的 `RowHeaderWidth`。客户端命名样式默认使用紧凑的 32 DIP，页面可显式覆盖；排序、筛选、增删和虚拟化回收后会重新编号。自定义 RowHeaderTemplate 时必须让 `DataGridRowHeader.HorizontalContentAlignment=Stretch`，否则模板只按最小内容宽度布局，即使 RowHeaderWidth 足够，多位数也会被裁剪。

### 2.1 视图行号与业务行重排

需要保留 WPF-UI 默认 RowHeader 外观时，可改用独立行号列：

```xml
<DataGrid xmlns:gridCore="clr-namespace:SwiftExportClient.Resources.Behaviors"
          gridCore:GridRowHeader.ShowRowNumberInColumn="True" />
```

`ShowRowNumberInColumn` 默认 false；启用后在最前方插入标题为“行号”的普通只读文本列，初始宽度 48 DIP，数字右对齐，可拖动调整列宽，禁止该列排序和拖动换位，不参与填充。它沿用宿主单元格和列头主题，不改写 RowHeaderStyle、RowHeaderTemplate 或 RowHeaderWidth，也不写业务字段。排序、筛选及容器回收后复用当前视图的一基行号。与 `ShowRowNumber` 同时开启时列模式优先，RowHeader 恢复原内容；关闭列模式后按 `ShowRowNumber` 设置恢复。关闭功能或卸载时只移除适配自己的列。页面原有业务“序号”列不会被自动删除。

业务行上下移按钮列已经移除。重排使用客户端共享 `RowDragReorder`；Grid 保留表头排序、列顺序、视图行号和其他单元格操作，不引用 Gong 或业务模型。

```xml
<DataGrid ItemsSource="{Binding Lines.Items}"
          CanUserSortColumns="False"
          rowDrag:RowDragReorder.IsEnabled="{Binding CanReorder}"
          rowDrag:RowDragReorder.MoveCommand="{Binding ReorderLineCommand}" />
```

`rowDrag` 指向客户端 `SwiftExportClient.Resources.Behaviors` 命名空间。页面声明行首手柄列，并在手柄上设置 `rowDrag:RowDragReorder.IsHandle="True"`。共享行为只发送 `RowReorderRequest`，由 ViewModel 解析业务目标并调用 `Lines.Move()`，再维护 LineNumber 或 SortNo；原有保存和撤销基线继续生效。

具体接线、权限、键盘、编辑提交和箱单分组边界见 [WPF 行拖拽重排 Skill](../../.codex/skills/wpf-dotnet10-design/wpf-row-drag-reorder/SKILL.md)。普通表格禁止在筛选、排序或分组视图重排；箱单只对既有包装分组开放业务适配，整组仍使用工具栏按钮。

### 2.2 客户端向下填充与页面业务命令

删除旧 GridOperations.IsEnabled 及 Operations 命名空间；删除 FillDownFieldPaths、CanFillDown、CanFillDownPath。不把这些字段列表搬进另一个反射写入器。

```xml
<DataGrid xmlns:i="http://schemas.microsoft.com/xaml/behaviors"
          xmlns:fill="clr-namespace:SwiftExportClient.Resources.Behaviors"
          ItemsSource="{Binding Rows}" SelectionMode="Extended"
          SelectionUnit="CellOrRowHeader" CanUserDeleteRows="False">
    <i:Interaction.Behaviors>
        <fill:DataGridFillDownBehavior Command="{Binding FillDownCommand}" />
    </i:Interaction.Behaviors>
    <DataGrid.Columns>
        <DataGridTemplateColumn Header="供应商"
            ClipboardContentBinding="{Binding SupplierName, Mode=OneWay}"
            fill:DataGridFillDownBehavior.Field="SupplierId">
            <!-- 保留原有显示模板和 Lookup 编辑模板 -->
        </DataGridTemplateColumn>
    </DataGrid.Columns>
</DataGrid>
```

- Field 为空默认禁止填充，不从原生 Binding 或 GridValidation.FieldPath 推断。Field 是业务键，不是反射路径。
- 行为按视图顺序构造 FillDownRequest(Source, Targets, Fields)，过滤隐藏、只读及未开放列；不写字段、不维护历史、不改变活动项和焦点。
- ViewModel 的 CanExecute 与执行方法均检查页面许可、Busy、有效行归属和字段白名单；目标行许可每次执行读取。直接调用 VM 命令也不能绕过。
- 普通字段显式强类型赋值；供应商等复合关系调用与 Lookup 确认相同的业务方法，完整维护 Id、编码、名称及联动事实。采购候选供应商通过选择对象更新，沿既有事件同步锚定子件的送达事实。
- 主图标志、图片地址、唯一编码、排序号及按钮列不开放。销售单位仅填充非标目标行；失效采购候选、只读/删除行不写入。
- 中性产品价格填充采用固定业务顺序：先采购价、汇率、利润率，再应用显式选中的美元售价（包含 null）。未选售价则保持自动计算；列重排不得改变结果。普通后续编辑仍触发重算，放弃修改恢复已接纳基线。
- 不使用 SuppressChangeTracking 接纳用户修改；已继承 BaseLineModel 的页面保留脏状态和原有 RejectChanges。它恢复最近 Load/AcceptChanges 的基线，不会逐步撤销 A→B→C；不继承该基类的候选页面不自动获得恢复功能。
- 不参与行基线的派生展示字段需按恢复后的身份重新解析。例如主型号的系列名称在页面放弃修改后从当前系列缓存重建，不保留填充前后身份不一致的名称。
- Loaded 注册 Ctrl+D，Unloaded/Detach 移除自身绑定，重载不重复。没有 Copy/Paste/Delete/Undo 绑定，不依赖 EnterpriseGrid.IsEnabled。

当前接入 12 个原有 Cell/CellOrRowHeader 可用表格。固定 FullRow 的入库、出库、采购详情及独立中性产品管理页只退出 Grid Undo，不额外增加填充能力。DataGridExtensions 本次不引入。

颜色页和销售订单页原有 Grid 撤销按钮已移除；页面已有放弃修改命令继续保留。其他宿主迁移时同时检查工具栏 `ApplicationCommands.Undo`、旧操作开关及历史提示，不能只删除命令实现而留下失效入口。

## 3. 验证与业务行状态

`GridValidation` 仅汇总当前五处使用的 `IDataErrorInfo` 模型软错误；原生转换、ValidationRule 和 BindingGroup 错误由 WPF 及共享样式直接处理，不再订阅 Validation.Error 或二次聚合。业务错误通过 `GridCellValidationState` 显示细边框和 Tooltip，不使用 `ValidatesOnDataErrors` 阻止用户离开 Cell；保存命令再执行硬校验。强类型转换失败仍由 WPF 原生提交事务处理。入出库数量绑定删除无消费者的 NotifyOnValidationError=True，原生 Validation.HasError、ToolTip 和提交阻断不受影响。错误引用只包含 Item、原生 DataGridColumn 和文本，不缓存虚拟化 Cell。

软验证观察 IDataErrorInfo 模型的 PropertyChanged；适配层没有实际消费者的 INotifyDataErrorInfo 分支已退出。采购候选模型自身的错误及业务通知保留，验证结果列直接绑定 ValidationDisplayMessage，保存/预览门禁不依赖 Grid。连续通知合并为一次 Dispatcher 刷新，后台错误通知回到 UI 线程读取，卸载/关闭取消待刷新并解绑，重载读取当前源。Errors/ErrorCount 是异步更新的模型软错误快照，不包含原生编辑器错误、不承诺展示顺序，也不能作为保存校验结果。颜色页计数仍表示模型错误数；其他页面的保存校验保持原有调用。

业务 Added/Modified/Deleted/Unchanged 仍由业务 Model 拥有。客户端使用 Trigger、Converter 或 Selector，把它映射到客户端 Resources/Behaviors 下 `GridRowPresentation` 的 MarkerBrush 画刷和 MarkerText 可访问文本；无模板读取方的 MarkerGlyph 及 Setter 已删除。框架没有 `GridRowState`。

当前 SwiftExport 的删除逻辑会把 Deleted 行移出可见 `Items`；是否保留墓碑行或提供撤销面板是业务列表决策，Grid 不伪造已移除数据。

## 4. 原生数字列和模板编辑器

NumericDataGridColumn、LookupDataGridColumn 及其编辑器/Provider 已退出。数字使用 DataGridTextColumn 与 Binding.ValidationRules；客户 PO 默认折扣率使用 Feature 内 DiscountRateValidationRule，保留空值、非负及最多六位小数；可空数字 Binding 显式设置 TargetNullValue=""，让清空文本提交为 null，保存校验仍在行模型。

枚举、复选框、Lookup 使用 DataGridTemplateColumn。静态候选使用稳定资源；已有 LookupTextBox 等编辑器由宿主提供，复杂编辑器放入 CellEditingTemplate，显示态只放轻量内容。候选初始化、卸载及重建不得清空业务值，不将 API 查询移入列。

当前客户字典列直接在 CellTemplate 内使用 ComboBox，不要求另建 TextBlock 显示态。产品分类筛选使用现有 ProductCategoryMutiSelectButton；行内分类随主型号带出并只读显示，不恢复旧单选分类 Lookup。销售表头的币种、付款方式、贸易术语、承运方式通过 Text 保存代码快照；现有 ComboBox 设置 IsEditable=True、IsReadOnly=True，让候选外历史代码可见并禁止自由文本录入，选择候选后才更新对应字段。

### 4.1 直接读取原生选区

DataGridSelectionBehavior 无业务调用，现已删除实现与专属测试，无需替代挂载。原生 DataGrid 已有 SelectedItems/SelectedCells；命令执行时读取集合即可，不维护持续同步快照。Microsoft.Xaml.Behaviors.Wpf 继续用于现有 Ctrl+D 等行为。

Cell 的 SelectedItems 为空，CellOrRowHeader 的 SelectedItems 只含完整行选择；需要格子涉及的行时从 SelectedCells.Item 去重。

~~~xml
<DataGrid x:Name="LinesGrid" ItemsSource="{Binding Rows}"
          SelectionMode="Extended" SelectionUnit="CellOrRowHeader" />
<Button Content="处理选中格"
        Command="{Binding ProcessSelectedCellsCommand}"
        CommandParameter="{Binding SelectedCells, ElementName=LinesGrid}" />
~~~

整行命令将路径改为 SelectedItems。参数是原生实时集合，不是快照；命令执行时读取，需要跨 await 使用时先复制本次数据。集合内容变化不等于 CommandParameter 引用变化；CanExecute 若依赖选区数量，按页面现有事件到命令机制刷新可用性。

## 5. 已退出的筛选与分组封装

Filtering 的描述模型、FilterRow、远程命令桥接均因没有业务入口退出。页面本地筛选、排序、分组直接使用 ICollectionView / CollectionViewSource；远程查询由页面已有查询条件与命令负责。应用视图变化前处理原生编辑提交失败，不丢弃编辑值。

## 6. 已退出的布局封装

GridLayout、GridLayoutManager、GridColumnChooser 和布局 DTO 已退出。列宽、显隐、顺序与冻结直接使用原生 Width、Visibility、DisplayIndex、FrozenColumnCount。当前没有跨会话布局保存业务入口，不预建持久化模型或版本兼容层。

## 7. 已退出的 Grid 导出

GridExport、CSV/XLSX Provider、导出模型与 IGridValueAccessor 已退出；DataGrid 本身不提供 Excel 文件导出。业务导出由客户端已有文件服务和具体用例负责，明确字段、权限、范围和格式，不从可视树提取数据。CanFilter、CanExport、ExportHeader、ValueAccessor 随所属功能退出；不得继续在页面列上声明。

## 8. 虚拟化与性能

GridVirtualization 已退出。客户端命名样式 SwiftExportDataGrid 直接设置以下原生属性；页面使用该样式即可，不需要 EnterpriseGrid.IsEnabled：

- `EnableRowVirtualization=True`
- `EnableColumnVirtualization=True`
- `VirtualizingPanel.IsVirtualizing=True`
- `VirtualizingPanel.VirtualizationMode=Recycling`
- `ScrollViewer.CanContentScroll=True`

框架不缓存 Row/Cell 容器。WPF Recycling 可能让已回收 Cell 暂留在内部视觉 Children 中，但它们不属于 realized 视口；不要用“可视树节点总数”作为列虚拟化指标。

这是 UI 虚拟化，不是数据虚拟化。十万级远程数据仍应由业务查询实现分页/增量加载；Grid 不复制或自动分页业务集合。

## 9. 生命周期与线程

- DataGrid、附加属性及选择命令必须在所属 Dispatcher 调用。
- 不再有协调器。行号和软验证各自管理 Loaded/Unloaded，卸载释放运行期订阅和自身呈现，重载读取最新数据源；关闭移除整个适配。Ctrl+D 行为独立管理自己的命令绑定。
- 客户端多选 Behavior 独立管理 Loaded/Unloaded/Detach，不需要协调器；所有表格都删除 EnterpriseGrid.IsEnabled。
- Grid 不接管宿主 ICollectionView.Filter，不恢复或覆盖页面的原生虚拟化属性。

## 10. 版本兼容与迁移清单

独立项目已退出；以下是从旧 EnterpriseGrid 迁出的破坏性清单，不保留兼容空壳。迁移顺序：

1. GridSelection 镜像改原生 CurrentItem / SelectedItem / CurrentCell；删除点击同步配置。GridCellReference 随 Operations 删除。
2. 删除无调用的选择桥接；选区由命令参数直接读取原生 SelectedItems/SelectedCells。
3. Numeric/Lookup 自定义列改原生文本列或模板；数字约束使用 Binding 验证。
4. 移除 Filtering、Layout、Exporting 相关调用与命名空间；同时删除 GridColumn.Key/FieldPath；只为真实模板软验证保留客户端 GridValidation.FieldPath。
5. 删除 GridVirtualization 配置，使用客户端 SwiftExportDataGrid 原生虚拟化设置；不使用该样式的宿主自行声明相同原生属性。
6. 三个选择转换器迁至 SwiftExportClient.Resources.Converters；GridRowPresentation 迁至 SwiftExportClient.Resources.Behaviors。它们的测试随类型迁到客户端。
7. GridOperations 及全部 Grid Undo 已退出；保留编辑器 Undo 和页面已有放弃修改命令。GridValidation.HasErrors、FirstError、FocusFirstError 已退出；消费 Errors / ErrorCount，软提示仍使用 CellState / RowState。保存校验继续由业务模型与命令负责。

## 11. 原生复制与粘贴、清空退出迁移

当前决策：Ctrl+C 完全交给原生 DataGrid；退出 Grid 级 Ctrl+V 和 Delete 清空。之前为 Grid 内多行备注往返保留的 TSV 管线不再适用，已连同复制字段反射、矩形准入、粘贴类型转换和清空默认值推断一起移除。Ctrl+D 迁到客户端业务命令，Grid 提交撤销退出，编辑器 Undo 和已有业务清空命令保留。

1. 复制不需要开启框架或客户端填充行为。原生支持整行、不连续选区，遵循视图顺序、列 DisplayIndex、隐藏列及 ClipboardCopyMode；不连续选区内的未选格按原生规则留空，不表示粘贴时会跳过目标格。
2. 绑定列默认使用 Binding；模板数据列必须显式声明 ClipboardContentBinding，使用业务展示字段，不能把 FieldPath 中的关联 ID 当显示文本输出。ClipboardContentBinding 只控制复制，不改变编辑或客户端填充的业务字段。
3. 图片、按钮、拖拽手柄及编辑状态标记列保持空白；数值、日期、勾选使用原生值，StringFormat 不保证剪贴板格式。不新增通用转换器或剪贴板重写行为。
4. Grid 级 Paste 不再批量写模型；进入编辑器后，粘贴仍沿原生编辑、绑定和校验流程处理。关联对象通过已有 Lookup 提交/清空命令维护 ID、编码和名称，不能仅清显示文本。
5. 保持 CanUserDeleteRows=False；原生 Delete 是删行，编辑器内 Delete 是删字符，均不替代业务关联对象清空。框架不安装全局按键吞噬逻辑。
6. 退出粘贴和清空专用测试，保留客户端填充、原生编辑器 Undo 和页面基线恢复断言；补原生命令路由和真实模板列取值测试。外部 Excel 对多行内容的粘贴效果需按目标应用验证，不将原生文本宣称为带引号 TSV。

```xml
<DataGrid ClipboardCopyMode="ExcludeHeader" CanUserDeleteRows="False">
    <DataGrid.Columns>
        <DataGridTemplateColumn Header="供应商"
            ClipboardContentBinding="{Binding SupplierName, Mode=OneWay}">
            <!-- 原有 CellTemplate / CellEditingTemplate 保留 -->
        </DataGridTemplateColumn>
    </DataGrid.Columns>
</DataGrid>
```

原生输出 Text、UnicodeText、CSV、HTML；纯文本中的换行沿用 WPF 规则，不再提供 Grid 内复制粘贴往返保证。实现参考：[DataGrid](https://source.dot.net/PresentationFramework/System/Windows/Controls/DataGrid.cs.html)。

## 12. 活动样式与容器生命周期

客户端 SwiftExportDataGrid 样式将 DataGridPresentation.Owner 设置为自身，行和单元格继承这个引用，通过 Self 路径直接读取 Owner.CurrentCell。容器未挂载时 Owner 为空，不再执行 FindAncestor，避免创建、回收或卸载期间的绑定警告。该附加属性仅提供样式宿主引用，没有事件订阅、选择镜像或容器缓存；无需在业务页面单独挂接。活动格、活动行和验证优先级继续由原生 CurrentCell 与无状态转换器决定。
