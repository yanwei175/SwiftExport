# 采购工作台与详情原位重构实施与验收

## 实施范围

本轮在既有 `PurchaseOrderManagerView` 与 `PurchaseOrderDetailView` 原位重构，没有新增另一套 Manager 或 Detail。管理页继续采用工具栏、筛选区、采购头主表、采购行从表、分页与底部状态的操作骨架；详情继续采用顶部命令区、头部资料卡、采购行页签、确认绑定页签和底部状态区。

新链是默认数据范围。历史旧链通过同一工作台的“历史旧链（只读）”范围单独分页和打开，不与新链结果合并。兼容投影只统一列表显示字段；旧宽 DTO 不进入新链编辑模型，也不生成新链保存、确认或取消确认命令。

## 页面职责

### 采购订单工作台

- 读取当前用户新采购能力。
- 在“独立采购新链”和“历史旧链（只读）”之间显式切换，各自独立查询和分页。
- 维持采购头、采购行主从查看与右侧快速查看习惯。
- 提供独立创建、净需求 Preview、详情、追踪摘要、历史追踪和采购跟进入口。
- 不执行保存、确认、取消确认或供应商进度写入。

### 采购订单详情

- 新建模式收集客户归属、实际供应商、产品、数量、基础单位来源和收货目标。
- 已保存新链订单只编辑商务白名单：备注、包装要求、价格、交期、供应商型号、描述和行备注。
- 确认前读取当前 BOM 上下文，为每个客供件完整路径绑定消耗仓库，再冻结确认快照。
- 对无下游事实的已确认订单执行取消确认，历史确认快照保留。
- 历史旧链只读加载；不把旧宽 DTO 转成新链命令。

## 原测试语义迁移

两份既有测试文件均保留，并迁移以下已经被能力地图废弃的断言：

| 原断言 | 迁移原因 | 新断言 |
|---|---|---|
| 工作台保存、确认、取消确认命令 | PROC-004 要求工作台只管理和导航 | 断言工作台不存在这些写命令，详情存在新链专用命令 |
| 工作台供应商进度写入及安排筛选 | 跟进写入属于独立跟进页 | 断言采购跟进路由保留，工作台不含进度命令 |
| 旧宽 DTO 直接作为工作台选中项和编辑行 | 禁止沿用宽 DTO | 断言统一只读投影无来源/进度/命令字段 |
| 详情旧包装大模型全部可编辑 | 新详情仅允许商务白名单 | 断言固定身份只读、商务字段可保存、BOM 消耗绑定独立 |
| 单一旧链分页 | 新旧链不能混合分页语义 | 断言显式数据范围及稳定 `IsLegacy` 打开请求 |

保留的有效测试职责包括：工作台主从选择、稳定文档身份、分页、快速查看、页面布局骨架、跟进与 Preview 入口、详情未保存保护、确认/取消确认显式命令和历史数据可发现性。

## 后端取消确认

取消确认复用 `Procurement.Order.Confirm` 权限能力，但使用独立幂等操作名 `CancelConfirmation`。Application 在串行化事务中锁定订单、行及下游事实；存在入库或库存事实时拒绝。成功后恢复待确认、清除活动确认引用及确认人/时间，采购确认行与节点快照不删除。原因随窄命令写入业务操作日志。

## Detail 布局恢复纠正

用户确认常规采购详情的大部分展示字段仍有业务价值，因此 Detail 以 HEAD 原页面为视觉基线恢复，窄命令契约只约束写入边界，不再作为删减页面展示字段的理由。

### 恢复区域

- 顶部恢复单号、状态以及保存草稿、确认、取消确认、追踪摘要、导出、刷新、关闭的常规单据命令排列；创建模式在相同区域显示创建按钮。
- 第一状态卡恢复系统单号、来源单号、确认/生命周期、预计交期、确认人、确认时间、复核人和取消确认原因。
- 头部资料卡恢复客户 PO、内部采购单号、业务员、跟单员、进水管、起泡器、托盘、内盒、标贴、说明书、外箱、Logo、折扣备注和采购文件夹等原位置；客户归属、实际供应商、日期、币种、备注和包装要求使用新 API 真实数据。
- 采购行恢复图片、客户型号、SKU、关联型号、供应商型号、中文描述、表面处理、配置、物料类型、供货方式、数量、未收货、已备好、安排和跟进摘要、价格金额、交期、送达供应商、来源与备注列；补充新链基础单位和收货目标列。
- 恢复来源贡献、入库记录占位、业务操作记录、底部金额/箱数/体积/入库/出货与创建更新审计状态。
- 客供件 BOM 消耗仓绑定保留为“确认消耗绑定”附加页签，不改变常规采购行的主视觉。

### 保留的完整页面模型字段

头部继续保留 `CustomerPoNo`、`BoNo`、`SalesPerson`、`PurchasePerson`、`InletHoseType`、`AeratorType`、`PalletType`、`BoxType`、`LabelType`、`InstructionManualType`、`CartonType`、`LogoType`、`DiscountRemark`、`ReviewedBy`、`PurchaseOrderFolder`、确认与审计字段、金额/箱数/体积/入库/出货摘要。

行继续保留 `MainImage`、`CustomerSku`、`LinkSku`、`FinishZh`、`FeaturesZh`、`MaterialType`、`SupplyType`、`RecQty`、`LinkedQty`、`Contributions`、`ProgressHistory` 以及商务字段，并增加 `UnitSnapshot` 与 `WarehouseName` 接纳新链真实快照。

### 新 API 到窄命令映射

完整 `PurchaseOrderHeaderEditorModel` 和 `PurchaseOrderLineEditorModel` 负责页面展示与编辑状态。新链保存仍由 ViewModel 显式选择 `Remark`、`PackagingRequirements`、`UnitPrice`、`TaxPrice`、`PlannedDeliveryDate`、`SupplierSku`、`DescriptionZh`、`SubNote` 映射到 `SaveProcurementOrderCommand`；创建、确认和取消确认同样显式构造各自命令。旧详情 DTO 只用于历史只读加载，不参与新命令。

### 详情字段 API 补齐与剩余缺口

`ProcurementOrderDetailDto` 已补采购头实体真实字段：执行模式、来源类别、内部采购号、客户 PO、来源身份、人员、分类包装、Logo、复核人、采购文件夹、折扣备注、预计/回复日期、确认人时和创建更新审计。`ProcurementOrderLineDto` 已补采购行实体真实字段：客户/关联型号、表面处理、配置、物料/供货方式、送达 Allocation、行来源身份和审计字段。Infrastructure 查询直接选择对应 `PurchaseOrderHead` / `PurchaseOrderLine` 列，不以默认值制造事实。

详情只新增 `ProcurementOrderProgressSummaryDto`，通过 `SupplierProgressReport` 按 Sequence 读取最新一条摘要；不返回完整跟进历史。来源/需求关联对独立采购可为空，实体来源字段真实显示，完整 Link 贡献仍归 Trace。图片不属于采购行实体且新查询没有权威来源，当前保留列为空。入库/出货、箱数和体积仍没有详情专用摘要 API，底部明确显示“新 API 尚未提供”。

### 最终采购行 TabItem

- `独立采购创建`：仅创建模式显示，使用产品和仓库候选建立新行。
- `采购行`：完整常规行查看与商务白名单编辑。
- `确认消耗绑定`：只服务确认上下文与客供件 BOM 路径消耗仓选择。
- `来源/需求关联`：只读显示实体来源；旧链继续显示真实贡献，独立采购允许为空。
- `供应商跟进摘要`：只读最新摘要；完整写入和纠错仍进入采购订单跟进页。

删除原空壳 `入库记录` Tab，因为采购详情禁止登记或过账且当前无真实摘要契约。删除详情内 `业务操作记录` Tab，因为完整操作/Trace 属于专用 Trace 页面；详情不复制全链聚合。完整入库摘要与完整 Trace 推迟到对应能力切片。

### Detail API 字段与数据来源矩阵

本次没有新增 GET 路由，扩展既有 `GET /api/procurement/orders/{uid}` 的专用详情响应。

| DTO 字段组 | SQL / 实体来源 | 页面用途 |
|---|---|---|
| `OriginKind` | `PurchaseOrderHead` | 采购单业务来源类别只读标识 |
| `BoNo/CustomerPoNo` | `PurchaseOrderHead` | 原常规单据编号区 |
| `DemandSourceType/Uid/No/ExecutionRequestId` | `PurchaseOrderHead` | 来源/需求关联只读身份 |
| 人员、分类包装、Logo、复核、文件夹、折扣 | `PurchaseOrderHead` 对应实体列 | 原头部资料卡，只读 |
| `ExpectedDate/ReplyDate/ConfirmedDate/ConfirmedBy` | `PurchaseOrderHead` | 状态与日期区 |
| 头创建更新审计 | `PurchaseOrderHead` BaseEntity 列 | 底部状态 |
| 客户/关联型号、表面、配置、物料/供货方式 | `PurchaseOrderLine` | 原采购行主表只读列 |
| `DeliveryTargetAllocationId` 与行来源字段 | `PurchaseOrderLine` | 收货/来源只读身份 |
| 行创建更新审计 | `PurchaseOrderLine` BaseEntity 列 | 契约保留，供审查 |
| `LatestProgress` | `SupplierProgressReport` 按 `Sequence DESC, Uid DESC` 的 `TOP(1)` | 详情最新跟进摘要 |

新增公开类型仅 `ProcurementOrderProgressSummaryDto`，独立文件存放。它不包含历史集合、写命令或库存事实。
