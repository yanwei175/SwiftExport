## 已确认范围

用户要求实现售后品质分类树，参考产品分类，父级和末级均允许选择；后端、前端分别执行，最后主控编译和 Review。分类为独立售后主数据，不与产品分类共表，不增加产品分配、结案核验、库存或单据流程功能。现有售后单继续保存 QualityCategoryId，旧字典分类迁移保留 Uid。

## 当前事实与字段处置

产品分类的实体、服务、仓储、维护树页面已经存在；可参考层级编辑、批量保存、防循环、版本冲突和引用删除保护。产品分配区不复制。售后候选当前来自 sys_dict_data，值无 ParentId；sys_dict_type 的树仅为字典类型分组。初始协调文档误把通用 ReferenceAsync 可用能力当成了分类字段已被实际核验：实际草稿和确认未调用该分类核验，此处现已更正。

新实体 AfterSalesQualityCategory 位于 Core/Entities/QualityControl，表 after_sales_quality_category。字段为 BaseEntity 审计与版本、CategoryName、ParentId、FakeName、CategoryCode、SortNo、IsEnabled。CategoryName 为显示名称，FakeName 为别名，CategoryCode 可空；层级、编码和排序规则参考产品分类。IsEnabled 保留旧活动资格，不新增叶子限定或“父停用级联停用”规则。

| 旧值 | 迁移处置 |
| --- | --- |
| Uid、Version、IsDeleted、审计 | 原样保留；不重写售后单引用 |
| DataNameZh / DataNameEn | CategoryName 用原中文、英文兜底；FakeName 保留英文，旧值为空时留空；不得丢失英文展示数据 |
| SortOrder | SortNo 用原排序，NULL 为 0；异常负值预检报告，不悄悄改业务值 |
| IsEnabled | 原样保留，新增节点默认启用 |
| Remark、CssClass、IsSystem | 旧字典记录保留，不擅自删除或修改；这些字段不复制为无实际分类树用途的新字段 |
| ParentId / CategoryCode | 迁入旧值初始为根节点、编码空值；不能把英文名称静默转成要求唯一的新业务编码 |

新读契约 AfterSalesQualityCategoryDto（BaseDto）与写契约 AfterSalesQualityCategoryEditDto 分开，均带 CategoryName/ParentId/FakeName/CategoryCode/SortNo/IsEnabled，写契约另带 Uid 用于本批新节点临时标识。新增专用 DTO，不能复用产品分类业务 DTO；复用 BaseDto、BatchSaveRequestBase、BatchSaveResponseBase 等平台语义。
