# 轻量系统参数与产品图片

实现日期：2026-10-12。首次部署须显式创建参数表及同步权限；已有 system_parameter 表时，本次新增参数不需要改表结构。不在应用启动时执行 DDL 或初始化。

## 数据与接口

产品图片字段继续保存完整原图地址或既有本地绝对路径，产品查询直接返回数据库值。`MainImage`、`MainImagePath`、`ImagePath` 的 DTO 语义未改变。缩略图地址只作为客户端加载输入，不进入业务保存请求。

轻量参数使用 `public.system_parameter`：`parameter_key` 唯一且不可变，`parameter_value` 最长 2048 字符，复用 Uid、Version、软删除与审计字段。名称、说明及值格式由应用层注册；没有任意增删、键更名、用户覆盖或租户继承。

| 参数键 | 用途 | 可填写值 |
| --- | --- | --- |
| `Product.Images.BaseUrl` | 产品图片引用重建 | HTTP/HTTPS 原图目录、Windows 本地绝对目录或 UNC 共享目录 |
| `Product.Images.UploadBaseUrl` | 上传回执和网络缩略图的公开基址 | HTTP/HTTPS 原图目录 |

| 接口 | 资格 | 行为 |
| --- | --- | --- |
| `GET /api/system-parameters` | 实时活动登录账号 | 返回所有注册定义与值；未配置时 Version 0、IsConfigured false；上传地址缺失时可显示旧网络重建基址作为待保存建议 |
| `PUT /api/system-parameters/{key}` | 实时活动管理员 | 保存 Value 与 ExpectedVersion，返回规范化值及新版本 |

`System.Parameters.Manage` 不可分配给普通角色。端点过滤器检查权限，应用服务复核活动投影与管理员身份。首次 ExpectedVersion 0 只插入，已存在时冲突；更新使用版本条件并递增，冲突返回 `VersionConflict`。事务由应用服务拥有，仓储不自行提交。

网络目录禁止凭据、查询、片段及 `Thumbnails` 目录，统一尾斜杠，例如 `https://192.168.3.12/files/ProductImages/`。本地目录统一使用 Windows 反斜杠和尾分隔符，例如 `D:\产品图片\`、`\\server\share\图片\`；拒绝相对路径、目录穿越及保留设备名，不检查客户端目录是否可达。修改参数不会移动服务器文件、修改静态路由或批量重写既有产品地址。

## 客户端维护与缓存

管理员从“设置 → 系统参数”的 DataGrid 编辑。每个注册参数一行，键、名称及说明只读；值可编辑，行内保存与撤销只处理该行。输入与生效缓存隔离，保存成功立即应用该键回执，无需重启；其他行草稿不受影响。冲突或结果不明保留输入，不自动重试。刷新接纳没有草稿的行并显示新增定义，有草稿的行保留输入和原版本；撤销该行才接纳最新缓存。导航和关闭检查全部行的未保存输入，权限撤销或会话结束释放模型并拒绝迟到结果。

已有系统升级后，先保存“产品图片上传地址”的建议值，再按需要把“产品图片重建基址”改为本地目录。新上传地址未单独保存时，上传和网络展示只临时兼容原有网络重建基址；不会把本地目录当作公开 URL，也不会隐式写库迁移。

全部活动用户可从“个人设置 → 刷新系统参数”手动刷新。其他客户端不会定时轮询或接收推送。独立单例缓存登录后预热，首次请求去重，失败保留有效快照；退出清空，旧会话及保存前启动的读取不能覆盖新值。缓存仅在内存中保存。

`ProductOptions.BaseImageFolder` 和前端 JSON 的 Product 配置已退出。两个中性产品编辑入口通过缓存的重建基址生成 `Trim(ProductCode) + ".jpg"`，保留编码内点号，如 `ABC.001.jpg`。网络基址使用 URI 单段转义；本地基址生成完整 Windows/UNC 路径，保留空格、中文和 #/% 等合法文件名字符。批量操作确认后固定一次基址快照，无效编码跳过，仍需普通保存命令提交。

## 图片分流与缓存

公共 `CachedImage` 保持 `Image` 类型和原始 `SourcePath`，通过 `DisplayMode` 区分 Thumbnail 与 Original。公共列表样式使用 Thumbnail，Tooltip 显式 Original，打开时才加载。参数更新通知当前可见控件重新解析，同一引用文本也能重新加载；卸载取消请求并解除订阅。

产品、主产品及采购/销售搜索候选显式使用 Thumbnail，保留原有仅显示小图的交互，不新增大图 Tooltip。

| 引用 | 列表小图 | 按需原图 |
| --- | --- | --- |
| 本机绝对路径、UNC | 原路径，保持原解码尺寸 | 同一路径，以较大解码尺寸读取 |
| 匹配上传地址协议、主机、端口及完整目录边界的托管 URL | `上传基址/Thumbnails/文件名`；有效解码宽度最多 256 | `上传基址/文件名` |
| 其他 HTTP/HTTPS URL | 原 URL 和既有解码尺寸 | 原 URL |
| 参数未配置或尚未加载 | 网络小图占位，不自动下载原图；本地正常 | 保存的完整网络 URL 仍可直接查看 |
| 空、相对路径、纯文件名或其他协议 | 占位 | 不加载 |

托管目录路径大小写敏感，仅识别平铺文件和 `Thumbnails/文件`。解析保留原查询参数，避免重复缩略图目录和重复转义。上传地址变化后，不匹配的新旧地址按外部网络引用处理。重建基址改为本地不会改变已配置上传地址下的网络图片分流。缩略图失败显示占位，仍可按需查看原图。

`ImageCacheService` 本身未改：HTTP 以实际 URL 和解码宽度为键，内存有效期 60 秒，不落磁盘；本地以路径、大小、修改时间和宽度为键，磁盘 PNG 缓存。内存限制 64 MB / 512 项，本地磁盘默认 512 MB / 30 天，失败缓存 30 秒，网络超时 15 秒，源文件上限 50 MB，解码并发 2。原有 OnLoad、Freeze 与文件句柄释放逻辑保留。

同名图片覆盖不会主动使所有可见控件刷新；后续重新加载在 HTTP 缓存有效期结束后取得新内容。这轮没有增加图片轮询或缓存刷新 API。

上传入口在批次开始、鉴权及存储启用检查后读取上传地址参数，整批固定公开基址；缺失或无效时在转码、写文件前拒绝。新上传地址存在但无效时不回退旧值。回执的 OriginalUrl 和 ThumbnailUrl 都来自该快照。上传请求发往客户端 Api.BaseUrl 所指的 API；公开上传地址只决定访问 URL，物理目录、公开静态路由和资源限制仍由该后端的部署配置控制。服务器仍须显式设置 FileStorage:ProductImages:UploadEnabled=true 并重启后端。上传不修改产品引用。

## 部署步骤

1. 明确 PostgreSQL 实例、库名及备份。在 [增量迁移](../SwiftExport.Infrastructure/Database/PostgreSQL轻量系统参数迁移.sql) 顶部核对数据库名、服务器 IP 和端口，再在选定目标库的独立会话中一次执行整个文件。当前三项值按用户提供的目标填写为 `dv_next`、`192.168.3.12`、`5432`；其他目标须显式修改。脚本使用标准 SQL，不依赖 psql 变量；三项连接目标仍会强制校验，表已存在时拒绝重复创建。不要把 Generated 空库预览应用到运行库。
2. 部署后端，并使用既有 [权限目录同步工具](../_tools/DbSeed/同步权限目录.ps1) 同步新增键。参数维护权限不可分配给普通角色。
3. 管理员在表格中先保存上传地址，再保存重建基址。旧初始化工具仍只补缺失的 Product.Images.BaseUrl，取明确服务器 JSON 中的 FileStorage:ApiBaseUrl 加 ProductImages:RequestPath（默认 /files/ProductImages），不会覆盖已有值；新上传地址由管理员逐行保存。无法推导时保持未配置。
4. 部署 WPF，核对原图及缩略图实际可达，再人工验证设置保存、其他客户端手动刷新、本地图片及网络小图/悬停大图。

使用数据库管理工具时，先确认连接并填写迁移文件顶部三项值。使用 psql 时，同样先填写三项值，再执行下列命令；连接凭据通过受控环境提供，不写入命令或仓库：

```powershell
psql -h 已确认主机 -p 已确认端口 -d 已确认库名 -v ON_ERROR_STOP=1 -f .\SwiftExport.Infrastructure\Database\PostgreSQL轻量系统参数迁移.sql
```

若工具提示“当前事务被终止，事务块结束之前的查询被忽略”，先在同一会话单独执行 `ROLLBACK;`，再查看最先出现的错误。这是某条 SQL 已经失败后的后续错误。旧版脚本的 `:'target_database'` 等占位符仅由 psql 替换，普通 SQL 编辑器会产生语法错误；当前脚本已改成普通字符串参数并保留目标校验。重试前可单独查询 `SELECT current_database(), host(inet_server_addr()), inet_server_port();` 核对连接；仍由执行人确认这是预期部署目标。

地址比较使用 `host(inet_server_addr())`。PostgreSQL 将 inet 显式转为 text 时保留 `/32` 等掩码，不能直接拿该字符串与不带掩码的 IP 比较。目标校验失败会显示实际及预期三项值；若经过容器、代理或端口转发，服务器接受连接的内部地址可能与客户端填写的连接主机不同，须核实部署映射后再显式调整预期值，不自动跳过校验。

初始化连接使用独立环境变量 `SWIFTEXPORT_SYSTEMPARAM_CONNECTION`。主机、端口、库名必须与连接配置逐项一致；先 dry-run，再在批准的目标执行写入：

```powershell
dotnet run --project .\_tools\DbSeed -- --initialize-product-image-parameter --config 已确认服务器JSON路径 --target-host 已确认主机 --target-port 5432 --target-database 已确认库名 --dry-run
```

回退应用版本时保留新增表和值，不删除参数数据。旧产品 DTO 与数据库图片字段保持兼容。
