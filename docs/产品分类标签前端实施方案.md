编制日期：2026-10-12。后端实现与专用复制库验收已完成，结果见后端方案。前端页面和缓存仍未实施；须先由用户完成生产迁移和后端发布，再进入本方案。

## 1. 用户场景与页面职责

用户先在产品分类中建立“顶喷”，为它配置“安装方式：吸顶/挂墙”“尺寸：8寸/10寸”。组设为单选时主型号最多选一项；组设为多选时允许选多项。主型号详情选择标签，管理列表看到“安装方式：吸顶；尺寸：8寸”等摘要。

| 位置 | 负责内容 | 保存范围 |
| --- | --- | --- |
| ProductCategoryManagerView | 左侧分类树；右侧“分类资料”“标签定义”两个 Tabs | 分类保存与定义保存分别明确 |
| 标签定义子 View/VM | 当前分类的属性组、当前组选项两张 DataGrid | 两张表合为一次定义批量保存 |
| ProductMasterDetailView | 下半部分“中性产品”“标签属性”两个页签；按分类提供单选/多选 | 与头部、中性产品同次聚合保存 |
| ProductMasterManagerView | 只读标签摘要；沿用现有 OpenDetailCommand 打开详情 | 首期不在列表内批量打标签 |
| ReferenceDataCacheService | 当前登录会话内的完整组/选项快照 | 非编辑数据，不缓存产品选择草稿 |

不新增标签独立主菜单，不修改通用字典编辑页；定义只做新增、修改、删除，没有启用/禁用。旧 ProductType/ProductTag 保留现有输入和查询兼容，新摘要不覆盖旧字符串。

## 3. 分类管理：两个 Tabs 与两张 DataGrid

### 3.1 宿主布局及保存范围

左侧保留现有分类树。右侧设置：

1. **分类资料**：现有名称、别名、代码、排序与快速归类功能。
2. **标签定义**：标题显示当前分类名；组 DataGrid 与选项 DataGrid 形成主从布局。

顶部原保存按钮明确标为“保存分类”，提交分类树；标签 Tab 自己提供“保存标签定义”“刷新”“撤销编辑”，只保存当前分类的组/选项。二者不能共用一个看似保存整页、实际只保存一部分的按钮。

标签定义使用独立子 View/VM，由分类宿主传入 CategoryId、显示名称及可写/Busy/分类草稿状态。定义子 VM 不直接修改分类树，不反向读取宿主 ViewModel；分类宿主负责协调切分类与关闭，API 和定义草稿由子 VM 负责。

### 3.2 DataGrid 内容

| Grid | 列 | 命令 |
| --- | --- | --- |
| 属性组 | 编码、名称、选择方式（单选/多选）、排序 | 新增组、删除组 |
| 当前组选项 | 编码、名称、排序 | 新增选项、删除选项 |

编码/名称不能为空，规范化采用 Trim；选择方式对应共享枚举 Single=0、Multiple=1；排序默认 0。不放入 IsActive/IsEnabled 列或停用命令。组/选项归属在创建后不可编辑，选项不能拖入另一组。

成员名与后端保持一致：组采用 CategoryId、GroupCode、GroupName、SelectionMode、SortOrder；选项采用 AttributeGroupId、OptionCode、OptionName、SortOrder。编码允许修改并接受有效唯一键校验，关系按 Uid 保持，不用编码重建关联。

两张表绑定编辑 LineModel，不直接绑定 DTO 或缓存项。已保存行删除进入删除池；新增行删除直接移除。删除未保存组时移除它的新选项；删除已保存组时标记其关联效果，不生成重复的显式子选项删除请求。服务端有引用时会阻止，失败保持全部草稿并允许撤销删除。

新增组具有客户端逻辑 Uid，新增选项可以立即关联它；同一次保存提交 GroupChanges 与 OptionChanges，由后端完成真实 Uid 映射。客户端只在成功回执及完整提交后快照确认后接纳基线、新 Uid 和 Version。

切换组仅切换当前选项视图，不丢弃同分类其他组草稿；使用保存在当前分类工作区中的全量选项集合或集合视图，不能每次切组重新覆盖编辑集合。

### 3.3 新分类、分类草稿及切换保护

- 新增分类尚未保存，即使本地已生成 Guid，也不能调用定义维护接口。标签 Tab 显示“请先保存分类，再维护标签定义”。
- 分类树存在未保存修改时，定义写入禁用并说明先保存或放弃分类；不能先提交定义，再用分类撤销把关联上下文退掉。
- 标签定义有草稿时切换分类、刷新、关闭页面，先处理“保存/放弃/取消离开”；保存失败继续停留原分类，取消恢复树选中项，不能显示新分类标题却保留旧分类草稿。
- 分类保存后的树重建必须按回执/真实 Uid 恢复刚保存分类，不能在默认跳到第一分类后继续拿旧临时对象编辑标签。
- 定义子 VM 保存期间冻结两张 Grid、组切换及分类选择；分类保存期间也冻结定义编辑，避免独立 Busy 状态互相穿透。
- 标签 Tab 按需首次打开读取当前分类定义；快速切分类取消旧请求，并用 CategoryId/加载代际防止旧结果回写。

## 4. 主型号详情：选择关系随聚合保存

详情下半部分使用“中性产品”“标签属性”两个页签，保留中性产品现有编辑能力，在标签属性页签根据 Header.CategoryId 与缓存定义显示该分类的组。每组只提供本组选项，没有继承父分类选项；两个页签共同服从顶部详情保存。

### 4.1 单选与多选控件

- 单选组使用可清空 ComboBox，值身份绑定 Uid，显示 OptionName；清空采用显式清除操作，不用虚构“无”选项写入数据库。
- 多选组复用 `MultiSelectLookupButton`，`ItemsSource` 为该组可选项、`SelectedItems` 为编辑工作区对象集合、`SelectedValuePath="Uid"`、`DisplayMemberPath="OptionName"`、`FilterMemberPaths="OptionName,OptionCode"`。
- 只在 `SelectionCommittedCommand` 确认后更新已提交编辑选择和 dirty；Popup 临时勾选不直接保存，取消或关闭不改变基线。
- 按 Uid 判断选择身份及集合变化，不按名称、对象引用或显示顺序判断；定义重载后实例改变也能恢复勾选。
- 使用选择展示摘要补充多选按钮的数量文字，用户能看到具体已选值。控件复用不要求改 EnterpriseGrid 框架或新建通用动态表单控件。

### 4.2 编辑模型、草稿与请求

主型号详情持有已保存 SelectedOptionIds 基线和当前选择集合，集合比较忽略排列顺序。标签 dirty 加入 HasUnsavedChanges、IsDirty、CanSave、刷新保护和关闭保护。

- 新建主型号允许选择已有分类及选项，选择保持本地草稿；随 SaveDetail 新建主型号后由后端关联真实 Uid。
- 新客户端提交明确完整最终集合，包括用户清空时的 `[]`；定义尚未加载成功或未接入选择编辑的旧入口不能冒充空选择。
- `null/省略` 是后端“保持”的兼容协议，不能被客户端请求构造或映射默认空数组替换。
- 保存成功只接纳提交后服务端详情、版本与选择基线；失败保持头部、中性产品和标签草稿。
- 分类换成新分类时，若有旧标签，确认提示将清除旧选择；确认后在本地清除、切分类并可重选新选项，同次保存。取消则恢复原分类与全部选择，不调用保存。
- 未分类状态显示提示，不提供任意分类选项；清分类也需要处理既有标签。

定义或选择数据不可用时必须区分“该分类确实没有定义”与“请求失败”。失败显示可重试状态，不把已保存标签默默变成空集合。缓存之外的失效选择保留可识别显示并提示处理，提交时接受后端最终校验。

## 5. 主型号管理：只读摘要及现有详情入口

新增只读 `TagSummary` 列，保留原附加标签字符串列的兼容用途；新列标题使用“分类标签”等明确名称，避免两类数据同名。

沿用现有 `OpenDetailCommand` 和“编辑”入口打开主型号详情，用户在详情的“标签属性”页签维护选择。保持现有导航和稳定文档身份；相同详情已打开时激活已有草稿，不用列表数据覆盖它。不新增标签编辑命令、按钮或专门定位标签页签的导航参数。

列表当前行有未保存修改时，先保存或放弃该行所在列表草稿，再打开详情；不能在列表编辑分类 A、详情仍加载已保存分类 B 时分别提交。详情保存后按现有变更通知刷新摘要和版本，不覆盖列表其他未提交行。

首期不增加批量打标签、批量新建组或标签筛选引擎。列表已有批量改分类如果因旧标签被后端拒绝，清楚提示到详情确认清除/重选，前端不偷偷代发 `[]`。

## 6. 前端会话缓存

扩展现有 `IReferenceDataCacheService/ReferenceDataCacheService`，增加只读属性组/选项集合、按 CategoryId/AttributeGroupId 的本地查找以及 `RefreshProductAttributesAsync`。命名在实现中与新 DTO 对齐，不新增平行全局单例缓存。

### 6.1 加载与一致性

- 接入当前会话的 `EnsureLoadedAsync` 首次使用加载；业务页已有 Ensure 调用可复用。不新增 LoginViewModel/登录预热流程，不把 WarmSystemParameters 顺手扩为全基础资料预热。
- 一次 GET `/api/ProductAttribute/definitions` 得到组/选项完整快照。集合原子替换，不能组刷新成功而选项仍是旧集合。
- 区分未加载、已加载空快照、失败；重复 Ensure 复用正在进行的任务，失败后允许重试。
- 查询只读缓存；维护 Grid 与产品选择使用自己的编辑模型，禁止编辑共享 DTO 或在缓存项上绑定勾选状态。
- 标签缓存失败保留旧完整快照，首载失败只禁用依赖定义的编辑/显示明确错误，不把登录失败或其他基础资料编辑强行扩大为全局阻断。
- 按会话代际丢弃旧请求；退出或切账号 Clear 同时清理组、选项、加载状态，禁止前一用户晚到结果回填。

### 6.2 刷新规则

1. 本机标签定义保存成功后刷新标签定义缓存；服务端已保存而缓存刷新失败，分别提示“已保存”和“缓存刷新失败”，允许手动重试，不回滚成功基线。
2. 分类标签 Tab 和主型号标签区提供手动刷新入口；刷新定义不重新加载、覆盖产品头部或中性产品草稿。
3. 重登录清空后首次使用重新加载，其他客户端新增/改名/删除通过手动刷新或重登录取得；第一期不保证跨客户端即时推送。
4. 当前产品选择按 Uid 重映射到新缓存对象；显示名称修改不会使选择产生假 dirty。若刷新时控件 Popup 打开，先处理临时编辑再接纳新候选，避免选中集合被静默替换。
5. 因其他客户端删定义或改模式导致旧缓存选项无效时，后端保存失败后保留产品草稿，提示刷新定义并重新确认，不自动删除用户选择。

GET 是已登录基础资料读取，定义 POST 使用 `Products.Category.Edit`。因此登录用户都能显示定义，Grid 写入能力才受分类编辑权限控制；当前 SaveDetail 端点固定使用 `Products.Master.Edit`，标签详情保存沿用 Edit。列表新建仍沿用其既有 Create，本期不调整详情新建时的现行权限行为。
