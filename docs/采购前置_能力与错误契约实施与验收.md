# 采购前置：能力与错误契约实施与验收

日期：2026-09-01。阶段三，Backend。基线为 `main`、HEAD `8fe3158a7e124de24555b67e30064ee1a198abc2`；实施期间完整保留阶段一主数据候选和阶段二仓库候选的未提交改动。

2026-10-02 并发处理更新：采购保存、确认和反向写入已按销售模式使用 `RepositoryWriteResult`，Application 在事务内检查失败并回滚，返回 `VersionConflict / ExpectedVersion`（HTTP 409）。锁定读取通过内部事实/错误元组返回引用集合冲突，不再使用专用并发异常。其余内容为当时阶段记录，当前 API、权限及确认规则以源码为准。

## 1. 实现与边界

在新采购根 `api/procurement/orders` 增加 `GET /capabilities`，返回当前用户的 `CanRead`、`CanCreate`、`CanEdit`、`CanConfirm`。能力来自当前有效 `SysUser`、未删除用户角色关系和未删除角色；Admin 获得全部能力。停用账号返回稳定禁止错误，角色撤销在下一次请求立即反映。能力只用于页面入口和按钮提示，搜索、创建、保存、确认仍在各自可串行化事务中实时复核权限。

能力查询不读取 WPF 角色缓存，不修改全局权限平台，不新增角色种类。它没有订单写入、命令回执、BOM、库存或入库副作用。

新采购 API 从全局 `ServiceResult<T>` 切换为专用 `ProcurementResult<T>`。旧采购 Workspace、其他模块 API 和全局包装保持原样；目前没有 WPF 消费新接口，因此不存在旧客户端兼容调用。专用结果保留 `Success`、`Message`、`Data`，并新增 `Error.Code`、`Error.Message`、`Error.Field`，后续 UI 不得解析中文消息。

稳定错误代码：

| 代码 | 语义 | 客户端处理 |
|---|---|---|
| `PROC_UNAUTHENTICATED` | 未认证 | 进入重新认证流程；HTTP 管道仍可直接返回 401 |
| `PROC_FORBIDDEN` | 当前账号或角色无权 | 刷新能力并禁用入口；命令仍重新授权 |
| `PROC_VALIDATION` | 请求字段无效 | 根据 `Field` 定位编辑字段 |
| `PROC_VERSION_CONFLICT` | 头、行或持久化乐观并发冲突 | 重新加载详情，不能覆盖保存 |
| `PROC_BOM_BASIS_CHANGED` | 确认上下文指纹已变化 | 重新读取确认上下文和消耗绑定 |
| `PROC_COMMAND_CONFLICT` | 同一 CommandId 被不同用户、操作或内容占用 | 生成新业务意图前先核对原请求；不得把它当网络重试 |
| `PROC_BUSINESS_BLOCKED` | 状态、资格、固定身份或其他业务规则阻断 | 展示消息并保留编辑内容 |
| `PROC_UNEXPECTED` | 服务端技术失败 | 不把它解释为业务失败；写命令若未收到确定响应，保留同一 CommandId 重试 |

网络超时、断线及客户端取消不属于服务端错误码。客户端没有收到响应时，结果仍未知，必须保留编辑状态并以同一 `CommandId` 重试。权限校验仍发生在回执读取之前，因此账号停用或角色撤销后不能靠旧回执绕过授权；相同操作者、操作和指纹才返回原始回执。

## 2. 契约与实现决定

- 新增 `ProcurementOrderCapabilitiesDto`、`ProcurementErrorDto`、`ProcurementResult<T>` 和稳定错误常量；公开类型各自独立文件，兼容 Contracts 的 netstandard2.0。
- Application 使用类型化 `ProcurementOperationException` 表达字段校验、版本、BOM 指纹和命令键冲突；未知 `InvalidOperationException` 仅映射为一般业务阻断，不按中文文本猜分类。
- Infrastructure 对 SQL 更新行数不符合预期返回 `RepositoryWriteResult`，错误码为 `CONCURRENCY_CONFLICT`；Application 复用 `ProcurementOperationException` 中断事务并转换为统一版本冲突。
- `IProcurementOrderRepository.GetCapabilitiesAsync` 与现有 `HasPermissionAsync` 使用相同账号、角色名称和删除口径；能力查询在独立短可串行化事务中完成。
- 不修改旧 `IPurchaseOrderWorkspaceApi`、旧 Workspace Service、全局 `ServiceResult`、主数据/仓库候选错误协议或任何 WPF 文件。

## 4. 前端交接

新采购 UI 可以在本阶段后开始实施。页面初始化先读取能力；管理页仅在 `CanRead` 时查询，创建入口使用 `CanCreate`，草稿保存使用 `CanEdit`，确认使用 `CanConfirm`。按钮状态只是提示，服务端拒绝仍是最终权威。

UI 应按 `Error.Code` 分流，字段错误使用 `Error.Field`；版本冲突重新加载，BOM 依据变化重新取得确认上下文。网络异常不能构造 `PROC_UNEXPECTED` 作为确定失败，必须保留原 `CommandId` 和待确认状态。
