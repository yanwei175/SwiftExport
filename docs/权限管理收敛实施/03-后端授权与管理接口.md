# 阶段 03：后端授权、初始化与管理接口

状态：未执行。前置：[阶段 01](01-目标模型与权限目录.md) 全部冻结。主执行职责：Backend，读取后端工作流及认证、Contracts、Dapper、DbSession、质量门禁技能。

## 1. 实施顺序

1. 补齐五实体的字段、元数据、唯一约束、逻辑关系与生成基线。
2. 建立单一代码权限目录及目录持久化初始化，补齐 SYSTEM_ADMIN 和首个管理员的引导流程。
3. 提供角色、权限目录、用户角色、角色权限和用户维护契约及后端实现。
4. 改造唯一权限计算入口与 `/api/auth/me`，切换到角色授权；管理员判断统一使用 RoleCode。
5. 按阶段 01 矩阵完成 API 和 Application 的授权覆盖，移除本阶段触碰到的旧兼容授权。
6. 独立验证后端闭环，再交付 WPF 阶段。此时不单独向用户发布旧客户端配新后端的组合。

## 2. 仓储与服务接线清单

| 入口 | 当前事实 | 目标与检查 |
|---|---|---|
| IUserPermissionRepository / UserPermissionRepository | 已被统一权限服务使用，读直接权限表 | 改为角色权限事实查询；删除替换模块写方法的接线须与旧端点退出同步 |
| IPermissionEvaluationService | 当前统一计算，带兼容分支 | 保留业务检查入口，返回有效角色与权限并集；不新增第二个计算器 |
| SysRole / SysUserRole 仓储接口 | 历史角色基础存在 | 全量核对实际实现/DI/调用方；修正 Guid RoleId 与历史 int 签名不一致 |
| 权限目录与角色权限仓储 | 缺少完整运行链 | 新增必要查询与整组保存，使用现有 RepositoryBaseContext/DbSession |
| UserAccountService 与 AuthRepository | 现有账号及管理员检查 | 保留密码/凭据语义，所有管理员判断统一到稳定身份 |
| AuthSessionService / MeDto | 已提供 me，IsAdmin 仍依赖名称 | 由服务端明确写入 IsAdmin/RoleCodes，客户端不推导角色身份 |

实施者必须补齐实际 DI 注册文件、生命周期、调用方和事务核对记录；此表不代表已经完成全部仓储签名审计。Application 控制事务，Infrastructure 不自行创建连接或开业务事务。

## 3. 管理 API 契约草案

以下路径为实施建议，阶段 01/03 冻结后同步 Controller、Refit 和测试；不存在的接口不能标记已提供。

| 用例 | 建议 HTTP 路由 | 说明 |
|---|---|---|
| 当前用户 | GET `/api/auth/me` | 复用现有入口，返回角色与有效权限 |
| 用户分页/详情 | POST `/api/system/users/page`；GET `/api/system/users/{id}` | 列表能看到启用和停用用户 |
| 创建账号 | 复用现有 POST `/api/auth/register` | 复用账号服务，无公开自助注册 |
| 修改资料/启停 | PUT `/api/system/users/{id}`；PUT `/api/system/users/{id}/status` | 版本校验、最后管理员保护；不允许顺带改密码/权限 |
| 用户角色读取/保存 | GET/PUT `/api/system/users/{id}/roles` | 整组替换，有 ExpectedVersion |
| 角色列表/详情/创建/编辑 | `/api/system/roles` 及详情/分页子路由 | 沿用项目结果包装、分页和 CRUD 约定 |
| 角色启停/删除 | 对应明确管理命令 | 内置角色禁止；有用户关联的角色删除先要求解除关联 |
| 角色权限读取/保存 | GET/PUT `/api/system/roles/{id}/permissions` | 普通角色显式授权；内置管理员返回自动全部的说明 |
| 权限目录 | GET `/api/system/permissions` | 只读，含分组和是否可分配 |
| 用户有效权限 | GET `/api/system/users/{id}/effective-permissions` | 管理员只读查看，不允许保存派生结果 |

密码修改和管理员重置继续复用现有接口与限制。第一版不扩大管理员重置其他管理员密码的边界。

所有管理接口按已冻结的保留管理能力保护，后端明确拒绝普通用户直接调用。不能只隐藏 WPF 入口。用户角色和角色权限写入必须同事务重新检查操作者权限，不能只依赖请求开始时的旧身份快照。

## 4. 并发、授权与审计

- 用户角色整组替换锁定用户聚合并校验/递增其 Version；角色权限整组替换锁定角色聚合并校验/递增其 Version，避免两人勾选互相覆盖。复用现有版本协议，不增加无用授权版本字段。
- 无效、重复、删除或不允许分配的 ID 明确校验，失败全部回滚；空集合表示清空普通授权。
- 多角色权限去重；停用用户、停用角色、软删除关系不贡献权限。
- SYSTEM_ADMIN 判断集中实现；登记并替换 SQL、MeDto、恢复工具、开发身份注入和客户端中的 RoleName == Admin 依赖。
- 最后管理员保护覆盖用户停用/删除和用户角色替换等全部入口，以一致锁顺序防并发清零。
- 授权变更写入项目既有审计能力，记录操作者、目标、前后角色/权限、时间；不另起通用审计平台，不记录密码或 Token。
- 后端撤权在变更提交后的下一次请求生效，不把 JWT 中旧角色当作永久有效授权。并发业务命令遵循现有事务授权核验协议，不新增全局业务锁。

## 5. 初始化

结构生成仍只建结构。扩展显式 DbSeed 流程，在新库中初始化代码权限目录、内置角色、首个管理员及关联；整个引导流程事务化。

重复执行应幂等，不能重复关系、重置密码或静默提升同名普通用户。已有账号冲突时明确失败并要求人工核对。管理员角色关系成功建立后才算初始化成功。

新增权限通过代码目录及显式同步进入 SysPermission；管理员随目录获得新权限，普通角色不会自动获得。同步发现目录/数据库不一致应报告失败，不能悄悄把两份目录混用。

## 6. 默认认证与端点覆盖

建立默认需要认证的 API 策略，只有经过盘点的登录、版本等入口显式匿名。区分 Controller 端点、静态文件和提前执行的中间件；全局 API 策略不自动保护静态图片入口。现有明确公开的图片行为要登记，不因本次权限收敛被无依据改变。

具体 Permission 由端点策略或 Application 检查实现，复用同一权限评估服务，不叠加两套权限语义。业务命令保留 Application 检查，查询 API 也需具体读取权限。仅有 Authorize 不等于业务权限覆盖。

开发免登录仅保留在明确 Development 开关下，按项目规则核对身份和权限；正式验收不能开 DevUser 来掩盖鉴权缺失。

## 7. 阶段验收

- 从空库初始化后管理员能登录、创建普通用户、建角色、赋业务权限、分配角色。
- 普通用户多角色取并集，无角色没有业务权限，未知权限键连管理员也不能通过。
- 管理员改显示名不影响权限，普通角色取名 Admin 不获得管理员能力。
- 撤权、角色停用、用户停用后已有 Token 对下一次受保护请求不能继续越权。
- 匿名请求返回 401，已登录但无权限返回 403，符合既有错误包装。
- 直接调用管理 API 越权失败；版本冲突、事务回滚、并发最后管理员保护有行为测试。
- 登录、本人改密、凭据失效和现有管理员密码恢复相关测试不回退。
- 后端构建、相关 Application/Auth 测试、结构 verify 与临时空库验证通过后交接。
