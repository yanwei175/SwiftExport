# 权限管理收敛实施总览

日期：2026-09-27。状态：实施文档已建立，业务代码尚未实施。

## 1. 目标与授权范围

保留现有账号认证基础，将授权收敛为五实体的扁平 RBAC。系统管理提供用户管理、角色管理和权限定义三个入口；WPF 与 ASP.NET Core 使用相同 PermissionKey，未来 Web 客户端复用同一契约。

本次只建立实施文档，不执行代码修改、数据库初始化、数据复制或部署。后续按阶段执行时重新读取 AGENTS、Router、对应 Workflow/Skill、最新源码及 Git 状态。本文的角色分工不授权自动创建聊天或启动并行 Agent。

已确认的决策：

- 核心实体为 SysUser、SysRole、SysUserRole、SysPermission、SysRolePermission。
- 普通用户的有效权限为有效角色所拥有的有效权限并集。
- 内置系统管理员角色使用稳定 RoleCode `SYSTEM_ADMIN`，自动拥有全部已定义权限，不逐项维护角色权限关系。
- 不通过可修改的角色名称识别管理员；未知权限键拒绝，管理员也不绕过业务状态、数据校验和账号停用。
- 不增加用户直接授权、角色继承、权限继承、Deny、数据范围或动态页面平台。
- 废弃 SysUserModulePermission、角色名兼容权限和采购模块隐式授权展开。
- 字典不需要动态页面配置；退出 SysViewRoute、字典 TargetViewKey 及完整依赖链，保留字典分类与字典项功能。
- 保留登录、BCrypt、JWT、CredentialVersion、统一权限计算入口和客户端当前用户服务，按需改接线。

## 2. 正确执行顺序

```text
01 目标模型、权限目录和端点/页面映射设计
  ├─ 02 独立清理字典动态路由
  └─ 03 后端 RBAC、初始化、管理 API 与服务端鉴权
       └─ 04 WPF 用户/角色管理与权限体验接入
            └─ 05 旧授权物理清理、完整验收与交付
```

建议顺序为 01 → 02 → 03 → 04 → 05。02 与 RBAC 无运行时依赖，可独立交付；这不代表同时启动多个写入任务。

不能先删掉正在生效的授权来源，也不能先做管理界面再决定权限含义。必须先有权限目录和 API 契约，再建立管理面。WPF 的页面来自本地导航注册，服务端返回权限集合；不增加“根据权限从数据库生成页面”的系统。

开发阶段允许分提交验证，但 03 到 05 必须作为同一套匹配的后端、Contracts、WPF 和新库基线发布。03 切换授权后不发布仍可编辑旧直接权限的客户端；不建立双读、双写或运行时兼容开关。05 完成前不得宣称整项交付完成。

## 5. 数据库与发布边界

遵循实体驱动、全新空库基线。结构修改通过 Core Entity/DatabaseSchema 元数据与 SchemaGenerator 生成，禁止手改 Generated/SwiftExport.Schema.sql；数据库不生成 FOREIGN KEY。

DbSeed 与结构生成分开。初始化输入沿用显式外部配置，不写固定密码、密码哈希或连接字符串到文档和源码。重复初始化不能重置密码，也不能把同名普通用户静默提升为管理员。

不默认提供旧库原地升级、旧用户授权迁移或删除真实数据库。现有主数据复制工具必须明确只支持匹配的新结构；跨旧授权结构复制时明确拒绝，不能静默丢失关系。若用户以后要求保留旧库数据，另立有限数据搬运任务，不能把自动迁移混入本轮。

实施前应把已确认长期决策同步到项目业务架构总纲及相关规则的适用章节；本次只新增实施文档，没有修改 `.agents`。若规则仍写直接授权，以本轮用户确认目标为准并记录偏差，不能把旧实现解释为目标。
