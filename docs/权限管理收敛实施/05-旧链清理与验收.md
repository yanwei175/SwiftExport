# 阶段 05：旧授权退出与完整验收

状态：未执行。前置：03 后端闭环与 04 WPF 接入均通过；02 字典清理已完成。清理是删除已无消费者的代码，不重构无关模块。

## 1. 删除清单

- SysUserModulePermission 实体/元数据、直接权限 SQL、专属仓储方法、Application 分配服务、旧 modules API、Refit/DTO、DI、旧 WPF 窗口和仅服务旧语义的夹具。
- 角色名作为权限键的兼容解析，以及采购模块自动展开操作权限逻辑。
- ParentRoleId、SysUserRole.UserName/RoleName、相关查询和注释。
- MeDto/SQL/工具/客户端中靠角色显示名 Admin 判定管理员的逻辑。SYSTEM_ADMIN 稳定代码为唯一身份依据。
- 若新旧映射确定不再使用旧模块键，则同步删除其常量、列表和消费者；仍被保留的显式能力不能因名称带 Module 就机械删除。
- 02 中已退出的 ViewRoutes 和字典 TargetViewKey 残留，涵盖生成结构、复制脚本、测试、注册和当前文档。

阶段 03/04 已完成的删除不重复实施。认证、当前用户、统一评估接口、本地导航和有用的回归测试继续保留。测试中旧语义断言按批准规则改写为新的行为验收，不通过删断言掩盖失败。

## 2. 工具与结构核对

- `_tools/DbSeed` 能在新结构完成目录和管理员引导，幂等且不静默提权。
- 主数据跨库复制脚本的表清单、关系核验及说明适配新结构；禁止保留对旧表/ParentRoleId 的查询。
- 权限目录初始化与复制不能各自生成不同 Uid 后误连：复制前核对两库 PermissionKey→Uid 一致性，或按稳定键显式重映射；不能按行顺序或名称猜关系。此项是同版本工具一致性，不是旧库迁移。
- Generated/SwiftExport.Schema.sql 只由生成器更新；验证临时空库，不触碰用户真实库。
- 搜索范围包含当前源码、工具、测试和非历史文档，排除 bin/obj 与弃用资料。实施文档中的删除说明允许保留历史类型名。

## 3. 必须通过的行为矩阵

| 场景 | 结果 |
|---|---|
| 全新空库初始化 | 管理员可完成基础设置 |
| 重复初始化 | 无重复关系，无密码重置，无同名用户自动提权 |
| 普通用户无角色 | 可读取本人身份，无业务权限 |
| 多角色含重复权限 | 权限并集正确且去重 |
| 停用/删除角色关系 | 不再贡献权限 |
| 管理员改显示名 | 自动全权限不变 |
| 普通角色名称为 Admin | 不获得系统管理员身份 |
| 新增有效权限目录项 | 管理员自动拥有，普通角色不自动拥有 |
| 未知权限键 | 所有身份均拒绝 |
| 无 View 直接请求查询 API | 被拒绝，不能只靠隐藏菜单 |
| 有 View 无 Edit/Delete/Confirm/Post/Reverse | 只读；各写操作独立拒绝 |
| 已登录期间撤权 | 下一次服务端请求拒绝，UI 刷新后更新 |
| 两人并发修改授权集合 | 一个成功，过期版本冲突，不悄悄覆盖 |
| 并发移除最后管理员 | 至少保留一名有效管理员 |
| 管理员操作非法状态单据 | 仍被业务校验拒绝 |
| 普通用户调用授权 API | 403，无数据变更 |
| 字典类型与字典项维护 | 不依赖任何动态页面路由 |

同时回归密码变更、CredentialVersion 失效、管理员密码恢复和开发身份边界。DevUser 必须关闭后完成正式鉴权验收。
