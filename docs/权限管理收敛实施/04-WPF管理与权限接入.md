# 阶段 04：WPF 管理界面与权限接入

状态：前端实施完成，自动化验证部分通过；新 RBAC 管理窗口、资源路由、会话刷新/旧响应防回写已有单元与 STA 测试，真实人工 UI 全链尚未验收，随阶段 05 交付报告保留限制。前置：[阶段 03](03-后端授权与管理接口.md) API/契约和后端验证通过。执行职责：Frontend，读取 .NET 10 WPF 入口、CommunityToolkit MVVM、页面架构、运行时安全和质量门禁技能。

## 1. 页面职责

```text
系统管理
├── 用户管理：账号资料、启停、分配角色、查看有效权限
├── 角色管理：角色资料、启停、分配权限
└── 权限定义：只读查看权限键、中文名、分组和用途
```

优先复用设置中心和现有账号/密码管理能力，不重写登录窗、Shell 或所有业务页面。具体 Page/Window 宿主沿用项目导航规则；不为三个入口新建 UI 框架。

## 2. 页面操作闭环

- 用户管理提供启用/停用筛选，选择用户后读取角色集合；保存角色时带版本并展示服务端冲突，不能在前端合并旧选项覆盖服务器。
- 角色管理从后端权限目录构建分组勾选列表，显示选中数量；目录里保留管理能力不可分配给普通角色。
- 系统管理员角色显示“自动拥有全部系统权限”，不提供逐项权限勾选、停用、删除或修改代码操作。
- 权限定义只读，不提供“任意输入一个权限键”来创造业务能力的表单。
- 用户有效权限为只读结果，不再显示直接授权复选框。
- 旧 UserModulePermissions 入口在本阶段替换并退出设置中心，不能保留一个保存成功但对新授权无效的窗口。

## 3. 复用现有权限链

当前 CurrentUserService 已消费 `/api/auth/me.Permissions`，NavigationAccessService 已检查 RequiredPermission；应保留并按新目录接线。

```text
登录/刷新身份 → me.Permissions → CurrentUserService
    ├── 导航与页面进入检查
    └── ViewModel 命令 CanExecute / 操作按钮
```

导航注册负责 RouteKey→页面类型，不存到 SysPermission，也不由服务端返回 ViewModel 类型。菜单分组是否可见可由其可访问子项决定，不创建额外“模块访问自动授权所有子页面”逻辑。

按阶段 01 矩阵同时核对菜单点击、程序化导航、详情链接、已有页签和业务命令。前端不再用角色名称推断权限；IsAdmin 只展示服务端身份事实，业务按钮使用 PermissionKey。

## 4. 权限刷新与会话边界

第一版不引入 WebSocket、轮询或全局事件平台。至少提供以下确定行为：

1. 登录成功后读取 me；登出清空全部身份与权限。
2. 当前会话执行角色/权限管理变更成功后刷新自身 me，并通过已有 CurrentUserChanged 通知导航和命令重新求值。
3. 提供用户可触发的权限刷新入口；新登录和显式刷新均从服务端获取最新集合。
4. 业务调用收到 403 时显示真实拒绝，不重试原写请求；可刷新 me 更新 UI。401 沿用既有会话结束流程。
5. 其他会话被管理员撤权时，界面可能在刷新前仍显示旧按钮，但后端下一次请求已拒绝；不得宣称 UI 具有实时推送能力。

刷新后丧失页面读取权限时阻止继续加载与操作，清除不应继续展示的服务端数据；未保存编辑遵循现有关闭/提示机制，不静默保存或丢弃。账号切换期间的旧异步响应不得写回新会话。

## 5. 文件范围

主要入口：`Features/SystemSettings/SettingsCenter`、`UserRegistration`、旧 `UserPermissions`、`Authentication/CurrentUserService.cs`、`Navigation` 及实际命中的业务 ViewModel/按钮绑定。

允许 WPF、相关客户端测试与已交接的 Contracts；不在前端阶段顺手修改后端业务行为或 EnterpriseGrid 框架。UI 状态用客户端 Model，CommunityToolkit MVVM 写法遵循项目强制规范。

## 6. 验收

- 管理员完成“创建用户→创建角色→分配权限→给用户角色→普通用户登录验证”。
- 同一权限键对应页面进入、操作命令和 API 的真实能力，无额外角色名判断。
- 只读角色能读不能写；具有 Edit 不自动获得 Delete/Confirm/Post/Reverse。
- 普通用户无法进入系统管理写入口，直接调用 API 同样拒绝。
- 本会话刷新后导航/按钮更新；另一会话撤权后后端立即拒绝并能刷新界面。
- 并发保存冲突、取消加载、登出切换、403/401 和未保存变更流程正确。
- WPF 构建和相关权限、导航、管理 ViewModel 测试通过；实际 UI 行为另行人工验收，不以编译替代。

未来 Refine 只需消费身份、有效权限、目录和管理 API，并维护自己的资源动作到 PermissionKey 映射。本阶段不实现 Refine，也不要求后端改成其专属返回结构。
