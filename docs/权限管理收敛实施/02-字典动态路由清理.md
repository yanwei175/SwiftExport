# 阶段 02：独立清理字典动态路由

状态：未执行。前置：[阶段 01](01-目标模型与权限目录.md) 的范围确认；不依赖新 RBAC 运行时。

## 1. 目标

字典只维护类型、层级、分组、排序和字典项，不配置要打开哪个页面。WPF 保留自己的 NavigationRouteRegistry。此阶段不删除 SysUserModulePermission 或改变现有授权来源。

## 2. 执行清单

1. 搜索 `SysViewRoute`、`ISysViewRoute`、`TargetViewKey`、`ViewModelTypeName`，逐项判断是否属于本条动态字典路线；其他功能的同名字段不能机械删除。
2. 后端移除字典 TargetViewKey 的 Entity/DTO 字段、映射、查询投影、标准化和保存校验。SysDictTypeService 的树结构、编码唯一性、并发、事务和批量保存结果继续保留。
3. 前端移除 DictionaryTypeEditModel、视图输入、映射中的动态页面字段，保留字典维护体验。
4. 删除 ViewRoutes 对应 Entity、Core 仓储接口、Infrastructure 仓储、Application 接口与服务、Controller、Contracts DTO/Refit、DI 注册及专属测试夹具。
5. 核对引用全部退出后，通过 Entity 元数据重新生成结构基线，更新受影响的复制工具说明和 SQL 引用。

Backend 负责后端、结构及共享契约；Frontend 负责 WPF 及客户端测试。共享 Contracts 先完成交接再写入，不同时修改同一文件。

## 3. 验收

- 字典类型新增、修改、层级调整、删除边界与字典项维护仍正常。
- 无需提交 TargetViewKey，保存不再查询 SysViewRoute。
- 当前 WPF 产品、订单、设置等导航仍由本地注册驱动。
- 新结构基线没有 SysViewRoute 表和字典 TargetViewKey 列。
- 生产代码、DI、复制工具无残留引用；实施文档中的历史说明不要求删除。
- 运行受影响字典测试、后端与 WPF 最小构建及 SchemaGenerator verify。

提交范围只包含本条依赖链，不借此重做字典架构或删改其他树形业务。
