## 数据模型、关系和并发设计门槛

| 实体 | 当前源码事实 | 目标字段与职责 | 约束 / Repository / DTO 来源 |
|---|---|---|---|
| `SysUser` | `Core/Entities/Auth/SysUser.cs` 已有账号、密码哈希、IsActive、CredentialVersion | 保留身份事实；不存直接权限 | 用户名唯一且不复用；账号资料 Query DTO 不带密码哈希；停用与角色撤销共用最后管理员事务协议 |
| `SysRole` | `Core/Entities/Auth/SysRole.cs` 有 RoleName/Description/ParentRoleId | 删除父角色；新增不可变 RoleCode、IsActive、IsSystem | RoleCode 全局唯一且不复用；`SYSTEM_ADMIN` 只由显式初始化建立，不允许普通管理命令创建、改码、停用、删除 |
| `SysUserRole` | `Core/Entities/Auth/SysUserRole.cs` 有 UserId/RoleId 和冗余名称 | 只保存 UserId/RoleId 与基类字段 | 活动行 `(UserId,RoleId)` 唯一，按 RoleId 查找；名称由 `SysRole` 当前 Join 得到，不作为授权事实 |
| `SysPermission` | 当前无实体；代码常量在 `Contracts/.../PermissionKeys.cs` | Uid、PermissionKey、DisplayName、GroupKey、SortOrder、IsActive、基类字段 | PermissionKey 唯一且不可重用；代码目录是权威、DbSeed 是持久化投影；目录查询 DTO 同时给可分配标记 |
| `SysRolePermission` | `Core/Entities/Auth/SysRolePermission.cs` 仅有两个 Guid，无 `[Table]`/基类 | 补齐 RoleId/PermissionId、Uid/Version/软删除/审计 | 活动行 `(RoleId,PermissionId)` 唯一，按 PermissionId 查找；查询 Join 过滤失效角色/权限/关系 |

所有关系为逻辑外键，不生成 SQL FOREIGN KEY。按项目 `DatabaseSchema` 元数据生成活动行过滤唯一索引，不手改 Generated SQL。Application 整组保存前验证每个 ID 存在、有效、未软删、可分配，重复 ID 拒绝；空集合只清空普通角色或普通用户授权。用户角色与角色权限分别锁用户/角色聚合，比较并递增聚合 Version，事务内重验操作者 `SYSTEM_ADMIN`。

最后管理员保护覆盖停用/删除用户、替换用户角色、停用/删除系统管理员角色（后一类直接禁止）。所有影响有效管理员集合的写命令采用同一数据库事务锁协议与稳定锁序，提交前重新计算有效管理员数；两个管理员并发互撤不能都提交。内置角色不逐项存授权。

Query DTO：用户/角色列表从当前 SysUser/SysRole 投影；用户角色从活动 SysUserRole inner join 有效 SysRole；角色权限从活动 SysRolePermission inner join 有效 SysPermission；有效权限从用户→有效关系→有效角色→有效权限去重，管理员从有效代码目录投影。Command DTO：用户角色/角色权限整组替换只传目标 Uid、目标 ID 集合、ExpectedVersion；所有名称与权限结论由服务端重算。`MeDto.Roles` 仅展示名称，新增 `RoleCodes` 与服务端 `IsAdmin`；Contracts 保持 netstandard2.0。

## 验证场景与交接

阶段 03 的最小证据：空库初始化及重复执行、同名普通用户拒绝静默提权；普通用户无角色/多角色并集/撤权；普通角色名 Admin 不提权、管理员改名后仍有全目录；未知键拒绝；管理 API 普通用户 403；两管理员并发互撤只允许一个成功；角色/权限整组替换版本冲突和回滚；匿名 API 401、无业务键 403。测试必须同时有隔离 SQL 与真实 HTTP 证据，mock 和源码字符串检查不能替代。

阶段 04 的最小证据：管理员用户/角色/目录三个入口和普通用户只读业务能力，显式刷新 me 后导航及 CanExecute 更新，另一会话撤权后服务端下一请求拒绝，登出/换号后旧异步响应不回写。实际 UI 人工验收与构建分开登记。

当前 `PermissionKeys.UserAssignable` 缺少采购五项操作键，但 `PermissionKeys.All` 包含；阶段 03 必须使这些键能明确赋给普通角色，且移除采购模块自动展开。`SysViewRoute`/字典动态路由在阶段 02 退出；旧 modules API/WPF 在 04—05 退出。未涉及旧库迁移，主数据复制工具只支持同版本新结构并须按稳定 PermissionKey 重映射。

例外与当前空壳：`api/auth/login` 和 `api/client-version` 保持匿名；`api/auth/me` 与本人改密只要求有效登录。`FileController.Download` 当前 `FileAccessPolicy` 对所有活动用户开放，上传仅 Admin；目标保留该读边界，用 `System.Files.Manage` 表达写边界，不把文件容器误当任意业务数据查询。销售履约两个 WPF 路由当前只承载空壳，不加载业务数据，沿用 `Sales.Order.View` 进入权限，本轮不提前创建独立履约 API 或权限。
