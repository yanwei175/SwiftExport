# 销售管理事实查询拆分方案

确认日期：2026-10-18。本文记录本轮已确认的字段、查询契约、目录边界和验收范围，不代表尚未执行的测试已通过。

## 范围与责任

销售管理维护订单事实、商业快照和草稿/确认/取消确认/关闭生命周期。查询不再承担成品需求、采购、装箱交付的核实和进度汇总；命令仍保留原有权限、版本、来源退出及历史保护。

本轮移除销售管理中的履约入口和相关显示，不新增跟踪页或过渡入口。现有成品需求及物料需求自身的追踪功能不删除。未来订单跟踪以成品需求行为粒度，按来源订单分组，独立解释拆解、采购及正式交付，待另行授权实施。

## 查询契约处置

复用现有销售管理搜索和详情端点：它们已有真实WPF、VSTO消费者，本轮将原有混合职责收窄为订单事实，迁移所有受影响调用方。列表、详情和保存命令仍各自独立，不合成万能DTO。

| 契约 | 处置与调用方 |
| --- | --- |
| SalesOrderManagerSearchRequest | 保留分页、关键词及事实筛选，删除QuickView；WPF/VSTO请求同步调整。客户代码沿用CustomerCodes集合，条件之间取交集。 |
| SalesOrderManagerListItemDto | 删除全部履约/交期预警/下游核实字段；保留其余事实。新增HasMixedUnits、HasMissingUnit解释数量不可合计的原因。WPF/VSTO列表同步消费。 |
| SalesOrderDetailDto / SalesOrderDetailLineDto | 头行商业快照及关闭信息不变；行删除ShippedQty/UnshippedQty/ReviewReason。管理明细、编辑详情及草稿/生命周期返回同步适配。 |
| 草稿及生命周期命令 | 保留现有命令、权限、版本及幂等协议；新建草稿新增默认交期规则。 |
| SystemParameterKeys | 新增SalesDefaultDeliveryDays，键为Sales.DefaultDeliveryDays；复用现有系统参数列表/更新端点，不创建新参数框架。 |

数量规则：仅订单有效行同单位且单位完整时求和；多单位或缺单位时TotalQty为空，分别标记HasMixedUnits/HasMissingUnit。空单数量为零、单位为空。不再因下游异常或交期差异隐藏订单数量。

已发现偏差：现有列表与详情共享FreezeLineFacts，下游快照不一致令已交未知并连带压掉订单总量；本轮替换为独立事实读取。旧VSTO列表也是实际消费者，必须同步，不留编译成功但绑定失效的进度列。

## 默认交期

- 用户确认初始值60个自然日，由现有系统参数机制展示及维护；未持久配置时使用代码定义的初始值，不自动写业务数据库。
- 参数值为非负整数，0代表订单当天；非法持久值或日期加法溢出返回明确错误。
- 新建订单未指定交期时，交期为订单日期.Date加参数自然日天数。用户明确填写的交期优先。
- 前端新建时预填，异步加载不能覆盖用户输入；后端创建保存兜底，WPF和ForExcel创建路径一致。
- 保存后日期成为订单事实，不随参数或后续日期编辑自动重算。历史已有订单空交期不因读取或普通保存被补齐。
- 行交期未指定时继承头交期；不把默认值强制写入每个空行交期。
- 原有客户LeadTimeDays不重新解释为系统参数，不影响其他日期。
