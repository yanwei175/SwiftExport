# 前端页面总纲

本文是 SwiftExport WPF/VSTO 页面开发的总入口，用来帮助后续智能体判断页面怎么组织、View 和 ViewModel 怎么分工、可编辑行模型怎么建、页面命令怎么落到 Refit API。

本文只覆盖当前桌面端前端：WPF .NET Framework 4.8、MVVMLight、Refit、MateWpfThemes、VSTO 宿主。未来 .NET 10 WPF 前端基础设施见 [.NET 10 前端 MVVM 基础设计](dotnet10-frontend-mvvm-blueprint.md)；未来 BS 前端不纳入本文，BS 只通过 [API 契约总纲](API契约总纲.md) 保持接口可消费。

- [WPF MVVMLight Guide](../guides/frontend-wpf/wpf-mvvmlight.md)

- [Dialog / Navigation Guide](../guides/frontend-wpf/wpf-dialog-navigation.md)

## 1. 总体边界

WPF 通用业务页面主要放在 `SwiftExport.View.FW/**`。

VSTO 只负责：

- Excel Add-in 启动和关闭。
- TaskPane 注册和承载。
- WPF 应用环境初始化。
- Excel 上下文服务接入。

不要因为入口来自 Excel 就把通用业务页面写进 `SwiftExport.VSTO`。业务页面、ViewModel、前端 Model、选择器、弹窗和路由优先放在 `SwiftExport.View.FW`。

前端任务默认禁止借机修改：

- `SwiftExport.WebApi/**`
- `SwiftExport.Application/**`
- `SwiftExport.Infrastructure/**`
- `SwiftExport.Core/**`

如果前端页面需要新 API，前端任务可以先补 `SwiftExport.Contracts/**` 中的 DTO、Refit Interface、枚举和通用契约；后端实现必须等用户明确要求。

## 2. 页面文件组成

业务模块页面优先沿用当前目录形态：

```text
XxxViews/
  Views/
  ViewModels/
  Models/
  Controls/
  Messages/
  Converters/
```

常见职责：

- `Views`：XAML 页面、窗口、UserControl。
- `ViewModels`：页面状态、命令、API 调用、页面级业务交互。
- `Models`：前端行模型、集合模型、页面编辑模型。
- `Controls`：有明确业务复用价值的控件。
- `Messages`：选择器、弹窗、跨组件通信消息。
- `Converters`：页面展示转换，不放业务决策。
- `Mappings`：DTO 与前端 Model 的映射规则。

新增页面通常需要同步检查：

- `SwiftExport.View.FW/DI/DependencyInjection.Pages.cs`
- `SwiftExport.View.FW/DI/DependencyInjection.Apis.cs`
- `SwiftExport.View.FW/Routing/ViewRoutes.cs`
- 后端路由配置或系统路由数据。

## 3. SalesOrder 参考模板

现有 SalesOrder 页面是后续单据类页面的重要参考样板。

Manager 页面职责：

- 左侧或顶部筛选条件。
- 分页查询。
- 主表列表。
- 选中主表后预览明细。
- 打开新建/编辑详情窗口。
- 执行列表级命令，例如确认、取消确认、删除、关闭、刷新。
- 局部刷新保存或命令执行后的当前行和明细。

Detail 页面职责：

- 维护头部字段。
- 维护明细 `DataGrid`。
- 行新增、删除、反选、选择器回填。
- 只读状态控制。
- 保存、取消和关闭。
- 保存成功后把结果返回给 Manager。

分工原则：

- Manager 不持有复杂行编辑逻辑。
- 行级编辑下沉到 Detail ViewModel、`BaseLineModel` 和 `BaseListModel`。
- Manager 可以显示只读或轻量预览明细，但不应承担详情页完整编辑职责。
- 详情页保存后，Manager 优先局部刷新当前头行和明细；必要时再重载全表。

## 4. View 拆分规则

View 一般不拆，优先保持单个业务页面 XAML 的完整性。

允许拆 View 的情况：

- 独立选择器，例如产品选择器、客户选择器。
- 独立弹窗或详情页。
- 可复用业务控件，例如订单行选择控件。
- 宿主差异明显的区域，例如 TaskPane 特有壳层。
- 一个子区域具有独立业务输入输出和复用价值。

不建议拆 View 的情况：

- 只是因为 XAML 行数较多。
- 只是为了把工具栏、筛选区、表格区机械拆成小 UserControl。
- 子 View 没有独立业务语义，只会增加绑定、DataContext 和调试复杂度。

如果页面已经像 SalesOrder 一样存在 Manager + Detail 的自然业务边界，优先保持这种拆法；不要进一步把同一业务页面拆碎。

## 5. ViewModel 拆分规则

页面 ViewModel 优先继承 `ViewModelBaseEx`，复用 Busy、命令刷新、Messenger、DisabledState 和页面级能力。

ViewModel 太大时要拆分。拆分方向优先为：

- 子 ViewModel：独立业务区域或独立弹窗。
- 前端服务：跨页面复用的 API 调用组合、消息提示、缓存装载。
- 选择器 ViewModel：搜索、选择、回填。
- 缓存/搜索 Helper：如 SKU 候选缓存、远程搜索防抖。
- Mapping Helper：DTO 到前端 Model 的复杂转换。

拆分依据是业务职责，不是机械按代码行数切割。

ViewModel 禁止：

- 直接访问 Repository、Controller、SQL。
- 直接创建后端对象。
- 把复杂业务流程硬编码在 WPF 层绕开 Application Service。
- 把 VSTO 宿主逻辑塞进通用业务 ViewModel。

命令规则：

- 使用 `RelayCommand` / `RelayCommand<T>`。
- 异步命令使用 `async () => await XxxAsync()`。
- 业务型命令不要写成 `async void`。
- 长耗时命令用 `BusyScope()` 和 `RegisterBusyNotifyCommand()` 防止重复触发。

## 6. BaseLineModel / BaseListModel 规则

`BaseLineModel` 和 `BaseListModel` 是 SwiftExport 可编辑表格、批量保存和行状态追踪的核心基础设施，普通任务不得绕开或重造。

可编辑行模型优先继承或复用 `BaseLineModel`。

`BaseLineModel` 负责：

- `Uid`、`Version`、审计字段等通用字段。
- `ModelState` 状态机。
- 脏数据追踪。
- `IsChecked` 等行选择状态。
- 字段级、行级和异步验证。
- `LoadFromDto`。
- `RollbackChanges`、`CommitChanges`。
- 通过 `SetUiProperty` 处理纯 UI 状态，避免误触发脏数据。

行集合/批量编辑集合优先继承或复用 `BaseListModel<T>`。

`BaseListModel` 负责：

- `Items` 和内部全量池。
- 新增、修改、删除、删除池。
- `GetChangeSet()`。
- `ReLoadRangeFromDtoList()`。
- 全选、反选、勾选计数。
- 列表级 `IsDirty`、`IsAllValid`。
- 注册 Dirty / Checked 命令刷新。
- 批量加载后的状态刷新。

适合使用轻量模型的情况：

- 只读展示模型。
- Lookup 结果模型。
- 纯导航节点。
- 不需要批量保存、删除池、变更集和验证的临时显示对象。

即使是树节点，如果需要完整行状态、验证、保存和删除池，也可以沿用 `BaseLineModel` 或项目既有树节点基类。

## 7. DTO / 前端 Model 边界

DTO 只做传输，不承载 UI 编辑状态。

前端 Model 负责：

- UI 编辑字段。
- 行状态。
- 脏数据。
- 勾选。
- 删除池。
- 验证。
- DTO 加载和保存前转换。

可编辑 `DataGrid` 禁止直接绑定 DTO。优先绑定：

- `BaseListModel<TLine>.Items`
- `BaseLineModel` 派生行模型。

保存时由 ViewModel 读取行集合的变更集，组装 Request 或 DTO 后调用 Refit API。

## 8. 页面类型模板

### 8.1 管理列表页

用于产品、客户、供应商、销售订单、采购订单、PackingList 等管理入口。

典型结构：

- 筛选区。
- 工具栏。
- 主表 `DataGrid`。
- 分页控件。
- 选中行预览区或只读明细区。
- 状态栏或结果提示。

典型命令：

- 查询 / 刷新。
- 新建 / 编辑。
- 保存列表级快速字段。
- 删除 / 关闭。
- 确认 / 取消确认等列表级命令。
- 反选 / 批量操作。

规则：

- 管理页负责定位对象和执行列表级动作。
- 复杂行编辑进入详情页。
- 查询、分页、刷新前如果存在未保存变更，必须提示用户。

### 8.2 头行详情页

用于销售订单、采购订单、入库单、PackingList 等头行结构。

典型结构：

- 头部字段区。
- 字典和 Lookup 下拉。
- 明细 `DataGrid`。
- 汇总行。
- 保存 / 取消按钮。
- 审计信息。

规则：

- 头模型和行集合分开。
- 行集合使用 `BaseListModel`。
- 明细行使用 `BaseLineModel`。
- 保存前校验头和行。
- 保存成功后用后端返回数据重新加载模型，并清理脏状态。
- 只读状态应由确认状态、过账状态或业务规则驱动。

### 8.3 选择器页 / 弹窗

用于选择产品、客户、客户产品、供应商、待入库行、未出货行等。

规则：

- 选择器返回明确结果，不直接修改调用方业务对象。
- 调用方负责把选择结果回填到当前模型。
- 选择器优先使用 Lookup/Search API 和轻量 DTO。
- 新搜索选择场景优先使用 `SearchableTextBoxPlus`。
- 选择器可以有自己的 ViewModel，不把搜索逻辑塞进调用方 ViewModel。

### 8.4 工作台页

用于净需求、待入库、未出货、采购跟进等业务动作入口。

规则：

- 工作台强调“筛选 + 批量选择 + 执行业务命令 + 结果反馈”。
- 批量命令必须显示影响范围。
- 执行后要刷新被影响行，必要时重载当前查询。
- 工作台不替代单据详情页；复杂编辑仍进入详情或正式单据。

### 8.5 单据过账页

用于入库、出库、PackingList 等影响库存的页面。

规则：

- 过账、反过账、红冲必须是显式按钮和显式命令。
- 危险命令必须有确认提示。
- 过账中使用 Busy 保护。
- 过账成功后页面进入只读或刷新为最新状态。
- 不允许在前端绕过正式单据直接写库存。

### 8.6 系统配置页

用于字典、路由、币种、汇率、权限等配置。

规则：

- 可以使用管理列表页模板。
- 不混入订单、需求、库存等业务流程。
- 字典值可以支持业务显示，但业务判断不能只靠前端字典文本。

## 9. 页面命令规则

保存、刷新、搜索、分页、关闭页面前必须检查未保存变更。

确认、取消确认、拆解、转采购、入库过账、PackingList 过账、反过账、红冲、关闭、作废等必须是显式业务命令，不能藏在保存里。

危险命令必须具备：

- 按钮或菜单上的明确业务动词。
- 执行前确认提示。
- Busy 保护。
- 执行结果反馈。
- 失败消息展示。
- 成功后刷新本地模型和命令状态。

命令执行后优先局部刷新当前对象。只有无法确认局部结果时才重载全表。

## 10. DataGrid 规则

可编辑 `DataGrid` 优先使用：

- `BaseLineModel`
- `BaseListModel`
- `DataGridExcelAssist`
- `UndoManager`
- 现有软验证和汇总能力。

规则：

- 删除已持久化行时进入删除池。
- 删除新增行时可直接移除。
- 保存成功后重新加载后端返回数据，或调用 `CommitChanges()` 清理状态。
- `IsChecked`、`IsSelected`、`IsExpanded`、`IsVisible` 等纯 UI 状态不得触发业务脏数据。
- 需要 Excel 风格编辑、粘贴、撤销、批量填充时，优先复用现有 DataGrid 扩展，不为单页重造。

## 11. 视觉与控件规则

优先复用：

- MateWpfThemes。
- 项目已有资源键。
- 现有 Button、TextBox、DataGrid、DialogHost、PaginationControl。
- 现有图片列、汇总行、软验证样式。

新搜索选择场景优先使用 `MateWpfThemes.FW.Controls.SearchableTextBoxPlus`。旧 `SearchableTextBox` 只用于兼容既有页面。

全局资源修改必须先搜索影响范围；单页视觉问题优先局部修复。

## 12. 路由、弹窗与 DI

新增页面时检查：

- ViewModel 和 View 是否在 `DependencyInjection.Pages.cs` 成对注册。
- Refit API 是否在 `DependencyInjection.Apis.cs` 注册。
- 页面是否需要路由入口。
- 页面是否需要系统路由数据。

弹窗规则：

- 有独立业务结果的弹窗可以使用独立 ViewModel。
- 弹窗返回结果，调用方负责回填。
- 不让弹窗直接修改调用方内部集合，除非这是明确设计的嵌入式子组件。
