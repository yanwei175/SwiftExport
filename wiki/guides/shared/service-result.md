# Service Result Guide

## 适用场景

用于 Application Service、Web API、客户端服务之间表达成功、失败、错误消息和数据返回。

## SwiftExport 规则

- 优先沿用项目已有返回模型，不随意引入新 Result 类型。
- Result 应清晰表达成功状态、错误码、错误消息和数据。
- 区分业务失败、验证失败、系统异常和权限失败。
- UI 层展示消息前，应确认消息是否适合直接给用户看。
- API 层错误模型应与 Refit 客户端解析方式一致。

## 修改前检查

- 项目是否已有统一 Result、异常中间件或验证模型。
- 调用方期望异常还是返回失败对象。
- 错误消息面向用户、开发者还是日志。
- 是否影响 API 契约或 Refit 客户端。

## 禁止事项

- 禁止在同一项目中混用多套返回模型。
- 禁止用异常替代所有业务失败。
- 禁止把内部异常堆栈作为 Result 消息返回。
- 禁止 Result 中塞入 UI 控件状态。
