## 传输与分类边界

| 内容 | 当前产生与消费链 | HTTP 边界 |
| --- | --- | --- |
| 服务执行失败 | Application 异常或 ServiceResult.Fail → Controller → ServiceResultHttpFilter → ServiceErrorResponse；WPF/VSTO 的 API 错误读取器消费 ServiceErrorDto | 仅失败包装的 Error.Code 查 ServiceErrorHttpMapper |
| 行级或逐来源保存错误 | RepositoryWriteResult → SaveItemResultFactory / 批量保存服务 → SaveItemResult；需求转采购 CreateSourceAsync → CreatePurchaseDraftSourceResult | 外层正常包装不按 Data 内错误码改状态 |

## 保留的技术故障及待确认分类

WRITE_FAILED、INSERT_FAILED、LOG_WRITE_FAILED、LOG_FAILED、NUMBER_FAILED、DOCUMENT_NO_FAILED、RESULT_MISSING、OUTCOME_INVALID、EXECUTION_INVALID，以及事务/未声明资源等内部执行错误继续进入现有默认 500 和脱敏出口。明确的技术失败没有改成业务拒绝。

SOURCE_HISTORY_INVALID、SOURCE_VERSION_MISSING、SOURCE_DELIVERY_HISTORY_INVALID、RECEIPT_HISTORY_INVALID、LEDGER_INTEGRITY、DOCUMENT_INTEGRITY 涉及历史事实或执行完整性：当前条件能证明不能执行，尚不足以统一决定应按 409、422 还是服务能力不可用处理。本次只补共享定义并保持原 500，不声称这些分类已解决。它们若在正常预览中出现，仍以原专用 DTO 传输；正常响应内信息不套用服务失败的脱敏规则。

未知码仍为 500，HTTP 出口将 Code 改为 UNEXPECTED，隐藏原 Message 与 Field。SCHEMA_NOT_READY、交付查询不可用等已有 503 分类保留。单参数 Fail(message) 仍使用既有 BUSINESS_BLOCKED 默认，不根据中文消息猜测新分类。
