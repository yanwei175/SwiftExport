# Web 工程入口与命令

SwiftExport.WebApp 是独立的 React Router Framework SPA。后端仍是 ASP.NET Core；本目录不引用 .NET 项目，发布只需要 `build/client` 静态文件。规范权威继续使用仓库 [架构决策](../../docs/Web客户端架构与脚手架决策.md)、[多标签设计](../../docs/Web多标签工作区设计.md)、[接口证据](../../docs/Web首批接口契约验收.md)。当前实现和验证范围另见 [骨架验收记录](骨架验收记录.md)。

## 环境与来源

- Node 24.16.0，npm 11.13.0；`.node-version`、`engines`、`packageManager` 和 lockfile 共同记录本轮组合。
- 2026-10-09 使用 `create-react-router@8.4.0` 官方默认模板，来源为 [react-router-templates/default](https://github.com/remix-run/react-router-templates/tree/main/default)。实际命令：`npm exec --yes --package=create-react-router@8.4.0 -- create-react-router SwiftExport.WebApp --no-install --no-git-init --no-agent-skills --yes --react-router-version 8.4.0`。
- CLI 下载默认分支而未输出模板 Git SHA；后续 `git ls-remote` 网络超时，未将在线另一个提交伪称实际生成来源。当前裁剪后的工程及 lockfile 是可复现基线，模板精确上游提交未核实。
- 裁剪 Tailwind、欢迎页和 Node 服务部署内容，配置 `ssr:false`。`entry.server.tsx` 只供框架开发与构建时静态根渲染，不是生产业务服务器。
- TypeScript 7.0.2 与 `typescript-eslint@8.71.1` 的真实 peer 范围冲突，选择兼容的稳定 6.0.3；没有使用 force/legacy-peer-deps。React 19.3.0、Ant 6.6.5、Query 5.104.1、Router 8.4.0、Vite 8.3.4、Orval 8.40.0 等均由 package.json 和 lockfile 锁定。
- ProComponents 独立接入，精确锁定 `@ant-design/pro-components@3.1.15-6`。2026-10-09 npm registry 的 latest 为 2.8.10，其 peer 只支持 Ant 4/5；本轮采用支持 Ant 6、React 18+ 的预发布版本，未强制绕过 peer 或升级原有顶层依赖。此预发布选择及实际组合验证范围见骨架记录，不能按在线主分支文档宣称稳定版本已支持当前组合。

## 常用命令

在本目录执行：

```text
npm ci
npm run dev:cert
npm run dev
npm run generate
npm run generate:check
npm run typecheck
npm run lint
npm run format:check
npm test
npm run build
npm run test:e2e
npm run verify:paths
npm run verify:static
npm run preview
```

`npm run dev` 使用 `https://localhost:5173`，固定端口并复用当前受信任的 .NET localhost 开发证书。`dev:cert` 只检查并导出已有证书到被忽略的 `.artifacts/https`，不创建、清理或改变信任；缺少受信任证书时停止并提示用户先执行 `dotnet dev-certs https --trust`。证书/私钥不进入浏览器包或生产 build。

开发 `/api` 代理目标由 `.env.example` 中 `API_PROXY_TARGET` 配置，不进入浏览器包。不要把 JWT 密钥、连接字符串或 token 放进环境变量/公开文件。Cookie 恢复的协议规则引用 [公共设施基线](../../docs/Web客户端架构与脚手架决策.md#web-common-services)，不把 HTTP 静态预览当作 Secure Cookie 验收。

默认 API 目标为后端 `https` 启动配置的 `https://localhost:7286`，后端需先正常启动。本机开发证书由 Vite 代理接纳，浏览器始终请求同源 `/api`；其他代理目标继续验证证书。后端启用了 HTTPS 重定向，使用 HTTP 5057 会把浏览器重定向到7286并绕过代理；只有确认对应服务不重定向时才配置 HTTP 目标。示例文件不会自动加载，覆盖配置应使用本地 `.env.local` 或进程环境。

`verify:static` 须在默认生产构建后执行，启动独占 HTTP 4174 预览站并在结束时关闭；核对静态 SPA 深链接、缺失资源/API 不回退、缓存和 Chrome hydration。它不覆盖真实 Secure Cookie 恢复或生产 HTTPS 托管。`test:e2e` 单独启动 `https://localhost:4173` 验收进程；不要复用正在服务用户的开发站。

`typecheck` 的 typegen、Framework build 和开发/验收站都会维护 `.react-router/types`；同一 checkout 按顺序运行这些命令，不能用并行 npm 进程同时生成或清理该目录。lint 与纯单测可独立并行；常驻开发站应在这组整合检查前停止，检查后再恢复。

Vite `optimizeDeps.include` 显式列出当前 React/Router 和 ProComponents 公开子入口，避免冷启动时首次懒加载触发依赖重打包及整页重载。首次完整冷安装验收曾在同一页面发现两套 React 预构建版本；修复与最终证据见骨架记录。此为开发依赖准备，不改变业务 Query 缓存或生产代码拆分；依据 [Vite 官方说明](https://vite.dev/guide/dep-pre-bundling)。

生产构建默认关闭验收页。需要本地查看 Form/Grid 和头行编辑验收会话时，把项目本地环境 `VITE_ENABLE_WORKSPACE_PROBES` 显式设为 `true`；Playwright 启动脚本只为自己的验收进程启用，不改全局环境或本地配置文件。页面目录仍核对实际权限键；所有保存是本地模拟，不调用 Product。

Playwright 默认使用本机 Chrome，可通过 `PLAYWRIGHT_CHANNEL` 选择已经安装的合法浏览器；浏览器实际验证 localhost 证书，不开启 ignoreHTTPSErrors。测试按真实生成操作模拟 login、browser-session csrf/restore/logout 和 me 协议，不连接业务库。具体覆盖与结果见骨架记录；失败截图、trace 和报告在被忽略的测试产物目录内。

## 契约导出与更新

从仓库根执行已有 [导出入口](../../_tools/Web契约验证/导出Web契约.ps1)：

```powershell
& .\_tools\Web契约验证\导出Web契约.ps1 -UpdateWeb
```

该命令运行指定的真实 HTTP Swagger 导出测试，同时从 PermissionCatalog.All 导出权限目录；宿主禁止连接业务库。按 `openapi/已审核端点.json` 递归投影 schema、生成权限 JSON/TS 和 Orval 客户端，再检查生成差异与类型。导出仅证明契约链路，不能证明真实业务写入/权限数据可用。详细来源及历史证据见 [工具说明](../../_tools/Web契约验证/使用说明.md)。

已有真实导出文件时，也可在 Web 目录定向更新；占位路径须替换为本次真实导出产物：

```text
npm run contract:update -- --openapi <OpenAPI完整.json路径> --permissions <权限目录.json路径>
npm run generate
npm run generate:check
npm run typecheck
```

新增接入先审核端点清单，再更新/生成，不手改 generated 或维护另一份权限键。`contract:update` 本身不运行 Orval，不能省略后续 generate；纯文档维护不执行这组导出/构建命令。

后端 Swagger 尚未命名的端点可在审核清单第四项明确标记 `web-alias`，由投影仅补客户端 operationId；若后端以后提供 ID，更新必须停止并重新审核，不能静默覆盖。真实字典端点的 DTO、响应与业务语义不在 Web 投影重定义。字典接入及独立目录导出的本轮证据见 [字典管理接入与验收](字典管理接入与验收.md)；默认工具构建目录被运行中 API 占用时，应使用同一导出测试的独立 `--artifacts-path`，不要终止业务服务来覆盖 DLL。

真实 Swagger 缺少成功正文 schema 时，审核清单第五项可显式标记 `response-untyped`；它记录缺口，不补造传输类型，feature 仍核对运行时完整正文。后端补齐 schema 后更新须停止重审；当前三个账号操作与 19 个系统设置新增操作的来源和检查范围见 [系统设置接入与验收](系统设置接入与验收.md)。

## 发布边界

IIS 与 Nginx 模板位于 `deploy`。需要按实际同源代理、HTTPS、文件服务和缓存规则单独验证；文件服务未接线时返回404，不能回退首页。不存在的资源也不返回 SPA HTML。`scripts/静态预览.mjs` 只供本地静态发布验收，不是生产托管服务。

本轮不部署、不推送，不改现有 API 网站。Linux 实际构建、真实 API/PG 和 IIS/Nginx 托管结果不由 Windows 浏览器模拟证明。
