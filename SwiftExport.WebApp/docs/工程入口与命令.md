# Web 工程入口与命令

SwiftExport.WebApp 是独立的 React Router Framework SPA。后端仍是 ASP.NET Core；本目录不引用 .NET 项目，发布只需要 `build/client` 静态文件。规范权威继续使用仓库 [架构决策](../../docs/Web客户端架构与脚手架决策.md)、[多标签设计](../../docs/Web多标签工作区设计.md)、[接口证据](../../docs/Web首批接口契约验收.md)。当前实现和验证范围另见 [骨架验收记录](骨架验收记录.md)。

## 环境与来源

- Node 24.16.0，npm 11.13.0；`.node-version`、`engines`、`packageManager` 和 lockfile 共同记录本轮组合。
- 2026-10-09 使用 `create-react-router@8.4.0` 官方默认模板，来源为 [react-router-templates/default](https://github.com/remix-run/react-router-templates/tree/main/default)。实际命令：`npm exec --yes --package=create-react-router@8.4.0 -- create-react-router SwiftExport.WebApp --no-install --no-git-init --no-agent-skills --yes --react-router-version 8.4.0`。
- CLI 下载默认分支而未输出模板 Git SHA；后续 `git ls-remote` 网络超时，未将在线另一个提交伪称实际生成来源。当前裁剪后的工程及 lockfile 是可复现基线，模板精确上游提交未核实。
- 裁剪 Tailwind、欢迎页和 Node 服务部署内容，配置 `ssr:false`。`entry.server.tsx` 只供框架开发与构建时静态根渲染，不是生产业务服务器。
- TypeScript 7.0.2 与 `typescript-eslint@8.71.1` 的真实 peer 范围冲突，选择兼容的稳定 6.0.3；没有使用 force/legacy-peer-deps。React 19.3.0、Ant 6.6.5、Query 5.104.1、Router 8.4.0、Vite 8.3.4、Orval 8.40.0 等均由 package.json 和 lockfile 锁定。

## 常用命令

在本目录执行：

```text
npm ci
npm run generate:check
npm run typecheck
npm run lint
npm run format:check
npm test
npm run build
npm run test:e2e
npm run verify:paths
npm run verify:static
npm run preview
```

`npm run dev` 默认 5173；开发 `/api` 代理目标由 `.env.example` 中 `API_PROXY_TARGET` 配置。该代理目标不进入浏览器包。不要把 JWT 密钥、连接字符串或 token 放进环境变量/公开文件。

默认 API 目标为后端 `https` 启动配置的 `https://localhost:7286`，后端需先正常启动。本机开发证书由 Vite 代理接纳，浏览器始终请求同源 `/api`；其他代理目标继续验证证书。后端启用了 HTTPS 重定向，使用 HTTP 5057 会把浏览器重定向到7286并绕过代理；只有确认对应服务不重定向时才配置 HTTP 目标。示例文件不会自动加载，覆盖配置应使用本地 `.env.local` 或进程环境。

`verify:static` 须在默认生产构建后执行，启动独占 4174 预览站并在结束时关闭；核对 SPA 深链接、缺失资源/API 不回退、缓存及真实 Chrome 登录/hydration。`test:e2e` 单独启动 4173 验收进程；不要复用正在服务用户的开发站。

生产构建默认关闭验收页。需要本地查看两个编辑验证页时，把项目本地环境 `VITE_ENABLE_WORKSPACE_PROBES` 显式设为 `true`；Playwright 启动脚本只为自己的验收进程启用，不改全局环境或本地配置文件。页面目录仍核对实际权限键；所有保存是本地模拟，不调用 Product。

Playwright 默认使用本机 Chrome；可以通过 `PLAYWRIGHT_CHANNEL` 选择已经安装的合法浏览器。测试精确模拟 login/me 两个真实 HTTP 端点，不连接业务库。失败截图、trace 和报告在被忽略的测试产物目录内。

## 发布边界

IIS 与 Nginx 模板位于 `deploy`。需要按实际同源代理、HTTPS、文件服务和缓存规则单独验证；文件服务未接线时返回404，不能回退首页。不存在的资源也不返回 SPA HTML。`scripts/静态预览.mjs` 只供本地静态发布验收，不是生产托管服务。

本轮不部署、不推送，不改现有 API 网站。Linux 实际构建、真实 API/PG 和 IIS/Nginx 托管结果不由 Windows 浏览器模拟证明。
