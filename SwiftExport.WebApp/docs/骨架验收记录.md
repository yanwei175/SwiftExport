## 实际实现

- 官方 Framework SPA 工程、独立 package/lockfile、严格类型和路由类型生成。准确 CLI、模板来源、实际依赖组合及 TypeScript peer 约束见 [工程入口](工程入口与命令.md)。
- 登录、工作区、404、白名单深链接；Ant 中文 locale、主题和 `App.useApp` 的 Modal/message/notification；可折叠导航、账户、权限刷新和受保护登出。
- 唯一 QueryClient、内存 Bearer 会话、同用户重新认证与换用户隔离、精确权限键；生成 Fetch 操作委托唯一请求执行边界，保留 HTTP/网络事实，不统一判断业务写入结果。
- 稳定 tabId、页面目录、业务身份去重和新草稿成功后的 Uid 转换；身份冲突保留两页，不覆盖草稿。已确认回执按原身份会话更新定位，401/撤权继续遮蔽业务内容，不因遮蔽把新建再次提交。
- Activity 只包展示；控制器、缓冲、关闭守卫和回执在边界外。保存准备显式等待展示握手，中断未发送时保留输入并解除准备锁。
- 两个显式开启的 Form/Grid 验收页验证完整输入保护、A/B/C 和行级回执、未知记录导出与两步人工终止。全部保存为本地模拟；默认生产构建不包含验收入口或模块。

## 开发登录代理的真实复验

后续本地预览发现 HTTP 5057 将登录请求307重定向到 HTTPS 7286，导致浏览器绕过同源代理；原记录中的认证模拟未覆盖这一真实部署接线。已将 Vite 默认目标与后端 `https` 启动配置对齐为 `https://localhost:7286`，仅本机开发证书由代理接纳，其他目标保持证书验证。同步 `.env.example` 和工程入口，不修改接口/认证行为。

验证期间后端停止，代理出现连接拒绝；核对启动链没有数据库初始化后，使用现有产物执行 `dotnet run --no-build --no-restore --launch-profile https` 恢复本地服务。真实 Chrome 通过同源 `/api/auth/login` 发送缺必填字段的 `{}`，返回400 JSON，URL仍在5173、未重定向；没有使用用户凭据或执行有效账号登录。此次 lint、严格 typecheck 通过；未重跑整套构建/29项模拟回归，实际账号登录及 me/运行库仍待用户操作核实。
