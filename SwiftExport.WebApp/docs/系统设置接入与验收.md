# 系统设置接入与验收

日期：2026-10-10。基于仓库 `0febbe8d` 的当前工作区接入；本轮只修改 `SwiftExport.WebApp/**`，未提交或推送。以下记录当前实现与本轮证据，不改写历史验收。保存、关闭与恢复规则引用 [多标签契约](../../docs/Web多标签工作区设计.md#workspace-contract)；字段所有权、权限与生成链引用 [架构决策](../../docs/Web客户端架构与脚手架决策.md)。

## 接入范围与入口

范围按 .NET 10 客户端 [SettingsPage](../../SwiftExport.Client.Wpf/Features/SystemSettings/Page/ViewModels/SettingsPage.cs)、实际页面、ViewModel 及现有后端契约核对，包括个人设置、用户、角色、只读权限定义及已有字典管理。WPF 与后端源码仅用于只读核对。

Web 导航和注册位于 [工作区布局](../app/layouts/工作区布局.tsx)、[页面目录](../app/workspace/页面目录.ts)。系统设置复用现有 Workspace、Ant Form/Select 和公共 ProTable，没有第二套 HTTP 客户端、窗口框架或权限服务。

| 功能 | 当前 Web 行为 | 现有接口与权限 |
| --- | --- | --- |
| 个人设置 | 查看当前身份、角色及权限，刷新权限，独立页签修改本人密码 | `GET /api/auth/me`、`POST /api/auth/change-password`；已认证本人 |
| 用户管理 | 服务端分页、名称搜索与状态筛选，查看/修改资料，创建用户，启停，分配完整角色集合，查看有效权限，重置普通有效用户密码 | `/api/system/users/*`、`POST /api/auth/register`、`POST /api/auth/admin/reset-password`；读取 `System.Users.View`，写入 `System.Users.Manage` |
| 角色管理 | 服务端分页、搜索与状态筛选，创建普通角色，修改资料，启停，分配完整权限集合，主动确认删除 | `/api/system/roles/*`；读取 `System.Roles.View`，写入 `System.Roles.Manage` |
| 权限定义 | 只读目录、分组和搜索，显示启用/可分配及保留权限 | `GET /api/system/permissions`；`System.Permissions.View` |
| 字典管理 | 沿用已接入的类型和字典项编辑，本轮未重写 | 见 [字典接入与验收](字典管理接入与验收.md) |

内置角色保持只读与自动全目录授权；角色编码创建后不可编辑；新用户不会自动分配角色；没有现有用户删除接口，Web 不新增删除行为。管理员与停用用户不可通过管理页重置密码。限制由现有后端决定，前端呈现并在提交前复核。

角色候选额外需要 `System.Roles.View`，权限候选额外需要 `System.Permissions.View`。缺少候选读取权时保留已有关系显示并禁用对应编辑，不临时扩权。停用/缺失的已有候选不被静默移除，新分配须符合当前合法候选集合；搜索只过滤显示，提交仍为完整关系集合。

## 生成链与真实契约缺口

[已审核端点](../openapi/已审核端点.json) 增加 19 个现有账号/RBAC 操作，共 34 个操作。Swagger 来源为既有 HTTP 契约导出测试；使用独立输出目录，不覆盖运行中 API 的 DLL。权限快照由 `PermissionCatalog.All` 导出，仍为 116 个权限键，本轮未增加或修改权限。

后端没有命名这些操作的 `operationId`，清单明确标记 `web-alias`。`register`、`change-password`、`admin/reset-password` 的 Swagger 成功响应没有正文 schema，以 `response-untyped` 标记该事实；投影不补造响应 DTO。生成器声明的空响应不能作为真实成功依据，feature 对统一执行边界保留的 `unknown` 正文执行运行时核对。后端补齐正文或 operationId 时，更新脚本停止并要求重新审核。

入口见 [queries](../app/features/system/rbac/queries.ts)、[提交契约](../app/features/system/rbac/提交契约.ts)。POST 明确选择后端现有支持的 `application/json`，不沿用 Swagger 排在第一位的 JSON Patch 媒体类型。

账号成功正文的 Swagger 声明、RBAC 可确认未生效的完整失败协议及未知结果查询仍需独立后端契约任务。本轮不修改 Controller、DTO、错误码、事务或命令管道。RBAC 服务的安全回滚函数会吞掉回滚异常，因此“业务拒绝”及 `UNEXPECTED` 文案本身不能证明未写入。现有这些操作没有服务器幂等键或提交结果查询协议；attemptId 仅用于本地关联。

## 编辑、回执与恢复接线

[编辑页签入口](../app/features/system/rbac/编辑页签入口.tsx) 将目标和动作放入独立页签；Ant Form 是当前值唯一所有者，控制器在 Activity 外持有基线、冻结请求及最新保护摘要。Form 使用独立 DOM 标识，隐藏切换、校验与重认证不串到其他表单。活动状态只取消显示读取，已发写入仍由原页签处理；缓存更新不覆盖草稿。

本 feature 按真实用例解释结果，不将通用 HTTP 状态作为事务结论：

| 结果 | 本次接入的证据与行为 |
| --- | --- |
| 确认成功 | HTTP 200、成功外层及完整真实正文。创建用户核对非空合法 Guid；实体操作核对完整 DTO、目标与新版本、提交字段或状态；关系操作核对目标、新版本和完整无重复集合；改密、重置及删除核对 `true`。接纳后才解除锁，清密码并更新相关列表与当前权限 |
| 确认未生效 | 请求事实证明尚未派发；另有本人改密 HTTP 422 + `BUSINESS_BLOCKED` + `CurrentPassword` 的具体短路分支，既有离线后端测试证明没有执行密码写入。保留输入、定位字段并允许修正；不按中文 message 推断 |
| 结果未知 | 其他已发失败、响应丢失或不完整成功回执均保留冻结与追踪，不能接纳、重发或普通放弃；批量关闭定位原页，不绕过恢复 |

成功删除不再重读已删除目标；一次性创建、状态、删除与凭据操作成功后不能重复提交。本人改密成功刷新身份，旧凭据失效进入既有重认证界面，其他页签草稿保留。最后管理员保护、关联角色删除拒绝、真实并发版本冲突由现有后端实施，浏览器模拟不构成真实写入验收。

恢复仅允许原身份、当前读取和写入权仍有效时主动导出 JSON。文件名 `SwiftExport-恢复记录-<recordId>.json` 对应正文标识；包含 attemptId、实际接口路径/方法、目标、基线版本、提交时间、必要冻结内容、允许的响应/追踪及未确认事项。密码、Token、任意响应正文、错误 message、Header 和密钥不导出；凭据操作明确标记省略，沿用现有合法业务/运维渠道核实。

浏览器下载不代表程序证明可靠保全。用户先确认已妥善保留，再确认释放本地草稿且服务器结果仍未知，才能返回 `manualTerminated` 并关闭原页；导出失败、取消、未确认或失权均继续保护。没有新增恢复数据库、文件服务或工单渠道。

## 本轮验证证据

浏览器写入均由精确同源 HTTP 模拟接收；真实 Chrome 经过注册、权限、Form、Workspace 和 Orval 请求链，不连接业务库。模拟器拒绝额外端点、不正确媒体类型和 DTO/版本，不吞掉断言或页面错误。
