# 字典管理 Web 接入与验收

日期：2026-10-09。范围为 Web 页面、现有客户端生成接线及相关验证；不修改后端、Contracts、权限、WPF 或数据库。保存、关闭、恢复的规则正文仍维护在 [多标签设计](../../docs/Web多标签工作区设计.md#workspace-contract)，字段与 API 分层引用 [架构决策](../../docs/Web客户端架构与脚手架决策.md)。本文记录该业务的实际契约和本轮证据，不重写通用规则。

## 真实端点与页面范围

| 用途             | 已有后端接口                              | Web 生成操作        | 权限                              |
| ---------------- | ----------------------------------------- | ------------------- | --------------------------------- |
| 字典类型         | GET `/api/sysdicttype/all`                | getDictionaryTypes  | System.Dictionary.View            |
| 选中类型的字典项 | GET `/api/sysdictdata/by-code/{dictCode}` | getDictionaryByCode | System.Dictionary.View            |
| 类型增改删       | POST `/api/sysdicttype/batch-save`        | saveDictionaryTypes | 按实际操作检查 Create/Edit/Delete |
| 字典项增改删     | POST `/api/sysdictdata/batch-save`        | saveDictionaryItems | 按实际操作检查 Create/Edit/Delete |

权限前缀均为 `System.Dictionary`，浏览器消费生成 PermissionKey；不扩大系统管理权。后三个新增审核操作中的类型读取及两项保存，后端 Swagger 没有 operationId；Web 审核清单明确标记 `web-alias`，仅给 Orval 补方法名。既有 by-code 方法名不变，所有 DTO、路径及响应 schema 取自真实导出。保存显式发送 `application/json`，不采用 Swagger 列表第一项 `application/json-patch+json` 作为普通批量 JSON 的首选类型。

页面为一个 Workspace 页签，左侧类型导航，右侧复用 ProForm 与 PreferenceDataGrid。Form 保存编码、名称、排序、备注的当前值；字典项编辑集合保存英文/中文名称、排序、启用、备注的当前值。短期原始输入缓冲归该 feature 会话，位于 Activity 展示边界外。未展示的 ParentId/分组信息、CssClass 等随真实 DTO 保留，不因页面没控件而清空。

类型与字典项有各自保存按钮，统一页签保存入口依序处理两个独立操作；任一失败或未知停止后续操作，不宣称跨端点事务。类型未保存时字典项只读，避免修改编码与旧类型数据混用。切换类型、新增类型、刷新及关闭消费同一完整保护摘要；只有成功读取目标数据后才替换原会话，后台 Query 更新不覆盖输入与基线。

系统类型按 IsSystem 及后端当前七个保留编码保护：CustomerType、Incoterm、PaymentMethod、ShippedBy、Unit、FlowTestFunction、FlowLimiterSpecification。系统字典项禁止删除，但可在合法编辑权限下修改后端允许字段。旧 AfterSalesQualityCategory 不作为管理入口显示。上述是定向 WPF/后端规则核对，不套用 WPF 实现框架。

## 字典保存的真实解释

两项 BatchSave 的成功契约为整批原子结果，不允许局部成功后把整页标为 clean。完整成功须核对 HTTP/外层成功、TotalCount、唯一完整 ClientKey 集合、操作、Uid、NewVersion 及各项成功标记后一次性接纳。新增类型提交的 Uid 为本地逻辑身份，后端创建返回真实 Uid；不得把请求 Uid 当成已持久化实体身份。

| 情况                                                | 本 feature 的解释                                                                                 |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| 请求确定未派发                                      | 确认未生效，保留输入，允许修改后再提交                                                            |
| 对应端点的精确前置拒绝                              | 仅经核对的状态及机器码组合：403/FORBIDDEN、400/VALIDATION、429/RATE_LIMITED；保留输入并解除提交锁 |
| 完整整批成功                                        | 一次性接纳回执及版本                                                                              |
| 422/BUSINESS_BLOCKED、500/UNEXPECTED                | 无法区分前置拒绝与写入后异常，结果未知                                                            |
| 已派发后的网络/取消、响应丢失、损坏或不完整成功回执 | 结果未知，不重发、不接纳、不普通放弃                                                              |

不分析中文 message 推断回滚。现有业务异常使用共用失败码，TryRollback 会吞回滚异常；中文“已回滚”不能证明本次未生效。字典端点暂无服务器结果查询或 CommandId 恢复协议，未知结果只提供合法记录保全及现有业务/运维渠道人工核实路径，不新增服务端能力。

当前 PG 通用更新源码会先增加实体 Version 再填 OldVersion，因此本 feature 不把 OldVersion 等于请求 Version 设为成功条件；以真实 NewVersion、Uid 和完整操作集合核验。该偏差未在本轮修后端，也未通过源码判断宣称真实写入验证完成。旧系统校验测试仍有“五个保留编码”的断言，与当前七个常量不一致，未运行或改写该断言。

恢复记录为用户主动导出的 JSON 文件，记录标识与文件名/内容对应；仅包含核实必要的冻结提交、已有回执/错误、允许保留的追踪元数据。导出继续校验当前身份及相关业务权限，不含 token/Authorization/密码，不落 localStorage。触发下载不能证明文件已保存；必须确认妥善保全，再确认终止只释放本地草稿、服务器结果仍未知。批量关闭不能自动执行该流程。
