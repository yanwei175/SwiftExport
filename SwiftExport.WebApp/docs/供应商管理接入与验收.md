# 供应商管理 Web 接入与验收

日期：2026-10-10。范围为 Web 供应商列表、现有 Orval 生成接线及定向验证。后端、Contracts、WPF、事务和权限行为只读核对，未修改，也未连接业务库。保存、关闭和恢复的规则正文继续引用 [多标签设计](../../docs/Web多标签工作区设计.md#workspace-contract)，字段所有权与 API 分层引用 [架构决策](../../docs/Web客户端架构与脚手架决策.md)。

## 真实接口与页面范围

| 用途       | 已有后端接口                    | Web 生成操作      | 当前权限                                                       |
| ---------- | ------------------------------- | ----------------- | -------------------------------------------------------------- |
| 分页查询   | POST `/api/supplier/page`       | getSupplierPage   | Suppliers.Supplier.View                                        |
| 批量增改删 | POST `/api/supplier/batch-save` | saveSupplierBatch | 非空操作集合分别需要 Suppliers.Supplier.Create / Edit / Delete |

列表入口要求 View；单元格、新增、删除及保存再次检查当前身份和对应操作权限。权限键消费现有生成产物，未扩大后端授权。页面目录显式 lazy 注册 `supplier-management`，同类列表单例；通过现有 Workspace 打开，不创建第二套标签状态。

保存端点的 Swagger 未提供 operationId，审核清单以 `web-alias` 仅补生成名称；路径、DTO 和响应 schema 来自真实导出。读写均使用现有生成操作、统一请求执行边界及 `application/json`，不维护手写 HTTP 客户端。

页面覆盖供应商代码、名称、单据关联号、联系人、邮箱、电话、地址、币种、付款条款、折扣备注、折扣、税率和默认交期。新增默认 CNY；单据关联号由用户填写，不自动推导。代码、名称和关联号为必填；折扣/税率为空或在 0 至 1 之间，交期为空或非负 Int32 整数。无效数字保留原文，不静默舍入。邮箱、电话、币种未增加后端不存在的格式或候选限制。本轮不接供应商产品关联等独立用例。

查询使用现有 keyword 分页接口，默认每页 20 条；后端目前未消费 BatchKeywords，页面不提供伪批量搜索。供应商列、宽度、单元格选择/区域填充、行选择和分页复用 PreferenceDataGrid；填充仅改变选中列的目标单元格。原始输入缓冲和编辑集合均在 feature 会话中，位于 Activity 展示树外；Query 仅保存服务器快照。首次初始化之后，后台查询不覆盖草稿或基线。查询、分页、刷新必须先处理完整保护摘要，只有成功读取目标数据后才替换原会话。

## 供应商保存的端点解释

SupplierService 的当前保存主线是整批事务，失败时不返回可接纳的行级部分结果。本 feature 完整核对外层成功、计数、唯一完整 ClientKey 集合、操作、RowIndex、Uid、版本及逐项成功后才一次性更新基线。其他业务的既有行级部分成功语义不受此页影响。

当前 PG 源码在 UpdateAsync 提高实体 Version 后返回 OldVersion，所以修改回执 OldVersion/NewVersion 均为提交版本加一；当前软删除不提高 Version，两者均为提交版本。新增回执 OldVersion 为空、NewVersion 为 1，并采用服务器返回的 Uid。本页按这一具体实现核对；这是源码事实，尚未由本轮真实 PG 写入验证。

| 结果                                                                    | 当前处理                                                     |
| ----------------------------------------------------------------------- | ------------------------------------------------------------ |
| 请求执行边界明确记录尚未派发，或 feature 在派发前校验/权限/展示握手失败 | 确认未生效，保留输入，解除准备/提交锁，允许用户修正          |
| 完整整批成功回执                                                        | 一次性接纳真实身份及版本，解除锁；复核完整摘要后才允许关闭   |
| 已派发的 400/403/422/429/500 等失败，或 HTTP 200 的业务失败             | 当前没有本端点独立短路验收证据，保守归结果未知，不机械解锁   |
| 网络中断、取消、响应丢失、损坏/遗漏/重复/错版本回执或局部成功           | 结果未知，保留冻结请求，不重发、不 acceptChanges、不普通放弃 |

用户看到业务拒绝不表示系统已证明未写入，不分析中文 message 猜测回滚或冲突。现有失败包装不能稳定区分前置拒绝与写入/回滚异常；端点暂无 CommandId、结果查询或服务器幂等恢复协议。需要扩展明确失败分类、回滚确认及恢复查询时，另走后端契约任务；本页没有补造这些能力。

未知区提供独立只读分页核实，读取不替换冻结会话，值相同也不认定整批成功或安全重发。用户可在当前同一身份且仍具备冻结操作权限时主动导出 UTF-8 JSON；`SwiftExport-恢复记录-<recordId>.json` 与文件内容/界面记录标识对应。白名单包含业务操作、时间、attemptId、ClientKey、Uid、提交版本、必要冻结 DTO、已有结构化回执/错误及追踪信息；不含凭据、原始响应或任意 Headers，不进入 localStorage。本地 attemptId 仅用于关联诊断。

下载触发不证明文件可靠保存。必须确认记录已妥善保留，再确认终止会释放本地草稿、服务器结果仍未确认且不能据此认定失败/回滚/安全重发，宿主才按 manualTerminated 关闭原页签。导出失败、未确认、权限不足或批量关闭均不能跳过恢复；不能合法保全时需现有合法业务/运维渠道介入。
