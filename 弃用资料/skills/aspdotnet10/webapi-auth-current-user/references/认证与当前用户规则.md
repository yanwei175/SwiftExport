# 认证与当前用户规则

## AuthController 当前职责

`AuthController` 位于 `SwiftExport.WebApi/Controllers/Auth/AuthController.cs`：

- `POST /api/auth/login`：用户名密码登录，返回 JWT。
- `GET /api/auth/me`：读取当前登录用户和角色。
- `POST /api/auth/register`：管理员注册新用户。
- `POST /api/auth/reset-password`：重置密码。

## JWT 规则

- `Auth:JwtKey` 必须配置。
- `Auth:JwtIssuer` 和 `Auth:JwtAudience` 应与 `Program.cs` 验证配置一致。
- 生成 token 时保持这些 claim：
  - `JwtRegisteredClaimNames.Sub`
  - `JwtRegisteredClaimNames.UniqueName`
  - `ClaimTypes.NameIdentifier`
  - `ClaimTypes.Name`

## DevUserMiddleware 规则

`DevUserMiddleware` 位于 `SwiftExport.WebApi/Middlewares/DevUserMiddleware.cs`：

- 只在 Development 环境生效。
- 只在 `Auth:UseDevUser=true` 生效。
- 请求带 Bearer Token 时不注入 dev 用户。
- 使用数据库中配置的 dev 用户 Uid 构造 ClaimsPrincipal。
- `Program.cs` 必须保留生产阻断：非 Development 禁止 `Auth:UseDevUser=true`。

## 安全边界

- 密码哈希使用 BCrypt。
- 登录失败不要泄露用户是否存在的过多细节。
- 注册用户需要 Admin 角色。
- 不要在日志中输出密码、JWT、校验码、完整敏感请求体。
- Reset Password 逻辑属于高风险接口，修改时必须说明验证方式和安全边界。

## 分层提醒

- 认证相关 Controller 当前可直接使用认证仓储和 `DbSession`，这是历史特例。
- 新增普通业务 API 不要照搬 AuthController 的直接 SQL 写法。
- 如果认证逻辑继续复杂化，优先抽到 Application Service。
