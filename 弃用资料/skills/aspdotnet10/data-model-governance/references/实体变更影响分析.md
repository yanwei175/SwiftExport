# 实体变更影响分析

## 适用范围

修改、删除、改名、拆分或合并任何 Core Entity 字段前，必须执行本分析。核心 Entity 包括产品、BOM、销售订单、毛需求、净需求、采购、入库、出库、PackingList、库存和业务追溯关系。

## 搜索链路

按以下顺序搜索真实引用：

```text
Core Entity
  -> 其他 Entity / Repository Interface
  -> Contracts DTO / Request / Response / 枚举
  -> Mapster 映射
  -> Infrastructure SQL / Dapper 字段别名
  -> Application Service / 业务命令 / 校验
  -> WebApi Controller / Refit API
  -> WPF Model / ViewModel / XAML Binding
  -> 数据库脚本 / 索引 / 约束
  -> 历史单据 / 库存流水 / DemandExecutionLink
```

不能只搜索同名 C# 属性；还要搜索数据库列名、SQL 别名、JSON 字段、映射配置和业务编码。

## 影响分类

- 编译影响：类型、接口、映射和调用方是否直接失败。
- 契约影响：JSON、Refit、DTO 和 WPF Binding 是否破坏兼容。
- 数据影响：现有列、历史数据、默认值和迁移方式。
- 业务影响：状态、数量、金额、单位、供应商、仓库和追溯语义。
- 历史影响：已有单据和库存流水能否继续解释当时事实。
- 查询影响：Dapper SQL、Join、筛选、排序、分页和索引是否需要调整。
- 写入影响：Application 校验、Repository 更新列和乐观并发是否变化。

## 判断规则

- 主数据当前值和单据历史快照分别分析，不能一起修改或删除。
- 删除看似重复的编码或名称前，确认它是否承担人工查账、外部交换或历史快照职责。
- 修改业务编码前，确认逻辑外键是否主要依赖 Uid，以及历史追溯是否仍保留原编码。
- 将 Entity 字段移至 Query DTO 时，确认所有写入路径不再依赖该字段，并定义稳定 Join 来源。
- 修改关系 Uid 时，检查所有上下游单据、`DemandExecutionLink` 和库存流水来源字段。

## 输出矩阵

| Entity/字段 | 引用方 | 当前用途 | 变更影响 | 兼容或迁移措施 | 风险等级 |
|---|---|---|---|---|---|

最终结论只能为：可直接调整、需要兼容迁移、必须保留为历史快照、需要先补关系/DTO、或待业务确认。
