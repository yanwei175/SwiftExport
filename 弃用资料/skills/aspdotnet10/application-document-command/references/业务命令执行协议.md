# 业务命令执行协议

## 身份语义

| 对象 | 语义 | 约束 |
|---|---|---|
| `ExpectedVersion` | 客户端读取的业务事实版本 | 更新条件必须包含当前版本；冲突后刷新，不自动覆盖 |
| `CommandId` | 一次业务意图的稳定身份 | 同一次重试复用；不能换内容复用 |
| `CommandItemId` | 命令内一条输出事实的稳定身份 | 流水、Link、命令明细等事实应有唯一约束 |
| `CorrelationId` | 一次 HTTP 或服务调用链 | 用于日志追踪，不作为业务幂等键 |

## 推荐执行顺序

1. 校验认证和当前操作细权限。
2. 校验命令身份、聚合身份和基础格式。
3. 计算包含用户、操作、聚合和业务输入的确定性请求指纹。
4. 开启事务并取得命令锁。
5. 读取命令回执：相同指纹重放，不同指纹拒绝。
6. 按稳定顺序锁定聚合、来源、容量和库存键。
7. 校验 `ExpectedVersion`、状态、数量、权限可见事实和业务资格。
8. 写业务事实、下游事实和不可变流水。
9. 同事务保存命令回执；需要强审计的命令同事务追加 `BusinessOperationLog`。
10. 在提交前响应取消，提交后返回持久化结果。

## 回执与审计

命令回执至少能够证明：

- CommandId、Operation、ActorUid、AggregateUid。
- RequestFingerprint。
- 执行状态或仅允许成功记录的追加语义。
- 可安全反序列化的稳定结果。
- 必要的发生时间和原命令关系。

`BusinessOperationLog` 记录操作名称、原因、摘要、前后变化和关联对象，面向业务追溯。日志归档或查询模型调整不得破坏命令重放。若现有模块暂以日志兼任回执，修改该链路时必须登记兼容边界和迁移方案，不能继续复制到新模块。

## 错误语义

- `VALIDATION_ERROR`：输入或字段格式不合法，可携带 Field。
- `UNAUTHENTICATED` / `FORBIDDEN`：认证或服务端细权限失败。
- `NOT_FOUND`：目标事实不存在或对当前权限不可见。
- `VERSION_CONFLICT`：事实已变化，应刷新。
- `COMMAND_BUSY`：原命令仍在执行，保持 CommandId 重试。
- `IDEMPOTENCY_CONFLICT`：同一命令身份被用于不同请求，不得继续执行。
- `STATE_BLOCKED` / `BUSINESS_BLOCKED`：状态或业务资格不满足。
- `OUTCOME_UNKNOWN`：结果无法确认，禁止生成新 CommandId 盲目重做。
- `UNEXPECTED`：未预期系统错误，仅服务端记录技术详情。

新命令不得要求前端解析中文消息判断分支。HTTP 状态映射由 WebApi 统一策略决定，不能由各 Controller 随意发明。
