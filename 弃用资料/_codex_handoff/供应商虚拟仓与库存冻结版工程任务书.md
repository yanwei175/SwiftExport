# SwiftExport 供应商虚拟仓与库存冻结版工程任务书

## 1. Codex 新任务启动提示词

> 请先完整读取本任务书和同目录《库存履约下游专项总索引》，再读取采购、入库、出库、PackingList、日志任务书、根目录 `AGENTS.md`、`.agents/router.toml`、命中的 workflow/skill 和真实源码。旧 `Warehouse/Inventory/InventoryTransaction` C# Entity、DTO、API、Service、Repository 已清理，不得从 Git 历史恢复；但必须优先复用现有 `Warehouse`、`Inventory`、`InventoryTransaction` 物理表。先只读审计真实列，再用新的专用 C# 语义映射旧表，只为缺失事实增加字段。默认不连接或修改共享数据库。

## 2. 业务目标

公司首期不管理自有实体仓库。各供应商所在地是系统中的虚拟仓，用于记录成品、客供件及其他采购物料实际位于哪个供应商处。

库存模块只负责两件事：

1. 给出某个供应商虚拟仓、某个产品当前可追溯的账面数量。
2. 保存每一次数量变化的不可变领域流水，并能追溯到正式入库、出库或反向单据。

供应商口头反馈“货已做好”不产生库存。只有正式过账单据才能改变库存。

## 3. 已冻结业务规则

- 每个活动供应商首期最多有一个活动虚拟仓，仓库以 Uid 为权威，仓库代码和供应商代码只用于展示与快照。
- 新供应商可显式创建虚拟仓；不得在普通查询时偷偷自动创建。
- 仓库被单据或流水引用后不得物理删除，只能停用。存在库存余额时不得停用。
- 当前库存余额是流水的投影，不是可直接编辑的业务资料。
- 所有库存变化必须由统一 `IInventoryPostingService` 在正式业务事务中完成。
- 库存流水追加后禁止 Update/Delete；纠错必须由反过账或红冲产生相反方向流水。
- 正常出库要求过账后数量不小于零。
- 特殊负库存只能通过 `NegativeStockExceptionOutbound=90` 交易类型，要求特殊权限、强警告、原因、CommandId 和业务日志。
- 同一仓库、产品并发过账必须串行锁定余额；多键过账按 WarehouseId、ProductId 的稳定排序锁定，避免死锁。
- 首期不管理库位、批次、序列号、冻结库存、质量状态或成本层。

## 4. 术语和数量口径

| 术语 | 定义 |
|---|---|
| 虚拟仓 | 某活动供应商处的逻辑库存地点 |
| OnHandQty | 已过账入库减已过账出库及反向流水后的账面数量 |
| AvailableQty | 首期等于 OnHandQty；保留将来占用量扩展，不单独持久化 |
| 已备好数量 | 采购跟单最新报告，不属于库存 |
| 期初余额 | 新库存账启用时经人工确认并一次性过账的起始数量 |
| 库存流水 | 每次正式过账形成的不可变有符号数量记录 |

## 5. 目标数据模型与现有表映射

首期不新建 `WarehouseSite`、`InventoryBalance`、`InventoryLedgerEntry` 同义物理表：

| 新 C# 类型 | 物理表 | 已有可复用列 | 最小扩展方向 |
|---|---|---|---|
| WarehouseSite | `dbo.Warehouse` | Uid/BaseEntity、WhseCode、WhseName、IsVirtual | SupplierId、IsActive/SiteType（若现有状态不足） |
| InventoryBalance | `dbo.Inventory` | Uid/BaseEntity、WhseCode、LocationCode、Sku、Unit、OnhandQty | WarehouseId、ProductId、LastLedgerSequence、Version（若缺） |
| InventoryLedgerEntry | `dbo.InventoryTransaction` | Uid/BaseEntity、仓/库位/SKU、BizType/BizNo/BizLineId、In/Out/Change/PostQty、RefNo | WarehouseId、ProductId、TransactionType、来源 Uid、ReversalOf、CommandId/ItemId、Reason、OccurredDate |

旧列保留为业务编码或历史快照。新命令以新增 Uid 字段为权威；只有 preflight 能唯一证明时才回填。C# 类型采用新语义名称并显式映射旧物理表，禁止恢复旧通用 CRUD。

### 5.1 WarehouseSite

| 字段 | 类型建议 | 规则 |
|---|---|---|
| Uid | uniqueidentifier | 主键 |
| Code | nvarchar(50) | 活动仓库唯一、人工可读 |
| Name | nvarchar(200) | 展示名称 |
| SiteType | tinyint | `SupplierVirtual=0`；预留 `Internal=1`，首期不开放 |
| SupplierId | uniqueidentifier nullable | 供应商虚拟仓必填，逻辑外键 |
| SupplierCodeSnapshot / SupplierNameSnapshot | nvarchar | 建立时快照 |
| IsActive | bit | 活动标志 |
| Version | int | 乐观并发 |
| Created/Updated 审计字段 | 标准字段 | 统一打戳 |

约束：

- 活动 `(SiteType, SupplierId)` 唯一。
- 活动 `Code` 唯一。
- `SupplierVirtual` 必须有 SupplierId；Internal 必须为空。

### 5.2 InventoryBalance

| 字段 | 类型建议 | 规则 |
|---|---|---|
| Uid | uniqueidentifier | 主键 |
| WarehouseSiteId | uniqueidentifier | 逻辑外键 |
| ProductId | uniqueidentifier | 产品权威 Uid |
| SkuSnapshot / UnitSnapshot | nvarchar | 首次建账快照，仅展示 |
| OnHandQty | decimal(18,4) | 当前账面数量 |
| LastLedgerSequence | bigint | 最近成功流水序号 |
| Version | int | 并发控制 |
| UpdatedDate / UpdatedBy | 审计字段 | 每次过账更新 |

唯一约束：`(WarehouseSiteId, ProductId)`。

### 5.3 InventoryLedgerEntry

| 字段 | 类型建议 | 规则 |
|---|---|---|
| Uid | uniqueidentifier | 主键 |
| Sequence | bigint | 全局单调序号，唯一 |
| WarehouseSiteId / ProductId | uniqueidentifier | 库存键 |
| TransactionType | smallint | 冻结交易枚举 |
| QuantityDelta | decimal(18,4) | 入库为正，出库为负 |
| BalanceAfter | decimal(18,4) | 本流水后的余额 |
| SourceDocumentType / SourceDocumentId / SourceLineId | 类型+Uid | 业务来源 |
| ReversalOfLedgerId | uniqueidentifier nullable | 红冲原流水 |
| CommandId / CommandItemId | uniqueidentifier | 命令幂等；Item 唯一 |
| Reason | nvarchar(500) nullable | 异常或调整必填 |
| OccurredDate / CreatedDate / CreatedBy | 审计字段 | 业务时间与入账时间 |
| WarehouseCodeSnapshot / SkuSnapshot / UnitSnapshot | nvarchar | 历史快照 |

冻结交易类型建议：

- `PurchaseReceiptInbound=10`
- `CustomerSuppliedReceiptInbound=11`
- `PackingListAutoReceiptInbound=12`
- `FinalCustomerShipmentOutbound=20`
- `CustomerSuppliedConsumptionOutbound=21`
- `NegativeStockExceptionOutbound=90`
- `OpeningBalance=100`
- `Reversal=900`

枚举值一经迁移不得重排。

## 6. 统一库存过账服务

`IInventoryPostingService` 是 Application 内部领域服务，不开放“任意改库存”的公共 HTTP API。入库、出库、PackingList 和期初余额服务向它提交规范化 Posting Item：

- WarehouseSiteId、ProductId、QuantityDelta。
- TransactionType。
- SourceDocumentType、SourceDocumentId、SourceLineId。
- CommandId、CommandItemId。
- 是否允许负库存及授权上下文。
- 快照和原因。

处理流程固定为：

1. 校验命令幂等和活动仓库/产品。
2. 规范化并按库存键排序。
3. 在当前 `DbSession.Transaction` 内锁定/创建 InventoryBalance。
4. 计算新余额并执行负库存规则。
5. 更新余额 Version。
6. 插入不可变 InventoryLedgerEntry。
7. 返回每个键的 BeforeQty、Delta、AfterQty 和 LedgerId。

入库/出库业务服务负责开启和提交事务；PostingService 不得擅自创建第二个事务。重复 CommandItemId 返回 AlreadyApplied，内容不同的重放返回 `IDEMPOTENCY_CONFLICT`。

## 7. 期初余额与遗留数据

- 现有 `Inventory` 和 `InventoryTransaction` 就是目标余额表和流水表；在补齐权威 Uid、幂等和反向字段并通过 preflight 后切换为新账权威，不建立第二套表。
- preflight 输出：旧仓代码、SKU、余额、能否唯一匹配活动 Supplier/Product、旧流水净额、余额与流水差异。
- 不能唯一匹配的记录进入异常清单，绝不猜测回填。
- 已有可证明余额不重复生成期初。只有明确属于新建账或无法由旧流水解释、且经用户确认的数据，才通过“期初余额预览/过账”命令生成正式流水，不允许 SQL 直接改余额。
- 期初过账以 BatchCommandId 幂等；共享库执行前需要用户提供完整备份及明确授权。
- 切换后只允许新专用仓储写这些现有表，旧 C# 写入口继续保持删除状态，不形成双写。

## 8. Repository 与数据库约束

建议接口：

- `IWarehouseSiteRepository`：Search、GetForUpdate、Create、Update、HasBalanceOrLedger。
- `IInventoryPostingRepository`：LockBalances、InsertMissingBalances、UpdateBalances、InsertLedgerBatch、FindCommandItems。
- `IInventoryQueryRepository`：SearchBalances、SearchLedger、GetTrace。

要求：

- Infrastructure 使用显式 Dapper SQL、显式列清单和当前 DbSession。
- InventoryBalance 允许 Update；InventoryLedgerEntry 仓储不提供 Update/Delete。
- 余额行不存在时使用可证明唯一的插入/重试策略，不能先查后插造成重复。
- `CommandItemId` 建唯一索引；来源行和库存键建查询索引。
- 头行关系可建立强 FK；Supplier/Product 等跨模块关系默认逻辑外键加索引，由 Application 校验。

## 9. HTTP/Refit 契约

### 9.1 仓库主数据 `/api/inventory/warehouse-sites`

- `POST /search`
- `GET /{uid}`
- `POST /supplier-virtual`
- `PUT /{uid}`
- `POST /{uid}/deactivate`

### 9.2 库存查询 `/api/inventory`

- `POST /balances/search`
- `POST /ledger/search`
- `GET /balances/{uid}/trace`
- `POST /opening-balances/preview`
- `POST /opening-balances/post`

不存在任意数量的 `PUT balance` 或 `DELETE ledger`。所有 Command DTO 携带 CommandId、ExpectedVersion 和必要原因；Contracts 保持 netstandard2.0。

## 10. WPF 工作台

Shell 的“库存”导航下建立：

- “供应商虚拟仓”：仓库搜索、创建、改名、停用和供应商精确选择。
- “库存余额”：按供应商/仓库、SKU、产品名称和是否非零筛选。
- “库存流水”：按日期、交易类型、业务单号、销售单号、供应商、SKU 筛选。

余额 Detail/Trace 应展示流水时间线和来源文档链接。页面只读展示库存数量，不提供直接编辑。期初余额属于管理员工具，必须 Preview、强确认、显示匹配异常和逐行结果。

## 11. 业务日志和权限

至少记录：创建/修改/停用仓库、期初余额过账、每个正式过账命令、反向命令和负库存异常放行。

## 12. 分阶段实施

### Phase 0：只读审计与 Contracts 冻结

- 审计旧表、供应商、Product 和遗留非零余额。
- 冻结 DTO、枚举、错误码、API 和迁移 preflight。

### Phase 1：现有表映射与库存内核

- 用新专用 C# 类型映射现有三个物理表，实现 Repository、PostingService 和并发/幂等测试。
- 使用一次性隔离库验证同键、多键、回滚和死锁顺序。

### Phase 2：查询与期初

- 实现余额/流水/Trace、期初 Preview/Post 和 WPF 页面。

### Phase 3：接入下游模块

- 入库、出库和 PackingList 只能调用共享 PostingService。
- 切换后静态扫描禁止直接更新 InventoryBalance 的其他 SQL。

## 13. 测试与验收

至少覆盖：

- 一个供应商只能有一个活动虚拟仓；停用被余额/流水引用的仓库阻断。
- 首次余额并发创建、重复过账幂等、不同内容重放冲突。
- 正常入库、出库、跨多个 SKU 原子成功与任一失败全回滚。
- 正常负库存阻断；异常类型缺权限/原因阻断；授权后生成 90 类型流水和业务日志。
- 反向流水恢复余额但不删除历史；重复反向阻断或幂等。
- 流水净额、BalanceAfter 和 InventoryBalance 数量守恒。
- 旧余额无法唯一匹配时只列异常，不猜测回填。
- 已备好数量变化不产生任何余额或流水。

## 14. 明确不做

- 自有实体仓、多库位、批次、序列号、保质期和质检库存。
- 库存预留、ATP、齐套计算和自动补货。
- 成本核算、总账、盘点和调拨；后续专项另行设计。
- 直接删除旧物理表或历史迁移。
