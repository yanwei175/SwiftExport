# Database Schema Guide

## 适用场景

适用于设计或调整数据库表、字段、主键、审计字段和基础约束，尤其是 SQLite 或轻量 ERP 类项目。

## 推荐做法

- 表结构优先简单、稳定、可迁移。
- 主键、审计字段、软删除字段和版本字段应遵循项目统一约定。
- SQLite 中日期、布尔、decimal 等类型要有明确存储规则。
- 字段命名保持一致，避免同一含义出现多个名字。
- 改表前先说明数据迁移、兼容性和回滚影响。
- 如果只是新增业务功能，先确认是否真的需要改数据库结构。

## 禁止事项

- 禁止在未确认需求时顺手改表结构。
- 禁止同一项目中混用不同主键策略。
- 禁止把 UI 状态字段写入业务表。
- 禁止通过动态列或万能扩展字段逃避建模。
- 禁止在 Guide 中强制某个业务系统的专属表结构。

## Codex 修改前检查清单

- 当前数据库类型、迁移方式、初始化脚本位置是否已确认。
- 主键、唯一索引、外键、审计字段和软删除规则是否已确认。
- 是否影响已有数据、导入导出、接口响应或报表。
- 是否需要补充迁移脚本或兼容读取旧数据。

## 常见错误

- 用字符串保存本应明确约束的状态值，却没有枚举或字典约定。
- decimal、日期、bool 在 SQLite 中存储格式不统一。
- 字段名过度缩写，后续难以维护。
- 删除字段前没有确认历史数据和旧版本兼容。
- 表设计混入页面显示状态。
