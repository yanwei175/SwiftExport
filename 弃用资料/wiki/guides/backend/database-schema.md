# Database Schema Guide

## 适用场景

用于设计或调整 SQL Server 表、字段、主键、审计字段、软删除字段、索引和迁移风险。

## SwiftExport 规则

- 表结构优先简单、稳定、可迁移。
- 主键、审计字段、软删除字段和版本字段应遵循项目现有 Entity / Repository 约定。
- 字段命名保持一致，避免同一含义出现多个名字。
- 改表前先说明数据迁移、兼容性、回滚影响和 API/前端影响。
- 如果只是新增前端展示或查询，先确认是否真的需要改数据库结构。

## 修改前检查

- 当前数据库类型、迁移方式、初始化脚本位置是否已确认。
- 主键、唯一索引、外键、审计字段和软删除规则是否已确认。
- 是否影响已有数据、导入导出、接口响应或报表。
- 是否需要补充迁移脚本或兼容读取旧数据。

## 禁止事项

- 禁止未确认需求时顺手改表结构。
- 禁止同一项目中混用不同主键策略。
- 禁止把 UI 状态字段写入业务表。
- 禁止通过万能扩展字段逃避建模。
