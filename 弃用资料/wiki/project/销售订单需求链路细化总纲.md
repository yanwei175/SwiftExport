# 销售订单需求链路细化总纲

本文定义 SwiftExport 从销售订单到毛需求、净需求、转采购入口的细化规则，重点回答确认、取消确认、拆解、改单、回退和追溯关系如何设计。

本文补充 [ERP 业务总纲](erp-business-blueprint.md)、[单据状态机与轻量改单机制](document-state-and-change-policy.md)、[领域模块总纲](领域模块总纲.md)、[产品 BOM 模块细化总纲](产品BOM模块细化总纲.md) 和 [API 契约总纲](API契约总纲.md)。

## 1. 链路目标

销售订单/需求链路要把“客户要什么”转成“系统需要准备什么”。

主线：

```text
SalesOrderHeader / SalesOrderLine
  -> IndependentDemand
  -> DependentDemand
  -> DemandExecutionLink
  -> PurchaseOrder / 未来 Production / Outsourcing
```

基本关系：

- 销售订单行 -> 毛需求：一对一。
- 毛需求 -> 净需求：一对多。
- 净需求 -> 采购单行：多对一或一对多，通过 `DemandExecutionLink` 追溯。

## 2. 销售订单职责

销售订单负责表达客户订单和交易快照。

销售订单头负责：

- 客户、订单号、客户 PO、日期、币种、贸易条款、金额汇总。
- 展示状态和确认状态。

销售订单行负责：

- 客户 SKU。
- 内部 `Sku`。
- 数量、价格、包装、颜色、描述。
- `MaterialType` 快照。
- 后续出货展示字段。

销售订单不负责：

- 直接生成采购单。
- 直接拆 BOM。
- 直接写库存流水。
- 直接决定客供件出入库。

## 3. 确认销售订单

确认是业务命令，不是普通保存。

确认前校验：

- 订单存在。
- 当前 `ConfirmationStatus = 待确认`。
- 订单头基础字段有效。
- 至少有一条有效明细行。
- 明细行有内部 `Sku`。
- 明细数量大于 0。
- 不存在未清理的重复有效毛需求。

确认后动作：

- 销售订单头确认状态变为已确认。
- 每条销售订单行生成一条 `IndependentDemand`。
- 毛需求保存销售来源、销售订单号、销售订单行、客户、客户 SKU、内部 SKU、数量和需求日期。
- 毛需求初始为待确认/未拆解/未执行状态。

当前源码事实：

- `SalesOrderManagerService.ConfirmSalesOrderAsync` 已承担销售订单确认和毛需求生成。

## 4. 毛需求规则

`IndependentDemand` 承接原始业务需求。

毛需求来源：

- 销售订单。
- 手工需求。
- 未来投诉补货。

毛需求应保存：

- `SourceType`
- `SourceUid`
- `SourceNo`
- `SourceLineId`
- 客户信息。
- 客户 SKU。
- 内部 `Sku`。
- 需求数量。
- 需求日期。
- 是否已拆解。

规则：

- 销售订单来源的毛需求与销售订单行一对一。
- 手工需求和投诉补货也进入同一个毛需求池。
- 毛需求不直接生成采购单。
- 毛需求拆解生成净需求后，应防止重复拆解产生重复有效净需求。

## 5. 拆解毛需求

拆解是业务命令，不是普通保存。

拆解前校验：

- 毛需求存在。
- 毛需求未关闭、未作废。
- 毛需求尚未存在有效净需求，或已有净需求已被合法回退。
- 产品资料和 BOM 信息可用。
- 数量合法。

拆解过程：

1. 根据毛需求 `Sku` 找到产品。
2. 判断产品是否有有效 BOM。
3. 有 BOM 时读取 BOM 明细。
4. 根据 BOM 计算子物料需求。
5. 子物料复制产品 `MaterialType`、`SupplyType`、默认供应商等执行基础字段。
6. 生成多条 `DependentDemand`。
7. 回写毛需求已拆解状态。

无 BOM 情况：

- 如果业务认为该物料本身就是执行对象，可以生成一条自身净需求。
- 如果该物料必须有 BOM，则返回明确错误。
- 当前此规则后续需要按模块实现时再锁定。

当前源码事实：

- `IndependentDemandService` 和相关 Controller 已存在按来源拆解入口。

## 6. 净需求规则

`DependentDemand` 是执行入口。

净需求应保存：

- 来源毛需求。
- 来源销售订单和销售订单行。
- 当前物料 `Sku`。
- 父项 `Sku`。
- BOM 编号、版本、层级。
- 需求数量。
- `MaterialType`。
- `SupplyType`。
- 默认供应商或目标供应商。
- 已转执行数量。
- 已入库数量。
- 已出库数量。
- 展示状态。

规则：

- 净需求是采购、生产、外协的统一入口。
- 当前阶段只实现 `SupplyType = 采购` 的转采购。
- `SupplyType = 生产`、`外协` 应保留展示和扩展口，不误转采购。
- 客供件由 `MaterialType = 客供件` 识别，但具体入库/出库由采购、入库、PackingList 链路完成。

## 7. 净需求转采购

转采购是业务命令。

转采购前校验：

- 净需求存在。
- 净需求未关闭、未作废。
- 净需求尚未完全转执行。
- `SupplyType = 采购`。
- 供应商可确定，或允许用户补供应商。
- 数量合法。

转采购动作：

- 按供应商、交期、币种、业务规则分组生成采购单。
- 可将多条净需求聚合到一条采购行。
- 写入 `DemandExecutionLink`。
- 回写净需求已转执行数量、目标单号和展示状态。

当前源码事实：

- `DependentDemandService` 已存在净需求转采购相关逻辑。
- `IDependentDemandApi` 已存在 `convert-to-po` 类接口。

## 8. DemandExecutionLink 规则

`DemandExecutionLink` 是净需求到执行单据的权威追溯。

必须用于：

- 净需求转采购。
- 多条净需求聚合到一条采购行。
- 未来净需求转生产或外协。
- 入库、出库、PackingList 回写需求执行进度。

不要只依赖：

- `DependentDemand.TargetNo`
- `PurchaseOrderLine.SourceNo`
- 单据号文本反查

这些字段可以作为快速入口或冗余展示，但权威关系应由 `DemandExecutionLink` 承担。

## 9. 取消确认与改单边界

销售订单取消确认：

- 如果只生成了毛需求，且毛需求未确认、未拆解、未执行，可以删除或回退毛需求后取消确认。
- 如果毛需求已拆解成净需求，但净需求未转采购、未执行，可以先回退净需求，再取消确认。
- 如果净需求已转采购，但采购未确认、未入库，可以按轻量改单机制删除或回退下游后再取消确认。
- 如果已入库、出库、PackingList 过账或产生库存流水，不能靠取消确认直接回退，必须走反过账、红冲或差异流程。

销售订单改单：

- 库存流水之前，可以人工或系统辅助回退未过账下游，然后修改订单，再重新确认、拆解、转采购。
- 已产生库存流水之后，不改历史事实，使用反过账、红冲、补差单据或新需求处理。

当前源码事实：

- `SalesOrderManagerService.CancelConfirmSalesOrderAsync` 已检查毛需求和净需求边界。

## 10. 页面设计

销售订单 Manager：

- 查询、筛选、分页、主表。
- 明细预览。
- 新建/编辑详情。
- 确认、取消确认、删除/关闭。

销售订单 Detail：

- 头部字段。
- 明细行 DataGrid。
- 客户选择、客户产品选择、SKU 回填。
- 保存、取消、只读状态。

毛需求工作台：

- 查询来源、客户、SKU、状态。
- 展示是否已拆解。
- 执行拆解命令。
- 跳转查看净需求。

净需求工作台：

- 查询来源、客户、SKU、物料类型、供给方式、供应商、执行状态。
- 补供应商。
- 批量选择转采购。
- 查看执行单号和剩余数量。

## 11. API 设计

销售订单：

- 保存详情。
- 查询 Manager 列表。
- 查询详情。
- 确认。
- 批量确认。
- 取消确认。

毛需求：

- 查询分页。
- 手工新增。
- 按来源拆解。
- 批量回退未执行需求。

净需求：

- 查询分页。
- 按来源查询。
- 转采购。
- 批量转采购。
- 设置供应商。

规则：

- 业务命令必须显式命名。
- 拆解、确认、转采购不能藏在保存接口里。
- 命令返回要包含成功/失败、影响数量、目标单号和失败原因。

## 12. 验收场景

销售订单确认：

- 新建含多行销售订单。
- 确认后生成同数量毛需求。
- 重复确认被拒绝。

毛需求拆解：

- 有 BOM 成品拆解出多条净需求。
- 子物料保留 `MaterialType` 和 `SupplyType`。
- 客供件子物料被识别。
- 重复拆解不会产生重复有效净需求。

净需求转采购：

- 采购型净需求可转采购。
- 生产/外协型净需求不误转采购。
- 多条净需求聚合采购行时写入 `DemandExecutionLink`。

取消确认/改单：

- 未执行下游可以安全回退。
- 已转采购但未入库可以按边界回退。
- 已产生库存流水后必须拒绝普通回退并提示反过账/红冲路径。
