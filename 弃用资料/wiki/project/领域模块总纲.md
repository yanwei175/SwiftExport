# 领域模块总纲

本文是 SwiftExport ERP 的领域模块边界说明，用来帮助后续智能体判断“这个需求属于哪个模块、应该读哪些代码、不能越界改什么、上下游如何衔接”。

本文补充 [ERP 业务总纲](erp-business-blueprint.md)、[数据模型总纲](数据模型总纲.md) 和 [单据状态机与轻量改单机制](document-state-and-change-policy.md)。技术分层和目录仍以 [项目地图](project-map.md) 为准。

## 1. 总体模块图

SwiftExport 当前按业务可分为以下领域模块：

```text
基础资料
  -> 产品 / BOM / 客户产品 / 客户 / 供应商 / 仓库

业务主链
  -> 销售订单
  -> 毛需求 IndependentDemand
  -> 净需求 DependentDemand
  -> 采购单 PurchaseOrder
  -> 入库 Receive
  -> 出库 Outbound
  -> PackingList
  -> 库存 Inventory / InventoryTransaction

未来扩展
  -> 投诉补货
  -> 生产单
  -> 外协单
```

核心业务主线：

```text
销售订单 / 手工需求 / 投诉补货
  -> 毛需求
  -> BOM 拆解
  -> 净需求
  -> 采购 / 未来生产 / 未来外协
  -> 入库
  -> 出库 / PackingList 过账
  -> 库存流水闭环
```

## 2. 模块边界总规则

1. 主数据模块只维护事实和默认值，不直接推动业务流程。
2. 销售订单只负责形成客户需求，不直接生成采购单。
3. 毛需求承接来源需求，净需求承接执行计划。
4. 采购、生产、外协都应从净需求进入，不绕开净需求工作台。
5. 入库、出库、PackingList 只要影响库存，必须生成正式单据和库存流水。
6. 库存流水只做库存变动和审计，不替代正式业务单据。
7. 业务流程判断优先读状态/改单总纲，不把所有判断塞进 `OrderStatus`。
8. 跨模块追溯优先使用 `Source*`、`Target*` 和 `DemandExecutionLink`。

## 3. 产品模块

产品模块维护内部 SKU 体系，是 BOM、销售、采购、需求拆解和库存的物料基础。

核心对象：

- `Product`
- `ProductCategory`
- `ProductColor`
- `ProductPackage`
- `ProductMaster`
- `ProductDetail`

应负责：

- 维护内部 `Sku`、产品描述、分类、颜色、规格、图片、包装和基础价格。
- 维护物料性质，例如成品、半成品、配件、客供件等 `MaterialType`。
- 维护默认供给方式 `SupplyType`，用于净需求阶段判断采购、生产或外协。
- 维护默认供应商、默认客户或默认 BOM 版本等基础默认值。

不应负责：

- 不直接生成销售订单、采购单、需求单或库存流水。
- 不用 `SupplyType` 表达是否有 BOM；BOM 是结构事实，供给方式是执行策略。
- 不把客户专属料号、客户条码、客户包装差异全部塞回通用产品。

主要入口：

- `SwiftExport.Core/Entities/MasterData/Product.cs`
- `SwiftExport.Application/Services/Products/ProductService.cs`
- `SwiftExport.Contracts/DTOs/Products/**`
- `SwiftExport.Contracts/Apis/ProductApis/IProductApi.cs`
- `SwiftExport.View.FW/ProductViews/**`

## 4. BOM 模块

BOM 模块维护父物料到子物料的结构关系，是毛需求拆解成净需求的依据。

核心对象：

- `Bom`

应负责：

- 维护父物料、子物料、用量、损耗、行号、BOM 编号和版本。
- 支持多层 BOM 拆解时保留父子关系、层级和来源链路。
- 在拆解时辅助识别子物料的 `MaterialType`，例如客供件。

不应负责：

- 不决定采购供应商，不直接生成采购单。
- 不写入库存流水。
- 不保存具体执行单据号；执行追溯属于净需求和 `DemandExecutionLink`。

主要入口：

- `SwiftExport.Core/Entities/Orders/Bom.cs`
- `SwiftExport.Application/Services/Products/BomService.cs`
- `SwiftExport.Contracts/DTOs/Products/BomDto.cs`
- `SwiftExport.Contracts/Apis/ProductApis/IBomApi.cs`

## 5. 客户模块

客户模块维护客户主体资料和贸易默认值。

核心对象：

- `Customer`

应负责：

- 维护客户编码、名称、联系人、地址、币种、付款方式和贸易条款。
- 给销售订单、客户产品、投诉补货提供客户主体事实。

不应负责：

- 不维护客户专属产品映射；该职责属于客户产品模块。
- 不生成销售订单、毛需求或投诉补货需求。

主要入口：

- `SwiftExport.Core/Entities/MasterData/Customer.cs`
- `SwiftExport.Application/Services/Customers/CustomerService.cs`
- `SwiftExport.Contracts/DTOs/Customers/**`
- `SwiftExport.Contracts/Apis/CustomerApis/**`
- `SwiftExport.View.FW/CustomerViews/**`

## 6. 客户产品模块

客户产品模块维护客户料号与内部 SKU 的映射，是外贸订单从客户语言进入内部物料体系的转换层。

核心对象：

- `CustomerProduct`
- `CustomerPoConfig`

应负责：

- 维护 `CustomerCode + CustomerSku` 到内部 `Sku` 的映射。
- 维护客户专属描述、条码、包装、单位、价格、MOQ、交期等交易默认值。
- 辅助销售订单录入时自动带出内部产品和客户侧信息。

不应负责：

- 不替代通用产品主数据。
- 不维护 BOM 结构。
- 不生成需求、采购或库存单据。

主要入口：

- `SwiftExport.Core/Entities/MasterData/CustomerProduct.cs`
- `SwiftExport.Core/Entities/MasterData/CustomerPoConfig.cs`
- `SwiftExport.Application/Services/Customers/CustomerProductService.cs`
- `SwiftExport.Contracts/Apis/CustomerApis/ICustomerProductApi.cs`
- `SwiftExport.View.FW/CustomerProductViews/**`

## 7. 供应商模块

供应商模块维护供应商主体资料、供应商产品能力和默认交易条件。

核心对象：

- `Supplier`
- `SupplierProduct`

应负责：

- 维护供应商编码、名称、联系人、地址、币种、付款方式和交期。
- 维护供应商可供 SKU、供应商料号、采购价、MOQ 和默认供货能力。
- 支持同一个供应商既可生产成品，也可生产配件或客供件相关物料。

不应负责：

- 不把供应商固定写死成 A 厂或 B 厂角色。
- 不决定客供件最终流向；流向由净需求、采购执行和入出库单据决定。
- 不直接写库存或需求状态。

主要入口：

- `SwiftExport.Core/Entities/MasterData/Supplier.cs`
- `SwiftExport.Core/Entities/MasterData/SupplierProduct.cs`
- `SwiftExport.Application/Services/Suppliers/SupplierService.cs`
- `SwiftExport.Contracts/Apis/SupplierApis/**`
- `SwiftExport.View.FW/SupplierViews/**`

## 8. 仓库与库存模块

仓库模块维护仓库、库位和库存余额；库存流水记录不可变的库存变动事实。

核心对象：

- `Warehouse`
- `Inventory`
- `InventoryTransaction`

应负责：

- 维护仓库编码、库位、供应商虚拟仓等库存位置。
- 维护当前库存余额。
- 记录所有入库、出库、红冲、反向流水等库存变动。

不应负责：

- 不替代入库单、出库单或 PackingList。
- 不由库存服务自行决定业务流程下一步。
- 库存流水不允许普通编辑或删除；错误通过反向流水或红字流水修正。

建议约定：

- 供应商仓可用虚拟仓表达，例如 `WhseCode = V_WH`，`LocationCode = SupplierCode`。
- 可用库存、预留库存、在途库存后续单独打磨，不能只靠当前余额推断所有业务状态。

主要入口：

- `SwiftExport.Core/Entities/MasterData/Warehouse.cs`
- `SwiftExport.Core/Entities/Orders/Inventory.cs`
- `SwiftExport.Core/Entities/Orders/InventoryTransaction.cs`
- `SwiftExport.Core/Interfaces/Repositories/IInventoryRepository.cs`

## 9. 销售订单模块

销售订单模块承接客户订单，是当前业务链路中已经较精心设计的起点。

核心对象：

- `SalesOrderHeader`
- `SalesOrderLine`

应负责：

- 维护客户订单、订单行、客户产品、数量、价格、交期和订单展示状态。
- 确认后为每一条销售订单行生成一条毛需求。
- 改单时按状态/改单机制判断是否允许安全回退或必须走红冲。

不应负责：

- 不直接拆 BOM。
- 不直接生成采购单。
- 不直接写库存流水。
- 不把下游执行进度全部塞回销售订单行字段。

主要入口：

- `SwiftExport.Core/Entities/Orders/SalesOrderHeader.cs`
- `SwiftExport.Core/Entities/Orders/SalesOrderLine.cs`
- `SwiftExport.Application/Services/Orders/SalesOrderManagerService.cs`
- `SwiftExport.Contracts/Apis/OrderApis/ISalesOrderApi.cs`
- `SwiftExport.View.FW/SalesOrderViews/**`

## 10. 毛需求模块

毛需求承接原始业务需求，是销售订单、手工需求、未来投诉补货进入需求体系的统一入口。

核心对象：

- `IndependentDemand`

应负责：

- 保存来源类型、来源单号、来源行、客户、SKU、需求数量和需求日期。
- 支持从销售订单行一对一生成。
- 支持未来手工需求和投诉补货进入同一需求池。
- 作为 BOM 拆解生成净需求的输入。

不应负责：

- 不直接生成采购单。
- 不直接表达最终供应商。
- 不写入库存。

主要入口：

- `SwiftExport.Core/Entities/Orders/IndependentDemand.cs`
- `SwiftExport.Application/Services/Orders/IndependentDemandService.cs`
- `SwiftExport.Contracts/Apis/OrderApis/IIndependentDemandApi.cs`

## 11. 净需求模块

净需求是 BOM 拆解和供给判断后的执行入口，是采购、未来生产、未来外协的统一工作台。

核心对象：

- `DependentDemand`
- `DemandExecutionLink`

应负责：

- 保存 BOM 拆解结果、父子物料关系、层级、来源毛需求和计划数量。
- 根据物料的 `MaterialType` 判断客供件等特殊物料。
- 根据物料的 `SupplyType` 判断采购、生产或外协执行方向。
- 支持从净需求转采购单，并通过 `DemandExecutionLink` 追溯。
- 提供净需求页面展示执行数量、执行单号、剩余数量和展示状态。

不应负责：

- 不直接入库或出库。
- 不把采购、生产、外协的全部字段复制成自身字段。
- `DependentDemand.TargetNo/TargetLineId` 只作为快速入口，权威追溯以 `DemandExecutionLink` 为准。

主要入口：

- `SwiftExport.Core/Entities/Orders/DependentDemand.cs`
- `SwiftExport.Core/Entities/Orders/DemandExecutionLink.cs`
- `SwiftExport.Application/Services/Orders/DependentDemandService.cs`
- `SwiftExport.Contracts/Apis/OrderApis/IDependentDemandApi.cs`

## 12. 采购模块

采购模块承接净需求中的采购执行部分，负责向供应商下达采购要求。

核心对象：

- `PurchaseOrderHead`
- `PurchaseOrderLine`

应负责：

- 从净需求生成采购单。
- 支持多个净需求聚合到一条采购单行，并通过 `DemandExecutionLink` 保留追溯。
- 维护供应商、采购数量、采购价格、交期、物料类型和采购状态。
- 接收入库回写到货数量和执行进度。

不应负责：

- 不直接修改销售订单。
- 不直接写库存流水；库存变化由入库单过账产生。
- 不删除已产生库存流水的历史事实。

主要入口：

- `SwiftExport.Core/Entities/Orders/PurchaseOrderHead.cs`
- `SwiftExport.Core/Entities/Orders/PurchaseOrderLine.cs`
- `SwiftExport.Application/Services/Orders/PurchaseOrderService.cs`
- `SwiftExport.Contracts/Apis/OrderApis/IPurchaseOrderApi.cs`

## 13. 入库模块

入库模块负责将采购、自动入库或其他合法来源形成正式入库单，并在过账时影响库存。

核心对象：

- `ReceiveHead`
- `ReceiveLine`

应负责：

- 保存入库草稿、确认入库内容并执行入库过账。
- 过账时生成 `InventoryTransaction` 并更新库存余额。
- 支持手动入库和系统自动入库，但自动入库也必须生成正式入库单。
- 回写采购单、净需求或执行链路的入库进度。

不应负责：

- 不绕过单据直接改库存。
- 不在过账后普通编辑数量；错误通过反过账、红冲或差异单据处理。

主要入口：

- `SwiftExport.Core/Entities/Orders/ReceiveHead.cs`
- `SwiftExport.Core/Entities/Orders/ReceiveLine.cs`
- `SwiftExport.Application/Services/Orders/ReceiveService.cs`
- `SwiftExport.Contracts/Apis/OrderApis/IReceiveApi.cs`

## 14. 出库模块

出库模块负责形成正式出库单，并在过账时扣减库存。

核心对象：

- `OutboundHead`
- `OutboundLine`

应负责：

- 承接手动出库、销售相关出库、客供件扣减和 PackingList 自动出库。
- 过账时生成 `InventoryTransaction` 并更新库存余额。
- 回写相关需求、PackingList 或执行链路。

不应负责：

- 不替代 PackingList 的装柜业务含义。
- 不直接决定销售订单是否完成；销售完成应由业务流程汇总判断。

当前状态：

- Core 实体已存在。
- API、Service、Repository 和前端页面仍需后续按业务总纲继续打磨。

主要入口：

- `SwiftExport.Core/Entities/Orders/OutboundHead.cs`
- `SwiftExport.Core/Entities/Orders/OutboundLine.cs`

## 15. PackingList 模块

PackingList 是外贸装柜箱单，代表供货生产环节的末端确认。

核心对象：

- `PackingListHead`
- `PackingListLine`

应负责：

- 维护装柜、箱单、订单行、产品、箱数、数量、重量和体积等外贸出货信息。
- 过账时按业务规则执行智能入库、出库和客供件扣减。
- 对未入库但需要出货的物料，后台应生成正式自动入库单，再生成正式出库单。
- 对已手动入库的物料，直接执行正式出库单。

不应负责：

- 不替代发票、收款或财务模块。
- 不绕过入库单、出库单直接写库存流水。
- 不把客供件逻辑写死为固定供应商 A/B；应由需求执行关系和单据行决定。

主要入口：

- `SwiftExport.Core/Entities/Orders/PackingListHead.cs`
- `SwiftExport.Core/Entities/Orders/PackingListLine.cs`
- `SwiftExport.Application/Services/Orders/PackingListService.cs`
- `SwiftExport.Contracts/Apis/OrderApis/IPackingListApi.cs`

## 16. 投诉补货模块

投诉补货是未来扩展模块，目标是不让客户投诉形成业务孤岛。

应负责：

- 记录客户投诉、问题原因、补货产品和补货数量。
- 当投诉需要补货时，生成毛需求并进入标准需求链路。
- 保留投诉单与毛需求之间的追溯关系。

不应负责：

- 不直接生成采购单。
- 不直接生成入库、出库或 PackingList。
- 不绕开毛需求和净需求。

当前状态：

- 作为未来模块规划，当前不要求立即实现。

## 17. 生产与外协扩展模块

生产和外协是未来供给方式扩展，当前阶段只实现采购链路，但模型应保留扩展口。

应负责：

- 从净需求中 `SupplyType = 生产` 或 `SupplyType = 外协` 的需求进入。
- 生成生产单或外协单。
- 通过 `DemandExecutionLink` 回写执行数量和执行单据。

不应负责：

- 不从销售订单直接生成。
- 不绕开净需求工作台。
- 不与采购单混用同一张业务单据。

## 18. 系统与权限模块

系统模块提供登录、权限、字典、单号和路由等支撑能力。

核心对象：

- `SysUser`
- `SysRole`
- `SysPermission`
- `SysDictType`
- `SysDictData`
- `SysDicCurrency`
- `SysDicCurrencyExchange`
- `DocumentSequence`
- `SysViewRoute`

应负责：

- 提供用户、角色、权限、菜单、字典、币种、汇率和单号生成。
- 为业务模块提供基础系统能力。

不应负责：

- 不承载订单、需求、采购、库存的业务流程。
- 不把业务状态规则写进系统字典后就跳过业务校验。

## 19. 模块交互规则

销售订单到毛需求：

- `SalesOrderLine` 确认后生成一条 `IndependentDemand`。
- 取消确认或改单必须检查毛需求及下游是否允许回退。

毛需求到净需求：

- `IndependentDemand` 通过显式拆解生成多条 `DependentDemand`。
- 重复拆解前必须判断是否已有未回退的净需求。

净需求到采购：

- `DependentDemand` 转采购时生成 `PurchaseOrderLine`。
- 多条净需求可以聚合到一条采购行，但必须写 `DemandExecutionLink`。

采购到入库：

- `PurchaseOrderLine` 通过 `ReceiveLine` 入库。
- 入库过账后必须生成库存流水，并回写采购和需求执行进度。

PackingList 到库存：

- `PackingList` 过账时可以触发自动入库、自动出库和客供件扣减。
- 每一个库存动作都必须落到正式入库单或出库单，再生成库存流水。

## 20. 新功能归属判断顺序

1. 如果需求是在维护事实、默认值、编码或资料，优先归入主数据模块。
2. 如果需求表达客户要什么，归入销售订单或毛需求。
3. 如果需求表达为了满足客户需求具体要准备哪些物料，归入净需求。
4. 如果需求表达向供应商买什么，归入采购模块。
5. 如果需求影响库存，归入入库、出库、PackingList 或库存模块，并遵守正式单据和库存流水规则。
6. 如果需求只是展示、查询、选择、导出，优先设计 DTO、ReadModel 和前端 ViewModel，不改变领域事实。
7. 如果需求跨多个模块，业务编排放在 Application Service，不放在 Controller、Repository 或 WPF ViewModel。
