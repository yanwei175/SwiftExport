# 采购入库 PackingList 闭环细化总纲

本文定义 SwiftExport 从净需求转采购、采购入库、出库、PackingList 过账到库存流水的闭环规则，重点约束正式单据、库存流水、客供件扣减和回写关系。

本文补充 [ERP 业务总纲](erp-business-blueprint.md)、[销售订单需求链路细化总纲](销售订单需求链路细化总纲.md)、[数据模型总纲](数据模型总纲.md)、[单据状态机与轻量改单机制](document-state-and-change-policy.md) 和 [测试与验收总纲](测试与验收总纲.md)。

## 1. 闭环目标

本链路把“净需求要准备物料”落实成“供应商交货、系统入库、装柜出货、库存流水可追溯”。

主线：

```text
DependentDemand
  -> PurchaseOrderHead / PurchaseOrderLine
  -> ReceiveHead / ReceiveLine
  -> Inventory / InventoryTransaction
  -> PackingListHead / PackingListLine
  -> OutboundHead / OutboundLine
  -> InventoryTransaction
```

基本原则：

- 采购从净需求进入。
- 入库必须生成正式入库单和库存流水。
- 出库必须生成正式出库单和库存流水。
- PackingList 过账不能绕过正式入库/出库单直接写库存流水。
- `DemandExecutionLink` 是净需求执行追溯的权威链路。

## 2. 当前事实

当前已存在：

- `PurchaseOrderHead`
- `PurchaseOrderLine`
- `ReceiveHead`
- `ReceiveLine`
- `PackingListHead`
- `PackingListLine`
- `OutboundHead`
- `OutboundLine`
- `Inventory`
- `InventoryTransaction`
- `DemandExecutionLink`

当前服务和页面：

- `PurchaseOrderService`
- `ReceiveService`
- `PackingListService`
- 采购、入库、PackingList WPF 页面和 ViewModel。

当前状态：

- 采购、入库、PackingList 主要链路已有实现基础。
- 出库实体存在，但 API、Service、Repository、前端页面仍需继续打磨。
- PackingList 智能入库/出库和客供件扣减需要继续按总纲收束。

## 3. 采购单规则

采购单承接 `SupplyType = 采购` 的净需求。

采购头负责：

- 采购单号。
- 供应商。
- 采购日期。
- 币种、金额、状态。

采购行负责：

- `Sku`
- 客户 SKU。
- 采购数量。
- 已入库数量。
- 物料类型 `MaterialType`。
- 供给方式 `SupplyType`。
- 目标送达位置 `DeliveryTo`。
- 来源净需求关系。

规则：

- 采购单不直接从销售订单生成。
- 多个净需求可以聚合到一条采购行，但必须维护 `DemandExecutionLink`。
- 采购保存不等于入库。
- 采购行到货、入库、关闭等进度要回写净需求和执行链路。

## 4. 待入库规则

待入库来源于采购行和相关净需求执行情况。

待入库行应展示：

- 供应商。
- SKU。
- 客户 SKU。
- 采购数量。
- 已入库数量。
- 可入库数量。
- 物料类型。
- 送达仓库或供应商仓。
- 来源采购单和采购行。

规则：

- 可入库数量 = 采购数量 - 已入库数量，实际以业务字段为准。
- 客供件默认可以筛选独立入库。
- 入库选择器只负责选择待入库行，不直接过账。
- 入库详情页负责形成正式入库单。

## 5. 入库单规则

入库单负责把采购到货、客供件收货或系统自动入库落成正式业务单据。

入库头负责：

- 入库单号。
- 供应商。
- 入库日期。
- 是否过账。
- 过账人和过账时间。

入库行负责：

- SKU。
- 数量。
- 仓库、库位。
- 来源采购单行。
- 来源净需求或执行链路。

规则：

- 手动入库必须生成入库单。
- 系统自动入库也必须生成入库单。
- 未过账入库单可以编辑。
- 已过账入库单不能普通编辑数量。
- 入库过账生成库存流水并更新库存余额。
- 入库后回写采购行、净需求和 `DemandExecutionLink` 的入库进度。

## 6. 库存流水规则

库存流水是库存变动审计事实。

入库流水：

- `InQty > 0`
- 关联入库单头和行。
- 回写过账后库存数量。

出库流水：

- `OutQty > 0` 或负向变化。
- 关联出库单头和行。
- 回写过账后库存数量。

规则：

- `Inventory` 可以更新余额。
- `InventoryTransaction` 只新增，不普通修改或删除。
- 错误通过反向流水、红字流水或反过账处理。
- 库存流水不替代入库单、出库单或 PackingList。

## 7. 出库单规则

出库单负责正式扣减库存。

出库来源：

- PackingList 自动出库。
- 客供件扣减。
- 手工出库。
- 库存调整出库。

出库头负责：

- 出库单号。
- 出库日期。
- 业务类型。
- 来源单据。
- 是否过账。

出库行负责：

- SKU。
- 数量。
- 仓库、库位。
- 来源 PackingList、销售订单、净需求或客供件关系。

当前策略：

- 出库实体已存在。
- 后续实现必须补齐正式 Service、Repository、API 和前端页面。
- 在出库服务未完整落地前，不允许用 PackingList 直接写库存流水替代出库单。

## 8. PackingList 规则

PackingList 是外贸装柜出货箱单，代表供货生产环节的末端确认。

PackingList 保存：

- 箱单号。
- 客户和订单信息。
- 出货日期。
- 箱数、数量、重量、体积。
- 销售订单/采购/需求/BOM 相关来源字段。

PackingList 过账是业务命令。

过账时应：

1. 校验 PackingList 未过账。
2. 校验明细行完整。
3. 找到相关销售订单、净需求、采购行或 BOM 关系。
4. 判断相关物料是否已经入库。
5. 对未入库但业务上应视为完成的物料，生成自动入库单。
6. 对需要出货的物料，生成正式出库单。
7. 对客供件，根据父物料出货完成情况，从对应供应商仓扣减子物料。
8. 写入库存流水。
9. 回写 PackingList、需求、采购和执行链路状态。

失败时应返回明确原因，不静默过账。

## 9. 客供件闭环

客供件由 BOM 子物料 `MaterialType = 客供件` 识别。

客供件入库：

- 供应商或外部来源送到目标供应商仓。
- 系统收到通知后，可以手动入库到供应商仓。
- 入库必须生成正式入库单和库存流水。

客供件出库：

- 父物料通过 PackingList 完成出货后，系统判断对应客供件是否需要从供应商仓扣减。
- 扣减必须生成正式出库单和库存流水。

规则：

- 不写死 A 厂/B 厂角色。
- 流向由净需求、采购执行、供应商仓和 PackingList 行决定。
- 供应商虚拟仓可使用 `WhseCode = V_WH`，`LocationCode = SupplierCode`。

## 10. 自动入库 / 自动出库

自动动作也必须有正式单据。

自动入库：

- 由 PackingList 过账或业务命令触发。
- 生成入库头和入库行。
- 标记来源和自动生成原因。
- 过账并写库存流水。

自动出库：

- 由 PackingList 过账触发。
- 生成出库头和出库行。
- 标记来源 PackingList。
- 过账并写库存流水。

规则：

- 自动动作不能只更新库存余额。
- 自动动作不能绕过审计字段。
- 自动动作失败时应整体回滚或返回可处理的失败结果。

## 11. 改单、反过账、红冲边界

未过账采购单：

- 可按业务规则修改或删除。
- 修改后同步净需求执行数量和 `DemandExecutionLink`。

未过账入库单：

- 可编辑或删除。
- 不影响库存流水。

已过账入库单：

- 不普通编辑数量。
- 错误通过反过账、红冲或差异入库/出库处理。

已过账 PackingList：

- 不普通编辑会影响库存的字段。
- 需要反过账或红冲时，必须同时处理关联出库、自动入库和库存流水。

已产生库存流水：

- 不靠删除下游单据解决。
- 不靠修改历史行数量解决。

## 12. 页面设计

采购 Manager：

- 查询采购单。
- 打开采购详情。
- 查看执行和入库进度。

采购 Detail：

- 头行编辑。
- 采购行编辑。
- 由净需求带入来源关系。

待入库窗口：

- 按供应商和物料类型筛选。
- 选择待入库采购行。
- 返回给入库详情页。

入库 Manager / Detail：

- 查询入库单。
- 新建或编辑未过账入库单。
- 过账入库。
- 查看过账状态。

PackingList Manager / Detail：

- 查询箱单。
- 新建或编辑箱单明细。
- 选择未出货行。
- 执行 PackingList 过账。
- 显示过账结果和库存异常。

出库页面：

- 后续补齐。
- 应按正式出库单头行模式设计。

## 13. API 设计

采购：

- 查询分页。
- 保存详情。
- 获取详情。
- 查询待入库供应商。

入库：

- 查询分页。
- 查询待入库行。
- 保存入库详情。
- 入库过账。
- 查询入库头和行。

PackingList：

- 查询分页。
- 查询未出货行。
- 保存详情。
- 过账。

出库：

- 后续新增查询、保存、过账、反过账接口。

规则：

- 过账必须是显式命令 API。
- 自动入库、自动出库由 Application Service 编排。
- Controller 不写库存逻辑。
- API 返回应包含影响单据、库存异常、是否需要用户确认等信息。

## 14. 验收场景

采购：

- 净需求转采购生成采购头行。
- 多净需求聚合采购行时写入执行链路。
- 修改未过账采购行能回写需求执行数量。

入库：

- 选择待入库行生成入库单。
- 入库过账生成库存流水。
- 库存余额增加。
- 采购行和净需求已入库数量回写。

PackingList：

- 保存 PackingList 明细。
- 过账未入库物料时自动生成入库单再出库。
- 过账已入库物料时生成出库单。
- 客供件从供应商仓扣减。
- 每个库存动作都有库存流水。

异常：

- 库存不足时返回明确错误或需要确认的结果。
- 来源关系缺失时拒绝过账。
- 已过账单据禁止普通编辑。
