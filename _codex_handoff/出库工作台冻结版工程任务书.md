# SwiftExport 出库工作台冻结版工程任务书

## 1. Codex 新任务启动提示词

> 请先完整读取本任务书和同目录《库存履约下游专项总索引》《供应商虚拟仓与库存冻结版工程任务书》《入库工作台冻结版工程任务书》《PackingList工作台冻结版工程任务书》，再读取净需求说明、根目录 `AGENTS.md`、路由、workflow/skill 和真实源码。旧 `Outbound/Stock` C# Entity、DTO、API、Service、Repository 已清理，不得恢复；新 `OutboundDocument` 专用模型优先映射现有 `OutboundHead/Line` 物理表。新出库只能通过统一库存过账服务扣减库存；先只读审计和决策完整计划，默认不执行共享数据库迁移。

## 2. 业务目标

出库工作台记录“某种货物从某个供应商虚拟仓被正式移出”的事实。首期支持：

- 最终客户发货：PackingList 提交并过账后，成品从执行供应商虚拟仓发往最终客户。
- 客供件耗用：父件成品发货时，按净需求拆解快照从父件执行供应商虚拟仓扣减客供件。
- 特殊负库存异常出库：只为保证极少数录单错误尚未纠正但不能耽误出货的业务，需特殊授权。
- 反过账：在下游事实允许时用反向单据纠错。

页面“最终客户已发货数量”必须来自已过账最终客户出库净额，而不是 PackingList 草稿数量。

## 3. 已冻结业务规则

- 出库草稿不改变库存；“提交并过账”才扣减。
- 最终客户发货首期只允许由 PackingList 过账内部创建，不提供绕开 PackingList 的普通手工发货入口。
- 客供件耗用数量来自毛需求拆解时形成并保留的净需求/Allocation 快照比例，不读取当前 BOM 重新计算历史订单。
- 客供件扣减仓库是父件 A 当前执行供应商的虚拟仓，不是客供件采购供应商 A 的仓库。
- 一条出库行必须能追溯到一个 PackingList 需求贡献或一条客供件 Allocation 贡献；不得只按 SKU 聚合后丢失销售来源。
- 正常出库必须有足够库存。负库存不是一个勾选框，而是独立异常命令、独立交易类型、特殊权限、必填原因和强警告。
- 负库存异常允许放行业务，但必须把不足数量、仓库、SKU、来源销售单和操作者写入业务日志，供后续纠错。
- 已过账出库不可普通编辑、删除或作废；反过账生成相反库存流水并保留原事实。
- 如果最终客户发货已经被外部出口/财务流程引用，未来应阻断反过账；首期至少检查 PackingList 当前状态和库存后续流水。

## 4. 出库类型与状态

冻结 `OutboundDocumentType`：

- `FinalCustomerShipment=20`
- `CustomerSuppliedConsumption=21`
- `NegativeStockException=90`

冻结 `PostingStatus`：`Unposted=0, Posted=1, Reversed=8`。生命周期沿用 `Active=0, Closed=8, Voided=9`。

交易类型 90 只标识实际允许负库存的异常行；同一单据中库存充足的普通行继续使用正常类型，便于审计。

## 5. 业务流程

### 5.1 PackingList 最终客户发货

1. PackingList Preview 生成逐需求贡献的成品出库计划。
2. 对尚未入库的成品，PackingList 先自动补正式入库。
3. 锁定出库来源、仓库和库存余额。
4. 生成 FinalCustomerShipment 出库头行、扣减库存、写流水和业务日志。
5. PackingList、自动入库、最终出库、客供件耗用必须在同一事务全成全败。

### 5.2 客供件耗用

1. 根据 PackingList 每条成品需求贡献定位毛需求拆解快照和相关 B Allocation。
2. 按快照单位比例 × 本次成品发货贡献计算理论耗用量，数量精度统一为 decimal(18,4)。
3. 依据历史已过账客供件耗用净额计算本次剩余，避免分批发货重复扣减。
4. 从父件执行供应商虚拟仓扣减。
5. 数量不足时作为 Blocker；用户只能通过独立负库存异常预览/授权后重新执行。

### 5.3 负库存异常放行

- Preview 明确列出正常可扣量、不足量和预计负余额。
- Request 必须包含原 Posting CommandId、新的 OverrideCommandId、已确认警告代码、原因和 ExpectedVersion。
- Application 校验 `Inventory.NegativeStock.Override` 权限。
- 只允许对当前 PackingList 命令中被库存不足阻断的行放行，不提供任意 SKU 手工负数接口。

### 5.4 反过账

- PackingList 生成的最终出库和耗用出库由 PackingList 反过账编排，普通出库页面只提供预览和跳转。
- 反向顺序为：最终客户出库/耗用出库反向 -> 自动入库反向 -> PackingList 状态反向。
- 反向后库存流水保留，原出库单标记 Reversed。

## 6. 目标数据模型与现有表映射

- `OutboundDocument` 映射 `dbo.OutboundHead`，复用 OutboundNo/Date、BizType、SourceType/No、WarehouseCode、LocationCode、Handler、IsPosted、PostedDate/By、Remark。
- `OutboundDocumentLine` 映射 `dbo.OutboundLine`，复用 LineNumber、OutboundId/No、Sku、Qty、Unit、仓库编码、SourceType/No/LineId、RefNo、Remark。
- 只追加 ProductId、WarehouseId、分层状态、PackingList/Allocation/Link Uid、异常放行、CommandId/ItemId 和反向关系等缺失字段。
- 不新建第二套 Outbound 头行表。遗留行只读，新行由专用仓储写入并以新增字段识别。

### 6.1 OutboundDocument

| 字段 | 说明 |
|---|---|
| Uid / Version / 审计字段 | 身份、并发、审计 |
| DocumentNo | 人工可读编号 |
| DocumentType | 冻结出库类型 |
| LifecycleStatus / PostingStatus | 分层状态 |
| WarehouseSiteId | 来源仓 Uid |
| Warehouse/Supplier 快照 | 历史展示 |
| ShipmentDate | 业务发货/耗用日期 |
| CustomerId / CustomerCode/NameSnapshot | 最终客户发货时填写 |
| SourcePackingListId | PackingList 生成时必填 |
| PostedDate / PostedBy | 过账事实 |
| ReversedDate / ReversedBy / ReverseReason | 反过账事实 |
| CommandId | 幂等范围 |

### 6.2 OutboundDocumentLine

| 字段 | 说明 |
|---|---|
| Uid / OutboundDocumentId / LineNumber | 稳定行身份 |
| ProductId / Sku/Description/UnitSnapshot | 产品关系和快照 |
| Quantity | 正数业务数量，`decimal(18,4)` |
| TransactionType | 20、21 或 90 |
| SourceType / SourceUid | PackingListContribution 或 NetDemandAllocation |
| PackingListLineId / PackingListContributionId | 成品发货来源 |
| NetDemandAllocationId / DemandExecutionLinkId | 客供件/采购追溯 |
| GrossDemandId / SalesOrderNo/LineNumberSnapshot | 业务来源快照 |
| IsNegativeStockOverride / OverrideReason | 异常放行事实 |
| OriginalLineId | 反向行关联 |
| Version / 审计字段 | 并发与审计 |

每一正常行对应一条负向 InventoryLedgerEntry；反向行产生正向 Reversal 流水。

## 7. 数量守恒

- 最终已发货量 = FinalCustomerShipment 有效过账量 - 对应反向量。
- 客供件已耗用量 = CustomerSuppliedConsumption/90 有效过账量 - 对应反向量。
- 分批 PackingList 的本次耗用不能使累计耗用超过该需求贡献的快照应耗量；尾差按最后一次发货吸收，规则必须在 PreviewBuilder 中单元测试冻结。
- 同一个 PackingListContribution 只能成功过账一次；CommandItemId 建唯一约束。
- 出库后 InventoryBalance = 过账前余额 - Quantity；90 类型允许结果为负，其他类型不允许。

## 8. Application 服务与事务

新建 `IOutboundWorkspaceService`：Search、Detail、PostPreview（内部/异常场景）、Post（内部）、NegativeOverridePreview、NegativeOverridePost、ReversePreview、Trace。

PackingList 使用一个专用内部端口批量构建并写入出库，不通过 HTTP 自调用。

锁序：

1. PackingList/OutboundDocument。
2. PackingListContribution、Allocation、Link，按 Uid 排序。
3. 已过账入库/出库贡献范围。
4. WarehouseSite。
5. InventoryBalance，按统一库存键排序。
6. Command/Override 幂等范围。

业务事务成功时写 BusinessOperationLog；负库存异常额外写结构化不足详情。

## 9. Repository 与兼容边界

- `IOutboundDocumentRepository`：头行插入、ForUpdate、状态/反向更新。
- `IOutboundSourceRepository`：锁 PackingListContribution/Allocation，查询历史耗用净额。
- `IOutboundQueryRepository`：Search、Detail、Trace、最终发货汇总。
- 禁止任何仓储直接更新 InventoryBalance；统一调用 PostingService。
- 遗留 `OutboundHead/Line` 行保持只读；同一物理表中的新行由专用仓储写入。`InventoryTransaction` 继续作为统一库存流水物理表。迁移 preflight 只能回填可证明的 PackingList/销售来源，不能按单号或 SKU 猜测。
- 新最终已发货查询在切换前可将可证明遗留事实单独标注展示；新命令不能操作不可证明遗留单据。

## 10. HTTP/Refit 契约

基址 `/api/inventory/outbounds`：

- `POST /search`
- `GET /{uid}`
- `GET /{uid}/trace`
- `POST /negative-stock/preview`
- `POST /negative-stock/post`
- `POST /{uid}/reverse-preview`

普通最终客户发货和耗用出库不提供公共 Create/Post 路由，由 PackingList API 编排。若未来新增手工调整，必须另立专项，不复用负库存入口。

## 11. WPF 工作台

Shell“库存”下新增“出库工作台”：

- 服务端分页；按单号、类型、状态、日期、供应商仓、客户、PackingList、销售订单号和 SKU 筛选。
- 以只读查询、Detail、Trace 和反过账预览为主。
- 最终发货和客供件耗用明确使用不同颜色/标签，不混为同一数量。
- 负库存异常只能从 PackingList 失败结果进入专用弹窗，显示预计负余额、权限、原因和警告确认。
- 已过账单据不显示编辑/删除命令；反过账由 PackingList Trace 入口发起。

## 12. 分阶段实施

### Phase 0：只读审计

- 审计遗留 Outbound/InventoryTransaction、PackingList 关系和旧已发货口径。
- 输出可证明/不可证明来源清单与 009+ preflight。

### Phase 1：Contracts、现有表扩展与内核

- 实现专用实体、DTO、枚举、仓储并映射/最小扩展 `OutboundHead/Line`，完成正常出库和库存不足测试。

### Phase 2：客供件与异常放行

- 实现拆解快照耗用、分批尾差、90 类型权限和审计。

### Phase 3：PackingList 集成与 WPF

- 完成内部批量端口、工作台查询、Trace 和反向入口。

## 13. 测试与验收

至少覆盖：

- PackingList 草稿不出库，过账后最终客户已发货量准确。
- 成品供应商仓正确；多供应商 PackingList 分头出库但整体事务一致。
- 客供件 A 采购、B 仓耗用；按拆解快照而非当前 BOM 计算。
- 分批发货、decimal 尾差、累计不超量和重复命令幂等。
- 库存不足正常阻断；无权限/无原因不能放行；授权后仅不足行写 90 类型。
- 任一出库/耗用失败，PackingList、自动入库、余额和流水全部回滚。
- 反过账生成反向流水并恢复最终已发货净额。
- 按销售订单号 Trace 到 PackingList、成品出库和客供件耗用。

## 14. 明确不做

- 脱离 PackingList 的普通客户发货。
- 销售退货、采购退货、调拨、报废和盘亏。
- 物流轨迹、提单、报关和财务出口确认。
- 自动掩盖负库存或后台静默补库存。
