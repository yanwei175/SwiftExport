# 销售订单工作区后端与数据库交接

## 本轮边界

新客户端、Contracts 契约和 WebApi 路由占位已经建立。本轮没有修改 `SwiftExport.Application`、`SwiftExport.Core`、`SwiftExport.Infrastructure`，也没有执行数据库变更。

WebApi 的 `/api/sales-orders/workspace/**` 当前统一返回带有“后端尚未实现”说明的失败 `ServiceResult`，禁止临时转调旧销售订单服务。没有使用 `NotImplementedException`，因为现有全局异常中间件会遮蔽异常信息，导致客户端只能看到“系统繁忙”。旧服务仍包含旧状态模型，直接复用会把 `SalesOrderStatusEnum` 重新带回新链路。

## 唯一状态模型

- `SalesOrderDocumentStatusEnum`：`Open`、`Closed`。
- `ConfirmationStatusEnum`：`待确认`、`已确认`，是唯一业务放行动作。
- `SalesOrderFulfillmentStatusEnum`：按真实发货数量查询计算，不落销售订单头。
- 不设置审批状态；不把 BOM 拆解、净需求或采购进度写回销售订单状态。
- 新代码不得映射或引用 `SalesOrderStatusEnum`。旧枚举文件暂留仅为旧项目编译，待旧链路迁移后删除。

## 保存与状态命令

### 保存

- 只允许 `DocumentStatus=Open` 且 `ConfirmationStatus=待确认`。
- 所有头、行写入和删除行必须处于同一事务。
- 头和已有行均使用 `Version` 乐观并发；冲突时返回可识别的并发错误，不静默覆盖。
- 服务端忽略客户端提交的行号并按有效行顺序重新编号，或严格校验行号唯一性，二选一后固定。
- 服务端必须根据行 `Uid` 重新生成非标 SKU，不信任客户端提交值。

### 确认

- 确认必须幂等。同一订单、同一版本重复请求不能重复生成毛需求。
- 在一个事务内：校验订单、更新确认状态、为每个有效订单行创建或同步一条 `IndependentDemand`。
- 标准行和非标行都必须生成毛需求；不得因 `ProductId IS NULL` 跳过非标行。
- 确认过程禁止查询或拆解 BOM。BOM 拆解仅由后续需求工作台执行。
- 建议以活动记录 `(SourceType, SourceLineId)` 唯一约束作为最终幂等保障。

### 取消确认

仅当本订单产生的毛需求均未被拆解，并且不存在净需求、采购、生产、收货、出货或其他执行记录时允许。取消时在同一事务撤销或软删除对应毛需求并恢复 `ConfirmationStatus=待确认`。

### 关闭与删除

- 关闭保留订单和全部历史，只把 `DocumentStatus` 设为 `Closed`。
- 删除只允许未确认、未关闭草稿，并遵循当前项目软删除规范。

## 非标件不可遗漏的链路

非标销售订单行：

```text
IsNonStandard = true
ProductId = null
Sku = NonStandardSkuGenerator.Create(LineUid)
CustomerSku = 客户型号（可空）
DescriptionEn = 必填
Qty > 0
```

临时 SKU 固定为 `非标件-{订单行Uid前12位大写N格式}`。不得创建临时 Product，也不得允许非标行原地切换成标准行。

确认生成毛需求时至少保留：

```text
IsNonStandard = true
SourceType = SO
SourceUid = SalesOrder.Uid
SourceLineId = SalesOrderLine.Uid
SourceSku = CustomerSku
Sku = 非标临时SKU
Description/ColorName/Features = 订单行历史快照
OriginalQty = Qty
HopefulDate = 行交期 ?? 订单交期
```

需求工作台遇到 `IsNonStandard=true`：

- 不查 Product、不校验 BOM、不递归拆解。
- 直接生成一条采购型 `DependentDemand`，`SupplyType` 固定为采购。
- 允许 `ProductId=null`，继续传递临时 SKU、客户型号、描述、颜色、规格、订单 Uid 和订单行 Uid。
- 采购工作台、采购保存和后续追溯必须接受这种无产品主数据的需求，不能按标准产品校验将其过滤。

## 数据库迁移顺序

1. 先执行只读预检查，输出空 Uid、重复行号、标准/非标关联冲突、重复毛需求和已经存在下游执行的数据。
2. 只做兼容性新增：新状态列、逻辑关联列、索引所需辅助字段。此阶段保留旧列。
3. 部署新 Application/Repository 并完成新旧数据回填。
4. 经过测试环境全链路验收后，才允许添加强约束和过滤唯一索引。
5. 所有旧调用移除后，另开迁移删除 `OrderStatus`、`ApprovalStatus`、`VersionNo`、`IsLocked` 和 `SalesOrderStatusEnum`。

严禁在 Application 尚未切换时执行删列阶段。建议 SQL 草案见同目录 `销售订单工作区数据库迁移草案.sql`。

## 验收清单

- 确认一次和重复确认均只保留每行一条活动毛需求。
- 取消确认遇到任一下游记录必须拒绝，并且不产生部分修改。
- 两条非标行的临时 SKU 不重复，重新加载后稳定。
- 非标行不在 Product 表创建记录，仍可进入毛需求、采购型净需求和采购流程。
- 订单、订单行、毛需求、净需求能通过 Uid 全链路追溯。
- 新工作区服务、映射、SQL 中均不存在 `SalesOrderStatusEnum`。
