# SwiftExport 客户端部署与更新

当前实现：进程启动后自动检查，Shell 右上角提供手动检查、下载进度及重启更新。自动检查只提示，下载和重启由用户选择。后端最低版本限制继续生效；旧版本在登录前提供更新窗口，关闭窗口则退出。开发目录运行会跳过包更新，使用安装包或 Velopack 便携目录后才可验证真实更新。

## 第一次发布

开发电脑可以直接双击同目录的 `一键打包客户端.cmd`。首次运行确认更新地址和 API 地址；以后回车沿用上次设置。版本默认在最新发布版本基础上递增补丁号，可手动输入更大的版本。填写一行更新说明或留空后，自动还原工具、编译 Release、生成安装器、完整包及差量包，完成后打开 Releases 目录。窗口会保留结果，不会一闪而过。

本机地址记在 `bin/Velopack/打包设置.json`，日志在 `bin/Velopack/Logs`，更新说明在 `bin/Velopack/Notes`，均不进入版本控制。不要清空 Releases，否则会失去本机递增版本及差量基础；失败残留的包也会保留其版本号，下一次自动建议更高版本。两个打包同时运行时会拒绝后进入的一次。

无交互自动化入口（无需手动输入，默认沿用地址并自动递增）：

```powershell
& .\SwiftExport.Client.Wpf\Deployment\一键打包客户端.ps1 `
  -NonInteractive -NoOpenFolder -Notes '修复 BOM 翻页及调整产品展示'
```

也可用 `-Version`、`-UpdateUrl`、`-ApiUrl` 显式覆盖。失败返回非零退出码，发布流程可据此停止。双击入口使用 Windows 自带 PowerShell 5.1；开发电脑仍需安装 .NET 10 SDK。工具完成本地打包，服务器复制和更新索引切换仍按下文执行。

在仓库根目录运行（示例地址来自当前配置，部署前确认服务器实际地址）：

```powershell
& .\SwiftExport.Client.Wpf\Deployment\打包客户端.ps1 -Version 0.1.0 `
  -UpdateUrl 'https://192.168.3.12/client-updates/' -ApiUrl 'https://192.168.3.12'
```

输出在 `SwiftExport.Client.Wpf/bin/Velopack/Releases`，采用 Windows x64 自包含发布，终端无需另装 .NET 10。Velopack 依赖和 vpk 使用固定版本，业务及后端兼容检查使用安装包实际版本，发布脚本同步配置中的旧版本字段。

1. 在服务器建立 `D:\ClientUpdates`，仅授予 Caddy 服务账号读取权限。不要使用图片和附件目录 `D:\ERPFiles`。
2. 将 `Caddy更新目录配置片段.txt` 合并到现有站点；保持原 `tls internal`、CA 存储及端口。先执行 Caddy 配置验证，再按现有服务运维流程重载。本脚本不自动操作服务器。以后用现有 Caddy 生成脚本重建配置时，必须保留此路由。
3. 上传 Releases 中的安装器、`.nupkg` 和 `releases.win.json`。保持文件名原样，URL 必须可以直接访问文件，无登录页、重定向到业务 API 或鉴权 Token。
4. 用户访问 `https://192.168.3.12/client-updates/SwiftExportClient-win-Setup.exe` 首次安装，之后从快捷方式运行。

安装与更新使用同一 HTTPS 目录。终端仍须信任当前 Caddy 根证书；HTTPS 证书不等于 Windows 代码签名。当前脚本没有代码签名，内网可部署，Windows 的发布者/信誉提示依策略仍可能出现。无需手工编写注册表，快捷方式和卸载信息由安装器管理。默认按用户安装；自定义位置可通过安装器的 `--installto <完整目录>` 指定，必须保留完整安装目录结构，更新器会更新原位置。

## 后续频繁更新

使用递增的版本号再次运行脚本，例如 `0.1.1`，可加 `-ReleaseNotes 'D:\说明\更新说明.md'`。保留本地 Releases，vpk 可根据旧完整包生成差量包。不要直接把普通 build 输出复制到服务器。

先上传所有新包，再上传新 Setup，最后用临时文件加同目录重命名原子替换 `releases.win.json`。可替换 Setup 前也先上传到临时文件，避免下载读到半个文件。保留旧版本包，防止客户端先读取旧索引后下载时文件已被删除。发布失败时不要替换索引。

应用打开时每个进程自动检查一次；运行期间通过右上角手动检查。检查/下载互斥，关闭更新窗口会取消检查结果接纳或下载；失败保留版本信息，可重试。已下载包下次启动仍可提示应用。重启前逐页调用编辑提交和离开确认，初始化、保存中或用户拒绝时停止重启，页签保留。没有离开协议的脏页面要求先完成编辑。更新时不默认丢弃草稿。

安装目录内的文件会随更新替换，不要把用户数据写入此目录。现有登录 Token 在 AppData、图片缓存在 LocalAppData，更新不依赖安装目录保存它们。API 地址和更新地址由发布脚本固定；不要在安装目录里长期手动修改运行配置。

## 上线验收

首次部署至少在一台测试终端安装 `0.1.0`，发布 `0.1.1` 后验证启动提示、手动检查、取消下载、下载进度及重启后真实版本；再测试断网、未保存 BOM 编辑拒绝重启和保存中拒绝重启。确认更新 URL 的 `releases.win.json` 返回 JSON 和包可下载，图片/API 路由正常。人工检查纯键盘 Tab/Enter/Esc、200% 缩放和高对比度下的更新窗口。

参考：[Velopack 集成](https://docs.velopack.io/integrating/overview)、[静态目录发布](https://docs.velopack.io/distributing/overview)、[安装路径](https://docs.velopack.io/packaging/installer)、[Caddy file_server](https://caddyserver.com/docs/caddyfile/directives/file_server)。
