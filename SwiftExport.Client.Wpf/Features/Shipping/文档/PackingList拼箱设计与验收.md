# PackingList 拼箱设计与验收

更新：2026-09-22。拼箱代码已贯通实体、草稿契约、保存查询和 WPF；数据库增量尚未执行，不能直接在未迁移库启用。

## 数据口径

- 只给 PackingListLine 增加可空 PackingGroupId，不新增表、空行或强外键。每条持久化行仍有真实 GrossDemandId。
- null 为普通包装；同一箱单内同一非空标识表示一只拼箱。同组成员行号连续，不允许组标识跨箱单复用。
- 拼箱成员保留独立数量、产品、来源、PO、Invoice 和备注。每箱数量规范化为本行数量，箱数为一。
- 同组重复保存相同净重、毛重、体积和箱唛；包装小计是共享指标副本，禁止直接跨成员 SUM。整单统计按每条普通行及每个拼箱分别计算一次。
- 单据数量、交付、发票号仍按真实行汇总，数量按单位分别统计。未知包装指标保留 null，页面同时显示已知部分和未填写提示。
- 查询仍返回平铺行，GroupStyle 只作 UI 展示。不存在组主行或组 CRUD API。

## 使用方式

1. 点击“新增拼箱”，目标组下拉选中该组。空组只存在客户端，会提示未保存，不能直接保存。
2. 点击“获取”加入来源，或者选中已有产品行后“移入选中拼箱”。部分尾数先使用现有拆尾箱。
3. 组头填写共享净重、毛重、体积和箱唛。各成员自行填写出货数量，共享指标不允许在产品单元格独立编辑。
4. “移出拼箱”恢复为普通单箱，不改变数量和来源，不合并其他行。移入/移出均先确认清空包装指标。
5. 成员增加、删除、转移或数量变化，受影响组净重/毛重/体积清空；目标箱唛保留。非空组不能直接删除，须先移出/删除成员，再删除空组。
6. 普通行与组按块移动，成员仅能组内移动。单据只读时不可改组。排序继续禁用；含拼箱时禁用通用 Grid 填充操作，避免绕过共享字段编辑边界。
7. “普通行模式”清除添加来源的目标组。取消保存、网络失败保留现有编辑，撤销恢复原组归属、顺序、包装资料并清除临时空组。

例：A101、B11，每箱10；A100为10箱、B10为1箱、A1和B1混装1箱。四条真实行，共12箱，A/B出货数量不变。

## 保存、锁与过账

- 原有头行版本、状态、显式删除及整单事务不变。服务端校验共享字段一致性，重算箱数/小计，不选择某个成员覆盖冲突。
- 命令重放优先；新命令先按排序后的组标识取得事务应用锁并检查其他箱单归属，再进入原来源和箱单锁流程。
- 保存已有单据先在同一事务内把旧有效行移到空闲临时正行号，再持久化最终顺序，避免交换行号触发唯一索引；删除行恢复原行号并软删除。失败整体回滚。
- 组标识进入草稿指纹。过账令牌原本序列化完整头行事实，组归属/包装/版本变化自然使旧预览失效。
- 采购容量、成品库存和客供件分配仍读取真实产品行，未修改库存内核、出入库 Port 或整单反向算法。
- 第三阶段行撤销/正常补记没有在本轮实现。
