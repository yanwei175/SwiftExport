# 设置页面与表单职责整理实施计划

## 目标与约定

统一为“页面命令 → 模块用例 Dialog 服务 → 公共 IDialogService.ShowAsync → finally 清理”的调用方式。参考 `Features/DemandPlanning/NetDemand/Services/NetDemandDialogService.cs`，不是新增公共弹窗框架。

本任务由 GPT-6 Sol、medium 推理强度在现有工作区实施。先读取 AGENTS、路由、前端工作流以及适用的 MVVM、页面架构、文件组织、运行时安全和验收 Skill。用户已授权实施以下全部范围；业务语义有歧义才询问，不凭猜测修改规则。

仅修改 WPF 客户端、直接相关测试和本说明。保留所有已有未提交修改，不提交、重置或回退。不改后端、Contracts、数据库、密码协议、权限规则、官方控件样式或其他 Feature。已有 App.xaml、TextBoxes.xaml、RoleManagementView.xaml 等包含其他修改，必须以当前源码为基线精准调整。

## 一、页面容器归位

- `Workspace` 改为 `Page`，`SystemSettingsWorkspaceViewModel` 改为 `SettingsPageViewModel`；保留 `SystemSettingsView` 名称，迁入 `Page/Views`。迁移 namespace、DI、DataTemplate、调用方和测试，不保留旧壳。
- 保留 `system-settings` 路由、标题“设置”、单页签身份、默认个人概览和现有 NavigationView。不要新增 Frame、恢复 SettingsCenter 或改变菜单层级。
- 页面 ViewModel 负责页面选择、按需创建页面模型、读取权限、活动表单门禁、字典编辑提交和页签生命周期。View 仅负责 NavigationView 呈现、控件事件到命令的必要桥接及 DataGrid 编辑提交。
- 移除从页面 ViewModel 暴露给 View 的 Dialog 服务、表单工厂及 `ShowChangePassword` 回调；code-behind 不再创建、初始化和展示业务表单。保留确有控件依赖的编辑提交回调，并完整解绑。

## 二、模块 Dialog 用例服务

- 在 `SystemSettings/Services` 建立 `ISettingsDialogService` 与 `SettingsDialogService`，页面/列表 ViewModel 注入接口。每个设置页签拥有独立实例，由页签关闭时释放；不能用持有活动表单状态的全局 Singleton。
- 提供具名方法：本人改密、创建用户、重置指定用户密码、编辑用户资料、分配用户角色、创建角色、编辑角色资料、分配角色权限。目标用现有 DTO/身份与版本传递，不传整个列表 ViewModel 或 View。每次打开创建新的表单模型，禁止复用旧编辑状态。
- 每个方法清楚展示：创建模型 → 初始化目标 → 创建 View/DataContext → 构造 DialogOptions → 调公共 ShowAsync → 提取成功结果 → finally Dispose。失败或取消也清理；初始化期间即登记活动状态，避免双开。
- DialogOptions 继续使用现有 PrimaryButtonCommand，保存由 ContentDialog 主按钮触发；不新增 IDialogPrimaryAction、宿主、消息服务或通用 Dialog 基础类。
- 使用一个模块内简单结果类型表达“是否保存成功、目标 ID、必要的创建用户名”；列表仅在确认成功且会话仍有效时重新读取并定位，不通过共享 SuccessfulWriteRevision 推断结果。密码方法无需给列表返回业务结果。
- 服务提供只读活动状态及变化通知，支持会话失效/目标失去操作资格时强制关闭活动表单。调用者据此保护页签关闭。初始化中的迟到结果也必须失效，不能在撤权或注销后重新打开表单。
- 正常关闭失败保留表单；强制关闭立即清理敏感输入并忽略迟到响应。主动密码修改成功仍结束旧凭据会话；旧请求不得结束切换后的新会话。

## 三、表单与列表真正分工

- 用户资料、用户角色、角色资料（创建/编辑）、角色权限继续放在现有 Users/Roles 的用例目录；创建用户、Passwords/Change、Passwords/Reset 保持各自目录。
- 各 FormViewModel 拥有自己的目标身份、版本、编辑字段/勾选集合、验证、保存命令、Busy、错误反馈、脏状态和成功结果。不能继续通过 `Model.*` 绑定共享 RbacManagementViewModel 的整套编辑字段，不能复制一套状态后又委托旧宽模型保存。
- 将现有 RBAC 查询/列表状态按 Users/Query、Roles/Query、Permissions/Query 归位为窄页面模型。用户启停留在用户列表，角色启停/删除留在角色列表。把现有 RBAC 宽模型中对应代码迁移过去，完成消费者迁移后删除旧宽模型及只负责转发的 RbacFormViewModel；不制造新万能 Manager。
- 保持原 API、版本、管理员/系统角色约束、本人权限刷新、错误提示和并发判断。用户角色与角色权限保存仍提交完整集合，搜索筛选只能影响显示。保存失败不覆盖用户输入；写入期间冻结对应编辑。
- 列表选择与弹窗草稿彼此独立；取消表单不能污染列表或另一个表单。成功后列表读回最新数据；读回失败显示读取错误，不再次执行写命令。
- 不为这些客户端编辑引入后端命令协议。可直接沿用现有 Refit 和 IApiCallRunner，不新增仅转发 API 的服务层。

## 四、共享关闭交互

- `SettingsFormState` 移入 `Forms/ViewModels`，继续只负责关闭准入、放弃提示和关闭意图；业务验证/保存放在具体表单模型。
- 在 `Forms/Views` 用一个轻量 XAML 内容包装控件承载正文与“继续编辑/放弃变更”提示，替代 SettingsFormDialogSession 中的 C# 拼控件。不产生新 ContentDialogHost。
- 删除 SettingsFormDialogSession；展示与 finally 清理由模块 Dialog 服务负责。所有表单正文保留右上角关闭命令，无内部重复保存按钮；View 仅保留绑定、焦点和 PasswordBox 读取清理。
- 当前表单上不弹嵌套确认框。切页、关闭、撤权、注销仍使用同一关闭状态，不通过 Unloaded 销毁页签持有的模型。
- 无管理权限仍可进入个人设置；管理权限全撤销清理管理数据、关闭管理表单并回个人概览，保留个人功能。注销/账号切换释放整个页签。不要让刷新权限无条件关闭仍有资格的个人表单。
