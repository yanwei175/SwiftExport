# 客户端公共文件服务

服务属于 `SwiftExport.Client.Wpf`，在 .NET 10 客户端内部完成 XLSX/CSV 读取和 XLSX 模板生成。无需 VSTO、Office COM、Excel 安装或正在打开的工作簿。生成后的公式由用户的 Excel 打开时计算。

当前依赖固定为 ClosedXML 0.105.1、ClosedXML.Report 0.2.12、CsvHelper 33.1.0。ClosedXML 和 ClosedXML.Report 使用 MIT，CsvHelper 声明 Apache-2.0 / MS-PL 双许可证；分发时遵守相应许可证并保留第三方声明。库升级时应运行本目录能力对应的真实文件测试。

## 服务与职责

调用方通过构造函数注入以下接口。基础生成和读取服务通过 `AddClientFileServices()` 独立注册；服务器模板入口通过 `AddServerExcelTemplateService()` 注册，并要求已有认证、API 和命名 HTTP 客户端。完整客户端启动同时接入这两组注册。

| 接口 | 输入 | 输出 |
| --- | --- | --- |
| `IExcelReadService` | XLSX 流、显式工作表名、平表或地址布局选项 | 工作表名称、平表快照或字段布局快照 |
| `ICsvReadService` | CSV 流、编码、分隔符及表头选项 | 保留字段原始字符串的平表快照 |
| `IExcelTemplateExportService` | 受控 XLSX 模板流、命名变量、输出流或本地路径 | XLSX 文档 |
| `IServerExcelTemplateService` | 数据契约、选中的服务器模板 ID/版本、稳定单据数据、本地输出路径 | 在线模板列表或 XLSX 文档 |

基础文件服务不访问业务 API、读取配置 DTO、DataGrid 或页面 ViewModel。服务器模板入口只访问模板目录和受保护的模板正文，不查询业务数据。公共服务不匹配客户/产品，不反射给业务模型赋值，也不解释拼箱规则。业务 Feature 将原始快照转换成自己的导入模型，完成匹配、错误展示和提交；导出时提供稳定的单据数据。箱单的拼箱关系、组内共享指标和实际箱数语义仍由业务模块表达，模板只消费确定的组与明细结构。

首期仅支持 `.xlsx/.csv` 导入及 `.xlsx` 导出，不支持 `.xls/.xlsb/.xlsm`、PDF 或 CSV 导出。不提供文件选择弹窗、用户模板管理、模板设计器或自动业务模板选择。

## 读取 XLSX

`InspectAsync` 列出工作表名。读取必须显式提供工作表，不自动采用第一张、活动工作表或服务端配置中的参考名称。

```csharp
// source 是调用方持有的可读流；InspectAsync 会从当前位置读到结尾。
var info = await excelReader.InspectAsync(source, cancellationToken: token);
var selectedWorksheet = info.WorksheetNames[0]; // 实际页面由用户明确选择。
source.Position = 0; // 非定位流应另开输入流，服务不会自动回退。
var table = await excelReader.ReadTableAsync(source, selectedWorksheet,
    new ExcelTableReadOptions
    {
        HeaderRow = 1,
        DataStartRow = 2,
        FirstColumn = 1,
        LastColumn = 6,
        Culture = CultureInfo.GetCultureInfo("zh-CN"),
    }, cancellationToken: token);
```

平表保持列顺序和原始行列，不把表头当成唯一字段键。空、重复表头和中间空行均保留；末行、末列按内容确定，仅样式空尾不扩大结果。业务需要更复杂的单头与明细布局时使用地址读取：

```csharp
var layout = new ExcelLayoutDefinition
{
    Fields =
    [
        new ExcelLayoutField("Customer", "B2", false),
        new ExcelLayoutField("DocumentDate", "F2", false),
        new ExcelLayoutField("ProductCode", "B6", true),
        new ExcelLayoutField("Quantity", "E6", true),
    ],
    EndMode = ExcelLayoutEndMode.LastNonEmptyColumn,
    LastRowColumn = "B",
};
var result = await excelReader.ReadLayoutAsync(source, "单据", layout, cancellationToken: token);
var customerCell = result.Header["Customer"];
var firstQuantityCell = result.Rows.Count == 0 ? null : result.Rows[0]["Quantity"];
```

`FieldKey` 只是结果关联标识，可以由 Feature 映射到配置中的字段键；公共服务不解释属性路径。字段地址必须是单个 A1 地址，允许绝对标记；所有向下字段从同一行开始。

结束规则二选一：

- `LastNonEmptyColumn`：在 `LastRowColumn` 列找末个非空缓存值。空白文本不延长明细，数值零和错误值算有内容；空缓存公式附诊断，不自动重算。
- `BeforeSummaryCell`：设置 `SummaryCellAddress`，读取至该地址所在行的前一行。地址必须在明细起点之后，不搜索“合计”等文字。

固定字段落在合并区域内时读取左上角，`Address` 保留请求地址，`SourceAddress` 指向实际取值格。平表及向下明细不扩散合并值，保留合并区域并附诊断，避免把箱数、重量等共享指标复制到每一行。

`RawValue` 仅包含基础 .NET 类型，`DisplayText` 按指定文化与数字格式从缓存值生成，能保留 `000000` 等编号格式。公式返回 `Formula` 及文件已有缓存，缓存可能不是最新；不调用源格的计算接口。不能只凭显示文本推断金额、数量或编码，也不能把空缓存等同于数值零。

## 读取 CSV

```csharp
var table = await csvReader.ReadTableAsync(source,
    new CsvReadOptions
    {
        Delimiter = ",",
        Encoding = new UTF8Encoding(false, true),
        HasHeaderRecord = true,
    }, cancellationToken: token);
```

默认严格 UTF-8，并接受该编码的 BOM。其他编码或分隔符由调用方明确指定；服务不尝试多种编码、不猜测分隔符。即使调用方提供容错编码实例，读取也拒绝坏字节。所有字段始终是原始字符串，不裁剪空格，不按系统文化解析数字、日期或公式。

表头可以为空或重复，按索引消费。宽度不一致的记录保留实际字段数量并附 `ColumnCountMismatch`；不截断或自动补列。`HasHeaderRecord=false` 时所有记录进入明细，`Headers` 为空。`RowNumber` 是包含表头的逻辑记录编号，`SourceAddress` 保存物理起止行，方便定位引号内换行的记录。

## 生成受控 Excel 模板

模板在 Excel 中设计样式、合并、列宽、打印方向与重复打印标题，并按 Report 约定维护命名区域。三份预制样例位于测试项目 `Services/Files/Templates/Fixtures`，作为嵌入资源读取；生成脚本用于维护夹具，测试不会运行该脚本。实际业务模板由管理员发布到服务器专用根目录，维护 `模板目录.json` 和 `模板ID/v版本/模板.xlsx`；客户端本地模板流保留用于底层测试和受控工具调用。

```csharp
var data = new ExcelTemplateData(new Dictionary<string, object?>
{
    ["Title"] = "销售单",
    ["Order"] = documentSnapshot,
    ["Lines"] = lineSnapshots,
    ["Note"] = "交货备注",
});
await exporter.ExportToFileAsync(templateStream, outputPath, data,
    overwrite: false, cancellationToken: token);
```

变量字典会复制，变量内的对象和列表不会深度克隆。调用方应提前准备普通数据对象及已物化数组/只读集合，在整个操作结束前不得修改。不要传入 ViewModel、控件、流、任务、委托、循环引用或延迟查询。

单格使用 `{{Title}}`、`{{Order.CustomerName}}` 等表达式；列表使用对应的命名区域和 `{{item.Code}}`。纵向区域需包含服务列、服务行；嵌套区域按 Report 的命名与边界规则建立，不将其当作任意矩形复制工具。

公式只保留，不保证已有结果缓存，不主动调用全工作簿重算；保存设置 `EvaluateFormulasBeforeSaving=false`、自动计算、打开时完整重算。重复列表内的公式用文本 `&=ROUND(C5*D5,2)` 等 Report 写法，展开时保持相对/绝对引用。列表区域外普通公式使用原生 Excel 公式；区域外不带变量的 `&=` 文本可能不被 Report 解释，不能统一将所有公式改成 `&=`。模板不应使用固化公式值的 `OnlyValues` 标签。Report 内部可能读取模板中的原生公式值，因此只承诺服务不增加主动重算步骤，受控列表样例采用延后公式写法。

文本变量以 `=`、`+`、`-`、`@` 开头仍按文本输出；业务值含 `<<` 或 `>>` 时首期拒绝并返回字段路径，避免被 Report 再次解释为模板指令。模板指令由受控模板维护。公式中的金额精度、ROUND 位数、组小计及整单合计由模板明确设计，公共服务不代替后端权威业务计算。

参考：[简单模板与公式](https://closedxml.io/ClosedXML.Report/docs/en/Simple-template.html)、[列表区域](https://closedxml.io/ClosedXML.Report/docs/en/Flat-tables.html)、[嵌套区域](https://closedxml.io/ClosedXML.Report/docs/en/Nested-ranges_-Master-detail-reports.html)。

## 选择服务器模板并导出

业务 Feature 准备单据数据快照并声明 `ExportTemplateContract`。模板列表按单据类型、契约键和契约版本精确匹配；标准单据类型使用现有 `DocumentTypeStaticsEnum.SO/PO/PL` 等常量。页面负责模板选择和保存位置，公共服务不弹窗。

```csharp
var contract = new ExportTemplateContract(DocumentTypeStaticsEnum.SO, "sales-order", 1);
var templates = await serverTemplates.ListAsync(contract, token);
// selected 是用户从 templates 中明确选定的一项；没有模板时由页面说明原因。
var request = new ServerTemplateExportRequest(selected.TemplateId, selected.TemplateVersion, contract, data);
await serverTemplates.ExportToFileAsync(request, outputPath,
    overwrite: false, progress: progress, cancellationToken: token);
```

`ExportToFileAsync` 再次在线查询，确认用户所选 ID、文件版本及契约仍可用，再使用经过完整性检查的缓存或下载模板。版本变化要求刷新后重新选择，不自动升级。网络失败、账号失效、停用和版本冲突均停止导出，已有缓存不能代替在线确认。通过本次确认后，生成使用固定版本的内存副本。

列表经专用 Refit 契约访问，下载经带 `AuthTokenHandler` 的命名 HttpClient 流式读取。二者使用既有 `Api:BaseUrl`，保留虚拟部署前缀和正常 HTTPS 证书校验；不需要独立模板服务器系统参数。

缓存位于 `%LOCALAPPDATA%\SwiftExport\Cache\ExcelTemplates\v1`，以规范化 API 地址、用户 ID、模板 ID、文件版本和 SHA-256 隔离。每次读取核对实际长度、SHA-256 和 XLSX 容器；损坏时重新下载。完整下载通过校验后才原子发布，单模板输入上限 20 MiB、声明解压上限 100 MiB、缓存总配额 200 MiB，按最近使用清理。同键下载协调，等待者退出不会取消其他使用者。退出、切账号、换服务器都会使旧结果失效；缓存和最终输出提交前再次验证所属会话。

管理员的打包、部署、停用、回退和两客户端验收步骤见仓库 `_tools/ExportTemplates/服务器模板部署说明.md`。本期不提供真实单据模板、模板管理页面、业务页面选择 UI 或数据库表；这些在对应 Feature 接入时完成。

## 容量、流与取消

默认 `FileReadLimits` 为输入 20 MiB、XLSX 包声明解压内容 100 MiB、10,000 行明细、256 列/字段、250,000 个结果单元格（含表头）。读取选项可传入不同上限，不能设为零或无限。ClosedXML 会整本加载工作簿，这些保护不代表流式 Excel 解析，也不代表严格内存配额。模板输入和生成规模使用默认保护值；模板数据树同时受节点数和深度保护。

输入流从当前位置读取到结尾，不关闭、不自动回退。输出流从当前位置写入，不关闭、不截断已有内容；调用方应提供新流或自己明确设置长度和位置。所有内部解析器、缓冲区与工作簿在方法完成前释放，结果不持有这些资源。同一个外部流不得并发参与多个操作。

同步的工作簿加载、Report 生成和保存无法立即中断；服务在后台执行，前后阶段和自有遍历循环检查取消，等待阶段退出后释放资源。进度为阶段代码及真实行数，没有可计数的阶段不提供虚构百分比。页面可用 `Progress<FileOperationProgress>` 接收回调并将阶段代码映射成自己的文案；回调不应抛出异常。

## 发布、失败与页面接入

`ExportAsync` 先生成内部完整内容，再复制到目标流；复制时 I/O 失败或取消仍可能留下部分内容，调用方须丢弃，不自动回滚调用方流。

`ExportToFileAsync` 仅接受 XLSX 路径，目标目录须存在，不自动建立目录。默认不覆盖；显式 `overwrite=true` 才允许替换。写入同目录随机独占临时文件，写完并关闭后最后发布；取消在发布前生效，发布成功后不因后到的取消误报失败。失败保留原目标，并尝试清理本次临时文件。

整体失败为 `FileOperationException`，包含稳定 `Code` 和可选定位 `Issues`；不要按中文消息猜测类别。`InnerException` 留给技术日志，不直接展示堆栈或完整数据。单元格/行问题保留在读取结果 `Issues` 中，由 Feature 判断接受、提示或阻止提交；读取成功不代表业务合法。用户取消使用 `OperationCanceledException`，应保留页面已有编辑状态。

后续业务接入由 Feature 拥有文件选择、导入/导出权限、敏感字段、单据数据范围、Busy 和取消生命周期。公共服务不会自行从 Grid 抽取当前视图，不会在 UI 线程访问控件，也不替页面弹窗或决定提交。
