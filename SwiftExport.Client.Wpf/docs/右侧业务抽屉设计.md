# 右侧业务抽屉设计

## 1. 结论

当前客户端使用 WPF-UI 4.3.0。该版本没有用于承载任意复杂业务内容的通用 Drawer：

- `Flyout` 基于锚点 Popup，适合菜单和轻量临时内容，不适合长时间编辑 BOM。
- `NavigationView` 的 Pane 服务于导航菜单，不应改造成业务编辑抽屉。

客户端现已提供原生 WPF `RightDrawerHost`，用于 BOM、关联资料或批量设置侧栏。它可以承载 WPF-UI 按钮和 Fluent 资源，但不依赖 WPF-UI 的导航状态。

## 2. 当前 API

```csharp
public sealed class RightDrawerHost : UserControl
{
    public object? MainContent { get; set; }
    public DataTemplate? MainContentTemplate { get; set; }
    public object? DrawerContent { get; set; }
    public DataTemplate? DrawerContentTemplate { get; set; }
    public bool IsOpen { get; set; }
    public double DrawerWidth { get; set; } // 默认 520，双向，可由拖动更新
    public double MinDrawerWidth { get; set; } // 默认 360
    public double MaxDrawerWidth { get; set; } // 默认不限制，但不会超过宿主可用宽度
    public bool IsResizable { get; set; } // 默认 true
    public DrawerDisplayMode DisplayMode { get; set; } // Push / Overlay
    public ICommand? CloseCommand { get; set; }
}
```

控件保留 `Push` 与 `Overlay` 两种能力，但业务抽屉默认采用 `Overlay` 浮层：不重新测量或挤压主 DataGrid，右侧留出浮层边距和边框。用户可拖动抽屉左边缘调整宽度，也可使用关闭按钮或 Esc 关闭。

## 3. MVVM 数据流

业务 ViewModel 只暴露状态和命令：

```csharp
[ObservableProperty]
private bool isBomDrawerOpen;

[RelayCommand]
private void OpenBomDrawer() => IsBomDrawerOpen = true;

[RelayCommand]
private Task CloseBomDrawerAsync() => ...;
```

- `IsOpen` 双向绑定 `IsBomDrawerOpen`。
- `DrawerContent` 绑定 BOM 子 ViewModel，由 DataTemplate 创建 View。
- ViewModel 不引用 `RightDrawerHost`、Window 或 WPF-UI 控件类型。
- DrawerHost 只发起关闭请求，不判断或清除业务脏状态。
- BOM 有未保存修改时，由 Feature Dialog Service 调用现有 `IDialogService` 确认；用户取消后保持抽屉打开。

## 4. 交互与可访问性

- Esc 和业务关闭按钮走同一个 CloseCommand。
- Overlay 模式将抽屉浮在主内容上方，不改变主表列宽和滚动位置。
- 默认宽度 520、最小宽度 360；拖动左侧调整柄实时调整，最大不超过宿主可用宽度。
- Esc、业务关闭按钮和 ViewModel CloseCommand 使用同一关闭流程。

## 5. ProductsView 接入

ProductsView 使用 Overlay 浮层承载 BomDrawerViewModel，并允许用户调整宽度。抽屉关闭时产品选择不会加载 BOM；打开后才跟随活动产品。切换产品或关闭前由业务 ViewModel 处理未保存确认，DrawerHost 不持有 BOM 状态。
