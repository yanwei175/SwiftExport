# 右侧业务抽屉设计

## 1. 结论

当前客户端使用 WPF-UI 4.3.0。该版本没有用于承载任意复杂业务内容的通用 Drawer：

- `Flyout` 基于锚点 Popup，适合菜单和轻量临时内容，不适合长时间编辑 BOM。
- `NavigationView` 的 Pane 服务于导航菜单，不应改造成业务编辑抽屉。

后续需要 BOM、关联资料或批量设置侧栏时，在客户端实现原生 WPF `RightDrawerHost`。它可以使用 WPF-UI 的按钮、图标和 Fluent 资源，但不依赖 WPF-UI 的导航状态。

## 2. 规划 API

```csharp
public sealed class RightDrawerHost : ContentControl
{
    public object? MainContent { get; set; }
    public DataTemplate? MainContentTemplate { get; set; }
    public object? DrawerContent { get; set; }
    public DataTemplate? DrawerContentTemplate { get; set; }
    public bool IsOpen { get; set; }
    public double DrawerWidth { get; set; } // 默认 560，最小 360
    public bool CloseOnOverlayClick { get; set; } // 默认 true
    public bool CloseOnEscape { get; set; } // 默认 true
    public ICommand? CloseCommand { get; set; }
}
```

第一版固定为 Overlay：主内容保持原宽度，抽屉从右侧覆盖并显示半透明遮罩。暂不加入 Push 模式，避免 DataGrid 列宽和虚拟化视口在开关时反复变化。

## 3. MVVM 数据流

业务 ViewModel 只暴露状态和命令：

```csharp
[ObservableProperty]
private bool isBomDrawerOpen;

[RelayCommand]
private void OpenBomDrawer() => IsBomDrawerOpen = true;

[RelayCommand]
private Task CloseBomDrawerAsync() => ...;
```

- `IsOpen` 双向绑定 `IsBomDrawerOpen`。
- `DrawerContent` 绑定 BOM 子 ViewModel，由 DataTemplate 创建 View。
- ViewModel 不引用 `RightDrawerHost`、Window 或 WPF-UI 控件类型。
- DrawerHost 只发起关闭请求，不判断或清除业务脏状态。
- BOM 有未保存修改时，由 Feature Dialog Service 调用现有 `IDialogService` 确认；用户取消后保持抽屉打开。

## 4. 交互与可访问性

- 打开时保存原焦点，动画完成后把焦点移动到抽屉标题或第一个可操作控件。
- Esc、关闭按钮和点击遮罩走同一个 CloseCommand。
- 关闭完成后恢复原焦点；原控件已卸载时退回页面主操作区。
- 抽屉打开时遮罩拦截主内容鼠标输入，键盘焦点限制在抽屉内。
- 默认宽度 560，最小宽度 360；宽屏页面可由宿主显式设置更大宽度。
- 动画只使用 `TranslateTransform` 和 Opacity，不改变业务布局宽度。

## 5. 后续 ProductView 接入

本阶段不修改 ProductsView、ProductLineModel 或 BOM 页面。真实接入时应独立完成：

1. 建立 BOM 子 ViewModel、加载与未保存状态。
2. 在 ProductView 外层加入 RightDrawerHost。
3. 选择产品变化时决定复用、重新加载或确认放弃当前 BOM 修改。
4. 验证抽屉开关、Esc、焦点、Busy、Dialog 和 DataGrid 虚拟化。
