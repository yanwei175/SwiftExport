# DvFileStorage 使用说明

`DvFileStorage` 是独立的 .NET 10 本地文件存储类库。它只处理根目录内的逻辑路径、文件流和本地发布语义，不依赖 ASP.NET、ERP、数据库或第三方存储框架。业务命名、权限、HTTP 接口、访问 URL 和数据库引用由宿主负责。

## 配置根目录

类库不读取 JSON。宿主先准备一个已存在的绝对目录，再把普通配置对象传给 `LocalFileStorage`：

```csharp
using DvFileStorage.Abstractions;
using DvFileStorage.Configuration;
using DvFileStorage.Local;

IFileStorage storage = new LocalFileStorage(new LocalFileStorageOptions
{
    RootPath = @"D:\ERPFiles"
});
```

根目录不会自动创建，也不会默认到当前工作目录。实例会保存启动时的根目录快照；更改配置后应重建实例或重启宿主。根目录本身不能是符号链接、junction 或其他重解析点。

使用依赖注入的独立宿主可以自行注册单例：

```csharp
services.AddSingleton<IFileStorage>(new LocalFileStorage(
    new LocalFileStorageOptions { RootPath = configuredRootPath }));
```

## SwiftExport WebAPI 接线

SwiftExport WebAPI 复用已有配置节：

```json
{
  "FileStorage": {
    "Enabled": true,
    "RootPath": "D:\\ERPFiles"
  }
}
```

组合根调用 `AddConfiguredFileStorage`：`RootPath` 缺失或空白时不注册 `IFileStorage`；显式非空时在启动阶段校验绝对路径、目录存在性和读取访问，然后注册单例。`Enabled` 只控制既有 `/files/ProductImages` 图片读取入口，即使为 `false`，有效的 `RootPath` 仍会注册底层存储。

不要用本示例覆盖生产 `appsettings`、JWT 或连接字符串。服务器启用写入前，应只给应用池身份授予选定根目录及其内部临时目录所需权限，不要授予整盘权限。启动检查只验证读取访问，不创建写权限探针；写权限不足会在实际写操作时抛出异常。

## 文件操作示例

逻辑路径必须使用 `/`，可以包含中文和内部空格，例如 `产品资料/说明书 2026.pdf`。不能传绝对路径、URL、反斜线、空段、`.`、`..`、ADS、Windows 保留设备名或内部 `.dvfilestorage-tmp` 路径。

### 写入

```csharp
await using var source = File.OpenRead(sourceFile);

// 默认拒绝覆盖；目标存在时抛 FileAlreadyExistsException（IOException 子类），旧内容保持不变。
await storage.WriteAsync("产品资料/说明书.pdf", source);

// 调用方明确允许覆盖时，发布完整新文件替换旧版本。
source.Position = 0;
await storage.WriteAsync("产品资料/说明书.pdf", source, overwrite: true);
```

写入从源流当前位置开始，不要求流可 seek，不把整个文件读入内存。无论成功、失败或取消，类库都不会释放源流。

### 读取和文件信息

```csharp
await using (var content = await storage.OpenReadAsync("产品资料/说明书.pdf"))
{
    await content.CopyToAsync(destination, cancellationToken);
}

var exists = await storage.ExistsAsync("产品资料/说明书.pdf", cancellationToken);
var info = await storage.GetInfoAsync("产品资料/说明书.pdf", cancellationToken);
```

`OpenReadAsync` 返回的流由调用方释放；文件不存在时抛 `FileNotFoundException`。`ExistsAsync` 对缺失返回 `false`，`GetInfoAsync` 对缺失返回 `null`。权限不足、占用和其他 I/O 故障会继续抛出，不会伪装成缺失。`StoredFileInfo` 只包含逻辑相对路径、字节长度和 UTC 修改时间，不公开物理根目录。

### 删除

```csharp
await storage.DeleteIfExistsAsync("产品资料/说明书.pdf", cancellationToken);
```

文件已不存在时正常完成。该方法不删除目录、不递归删除，也不清理空父目录；权限或占用故障会抛出。

## 覆盖、取消和临时文件语义

- 每次写入先在根目录下的 `.dvfilestorage-tmp` 生成随机独占临时文件，流式复制和刷新完成后再通过同卷移动或替换发布。
- 默认 `overwrite:false` 的最终排他性由文件系统发布操作保证；同一路径并发创建只有一个成功。
- 默认覆盖冲突使用 `DvFileStorage.Exceptions.FileAlreadyExistsException`，调用方不需要把其他权限、锁定或磁盘 `IOException` 猜成同名冲突。
- `overwrite:true` 允许多个写入者竞争，最终文件是最后成功发布的某个完整版本；本类库不提供业务版本控制或写入顺序承诺。
- 发布前检查取消。取消或复制/发布失败时会关闭类库自己的流，并在不使用已取消令牌的情况下尝试删除自己的临时文件；已有正式文件在发布前失败时保持不变。
- 发布成功后不再把后到的取消报告为失败，也不会删除已发布文件。
- 如果临时清理本身失败，原始异常类型保持不变，清理异常放在 `Exception.Data[LocalFileStorage.CleanupFailureDataKey]` 中。
- 进程强杀或断电可能留下 `.dvfilestorage-tmp` 文件。首期没有后台清理器；只能在停止所有使用同一根目录的写入进程后人工清理，运行期间不能按时间随意删除。

## 路径安全与已知限制

- 已存在的根目录、父路径段和目标只要是重解析点就会被拒绝，不会主动跟随到根目录之外。
- 路径检查与实际打开之间仍有本地文件系统竞争窗口；根目录及子目录必须由受控服务账户管理。本类库不是针对拥有本机目录写权限攻击者的 OS 沙箱。
- 写入只保证不会发布半个文件，不承诺数据库事务、业务附件生命周期或断电持久性。
- 首期未验证 NAS 语义、跨进程分布式锁、MinIO/S3、MIME、缩略图、访问 URL、后台清理或 NuGet 发布。
- SwiftExport 的现有产品图片中间件仍只公开根目录下的 `ProductImages`，不会把整个存储根目录映射到 HTTP。
